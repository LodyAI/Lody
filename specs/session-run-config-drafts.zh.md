# 会话运行配置的私人草稿

Status: draft
Translation: current

[English](session-run-config-drafts.md)

## 场景与意图

在已有会话中开启或关闭 Fast，切到其他标签再返回，尚未发送的选择应当保留，就像未发送
文字一样。另一台设备的新轮次只更新共享基线，不清除本机未发送的设置。这是
[PR #1287](https://github.com/LodyAI/Lody/pull/1287) 选择的产品方向；本文修订仍为 draft，
不宣称已获正式文档审批。

## 职责

- 有效配置由私人字段修改、运行时状态、已接受或排队轮次的偏好及能力声明派生，
  不另存解析结果作为新的权威。
- 只有实际修改的字段才创建保留的草稿记录，按账户、工作区、会话隔离。
  明确关闭和重复选择同一个值也算修改。不保存对话历史或访问过的轮次 ID 集合。
- 每次字段修改都有新的代际标识。发送时只捕获最终冻结 inputConfig 中保持原值的字段代际。
- 本机发送被接受后，只消费这些捕获的代际。接受指完成本地轮次写入，或进入现有等待发送
  队列，不等待上传完成、远端交付或模型回答。
- 确认绑定原作用域，卸载后仍有效。较新的修改（即使数值相同）必须保留。
  接受之前失败不得消费草稿。
- 等待发送条目已拥有冻结配置。之后上传失败保留条目及重试入口，转为历史记录时不再确认一次。
- 删除、明确丢弃及权威账户退出清理对应意图。旧异步回调不能重建它，也不能清除另一账户
  新建的草稿。加载期间缺少元数据不等于已确认删除。
- 已确认的代理或提供方切换清理旧目标的草稿并使编辑回调失效；加载时缺少目标元数据不算确认切换。
- 普通标签或工作区导航，以及可恢复的归档，保留意图。不用任意 TTL 或 LRU 淘汰真实草稿。
  草稿只存于内存，不承诺重启后恢复。
- Role 目录未知且有手动草稿修改时，不能为无法确认属于该 Role 的轮次附加继承的
  Role 来源或记忆提供方。

## 证据与限制

实现与确定性测试位于共享 components 包。
[决策记录](../.agents/notes/implemented/bug-fix/2026-10-07-session-run-config-drafts.zh.md)
说明验证与环境限制。本约定改变了原来“远端新轮次可以确认本地修改”的隐式规则，
不改变共享会话协议或提供方执行语义。
