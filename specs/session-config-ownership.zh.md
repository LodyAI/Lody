# 会话配置归属

Status: draft
Translation: current

[English](session-config-ownership.md)

## 场景与决定

Agent 退出 Plan 并开始实现获批计划后，下一条消息不能因为历史仍在加载或能力目录刷新而恢复 Plan。会话执行所有者独立于转录加载维护已确认的运行配置。私有编辑描述下一次请求，不可变的 Turn 输入描述已接受的工作；二者都不证明 agent 已经改变状态。本方案拟替换现有基线和失败策略，不代表已发布行为。

Composer 使用已确认值加私有编辑。待发送和排队消息单独展示自己的冻结请求，不为另一条消息提供默认配置。历史不作为日常回退来源。能力刷新可以标记某值不可用，但不能将其替换为默认值或第一个选项。新会话默认值在 agent 确认前只是初始请求。

## 应用请求

现有准入只消费发送时捕获的私有编辑代次。从已确认快照构造的输入携带该快照 revision；执行所有者在接受输入前拒绝过期基线，保留请求供修正。本地待发送准入与执行所有者接受仍是不同阶段。已经接受的队列条目保持冻结配置，即使运行中的 agent 随后改变模式；队列条目必须展示这份请求。删除或重排队列不会改变当前配置。

执行所有者通过既有输入 receipt/writer 边界持久接受不可变输入，才算 owner acceptance。回执关联输入身份及成功的基线检查。相同已接受身份在重试或重启后复用回执，不再次检查旧 revision；本地待发送记录本身不是该证明。原有已被执行所有者接受的旧条目保持已接受状态，不新增一套发送 journal。

依次应用 mode、model 和依赖选项。已接受请求中的每个具体值都是要求。拒绝、矛盾确认、操作缺失或结果未知都应使该输入失败，不提交其 prompt。所有 provider 都展示安全的诊断，标明字段和原因。保留已确认的部分变更，不回滚、不降级、不在拒绝后换协议重试，也不自动重放结果未知的输入。冻结请求保留用于检查、明确重试或修正。

Native steer 不在 prompt 运行期间重新应用配置。仅当冻结要求与当前连接的已确认状态匹配时才使用该连接；已知配置不匹配沿用普通排队路径，并显示为排队。配置错误或结果未知不等于已证明 steer 未送达，不得因此自动转为普通执行或重放。普通的已证明未送达沿用现有策略。如果必须退役连接，也由既有生命周期所有者结算并报告正在运行的 prompt 的结果。

已确认状态须在依赖它的 prompt 提交前完成本地持久化。写入失败须可见；远端同步不作为提交屏障。Agent 主动改变配置也通过同一所有者更新当前配置，不改写驱动 Turn。旧连接观测不能更新替代连接。必要的连接代次和请求检查集中在这一边界，不放在 UI 中。

## 初始化与兼容

打开会话不会启动 ACP 进程。首次 live snapshot 到来前，显示运行配置尚未确认。允许请求明确选择让未指定字段使用 agent 默认值；正常 dispatch 路径建立或加载 agent，确认其状态，应用显式要求，并在提交 prompt 前持久化。字段缺失意味着继承，不是空值、false，也不是恢复历史选择的请求。

旧会话通过 session load/resume/new 获得首次确认；适用时可使用受支持旧协议的成功 ACK。不得遍历旧 Turn 重建当前配置。原有已接受输入保留其要求。旧的持久快照可作为“最后已知”显示，但不算新连接的确认。无法获得协议支持的确认时明确失败。

通过 machine capability 协商新配置契约。机器不支持时，新客户端显示需要升级，不悄悄切回旧的回退链。历史查看和 Stop 仍可用。不要求批量改写历史或迁移 provider。
