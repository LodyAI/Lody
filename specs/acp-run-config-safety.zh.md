# ACP 运行配置的安全保证

Status: draft
Translation: current
Language: [English](acp-run-config-safety.md)

用户选好权限模式（例如 Plan 或只读）和模型后发送消息。在 agent 开始处理这条消息之前，
Lody 必须确认 agent 的权限不会超过用户的选择：切换模型不能悄悄放宽权限，
Lody 也不能认为自己请求的设置已经生效。

## 顺序

Lody 按以下顺序应用一个 turn 的运行配置：先切模型，再设推理强度、Fast 等普通选项，
然后设独立的 Plan，最后设权限模式。切换模型可能会重建 agent 的其他选项，包括权限模式，
所以切换之前设置的内容都不能假定在切换后仍然有效。

## 意图

turn 的配置可以不带权限模式或 Plan。这时它沿用同一 session 中更早的、最近一次设置过该项的 turn。
两项分别解析；显式关闭 Plan 也会被保留。更晚的 turn（例如排队中的）不参与解析。
如果本 turn 切换了模型，或者 agent 当前报告的状态与继承的设置不一致，Lody 会重新发送该设置。

## 证据

只有 agent 自己的报告才算数：

- **确认**：agent 针对这次设置返回的完整选项列表，或者一个真正发出并成功返回的 `session/set_mode` 请求。
- **不算确认**：空回执、Lody 自己填入的值，以及本 turn 设置之前的任何报告。
- **异步报告**：它不带请求 id，所以只能否定确认，不能单独构成确认。

## 发送前的判定

请求属于受限请求的情况：内置 agent 的只读或 Plan 模式，或者 Core `plan_mode` 为开启。
第三方 mode 无论叫什么名字，都不算受限。内置模式有已知的从窄到宽的顺序；其他任意两个模式之间不可比较。

| 请求 | 结果 | turn |
| --- | --- | --- |
| 受限 | 确认相等，或更窄 | 正常运行 |
| 受限 | 未确认、设置失败、不可比较，或被否定 | 在发送 prompt 之前停止 |
| 任意 | 确认更宽 | 在发送 prompt 之前停止 |
| 非受限 | 未确认、设置失败，或不可比较 | 运行，并显示可见警告 |

被停止的 turn 会报告请求值、实际值和模型。用户修改设置后重新发送。
Lody 不会自动重试，也没有一次性放行。
