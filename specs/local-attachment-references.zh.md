# 直接本地附件引用

Status: draft
Translation: current

[English](local-attachment-references.md)

## 决策

同桌面普通文件直接使用路径，不作为已上传对象或已登记能力。`local_attachment`
携带所属机器、绝对路径和展示信息。原文件保留在原位置；无路径或生成内容在发送前
保存到持久本地附件目录，随后使用相同的路径表示。不维护 ID 到路径的登记表，不绑定
单次提交，不提供解析 RPC 或继承操作。重发、排队和同机 fork 直接复用 payload。

因此，绝对路径成为对话内容的一部分，并参与既有同步。路径标识文件，不授予读取权限。
本次修订替代此前草案中的不透明登记与逐 turn 继承设计。这是明确的取舍：普通文件采用
正常的路径语义，不再引入第二套附件授权和存储协议。

## 准备与执行

共享准备流程只选择一次传输方式。可信的原生机器身份与目标匹配时走本地准备；其他情况
使用既有传输路径。选定本地路径后，失败直接报错，不静默上传普通文件。原文件无需准备
RPC、复制或内容哈希。生成字节完整保存后才返回路径，准备失败保留草稿。保存的文件供
重试和历史继续使用，自动回收不在本次范围内。

实际执行时，host 检查所属机器、既有请求者权限及路径是否为普通文件。普通路径转换为
正确编码的 ACP `file://` resource link。Agent 沙箱仍是其读取边界，选择工作目录以外的
路径不扩大权限。文件丢失、不可读或被沙箱拒绝时报告错误。附件准备从不修改或删除原文件，
使用时读取当前内容。符号链接在使用时解析，不冻结此前的目标或字节。

不能仅通过更换 `machineId` 把准备好的路径转移到另一台机器。跨机器重发或 fork 需要显式
替换为已传输附件。本机预览沿用既有文件资源边界。其他设备显式下载时使用经过认证的
文件 RPC 及其既有工作区路径限制；本地附件不能让任意 host 文件绕过这些限制。
位于允许下载范围之外的生成文件可能仅在本机可用。分享、导出须披露本地内容缺失，或拒绝
完整附件导出，不能隐式上传原路径。

## 图片

图片保留 image payload。同桌面准备在发送前保存独立本地快照，因此预览和 Agent 执行
不等待云端认证或上传。已授权的后台上传流程发布快照，在联网恢复后重试，并根据持久元数据
及回执恢复。发布后保留本地身份，支持后续离线读取。回执统一更新历史、冻结输入及排队引用，
包括上传完成后才写入的消息。远程目标保留既有图片传输路径。

ACP 接收视觉图片字节及 resource link 使用的工作目录副本，持久快照不暴露在 Agent
可写路径中。冻结输入仍可能引用快照时保留快照，配额不足拒绝新图片，而不猜测哪些快照已无用。
加密工作区的明文准备仍不支持。OSS 组合保持仅本地，不增加云端能力。

## 兼容性与证据

新路径引用不进入旧文件补传。已有传输型 `file`、`image` 输入保留原传输语义。
被删除的不透明登记格式不提供兼容解析器；没有路径的旧引用不可用，需要重新选择。
不支持的执行输入须使整个请求失败，不能在解析时被丢弃。不增加附件专用版本预检。

实现分别由共享准备层、Electron 本地文件边界、负责生成文件保存和实际读取的
`session-local-attachments.ts`，以及负责执行和图片上传的 `message-handler.ts` 承担。
[附件生命周期说明](../.agents/docs/cli-lib-session-files.md)解释代码。
打包应用离线重启及真实跨设备图片上传仍需手动验收，本文不声称这些验收已经通过。
