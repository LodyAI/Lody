# 会话工作树生命周期

Status: draft
Translation: current

[English](session-worktree-lifecycle.md)

用户归档了一个在独立工作树中运行的会话。Lody 必须最终在所属机器上移除该工作树目录，保留分支以支持恢复，并且不依赖请求、确认或队列：会话的归档状态是唯一输入。

## 场景

Alice 在本地项目上运行三个会话，每个都使用 Lody 数据目录下的独立工作树。所属机器休眠时，她从笔记本归档其中两个。机器的 daemon 恢复并同步工作区元数据后，发现这两个会话已归档，移除其工作树目录并保留分支。一周后 Alice 恢复其中一个会话，工作树从保留的分支重建；她删除另一个会话，磁盘上无需额外操作。

## 预热交接

用户可能在草稿预热被取消、替换或失败时发送消息。正式执行或下一次预热复用该会话的工作目录前，daemon 必须完成旧预热的资源释放，包括取消后才返回的创建结果。预热从可用池移除不代表清理已经结束。迟到的清理绝不能删除正式执行已接管或重建的工作目录。等待按会话隔离，其他会话无需等待。

此交接约束针对尚未接管的预热资源，不改变下述归档与恢复的保留规则。

## Git 执行失败

Worktree Git 操作拥有命令，直至完成或等待清理结束。启动、超时、输出/流和未解决的
释放失败必须可观察，不能代表分支不存在、默认 identity 或尽力 fetch 成功。强制删除
不能仅因为 Git 无法启动或清理未解决而移除未提交文件。已完成的 Git 退出与这些
基础设施失败区分，由管理器按操作进一步分类。本修订不提供 Git 回滚或崩溃事务。

Git 调用保留 10 分钟期限与有界输出。Credential-helper 探测具有 5 秒期限。普通诊断
失败可以记录，但原始 Git 操作仍失败；未释放的诊断进程必须保留拥有者并报告。
取消/期限完成等待既有有界进程树清理，失败保留恢复拥有者，不能宣称 released。
原生命令边界尚未让 Promise Session/setup/GC 调用方获得端到端结构化取消。

## Worktree 观察操作

检查区分缺失目录、健康的干净或脏 worktree，以及 Git 已完成退出所表示的失败。
启动、超时、文件系统和未解决的清理失败继续报错。列举不能隐藏已存在的损坏仓库
或不可读根目录，返回不完整的成功结果。只有真正未诞生的命名分支可报告 null HEAD，
任意 Git 失败不能充当 HEAD 缺失；detached commit 仍报告其提交。
列举保留仅目录的策略，排除符号链接条目和不安全的 Session 名称。

检查和列举共享变更拥有者的 repo 锁。已取消的排队查询不能稍后获取它。
执行中的查询持有租约直到命令清理完成，失败和中断也如此，后继操作不能与清理重叠。
变更内部在已持有的锁下读取信息，不能再次获取同一把锁；同上下文重复获取仍立即报错。
有界清理失败时保留外部进程恢复所有权，文件租约释放不证明进程已消失。
这些观察操作不提供多条命令间的原子快照或 Git 回滚。

## 本地源准备

本地项目 worktree 准备在发布新元数据前验证源。已有源元数据和用户文件保持原样。
准备写入失败或取消不能发布半写元数据；独占发布完整文件，保留其他写入者安装的
元数据。这不提供断电持久性，也不回滚持久目录或 Git 变更。

变更调用方拥有仓库租约；准备操作仅拥有元数据临时目录并等待释放。释放等待有五秒
上限，失败或超时保留唯一拥有的路径及有界重试能力，即使发布已完成也不能报告准备
成功。已提交给内核的文件系统操作可能超过本地等待，释放失败不能描述为已确认删除。

## 职责

所属机器的 daemon 是唯一可以操作该机器磁盘的执行者。它根据会话状态对自己创建的目录树进行协调：

- 范围仅为 Lody 托管工作树树形目录：`<data>/repos/<repo>/worktrees/<session>`。每个目录以拥有它的根会话命名。此范围外的目录不会被清理；直接在用户目录中运行的会话没有自己的工作树。
- 根会话归档或删除后，目录进入移除范围。子标签页共用根会话工作树，不决定其生命周期；单独归档子标签页不会移除目录。
- 所属会话未知的目录保持不动。一台机器可能服务多个工作区，因此未知目录可能属于 daemon 看不到的会话。已删除会话有工作区删除标记，与从未见过的会话可区分。
- daemon 只有在工作区元数据完整后才执行清理。在此之前，它无法区分尚未同步的会话和已归档会话，不能猜测。
- 移除备份的是 cleanup 脚本执行后剩余的状态。未提交的非 ignored 改动先提交到会话分支；归档、恢复或删除都不会删除该分支。被 Git 忽略的文件（构建产物、本地环境文件）可能随目录丢弃。备份是本地提交，不是远程推送或完整目录备份；脚本在提交前删除或修改的文件不在备份保证内。备份提交失败会阻止移除，并等待重试。无法通过 Git 解析所属仓库（项目目录消失或仓库损坏）时，工作树必须保留并重试：备份无处提交，目录可能是工作的唯一副本。注册为仓库子目录的项目由该仓库拥有。
- 移除时 Git 报告的分支名会写回会话，因此用户在终端中重命名分支后仍可恢复。
- 配置的 cleanup 脚本在移除前运行。失败会通过会话历史和 daemon 日志报告，但不会阻止移除。成功移除目录后，脚本不会再次运行。
- 协调可幂等重复执行。在元数据同步完成、会话归档或删除状态变化时以及定期触发。清理失败的目录会按退避策略重试，没有一次尝试是最后一次。

## 操作

| 操作         | 磁盘影响                                                                       | 分支影响 |
| ------------ | ------------------------------------------------------------------------------ | -------- |
| 归档根会话   | 备份提交后移除工作树                                                           | 保留     |
| 恢复归档会话 | 从保留分支重新创建工作树                                                       | 保留     |
| 删除归档会话 | 无需在归档之外追加磁盘操作；若归档清理尚未完成，删除标记让目录继续进入清理范围 | 保留     |
| 移除本地项目 | 会话归档，工作树按归档规则清理；移除对话框中的可选立即清理只改变时机           | 保留     |

daemon 观察到归档状态后，会及时释放会话运行时：关闭 Agent 进程、终端、在线状态和预览隧道。运行时释放与磁盘协调独立，不等待磁盘清理。

已不属于工作区的机器不在范围内：没有执行者可以操作其磁盘，其他机器也不得尝试。

## 公开保留合同

手动归档和 PR 自动归档使用同一清理合同。公开文档及自动归档设置必须区分保留的对话历史和本地分支，以及可能在永久删除会话前被移除的托管工作目录。必须说明 ignored 文件和 cleanup 脚本的保护边界，并提醒用户在归档或启用自动归档前把需要的文件另存到工作树之外。

恢复会话后，继续执行时会从保留分支重建缺失工作树，并再次为新目录运行 setup 脚本。恢复不会找回被丢弃的 ignored 文件或被 cleanup 脚本移除的文件。所属仓库与分支必须仍可用；被移除的本地项目须重新注册。删除会话会删除对话，但不会删除本地 Git 分支及备份提交。

PR 自动归档设置位于“设置 → 偏好设置”，仅在当前设备启用，并仅在该设备观察到当前用户拥有的会话关联 PR 进入已启用的终态时触发。应用启动时观察到的已终结 PR 不会导致追溯归档。产生的归档状态可以触发所属机器上的工作树清理，即使归档是在其他设备发起。

## 替代的机制

较早版本使用持久化的逐机器命令队列（归档请求和带载荷的删除请求），由 daemon 消费并确认。命令以错误结果被消费后无法再处理；项目根目录等必要数据可能晚于命令到达，临时读取失败也可能确认实际未发生的清理。状态协调消除了确认和顺序依赖：目录仍存在就是尚有工作待处理的唯一证据。删除不再删除分支，因此也不需要载荷。

旧客户端写入的队列条目会直接丢弃，不再处理；这些会话由旧客户端同时写入的归档或删除状态覆盖。

## 未决边界

- 尚未确定删除标记是否能经受长期元数据压缩。若标记消失前清理仍未完成，该工作树可能保留至手动移除。
- 本地项目移除对话框仍提供跳过脏工作树并报告保留的立即清理选项。按本合同，这些目录之后仍会被归档规则清理（先备份提交），因此对话框对“保留”的描述过强；该对话框的简化是另一项改动。
- 会话在归档清理完成前被删除时，不再执行 cleanup 脚本，因为配置和记录执行结果的会话历史已随文档删除。
