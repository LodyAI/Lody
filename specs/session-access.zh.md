# 单会话团队访问

Status: draft
Translation: current

[English](session-access.md)

机器所有者可以只共享一个会话供团队阅读，同时保持机器私有。同事能阅读完整对话，
并在自己的会话中引用它，不能在被分享的会话中发消息、执行命令或管理会话。
普通与加密工作区使用相同的规则和控件。

## 权威来源和有效权限

权限不写入可变的 CRDT SessionMeta。只有会话当前 `machineId` 对应机器的所有者
能管理共享，分配的 `userId` 不产生权限。另一台机器上的授权无效。子 Tab 和 Side Chat
只在机器相同时跟随根会话；由它打开的独立 Session 不继承。

| 当前授权 | 有效权限 |
| --- | --- |
| 机器所有者 | 管理、编辑，始终可见 |
| 机器及会话使用的本地项目均已共享 | 沿用现有可编辑行为 |
| 同机器上根会话的明确只读授权 | 只读 |
| 无授权 | 隐藏 |

会话只读不打开机器或项目共享，也不授权执行。本阶段不能在已共享的机器／项目中
单独将某个会话设为私密。

## 存储和信任边界

普通工作区将 `readSharedSessionIds` 存在权威机器行。服务端检查当前工作区成员身份，
且仅允许机器所有者修改集合，Convex 订阅实时推送变化。公开源码只包含 DTO 和能力
开关后的调用，后端处理器属于私有组合。

加密工作区将 `sessions: [{sessionId, level: 'read'}]` 放在机器所有者签名的完整 v3 策略。
`session` 改动只增删该 ID，不改变机器／项目开关。格式 current-only，不保留旧格式
读取、迁移或重建脚本；E2EE 尚无生产数据。先部署兼容的后端准入，再发布客户端；
旧客户端拒绝 v3，不改成员账本格式。

只验证最新原文：解密、验证当前有效的所有者个人设备签名、核对资源／绑定／代次，
并比较本地最高版本 pin。较低版本和同版本不同摘要均拒绝；缺少中间版本不影响读取。
父摘要只用于服务端 CAS 写排序。签发者撤销后其策略失效，另一有效所有者设备从私密
默认值重新共享，不继承被撤销设备的授权。

可订阅的加密查询只暴露机器／代次／版本提示，触发主机重读策略；打开深链接也强制
重读。提示本身不授权。撤回沿用[机器共享 Spec](e2ee/machine-sharing.zh.md) 中接收端
的新鲜度窗口与信任限制。执行仍要求机器／项目权限，CLI/MCP 历史读取可以接受匹配的
会话只读授权，不因此授予执行权。

其他成员默认看不到加密私有机器上的会话，除非存在机器／项目或会话授权。
**这只是界面隐藏，不是密码学私密**：成员仍持有内容密钥，可以绕过界面恢复内容。
本设计没有服务器按房间过滤，也没有每会话密钥。

## 只读界面

标题栏直接显示「私密／团队只读／团队可编辑」。「团队访问」面板提供「私密」和
「团队只读」选项。有效机器／项目共享决定可编辑时说明原因，并提供机器设置入口。
非所有者看到相同面板，但控件禁用并说明归属限制。公开链接保留独立的发布同意与授权。

只读页用「只读 · 运行在 X 的机器上」和「在新会话中引用」替换输入框，引用动作预填
真实的会话 mention。保留置顶、标未读、复制 Markdown 和引用。隐藏停止、Steer、
排队、审批／问题回复、运行／Role 配置、重命名／归档／改 owner／共享修改、文件保存、
终端输入、Commit／Push、浏览器与模拟器预览。桌面和 mobile 列表显示只读标记；
管理命令重新检查当前权限，不相信旧界面回调。
