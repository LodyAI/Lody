## 托管操作提案

[托管 daemon 更新草案](daemon-upgrade-installation.md)为此契约增加机器级持久化操作。
本节尚未实现；下文的旧回调行为仍是当前实现。

只有所有者授权、目标解析及本地操作持久化成功后才接受。不可变请求绑定操作 ID、
机器代际、动作、确切版本及中断策略。同一请求重试返回原操作；同一 ID 携带不同
输入则拒绝。跨 workspace、跨进程重启串行处理生命周期操作。已有活跃操作时，
新请求返回该操作身份，不替换目标、不打断它。

ACK 丢失不取消已接受的处理。处理可以结束于准备失败、取消、过期、授权拒绝、
已应用、已回退或恢复失败；接受不承诺无条件中断。切换前检查当前授权。
等待空闲的有效期必须持久化。相同不可变操作可取得新的授权，但不得复活过期或
已取消操作，也不得静默延长等待期限。

先在本地持久化有序进度及最终结果，再发布。daemon 替换后保留操作身份和结果；
详细记录过期时仍有明确的重放拒绝下界。响应丢失后查询原操作，不自动创建新的
重启请求。未知或断联不等于最终失败。结果查询与取消使用同样的所有者授权。
结果绑定操作 ID、机器代际、实际运行版本及递增修订号，旧消息不能覆盖新结果。
本地应用可在远端发布断网时完成；UI 观察到经过认证的已应用结果后才确认成功。

## 已接受的工作与响应投递

当前实现中，CLI 已授权并接受的重启或更新即使无法投递回执也要继续。
接受更新前仍须成功写入已有更新意图。被拒绝的操作不触发生命周期退出。

RPC 服务先在总计五秒的预算内尝试投递 accepted 响应。成功、重试耗尽或截止时间
到达后，调用现有 CLI 生命周期回调。ACK 投递错误用于诊断，不得产生与已接受状态
矛盾的操作失败响应。迟到的投递结果不能再次触发操作。

已有进程边界保留一次性退出保护。此旧流程不提供进程级准备串行化或跨重启请求去重。
截止时间只限制等待，不取消底层 HTTP 请求。客户端超时表示结果未确认，不取消
已接受工作，也不证明 daemon 重启或更新失败。完成态报告是独立职责。
