# E2EE 确定性攻防实验室

Status: draft
Translation: current

[English](e2ee-adversarial-lab.md)

## 1. 目标与范围

用一个攻击 Agent 探索漏洞，其余全部由确定性程序完成：多人协作、离线重连、邀请、撤权、换代、同步，以及结果判定。攻击 Agent 可以在明确的事件边界读取或修改后端数据，并观察后续结果。发现的问题必须能脱离 Agent 重放，成为回归测试。

本方案替代旧 demo 和游戏教程方向。目标包为当前仓库、当前分支上的 `packages/e2ee-lab`；不新开仓库，不在临时目录长期开发。后端仍是本地 Node + SQLite Riverrun。使用真实 `@lody/e2ee-core`、streams-crdt、Loro/Flock，不模拟签名、加密、验证或 CRDT 合并。不接入 Lody 产品，不改变协议，不增加云服务，不做 UI 或游戏。

实验室位于 `packages/e2ee-lab`。本文仍为 draft：不是安全验收证明，也不是产品启用。接口名称可微调，但不得悄悄改变安全边界。

技术方向已选择 **TypeScript + Effect**，不再采用 Rust 主控。允许在 e2ee-core 内局部引入 Effect，但不整体改写密码学或纯账本。实施清单和证据统一维护在[实施计划](../.agents/notes/proposed/testing/2026-09-16-e2ee-adversarial-lab.zh.md#实施计划与唯一任务表)，本文定义验收契约，不重复维护进度。

## 2. 四个职责

```text
攻击 Agent ──受限攻击接口──► 调度器 ──► 本地 Riverrun / 网络响应
                               │
                        确定性诚实客户端
                               │
                         私有裁判与记录器
```

| 模块       | 负责                                         | 不允许                                            |
| ---------- | -------------------------------------------- | ------------------------------------------------- |
| 诚实客户端 | 按脚本编辑、邀请、收发密钥、验证、同步、重启 | 让 LLM 决定正常操作或绕过公开 API                 |
| 调度器     | 全序事件、虚拟时钟、网络投递、持久化完成点   | 依赖真实 sleep 或操作系统调度决定结果             |
| 攻击接口   | 暴露服务器数据与可操纵的请求/响应            | 暴露客户端明文、密钥、私有记录或裁判状态          |
| 裁判       | 检查安全属性、收敛、崩溃恢复并生成证据       | 仅凭攻击 Agent 声称成功，或只凭 HTTP 状态判定安全 |

测试的全序只描述一次执行，不把实际分布式协议改成无并发协议。例如 A/B 都读到 head H，各自提交 CAS，再由调度器确定先处理哪一个。

### 2.1 核心与 Effect 的边界

| 层                 | 所有者    | 契约                                                                                                       |
| ------------------ | --------- | ---------------------------------------------------------------------------------------------------------- |
| 纯计算             | e2ee-core | 普通 TS 编解码、哈希、验签算法、权限规则和状态转换；无隐式网络、存储、时间、随机数、环境探测或 Worker 创建 |
| 能力接口与实际适配 | e2ee-core | 明确注入加密能力、时钟/定时器、流、存储、实时授权及验签执行策略；真实算法不替换成 mock                     |
| 业务流程           | e2ee-core | 用 Effect 管理提交/恢复、分钥、准入及资源生命周期；保留 Promise API 薄入口，只有一套业务实现               |
| 实验调度与攻击     | e2ee-lab  | 纯事件状态机、受控能力实现、攻击接口、记录和裁判；核心不能反向依赖实验室                                   |

以下为新增验收契约 E1–E8；协议、权限、恢复及首轮同步的既有规则不变：

- **E1 纯计算边界**：相同显式输入产生相同结果/错误；调用不得修改输入或旧账本。内部局部 mutation 可用于计算，但不外泄；缓存应按实例显式管理且可禁用，不得跨实验共享状态或影响验签结论。密码库必要初始化归属明确，不能由测试随意覆盖全局验签配置。
- **E2 执行策略显式化**：账本内部不读环境变量、不自动创建 Worker。单线程是确定性基线，并行验签由显式适配器执行；所有验签、嵌套证明和错误位置语义保持。不得新增公开 `verified=true` 或裸布尔验签结果绕过安全入口。
- **E3 副作用闭合**：统一控制时间读取和定时器；网络、文件、SQLite、密钥生成、nonce、HPKE 临时密钥及 CRDT/Wasm 随机/时钟均列出实际来源。仅包 `Effect.tryPromise` 不算完成注入；未受控来源阻止相应重放验收。
- **E4 一套业务实现**：保留现有 Promise 调用方式；新增 Effect 入口使用明确的依赖和错误类型。Promise 入口只运行同一实现，实验室也调用它，禁止另写“模拟版 submit”。最外层才创建/释放 runtime，不能每次网络请求创建隐藏 runtime。沿用仓库 Effect 3.18.4，不搭车升级。
- **E5 安全顺序**：固定字节先耐久保存为 pending，再发 CAS；未知结果保留 pending 并读回确认，冲突不重新签名。原始截止时间不能被重试、缓存或恢复延长。异步验签后仍检查当前权限；最终同步检查与受保护操作之间不插入新的 yield/await。
- **E6 中断与崩溃**：Fiber 中断不等于网络撤回、事务回滚或进程崩溃。明确请求是否已派发和结果是否未知。正常退出用 Scope 释放资源；真实崩溃测试使用进程终止/重启，不依赖 finalizer 帮忙落盘。只保护必要的短同步提交区，不把整段网络等待设为不可中断。
- **E7 明确调度**：状态机形如 `transition(state, event) -> { state, commands }`，不执行副作用。Effect 解释 commands；影响业务状态的操作必须先获得许可再开始。异步完成只代表结果就绪，交付顺序由事件计划决定。稳定 ID 按逻辑 actor/operation/phase 分配，不按回调先后分配。
- **E8 受控而非虚假环境**：Effect 不是安全沙箱，TestClock 不接管第三方全局定时器或 Wasm。真实 SQLite/HTTP 仍执行；一次运行只在声明边界交错，不承诺重放任意原生内部线程竞态。无法控制的内部边界标记未覆盖。受控与真实运行适配器须做同语义对照。

这些是目标，不是当前代码事实。源码核对发现自动 Worker 选择、模块级缓存、部分全局随机源和全局定时器，正是本次重构要消除的隐式依赖。详细 API 在第一阶段以类型草图和兼容性测试冻结，不扩展成通用运行平台。

## 3. 时间与事件

每个事件有稳定 `eventId`、递增 `step`、虚拟时间、参与者、操作引用和阶段。正常事件脚本固定；攻击可以插入动作、延迟/丢弃消息、触发确定的错误分支。最终执行顺序完整记录。

至少暴露这些边界：

1. 本地编辑完成。
2. 生成待发送的真实加密/签名字节。
3. pending 持久化完成、尚未发送。
4. 请求排队、尚未提交后端。
5. 后端提交完成、尚未送达回执。
6. 响应到达、尚未验证或导入。
7. 验证/导入结束、本地文档尚未落盘。
8. 本地文档落盘、cursor 尚未落盘。
9. cursor 落盘、一步完成。

不同操作只使用适用阶段；不为凑事件伪造内部步骤。“任意时刻”指任意已暴露边界，不是任意 CPU 指令。攻击者可知道公开的阶段标签，但不能通过事件参数看到明文或密钥。重试、超时、凭证到期、断线、重启和异步完成顺序全部由调度器推进。Wasm/CRDT 的 peer ID、时钟和随机来源也须盘点；无法控制的来源不得标成已可重放。

## 4. 攻击能力与隔离

两种场景分开报告：

- **外部攻击者**：拥有自己的设备密钥，可调用正常服务接口，不能绕过后端权限。
- **恶意服务器**：可读取并修改 Riverrun 中全部服务器可见数据，可替换/截断/删除/重放响应，对不同客户端提供不同视图。此模式故意绕过服务器权限层，用于检验客户端防线。

支持攻击者自行生成任意字节或执行受限数据库修改，不仅提供固定攻击按钮。数据库修改必须在调度器屏障内通过事务，或正确停机再改；处理 WAL/sidecar，记录修改前后数据。物理数据库损坏属于可用性攻击，不能冒充签名绕过。

攻击者不能读取诚实客户端目录、进程内存、环境、密钥、解密日志、恢复文件或裁判预期值，也不能改客户端/裁判代码。隔离使用实际容器/沙箱权限或仅暴露能力接口；同一用户下两个普通进程、目录前缀和 prompt 约束均不构成隔离。不能验证隔离时，只允许固定脚本测试，不启动自由攻击 Agent。

攻击 Agent 的上下文不得继承调试者看过的秘密。攻击载荷是数据，不是客户端、裁判或工具执行的新指令。执行时间、输入大小、磁盘和输出量设定预算；超限单独报告，不能伪装成通过。

## 5. 编程接口草案

```ts
interface AttackLab {
  observe(): Promise<PublicView>;
  advance(input: { steps: number }): Promise<PublicView>;
  advanceUntil(input: { actor?: string; phase: string; maxSteps: number }): Promise<PublicView>;
  readBackend(input: BackendRead): Promise<Uint8Array>;
  mutateBackend(input: BackendMutation): Promise<MutationReceipt>;
  intercept(input: ResponseMutation): Promise<MutationReceipt>;
  submitClaim(input: AttackClaim): Promise<ClaimReceipt>;
  finish(): Promise<PublicReport>;
}
```

这是测试接口，不加入 e2ee-core。CLI/JSON-RPC 可薄封装同一接口。`advanceUntil` 是有界推进，条件未出现也有明确结果。修改必须引用当前事件和具体对象；失效目标返回错误，禁止猜测后静默改别的数据。拦截可以表达 drop、delay、duplicate、replace 和 per-client fork，所有动作记录实际字节与执行位置。

上面的 Promise 是 Agent/CLI 边界；内部同一实现使用 Effect。首版能力按职责收拢为 Clock、Crypto/Entropy、Network、Storage、Actors、Recorder，不为每个函数新建 service。调度器一次放行一个选定阶段；跨客户端操作仍可在阶段间交错。调度命令需有确认，禁止“后端已经写完、只拦返回值”冒充提交前暂停。

`observe` 只返回服务器可见元数据、公开事件和经审查的错误类别。`submitClaim` 可提交“恢复出某段明文”或“伪造状态被接纳”等证据；详细裁判预期在运行结束前保持私有，不能把裁判做成无限明文猜测接口。`finish` 关闭本轮攻击并按场景运行有界收尾，不自动修复被永久删除的数据。

## 6. 可重放材料

一次运行记录：代码提交与脏树标识、依赖/构建哈希、场景版本、初始状态、虚拟时钟、所有调度选择、请求/响应字节、数据库修改、异常与最终裁判结果。未记录的宿主 SQL 或外部修改使该次运行失去可重放资格。

分开存放：

- **攻击者视图**：它当时看到的事件、后端密文、动作和公开结果。
- **私有复现包**：初始客户端状态、秘密随机输入/随机带、真实预期值及必要的完整网络材料。仅可信 replay runner 可读取，不提交仓库、不交给攻击 Agent。

不能只保存一个公开 seed：如果它能推导客户端密钥，保密实验已经失效。测试专用可控随机源必须显式注入且禁止成为生产默认值；若某库无法注入，则保存安全的初始状态或增加窄测试接口，并如实记录限制。生产加密算法保持不变。

重放时无需 LLM，使用记录的攻击动作。验收要求相同事件序列、协议字节、接纳/拒绝结果、逻辑状态和最终判定；SQLite 文件布局、进程 ID、真实耗时不要求字节一致。任何偏差报告首个分歧事件，不算重放成功。

## 7. 场景与安全判定

先做三个成员、一个 Loro 文档的持续协作：创建、邀请、分钥、多轮交错编辑、离线重连、一次撤权和换代、剩余成员继续同步。撤权前已获取的历史密钥不要求“收回”。首个完整反例必须在 Riverrun 内修改真实密文，证明接收端拒绝且未污染状态，再精确重放。

随后扩展：

| 场景                                      | 必须观察的结果                                                    |
| ----------------------------------------- | ----------------------------------------------------------------- |
| 密文/签名/密钥包篡改，跨文档或跨 Org 替换 | 验证失败；不得导入伪造状态、授予权限或推进越过坏数据的持久 cursor |
| 未授权设备追加、伪造邀请/角色提升         | 不进入客户端已认证状态；后端拒绝和客户端拒绝分开验证              |
| 两个 CAS、重复投递、提交后丢 ACK          | 仅合法提交生效；恢复既有 pending，不重新创造重复操作              |
| 文档持久化和 cursor 持久化之间崩溃        | 重启后不静默丢数据；重复导入保持幂等                              |
| 撤权与换代、旧凭证、延迟上传              | 按现有权限和截止规则判断，不擅自引入跨流事务或更严格即时撤权      |
| 快照替换/截断、bootstrap 与增量交错       | 不把未认证内容当作有效快照；历史合法快照不因作者后来撤权而失效    |
| 回滚、分叉、伪造对账纸条                  | 本地已有锚点和独立对账分别验证；未经独立核验不得显示 checked      |
| 密钥历史链、Flock、恢复备份               | 同样通过真实公开 API 验证；恢复只承诺当前实际实现的范围           |

裁判分别输出：保密、身份/权限、完整性、持久性、可用性、可检测性。结果为 `pass`、`violation`、`unavailable`、`outside-model` 或 `harness-error`，不得合并成一个模糊的成功标记。

保密挑战使用诚实侧私有生成的未知内容；攻击者提交恢复证据，裁判私下比对。扫描后端明文泄漏是补充检查，不是密码学证明。长度、访问时机和公开账本等元数据不承诺隐藏。已授权恶意成员主动泄密、诚实端私钥被偷不属于服务器保密保证。

**不承诺所有攻击立即被发现。** 签名伪造可被拒绝；删除和持续停服只能判定不可用，不能确证恶意；首次加入者面对合法签名的旧视图或有权背书者与服务器合谋，可能需要独立诚实成员对账。若没有独立证据，裁判应展示模型限制，而非假造检测能力。

当前依赖诚实后端的新鲜度、无分叉和凭证截止保证，不会在恶意服务器模式自动成立。15 分钟截止在相应假设成立的场景验证；绕过该假设另列结果。攻击停止且必要数据仍可获得、合法密钥仍可取得后，才要求在场景规定的步数预算内收敛。永久删光历史不要求凭空恢复。

## 8. 实施阶段与验收

每阶段必须留下命令、精确版本、原始结果、未通过项；测试数量不能代替属性覆盖。先完成固定反例与重放，再接 Agent。

实施顺序为 **P0 盘点 → C1 依赖显式化 → C2 提交/恢复试点 → C3 其余流程 → P1 常驻协作 → P2 重放 → P3 固定攻击 → P4 Agent → P5 交接与清理关闭**。C1–C3 是本次新增的核心重构阶段，原 P0–P5 ID 保留。详细任务、依赖、验收和证据在[唯一任务表](../.agents/notes/proposed/testing/2026-09-16-e2ee-adversarial-lab.zh.md#实施计划与唯一任务表)。P0 先备份与冻结删除清单，旧 demo 最终删除在行为覆盖迁移后完成，不提前丢掉唯一的回归证据。

完成状态：一条命令运行确定性正常协作；攻击接口可编程操作真实服务器数据；一条命令无 LLM 重放；报告能定位首次违反属性的事件。新的 CLI 命令在 P1 确定并写入 README，不把这里的建议误称为已存在命令。

## 9. 执行记录与设计变更

设计依据：已确定的单攻击 Agent、正常程序确定性、全序调度和可重放方向。实验室使用官方 sqlite Riverrun `0.3.0` 与 pinned continuationOffset streams-crdt tarball。证据与剩余限制见实施说明；本文仍为 draft，不是数学安全证明。
