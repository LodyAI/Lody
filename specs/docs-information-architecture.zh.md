# 文档信息架构

Status: draft
Translation: current

[English](docs-information-architecture.md)

带着具体任务来到公开文档的读者——「我是新用户」「我已经在用 Codex」「我要带团队」——必须能在
不知道 Lody 功能名称的前提下找到自己的起点。文档按读者的任务和阶段组织，而不是按功能上线的先后
顺序排列。既有页面仍是内容本体；本约定只规定它们放在哪里、如何互相链接。

## 结构

`content/docs/{en,zh}` 下的顶层分组表达读者的路径：

| 分组 | 读者的问题 |
| --- | --- |
| 快速开始 | 怎样安装 Lody 并完成第一次会话？ |
| 核心概念 | 每个界面都默认我理解的对象是什么？ |
| 实战指南 | 怎样端到端完成一个真实工作流？ |
| 从其他 Agent 迁移 | 我已经在用 Codex 或 Claude Code，会有什么变化？ |
| 参考 | 某一个能力具体做什么？ |

带括号的目录名是虚拟分组：它们改变侧边栏层级，但不改变已发布 URL。中英文目录保持相同的分组名、
页面 slug 和 `meta.json` 顺序。新增或移动页面时，必须在同一次改动里更新两个语言树以及所有受影响的
`meta.json`。

描述可重复的端到端任务的页面放在 `(guides)` 下；描述单一能力的页面放在 `(reference)` 下，并按
界面分组建。概念分组只承载最小心智模型，不承载配置或功能参考。

## 页面约定

每个已发布的文档页面：

- 同时具有 `title` 和 `description`；
- 开头说明读者的目标和适用对象；
- 在步骤之前链接前置条件或起点页面；
- 结尾给出下一步，而不是断头；
- 只在确有问答时使用 `## FAQ` / `## 常见问题`，因为该区块会自动生成 FAQPage JSON-LD；
- 优先使用已注册的富文本 MDX 组件，而不是没有结构的整段文字。

## URL 稳定

页面在带括号分组之间移动、或在语言树之间移动时，不得改变已发布 URL。改 slug 属于重定向决策，而不是
编辑决策；站点没有运行时重定向层，因此改 slug 之前必须先做出明确的兼容性决定。

## 非目标

本约定不要求重写所有既有页面、补齐缺失的翻译，也不承诺各运行时功能完全对齐。文档搜索、生成的 SEO
文件或 FAQ JSON-LD 都不是目录树的事实来源。

## 实现证据

- `site-docs/content/docs/{en,zh}/meta.json` 以及各分组的 `meta.json`。
- `site-docs/components/mdx.tsx` 注册富文本 MDX 组件。
- `site-docs/scripts/site-paths.mjs` 将带括号的分组扁平化为已发布 URL。
- `site-docs/scripts/generate-llms.mjs` 按 `meta.json` 顺序生成。
