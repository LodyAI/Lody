# Lody deep links

Status: draft
Translation: current

[中文](deep-links.zh.md)

Conversation references open the exact conversation in the current Lody application. Links opened from another application go to the OS-selected default Lody installation. All versions generate the same resource format. Links identify destinations and do not grant access.

## Addresses and versions

| Purpose                     | Address                                                         |
| --------------------------- | --------------------------------------------------------------- |
| Session, all versions       | `lody://session/<sessionId>?workspace=<workspaceId>`            |
| New Stable login callback   | `ai.lody.stable://auth/callback#token=…`                        |
| Nightly login callback      | `ai.lody.nightly://auth/callback#token=…`                       |

Workspace is a stable ID resolved to the current route slug. Every new link addresses the target conversation directly by its real session ID, whether generated by copy, mention or Markdown export. Parent relationships and UI tabs are internal navigation details, not part of the public address. Earlier root+tab links remain readable for compatibility; rebuilding or exporting them produces the direct target ID without a tab parameter. Bare IDs and legacy workspace-less references resolve only in the existing invocation context without searching other installations.

`lody-oss://session/…`, `ai.lody.nightly://session/…` and `ai.lody.stable://session/…` remain targeted installation entries; new resource links always use `lody://`. Keep in-app legacy `session://<id>` reading, without registering the OS session scheme or rewriting stored history. Message copy and both UI/CLI Markdown exports normalize prose references to the common scheme, filling missing workspace identity only when the source workspace is known. Explicit foreign workspace IDs, code examples and tool payloads are preserved. Anonymous exports never infer a source workspace from the viewer. Edit-and-resend keeps the original stored text; old external links cannot reliably launch Lody.

The OS selects one default resource handler. Settings → About exposes Set as default; startup cannot replace an existing common handler. Packaged Windows registers it after readiness only when no handler exists; this repairs first launch, not dispatch before first launch. Packages advertise both common and installation-specific schemes; first-install and user-selection outcomes belong to the OS. AppImage desktop entries advertise both, setting the common default only upon explicit user selection.

Authentication bypasses resource routing. New Stable attempts explicitly select the stable channel and return to `ai.lody.stable`; Nightly retains `ai.lody.nightly`. Legacy browser callers without a channel still emit `lody` callbacks, which Stable continues accepting. Non-Stable handlers forward common legacy auth, invite, GitHub installation, checkout and machine-connect routes to Stable's private alias without exchanging credentials themselves. A missing handler, failed handoff or unknown route produces a visible, redacted error. `chat/new` and [Magpie provider import](magpie-provider-import.md) stay in the selected installation. Provider import stages a confirmation dialog; it grants no write authority. OSS retains its private `lody-oss` entry and never starts cloud authentication.

## Dispatch and access

```text
mention / copy → shared builder → lody://session/…
Markdown click → current conversation navigation
OS URL / product-window link → current installation's renderer queue
                              ↓
                      ready workspace directory
                              ↓
                      session route and tab restoration
```

Normal in-app clicks remain in the source window. Product-window navigation, new-window links and external-link IPC recognize session resources first and never relaunch the application through the OS for them. Private references on public shares remain inert; public embedded browsers gain no product-navigation authority. Other external links retain the HTTP(S) policy.

OS URLs use existing window lifecycle and preload buffering. Renderer navigation waits for the workspace directory and current workspace to be ready. Explicit destinations encode a concrete tab instead of restoring the last visited tab; after target metadata is ready, existing tab restoration handles closed tabs. A pending session restoration waits for child metadata, expires with a visible failure after 15 seconds, and is cleared when navigation is abandoned. The newest waiting resource destination wins; this is not a durable queue across main-process crashes.

An unavailable workspace never falls back to the current workspace. Show the failure and explicit actions for other registered versions. For session resources, only a user click hands off to another installation; no automatic permission bypass. OSS queries only local catalogs. Existing session pages own access control, deleted/loading/offline states and archive semantics; links do not automatically unarchive resources. Existing OS intake still uses the main window, without introducing a cross-window workspace directory.

## MCP, paste and validation

`@lody/shared/session-link` owns pure construction and parsing. MCP arguments and instructions support complete new URIs, old URIs and bare IDs; explicit workspace must match the authorization context. MCP rejects compound root+tab selectors and requests the direct child ID instead; UI producers already emit direct child IDs.

Invalid batch-status references produce per-item `SESSION_NOT_FOUND` without aborting valid siblings. New URI paste converts to a mention only within the same workspace, using the child ID of a compound root+tab link. Existing HTTPS session addresses retain trusted-origin recognition; Cmd/Ctrl+Shift+V preserves plain text. Public sharing retains its separate HTTPS workflow; copying a session link does not publish content.

Parsing is bounded to 8 KiB and known schemes, session resource, ASCII IDs and workspace/tab parameters. Reject credentials, ports, duplicate/unknown parameters, fragments, empty IDs, traversal, whitespace, backslashes and percent encoding. Preserve ID case; the restricted character set needs no percent encoding. Never execute a path/query as an arbitrary UI route or command.

## Acceptance and release boundary

Verify both formats, workspace-bearing mentions/copies, MCP cross-workspace rejection, same-workspace paste, inert anonymous shares, startup preserving the common default, and callback isolation. Source tests use deterministic events and injected state, not real sleeps.

Upgrade consumers first: shared UI, desktop intake, MCP and browser authentication callback pages. Then release new-link producers. Old MCP can read a bare session ID within its own workspace but cannot interpret the new URI; mixing new clients and old daemons has a compatibility limit. Old clients cannot read new links; release notes must explain this.

This public repository implements shared code and OSS packaging. Packaging flows reusing beforePack automatically add the common and version callback schemes; channels overriding the hook must declare equivalent protocols in their own builds. Real macOS/Windows/Linux cold/warm launch, default selection, installer upgrades and hosted authentication page deployment still require release acceptance; unit tests do not establish them.
