# Agent Role 记忆 Provider

Status: draft
Translation: current

[English](agent-role-memory.md)

## 场景与职责

用户在设置 → 记忆中选择机器，管理 Lody 保存的记忆关联。“添加记忆体”打开与
Agent Config 一致的双栏编辑器，左侧选择 Provider，右侧提供创建和导入两个 Tab。
创建会在 Provider 中登记身份并自动关联；导入页展示设备上的身份，通过 checkbox 多选
批量导入，并复制每个所选身份的名称和描述。已经关联的身份仍显示，但不能重复选择。

记忆内容由 Provider 管理。Lody 在所选机器的 Loro/Flock 文档中以
`['memory', providerId, memoryId]` 保存机器 ID、名称和可选描述。写入使用现有
workspace writer，本地持久化完成即成功，远程上传为尽力而为。稳定键保证重复关联
不会覆盖已自定义的元数据。编辑通过适配器修改 Provider 档案，并将返回的名称和描述同步到 Lody；删除仅移除关联，不删除 Provider
数据。登记成功但本地保存失败时，可以重试关联而不重复登记。不会自动导入已有身份。

卡片最左侧显示垂直居中的灰度 Provider logo，右侧显示名称及第二行描述；悬停或键盘聚焦显示编辑与
删除操作。页面右上角提供添加和刷新。只有成功取得的 Provider 列表缺少已关联身份时
才显示警告；离线、未运行和探测失败不证明身份被删除。进入页面、重新聚焦及页面可见
期间每 30 秒探测，已有请求进行中时跳过自动刷新。记忆设置页和 Role 编辑器的记忆栏在探测
期间保留已有列表，不展示 loading；探测完成后的异常仍以内联状态显示。

Role 编辑器顶部提供“配置”和“团队”两个 Tab，共享草稿及保存操作。“共享到工作区”仅放在团队 Tab。
记忆属于具体机器，因此作为配置 Tab 中每个机器 Tab 的一栏（见[多机器配置](agent-role-machine-targets.zh.md)），
复用设置页的 logo、名称与描述卡片，列出该机器的导入记录，点击卡片
即可选择关联，也可取消关联。每个机器配置的运行配置与
turn 输入仍只保存 `{ providerId, memoryId }`；添加机器时，只有该机器有相同关联才会沿用记忆体。
删除目录关联不会改写现有 Role 或已接受的 turn。Role 取消关联只影响未来的 turn，
已接受的 turn 与 Operation 保持冻结配置。记忆内容和凭证均不进入目录。

## Provider 边界

Daemon 负责检测安装与运行状态、列出和创建身份，以及将身份映射到 ACP 进程环境变量。
Provider 向界面提供名称、安装链接和支持的创建字段。调用方不能通过记忆 RPC 传入命令
或任意环境变量字典。

首个适配器为 Nowledge Mem。执行 `nmem status -j`；找不到可执行文件时，在该机器的
记忆设置页（以及 Role 记忆选择区）内显示说明文案，并提供
`https://mem.nowledge.co/en`；命令成功退出且顶层状态为 `ok` 或 `healthy` 时视为就绪，
其他状态值提示启动 Mem 后刷新。进入记忆设置
仍会自动探测当前机器。nmem 未安装或未运行不得弹出对话框。就绪后执行
`nmem agents list -j`，读取 `agentProfiles`。创建执行 `nmem agents enroll <id> -j`，
名称必填，描述、角色和默认 Space 可选，表单复用现有设置编辑对话框。Enrollment
只创建新身份，已有 ID 保持原档案，最终以 Provider 返回的列表为准。

设置页复用 Agents 的机器选择：桌面窗格在可见机器多于一台时使用 line tabs，窗格外
使用 pills，纯本地平台不显示远程机器选择。已保存的关联使用与 Agents 一致的目录卡片。
Role 编辑器的记忆栏复用关联卡片、状态文案与安装链接。离线机器以及未声明 `memoryProviders` v1 的
daemon 不会收到记忆 RPC。请求沿用现有本地/远程机器路由，本地失败不回退到远程传输。

## 执行

选择 Role 时将记忆引用冻结到用户 turn 和已接受的创建 Operation。预热匹配也包含此引用。
ACP 启动在环境组装完成后解析适配器，Nowledge Mem 注入 `NMEM_AGENT_ID=<memoryId>`。
在 turn 之间切换身份时，沿用恢复路径重建 ACP 进程，因为运行中进程的环境不能修改。
Fork 和恢复读取冻结的历史配置，不重新查询可变 Role。未知 Provider 明确失败。
其他 Provider、自动安装或配置 Agent 端 Mem 插件不在本次范围内。

记忆编辑器在整个窗口居中，桌面尺寸为紧凑的 900 × 600 px，并限制在 96dvw × 92dvh 内。
创建表单要求名称非空，并将名称和 Agent ID 按顺序放在同一行，未手动修改 ID 时随名称转为全小写。
Space 暂时隐藏，默认不传值；Nowledge 登记固定传 source-app 为 lody.ai。
关联列表始终只显示名称和描述，选中后不展开详情，也不再请求额外的 Provider 档案字段。

Provider 侧栏使用与 Agent Config 一致的平面选中列表行，只有一个 Provider 时也相同。
设置中保存关联记录的文案为“导入”，Role 绑定记忆体仍称“关联”。

机器 Tab 显示在线状态圆点，默认选中本机。Nowledge 编辑表单与创建一致，ID 只读，
名称、描述和角色可编辑，通过 nmem agents set 修改。清空可编辑字段会显式传递空值，
隐藏的 Space 与来源字段保持不变。Provider 修改失败时不保存本地元数据。

可访问的 Role 目录加载完成后，没有被其中任何 Role 关联的记忆体会在编辑和删除前显示
“去关联角色”。入口打开完整角色页，定位到第一个在该机器上运行的角色并以该机器 Tab 打开编辑，
新建角色预选该机器，不自动修改 Role 或选择记忆体。角色页不提供机器 Tab 或机器筛选，校验使用完整可访问角色目录。

已关联的记忆体显示“已关联：”及可访问的关联角色 emoji 头像。桌面悬停或聚焦显示
角色名称，移动端点击显示名称浮层。关联按 Role 任一机器配置的机器、Provider 和记忆 ID 精确匹配，并随
角色目录更新。

## 内置记忆提案（Lody Memory）

### 需求与范围

用户创建具名记忆体并关联 Role，让 Agent 通过 Lody 工具在不同 turn 和设备上读取、更新记忆。
优先保障 Agent 工具更新可靠；兼容所有外部编辑器的保存方式不是这条工具路径的前置条件。
Lody Memory 属于个人或工作区，位于机器标签页之上。上面的外部 Provider 仍归入“集成 Provider”，保留机器作用域行为。

已确定的需求：

- 在 Lody 托管的 Drive9 中保存 Markdown 文件。Loro 版未发布，不迁移数据、不做向后兼容。
- 支持私有与共享记忆，创建后可修改可见性。私有记忆仅所有者通过 daemon 访问，绝不挂载；共享记忆对所有工作区成员开放读写。
- 接受仅在线使用、托管明文存储和记忆不做 E2EE。仅本地运行的 OSS 桌面版没有 Lody Memory。
- 优先保障 Agent 工具可靠读写。并发冲突必须明确返回，不得盲目覆盖较新版本。
- 提供当前记忆内容的溯源能力。不要求恢复旧版本、撤销或完整历史审计。
- 正常凭据续期不能打断挂载、使已打开句柄失效或丢失进行中的写入。不能用卸载重挂实现续期；明确撤销权限仍必须阻止后续访问。

共享挂载仍是目标，但是否必须与首个可用的 Agent 工具版本同时交付，尚待决定。
跨设备实时刷新目前建议延后，尚未作为已批准的需求取舍。

### 当前方案

每个工作区对应一个 Drive9 tenant；每个记忆体占用 `/memories/<memoryId>/` 目录。
相对路径即文档身份。`MEMORY.md` 的 front matter 保存名称与描述，并作为入口文档；其他 Markdown 文件保存主题内容。
可见性存为目录元数据，切换时不移动文件。改名不得静默覆盖已存在的目标。

Role 绑定 `{providerId: "lody", memoryId}`，多个 Role 可以共用一个记忆体。
绑定在每个 turn 中冻结，模型输入不能选择其他记忆体或提供凭据。冻结绑定不保留已经撤销的权限。
取消 Role 关联影响未来 turn，不删除内容；删除记忆体会删除文件。已披露的对话上下文无法抹除。

```text
Lody 客户端（桌面 / Web / 移动端）
              | daemon RPC
              v
Daemon：turn 绑定工具、提示上下文、MemoryBackend
              | 限定记忆目录的文件系统 token
              v
Drive9：/memories/<memoryId>/ 下的 Markdown 文件

Lody 托管服务：身份、成员关系、可见性、限定范围 token 签发
共享挂载：额外访问路径；必须支持不中断的凭据续期
```

Daemon 持有 Drive9 SDK，经现有记忆工具和 RPC 边界提供读取、搜索与更新。
修改前取得当前 revision，再提交条件写入；发生冲突时返回 Agent，由其重新读取并明确处理冲突。
读取和搜索限制在所绑定记忆的路径前缀内。通过 `MemoryBackend` 隔离存储与现有调用方；
涉及历史的接口须调整，不能假装 Drive9 支持旧的恢复合同。兼容 daemon 声明 `builtinMemory: 2`。

托管服务保管 tenant owner key，校验身份与当前访问权，签发限制记忆路径的短期文件系统 token。
公共代码经 `packages/platform` 端口和 `packages/cloud-api` DTO 访问服务。Owner key 不下发到设备。
文件系统 token 使用 `DRIVE9_API_KEY`，不是 `DRIVE9_VAULT_TOKEN`；不得持久化到 CLI 配置或挂载状态。
Token 可以存在 daemon 和挂载进程的内存中。

共享挂载目标路径为 `~/Lody/Memory/<name>`。挂载不受 Role 授权约束，同一用户运行的其他程序也能访问。
私有改为共享时为成员授权；共享改为私有时撤销成员 token，并在在线设备上卸载。
已披露或缓存的副本不能收回，界面须在确认前说明。这种主动撤权与正常续期不同。

首版建议在打开或使用记忆时读取当前内容，工具更新成功后刷新本地视图。
其他设备在下次读取或主动刷新时取得最新内容，不承诺即时通知。这样不依赖 SSE：
测试版本的文件系统 token 不能订阅事件，owner SSE 则覆盖整个 tenant。
只有要求实时刷新时才需要限定范围的中继或上游事件权限扩展；当前首版方案不选择其中任何一种。

### 当前内容的溯源

首版建议以文件当前 revision 为溯源单位，不按每句话或每个事实记录。
Lody Agent 更新关联记忆 ID、路径、revision（或内容哈希）、用户 ID、机器 ID、会话 ID、turn ID、
工具调用／变更 ID，以及服务端确认时间。身份来自认证上下文，调用方自填的 actor 标签不构成身份证明。
会话链接仍受会话访问控制约束，不得向共享记忆读者泄露私有对话内容。

来源记录必须匹配展示的内容，不得用旧记录把新内容归属给上一位写入者。
先修改文件、再单独追加来源记录可能在中间失败；实现设计必须明确幂等对账、重试行为和不完整结果。
只有内容保存成功时，不得报告内容与来源均已完成。记录存储与提交机制仍待技术设计，不能假定 journal 具备原子性；
文件系统 token 本身也不能追加 Drive9 journal。

外部程序经挂载修改时，Lody 无法推断 Agent 会话或 turn。建议在能认证时显示用户／设备，
否则把当前版本标为外部／未知来源；是否接受这一回退需要确认。
外部修改发生后，下次读取当前内容时必须使旧的 Agent 归属失效。
仅为提供当前版本溯源，不必保存旧文档正文。

### 实施计划与验收

| 阶段 | 交付内容 | 验收边界 |
| --- | --- | --- |
| 1. 合同设计 | 明确下方范围问题，定义 backend DTO、当前版本来源状态、访问校验和凭据生命周期。 | 不分发 owner key，不隐含承诺历史恢复，明确写入不完整与冲突结果。 |
| 2. Agent 工具路径 | 实现托管凭据端口与 Drive9 backend 的创建、列举、读取、搜索、更新、改名、删除；接通 Role 绑定工具和客户端 RPC。 | Agent 更新可在后续读取中看到；拒绝同级记忆越权；旧 revision 冲突；撤权后拒绝访问。 |
| 3. 溯源与界面 | 实现当前内容来源记录及对账，提供记忆管理、可见性和来源查看。 | 展示来源与当前内容匹配；来源写入中断不会产生旧归属或虚假成功；私有会话受到保护。 |
| 4. 共享挂载 | 打包管理 Drive9，实现不卸载的凭据热更新；单独调查外部编辑器原子替换。 | 正常续期保留挂载、已打开句柄和进行中操作；撤权阻止新服务端访问；凭据不进入持久化状态。 |
| 5. 发布验证 | 验证支持的平台、私有／共享切换、多设备读取、工具冲突与托管限制。 | 所选发布范围通过行为验证；明确配额与失败行为；不宣称离线、历史恢复或通用编辑器兼容。 |

阶段 2、3 可以在挂载兼容性完成前开发。是否可在阶段 4 之前发布，取决于下方发布范围决定；
续期不完整的挂载不能被描述为已支持。托管价格、配额及开通行为仍须调查，不能从本地 TiDB 测量推定。

### 需要产品决定的问题

1. 首版是否可以先交付 Agent 工具，共享挂载后续补齐，还是首版必须同时包含两者？工具优先不自动确定挂载交付时间。
2. 溯源是每个当前 Markdown 文件最后一次更新的来源及对应会话／turn，还是每条事实／段落的来源？后者需要更细的内容与来源关联，不属于当前建议方案。
3. 对外部挂载修改，无法认证用户／设备时，是否接受显示外部／未知来源？

除非评审时调整，当前建议延后实时 SSE 刷新、可恢复历史、只读成员角色和用户自带 Drive9 端点。
其中只有“不要求历史恢复”已经确定，其他延后项仍是建议的范围取舍。

### 证据与实现状态

P1 已验证限定范围文件访问、基本中英文搜索、条件写入冲突、撤权后新请求拒绝以及 macOS 基本挂载读写。
挂载上原子替换已有文件返回 `EINVAL`，具体失败层尚未定位。挂载客户端保留最初的凭据；
限定范围 SSE／journal 不可用；journal 本身不能恢复旧文件内容。这些是验证发现，不代表 Lody 已完成集成。
