# 桌面多窗口

Status: draft
Translation: current

[English](desktop-windows.md) | 中文

用户可并排查看对话和工作区，打开新窗口不改变来源窗口。

| 操作                                           | 结果           |
| ---------------------------------------------- | -------------- |
| 普通点击 Session 或切换工作区                  | 当前窗口导航   |
| macOS Command 点击、其他桌面 Control 点击      | 新窗口打开目标 |
| Session 更多或右键菜单中的“在新窗口中打开对话” | 新窗口打开对话 |

本版不支持拖出开窗；Session 拖拽仅保留原有提及交互。

工作区选择器底部展示 Command/Ctrl 点击开窗提示；右键工作区提供“在新窗口中打开”，
打开右键菜单不切换当前工作区。
侧栏会话菜单依次为：展开/收起子会话、置顶、标记未读、重命名；复制链接、复制分支、分享；
打开 PR、前往来源会话、在新窗口中打开；归档。
分组之间用分隔线，不显示组标题或空组；不可用操作按现有条件隐藏。
新窗口操作放在倒数第二项，归档最后且使用普通文字样式。

对话窗口首帧收起左侧栏，打开指定对话并一次性聚焦输入框；仍可展开侧栏。
工作区窗口使用完整导航。各窗口的导航、草稿标签和面板状态独立。

开发者选项中的窗口预热只准备应用外壳，不准备目标会话数据。
中性遮罩等待目标会话加载并同步、工作区首页挂载，或目标会话的元数据投影处理完毕后确认会话不存在。
无关文档的元数据失败不得阻止该判定。
Loading 文案和侧栏内容不能作为就绪信号。遮罩最长保留五秒，之后露出慢加载、离线或错误
状态的恢复界面；该兜底不代表加载完成，也不保证瞬间打开。
领取后的窗口遵循普通产品窗口的生命周期，其他窗口关闭时仍保持打开。崩溃恢复须重载
绑定目标，不得回到中性预热路由；关闭已领取窗口不得取消替补窗口的超时。

Composer 草稿归属工作区并持久化：不同工作区必须隔离，工作区窗口之间不按打开来源区分主辅。
同一工作区内的所有 Chat Landing 入口复用同一份 Composer 草稿；“新建对话”只切换目标项目，
不得清空或覆盖已有输入。只有首条消息成功写入 Session 后才清空这份草稿。
关闭其他工作区窗口不停止 CLI 或 Agent；关闭菜单和快捷键操作当前窗口。
Cmd/Ctrl+W 在对话区有多个标签时关闭当前标签，只剩一个标签（包括草稿）时关闭当前窗口，
不更改会话的共享关闭状态。侧面板有焦点时优先关闭其当前标签；显式点击标签 × 仍关闭标签。
主窗口和新开的会话窗口遵循相同规则，保留各窗口已有的原生关闭/隐藏行为。
应用内快捷键配置按设备共享，任一窗口修改后对所有已打开窗口生效；快捷键执行仍只作用于接收按键的窗口。
原始窗口保留已有的关闭/托盘行为；不自动恢复其他工作区窗口。

隐藏侧栏卸载其内容并暂停会话预取；当前对话和 Tasks 页所需数据继续同步。
同一工作区只有一个窗口执行通知、角标和后台状态检查，退出后自动交接。
清缓存和登出属于应用级操作，会关闭其他窗口以释放连接。

工作区开窗使用现有平台提供的目录；公开桌面端仍是单一本地工作区。
共享 UI 的多工作区入口不得通过全局账户选择改变其他窗口的目标。

需求：[Issue #526](https://github.com/LodyAI/Lody/issues/526)。
