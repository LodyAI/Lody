# 会话自动化事件

Status: draft
Translation: current

[English](session-automation-events.md)

## 场景

Agent 结束当前回合时，工作的一部分仍然依赖外部世界：CI 还没有回报、部署尚未
就绪、委派的会话还在运行、长命令还没有退出。用户期望的是：他们关心的状态一
变化，对话就在那一刻继续，而不是按定时器醒来。

因为每条等待只完成一次，需要“持续检查”的 agent 今天只能每次醒来后重新注册
一条新等待。真实使用中，这种链式模式单个任务重注册几十次，账本堆满失效的
一次性记录；繁忙会话被灌入一排排排队续航，等轮到执行时其中的指令早已过期；
当唤醒文本驱动跨会话协调时，还会产生无人值守的消息风暴——而因果深度上限对
此完全失明，因为经由账本投递的输入根本不携带深度。

## 决策

**Automation 感知状态跃迁；时间只用于调度观察。** 等待存在的意义是侦测
Host 事先无法预知的变化：外部状态翻转，或托管进程退出。时钟永远不是事件。
用户想让 agent 每 N 分钟醒一次、或在某个时间点醒一次，使用 Schedule——它
保留人类确认与暂停控制。Lody 不通过 automation 注册提供周期或延时唤醒，
agent 指引也必须把周期与延时请求导流到 Schedule。

**没有观察就不会产生唤醒。** 一次求值如果没有通过 `ctx.read`、`ctx.fetch`
或 `ctx.exec` 执行任何观察就返回结果，则该结果无效：它只可能是时钟比较或
常量，两者都不是信息。该等待在这次求值失败，而不是完成。观察后回答 `false`
的求值完全不消耗 agent 唤醒，因此轮询观察留在 Host 侧。

这是一道误用护栏，而非授权证明：程序可以在观察后不依赖观察结果。这个原语
的诚实定义是 Host 轮询的单次谓词等待；把时间触发的工作导流到 Schedule 是
一条产品策略，由指引与因果预算执行，而不是由对程序意图的静态或动态分析
执行。

**等待是单次槽位，按名取代。** 每次注册属于一个槽位：它的 `key`，或未命名
的默认槽。向槽位注册新等待时，原子地取代该槽位上未完成的旧等待，并通过
Session 输入属主撤回其尚未开始执行的续航输入。并行观察需要通过不同 key
显式选择。精确匹配去重仅保留为重试捷径。因此取消槽位里的
当前等待即终结其整条血缘；改口或重新注册是替换，而不是翻倍。未带 key 的
注册共享同一个默认槽是一条刻意的行为契约：会话保留一条未命名观察，真正
独立的并行等待必须显式命名。

**注册冻结因果源头，且预算被强制。** 注册记录产生它的机器成因输入：有
provenance 时用精确的调用回合，否则用请求会话的在途回合，再否则是深度为零
的人类或外部根。续航输入无论来自条件等待还是托管运行，都在该冻结深度上
恰好加一，目标会话的历史永远不会重置它——时序不是因果。恢复未完成的工作
是续作而非新意图：其续航保留原始输入的深度，不消耗跳数。处于
[会话编排](session-orchestration.zh.md)因果上限的回合不能注册新的机器成因
工作；冻结深度会越限的续航以持久失败终结，而非永久阻塞。于是同一份预算
同时覆盖：会话经由账本自转、会话互相 steer、以及在两者之间交替的混合回路。

**续航输入自报家门。** 投递的输入以事实开头——来源等待、其理由与注册时间——
作为参考数据，使 agent 能区分自动化唤醒与人类消息；过期的续航无法伪装成
新指令。前缀只携带事实，不指挥 agent 的工作。

**账本退役已终结之物。** 收据在其投递的输入完结时即告结清，不论会话组里
其他工作是否仍在运行；委派结果有自己的回报机制。取消、过期、失败与被取代
都会关闭该注册的内部 rule。归档或删除会话会取消其未完成的等待。终态等待
——包括续航已结清的正常完成等待——连同其一次性 rule 在终态结算后的保留期
过后清理；收据作为可检视历史保留。检视默认只呈现活跃行。

**取代不是取消。** 槽位替换只在续航输入尚未开始执行时撤回它；已在运行的
回合属于会话属主，自行完成。观察的所有权在执行的所有权开始之处结束。

## 保证

- 时间触发的工作一律经过人类确认的 Schedule 面。注册不接受周期、延时或
  纯时钟条件，自动化层不存在任何为已完成等待重新装填的机制。
- 一个槽位最多容纳一条未完成等待。用户改口不会让上一个观察者并行残留；
  取消可见的等待即取消其背后的整条血缘。
- 每个机器成因输入推进同一份共享因果预算，无论由何种介质投递；只有人类
  成因的工作从预算根部重新开始。该上限在注册与续航准入两侧都被强制，
  因此经由账本与消息通道任意组合的无人值守回路，都会在同一固定跳数内
  撞上 `CHAIN_DEPTH_EXCEEDED`，且该拒绝是持久失败而非反复重试的阻塞。
- 等待已被取代或取消、且其输入尚未开始执行的续航，永远不会到达会话；
  已在执行的不被撤销。
- 单个会话的活跃等待、rule 与可见注释数量，以活跃槽位加保留期为界；
  收据与事件作为可检视审计历史保留，每条实际投递的续航恰有一条，而非
  依时钟过期。
- 账本隐私、冻结授权、准入复查、Stop 语义与匹配即终局契约均不改变。

## 未决问题

- 终态行的保留窗口（建议 48 小时）是待评审的起始值。
- `lody_schedule` 的 `existing_session` 要求显式 `sessionId`；一个
  `current` 简写会消除最后一处摩擦——当用户要求在当前对话里周期检查时，
  正是这处摩擦把 agent 推向账本定时器。这属于 Schedule 面的变更，与本
  Spec 可分。
- 由自动化驱动的回合发起的跨会话 chat，对繁忙目标应排队而非 steer，是
  `lody_session_chat` 的通用语义问题，与 automation 无关，本 Spec 刻意
  不作回答。
