# 本地 GitHub PR 观测

Status: draft
Translation: current

[English](local-github-pr-observation.md)

带有 GitHub 远端的本地 Git 项目可以使用所属机器上的凭据显示对话的 PR 和 CI
摘要，无需 Lody 云端账户、GitHub App 安装或产品云端仓库登记。远端只标识仓库，
成功的 GitHub 查询才证明读取权限。没有 GitHub 远端的目录仍支持本地分支展示。

## 职责

创建时记录共享 Git 远端解析器识别出的仓库。激活或显式刷新已有本地工作目录时，
先观测运行时分支，再补齐缺失的仓库标识；不替换已记录的仓库，也不改变本地项目身份。

机器上的现有 PR 协调器统一负责发现、状态、CI 摘要、配额、重试和轮询频率。
可用时优先使用托管凭据，否则使用本地 `gh` 对 github.com 的认证。凭据留在机器上。
缺少凭据时可重试，凭据变更无需重启。无法查询 `/user` 不等于没有 PR 读取权限；
无法识别身份的凭据共享保守的配额桶。

本地及托管工作区都把经 GitHub 验证的精确分支 PR 观测写入所属会话元数据。
托管 webhook 关联是独立效果：拒绝或传输失败不得隐藏已验证的 PR，也不得让
Create PR 继续可用。关联重试遵循既有轮询门控；只有关联及发布均成功才记录
发现成功时间。托管客户端还会按工作区与仓库对跨调用方的关联失败请求冷却：
权限拒绝等待 15 分钟，临时故障从 1 分钟退避至最多 15 分钟。该门控不阻止
GitHub 观测及发布，也不把跳过的关联当作成功。后续满足条件的新调用重新验证权限，
不通过定时器重放旧请求。冷却是有界的运行时状态，客户端重建后重置。
发布终态 PR 后，旧发现指纹不得阻止关联重试。关联成功仅在当前
工作区运行时记忆；重启后，仍有资格发现的 PR 可以幂等地重新关联。
缺少认证、仓库不可访问或查询失败，不得虚构 PR 或删除既有成功观测。
登录和权限变更在后续满足冷却条件的轮询中生效。

桌面端对本地与托管项目读取相同的元数据。没有托管 GitHub 集成时，PR 链接在浏览器
打开 GitHub；本地摘要读取不会启用详细检查、审查和修改 API。托管详情读取失败——
包括仓库身份未确认——时，已记录的 PR 保持为带 GitHub 链接的可恢复呈现，而不是
一次裸失败；详情恢复前不提供修改入口。分支观测由事件触发，
PR 发现与状态使用有界后台轮询，不为每个视图增加轮询循环。本地模式仍禁止产品云端请求。

仓库关联未确认或服务端返回 `repo_not_linked` 时，PR 与评论界面展示本地化的修复指引，
提供当前工作区的 GitHub 设置入口，并说明管理员应检查 App 安装与仓库访问范围。
已有缓存不得遮住该提示或保留修改入口；恢复后重新显示详情。修复操作不绕过身份校验
或关联冷却，也不新增轮询、toast 或同步元数据。关联拒绝仍是 HTTP 非成功结果，
以兼容仅检查 HTTP 状态的客户端；预期的配置缺失无需成为服务端执行异常。
