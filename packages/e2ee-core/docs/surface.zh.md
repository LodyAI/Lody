# 公开接口

[English](surface.md) · [导读](../README.zh.md)

按用途分组列出每个公开入口的全部导出。每个导出、命名空间内的导出与 service 成员都有 JSDoc（由 `pnpm --filter @lody/e2ee-core check:docs` 与 `test/public-docs.test.ts` 保证）。检查器只检查注释存在性；所有权、失败与重试语义是否说明充分仍需人工检查。用 `pnpm --filter @lody/e2ee-core exec tsx scripts/check-public-docs.ts --list` 打印当前的精确列表。

`@lody/e2ee-core/internal` 不是公开接口：它为本仓库测试与 Lab 重新导出内部实现，不做任何兼容性承诺。

## `@lody/e2ee-core/adapters/loro-streams`

`streamsLedgerLog`, `makeStreamsLedgerLog`, `StreamsLedgerLogOptions`,
`LedgerSubmissionStream`, `streamsLedgerFeedSource`, `makeLedgerStreamReader`,
`LedgerStreamReader`, `streamsDocumentBinding`, `StreamsDocumentBindingOptions`,
`makeStreamsUpdateBinding`, `makeRealtimeContentBinding`.

文档 binding 也提供 `openAuthenticated(input)`：与 SDK open 方法 相同的签名、上下文和 AEAD
检查后返回 `{ plaintext, author }`。`author.device`、`author.actor` 和
`author.memberInstance` 来自已验证的历史账本身份；调用方拥有并清理明文。这只证明
历史归属，不授予当前权限或执行新鲜度；快照签名者也不是其中每条 turn 的原作者。
SDK 的 SDK open 方法 仍只返回明文字节。

## `@lody/e2ee-core/cloudflare`

`ed25519WasmActive`。在 Cloudflare Worker 中导入一次该入口即可：workerd 禁止在运行时从字节编译 WebAssembly，因此改由打包器编译包内的严格 Ed25519 模块。不导入时，core 仍会用纯 JS 正确验证，只是更慢。`@lody/e2ee-core/protocol` 也导出 `ed25519WasmActive`（同一个状态），供无法打包本入口的宿主（如 Convex）上报当前是否使用 WebAssembly；首次调用时可能会实例化内嵌模块，与第一次验签的行为相同（失败则回退到纯 JS）；它不会替换或关闭任何验证后端。

## `@lody/e2ee-core/adapters/node-custody`

`KekWrapper`、`NodeE2eeCustodyError`、`PreparedNodeE2eeDevice`、`NodeE2eeDevice`、
`makeNodeE2eeCustody`、`NodeE2eeCustody`、`nodeE2eePorts`。

仅 Node 可用，由显式 Scope 持有。宿主负责核对 KEK 包装器的实际保护能力；
文件保护只能创建机器身份，个人身份必须使用系统安全存储。

`NodeE2eeCustody.prepareDeviceCredential(genesis, signingPublicKey)` 一次性持久保存独立的 32 字节设备访问凭证，返回小写 hex 凭证及原字节的 SHA-256。`NodeE2eeCustody.deviceCredential` 只重开已有原件，缺失或损坏时不重新生成。凭证用独立用途域、genesis 与设备公钥绑定后由现有 KEK 保护，不改变设备文件和 epoch 密钥格式。它只用于服务端访问，不是内容密钥。

凭证位置同时包含 genesis 和签名公钥。以前仅包含 genesis 的位置只读：只有用途域、
genesis、公钥 AAD 完全匹配的当前 v1 原件才能重开。属于其他公钥的真实凭证原样保留；
显式准备为新公钥保存独立原件。损坏数据、不安全权限和未知格式仍拒绝。
这只改变本地文件名，不转换原件、不迁移、不导入旧格式。

保管错误区分 "permissions"（修复仅所有者权限后重试）、"identity-lost"（原件或 KEK
缺失）、"corrupt" 和系统保护不可用。其他原件仍在时，缺失 KEK 不会生成替代品。
宿主显式恢复须先关闭并整体归档旧身份，再打开独立保管；普通重试不授予替换权限。

`NodeE2eeCustody.forgetDevice(genesis, signingPublicKey, kind)` 仅供宿主确认整成员移除、等待工作区使用者结束后调用。它只删除匹配的设备/凭据，避开不同身份并保留共用 KEK；epoch/内容存储删除和跨进程互斥由宿主负责。
