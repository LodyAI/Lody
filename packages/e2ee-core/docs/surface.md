# Public surface

[中文](surface.zh.md) · [Reading guide](../README.md)

Every export of every public entry, grouped by purpose. Each export, namespace export and service member has JSDoc
(enforced by `pnpm --filter @lody/e2ee-core check:docs` and
`test/public-docs.test.ts`). This checks comment presence, not whether an
explanation is sufficient; reviewers must still check ownership, failures and
retry semantics. Print the exact current list with
`pnpm --filter @lody/e2ee-core exec tsx scripts/check-public-docs.ts --list`.

`@lody/e2ee-core/internal` is not public: it re-exports internals for this
repository's tests and the Lab, with no compatibility promise.

## `@lody/e2ee-core/adapters/loro-streams`

`streamsLedgerLog`, `makeStreamsLedgerLog`, `StreamsLedgerLogOptions`,
`LedgerSubmissionStream`, `streamsLedgerFeedSource`, `makeLedgerStreamReader`,
`LedgerStreamReader`, `streamsDocumentBinding`, `StreamsDocumentBindingOptions`,
`makeStreamsUpdateBinding`, `makeRealtimeContentBinding`.

The returned document binding also exposes `openAuthenticated(input)`: the same
signature/context/AEAD checks as the SDK open method, returning `{ plaintext, author }`, where
`author.device`, `author.actor` and `author.memberInstance` come from the verified
historical ledger identity. The caller owns and clears plaintext. This result
establishes historical attribution only, never current permission or execution
freshness; a snapshot signer does not identify the origin of every embedded turn.
The SDK-facing the SDK open method continues to return only plaintext.

## `@lody/e2ee-core/cloudflare`

`ed25519WasmActive`. Import this entry once in a Cloudflare Worker: workerd forbids compiling WebAssembly from bytes at runtime, so the bundler compiles the packaged strict Ed25519 module instead. Without it core still verifies correctly in pure JS, only slower. `@lody/e2ee-core/protocol` exports the same `ed25519WasmActive` so hosts that cannot bundle this entry (such as Convex) can report whether WebAssembly is in use; it may instantiate the embedded module on first use, exactly as the first verification would (falling back to pure JS on failure), and never replaces or disables a verification backend.

## `@lody/e2ee-core/adapters/node-custody`

`KekWrapper`, `NodeE2eeCustodyError`, `PreparedNodeE2eeDevice`, `NodeE2eeDevice`,
`makeNodeE2eeCustody`, `NodeE2eeCustody`, `nodeE2eePorts`.

Node-only custody with an explicit owning Scope. The host qualifies its KEK wrapper;
file protection admits machine identities only. Personal identities require OS protection.

`NodeE2eeCustody.prepareDeviceCredential(genesis, signingPublicKey)` publishes an independent 32-byte device access credential once and returns its lowercase hex value plus SHA-256 of the raw bytes. `NodeE2eeCustody.deviceCredential` only reopens it; missing or corrupt originals never regenerate. Credential blobs use a distinct KEK-protected purpose bound to genesis and public key, without changing device or epoch formats. These are access credentials, never content keys.

Credential locations include both genesis and the signing public key. The former
genesis-only location is read-only: the same current v1 blob reopens only with exact
purpose/genesis/key AAD. A genuine credential for another key remains untouched;
explicit preparation publishes a separate original for the new key. Corrupt data,
unsafe permissions and unknown formats still fail closed. This changes the local
filename only, with no blob conversion, migration or older-format import.

Custody errors distinguish "permissions" (repair owner-only access and retry),
"identity-lost" (missing originals/KEK), "corrupt" and unavailable OS protection.
A missing KEK with surviving originals never creates a replacement. Explicit host
recovery closes and archives the complete identity before opening independent
custody; ordinary retry grants no replacement authority.

`NodeE2eeCustody.forgetDevice(genesis, signingPublicKey, kind)` is reserved for host-authenticated terminal member removal after workspace users drain. It removes only the matching retained device/credential, spares a different identity and keeps shared KEK custody. The host owns epoch/content-store deletion and cross-process exclusion.
