# 主屏幕小组件空快照的恢复

Status: implemented
Translation: current

[English](2026-10-31-widget-cache-recovery.md)

## 摘要

元数据加载可能清空主屏幕小组件快照，并阻止独立的 Token 查询。原生写入被拒绝后
也需要等待新输入才能恢复。发布者现已区分 runtime 身份与元数据就绪状态，并自动
重试失败的原生写入。

## 决策

- 会话和额度读取要求元数据属于完全一致且已就绪的 runtime。加载期间，`pendingScope`
  保留解码有效且用户、工作区 ID 一致的快照，保持原时间戳；无效或归属不同的数据会被
  清除。Token 查询使用已认证 runtime 身份，保留已有的认证会话与查询结果校验。
- 缺少 runtime 身份时清理缓存，包括冷启动早期。确认退出后仍锁定当前页面的发布。
  快照过期时间保持 15 分钟（Token 用量从源统计窗口结束时计算新鲜度）。
- 写入被拒绝后分别在 1、5、30 秒重试，每次读取当前发布状态。输入变化或回到前台可
  重新开启恢复预算。拒绝也会使去重基线失效，因为原生存储可能已改变，只是确认响应
  失败。写入保持串行；释放时等待原生调用及有界的最终清理恢复结束。
- 原生桥接失败输出固定错误码。明确清理即使发现缓存键已缺失，也会请求重载时间线，
  因为先前已呈现的条目可能仍在显示。

## 验证

移动端通过 82 项 JavaScript 测试，其中包含 31 项小组件行为测试；Foundation 测试
覆盖缓存归属、保留字节不变和过期边界。确认响应丢失后的清理、无新输入时自动恢复，
在原同步器上失败、修复后通过。受影响范围检查和仓库格式化通过。使用修改后的原生
源码及已有生成 WebView 资源，iOS 模拟器 App 与扩展构建通过。

完整移动端 TypeScript 检查与未修改基线的依赖/API 诊断一致。新 WebView 构建因借用
依赖图缺少 `@lody/platform/telemetry` 导出而受阻。发布签名实机的呈现和最初设备症状
仍需验收；重绘调度由 WidgetKit 控制。原生持续失败或调用始终未结束时，清理可能无法
完成。
