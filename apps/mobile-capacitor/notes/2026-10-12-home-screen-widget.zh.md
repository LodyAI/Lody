# iPhone 主屏幕小组件

状态：已在本地实现并通过模拟器构建与行为检查；发布签名及已登录实机验证待完成。

小号小组件展示一条重点会话，中号展示最多三条，包含标题、Agent、状态和最近活动
时间。复用现有 WidgetKit 扩展和 App Group，不新增 Apple 标识符、能力或云端接口。
点击沿用默认的打开应用行为，保留现有 OAuth 和网站链接路由策略。

## 信息与外观

最初只显示数量的概览丢掉了[实时活动卡片](../ios/App/LodyLiveActivityWidget/LodyLiveActivityWidget.swift)
中有用的会话信息。按用户反馈，本地实现改为会话进展。复用现有实时活动选择器，
保留所有权、归档和未读语义；待回应会话优先，其次为运行中和有新回复的会话。
持久化的 `awaitingUserSince` 让机器离线后的未回答请求仍然可见。现有元数据无法区分
审批与提问，所以统一显示“等你回应”；未读显示“有新回复”，不据此声称任务完成。

通过 [LodyWidgetAppearance.swift](../ios/App/LodyLiveActivityWidget/LodyWidgetAppearance.swift)
复用原生实时活动的品牌标识、Agent 图标和蓝/橙/绿状态色。已有会话信息卡与统计分享
卡在 Storybook 中实际渲染作为参照；轻微蓝绿色底色参考
[统计分享卡片](../../../packages/components/src/components/settings/usage-share-card.tsx)。
未同步、已就绪但暂无动态、数据过期分别显示可读状态。iOS 着色模式保留系统前景/背景
控制权。WidgetKit 根视图把尺寸和绘制模式交给纯展示层，视觉样例渲染生产视图，不写缓存。

## 归属与本地数据

- `src/home-widget.ts` 订阅现有 Jotai 状态，需要已登录用户、路由选择的工作区，
  以及归属一致且就绪的 runtime/meta，含 `runtime.accountId === user.id`。
  共享本地认证清除信号锁定当前页面的发布。读取新鲜会话 presence 和现有 Agent 配置名，
  不打开会话文档，不发起网络请求。
- `src/home-widget-core.ts` 明确投影最多三条会话的 ID、标题（限 96 字符）、状态、
  Agent 标识/名称和活动时间，不复制权限命令/请求 ID、消息、提示词及凭据字段；
  不检查允许展示的文本中是否嵌入敏感内容。用固定
  起点的 250ms 窗口限制扫描，串行写入原生缓存，只保留最新待写状态。归属失效
  立即清理；失败仍可重试，相同内容至多每五分钟或回到前台时续新。
- `LodyHomeWidgetPlugin.swift` 解码类型化元数据，`LodyHomeWidgetStore.swift` 校验
  并在 `group.ai.lody.mobile.onesignal` 中保存第 2 版快照。拒绝损坏、重复、未知版本、
  未来时间、条目过多或已设边界校验失败的快照。保存/清理时移除先前本地的计数快照，
  保留其他设置。
- `LodyHomeScreenWidget.swift` 读取本地时间线，安排在 15 分钟过期时隐藏会话细节的条目。
  条目的实际显示由 iOS 调度；这是缓存概览，不承诺应用挂起后连续监控。不增加桌面权限审批
  操作，也不扩展深链接路由。
- 按 [Apple 的 API 使用理由文档](https://developer.apple.com/documentation/bundleresources/app-privacy-configuration/nsprivacyaccessedapitypes/nsprivacyaccessedapitypereasons)，
  应用和扩展的隐私清单声明同 App Group 存储的 UserDefaults 使用理由 `1C8F.1`。

标题属于设备本地展示元数据，与已有实时活动卡一致。现行 [E2EE 规范](../../../specs/e2ee/README.md)
不要求为本地正文/缓存增加应用层加密。本功能不新增远端发布或密钥存储。

## Token 用量小组件

`src/token-usage-widget.tsx` 在私有移动端组合中，为已有认证路由增加仅 iOS 使用的
后台叶子组件。通过 `usageAnalytics`、受保护的 `usage:getWorkspaceUsageTimeline`
描述符和共享认证/查询恢复读取数据，不新增 Convex 客户端、后端接口、Streams
订阅或会话历史读取。只有前台叶子拥有按小时的 `day` 查询；参数相同时与统计页
共享查询租约。局部错误边界避免统计失败替换整个应用。

以返回的 `startMs`、`endMs` 和有序小时桶为准。当前私有后端按 UTC 当日对齐，
包含尚未发生的零值小时；公共时间线草案描述滚动窗口。因此，小组件仅在起点为
同日 UTC 零点时显示“今日 · UTC”，其他情况展示真实时段，不修改草案，也不声称
改变已部署的统计逻辑。未来小时必须为零并淡化。投影剔除费用和成员记录，最多
保存 25 个小时桶与两个最高用量模型，保留真实零值。输入/输出/缓存读取明细只在
接口提供时显示。通过 `formatCompactNumber` 按产品语言预先格式化数值标签。

`LodyTokenUsageWidgetStore.swift` 拥有独立的第 1 版本地缓存，原生校验限制数字、
文字、模型和日期。过期依据服务端 `endMs`，前台恢复或切换语言不能给旧统计窗口
续新；允许一分钟的来源/设备时钟偏差，拒绝未来小时中的非零用量。
`LodyTokenUsageWidget.swift` 复用会话小组件的标识与底色，绘制紧凑小时柱图。
两种尺寸都显示 Token 总量；中号显示模型用量，或接口提供的 Token 类型拆分。
仅元数据进入 App Group，WidgetKit 不发起网络请求。

发布同时校验用户、工作区、认证会话和 runtime 对象身份。入口拥有串行发布器、
合并更新定时器和 Capacitor 监听器；路由拥有查询和错误边界。进入后台释放查询，
保留同归属的有效快照；归属丢失、本地退出意图或路由卸载清理缓存，旧来源的迟到发布
无法跨归属写入。释放恢复原路由，并等待监听器移除及无法中断的原生写入。查询
恢复沿用共享预算；耗尽后清空可选小组件数据，等待新的路由/会话生命周期。
原生写入失败可在新输入或恢复时重试。

移动端直接声明已经使用的 `@lody/platform` 与 `react-i18next` 依赖，锁文件仅增加
这两条导入边，不改变任何解析版本或公共子模块指针。按 Effect 功能修复模式评估
后保留小型 React/Capacitor 边界：移动端仍没有直接可解析的 Effect 依赖，共享
查询/认证编排也未构成完整原生迁移单元。不更新迁移账本或完成声明。

## 订阅额度小组件（2026-10-15）

`src/provider-quota-widget.ts` 新增独立的“订阅额度”小组件，保留原有 Token 消耗统计。
复用共享归一化工具读取 `machine.raceLimits` 中按 Provider 配置隔离的记录，并沿用
订阅额度能力判断。只选择当前用户拥有的电脑，不合并不同配置或同周期的具名窗口。
优先在线电脑，先覆盖不同 Provider 品牌，最多三行；每行显示配置名称、电脑、最多
两个实际返回的额度窗口，以及额外窗口数量。

应用进入前台或电脑重连时，对选中的最多三个支持主动查询的在线配置调用
`WorkspaceRuntime.requestProviderRateLimitsRefresh`，复用
[已有 runtime/daemon 查询契约](../../../.agents/notes/implemented/architecture/2026-10-13-provider-quota-refresh.md)
的请求合并与只读 ACP 清理，不创建会话、不增加厂商 HTTP 客户端，也不复制凭据。
旧版或离线电脑保留缓存，含义不确定的空返回不会转成零额度；API Key 覆盖配置沿用
共享规则过滤。WidgetKit 扩展只读本地缓存，不发起查询。

`LodyProviderQuotaWidget.swift` 在小号、中号展示剩余百分比、接口提供的窗口标签和
重置时间。小号用高对比度圆环表示剩余比例：实际返回两个窗口时显示双环，只有一个
窗口（含仅 7d 的账号）时显示居中的大圆环。小号在各状态都沿用会话卡片的顶部结构：
左侧 19 点 Lody 图标与 14 点粗体圆角名字，右侧工作区名。Provider 标识放在标题下方的
内容区。单环直径调整为 62 点，双环保持 58 点，为重置标签和底部来源电脑信息留出
空间。单环和双环统一使用 16 点粗体圆角百分比、8 点周期标签，给单环内部保留更多
留白。长工作区名、电脑名分别截断，Lody 名字保持完整，页脚不重复品牌。
中号每行一家 Provider，用统一长度的
额度条和百分比进行比较。常见 5h/7d 窗口上下对齐，缺失周期仅保留对齐空间，不画
轨道或零值。所有 Provider 都只有 7d 时用一列较宽的额度条。同周期的具名窗口仍
按来源顺序分别显示，不错误归入另一个周期列。周期前缀来自现有生产端的
“时长 · 标签”展示契约。两列间距为 12 点，在系统边距内再增加 8 点水平留白。
选择器示例也包含只有 7d 的合成 Provider。

仅当 Provider ID 的电脑前缀与显示名称都一致时，中号才把电脑名合并到页脚；不同
电脑仍保留每行名称。剩余不超过 20% 时用橙色提示，最低剩余窗口的重置信息放在
对应 Provider 名称下方，已过重置时间的窗口优先提示刷新。常规重置时间不再占据
每行空间。页脚只保留来源和快照标记，不显示“打开刷新”等操作文案或箭头，整张
小组件仍可点击打开应用。小号圆环展示保持原有结构。真实零值只绘制空轨道；重置时间已过时不绘制额度圆弧/条，并
提示刷新，不自行推算为满额。这些属于原生展示调整，查询、认证、缓存与释放的
所有权不变。15 分钟有效期只衡量快照复制
到原生缓存的时间；目前持久化额度行没有权威获取时间，不能据此声称厂商额度刚更新。
底部明确标记“额度快照”，实际呈现时机由 WidgetKit 控制。

新键 `LodyProviderQuotaWidget.v1` 在桥接解码、存储读取解码及保存时限制序列化数据
不超过 32 KiB，并按 UTF-8 字节限制字段。桥接大小检查在 JSON 序列化之后，不能
限制最初的桥接分配。原有会话/Token 格式不变，三个缓存仍是未加密的 App Group
展示元数据。退出或归属丢失时，在未完成写入之后串行清理；完整重置也删除新键。
行为测试覆盖真实额度归一化与 runtime 查询、前台刷新、API Key 排除、写入未完成时
退出及释放、原生字节边界、重置/过期边界，以及保留其他偏好。

## 生命周期与代码边界

改动全部属于私有移动应用，`lody-oss` 保持锁定版本。移动应用没有可直接解析的
Effect 依赖；按功能修复模式评估后保留小型 Capacitor/Jotai 适配层，不引入新运行时，
不声称迁移单元完成。入口拥有订阅、定时器和 Capacitor 监听器。共享认证清除信号
在退出网络请求完成前立即关闭三个发布者；初始化也检查该客户端已有的退出意图代数。
锁定在当前页面内持续有效，根认证恢复或回到前台不能重新开启；原生登录替换整页，
创建新的所有者。

归属失效在无法中断的原生写入之后串行发布清理。释放先取消输入订阅，完成最终
清理后才停止发布者，并等待监听器移除，不能丢弃待写清理而让旧快照成为最终状态。
桥接失败会有界自动重试，每次重新检查归属；新输入或恢复可重新开启恢复预算。
[缓存恢复决策](2026-10-31-widget-cache-recovery.zh.md)说明元数据加载和原生写入确认的处理。

## 与原生重置集成

最新主分支的完整数据重置在旧 renderer 和 Capacitor 写入队列停止后清除三个
小组件缓存及旧版会话键；中断重置的启动恢复也在应用导入前清除。请求三个
WidgetKit 时间线重新加载，保留 App Group 的其他偏好；原生缓存测试验证这个
联合缓存键清理。可选查询错误边界使用 `fallbackRender` 返回空内容；共享边界会
把 null `fallback` 当作未提供，因此不能用它来隐藏失败 UI。

## 风险评估（2026-10-14）

私有仓库把持久化格式、认证/租户边界及数据清理路径强制定为 `risk:high`。
本次新增代码在这三方面的实际后果不同：

| 范围            | 出错后果                                       | 已验证的防护                                                                                                                                                          | 剩余风险                                                                                               |
| --------------- | ---------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| 持久化格式      | 小组件缺失、陈旧，或本地元数据被读取           | 独立版本化缓存键、类型化投影、校验，以及可覆盖/清理的恢复路径。不迁移会话文档、权威用量记录或凭据格式。                                                               | Defaults JSON 没有应用层加密，过期不删除；会话/Token 原生解码没有总字节上限；新额度缓存限制为 32 KiB。 |
| 账号/工作区隔离 | 上一个身份的工作区名称、任务标题或用量仍然可见 | runtime 账号及就绪路由/meta 归属、三个发布者的页面生命周期退出锁定、会话所有者过滤、Token 会话/runtime 校验，以及释放时保留最终串行清理。认证仍由已有受保护查询负责。 | 原生读取不独立检查当前认证；跨进程落盘与 WidgetKit 实际显示时机仍需签名实机验证。                      |
| 清理/重置       | 小组件元数据残留，或其他存储被误删             | 旧 renderer/原生队列停止后，只删除四个指定键；中断恢复在应用导入前重复清理。实际 UserDefaults 测试保留其他哨兵值。                                                    | 内存删除不能证明跨进程落盘或画面立即消失；完整重置仍继承已有凭据/服务端会话撤销限制。                  |

新增清理仅涉及现有 App Group 中的 `LodyHomeWidgetSummary.v2`、旧版 `.v1`
、`LodyTokenUsageWidget.v1` 和 `LodyProviderQuotaWidget.v1`，不清空整个 domain。其他 App Group 偏好，包括已有
实时活动配置，继续由原生命周期管理。本次小组件改动不扩大完整重置已有的 WebKit
本地数据删除范围，也不增加服务端账号/文档删除。

展示元数据仍可能敏感。标题、工作区名称、模型名称及用量总数保存为 Defaults JSON，
现有 App Group 成员（含 OneSignal 扩展）可以读取。类型化重编码不复制凭据、
提示词、会话正文及权限命令字段到小组件键中，但不移除允许展示的文本中嵌入的
敏感字符串；这个结论不覆盖共享 group 的所有键。
[Apple 文档](https://developer.apple.com/documentation/foundation/userdefaults)说明 Defaults
使用未加密的数据格式、异步写入磁盘，持久化 Defaults 数据库也会进入设备备份。
本功能不新增应用拥有的远端发布，但不承诺排除系统备份或安全擦除历史副本。

有效性根据 `entry.date` 判断；15 分钟过期时或之后的条目不包含会话/用量细节，
重绘较早的条目仍可保留它们。实际缓存上的临时合成探针确认：过期快照仍可从同进程
的 UserDefaults 中读取；过期视图也继续显示工作区名称。清理请求重新加载时间线，
provider 预设过期条目，但 [Apple 的时间线契约](https://developer.apple.com/documentation/widgetkit/timeline)
允许显示更新延后。过期和退出都不承诺系统已绘制的小组件立即擦除；缓存校验不能
证明画面消失的最晚时间。

现有会话/Token 缓存的原生校验限制条目数量及部分文字/数值字段，未限制整个序列化载荷。直接写实际缓存的
合成探针保存并读回一兆字节工作区名称；一个 200,001 字节的组合字符标题通过原生
字段校验，探针未保存该标题。正常生产端限制
工作区 slug，并在发布前截断显示文字，因此未据此证明已发布路径上的 P0/P1。
损坏缓存或直接桥接输入仍可能耗尽扩展解码预算；未来如增加总字节上限，应在解码
前检查，并覆盖读取和保存两端。

此前的风险评估只修改文档。后续确定性探针复现了两处实际缺口：就绪元数据可把
新用户与旧 runtime 配对；退出网络请求尚未完成时，回到前台会重新发布旧标题。
直接运行已安装认证模块的探针还确认：已发出的 `get-session` 响应可在原生退出
钩子清除后恢复旧原始会话。

代码现已要求 runtime 账号与当前用户一致，并用 `subscribeLocalAuthStateCleared`
锁定当前页面生命周期。三个发布者共享此校验，迟到的认证恢复、旧查询结果及回到
前台不能重新开启。初始化检查 `getAuthSessionIntentGeneration`，覆盖适配层挂载前
已经发生的退出。释放等待未完成原生写入后的最终清理。这修复小组件发布隔离，
不修改上游 Better Auth 的响应处理；正常原生登录创建新页面。

七项永久回归扩展原测试集，使用实际共享认证信号、Jotai runtime/路由原子、React
Token 宿主和生产发布者，仅控制查询结果、时钟及原生写入。七项在修复前源码上全部
失败，修复后全部通过：缺失/不匹配 runtime 账号、根认证尚未清理的延迟退出、
新账号配旧就绪 runtime、未完成写入后的最终清理、退出时释放、根归属尚未清理时
Token 已确认认证丢失后的释放，以及挂载前退出与
新页面正常发布。已有核心与 Foundation 缓存测试也验证投影、重叠发布/清理后的
最终状态、联合键清理和恢复顺序。这些不验证应用/扩展跨进程落盘、原生 Preferences
失败、进程中断或系统快照显示时机。
