# Lody iOS 国际化

## 问题

Lody 当前没有 i18n 入口。产品文案同时散落在 React Native、`definePage` 静态标题、TypeScript 状态格式化、Swift/UIKit 聊天组件和 `Info.plist` 配置中。简体中文写死后，单独替换某一层会产生混合语言界面：列表可能已是英文，原生输入框、附件页或 VoiceOver 仍是中文。

本次只支持简体中文和英文，语言跟随 iOS 的 App Language。所有人工维护的文案必须位于一个目录，使用扁平 key；React Native 与 Swift 从同一份源文案生成结果。

## 决定

唯一文案目录是：

```text
apps/mobile/locales/
├── en.json
└── zh-Hans.json
```

两个文件都是一层 JSON object，所有 value 都是 string。目录之外不再维护第二份翻译文件、`.strings`、`.stringsdict` 或 `.xcstrings`。

```json
{
  "common.cancel": "取消",
  "session.machineCount.one": "{count} 台电脑",
  "session.machineCount.other": "{count} 台电脑",
  "chat.lastSynced": "上次同步：{time}",
  "native.chat.composer.placeholder": "给 Lody 发消息…",
  "native.chat.attachment.addCount.one": "添加 {count} 项",
  "native.chat.attachment.addCount.other": "添加 {count} 项",
  "ios.info.bundleDisplayName": "Lody",
  "ios.info.photoLibraryUsage": "选择照片作为消息附件。"
}
```

英文文件必须拥有完全相同的 key：

```json
{
  "common.cancel": "Cancel",
  "session.machineCount.one": "{count} computer",
  "session.machineCount.other": "{count} computers",
  "chat.lastSynced": "Last synced: {time}",
  "native.chat.composer.placeholder": "Message Lody…",
  "native.chat.attachment.addCount.one": "Add {count} item",
  "native.chat.attachment.addCount.other": "Add {count} items",
  "ios.info.bundleDisplayName": "Lody",
  "ios.info.photoLibraryUsage": "Choose photos to attach to your messages."
}
```

## 语言解析

内部 locale 只允许：

```ts
type Locale = 'zh-Hans' | 'en';
```

LodyKit 的 `initialLocale` 读取 `Bundle.main.preferredLocalizations.first`，RN 启动与原生字符串使用同一个可用语言选择。`expo-localization.getLocales()` 返回原始用户偏好，不能只读首项来决定应用语言，否则首选语言不支持时会与原生回退不一致（SET-19 修正）。匹配规则：

| iOS language tag                           | Lody locale |
| ------------------------------------------ | ----------- |
| `zh-Hans`、`zh-CN`、`zh-SG`、无脚本的 `zh` | `zh-Hans`   |
| `en` 及所有 `en-*`                         | `en`        |
| 其他语言                                   | `en`        |

英文是 fallback，并与 Xcode 的 `developmentRegion = en` 保持一致。语言在进程启动时解析一次；切换由 iOS 设置完成并重新进入 App。本期不增加应用内语言选择器、locale store 或语言偏好持久化。

Expo 配置声明 `zh-Hans` 和 `en` 为 iOS supported locales，使系统设置显示 Lody 的 App Language 入口。`apps/mobile/ios` 仍由 prebuild 生成，不能成为文案源。

## 所有权

```text
┌──────────────────────┐
│  iOS App Language    │
└──────────┬───────────┘
           ▼
┌──────────────────────┐
│ locales/*.json       │
│ 唯一人工维护文案源      │
└──────────┬───────────┘
           ▼
      ◆ key 前缀？ ◆
       /      │       \
      ▼       ▼        ▼
┌─────────┐ ┌─────────┐ ┌──────────────┐
│ 普通 key │ │ native. │ │ ios.info.    │
│ RN 读取  │ │ prebuild│ │ InfoPlist    │
└─────────┘ └────┬────┘ └──────┬───────┘
                 ▼              ▼
           Swift/UIKit     系统权限与名称
```

- 普通 key：由 React Native 的 `t` / `tp` 使用。RN 在把 title、subtitle、菜单项或 accessibility label 交给原生 view 之前完成翻译。
- `native.*`：Swift/UIKit 自己创建且 RN 不拥有生命周期的文案，例如聊天输入框、附件选择器、原生错误态和原生 accessibility 文案。
- `ios.info.*`：App 名称、权限说明等 `InfoPlist.strings` 内容。

用户输入、会话标题、项目名、电脑名、文件名、路径、分支、模型名、工具输出和服务端正文都是数据，不进入 catalog，也不翻译。协议状态、错误 code、SF Symbol 名称、accessibility identifier 和测试 fixture 同样不是文案。

开发专用 `/debug` 页面不阻塞英文发布；其中复用的生产组件仍必须显示所选语言。面向用户可达的错误和提示必须迁移。

## Key 规则

key 使用点分隔的 lower camel case 语义路径：

```text
common.cancel
tabs.sessions
auth.signIn
settings.connection.offline
session.create.selectProject
chat.composer.send
files.error.permissionDenied
native.chat.image.retry
accessibility.session.openDetails
ios.info.photoLibraryUsage
```

规则：

1. key 描述含义，不使用中文或英文原句作为 key。
2. 改文案不改 key；只有语义变化才新建 key。
3. 同一语义在多个 RN 页面复用同一个 key。
4. Swift 独占文案使用 `native.`；系统 metadata 使用 `ios.info.`。
5. 不建立嵌套 object、namespace 文件或 feature 级 catalog 文件。
6. 不用字符串拼接组句。完整句子由翻译模板表达。

## React Native API

`src/i18n` 只保存代码：locale 匹配、catalog 类型和格式化函数。文案仍只存在于 `locales`。

```ts
t('common.cancel');
t('chat.lastSynced', { time });
tp('session.machineCount', count, { count });
```

`TranslationKey` 从 `zh-Hans.json` 的 key 推导。catalog 映射要求英文满足 `Record<TranslationKey, string>`。`PluralKey` 从同时存在 `.one` 和 `.other` 的 base key 推导；`tp` 不接受普通 key。

不需要 React Provider。locale 在 App 启动时固定，`t()` 可以安全用于组件、普通函数、`definePage` 的模块级静态标题和原生 props 组装。这样不修改现有 `definePage` contract。

## Template string

模板只支持 named placeholder：

```text
{count}
{name}
{time}
```

语法为 `{` + ASCII identifier + `}`，identifier 匹配 `[A-Za-z][A-Za-z0-9_]*`。

格式化规则在 JS 和 Swift 中相同：

1. 单次从左到右替换，不递归处理替换值。
2. 变量只接受 string 或有限 number。
3. 缺少变量时保留原 placeholder；开发构建输出 warning。
4. 多余变量忽略。
5. 不执行表达式，不支持 `${...}`、HTML、Markdown、条件或嵌套模板。
6. `{` 和 `}` 保留给 placeholder；需要显示代码花括号的内容不应放入产品文案。

locale 校验必须确认同一 key 在中英文中包含完全相同的 placeholder 集合。这样翻译不能遗漏 `{count}` 或自行引入调用端没有提供的变量。

## 单数与复数

复数使用 flat-key suffix：

```text
session.machineCount.one
session.machineCount.other
```

每个 plural group 在两个 locale 文件中都必须同时存在 `.one` 和 `.other`，即使简体中文两条文案相同。当前只支持 cardinal `one` / `other`：

| locale    | count category               |
| --------- | ---------------------------- |
| `en`      | `1` 为 `one`，其余为 `other` |
| `zh-Hans` | 所有 count 都是 `other`      |

JS 使用 `Intl.PluralRules(locale, { type: 'cardinal' }).select(count)`。若平台返回当前 catalog 没有的 category，回退到 `.other`。`count` 必须是大于等于零的有限整数。

普通 RN plural 由 `tp(baseKey, count, vars)` 选择 suffix，再走同一个 template formatter。

`native.*.one` / `native.*.other` 在 prebuild 时合并成 Apple String Catalog 的 plural variation。生成器把 plural selector `{count}` 转成 Foundation 的数值 substitution；其他 named placeholder 在 Foundation 选择 variation 后由 Swift formatter 单次替换。Swift 调用 `LodyStrings.plural(baseKey, count, vars)`，复数类别交给 Foundation，不在业务 Swift 中写 `count == 1`。

本期不支持 ordinal、`zero` 特例、区间复数或完整 ICU MessageFormat。出现“没有电脑”这类特殊产品句式时使用独立语义 key，由业务状态选择；不要把它伪装成通用 plural category。增加需要 `few` / `many` 等类别的语言时，再扩展 catalog 校验和 native generator。

## 数字、日期与相对时间

模板不负责 locale-aware 数据格式化：

- JS 使用 `Intl.NumberFormat`、`Intl.DateTimeFormat` 和 `Intl.RelativeTimeFormat`。
- Swift 自己拥有的时间或数字使用 Foundation `FormatStyle`。
- 格式化结果再作为 `{count}`、`{time}` 等变量进入模板。

`src/ui/time.ts` 必须移除固定的 `zh-CN`。同一个时间在 RN 和 Swift 无需逐字符一致，但必须遵循当前 App Language 的语义、单位和日期顺序。

## 原生资源生成

增加一个本地 Expo config plugin，读取 `apps/mobile/locales/*.json`：

1. 校验文件是一层 string map。
2. 校验两个文件 key 完全一致。
3. 校验 placeholder 集合和 plural group 完整。
4. 把 `ios.info.bundleDisplayName`、`ios.info.photoLibraryUsage` 映射成每种语言的 `InfoPlist.strings`。
5. 把 `native.*` 普通 key 和 plural group 生成到 `Localizable.xcstrings`。
6. 把生成资源注册到 App target，并声明 `CFBundleLocalizations = [en, zh-Hans]`。

生成结果只进入 Expo prebuild 产物。不要提交后再人工编辑生成的 `.strings`、`.stringsdict` 或 `.xcstrings`。

Swift 通过一个 `LodyStrings` helper 读取 `Bundle.main`：

```swift
LodyStrings.text("native.chat.composer.placeholder")
LodyStrings.text("native.chat.attachment.preview", ["name": name])
LodyStrings.plural(
  "native.chat.attachment.addCount",
  count,
  ["count": count]
)
```

原生业务文件不能直接出现新的用户可见中文或英文 literal。机器可读错误 code 保持稳定；展示层把已知 code 映射到 catalog。未知错误对用户显示本地化通用错误，原始 message 只进入开发诊断。

## OTA 边界

普通 RN key 位于 JS bundle，可以通过 OTA 更新。`native.*` 与 `ios.info.*` 会编译进 App binary；修改这些 key 或 value 必须随 TestFlight/App Store build 发布，不能把 OTA 成功当成原生文案已经更新。

新增原生 UI 时，优先让 RN 传入已翻译 label；只有完整生命周期在 Swift 内、无法自然由 RN 提供的文案才进入 `native.*`。这样原生 catalog 保持小，绝大多数文案仍可随 OTA 更新。

## 迁移顺序

1. 增加两个 flat catalog、locale matcher、`t` / `tp`、catalog verifier 和 `expo-localization`。
2. 迁移共享格式化入口：`ui/time.ts`、状态 label、list state、toast 和常见错误。
3. 迁移路由标题、Tabs、设置、登录、会话列表、新建会话、文件与 diff 页面。
4. 在 RN 组装 `NativeGroupedList`、菜单、Alert 和 accessibility props 前翻译。
5. 迁移 LodyKit 自有聊天、附件、错误态和 accessibility 文案到 `native.*`，接入生成资源。
6. 迁移照片权限说明和 App metadata 到 `ios.info.*`。
7. 全部产品入口迁移并完成双语言验收后，才在发布配置中声明英文支持。

迁移过程中不翻译 debug fixture、协议字符串或用户数据，也不顺带重构页面结构。

## 验证

静态校验作为 `pnpm check` 的一部分运行：

- locale 文件只有一层 string key/value
- 中英文 key 集合完全一致
- placeholder 集合一致
- plural group 同时拥有 `.one` / `.other`
- `ios.info.*` 映射完整
- Swift 产品源不再新增用户可见硬编码文案

最小行为检查：

1. locale matcher：`zh-Hans`、`zh-CN`、`zh-SG` → `zh-Hans`；`en-*` → `en`；不支持语言 → `en`。
2. template formatter：多变量、重复变量、缺失变量、变量值含 `{name}` 时只替换一轮。
3. plural：中英文的 `0 / 1 / 2` 输出正确；JS 和生成后的 Foundation 结果一致。

模拟器使用一次性构建与可重置 Debug 场景，分别以 `zh-Hans` 和 `en` 启动：

1. Sessions、Search、Settings 的 Tab、标题、列表、空态和 VoiceOver label 全部同语种。
2. 登录、新建会话、项目/电脑选择、权限确认、文件和 diff 错误态全部同语种。
3. 原生聊天空态、输入框、模型菜单、发送与附件操作、图片失败态全部同语种。
4. 英文长文案不截断，44 pt 触控区域和原生导航行为保持不变。
5. 把系统语言设为不支持的语言时，RN、Swift 和权限说明都回退英文。
6. 重置照片权限后触发系统权限弹窗，说明文字与当前 App Language 一致。

最终运行 `pnpm check`、`pnpm test`、`pnpm bundle`、正常签名的 iOS 模拟器 build、两种语言的 `pnpm verify:ui`，以及覆盖 native template/plural 的 `pnpm verify:native`。截图用于检查排版，行为断言与 accessibility tree 用于确认实际文案，不能只凭截图通过。

## 非目标

- 应用内语言选择器和无需重启的动态切换
- 繁体中文、日语、韩语或 RTL
- 完整 ICU MessageFormat
- 在线翻译、翻译平台同步或自动机器翻译
- 翻译用户内容、模型输出、文件内容和服务端正文
- 为 i18n 引入全局状态库或 React Provider
