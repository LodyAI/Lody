# Create session (iOS)

Read before changing the new-session page, creation options, Agent Roles on new chats, GitHub branches or project groups. These rules bind every caller of the area, not only files in its directory.

- Model capabilities are per agent config (ACP provider), as web (`['acpCapability', configId]`): `creationOptions` keys them by config and carries `agentConfigId`; look them up with `CreateLogic.capability(in:machineId:configId:...)` (new session by `agent.id`, a session by catalog `agentConfigId`), falling back to agent type only for legacy rows. Never match by agent type alone, or one provider shows another's models.

- `ChatComposerView` in LodyKit owns the shared native input, draft handoff/restore, and model controls. Chat embeds it directly. The new-session form is native (`CreateSession/CreateSessionController`) and is shared by the app sheet (`CreateSessionHostController`) and the Share Extension; it places the composer on the keyboard layout guide, so do not add a second keyboard avoidance owner. On iPhone it is pushed full screen over Home like web (`params.pushed`, back button; the shell page hides its header because the form owns a navigation bar for its pickers); iPad and shared content keep the sheet. Its root page follows web's mobile new-chat page (checked by driving its Storybook stories): `CreateSession/CreateSessionContext` (SwiftUI, hosted by the controller) shows computer and project as plain full-width lines (no fills: the page reads as Liquid Glass composer + content) whose options expand in place right below them, aligned with the line (no indent) and with no surface of their own; computers carry their OS (catalog `machineOs` from machine meta `os`) and show the matching SF Symbol (Mac laptop / iMac / mini / Studio / Pro by name, `pc` for Windows, `server.rack` for Linux); the panel is bottom-anchored, so a list fades in place (`.blurReplace`) while the layout rises, never sliding against it (web's inline picker: one open at a time; computers without an online assistant listed but disabled; the project list searches every usable project and leads with No project, the five most recent projects usable on that computer, then More projects… which pushes the picker), then the worktree chip for local projects (`useWorktree` through the draft record into the runtime's local project ref) or the GitHub branch line expanding inline with search. The assistant is not on the page. The composer runs in `cardStyle` (the Liquid Glass surface, kept a rounded card while typing instead of morphing into the keyboard sheet; one text line at rest and three while editing (two with attachments), growing on a spring with the keyboard; 80-point attachment tiles align with the text and retain separate preview/remove targets; no @ button, as web (typing @ still opens mentions); +, @, the run-config chip `mark  model · effort · mode`, send; placeholder "Work with <assistant>"); the chip opens `CreateRunConfigSheet` (Agent when there is a choice, Model, Reasoning, Mode rows expanding in place; no Plan / Fast on new sessions). The Share Extension compiles these files directly, so it links `LodyDesignSystem` and includes `CreateSessionContext.swift` (`apps/ios/project.yml`). New-session drafts carry text and attachments together into the first turn, including native restoration when upload fails.

- New-session options persist in `LocalStore` under versioned account/workspace/project keys. Restore the complete provider/capability projection before runtime refresh; cached options can populate pickers but cannot authorize Send. Refresh failures retain the cached list, and successful reads replace it. Generation fencing prevents an in-flight read from repopulating storage after logout.

- The creation preferences also remember, per computer, the last agent and choice used there (`CreatePrefs.machines`, written with every selection): picking a computer, or loading options for one whose project has no saved agent, restores them while that agent is still offered (`CreateLogic.restoreMachine`), else its first agent. The run-config sheet leads with web's "Recently used" group (`lib/recent-run-configs.ts`): `CreatePrefs.recents` keeps up to 12 whole configurations (agent, full choice, Role) recorded only on Send, and the sheet shows at most 3 for the selected computer whose agent is still offered and whose Role is still runnable, excluding the current one. A pick applies the whole entry (a Role entry re-applies the Role; values the agent no longer offers are dropped by `CreateLogic.applicableChoice`) and closes the sheet.

- An open creation page refreshes from catalog/presence events, without polling. Unknown presence retains cached choices. A failed options read, or one that lists no assistant, shows a "Tap to retry" note that is itself the retry control (`CreatePanel.noteRetry`); a failed read is also read again in the background once the runtime publishes `live`, since it usually failed because the runtime was not ready. The selected online provider may request missing capabilities through machine RPC; skip binary-progress frames and apply only the final response matching workspace, machine, config and provider identity to the local display projection.

- New-session GitHub branches restore a credential-free SQLite projection keyed by account, workspace and repository, then refresh page 1 in the background. Refresh replaces the cached page set; pagination appends only to the fresh set. Failed refreshes retain the cached list and can retry page 1. Explicit branch choices are remembered per repository in the scoped creation preferences and are never overwritten by a refresh. Cache writes use the creation service's store generation so logout fences late responses.

- New-chat Agent Roles follow web's chat landing (`composer-agent-roles.ts`, mobile run-config sheet): a Role row above Agent (`CreateSessionContext.runConfig`, shown once `agentRoles` lists the workspace's Roles, reading None when there are none to pick) offers None, then the Roles bound to the selected computer by emoji + name; an unavailable Role (machine gone, agent removed, agent offline) stays listed, disabled, with its reason. Picking one (`CreateSessionForm.selectRole`) selects its agent and seeds exactly what it pins (model, mode, the reasoning option as effort, other options); None clears only the name; another computer clears it. It names the composer only while still applied (`activeRole`: same agent, every pinned value unchanged; independent Plan toggles keep it): the run-config chip then leads with the Role's emoji instead of the assistant mark, followed by the Role's name and model · effort · mode in secondary ink when that fits the chip's room (`ChatComposerView.roleFace`), else the emoji right before the model; the placeholder reads "Work with <Role>"; the sheet's Role row shows the emoji too, and None keeps an empty glyph so titles line up. The draft carries `agentRoleId` / revision: creation records them on the session meta as provenance, and the first turn's `sendTurn` carries only the id — the runtime re-reads the row (`resolveTurnRole`: readable, bound on the session's machine to the session's own Agent Config from metadata), refuses a changed or unbound Role (`role_changed` / `role_unavailable`), and applies the prompt prefix before the task, memory and the Role snapshot. Role listings carry the emoji and each target's safe pinned run config (secret-shaped option keys and memory never leave the row).

- A pushed creation page must not enable composer relay: it covers Home’s destination, so waiting for the destination to appear creates a navigation deadlock. Publish the local outbox turn, prepare Home’s conversation and split-column layout without animation beneath the form (animating them exposes the list), retain composer focus until removal, then crossfade it away (`LodyShell.close(crossfade:)`) as the text flies into its bubble, never sliding back; sheet creation can retain its composer relay.

- Multi-repository projects (web Project groups: a workspace row `['project', <uuid>]` in `${ws}:wf:workspace`, members GitHub repos or local folders): the runtime lists them (`projectGroups`, `protocol/project-groups.ts` ports web's validation, paths, `buildSessionProjectRun`, bound machine and legacy project ref) and `createSession(projectGroupId)` re-reads the group, requires its computer (local members pin one) and the machine's `multiRepoProject` (plus `projectRepositoryMembers` for `preferLocal`), and writes the frozen `projectRun`, the first member as the legacy `project`, no branch. Catalog sessions with a `projectRun` list under `group:<id>` and carry its members. The new-chat picker lists runnable groups as `group:<uuid>` projects ("N repositories", pinned to their computer or any); the draft sends `projectGroupId`; group conversations read workspace-wide options. No per-member branch or subset, as web. Mobile only displays groups ([README](../../README.md#project-groups)).
