# Home (iOS)

Read before changing Home: its tabs and bottom bar, the workspace capsule, the Schedules tab entry or the iPad / iPhone Duo split list. Conversation-list rows also follow the [Sessions rules](../../packages/LodyKit/Sources/LodyKit/Sessions/AGENTS.md). These rules bind every caller of the area, not only files in its directory.

- iPhone Home follows the shared mobile design system in `packages/LodyAppearance` (SwiftPM `LodyDesignSystem`: semantic tokens, system fonts, Lucide icons). Layout: workspace capsule leading; search (iOS 26 `integratedButton` placed via `searchBarPlacementBarButtonItem` with toolbar integration off, otherwise UIKit drops it to the bottom edge under the tab bar; hides the capsule while active) then the view menu trailing; `HomeTabsController` (`Shell/HomeTabs.swift`: a system `UITabBarController` with stable Chats / Schedules / Settings tabs and a create action intercepted by its delegate). Each destination keeps its root page; on iPhone, pages opened from a tab push onto the outer Home stack over the whole tab controller, like conversations (`HomeController.pushTarget`), because UIKit's hide-bottom-bar return draws the tab items before their Liquid Glass. Because the outer bar is hidden over the tab controller, such a page keeps its own navigation stack and bar inside the pushed view (`Shell/LodyPageStackHost`, with its own Back button), and its later pages push onto that stack; a native bar that appears with the page moves apart from it on an edge swipe back. UIKit owns Liquid Glass selection and minimization. iOS 27 uses `prominentTabIdentifier` for the separate create action; iOS 26 keeps it as the fourth tab. The view menu also has an Archived switch that turns Chats into the archived list (see Sessions rules) and scopes Chats to My tasks (session `userId` is the signed-in user; `HomeScope`, UserDefaults, default My tasks; search is unscoped). Chats groups by the view menu's single choice (`Sessions/HomeGrouping`, UserDefaults, default status) via `InboxSections.home`: time buckets, projects by latest activity (rows drop the project from line 2), or status (`HomeStatusGroup`, classified as web `lib/home-now.ts`, listed needs you / just finished / open PRs / running / idle; idle folds after 20). Within a group chats are newest activity first; there is no separate sort. Outside search, tapping a group label collapses or expands its group: a trailing chevron points down while open and right when collapsed, turning with the rows' diffable animation (`ChatGroupFolds`, UserDefaults, archived buckets kept separately); collapsed groups keep their label and project-index destination. Connection trouble is not in the capsule: `Sessions/HomeSyncPill` uses the navigation title view while the workspace name animates down to its logo to make room (web `MobileConnectionStatus`: syncing spinner, a "Connecting" spinner while the connection is restored (never "Offline"), "Connected" for 1.2 s, no touches). The Projects tab is hidden for now; `Projects/` sources stay for its return. Schedules (`Schedules/SchedulesController`, web mobile Home's Schedules tab; the create action keeps the compose glyph and adds a schedule there) shares the Chats header without a title (search filters by name); its view menu (`InboxChrome.pageMenu`) holds only a Show finished switch, in memory and off at launch, so ended schedules (they will not run again) stay hidden until it is on. It lists Scheduled tasks and messages (runtime `schedules`) in the Chats list's design language: a plain list without separators or cards, grouped as on web into Scheduled tasks and Scheduled messages (`scheduledMessage`) under Chats-style group labels that pin under the bar over the same blur backdrop as Chats (`Chrome/LodyPinnedLabelBackdrop`), each group ordered by state (needs attention, active, paused, ended), rows with the title and status in words (`ScheduleFormat`, tinted only for `attention`) on line 1 and a kind glyph, repeat summary and computer · project on line 2. The main Settings page uses the same language (`LodyGroupedList.setChatStyle`, with group labels spaced from the previous group and their rows); its workspace footer appears only when offline. Chats, Schedules and main Settings rows use the wider `LodyLayout.listEdgeX` inset. Inner Settings pages keep the flat settings rows. Swipe (never full-swipe) and the context menu run, pause / resume (owner only; resume and run need `machineSupported`) and delete (always confirmed). Rows push `ScheduleEditorController`: read only for teammates and messages; an untouched rule is sent back unchanged; wall-clock rules use the computer's zone. Each command carries a fresh `requestId`, reused only to retry a save of unknown outcome. Schedule lists restore account/workspace-scoped SQLite display snapshots before refreshing; persist only accepted successful reads, never optimistic previews, and fence late writes with the LocalStore logout generation. Cached rows never authorize writes; optimistic pause/resume must roll back on failure, fence older reads and preserve unknown-outcome errors. Long-press Settings opens Debug. Regular width (iPad, unfolded iPhone Duo) keeps the split with the gear and `InboxPadBar` (search and new chat, because there is no tab bar), but its list column is the same Chats list: `SessionListView` always hosts `ChatListView` with `InboxSections.home`, the same view menu (scope, grouping, row details, Archived), group folds and project index. The conversation open beside the list stays highlighted (`ChatListView.selectedRowId`, `fill.selected`). There is no separate sidebar list, density or view/sort mode.

- The Chats bottom bar uses UIKit `tabBarMinimizeBehavior = .onScrollDown`; other tabs use `.never`. Bind the actual active list as the content scroll view. UIKit owns the compact active icon and expansion behavior; never mutate tab items, frames, or transforms to animate minimization.

- On the Schedules tab the system tab bar's create action turns into "+" ("New schedule", `HomeTabsController.updateCreate`) and pushes a new schedule's editor (`SchedulesController.newSchedule`). The Projects add menu (`Projects/ProjectAddMenu`, `GitHubRepositoryPicker`) is unwired while the Projects tab is hidden.

- The workspace capsule opens `Chrome/WorkspaceSwitcherPanel`, a popover that never adapts into a sheet, because a `UIMenu` wraps long names and cannot fade them. Each workspace name stays on one line and fades out at the trailing edge (no wrapping, no ellipsis); rows keep the leading checkmark, workspace avatars, full VoiceOver names and the selected trait. The email heading comes only from the source’s account projection, never a global-auth fallback; empty identity clears it. Choosing the current workspace is a no-op. Workspace management remains in Settings › General.
