# Home (iOS)

Read before changing Home: its tabs and bottom bar, the workspace capsule, the Schedules tab entry or the iPad sidebar. Conversation-list rows also follow the [Sessions rules](../../packages/LodyKit/Sources/LodyKit/Sessions/AGENTS.md). These rules bind every caller of the area, not only files in its directory.

- iPhone Home follows the shared mobile design system in `packages/LodyAppearance` (SwiftPM `LodyDesignSystem`: semantic tokens, system fonts, Lucide icons). Layout: workspace capsule leading; search (iOS 26 `integratedButton` placed via `searchBarPlacementBarButtonItem` with toolbar integration off, otherwise UIKit drops it to the bottom edge under the tab bar; hides the capsule while active) then the view menu trailing; `HomeTabsController` (`Shell/HomeTabs.swift`: a system `UITabBarController` with stable Chats / Schedules / Settings tabs and a create action intercepted by its delegate). Each destination keeps its root page; on iPhone, pages opened from a tab push onto the outer Home stack over the whole tab controller, like conversations (`HomeController.pushTarget`), because UIKit's hide-bottom-bar return draws the tab items before their Liquid Glass. UIKit owns Liquid Glass selection and minimization. iOS 27 uses `prominentTabIdentifier` for the separate create action; iOS 26 keeps it as the fourth tab. The view menu also has an Archived switch that turns Chats into the archived list (see Sessions rules) and scopes Chats to My tasks (session `userId` is the signed-in user; `HomeScope`, UserDefaults, default team; search is unscoped). Chats groups by the view menu's single choice (`Sessions/HomeGrouping`, UserDefaults, default time) via `InboxSections.home`: time buckets, projects by latest activity (rows drop the project from line 2), or status (`HomeStatusGroup`, web `lib/home-now.ts` order: needs you / just finished / running / open PRs / idle; idle folds after 20). Within a group chats are newest activity first; there is no separate sort. Connection trouble is not in the capsule: `Sessions/HomeSyncPill` uses the navigation title view while the workspace name animates down to its logo to make room (web `MobileConnectionStatus`: syncing spinner, offline dot, "Connected" for 1.2 s, no touches). The Projects tab is hidden for now; `Projects/` sources stay for its return. Schedules (`Schedules/SchedulesController`, web mobile Home's Schedules tab; the create action keeps the compose glyph and adds a schedule there) shares the Chats header without a title or view menu (`InboxChrome.showsViewMenu`; search filters by name) and lists Scheduled tasks and messages (runtime `schedules`) in the Chats list's design language: a plain list without separators or cards, grouped by state (needs attention, active, paused, ended) under Chats-style group labels, rows with the title and status in words (`ScheduleFormat`, tinted only for `attention`) on line 1 and a kind glyph, repeat summary and computer · project on line 2. The main Settings page uses the same language (`LodyGroupedList.setChatStyle`, with group labels spaced from the previous group and their rows); its workspace footer appears only when offline. Chats, Schedules and main Settings rows use the wider `LodyLayout.listEdgeX` inset. Inner Settings pages keep the flat settings rows. Swipe (never full-swipe) and the context menu run, pause / resume (owner only; resume and run need `machineSupported`) and delete (always confirmed). Rows push `ScheduleEditorController`: read only for teammates and messages; an untouched rule is sent back unchanged; wall-clock rules use the computer's zone. Each command carries a fresh `requestId`, reused only to retry a save of unknown outcome. Schedule lists restore account/workspace-scoped SQLite display snapshots before refreshing; persist only accepted successful reads, never optimistic previews, and fence late writes with the LocalStore logout generation. Cached rows never authorize writes; optimistic pause/resume must roll back on failure, fence older reads and preserve unknown-outcome errors. Long-press Settings opens Debug. iPad keeps the split, sidebar, gear and `InboxPadBar`.

- In the iPad sidebar, Home section heads are `lodyBand` bands inset with 12 pt side margins and rounded corners, because full-bleed bands clash with the inset sidebar rows.

- The Chats bottom bar uses UIKit `tabBarMinimizeBehavior = .onScrollDown`; other tabs use `.never`. Bind the actual active list as the content scroll view. UIKit owns the compact active icon and expansion behavior; never mutate tab items, frames, or transforms to animate minimization.

- On the Schedules tab the system tab bar's create action turns into "+" ("New schedule", `HomeTabsController.updateCreate`) and pushes a new schedule's editor (`SchedulesController.newSchedule`). The Projects add menu (`Projects/ProjectAddMenu`, `GitHubRepositoryPicker`) is unwired while the Projects tab is hidden.

- The workspace capsule uses a native `UIButton` menu like conversation More. UIKit owns sizing, scrolling, truncation, checkmarks and accessibility; retain full action titles and workspace avatars. The email heading comes only from the source’s account projection, never a global-auth fallback; empty identity clears it. Choosing the current workspace is a no-op. Workspace management remains in Settings › General.
