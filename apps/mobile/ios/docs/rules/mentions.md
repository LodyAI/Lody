# Mentions and prompt shortcuts (iOS)

Read before changing @ references, `/` commands or prompt shortcuts in any composer. These rules bind every caller of the area, not only files in its directory.

- @ references follow Notion: `Chat/ChatMentionPanel` is docked at the composer's bottom edge, directly on the keyboard, with the prompt above it (`ChatComposerLiquidGlassSurfaceLayout.setBottomInset` lifts the surface by `ChatMentionPanel.dockHeight`). It hosts a contained `UINavigationController` of `ChatMentionLevelController` lists (diffable `UICollectionViewListCell`s, `UIContentUnavailableConfiguration` when empty): the root shows the categories (typed text shows matches), a category or folder pushes its level with the native push transition and back button, and a folder level leads with "Reference folder". The system bar is hidden (far too tall for the 280 pt panel): deeper levels draw a 44 pt header (plain back chevron + title + hairline) above their list, opaque so the covered level never shows through the push, and the edge swipe still pops. Role rows lead with the Role's emoji (runtime mention items carry `emoji`). Prompt shortcuts (runtime `cmd` items inserting `/shortcut:<slug>`) list as their own "Prompt Shortcuts" category; `/` offers both, shortcuts first. The runtime lists every readable shortcut whose saved project, computer and agent scope matches the composer (web `resolveShortcutAvailability`), including ones whose body carries references, since choosing one inserts them as chips; it answers from its last listing while reading a fresh one, and a listing missing one owner's index is incomplete rather than empty, so it never replaces the cached shortcuts. Root categories and typed matches lead with Agent Roles and Prompt Shortcuts, then files, skills, conversations, issues, PRs and the agent's commands. Roles and shortcuts are workspace-wide, so `MentionCatalogStore` shows the last accepted lists (`MentionWorkspaceCache`: memory plus an account/workspace-scoped `SettingsSnapshotStore`) at once while each composer reads its own; a Role read made before presence is live never replaces cached Roles, and cached rows only display. When a host cannot fit the composer and the panel above the keyboard (the new-chat card on a short screen), the panel ends its lists at its own `keyboardLayoutGuide` so the last rows stay reachable; it never moves the composer. Rows never take focus, so the keyboard stays; the text after the trigger filters the visible level; losing the trigger hides the panel and pops to the root. The old category page (`MentionPickerController`) is no longer opened from the composer. Android mirrors the panel (`chat/MentionPanel.kt`) but not yet the Role-and-shortcut-first order or the workspace cache.

- `/` lists prompt shortcuts before the agent's commands. Choosing a shortcut writes its body, as web's `prepareShortcutSelection`: `ChatMentionPanel.loadShortcut` (`PromptShortcutsController.body`, runtime `promptShortcuts` list → read) and `ChatShortcutInsertion.segments` turn the prompt and its references into text and chips (files `@path`, skills `$name`, issues / PRs `#number`, Agent Roles labelled); if the read fails the `/shortcut:<slug>` token goes in. An Agent Role chip reads as its emoji and name but sends `@role:<id>` (`ChatComposerInput.labelledReferences`, substituted in `markdown`, kept in the draft envelope), which the runtime expands at send.
