# Composer and action bar (iOS)

Read before changing the conversation composer, its action bar, merge, the native PR page or usage beside Send. These rules bind every caller of the area, not only files in its directory.

- The conversation composer is the new-chat composer (web's mobile session page): `SessionController.wireSendEvents` sets `cardStyle` and `restsCollapsed`: at rest it is one Liquid Glass line (+, the prompt, the agent mark (`collapsedMark`, no chevron, opening the run-config sheet directly) and Send; a typed draft keeps the card open); sending dismisses the keyboard; editing opens it into the new-chat card (three lines; +, the run-config chip, Send, which turns into Stop while a turn runs and nothing is typed; both use Ink fill and contrasting foreground, never red), with no @ button (typing @ still opens mentions). The action bar and the full-screen grabber follow actual editing, not the always-expanded card. The chip opens `SessionController.presentRunConfig`, the shared `CreateRunConfigSheet` fed by `SessionComposerModel.runConfig`: Role, the conversation's Agent shown locked (web locks it once a chat has history; no agent switching), Model, Reasoning, Mode, then Plan and Fast switches when the agent offers them (`CreateLogic.planMode` / `fastMode`). Roles follow web `selectSessionAgentRoles` (`Sessions/SessionRoles`): only Roles bound to the session's computer AND Agent Config, None first, unavailable ones disabled with their reason. Picking one applies only the values it pins; the composer names it while they still hold (latest turn's Role from the runtime `composer.agentRoleId` projection, a local pick overriding until a newer turn lands). Each turn sends `agentRoleId` (the Role, `{value: null}` for an explicit or drifted None, omitted while the list loads); the runtime applies a Role's prompt prefix only on a session's first turn. The composer relay from the creation page carries `onRunConfig` and `cardStyle` over.

- The conversation composer's agent mark travels from its trailing collapsed button to the leading run-config button on the same expansion curve, reversing on collapse. Keep one visible mark during the transition, preserve button hit targets, and respect Reduce Motion.

- The conversation's action bar (web `SessionInfoBar`) is a row of grouped Liquid Glass capsules above the composer, so the composer stays the only full-width shape (`Chat/ChatActionBar`: SwiftUI `ChatActionBarContent` in a `GlassEffectContainer`, hosted by `ChatActionBarView`, fed by composer state `actionBar` from `SessionController+InfoBar.actionBarState`; actions return as `bar:` ids through `onPreview`). Capsules: environment (computer with presence menu, browser preview and simulator from `resourceItems` — tap opens, menu copies / stops; sub-tasks stay in the transcript), context (PR number, else branch, else repository name without owner; CI trouble tints the glyph; the ±diff inside; tap always opens a destination popover: the native PR page, workspace changes with coloured ±counts, copy branch; multiple destinations show a down chevron) and, pinned trailing, the top repository action as a neutral split capsule whose chevron `Menu` holds the rest; Merge also shows a chevron for its method picker. Colour is for status only so Send stays the one accent. It never scrolls: `ViewThatFits` takes the first stage that fits one line (labels capped at 140 pt, then the diff hidden (counts stay in the context menu), then the environment folded into one icon with a `+n` badge and a menu of all), and only at very large text stacks the action on its own trailing row (`fittingHeight(width:)`). There are no quick replies; the bar stays while typing and hides in expanded editing. `Sessions/SessionInfoBar` ports `resolveSessionInfoBarGitHubActionIds` and web's prompts; prompt actions send as ordinary turns, only while still offered. Merge (after an action sheet of merge / squash / rebase that doubles as confirmation, last method first) and Ready for review write to GitHub directly through `Cloud/GitHubPullRequests` (`merge` pins the head SHA it just read; `ready` runs GraphQL `markPullRequestReadyForReview`) with the Lody Cloud brokered write grant; never retried, a lost response is reported as unknown. The runtime catalog projects `workspaceDirty`, `workspaceUnpushed` and PR `merge`. Goal and schedule stay on web. A draft carries no merge state and the computer's PR poller may not refresh it for minutes, so after Ready for review succeeds `PullRequestMergeSettle` reads GitHub's `mergeable_state` (read grant, `mergeState` operation) a bounded number of times and `SessionPullRequestUpdates.observeMerge` holds it until the catalog reports its own; Android `PullRequestMergeSettle` mirrors this.

- The merge-method popover (`MergeOptionsController`) anchors to the measured primary action button in `ChatActionBarView`, never the whole composer. Its compact menu rows keep the irreversible-action explanation and show the last-used method first with a checkmark; selecting a method remains the explicit merge confirmation.

- The native PR page's toolbar offers Merge while the PR is open: `MergeOptionsController` anchors to that item, shares the action bar's last-used method, and the method choice is the confirmation. Once merged, it offers Delete branch after a confirmation alert, only while the PR's own same-repository head branch exists and differs from the base. `GitHubPullRequests` `deleteBranch` re-reads the PR with the write grant, treats a branch already gone as deleted, and is never retried.

- The repository context popover leads with the repository owner logo (folder for local projects) and repository/project name, closely followed by a small one-line “Current branch” label and branch plus trailing copy button. Its aligned action columns show View PR / #number (never localized digit grouping) and All changes / coloured ±counts. Compact capsules omit diff counts without substituting an unexplained dot; short PR labels use intrinsic width.

- Conversation usage beside Send is display-only: context occupancy comes from the session usage projection, never turn billing totals. Resolve subscription windows against the exact machine, agent config and selected model, requiring eligibility and the rate-limits capability. Keep unknown context hidden, compacting distinct, neutral used-percent meters and an independent relative/concrete reset-time toggle for each window.
