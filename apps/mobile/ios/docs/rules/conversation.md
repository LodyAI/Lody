# Conversation (iOS)

Read before changing the conversation page: the transcript and its turns, header, Tabs, message actions, members and avatars, images or agent marks. These rules bind every caller of the area, not only files in its directory.

- Conversation turns follow web's mobile session page: a user turn's first row (attachments, else bubble) carries its sender (`ChatRow.author`, from the session entry `userId` the runtime projects; `ChatAuthors.unknownSender` for older turns and local sends, resolved to the signed-in user), time and read state (seen check / sent circle / queued clock / sending), drawn as a right-aligned header (mark, time, name; web's order) in one secondary ink with the sender's 36 pt avatar beside it; attachments use the bubble column; other members show as Member until the member list is loaded. The agent footer is one compact row of actions followed by the timestamp; model and reasoning details stay in the turn-information panel. `ChatReadingColumn.cellMargin` is 16 pt, web's mobile inset.

- Agent turns follow web's folding (`ChatTranscript.entryRows`): a running turn (or one that ended without an answer) keeps prose inline, with DSH thoughts and consecutive tool calls in separate closed disclosures (`think` steps hidden); opening a thought shows its prose, while a tool summary shows single-line, tail-truncated tool rows under the live "Working for …" row; once an answer ends it (`answerRun`, the final contiguous text run before the never-folded tail) the work folds into "Worked for … ›", which opens it in place (`LodyChatView.expandedWork` → `ChatTranscript.expandedWork`; the chevron turns on a spring, the tapped row anchors the layout (`toggleAnchor`) while bottom-follow pauses, and rows come and go through the diffable snapshot). Only builtin DSH keeps thoughts (`LodyChatView.showsThoughts`); other providers' thoughts and `think` steps are dropped before the transcript. No warning orange anywhere in a conversation (`chromeColor`, duration rows carry no attention). A turn closes with its output card — the tasks row (`hangSubagents`) and the changed-files row (`changesHeader`, group first/last/only), both drawn by `configureOutputRow` (leading symbol or live spinner, title, detail, trailing, disclosure), each opening its own near full-screen sheet (`TasksController`, `TurnFilesController` → file diff pushed inside the sheet) — and then the meta line, always last.

- Chat process, summary and sub-agent rows use Home's rail glyphs and tree lines; answer text uses the full width with 16 pt margins. File changes form one grouped `lodyInset` block, and code blocks use `lodyInset` fill. The composer is outside the design language rail scope.

- Process headers use the duration’s regular 12 pt monospaced style throughout, without enlarged or bold status text. Duration headers have no loading/done glyph; completed headers omit tool counts. Expanding work preserves prose/tool/prose order: each tool summary stays after its preceding text and opens only that contiguous tool group; command rows remain one line with tail truncation.

- A failed command gets no special treatment in a conversation (no warning mark, no orange): only a step waiting on permission flags its process summary, with a neutral mark. Android's step rows likewise drop the red "Failed" label.

- Process summary and duration rows put their chevron right after the text, not at the row's edge.

- Message footers expose copy, turn information and fork as visible 44 pt buttons (`ChatMessageActionsCell`), with prose-aligned glyphs, 32 pt spacing and time 12 pt after Fork. No More menu. Do not repeat model or reasoning metadata above the buttons. User messages collapse to six measured lines and have no inline action row: long-press offers Copy, plus Edit only for `editableMessageID`, with eligibility rechecked when Edit is selected. Copy uses `ChatMessageShare` for visible answer text and gives inline checkmark feedback. Fork revalidates the exact completed provider turn through `forkSession` and creates a new Tab sharing the working directory; uncertain requests are not replayed. Keep source-session identity checks and native scope ownership when opening action sheets.

- Definite send failures must leave the composer available for a fresh turn. Keep the failed pending turn retryable until an explicit replacement; never reuse its attachments for the new turn or relax the fence for unconfirmed delivery.

- `SessionFeed` retains a subscription on its captured runtime and releases only the final page owner (`SessionSubscriptions`). Cache/bootstrap/recovery snapshots set `isLiveUpdate = false`; the transcript suppresses reveal/fade for those snapshots and only the current visible text tail streams. Combined Fast/model/effort changes use `CreateLogic.applyingComposerChange` atomically. Session sync diagnostics hash session IDs and allow only bounded status/code fields, never message bodies.

- The conversation Tabs panel (`Chat/ChatTabsPanel`, `SessionController.presentTabs`) uses `ChatTabsOverlay`, a Liquid Glass card below the header with a clear tap-to-dismiss layer. It retains status marks, selection, close/history/restore and Reduce Motion behavior. The header machine subtitle opens machine details, not Tabs.

- Current-working-directory conversations open from the trailing conversations button joined to More, visible only with other open Tabs. Its status summarizes other open conversations with local read watermarks applied. More owns “New current working directory conversation” using the existing create-Tab operation, and exposes closed-Tab recovery even when the button is hidden. Machine identity appears below the title in secondary text with a leading presence icon; tapping the header opens owner and visibility details in an anchored popover that does not adapt to a sheet on iPhone. Do not duplicate it above the composer.

- Conversation members use native `AuthAPI.members` pagination and the account/workspace-scoped `WorkspaceMembers` SQLite projection (ID, name, HTTPS avatar URL only). Cached identities render first; fresh responses reconfigure message rows without waiting for new messages. Request cancellation, account/workspace ownership, credential equality and LocalStore generation fence stale results and logout writes. Failed refreshes retain cached identities.

- Conversation avatars prefer workspace member identities over the login snapshot, including the signed-in sender and local turns. `LodyListPhoto` caches public avatar bytes through `PhotoDiskCache` in Caches/avatars-v1 (16 MiB / 128 files, URL-hashed keys); disk IO stays off the main thread. Cached photos render immediately; entries older than one day refresh in the background and remain visible on failure.

- The conversation More menu follows web `SessionHeaderMenu` (`SessionController+More`): Rename and Change owner (multi-member workspaces; writes only `SessionMeta.userId`, never sharing) are hidden for archived chats; Copy offers base branch (only when it differs from the current branch), path, Markdown, URL and deeplink. Path and Markdown come from runtime ports of web `session-workspace-path` and `conversation-markdown`; keep them in step with web.

- The conversation header has no PR button or historical PR menu. PR navigation stays in the context capsule above the composer.

- A GitHub PR link in conversation text (`Chat/ChatPullRequestLink`) opens the native PR page instead of the browser when its repository belongs to the session's project, compared case-insensitively: the project's repository, or any GitHub member of a multi-repository project (catalog `Project.repositories`, from the session's `projectRun`). Other links still open in the browser.

- Conversation changed files never expand inline: the files row keeps file count and line totals and opens `TurnFilesController` (titled with the file count). Keep the tasks row, files row and final model/time footer ordering when changing this output card.

- Agent provider marks follow web `AgentIcon` (`LodyAgentIcon.mark(cliType:agentType:)`): builtin / registry agents by agentType, custom commands a terminal, unknown agents the generic mark. The template SVGs in `apps/ios/Resources/AgentIcons.xcassets` (consumed by the app and the Share Extension) (`lody-agent-<name>`, imported from web's agent assets, `currentColor` normalised to black) are also the source of Android's marks — keep `LodyAgentIcon.assets` in step and rerun `node android/scripts/agent-icons.mjs` after changing them. The create page's agent options and chip, and the conversation composer's model chip (`SessionComposerModel.agentAsset`, drawn in resolved label ink so it reads in dark mode), lead with the mark.

- Agent images that only tool work separates fan into one `imageStack` row; prose ends a stack. Stacked images keep their own preview ids. The preview closes by swiping down and offers Copy, Save and Share of the original, never the thumbnail. See [Conversation images](../../../README.md#conversation-images).
