# Session UI

## Conversation lists

- `ChatListView` renders Home conversation lists on every size class, including the iPad / iPhone Duo split column (outside search, one tertiary-ink `groupLabel` header pins under the bar and yields to the next; sections remain separated by spacing; a shared native blur backdrop (`Chrome/LodyPinnedLabelBackdrop`, also used by Schedules) extends from that label to the window top; a blurred base and stronger upper layer avoid mixing sharp text back through the gradient, with a dark-mode page tint and no separate navigation edge or second label; Android pins the same label over a page-colour fade) (and project pages) from `InboxSections` projections and emits the same `rowPress` / `rowAction` events as `LodyGroupedList`. Rows lead directly with the title at the page margin. The trailing first-line slot shows the status mark (alert, hand, `LodyWorkingGrid`, unread dot) instead of the age whenever one is present; otherwise it shows the compact age and an inline PR when there is no detail line. An optional second line shows repo / folder + project and branch, keeping the PR at its trailing edge. Open / draft PRs carry the web CI verdict badge. Opened chats nest one level under their opener (`SessionRows.treeRows`; a child hides a project that repeats its opener's). The opener row stays like any other (its own project / branch line); below it the family line `⌄ 7 opened chats` (`ChatRowContent.familyToggle`, count from `LodyListRow.childCount`, whole-row target, chevron at the opener's title edge, turning right when folded; `homeFoldedOpeners`, default unfolded) heads the family. Children read one size down (callout, 40 pt rows), keep status at the trailing edge, and connect to a thin branching line under the chevron (a smooth curve into each title; only intermediate children continue the trunk) with titles stepped in `childLevel`. An opener shows its own conversation status, including internal Tabs. When its children are folded, their most urgent status appears at the trailing edge of the child-count row; expanded children show their own marks. The view menu is a multi-select (`ChatRowDetails`, UserDefaults, default project + PR) of what line 2 shows; none leaves rows one line.

- Home builds complete parent families before time/status/project bucketing. Tabs and side chats (`parentSessionId`) belong to their conversation and never list, as web `sessionListAtom` (iOS `SessionRows.isTab`, Android `ChatListModel.isTab`; Projects counts skip them too). Families come only from openedBySessionId, then openedByRootSessionId, against visible sessions, an opener that is a Tab resolving to its conversation; do not require matching projects. Only the parent determines the bucket; every descendant stays adjacent under that root. Missing/archived parents and cyclic references must not hide rows. My tasks preserves complete matching families; idle limits count roots and never split a family. Cross-project children keep their project label, and child urgency remains separate from the parent status.

- Chat list backdrop geometry must use visible supplementary view frames, never query layout attributes using visible header index paths during diffable updates. UIKit may retain old headers while the new snapshot has fewer sections. Refresh the backdrop from the collection view's finished layout pass, never `scrollViewDidScroll`, which sees pinned header frames from the previous offset and flickers the label and blur; refresh it again after snapshot completion and preserve native sticky-header hand-off. Regression: [home-grouping-crash.py](../../../../../apps/ios/verification/ui/home-grouping-crash.py) with the sticky-groups fixture.

- The entire family line (`⌄ N opened chats`) toggles children, including blank space and status. The opener above opens the conversation. It sits just under its opener and may be shorter than 44 pt; its target extends into the opener's blank bottom space.

- Team conversation lists show a compact circular owner avatar after the trailing time/status (including children), resolved from the workspace member cache with a name-initial fallback. My tasks omit this avatar; special status stays trailing. Titles and project details share the leading edge.

- Every Home grouping (time/project/status) starts with a separate Pinned group when nonempty, within the current owner/project scope. Partition whole visible families before bucketing, so pinned families appear once and retain child folding. Project conversation lists use the same projection; archived chats and hidden Tabs never enter Pinned.

- Conversation list attention includes its non-archived internal Tabs on the same
  machine, with failed, waiting, running, then unread priority. Side-panel sessions
  and independently opened chats do not contribute. Closed Tabs still contribute
  active status but not unread. Preserve Tab inputs through owner filters, keep
  Tabs hidden as list entries, and apply the summary to status grouping as well as
  row markers without rewriting catalog session state.

- Conversation-list Mark Read availability respects the local viewed-message watermark, just like unread emphasis. Swipe actions require an explicit button tap, never a full-swipe commit. When a chat row’s swipe commands change, replace its cell to discard the previous swipe presentation.

- The Chats view-menu toggles are built when the menu opens (uncached) and close it on tap; a kept-open menu (`keepsMenuPresented`) never redrew the checkmark.

- Presence and connection-only catalog notifications update Home chrome and empty-state text without rebuilding unchanged conversation content. Account/workspace changes, read watermarks, search results, members, preferences, traits and foreground refreshes must still invalidate content. Build Home's session index, attention summary and families once per projection, and carry whole families through pinning and grouping.

## Project index

- The Chats project index (compact and split column alike) appears while scrolling over the list, accepts direct tap/scrub only inside its visible opaque rail, and resolves jumps against committed rendered sections. Never attach an index long-press recognizer to the list. Linger dismissal must be invalidated by renewed scrolling/touch, snapshot replacement, backgrounding and detachment; search and other groupings retain their existing behavior.

- Project grouping may hide the repeated place label, but must retain raw repository identity for the index. On iOS and Android, each project group label leads with that repository's owner avatar (`RepositoryIcon`, `muted` off) in original colours, without the row marks' saturation or opacity. Keep index artwork at 24 pt in targets with at least 48 pt pitch; overflow uses bounded landmarks instead of squeezing targets. Keep landmarks fixed during a gesture and retain every destination through scrubbing and accessibility. Anchor scrubbing to the tapped landmark so small finger movement cannot jump to an unrelated proportional destination. The rail background must remain opaque in both light and dark appearances.

- Index entrance and exit use restrained movement with full opacity at rest. Disable hit targets when dismissal begins, fence interrupted animation completions, and skip movement under Reduce Motion. Lifecycle cancellation must stop animations and hide immediately.

- Operation receipts and the relations tree use compact conversation-list rows with provider marks, trailing status and curved child rails. Preserve separate reply and exact-target actions; receipt status belongs to its creating turn, while tree status follows the live catalog.
- Operation cards consume the public progress/completion/batch projection without rewriting receipts. Hide duplicate successful creation completions linked to progress; retain failed/cancelled targets, uncertain delivery and omitted-member counts. Navigation revalidates the live catalog and keeps the exact Tab target. Saved reply text remains readable after its target disappears.
- The composer relations capsule opens a catalog-backed tree. Containment owns Tabs: keep them in their conversation’s horizontal row, with hidden scrollbars and directional overflow fades. Only precise opened-by links add depth and curved rails between conversations. Require the precise opener and its root to exist, never route through `openedByRootSessionId` alone, exclude archived and side-panel targets, and guard cycles. Scope changes clear the tree and disable old navigation.

- Relation and receipt rows express containment through layout, without auxiliary Tab/current/directory labels. Mark only the current exact target with a subtle background and accessible selection. Keep status descriptions accessible, use icons instead of redundant visible status words, and preserve reply text, truncation/error notices and action labels.

- Archived chats have no Settings page. The Chats view menu (iPhone and iPad) carries an Archived switch (`HomeArchive`, in memory, so each launch opens on open chats). While on, the list and search show only archived chats in activity buckets (`InboxSections.archived`, honouring My tasks, no Pinned group or project index) on the darker, greyer `bgArchived` page with grey titles. Archived rows swipe left only to Unarchive, have no pin swipe, and their context menu offers Unarchive, Share and Delete.

- Archiving from conversation More immediately returns to the list while its write outlives the page. Success is silent; failure warns only in the original active Home/account/workspace scope, fenced by logout generation. Home clears only that conversation’s detail. Unarchive retains its page and feedback.
