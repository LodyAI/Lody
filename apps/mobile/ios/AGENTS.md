# Lody iOS

- This is an independent iOS-only UIKit client. pnpm builds the bundled cloud protocol assets; XcodeGen generates app, extension and verification targets; Swift Package Manager builds LodyKit and its native dependencies.
- First-party UI and state live in the Swift package `packages/LodyKit/Sources/LodyKit`; the application entry point is `App`, and extensions are in `Extensions`. Use Swift/UIKit or SwiftUI; do not add bridge packages. SwiftPM discovers LodyKit sources automatically. Run `pnpm prebuild` after changing app/extension source membership or shared extension references in `project.yml`; never edit the generated Xcode project by hand.
- Do not add Android implementations, fallback stubs, or Android build scripts.
- `apps/ios/Lody.xcodeproj`, `.generated` are generated. Persist app configuration in `apps/ios/App`, app/extension target definitions in `apps/ios/project.yml`, and package dependencies/resources in `packages/LodyKit/Package.swift`. Run `pnpm prebuild`.
- Keep normal Xcode signing enabled, including simulator validation. Do not use `CODE_SIGNING_ALLOWED=NO`.
- Cloud integration targets official Lody Cloud. Use browser-safe public protocol imports in `packages/cloud-runtime`; do not import Node-dependent `@lody/shared` or `@lody/loro-streams-rpc` root entries, absolute paths from another checkout, or private backend packages.
- Credentials belong in Keychain. Never copy desktop credentials, tokens, transcripts, or private service configuration into this repository.
- `LodyApplication` owns lifecycle and application coordinators. `AuthSession`, `CatalogSession` and `OutboxSession` own native state; feature controllers observe their projections. Keep protocol code in `packages/cloud-runtime` and generated wire types in `packages/lody-core` (`pnpm contract`).
- Shell pages use transparent headers and soft scroll edges. Native pages bind their scroll view through `LodyScrollEdges`.
- Preserve user edits. Before destructive revert/restore/rollback, inspect the working tree and obtain explicit confirmation.
- Verify with `pnpm check`, `pnpm bundle`, and an iOS simulator build when changing native code. Prefer behavioral checks over implementation snapshots.
- Do not nest ternary expressions. One `cond ? a : b` is fine; a `?` inside either branch is not. Map a closed set with a dictionary, and use `if` / `switch` for ordered or overlapping conditions. Optional chaining and `??` are not ternaries.

## UI baseline

- New surfaces should adopt the design system; other pages keep the system baseline until migrated. All copy goes through `Localizable.xcstrings` (en + zh-Hans).

- Apple HIG is the primary UI requirement. Chat references inform behavior only; preserve native conventions.
- Native text uses system fonts, with system monospaced fonts for code. Keep semantic sizes, weights and Dynamic Type in `LodyTextStyle`; do not bundle or select custom font families for native UI. Chat inline code uses body size and secondary-label ink, retaining link colours. Preserve fenced-code themes; with the current per-block renderer, containers holding fences retain their original code colours.
- Use fixed Ink for the app accent; do not expose an accent picker or read legacy accent preferences. Preserve conversation activity/status colors from the design system. Diff additions use systemGreen, paired with systemRed deletions. Use UIKit semantic content colors, Ink actions, neutral backgrounds, and explicit toast semantics: neutral information/completion, orange warnings, red failures. Preserve automatic dark mode and accessibility contrast adaptation.
- App-owned dark canvases use fixed soft `#111113`, never pure black; ignore legacy `darkBackground` preferences and do not expose a picker. Preserve light semantics. Camera and simulator media backdrops stay soft dark in either theme; masks, translucent scrims, shadows, artwork and foreground ink are not canvas fills.
- Preserve native navigation, safe areas, VoiceOver labels, and at least 44 pt touch targets. MVP acceptance uses the default text size; keep system text behavior but do not add special layouts or remount logic for oversized accessibility text.
- Reference Yohaku iOS for native UI boundaries. System grouped rows use `LodyGroupedList` / `UICollectionViewListCell` in LodyKit; navigation uses UIKit automatic scroll edges through the existing native stack. Register native collection views with UIKit directly; do not simulate native effects with decorative overlays.

Deselect alongside the navigation transition and restore selection when an interactive return is cancelled; ordinary action rows deselect immediately. - Settings has no Machines entry. Keep Roles separate and preserve machine details and execution-machine selection elsewhere. Provider list DTOs and caches must exclude credentials and environment values. Saves and deletes update the list at once and roll back on failure. Settings list reads use an incremental per-runtime stream cache (cleared when the account or workspace changes; writes and turn-time reads bootstrap fresh) and lists providers from the synced workspace replicas, online and own computers first; new providers come from the page's "+" for the selected computer.

- `HomeController` owns the adaptive UIKit split and list, session and inspector navigation controllers. Preserve native interactive pop. `SessionNavigation` handles session actions; tool pages use `LodyShell.presentDetail`. Keep sheets for transient flows and Debug demos.

Inject service closures for I/O; offline preview subclasses use scripted services. Use `String(localized:bundle:)` with `.lody` and edit `packages/LodyKit/Sources/LodyKit/Resources/Localizable.xcstrings` directly. - Pages write bar items to the hosting `LodyPageController.navigationItem`. Bottom toolbars appear only while their page is top; item updates wait for the running transition. Remove observers when their owner goes away; UIKit work runs on the main actor.
- `LodyFormController` editors use inline-label `LodyFormRow` rows in hairline-separated `LodyFormGroup` groups on `lodyGround`.
- `pnpm test` checks cloud protocol and verification tooling. Use Node 22 LTS (22.13+) for TypeScript stripping and module mocks. `pnpm verify:native` checks native behavior; `swift test --package-path packages/lody-core` checks routing and protocol policy.

- Build-time backends are resolved by the shared `../backend-config.mjs`; see [backend configuration](docs/backend-configuration.md). ## Cloud POC

- Login is native, with each provider following [its native protocol](docs/native-auth.md#public-protocol) (GitHub/Discord through a one-use PKCE backend handoff). Never restore device-code polling or a Web login screen. `AuthSession` alone installs Keychain credentials, after account validation and cancellation checks after every suspension. Credential HTTP requests refuse all redirects and cookies; persist only the raw JSON `token`, never the signed `set-auth-token` cookie header, because Streams authorization looks up the raw session token. Never substitute desktop credentials for app authorization. Keep the sign-in page in step with web `/login` ([details](docs/native-auth.md#sign-in-page)).
- `data-runtime` in LodyKit owns the POC's catalog replicas, Streams reads, cursors and retry. Native sessions observe projected catalog events; do not add a second live replica. The old offline decoder is retained only as a comparison path.
- Swift owns the offscreen WebView and watchdog. Keep startup/heartbeat deadlines outside JS, ignore callbacks from replaced views, and bound automatic restarts. Background suspension is not a watchdog failure: retain the WebView and reset its heartbeat deadline on foreground; recreate only a missing or failed runtime. User-started sends use only a short UIApplication background allowance through reply synchronization; never request BGContinuedProcessingTask, which displays a system Live Activity, or use idle connection keepalive.
- The host↔runtime boundary is the versioned contract in `packages/cloud-runtime/src/contract`, with generated Swift in `packages/lody-core` (`pnpm contract`). Add methods there: the runtime exposes only `dataRuntime.receive` and posts only `ready` / `envelope`; do not add `callAsyncJavaScript` commands.
- Only short-lived workspace Streams grants enter the bundled WebView; long-lived Better Auth credentials stay in Keychain. Never load remote scripts or expose tokens in diagnostics. Logout and unsubscribe must stop the owned runtime.
- This POC reads catalogs and session history, and sends text turns. CRDT replicas restore from server bootstrap. App account/workspace context and complete catalog display projections restore from SQLite in LodyKit before background authentication and sync; credentials remain in Keychain. Loro/Flock updates use uint32 big-endian length frames; never append raw WASM exports. Persist the user history before the durable dispatch pointer and Machine RPC. A machine ACK is delivery, not completion. Never automatically replay writes across runtime recovery. Catalogs have an explicit 16 MiB per-replica input ceiling; do not label an incomplete or failed sync as live.
- Generate native runtime assets before prebuild/build. Preserve dependency licenses beside generated resources. Native watchdog behavior has a deterministic Swift check in `verification/kit/watchdog`.

- Model capabilities are per agent config (ACP provider), as web (`['acpCapability', configId]`): `creationOptions` keys them by config and carries `agentConfigId`; look them up with `CreateLogic.capability(in:machineId:configId:...)` (new session by `agent.id`, a session by catalog `agentConfigId`), falling back to agent type only for legacy rows. Never match by agent type alone, or one provider shows another's models.
- `ChatComposerView` in LodyKit owns the shared native input, draft handoff/restore, and model controls. Chat embeds it directly. The new-session form is native (`CreateSession/CreateSessionController`) and is shared by the app sheet (`LodyCreateSessionView`) and the Share Extension; it places the composer on the keyboard layout guide, so do not add a second keyboard avoidance owner. On iPhone it is pushed full screen over Home like web (`params.pushed`, back button; the shell page hides its header because the form owns a navigation bar for its pickers); iPad and shared content keep the sheet. Its root page follows web's mobile new-chat page (checked by driving its Storybook stories): `CreateSession/CreateSessionContext` (SwiftUI, hosted by the controller) shows computer and project as plain full-width lines (no fills: the page reads as Liquid Glass composer + content) whose options expand in place right below them, aligned with the line (no indent) and with no surface of their own; computers carry their OS (catalog `machineOs` from machine meta `os`) and show the matching SF Symbol (Mac laptop / iMac / mini / Studio / Pro by name, `pc` for Windows, `server.rack` for Linux); the panel is bottom-anchored, so a list fades in place (`.blurReplace`) while the layout rises, never sliding against it (web's inline picker: one open at a time; computers without an online assistant listed but disabled; the project list searches every usable project and leads with No project, the five most recent projects usable on that computer, then More projects… which pushes the picker), then the worktree chip for local projects (`useWorktree` through the draft record into the runtime's local project ref) or the GitHub branch line expanding inline with search. The assistant is not on the page. The composer runs in `cardStyle` (the Liquid Glass surface, kept a rounded card while typing instead of morphing into the keyboard sheet; one text line at rest and three while editing (two with attachments), growing on a spring with the keyboard; 80-point attachment tiles align with the text and retain separate preview/remove targets; no @ button, as web (typing @ still opens mentions); +, @, the run-config chip `mark  model · effort · mode`, send; placeholder "Work with <assistant>"); the chip opens `CreateRunConfigSheet` (Agent when there is a choice, Model, Reasoning, Mode rows expanding in place; no Plan / Fast on new sessions). The Share Extension compiles these files directly, so it links `LodyDesignSystem` and includes `CreateSessionContext.swift` (`apps/ios/project.yml`). New-session drafts carry text and attachments together into the first turn, including native restoration when upload fails.

- New-session options persist in `LocalStore` under versioned account/workspace/project keys. Restore the complete provider/capability projection before runtime refresh; cached options can populate pickers but cannot authorize Send. Refresh failures retain the cached list, and successful reads replace it. Generation fencing prevents an in-flight read from repopulating storage after logout.
- An open creation page refreshes from catalog/presence events, without polling. Unknown presence retains cached choices. The selected online provider may request missing capabilities through machine RPC; skip binary-progress frames and apply only the final response matching workspace, machine, config and provider identity to the local display projection.

## Push notifications

- Native OneSignal SDK ownership stays in LodyKit `Notifications/PushNotifications.swift`;
  `PushLifecycle` initializes at app launch, retains SDK listeners and caches
  clicks until `LodyApplication` resolves and acknowledges them. `PushRegistration` serializes
  session-bound APNs writes; only the exact `configuration.selfHostedEnabled` Boolean
  selects direct APNs. OneSignal uses the original verified `userId`, unchanged, as does native ownership.
- `project.yml` and `App` persist the NSE, App Group,
  SDK pin and entitlements across prebuild. Never fix only generated `ios/` files.
- Notification navigation accepts only the legacy workspace/session route and resolves
  against the signed-in user's catalog. `recipientUserId` fences clicks after an
  account switch; payloads without a raw recipient are rejected.
- Debug's offline notification fixture never initializes OneSignal or requests real
  permission. See `apps/ios/PUSH_NOTIFICATIONS.md` for setup and verification limits.

- New-session GitHub branches restore a credential-free SQLite projection keyed by account, workspace and repository, then refresh page 1 in the background. Refresh replaces the cached page set; pagination appends only to the fresh set. Failed refreshes retain the cached list and can retry page 1. Explicit branch choices are remembered per repository in the scoped creation preferences and are never overwritten by a refresh. Cache writes use the creation service's store generation so logout fences late responses.

- The compact new-chat permission face uses a neutral shield for agent/default (a mobile override of web); unknown modes are hidden, read-only/edit/plan use icons, full-access modes use the warning shield, and auto uses the short `Auto` label. Full permission names stay in the picker and accessibility label.

- Conversation members use native `AuthAPI.members` pagination and the account/workspace-scoped `WorkspaceMembers` SQLite projection (ID, name, HTTPS avatar URL only). Cached identities render first; fresh responses reconfigure message rows without waiting for new messages. Request cancellation, account/workspace ownership, credential equality and LocalStore generation fence stale results and logout writes. Failed refreshes retain cached identities.

- The conversation More menu follows web `SessionHeaderMenu` (`SessionController+More`): Rename and Change owner (multi-member workspaces; writes only `SessionMeta.userId`, never sharing) are hidden for archived chats; Copy offers base branch (only when it differs from the current branch), path, Markdown, URL and deeplink. Path and Markdown come from runtime ports of web `session-workspace-path` and `conversation-markdown`; keep them in step with web.

- The conversation header has no PR button or historical PR menu. PR navigation stays in the context capsule above the composer.

- Conversation changed files never expand inline: the files row keeps file count and line totals and opens `TurnFilesController` (titled with the file count). Keep the tasks row, files row and final model/time footer ordering when changing this output card.
- Agent provider marks follow web `AgentIcon` (`LodyAgentIcon.mark(cliType:agentType:)`): builtin / registry agents by agentType, custom commands a terminal, unknown agents the generic mark. The template SVGs in `Resources/AgentIcons.xcassets` (`lody-agent-<name>`, imported from web's agent assets, `currentColor` normalised to black) are also the source of Android's marks — keep `LodyAgentIcon.assets` in step and rerun `node android/scripts/agent-icons.mjs` after changing them. The create page's agent options and chip, and the conversation composer's model chip (`SessionComposerModel.agentAsset`, drawn in resolved label ink so it reads in dark mode), lead with the mark.

- The Chats bottom bar uses UIKit `tabBarMinimizeBehavior = .onScrollDown`; other tabs use `.never`. Bind the actual active list as the content scroll view. UIKit owns the compact active icon and expansion behavior; never mutate tab items, frames, or transforms to animate minimization.
- The conversation composer is the new-chat composer (web's mobile session page): `SessionController.wireSendEvents` sets `cardStyle` and `restsCollapsed`: at rest it is one Liquid Glass line (+, the prompt, the agent mark (`collapsedMark`, no chevron, opening the run-config sheet directly) and Send; a typed draft keeps the card open); sending dismisses the keyboard; editing opens it into the new-chat card (three lines; +, the run-config chip, Send, which turns into Stop while a turn runs and nothing is typed; both use Ink fill and contrasting foreground, never red), with no @ button (typing @ still opens mentions). Picking one applies only the values it pins; the composer names it while they still hold (latest turn's Role from the runtime `composer.agentRoleId` projection, a local pick overriding until a newer turn lands). Each turn sends `agentRoleId` (the Role, `{value: null}` for an explicit or drifted None, omitted while the list loads); the runtime applies a Role's prompt prefix only on a session's first turn.
