# Home (Android)

Read before changing Home: the Chats list, grouping, families, the project index, the bottom bar or the hidden Projects tab. These rules bind every caller of the area, not only files in its directory.

- `home/HomeActivity` is the launcher: native sign-in without an account, otherwise `home/ChatListScreen`, which opens `chat/ChatScreen` for a row. It reads `AccountController` / `CatalogRepository` state only and picks the first workspace when none is restored.

- Layout matches iOS Home: Chats tab has the workspace capsule (logo + name) leading (its switcher menu is 200–260 dp wide and keeps each workspace name on one line, fading at the trailing edge via `LodyFadingText`, as iOS `WorkspaceSwitcherPanel`), search and the view menu trailing, and `HomeSyncPill` floating centred over the bar for syncing / offline / briefly connected (web `MobileConnectionStatus`); search takes over the bar and hides the capsule. A floating bar holds labelled Chats / Schedules / Settings tabs plus a separate create button. Schedules keeps the Chats header without the view menu; Settings shows account, workspace switching and sign-out. The Projects tab is hidden for now: its sources (`ProjectCards`, `ProjectAddSheets`, `ProjectAdding`) and the composables in `ChatListScreen` stay for its return, but nothing wires them.

- The view menu scopes Chats to My tasks (catalog session `userId` equals the signed-in user; `HomeScope`, SharedPreferences, default team; search is unscoped). Chats follow the view menu's single grouping choice (`HomeGrouping`, SharedPreferences, default time) via `ChatListModel.home`: time buckets (last message, else `createdAt`), projects by latest activity (rows drop the project from line 2), or status (`StatusGroup`, web `lib/home-now.ts` order: needs you / just finished / running / open PRs / idle; idle folds after 20). Within a group chats are newest activity first; there is no separate sort. Search stays by time. Outside search, Compose `stickyHeader` keeps a single accessible group label under the app bar; the next group pushes it off. Headers use the page colour without blur or a separate overlay. Search labels scroll normally. Rows mirror iOS: the title starts at the page margin and status (failed > waiting > working > unread) replaces the age at the trailing end of line 1. Without a status, show the age and an inline PR when no detail line is present. The optional second line shows repo / folder + project and branch, with the PR mark trailing; open / draft PRs carry the web CI verdict badge. Opened chats nest one level under their root opener within each group (`ChatListModel.nest`, mirroring iOS `SessionRows.tree`; contained Tabs keep their own row), as on iOS: the opener row stays like any other (its own project / branch line); below it the family line `⌄ 7 opened chats` (`FamilyToggle`, count from `ChatItem.childCount`, whole-row target, chevron at the opener's title edge, turning right when folded; `FoldedOpeners`, default unfolded; `ChatListModel.fold`) heads the family. Children read one size down (callout, 40 dp rows), keep status trailing, and connect to a thin branching line under the chevron (`drawRail`, a smooth curve into each title; only intermediate children continue the trunk) with titles stepped in `TreeLevel`. Children hide a project that repeats their opener's. A folded family's most urgent child status appears at the trailing edge of the count row; the opener keeps its own status. The view menu is a multi-select of those details (`ChatRowDetails`, SharedPreferences, default project + PR); none leaves rows one line. Optional catalog fields (repo, branch, read / message / awaiting times, PRs) are parsed leniently in `runtime/CatalogJson` so older caches still load. `ChatListModel.groups` (pinned, projects by name, unassigned last) feeds the Projects tab. Keep the model pure and covered by `ChatListModelTest`.

- Every Home grouping (time/project/status) starts with a separate Pinned group when nonempty, within the current owner/project scope. Partition whole visible families before bucketing, so pinned families appear once and retain child folding. Project conversation lists use the same projection; archived chats and hidden Tabs never enter Pinned.

- The Chats view menu ends with an Archived switch (iOS `HomeArchive`, #2541 / #2563), held in memory so every launch opens on open chats. While on, the Chats list and its search show only archived chats in activity buckets (`ChatListModel.home(archived = true)`, honouring My tasks; no Pinned group, no project index), the page uses `bgArchived` with titles in tertiary ink, and a loaded catalog without archived chats reads "No archived chats". Settings has no Archived entry. Android has no unarchive write yet, so archived rows only open their conversation.

- Home builds complete parent families before time/status/project bucketing. Tabs and side chats (`parentSessionId`) belong to their conversation and never list, as web `sessionListAtom` (iOS `SessionRows.isTab`, Android `ChatListModel.isTab`; Projects counts skip them too). Families come only from openedBySessionId, then openedByRootSessionId, against visible sessions, an opener that is a Tab resolving to its conversation; do not require matching projects. Only the parent determines the bucket; every descendant stays adjacent under that root. Missing/archived parents and cyclic references must not hide rows. My tasks preserves complete matching families; idle limits count roots and never split a family. Cross-project children keep their project label, and child urgency remains separate from the parent status.

- The entire family line under an opener (`⌄ N opened chats`) toggles child expansion; the separate opener row opens the conversation.

- A parent chat retains its own conversation status, including internal Tabs. When its children are folded, show the most urgent child status between the family chevron and child count; never replace the parent status with a child status.

- Conversation list attention includes its non-archived internal Tabs on the same
  machine, with failed, waiting, running, then unread priority. Side-panel sessions
  and independently opened chats do not contribute. Closed Tabs still contribute
  active status but not unread. Preserve Tab inputs through owner filters, keep
  Tabs hidden as list entries, and apply the summary to status grouping as well as
  row markers without rewriting catalog session state.

- Team conversation lists show a compact circular owner avatar after the trailing time/status (including children), resolved from the workspace member cache with a name-initial fallback. My tasks omit this avatar; special status stays trailing. Titles and project details share the leading edge.

- The Chats project index is enabled only for project grouping with multiple sections and scrollable content. Scrolling reveals a solid icon capsule over the full-width list; it lingers for 800 ms (or the system accessibility timeout) after scrolling or direct interaction ends. Use a short slide transition without fading the opaque surface; remove pointer and accessibility targets as exit begins, and keep targets at least 48 dp apart. Use bounded landmarks when all sections do not fit; taps select the displayed section, scrubs stay anchored through touch slop and can reach every section, and accessibility range actions expose omitted sections. Only the visible capsule accepts taps and scrubs, with no long-press activation or hidden rail. Scrubbing targets rendered headers after family folding. Backgrounding, disposal or unavailable scrolling dismisses the index and cancels pending jumps. Project icons prefer catalog repository identity through the existing image cache, with repository/monogram fallbacks.

- The Chats bottom bar collapses after a user scroll passes the shared spacing threshold: hide tab labels and inactive tabs, contract the capsule toward the leading edge to show only the active icon, and shrink the separate create button. Keep it compact while scrolling back; restore only at the list top. Other tabs use the expanded bar. Retain accessibility labels and stable bottom content insets during the animation.

- Projects tab, while hidden (iOS `ProjectsListController`), restores as follows: the Chats header (`HomeTopBar` with workspace capsule, sync pill, search and its own `ProjectsViewMenu`) and no title; `ProjectCards.build` cards (`ProjectCardView`, `bgSunken`), newest activity first, showing a 40 dp logo centred on both lines (GitHub owner avatar, else the name's initial), the name (`Owner/Repo`), the compact age, the computer (local) or GitHub, and the most pressing open-chat state by `StatusGroup` (needs you, running, just finished, open PRs, else the count). Search filters the cards in place; the view menu holds the shared scope, the source (`ProjectSource`) and hiding projects without open chats (`ProjectViewPrefs`). A project without chats still opens to its empty list.

- On Schedules the create button turns into "+" (`HomeBottomBar(adds)`) and opens a new schedule. A restored Projects tab's "+" toggles `ProjectAddMenu` (two capsules springing up from it over a scrim; Back / scrim fold them). `ProjectAdding` (`LiveProjectAdding`, `LodyApplication.projectAdding`) does the work: local folders through the shared runtime's `localProjects` (bridged as `RuntimeCommand.LocalProjects`: machines, browse, add, cancel), GitHub repositories through Convex with the verified account, as iOS `WorkspaceSettingsCloud` (`github:listWorkspaceReposWithStatus`, `github:setRepoEnabled` for admins / owners with a read back, `github:createGitHubInstallState` → the App's install page). `LocalFolderSheet` picks the computer (skipped when one), browses from home with an up button and a typed path, and adds the open folder; `GitHubRepoSheet` searches the repositories, not-yet-added first.
