# Create session (Android)

Read before changing the new-chat page, creation options, submissions or project groups. These rules bind every caller of the area, not only files in its directory.

- New chat opens `create/CreateSessionScreen` full screen, kept in step with iOS: computer and project as plain full-width lines (no fills) whose options expand in place right below them, aligned with the line (one open at a time; the bottom-anchored panel reveals a list from its top edge so it moves with the layout; project list: No project, five recent, More projects…, search over all), computers with OS icons (`CreateSessionModel.machineKind` from catalog `machineOs`), then the worktree chip (local) or the typed branch line (GitHub), then the composer on a floating overlay surface (+, run-config chip `model · effort · mode` opening a label/value sheet whose rows expand in place, send; no @; one line at rest, three while editing). When the iOS create page changes, change this page in the same change. Creation reads online assistants and advertised models/reasoning/modes through `CreateSessionRepository` using the existing scope lease. GitHub branches use native authenticated Cloud token brokerage followed by bounded GitHub reads; tokens never enter Compose or the WebView. AccountController fences results across logout. The branch picker restores a cached list and selection by account/workspace/repository, refreshes page 1 in the background, and appends further pages on demand. Explicit choices survive refresh, failures retain cached choices, and a computer change does not reset the branch. AtomicCatalogStore retains at most 16 branch snapshots (1 MiB each), clears them with account data and prunes removed workspace access. Keep empty-assistant guidance out of the page; the configuration chip and disabled send state express availability. Send creates the session stream and catalog metadata, ensures the session replica, then uses upstream text-turn persistence and dispatch; a machine ACK is delivery only. Stable session/turn IDs and the attempted state prevent automatic replay after timeouts, suspension or rotation. Unknown results offer opening the conversation, never an automatic resend. Agent Roles follow web's chat landing, as iOS: the run-config sheet leads with a Role row (None, then the selected computer's Roles by emoji + name from the `agentRoles` runtime list; unavailable ones disabled with the reason); picking one selects its agent and seeds its pinned model, mode and reasoning, None clears only the name, and another computer clears it; it names the composer only while `CreateSessionModel.roleApplied` holds (`AgentRoleSelectionTest`): the chip then leads with the Role's emoji instead of the assistant mark, followed by the Role's name and model · effort in secondary ink when a text measure says it fits, else the emoji right before the model, and the placeholder reads "Work with <Role>" (else the assistant). `createAndSend` re-reads the Role, requires it bound to the chosen agent, records `agentRoleId` / revision on the session, and sends the first turn with the Role id, the agent's config id and the Role's other pinned options; the shared runtime applies the prompt prefix and memory or refuses. Attachments and mentions remain unavailable. `CreateSessionModel` is pure and covered by `CreateSessionModelTest`. `CreationJson` owns JSON; UI never handles bridge objects.

- Creation options share the atomic cache lifecycle: persist all providers and model/mode/effort choices by account + workspace + project target, restore before refresh, retain on read failure, and enable Send only after live validation. Options files are separately bounded to 16 snapshots and cleared with account cache on logout.

- An open creation page refreshes on runtime, catalog and presence events, without a polling timer. Unknown presence must not replace cached options. Missing capabilities are probed only for the selected online provider; the RPC reader skips binary-progress frames and merges validated final capabilities into a workspace/provider-scoped display overlay. Keep these changes in the shared source and reviewed snapshot.

- Creating a conversation navigates immediately with the local first turn. `CreationSubmissions` owns the single write in application scope; the form never waits for network acceptance, and leaving the form/chat must not cancel or replay it. Scope changes fence and clear its projection. Keep unknown/rejected results visible on the conversation and deduplicate the first turn by its stable turn ID when the transcript arrives.

- Multi-repository projects (web Project groups): the runtime adapter lists them (`projectGroups`, `RuntimeCommand.ListProjectGroups`) and `createAndSend` with `projectId = group:<uuid>` creates through `projectGroupId` (workspace-wide agents; the runtime checks the computer and capability and writes the frozen `projectRun`). The new-chat page merges runnable groups into its catalog as `group:` projects ("N repositories", `CreateSessionModel.isGroup` / `isUsable`: pinned to their local members' computer or usable on any); no branch line or worktree chip. Catalog sessions with a `projectRun` list under `group:<id>` and carry its members. Android only displays groups ([README](../../README.md#project-groups)).
