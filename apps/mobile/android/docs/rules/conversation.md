# Conversation (Android)

Read before changing the conversation page: the transcript and its turns, composer, action bar, attachments, images, Tabs, message actions, members, PRs or usage. These rules bind every caller of the area, not only files in its directory.

- `chat/ChatScreen` follows web's mobile session page as it runs in the app: a floating header (round back button, title, GitHub repo line) over the transcript, which scrolls beneath it; user turns are large rounded right-aligned bubbles with the delivery mark (web `UserMessageSendStatus`: open circle sent, check read, clock queued), time and sender name above and a 36 dp avatar beside the bubble's top; agent turns follow web's turn layout (`chat/TurnLayout`, pure, `TurnLayoutTest`, over the `TurnItem`s `RuntimeProtocol` parses from the session entry summary): consecutive thought / tool steps form one group whose disclosure row summarizes it ("Ran 3 commands · Read 2 files", chevron trailing, open while the turn runs and closed once it settles) with steps as sibling rows when open (verb in tense + file name / command / title, ±lines, failed / awaiting approval), never a nested scroller; only builtin DSH (`cliType` builtin + `agentType` deepseek) shows thoughts, as their own groups closed by default, with secondary-ink Markdown when opened, and `think` steps never show; a streaming turn stays expanded and ends with the live status (text-only "Working…" / "Thinking…"; the running group and step pulse); a finished turn keeps its answer — the final contiguous text run before the never-folded tail (proposed plans, checklists, notices, plan approvals) — and folds the earlier work under one "Worked for …" disclosure, only when such an answer exists (`TurnViews.kt`; rows use `animateItem`, toggles a context-click haptic, and a toggled row keeps its place on screen: `ChatTranscript` records row keys in order (`KeyRecorder`) and after the toggle's layout scrolls the row back to its previous offset, since the lazy list only pins its first visible row and a fold that removes that row jumped the page); a step with a detail is itself a disclosure whose next sibling row is ONE detail card (web `ToolDetailSheet`: command in code type, output tail, diff lines, selectable text), loaded on first open through the `itemDetail` runtime command (local replica read, `ChatRepository.detail`, cached per step + status in `StepDetails`); background tasks and sub-agents (`TurnItem.Task` from `subagent_task`, run state preferred over legacy status) form, with the turn's changed files (`SessionMessage.files` from entry `fileDiffs`), ONE output card after the live status, matching iOS (`turnOutput`: a tasks row and a files row "N files +a −r", each opening its own near full-screen sheet, `TasksSheet` / `FilesSheet`; the meta footer `turnFooter` — Copy, Info and Fork, then the finish time beside them (iOS `ChatMessageActionsCell`; no model) — always closes the turn). The tasks row (`TaskCard`: spinner / stack glyph cross-fading, "Waiting on N tasks" / "N tasks", the newest running task's latest step, a chevron); tapping it opens `TasksSheet`, a near full-screen `ModalBottomSheet` (`skipPartiallyExpanded`) with a `SingleChoiceSegmentedButtonRow` between Subagents and Tasks when the turn has both (runtime `group`, web `groupOf`; a live segment shows a spinner, segment-tick haptic), then the task list as one card of ruled rows (`cardSegment`, `animateItem`); a row slides to that task's run inside the sheet (`AnimatedContent`, back arrow and system Back slide back); nothing expands inline; colour only for failure; a round scroll-to-latest button appears once the reader scrolls up; the composer is the new-chat composer (web's mobile session page; `ChatComposer` mirrors `create/CreateSessionScreen` `Composer`): always the open card — attachment chips, the prompt (one line at rest, three while editing; "Work with <Role or agent>"), then + (photos / files), the run-config chip (the Role's emoji or the provider mark, model · effort, mode glyph, Plan / Fast when on) and send, which cross-fades to stop while a turn runs and nothing is typed; no @ button. The chip opens the shared `RunConfigSheet` as web's conversation sheet: Role (None first, then only Roles bound to this session's computer AND agent config — `SessionRoles`, web `selectSessionAgentRoles` — unavailable ones disabled with their reason), the conversation's Agent (locked: a conversation never switches agent), Model, Reasoning, Mode, then Plan and Fast switches when the agent offers them (`CreationCapability.planSwitch` / `fastSwitch`). Picking a Role applies only its pins; the turn carries `agentRoleId` while the Role still applies, null once it detaches or None is picked, and nothing while the Role list loads (`RoleSend`); the runtime applies a later turn's Role without its prompt prefix. `TranscriptMargin` is 16 dp. Above the composer, `ChatActionBar` is web's `SessionInfoBar` as grouped raised capsules (36 dp, `barCapsule`) with native `DropdownMenu`s, so the composer stays the only full-width shape: computer (menu names it), context (PR number, else branch, else repository name without owner; CI trouble tints the glyph; the ±diff inside; menu: counts, open the PR URL, copy branch) and, pinned trailing, the repository action as a neutral split capsule (top action on tap with a confirm haptic; chevron menu for the rest). Colour is for status only so Send stays the one accent. It never scrolls: `FirstThatFits` (a `SubcomposeLayout`) probes each stage unbounded and shows the first that fits one line (labels capped at 160 dp, then the diff hidden (counts stay in the context menu), then the context label narrowed in steps down to 40 dp); the narrowest stage clips the context rather than wrapping, so the bar is always one line. The related-conversations button is a 36 dp capsule with the conversations glyph, never a git glyph. `SessionInfoBar` (pure, `SessionInfoBarTest`) ports `resolveSessionInfoBarGitHubActionIds` (Commit & Push first on unpublished work; Create PR / Draft without a PR; Resolve Conflicts on merge state `d`; Fix CI on `f`/`e`; Ready for review on a draft; Merge whenever GitHub would accept it (merge state `c` or `u`, so also while CI runs), kept in the menu behind Commit & Push; nothing while busy) and web's localized prompts, sent through the ordinary turn path only while still offered. Merge (after `MergeSheet`, a bottom sheet of merge / squash / rebase that doubles as confirmation, last method first) and Ready for review write to GitHub directly: `GitHubPullRequestWrites` gets a Lody Cloud brokered write grant (`getOperationAccessTokenByRepoNameForClient`, operation write) under `AccountController.withVerifiedAccount`, merges with the head SHA it just read (409 = head moved) or runs GraphQL `markPullRequestReadyForReview`; never retried, and a lost response is reported as unknown. Goal and schedule stay on web. The catalog carries `diff`, `workspaceDirty`, `workspaceUnpushed` and PR `url` / `merge`. Senders other than the signed-in user show as Member until the member list is loaded.

- Sending is live (no read-only label): `ChatRepository.send` runs the `sendText` runtime command (Android adapter over upstream `sendTurn`) with a fresh stable turn id; running sessions queue. An optimistic bubble shows until the transcript carries the turn id; `not_sent` marks it failed, an uncertain result stays sent, and nothing is resent automatically. The one exception is `not_sent` with `previous_input_pending`: an earlier Roost input still awaits its owner and nothing was written, so the bubble stays sending and the same turn id is sent again, as on Web. The catalog supplies the session's machine, cliType, agentType and resume; the session entry summary carries `userId`. The chip shows the latest user turn's config from the session snapshot (runtime `composer` → `SessionSnapshot.composer` / `RunChoice`, as iOS `composerJSON`) and sends nothing while untouched (upstream keeps it); the first change copies that config and from then on the whole choice rides on each turn (`SendTextRequest.explicitChoice`: a null model / effort clears to the agent default, a null mode keeps it), like iOS `hydrated`.

- The conversation composer rests as one capsule line (+, the prompt, the agent's mark (no chevron) opening the run-config sheet, Send / Stop) and opens into the new-chat card while editing or with attachments waiting; the one text field stays in place across both, so focus and the keyboard survive.

- The conversation composer's mark is a Compose shared element between its trailing collapsed button and leading expanded run-config button, following the composer's spring in both directions. `ComposerMotionProbeActivity` exercises the production composer offline without changing account data.

- Conversation navigation uses full-screen directional enter/back transitions without a route size transform (IME resizing owns the page height). The transcript starts at the latest row and follows measured tail/viewport geometry, including keyboard and composer changes. Only user drags leave following; explicitly jumping to latest restores it. Use the stable end row rather than an unbounded scroll offset. Keep sender projection memoized across composer-only updates.

- Only the final visible content activity group shimmers while its turn is working; hidden thoughts and think tools are filtered before grouping, and task/footer bookkeeping does not displace it. Later visible prose or persistent content stops the earlier group’s shimmer. Tool activity groups start collapsed even while the agent is running; preserve explicit user toggles across streaming updates. Expanded tool rows show one ellipsized line, with full output available through the existing detail disclosure. DSH thought-only groups retain their own default.

- A turn's output card stacks the tasks row (`TaskCard`) and the changed-files row (`FilesRow`), both built on the shared `OutputRow` (leading glyph or live spinner, title, caption, trailing, chevron) as card segments, then the actions/time footer, always last. Each row opens its own near full-screen sheet: tasks open the task sheet; files open `FilesSheet` (the file list with totals), and a file slides (`AnimatedContent`, back via `BackHandler`) to its diff (`DiffPage`): the `turnDiff` command (contract bridge → sealed machine RPC to the session's computer) returns the text before and after the turn, and `LineDiff` (pure, `LineDiffTest`) computes hunks with three lines of context off the main thread — gutter line numbers, diff tints, folded unchanged runs, selectable text; binary, oversized and unavailable diffs say so.

- User messages expose Copy and, only for the runtime-confirmed latest editable turn, Edit through a long-press menu, not inline buttons. User text collapses to six lines with Show more / Show less. Finished assistant footers align Copy, Info and Fork with the message edge, packed with overlapping 48 dp touch targets as on iOS, with the finish time beside them. Copy uses visible answer text (not folded work). Edit reads the original draft and retains its attachment IDs; send and fork are never replayed after uncertain delivery. Fork continues from the selected completed provider turn in a new Tab, sharing the current working directory. Android work duration follows Web/iOS: prefer the turn timestamp, fall back to startedAt, subtract permissionWaitMs, and localize minute/second units; unknown timing shows execution details, not a fabricated duration.

- Attachments (iOS `SessionAttachments`): + opens a menu of Photos and videos (system Photo Picker) and Files (`OpenMultipleDocuments`); picks wait as removable chips above the prompt (at most 8 images + 8 files; videos go as files) and upload only on send. `SessionAttachmentUploads` sends the bytes natively to the build-configured Worker session-images / session-files endpoints with the verified account bearer (`withVerifiedAccount`): images over 5 MiB or in other formats re-encode to JPEG (longest side 2048); files up to 100 MiB carry sha256 and a text-preview probe, and above 16 MiB go in multipart parts (aborted on failure). Only the returned `image` / `file` blocks reach `sendText` (`attachments` → upstream `attachmentBlocks`); a failed upload fails the turn before anything is written and hands text and attachments back to an empty composer. Nothing is retried. User turns show their attachments as chips above the bubble (`MessageAttachment`, parsed from `image` / `image_group` / `file` items; attachment-only turns stay). Stop runs `StopTurn` (bridge `controlTurn` → upstream `controlTurn` stop on the watched session), one at a time, never retried; a failure shows a snackbar.

- Plans follow web's one plan surface (`plan-surface.ts`). `chat/PlanCards` renders a `proposed_plan` item (Codex) and the plan a plan-approval (`switch_mode`) step carries (runtime `plan`: Claude's `rawInput.plan`, Kimi's first text block) as the same raised card: a "Proposed Plan" header with a copy action, then the plan through the transcript Markdown renderer. A step's carried plan shows only when the turn has no non-empty `proposed_plan`, so the plan never prints twice, and in a turn with a `proposed_plan` the plans move just before the approval step (or to the turn's end), with images and files after them (`TurnLayout.planOrder`, web `buildAssistantMessageRenderItems`). A plan opens in full while its turn's approval is unanswered or while it is still being written; otherwise it clamps to 240 dp with a fade, and its header toggles it. A plan the reader decided on does not collapse under them.

- A pending plan approval is answered in the transcript, standing in for desktop's composer prompt: the plan card (or, for Codex, a row under its `proposed_plan`) ends with the provider's options in the provider's order and words, allow kinds filled and reject kinds quiet. An answer goes through the `respondPermission` runtime command (bridge over the shared runtime's `respondPermission`; `ChatRepository.respondPermission`), one at a time, never retried; a stale request, an answer recorded elsewhere, an invalid option and a failed send each show their own copy. Only a live, open conversation offers the options; otherwise, or without options, the approval reads "Waiting for your answer". Once answered, the chosen option's name (read from the step's `itemDetail` outcome, since the summary only says it is settled) is a one-line record; a withdrawn request shows nothing. A `switch_mode` step without a plan or a permission stays an ordinary step. Other permission requests are not answered on Android.

- Agent images (`TurnItem.Images`) are never folded; images that only tool work separates share one fanned stack (`TurnLayout`), and prose ends it. Reads use the verified account bearer without redirects; Copy, Save and Share use the original bytes. See [Conversation images](../../../README.md#conversation-images).

- Agent provider marks follow web `AgentIcon` (`home/AgentLogo`, `AgentMark`, `AgentLogoTest`): builtin / registry agents by agentType (aliases `claude-p`, `claude-code`, `kimi-code`, `grok-build`, `pi`), custom commands a terminal, unknown agents the generic bot. They appear in the create page's agent options, run-config sheet and chip and the conversation chip. The drawables (`res/drawable/lody_agent_*.xml`) and `AgentLogos.generated.kt` are generated from the iOS agent SVGs by `node android/scripts/agent-icons.mjs` (`--check` fails on stale output); do not edit them by hand.

- Conversation sender identities load native `/api/auth/organization/list-members` pages by workspace and match `userId`, never membership `id`. `WorkspaceMembers` emits the account/workspace cache before a background refresh; failures retain it. `AtomicCatalogStore` persists only ID, name and HTTPS avatar URL, prunes removed workspaces and clears members on logout. `AccountController` fences network results across account changes. Member updates refresh names/photos independently of message rendering.

- Conversation avatars prefer the workspace member projection over the login snapshot, including the signed-in sender and optimistic turns. `AvatarImages` caches public HTTPS image bytes in `cacheDir/avatars-v1` (16 MiB / 128 files, URL-hashed keys), displays cached images first, and refreshes disk entries older than one day without removing the cached image on failure. Same-URL loads are serialized.

- Current-working-directory conversations open from the trailing conversations button only when open child Tabs exist. Its status summarizes other open conversations with local read watermarks. More owns “新建当前目录对话” and closed-conversation recovery even when the button is hidden. Keep close/restore semantics unchanged. The tappable secondary machine subtitle below the title shows presence before the name and opens owner/visibility details; do not duplicate it in the bottom action bar.

- The repository context popover leads with repository name and a small one-line branch plus trailing copy button. Its aligned action columns show View PR / #number (never localized digit grouping) and All changes / coloured ±counts. Compact capsules omit diff counts without substituting an unexplained dot; short PR labels use intrinsic width.

- The PR panel (`PullRequestSheet`) offers Merge while the PR is open, opening `MergeSheet` as the confirmation. Once merged, it offers Delete branch after a confirmation dialog, only while the PR's own same-repository head branch exists (`GitHubPullRequestWrites.headBranchExists`). `deleteBranch` re-reads the PR with the write grant, treats a branch already gone as deleted, and is never retried.

- A transcript link to a PR in the session's project, including a multi-repository project's GitHub members, opens the PR panel; other links open in the browser. See [PR links](../../README.md#pr-links).

- Free-plan limits follow web and iOS: the session envelope's `billableTurnCount` (user turns plus queued inputs) drives the composer; once it reaches 25 the page reads the plan (`WorkspacePlan`), and on a Free workspace a notice above the composer says how many of the 30 messages remain, then closes the composer at 30. The runtime remains the gate: `free_session_turn_limit_reached`, `free_session_limit_reached` and `workspace_payment_required` refusals wrote nothing, show their own copy and hand the draft back. A turn with attachments first asks the runtime's `turnQuota` (upstream `checkTurnQuota`) so a refused turn uploads nothing; a failed check admits it and the send checks again. Opening a Free session already at its limit shows one alert per visit (iOS `announceQuota`), and the closed composer reads "Message limit reached". Files (and videos) over 100 MB are refused when picked, with their name, in both composers.
- Conversation usage is a display-only session projection (`SessionUsageJson`): context tokens take precedence, compacting replaces the ring, and quota-only rings prefer the five-hour window (including zero) then the longest reported window. The runtime emits `usage.quota` only after eligibility and selected provider/config/model resolution; native requires `quotaEligible: true`; native code must not infer subscription eligibility from provider names or per-turn token totals. Missing data stays hidden; an explicitly reported empty plan says unavailable. Reset times switch between localized relative and absolute presentation.

- Operation receipt cards are display-only. Preserve creation-progress duplicate
  suppression and failure/cancellation details. Related-conversation navigation
  requires the exact target and its containing root in the current catalog;
  opened-by provenance never becomes Tab containment. Relation trees group a root
  and its contained Tabs in one horizontally scrollable row without a scrollbar,
  with overflow edge fades; only opened-by conversations receive hierarchy depth
  and curved connectors. See the conversation
  behavior in [README.md](../../README.md).
