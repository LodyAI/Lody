# Schedules (Android)

Read before changing the Schedules tab, its editor or its cache. These rules bind every caller of the area, not only files in its directory.

- Schedules (web `schedule-list.tsx` / `schedules-workspace.tsx`, `schedules/`): the tab follows the Chats list's design language: flat rows grouped as on web into Scheduled tasks and Scheduled messages (`scheduledMessage`; empty groups hide) under the Chats section title, each group ordered by runtime `state` group (needs attention, active, paused, ended), filtered by the search query. The header's view menu holds a Show finished switch, in memory and off at launch: ended schedules (they will not run again) stay hidden until it is on, and a list with only hidden ones offers to show them. A row shows the name (dimmed once ended) with the status in words trailing, then a kind glyph (message, manual, timed), the frequency and computer · project; only the `attention` group is tinted. Its long-press menu offers Pause / Resume for a timed task, Run for a manual one, Open last chat and Delete, which always confirms; writes are owner-only, and resume and run also need `machineSupported`. The list refreshes on show, pull, workspace or connection change and after every command. The editor reads computers, Agents, models and modes from creation options, projects from the catalog, and authors wall-clock rules in `machineTimeZones[machineId]`, else `deviceTimeZone`. An untouched received rule, including `unsupported`, is sent back exactly as received. Scheduled messages, `existing_session` destinations and other users' schedules are read-only. A new schedule's id is a lowercase UUID chosen once per editor; every intent gets a fresh `requestId`, reused only to retry the same attempt after `schedule_write_unknown`, which asks the reader to check before retrying. `ScheduleForm` is pure and covered by `ScheduleFormTest`; the bridge and stream gates are described in [runtime snapshot](../runtime-snapshot.md#schedules).

- Schedule lists restore account/workspace display snapshots before live refresh, share account-cache pruning and logout fencing, and never persist optimistic intents. Pause/resume update immediately, suppress concurrent row commands, roll back failures and reject older reads; refresh again after completion.
