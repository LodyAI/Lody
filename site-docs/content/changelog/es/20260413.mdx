### Cambios incompatibles y migración

- Después de actualizar, es posible que debas volver a iniciar sesión.
- Si utilizas GitHub Worktree, la máquina que ejecuta el agente debe estar configurada con tu identidad de GitHub (mediante `gh auth`); de lo contrario, usaremos de forma predeterminada la identidad `lody` para crear el Pull Request.
- Lody ha cambiado a un nuevo motor de sincronización y estructura de datos. Los espacios de trabajo anteriores dejarán de estar disponibles, por lo que deberás crear un nuevo espacio de trabajo para usar Lody.
- Lody ya no solicita permisos de identidad personal de GitHub a los usuarios. Como resultado, ya no ofrecemos la posibilidad de autorizar un mismo repositorio de GitHub una sola vez para compartirlo entre varios espacios de trabajo. Ahora un repositorio solo se asocia con un único espacio de trabajo.

### ✨ Sesiones con múltiples pestañas

Ahora puedes abrir múltiples pestañas de conversación y visores de archivos dentro de una misma sesión. Al igual que la barra de pestañas de VSCode, puedes chatear con el agente a la izquierda mientras ves archivos y diffs a la derecha sin interrumpir ninguno de los lados. Las pestañas secundarias heredan el directorio de trabajo de la pestaña principal y admiten reordenamiento mediante arrastrar y soltar, así como cambio de nombre.

### 🖥️ Modo daemon

La CLI ahora admite el modo daemon, manteniendo Lody en ejecución en segundo plano con reinicio automático:

```bash
lody daemon start     # Iniciar el daemon en segundo plano
lody daemon status    # Comprobar el estado
lody daemon logs      # Ver los registros
lody daemon stop      # Detener el daemon
```

### 🔗 Mejoras en la integración con GitHub

- El estado de las comprobaciones de CI de los PR se sincroniza en tiempo real con la interfaz de la sesión, de modo que no necesitas cambiar a GitHub para ver los resultados de compilación
- Las sesiones vinculadas a un PR admiten commit y push automáticos

### 🌐 Sincronización y estabilidad

- Se reemplazó el motor de sincronización para mejorar la fiabilidad
- Límites de recursos de la CLI adaptados a cgroups para evitar bloqueos en entornos de contenedores Linux
- El tiempo de espera por inactividad de ACP se redujo a 30 minutos para ahorrar recursos
- Liberación automática de sesiones ante presión de memoria
