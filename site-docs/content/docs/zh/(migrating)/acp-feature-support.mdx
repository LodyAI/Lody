# ACP 与扩展能力支持一览

本页面向从 Codex、Claude Code 或其他 ACP Agent 迁移过来的读者：你原本用的能力，换到 Lody
之后哪些还在。页面先说明 ACP 是什么、Lody 如何扩展它，再给出每个内置 provider 的支持矩阵。
如果还没有接入运行时，请先看[从 Codex 或 Claude Code 过来](/zh/docs/from-codex-claude-code)
或 [Agent Config](/zh/docs/quickstart)。

## ACP 是什么

[Agent Client Protocol](https://agentclientprotocol.com/)（ACP）是客户端（你使用的应用）与
Agent（真正执行工作的运行时）之间的开放协议。Lody 是 ACP 客户端：它启动 provider 的 ACP
服务，在 `initialize` 阶段协商能力，然后通过同一条连接交换 prompt、流式更新、工具调用、权限
请求和会话生命周期事件。

ACP 只覆盖共同的核心，因此两个 ACP Agent 在可选能力上仍可能不同：图片、内嵌上下文、会话恢复
或 Fork、MCP 传输、提问（elicitation）等等。所以 Lody 会协商能力，而不是默认它们存在。所有
内置 provider 都具备同一套基线：文本 prompt、流式更新、工具调用、权限请求、取消，以及 Lody
提供的文件系统与终端回调。

## Lody 如何扩展 ACP

Lody 自己的扩展能力定义在 [`acp-extension-core`](https://github.com/LodyAI/acp-extension-core)
里：这是 ACP v1 之上、与 provider 无关的契约。流式子代理事件、用量记账、速率限制、持久目标、
上下文压缩等能力需要一份稳定的共享描述，因此每项能力独立版本化，并通过 `_meta.lody` 单独声明：

- Agent 在 `InitializeResponse.agentCapabilities._meta.lody` 上声明自己实现的能力；
- 客户端在 `InitializeRequest.clientCapabilities._meta.lody` 上声明自己支持的能力；
- 缺少某个键就表示对方不支持该项能力，支持其中一项绝不代表支持其他项。

公开的 `acp-extension-*` 适配器把各运行时翻译成这套契约，因此无论连接背后是哪个 provider，
Lody 客户端读到的结构都一致。自定义或注册表里的 ACP Agent 也可以实现同样的键。具体 payload
见[能力一览](https://github.com/LodyAI/acp-extension-core/blob/main/README.zh.md#%E8%83%BD%E5%8A%9B%E4%B8%80%E8%A7%88)。

### 扩展能力说明

`Lody：`列描述的是 provider 声明了什么。以下是每一列对应的 provider 侧能力：

- **子代理事件** —— 适配器通过 `_lody/subagents/event` 推送子代理运行的快照、进度和输出。
- **会话标题** —— 适配器生成标题，并以带 `_meta.lody.titleSource` 的标准
  `session_info_update` 推送。
- **用量** —— 标准 `usage_update` 上的上下文与 token 记账，按模型累计。
- **速率限制** —— 通过 `_lody/rate_limits/update` 推送额度快照，可选
  `_lody/rate_limits/get` 查询。
- **按轮 Fork** —— `session/fork` 可以指定从哪一轮历史分叉。
- **转向** —— 通过 `_lody/session/steer` 或 `_meta.lody.steer` 向进行中的轮次注入指引。
- **任务** —— 后台或定时任务沿用普通工具调用生命周期，并带 `_meta.lody.task`。
- **子代理** —— 子代理生命周期，以及可选的列表、取消和输出查询。
- **持久目标** —— 跨单条 prompt 存续的会话目标，支持 set、pause、resume、clear。
- **上下文压缩** —— 以带 `_meta.lody.activity` 的工具生命周期上报上下文压缩和重试。

注释：

1. **任务：** Claude Code、Codex、Kimi Code 声明的是后台任务；Grok 声明的是定时任务。没有
   provider 同时声明两者。
2. **子代理：** Claude Code 和 Codex 只声明生命周期，不声明列表、取消或输出查询。
3. **Grok 任务**只有定时任务。
4. **Kimi Code 会话标题**仅在安装的 Kimi 引擎支持其标题功能时才会声明；否则由 Lody 自己
   生成标题。
5. **DeepSeek Harness 图片输入**取决于所选模型。只有当前模型声明支持图片输入时，适配器才会
   开启该能力。
6. **Dimcode MCP：** Dimcode 声明 Streamable HTTP 和 SSE，但报告不支持 stdio MCP。

`ACP：MCP` 一列中，`HTTP+SSE` 表示 provider 声明了两种传输，`HTTP` 表示只声明了 HTTP。stdio
通常是 ACP 的默认 MCP 传输；Dimcode 是注释 6 中的例外。`Devin` 和 `Grok` 的标准 ACP 能力来自
其官方运行时，Lody 列则显示 Lody 兼容代理额外添加的能力。`Bub` 和 `Dimcode` 是 Lody 启动的
外部 ACP 服务，它们两行的结果来自这些服务自己的声明，包括它们直接实现的 Lody 扩展。

上表反映 Lody 适配器和外部 ACP 服务随版本声明的能力。Lody 会在会话建立时读取协商结果，因此
provider 升级后，应用里显示的能力可能先于本页更新。若要查看标准 ACP 实现的独立、带版本的对比，
见 [ACP Wall](https://github.com/wibus-wee/acp-wall)。
