# 代理配置

Agent Config 将编程运行时与它的设置、认证和执行机器连接起来。Lody 支持内置集成、托管运行时、
模型服务预设、Registry 运行时和自定义 ACP 命令；统一界面不代表各运行时的能力完全相同。

产品概览见 [One GUI for Your Coding Agents（英文）](/coding-agent-gui/) 和
[Remote Control for Your Coding Agents（英文）](/coding-agent-remote-control/)。

## 选择集成方式

| Agent 或模型服务 | Lody 中的配置 | 需要区分的边界 |
| --- | --- | --- |
| Codex | 选择 Codex，使用机器上的受支持登录或配置 | 模型与控件取决于运行时和账号 |
| Claude Code | 选择 Claude Code 并配置认证 | Lody 从配置中发现可用命令和模式 |
| Kimi Code | 选择托管 Kimi Code Provider 并登录 | 原生 Kimi Code 与通过 Claude 兼容端点使用 Kimi 不同 |
| GLM over Claude Code | 使用 GLM 预设，选择匹配的端点并填写 API Key | 通过 Claude Code 运行的模型服务预设，并非独立原生 GLM Agent |
| DeepSeek Harness | 选择内置 ACP Provider，配置端点和 Token | 与 DeepSeek over Claude Code 不同；委派限制见下文 |
| Pi | 在受支持的机器上选择内置 Pi Provider | 托管运行时；模型和扩展支持取决于固定版本的运行时 |

执行机器需要具备运行时所需的认证和依赖。远程工作还要求机器保持唤醒、联网，且 Lody CLI 持续运行。
此列表说明集成路径，不代表每个模型、模式、扩展或移动客户端均经过端到端验证。要求见
[移动端访问](/zh/docs/mobile/) 和 [CLI 类型支持](/zh/docs/cli-runtimes/)。

## 认证

Lody 会自动使用启动 CLI 的机器上的 Claude Code / Codex 的订阅登录，你也可以使用环境变量的方式来配置其他的使用方案。

非订阅登录的方式你可以在 **设置**-**Agent 配置** 中点击加号按钮，创建新的配置，对于 Claude Code 在配置类型中选择 **Claude**。

<img src="/_docs-assets/agent-config-select.png" width="200px" alt="Agent Config 运行时选择器" />

以下是官方以及第三方的 API Key 方案的配置方式，可以复制粘贴到环境变量中，并替换你的真实的 API Key

如果你的 ACP 兼容 Agent 尚未发布到 ACP Registry，可以选择 **Custom ACP** 并自行填写启动命令。具体步骤和命令解析规则见
[CLI 类型支持](/zh/docs/cli-runtimes#自定义-acp-agent)。

Agent Config 可以共享给团队，让同事使用同一套 CLI 配置。要交接正在跑的会话——而不只是配置——见[共享并交接 Agent 会话](/zh/docs/session-handoff)。

## Claude

```
ANTHROPIC_AUTH_TOKEN=${CLAUDE_CODE_API_KEY}
```

## DeepSeek

```
ANTHROPIC_BASE_URL=https://api.deepseek.com/anthropic
ANTHROPIC_AUTH_TOKEN=${DEEPSEEK_API_KEY}
API_TIMEOUT_MS=600000
ANTHROPIC_MODEL=deepseek-chat
ANTHROPIC_SMALL_FAST_MODEL=deepseek-chat
CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1
```

[参考文档](https://api-docs.deepseek.com/zh-cn/guides/anthropic_api)

### DeepSeek Harness

Lody 内置 **DeepSeek Harness** ACP Provider。新建 Agent Config 并选择 DeepSeek Harness 后，
在 **DeepSeek 官方** Tab 中只需填写 DeepSeek API Token；在 **自定义 Endpoint** Tab 中可以填写
兼容 Harness 的 HTTP(S) API Endpoint 及对应 API Key。Lody 会将它们保存为
`DEEPSEEK_BASE_URL` 和 `DEEPSEEK_API_KEY`，无需另外安装 standalone `dsh` 命令。保存官方配置时
会显式使用 `https://api.deepseek.com`，避免启动机器环境中已有的 Endpoint 变量意外改写配置。

> **已知的委派限制：** 当会话使用 DeepSeek-V4-Pro 以外的模型时，委派的子智能体可能仍会使用
> 会话创建时写入的 DeepSeek-V4-Pro，而不是父会话界面显示的模型，因而可能产生更高费用。继承
> 行为的修复进展请关注 [DSH 上游讨论](https://github.com/deepseek-ai/deepseek-harness/discussions/4065)。

Lody 遵循标准的 `DSH_HOME` 路径，因此单独安装的 `dsh` 可能与 Lody 共用
`~/.dsh/sessions`。Harness 要求一个 session root 只能使用一种压缩格式：对于空 root 或已有
压缩工件的 root，Lody 使用上游默认的 `zstd`；对于仅包含旧版未压缩工件的 root，Lody 继续使用
`none`。如果 root 同时存在 `session.jsonl` 和 `session.jsonl.zstd`，Lody 会在启动 Harness 前
停止，并保持所有工件不变。请先备份并将整个 root 迁移成同一种格式，或为 Lody 使用独立的
`DSH_HOME`。

共用 root 只表示两个安装可以共存，并不表示它们的 ACP session 可以互相恢复。这个 Provider 与
**DeepSeek over Claude Code** 不同；后者通过 DeepSeek 的 Anthropic 兼容接口运行 Claude Code。

## Kimi

Lody 内置 **Kimi Code** 托管 Agent Provider。创建或配置 Agent 时选择 Kimi Code，并完成登录即可使用；Lody 会在当前机器上管理所需 Runtime，无需单独安装或维护命令。

如果希望通过 Claude 兼容端点使用 Kimi，仍可使用以下环境变量配置：

```
ANTHROPIC_BASE_URL=https://api.kimi.com/coding/
ANTHROPIC_API_KEY=sk-kimi-xxxxxxxxxxxxxxxxxxxxxxxxxx  # 生成的 API Key
```

[参考文档](https://www.kimi.com/code/docs/more/third-party-agents.html)

## Pi

Lody 在受支持的机器上通过经过校验的托管 ACP 运行时提供 Pi。请在执行机器上或 Provider 环境中
配置认证，再选择该 Pi 配置开启对话。可用模型和模式由运行时提供。

当机器支持内置 Pi 时，旧版 Pi 配置可能提供需明确确认的迁移入口。迁移会保留 Provider 配置，
但不会转换旧的原生会话 ID；迁移后请开启新对话。扩展控件需要兼容的运行时和机器能力，
不能假设任意 Pi 扩展或终端界面都能在 Lody 中使用。

## Bub

Lody 内置 **Bub** ACP Provider。与上面的托管 Runtime 不同，Bub 需要你自行安装，Lody 只提供集成、不负责下载命令。请先在提供 `bub` 的环境中安装 Bub 及其 ACP Server 插件：

```bash
curl -fsSL https://bub.build/install.sh | bash -- --preset acp
```

然后在新建 Agent Config 时选择 **Bub**。Lody 会启动 `bub acp` 并通过 ACP 与其通信。如果命令不存在或启动失败，Provider 验证界面会给出安装提示并链接到下述教程。

[安装指南](https://bub.build/docs/tutorials/acp-server/?utm_source=lody)

## GLM

最快的方式是在 **设置**-**Agent 配置** 中选择 **GLM over Claude Code** 预设，先选择与 API Key 匹配的
端点，再粘贴你的 GLM API Key，其余配置会自动注入。

智谱 BigModel 端点（国内）：

```
ANTHROPIC_BASE_URL=https://open.bigmodel.cn/api/anthropic
ANTHROPIC_AUTH_TOKEN=<GLM_API_KEY>
ANTHROPIC_DEFAULT_OPUS_MODEL=glm-5.2[1m]
ANTHROPIC_DEFAULT_SONNET_MODEL=glm-5.2[1m]
ANTHROPIC_DEFAULT_HAIKU_MODEL=glm-4.7
CLAUDE_CODE_AUTO_COMPACT_WINDOW=1000000
CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1
API_TIMEOUT_MS=3000000
```

如果使用 z.ai 国际端点，其余保持不变，只需替换 Base URL：

```
ANTHROPIC_BASE_URL=https://api.z.ai/api/anthropic
```

请在所选端点的控制台（open.bigmodel.cn 或 z.ai）创建 API Key。

## MiniMax

最快的方式是在 **设置**-**Agent 配置** 中选择 **MiniMax over Claude Code** 预设，只需粘贴你的 `MINIMAX_API_KEY`，其余配置会自动注入：

```
ANTHROPIC_BASE_URL=https://api.minimaxi.com/anthropic
ANTHROPIC_AUTH_TOKEN=<MINIMAX_API_KEY>
API_TIMEOUT_MS=3000000
CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1
ANTHROPIC_MODEL=MiniMax-M3
ANTHROPIC_DEFAULT_SONNET_MODEL=MiniMax-M3
ANTHROPIC_DEFAULT_OPUS_MODEL=MiniMax-M3
ANTHROPIC_DEFAULT_HAIKU_MODEL=MiniMax-M3
```

[参考文档](https://platform.minimaxi.com/docs/coding-plan/claude-code)

## 小米 MiMo

最快的方式是在 **设置**-**Agent 配置** 中选择 **MiMo over Claude Code** 预设。该预设同时支持按量 API Key 和 MiMo Token Plan。

按量 API Key 示例：

```
ANTHROPIC_BASE_URL=https://api.xiaomimimo.com/anthropic
ANTHROPIC_AUTH_TOKEN=sk-xxxxx
ANTHROPIC_MODEL=mimo-v2.5-pro
ANTHROPIC_DEFAULT_OPUS_MODEL=mimo-v2.5-pro
ANTHROPIC_DEFAULT_SONNET_MODEL=mimo-v2.5-pro
ANTHROPIC_DEFAULT_HAIKU_MODEL=mimo-v2.5-pro
CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1
CLAUDE_CODE_DISABLE_NONSTREAMING_FALLBACK=1
```

Token Plan 需要使用 `tp-` 开头的 Key，并填写 MiMo 订阅页提供的 Anthropic 兼容 Base URL，例如：

```
ANTHROPIC_BASE_URL=https://token-plan-cn.xiaomimimo.com/anthropic
ANTHROPIC_AUTH_TOKEN=tp-xxxxx
ANTHROPIC_MODEL=mimo-v2.5-pro
ANTHROPIC_DEFAULT_OPUS_MODEL=mimo-v2.5-pro
ANTHROPIC_DEFAULT_SONNET_MODEL=mimo-v2.5-pro
ANTHROPIC_DEFAULT_HAIKU_MODEL=mimo-v2.5-pro
CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1
CLAUDE_CODE_DISABLE_NONSTREAMING_FALLBACK=1
```
