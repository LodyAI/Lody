# 设备资源监控

Lody 可以展示每台已连接设备以及其中每个驻留 ACP session 的当前资源使用情况。你可以通过这个页面
找到占用 CPU 或内存的 Agent、打开对应 session，或者在不删除对话的前提下终止 ACP 进程。

进入 **设置 -> 设备**，然后选择一台在线设备。页面会自动开始采样和刷新，不需要手动点击刷新。

## 什么是驻留 ACP Session？

每个对话都会通过一个 ACP 进程与编程 Agent 通信。一次任务进入空闲状态后，这个进程仍可能继续驻留，
以便更快地处理下一轮对话，但它也会继续占用一部分内存。ACP sessions 表格展示的是当前仍有 Agent
进程存在于所选设备上的对话。

因此，这里是进程视图，并不是所有已保存对话的列表。即使某个对话的 ACP 进程已经停止，对话本身仍会
保留在 Lody 中，只是不再显示在这张表格里。

## 资源概览

页面顶部按照三个范围展示资源。它们的统计边界不同，不应该直接相加：

| 范围             | CPU                                                         | 内存                                      |
| ---------------- | ----------------------------------------------------------- | ----------------------------------------- |
| **CLI**          | Lody CLI 控制进程自身使用的 CPU                             | Lody CLI 控制进程自身使用的内存           |
| **ACP sessions** | 所有驻留 ACP session 进程树使用的 CPU 总和                  | 所有驻留 ACP session 进程树使用的内存总和 |
| **设备信息**     | 整台设备的 CPU 使用量，包括 Lody、Agent、操作系统和其他应用 | 设备已用内存 / 有效总内存                 |

**设备信息并不等于 CLI 与 ACP sessions 之和。** 它还包含机器上的所有其他进程；CLI 和 ACP
sessions 两项则用于判断设备资源中有多少是由 Lody 使用的。

### CPU 百分比

三个范围使用相同的多核百分比口径：

- 一个逻辑核心完全占用时为 `100%`
- 两个逻辑核心完全占用时为 `200%`
- 在 8 核设备上，设备 CPU 的理论上限约为 `800%`

例如，一个 ACP session 平均使用 1.5 个核心时会显示 `150%`。由于各项数据来自短时间采样窗口，
并且不同平台的进程树统计方式不同，设备、CLI、ACP 汇总值和单个 session 之间可能暂时存在少量误差。

### 内存

内存表示当前驻留内存足迹，而不是进程从启动以来累计申请过的内存。具体统计方式取决于操作系统：
可用时 Lody 会使用 cgroup 统计，否则会统计相关进程树。在 macOS 上，物理内存足迹与只汇总 RSS
的工具可能显示不同结果。

设备内存以 **已用 / 有效总内存** 展示。如果 Lody 运行在容器或受 cgroup 限制的环境中，“有效总内存”
可能是内存限制，而不是宿主机实际安装的内存。可用内存、缓存、共享页面和平台统计方式也会导致各行
内存手动相加后与设备总量不完全一致。

### 为什么有些值会显示 `-`

CPU 使用量需要通过前后两次采样的变化计算，因此刚开始监控或 CLI 重启后的第一份样本无法显示 CPU。
如果操作系统不能可靠统计某个 session 的进程树，它的 CPU、内存或进程数也可能显示 `-`。可以先等待
下一次自动采样；如果之后仍然没有数值，请确认设备在线，并将该设备的 Lody CLI 更新到最新版本。

## ACP Session 表格

每一行对应一个驻留对话：

| 列          | 含义                                                                                                             |
| ----------- | ---------------------------------------------------------------------------------------------------------------- |
| **Session** | 对话标题、ACP 名称和 ACP Logo。点击这一列会打开对应 session 和正确的标签页；标题被截断时，悬停可以查看完整标题。 |
| **状态**    | 当前 ACP 的生命周期或活动状态                                                                                    |
| **内存**    | 当前归属于该 session ACP 进程树的内存                                                                            |
| **CPU**     | 该进程树使用的 CPU，一个逻辑核心满载为 `100%`                                                                    |
| **进程数**  | 当前归属于该 session 的进程数量，包括被追踪的子进程                                                              |

表格最多展示 100 个驻留 session。进程创建或退出后，监控数据可能有短暂延迟；在需要通过进程树估算
归属关系的平台上，这种延迟可能更明显。

### 状态说明

| 状态           | 含义                                              |
| -------------- | ------------------------------------------------- |
| **正在初始化** | Lody 正在启动或连接 ACP 进程                      |
| **运行中**     | Agent 正在处理一轮任务                            |
| **等待授权**   | Agent 已暂停，正在等待用户处理权限请求            |
| **正在收尾**   | Agent 的主要工作已经完成，Lody 正在执行最后的处理 |
| **空闲**       | ACP 进程仍然驻留，但当前没有处理任务              |
| **正在停止**   | 已发起终止请求，Lody 正在等待进程退出             |
| **失败**       | 驻留 session 或其 ACP 进程发生错误                |

## 释放 ACP Session 资源

点击 session 行末尾的停止图标，可以终止该 session 的 ACP 进程。停止空闲进程会直接执行；如果
Agent 正在运行、初始化、等待授权或收尾，Lody 会要求二次确认，因为当前任务会被中断。

停止图标会原地显示 loading，直到 ACP 进程已经退出，并且设备监控确认该 session 不再驻留。
如果终止失败，Lody 会展示错误信息，你仍然可以保留 session 并再次尝试。

终止 ACP 进程会：

- 停止当前 Agent 任务及其被追踪的子进程
- 释放该驻留进程树占用的 CPU 和内存
- 保留对话历史、session 元数据、分支、worktree 和项目文件
- 不会归档或删除 session，也不会回收它占用的磁盘空间

如果在 Agent 正在修改文件或执行命令时终止进程，已经执行的操作不会自动回滚。建议随后检查 session
中的文件和 diff。

## 之后继续对话

你可以随时回到已经终止 ACP 进程的 session 并发送新消息。Lody 会重新启动 ACP 进程，并从持久化的
session 上下文恢复对话。由于需要启动和重新连接 Agent runtime，恢复后的第一轮可能会稍慢，但对话
内容和文件会一直保留。

进程内部尚未持久化的临时状态会随着 ACP 进程终止而消失。可恢复的持久上下文来自已保存的对话、
Agent 的 resume 能力以及 session 工作目录中的文件。因此，可以在暂时不工作时通过终止 ACP 来释放
CPU 和内存；只有在还需要改变 session 可见性或回收磁盘空间时，才需要归档或删除。归档、恢复和删除
的区别请参阅[会话](/zh/docs/session)。

## 按需实时上报

资源监控使用 ephemeral（临时）状态，按需工作：

- 有人查看设备页面时，在线设备才会上报并刷新资源快照
- 页面保持可见时会自动动态更新
- 快照过期后会消失，不会作为历史指标时间线长期保存
- 没有人查看时，Lody 不会持续请求资源采样

如果设备已经共享到 workspace，可以访问这台设备的团队成员都能看到它当前的资源信息。监控只上报
资源数据和用于识别 session 的展示信息。在共享设备上终止 ACP 会影响所有人看到的同一个 session，
因此请在停止其他成员正在执行的任务前确认其状态。监控不是进程命令行查看器，也不能替代操作系统级
性能分析工具。

设备离线时，Lody 无法获取新样本，也无法终止其中的 ACP 进程。请先让 CLI 恢复在线，再重新进入
**设置 -> 设备** 并等待第一份样本。
