# Agent 对话控制

Lody Agent 可以通过内置 Lody MCP 工具跨对话工作。你可以让一个 Agent 将任务拆分为多个专注的对话、检查进度、发送后续任务，并在原始对话中汇总完成结果。

自己开多条会话——隔离 Worktree、混用模型、团队可见性——见[并行 Coding Agents](/zh/docs/parallel-agents)。本页讲的是控制路径：一个 Agent 去协调其他对话。

包含 Claude Code、Kimi、Codex 和 Grok 的完整示例，以及会话引用和跨机器协作步骤，见 [Agent 协作工作流](/zh/docs/agent-collaboration/)。

## 在对话中使用

直接在普通提示词中描述目标和分工即可，例如：

```text
为这个项目创建两个审查对话：一个检查正确性，一个检查测试覆盖。两个都完成后，在这里汇总发现的问题。
```

Agent 可以创建或复用对话、读取其状态和有限历史、发送后续指令，或在合适时取消正在运行的回合。目标工作结束后，结果会返回到发起请求的对话。

创建新会话时，Agent 还可以从目标机器可用的兼容选项中指定模型和推理强度。如果这些配置很重要，请在提示词中说明，例如：

```text
创建一个使用 Codex 高推理强度的代码审查会话，完成后在这里汇总发现的问题。
```

## 协调 PR、Issue 和跨仓库修复

### 让 Claude Code 统筹任务

可以让 Claude Code 先过一遍一组 PR 或 Issue，识别依赖关系，再把具体工作分派给 Kimi、Codex、Grok 等其他 Agent。每个 Agent 在独立对话中工作，负责统筹的 Agent 可以发送后续指令并汇总结果。访问仓库使用各 Agent 可用的工具和凭据。

```text
过一遍这些 PR 和 Issue，把相关工作分组并识别依赖关系。
创建独立对话，将可独立执行的修复分配给 Kimi，将审查分配给 Codex。
汇总它们的发现，说明哪些改动已经可以交给我审查。
```

### 同时修复多个仓库中的问题

当一个 bug 涉及客户端、SDK 和服务端时，可以为每个受影响的仓库创建一条对话。几个 Agent 并行调查和实现独立改动，互相发送消息确认共同的接口约定，再协调存在依赖的修复。

```text
在客户端、SDK 和服务端三个仓库中调查这个 bug。
为每个仓库启动一个专注的 Agent 对话，让它们互相交流发现，
先确认接口改动，再实现存在依赖的修复。
在这里汇总补丁和验证结果。
```

### 让 Agent 之间进行审查与修复循环

Agent 可以给其他有权访问的 Lody 对话发送消息、委派任务。你也可以直接让一个 Agent 给另一个 Agent 发消息：让审查者检查指定提交，将问题发给实现者修复，再检查修复后的新提交。

```text
让审查 Agent 只读检查实现 Agent 的当前提交。
把可执行的审查意见发给实现 Agent，让它修复。
再让审查者检查更新后的提交。最多进行两轮，没有剩余问题时提前结束，
最后把结果汇总给我。
```

这些是可以通过提示词组织的工作流，不是预设流水线。请明确目标仓库、工作范围、完成条件和审查轮数。并行完成的改动仍需经过集成检查，才能准备合并。

## 使用方式

- 每个对话都是独立任务，拥有自己的历史和活跃回合。
- 目标机器在线时，多个任务可以并行执行。
- Lody 会保留与发起对话的关联，因此 Agent 能在委派工作结束后继续处理。
- 临时对话完成后，可在会话列表中归档。

## 限制

对话控制有明确边界：Agent 只能读取 Lody 自身的对话数据，不能将其作为无限制的后台调度器。被委派的任务可能会在请求的截止时间后才完成；即使发起对话已经收到超时结果，输出仍会保留在对应对话中。

要把正在跑的会话交给同事，而不是让 Agent 去协调其他对话，见[共享并交接 Agent 会话](/zh/docs/session-handoff)。
