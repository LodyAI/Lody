# Agent 角色

**Agent 角色**打包的是「你怎么用一个 Agent」：它跑在哪台机器的哪个
[Agent 配置](/zh/docs/agents)上、用什么模型和推理强度、用什么权限模式，以及一段可选的默认指令。给它一个
emoji 和名字，这些选择就变成了一次点击。

角色不是新的 Provider，也不是常驻的 Agent。它不保存 API Key，也不保存 MCP 选择——那些留在 Agent 配置里。

## 创建角色

两个入口，同一个编辑器：

- **设置** → **Agent 角色** → `+` 按钮。
- 输入框运行配置里的**角色**行 → **使用当前配置新建角色**。这个入口会用你正要运行的配置预填表单，是把刚调好的一套设置保存下来最快的方式。

选择机器和 Agent 配置，然后是该 Agent 公布的模型、推理强度和权限，以及可选的默认指令。新角色默认只对你自己可见，直到你打开**共享到工作区**。

## 开始新对话时使用角色

运行配置里的**角色**行在 **Agent** 之上——因为一个角色一次就回答了它下面每一行。

- 桌面端：点开输入框底部的运行配置按钮，悬停**角色**；左边是列表，右边的面板会写明高亮的那个角色究竟会跑什么。
- 移动端：打开运行配置面板，**角色**是第一行。

选中之后，下面几行会随之改变。输入框底部随即显示角色的 emoji 和名字，旁边用更小的字号列出它的取值。你真正用来开过对话的角色也会出现在**最近使用**里。

**无**清掉的是名字，不是配置：角色设下的那些值现在是你自己的，离开角色不会把它们退回去。

只有当配置仍然是那个角色的时候，底部才会显示角色名。你手动改了模型，名字就会消失——底部不会挂着一个名不副实的角色。

已有对话里尚未发送的新建子标签也遵循这套“新对话”规则。它的机器和工作目录仍然跟随主 session，
但角色列表会提供该机器上所有 Agent 类型的角色。选中角色后，draft 会切换到角色绑定的 Agent 配置；
首次发送时，运行配置、默认指令和角色来源会一起冻结进新的子 session。

## 在对话中使用角色

对话一旦创建，就已经在某台机器上跑着某个 Agent，角色没法把它挪走。所以这时对话内的**角色**行：

- 只提供绑定了**同类型** Agent 的角色，它们的模型、推理强度和权限取值正是这个 Agent 认得的；
- 也只应用这部分运行配置——角色的默认指令不会被加进一段已经在进行的对话。

之后每一行仍然可以随时再改。

## 用 @ 提及角色

输入 `@` 并在 **Agent 角色**分类里选一个，就是让当前 Agent 用它开一个**新对话**：

```text
@代码审查 检查这个分支的改动，把可能出错的地方报出来
```

新对话会在该角色的机器和 Agent 配置上启动，模型、推理强度、权限和默认指令都已就位。你发送消息那一刻角色的内容会被冻结进这次请求，所以之后编辑或删除角色，不会改变已经被接受的工作。

能提及哪些角色取决于当前位置：本地项目或纯聊天只提供同一台机器上的角色；GitHub 项目还可以用到你其他已授权机器上的角色，因为新对话会自己克隆仓库。其他提及类型见[提及](/zh/docs/mention)。

## 共享

角色在共享之前只属于你自己。**共享到工作区**之后，工作区里每个成员都能看到、提及和运行它。它仍然跑在自己那台机器上，所以成员需要有那台机器的访问权限。

私有的含义是其他成员无法通过 Lody 发现、提及或运行它。这不是加密——这也正是角色一开始就不保存任何密钥的原因。

## 角色不可用时

角色精确绑定一台机器和一个 Agent 配置，绝不会悄悄换成别的。如果机器离线或 Agent 配置被删除，角色仍然会列在设置和选择器里，并标出确切原因，在你修好之前无法被选中。

编辑角色只影响之后的使用，已经用它开过的对话会按原样继续运行。
