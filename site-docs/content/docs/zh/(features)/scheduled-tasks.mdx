# 定时任务

**定时任务**会在你设定的时间，用你选好的 Agent、模型、权限和项目，自动发出一段 prompt。每次运行都是一段普通对话：你可以随时打开它、接着聊，或者把它停掉。

典型用法：每天早上汇总昨天合并的提交、每个工作日检查依赖的安全公告、每周五起草周报；或者存一个手动任务，需要时点一下就跑。

想先了解定期执行编程任务的用法，可以阅读[编程 Agent 定时任务（英文）](/coding-agent-scheduler/)。

## 在哪里运行

定时任务不在云端运行，而是由**你自己的一台机器**负责：

- 那台机器上需要运行 [Lody CLI](/zh/docs/cli)（桌面端会自动启动它），并且是支持定时任务的新版本。
- 编辑器按**那台机器的本地时区**解读时间，没有时区选择器。「每天 9:00」就是那台机器上的 9:00。如果旧版机器没有上报时区，编辑器会使用当前查看页面的设备时区。保存前请检查**接下来的运行**。
- 机器关机、睡眠或 CLI 没在运行时，到点不会执行。恢复后如何处理见[错过的运行](#错过的运行)。

网页端、桌面端和手机都可以查看和管理定时任务，但真正执行的只有它所属的那台机器。

日历规则会保存明确的时区。**仅一次**保存的是一个绝对时刻：切换所选机器后，会按新机器的时钟显示同一时刻。已有的高级 cron 规则会保留其保存的时区。

## 选择编程 Agent

定时任务会用所选的 [Agent Config](/zh/docs/agents/) 创建普通 Session，可以使用以下接入方式：

- **Codex**：选择执行机器上已经配置好的 Codex Agent
- **Claude Code**：选择它的 Agent Config，以及可用的模型和权限设置
- **Kimi Code**：使用托管的 Kimi Code provider，并完成登录
- **通过 Claude Code 使用 GLM**：选择 GLM provider 预设，配置匹配的端点和凭据；它通过 Claude Code 运行
- **DeepSeek Harness**：使用内置 Harness provider；它与通过 Claude Code 使用 DeepSeek 是两种不同的接入方式
- **Pi**：在支持的机器上使用托管 Pi provider；没有权限选择器的 provider 使用自身的执行策略

凭据、模型访问权限、工具和依赖都需要在执行机器上准备好。以上列的是接入方式，不代表每个模型或权限组合都经过了定时执行验证。先用你选择的配置运行一个简单的手动任务。各 provider 的要求和限制见 [Agent Config 指南](/zh/docs/agents/)。

## 新建定时任务

从侧边栏的**定时任务**进入，点击**新建定时任务**（也可以在命令面板里搜索「新建定时任务」）。编辑器和对话输入框长得一样：

1. **名称和 prompt**：每次运行要让 Agent 做什么。
2. **Agent、模型和权限**：就是输入框底部那组控件。新建时会沿用你在对话首页上次用的机器、Agent 和该 Agent 记住的设置，一般不用再选。 保存时无需额外选择权限，但记住的配置仍需通过运行时校验。Pi 等没有权限选择器的 provider 使用自身的执行策略。
3. **机器、项目、worktree**：项目是可选的；不选项目时，每次运行都是与 Agent 的普通对话，不会检出任何仓库。
4. **发送到**和**触发**：见下文。

漏填的地方会在对应控件旁边出现感叹号，保存后回到列表。

## 触发方式

**触发**有两种：

- **定时**：在**重复**里选一种规则，再填时间：
  - 每天、工作日、每周（选星期几）、每月（选几号）
  - 每几小时、每几分钟
  - 仅一次（指定日期和时间）
- **手动**：不会自动运行，只在你点**立即运行**时执行。适合存一套常用的指令。

编辑器下方会列出**接下来的运行**时间，方便确认规则对不对。时间和日期都是直接键入的。

## 可以尝试的 prompt

先选择这些指令要检查的项目。以下是可以调整的示例指令，不是已经完成的运行报告。

### 用手动任务检查配置

选择**手动**、**每次新建对话**和所需的 Agent Config，保存下面的 prompt，再点**立即运行**：

> 阅读这个项目的 README，以及包管理或构建清单。返回项目名称、文档中的测试命令，以及缺少的环境准备信息。不要修改文件、安装依赖或运行测试。

打开**上次运行**，确认对话使用了预期的机器和 Agent。这能检查当前任务的这组配置，但不能验证以后每一种工具调用或权限请求。

### 每天早上汇总仓库近期变化

选择**每天 9:00**和**每次新建对话**：

> 检查这个项目最近 24 小时的本地 Git 历史。汇总最多十项变化，附上提交哈希，将相关变化归类，并单独列出后续需要确认的问题。如果这段时间没有提交，请明确说明。报告检查的是哪个分支。不要拉取远端、修改文件或发布任何内容。

这会读取当前检出目录中已有的历史，不保证本地分支包含远端刚合并的所有提交。

### 每个工作日检查依赖安全公告

选择**工作日 10:00**：

> 阅读这个项目的依赖清单和锁文件。查询可访问的官方安全公告，检查已安装的版本。每项匹配结果都列出包名、已安装版本、公告链接和受影响的版本范围。如果无法联网或某个来源不可访问，请说明哪些内容无法验证。不要更新依赖或创建 PR。

Agent 需要能够访问相关文件、网络和工具。先检查第一次运行的结果，再把它作为定期报告使用。

## 发送到哪里

- **每次新建对话**（默认）：每次运行开一个新对话，互不干扰。
- **固定一个对话**：所有运行都追加到同一个对话里，适合需要延续上下文的任务。第一次运行时创建这个对话；之后可以点**开始新对话**，让后续运行换到一个新的对话里。
- **已有对话**：追加到你选定的一个现有对话。这时会使用那个对话的 Agent，也不再单独选择项目。

## 管理定时任务

列表里每一行显示名称、频率、下次运行和运行配置：

- 定时任务行上可以直接**暂停** / **恢复**，手动任务行上可以直接**立即运行**。
- 右键一行可以打开、立即运行、暂停或恢复、查看**上次运行**，或删除（删除需要确认）。
- 点一行会从右侧滑出详情：顶部是暂停、立即运行、删除，最下面是**运行历史**。拖动列表和详情之间的分隔线可以调整宽度，点列表空白处收起详情。

只有创建者可以编辑、暂停和删除自己的定时任务。暂停只会停止之后的运行，已经开始的对话需要单独取消。

## 让 Agent 帮你设定

在对话里直接说「每个工作日早上 9 点帮我检查一下依赖更新」，Agent 会整理好名称、prompt 和时间规则，在对话里给出一张**把它设为定时任务？**卡片。

- 卡片默认沿用当前对话的 Agent、权限、机器和项目，并列出最终会创建的内容。
- 点**编辑**可以直接在卡片上修改名称、prompt 和时间规则。
- 点**创建**才会真正创建；点**忽略**则放弃。创建之后卡片不能再修改，要改请到定时任务页面编辑。

提议会一直等待，直到你点**创建**。内置定时任务工具也允许 Agent 列出、查看和暂停已有任务，但不能直接创建、编辑或恢复任务；这些操作请使用定时任务界面的控件完成。

## 错过的运行

使用编辑器默认的错过运行策略时，机器唤醒或 CLI 重新启动后只会**补跑一次**，对应最近错过的那个时间点，不会逐一重放所有错过的运行。如果 Agent 或配置还不可用，这次运行仍可能需要等待。

如果到点时上一次运行还没结束，这次会排队，等上一次完成后再执行；最多只排一次。

## 常见问题

### 定时任务显示「正在等待任务配置同步完成」？

表示负责运行的机器还没有拿到最新的任务配置，刚保存后出现几秒属于正常。如果一直不消失，请确认那台机器在线、CLI 已更新到最新版本。

### 为什么选不了某台机器？

定时任务只能运行在你自己的、已经安装了支持定时任务的 CLI 的机器上。请在那台机器上更新 Lody CLI。

### 电脑睡眠时会自动唤醒来执行吗？

不会。定时任务由 CLI 在机器运行时检查执行，不会唤醒睡眠中的电脑。醒来后会按[错过的运行](#错过的运行)补跑一次。

### 为什么保存的任务还没开始对话就失败了？

一个已知情况记录在 [issue #1247](https://github.com/LodyAI/Lody/issues/1247#issuecomment-5986803074) 中：如果任务保存了 `fast: "false"`，而能力探测使用的模型没有 Fast 选项，任务可能在创建 Session 前失败。这个值可能来自记住的对话设置，即使你没有在定时任务编辑器里改过 Fast。

创建流程拒绝了保存的选项，但调度器把失败标为 `DISPATCH_UNAVAILABLE` 并重试。[2026 年 10 月 5 日检查的源码](https://github.com/LodyAI/Lody/blob/cd3f5b3ca969be5fa2e327744d449ffd802efe7b/apps/cli/src/commands/session.ts#L3099-L3105)中仍存在这个验证缺口；此现象不代表 Agent 本身不可用。修复进度请查看该 issue。反馈时，请提供 CLI 版本、所选 Agent 和模型，以及显示的错误；不要包含凭据或私人 prompt。
