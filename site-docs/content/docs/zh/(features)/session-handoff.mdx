# 和团队共享、交接编程 Agent 会话

Lody 里的 **编程 Agent 会话交接**，指的是同事打开你已经在跑的**同一个**会话，接着往下做。对方拿到的是现场对话、Agent 改过的文件差异，以及这次会话的 [Worktree](/zh/docs/worktrees)——不是截图、Markdown 导出，也不是 ChatGPT 那种只能*阅读*的分享链接。

这和常见的「分享 Claude Code session」做法不同：那些多半是在发布一份对话记录。Lody 是把人请进现有会话，让对方继续聊、继续 steer Agent。

另见 [会话](/zh/docs/session)、[团队功能](/zh/docs/team) 和 [Agent Config](/zh/docs/agents)。

<Callout title="这里的「接着做」指什么">
能打开该会话的工作空间成员，可以在同一段上下文里继续对话。Lody 不会把交接变成只读回放。共享范围仍受机器和项目可见性约束，见下方的[权限](#权限)。
</Callout>

## 为什么「发一份记录」不算交接

团队分享 Agent 工作的方式很多，大多数停在「你看一下」。交接要的是「你接下来做」。

| 做法 | 对方拿到什么 | 是否同一个现场会话 | 差异和工作树 |
| --- | --- | --- | --- |
| 截图 | 对话的一张图 | 否 | 否 |
| Markdown / 对话导出 | 可以粘到别处的静态文本 | 否——只能新开对话 | 否 |
| ChatGPT 式分享链接 | 只读的对话快照 | 否 | 否 |
| [Lore](https://lore.link/share) | 渲染好的 thread（提示词、工具调用、改过的文件），可查看或 fork 进**新的** Agent 会话 | 否——原会话仍停在原来的运行环境 | 浏览或蒸馏上下文，不是原来的工作区 |
| [SpecStory](https://docs.specstory.com/cloud/session-sharing) | 保存下来的历史，或公开的查看链接 | 否——查看者不会加入你正在跑的会话 | 历史 / 导出，不是会话 Worktree |
| **Lody** | 工作空间里已有的[会话](/zh/docs/session) | **是**——打开后接着聊 | **是**——实时 [Diff](/zh/docs/diff-viewer) 和会话 Worktree |

如果只需要留档，Lody 也可以把对话复制成 Markdown。那是另一件事，见[复制对话](/zh/docs/copy-md)。只复制会话 URL、却没有把会话共享给团队，也不会授予访问权限——这条链接对所有者仍然有效。

## 如何交接一个会话

### 1. 先把同事请进工作空间

交接发生在团队工作空间里。对方必须已经是成员。

1. 打开 **设置** -> **工作区** -> **通用**。
2. 在 **成员** 一节点击 **邀请成员**。
3. 填写对方的邮箱，并选择角色。
4. 对方可以从邮件接受邀请，你也可以复制邀请链接手动发给对方。

详见[邀请成员](/zh/docs/team#邀请成员)。

### 2. 让团队看得到这个会话

新机器默认是**私有的**。只有会话所依赖的资源被共享之后，这个会话才会对团队可见。

在会话里：

1. 打开会话的 `...` 菜单，或桌面端会话标题栏上的 **Private（私有）** 控件。
2. 选择 **Share with team…（与团队共享）**。如果缺的是机器或本地项目授权，文案可能是 **Share device with team…** 或 **Share project with team…**。
3. 确认。Lody 会共享所需的机器；若会话用的是本地项目，也会共享该项目，然后复制一条链接。

只有**设备所有者**可以共享。如果这台设备还没有登记团队访问，需要先完成登记。也可以不打开某个会话，直接在 **设置** -> **机器** 里打开 **共享机器**。见[团队机器可见性](/zh/docs/team#团队机器可见性)。

<Callout type="warn" title="共享一个会话，可能让更多对话一起可见">
共享会话时，可能会把对应机器和/或本地项目共享给工作空间里的所有人。这台设备上的其他对话也可能随之可见。确认框会先说明范围。
</Callout>

### 3. 把对方带到这个会话

会话对团队可见之后：

- 把复制好的会话链接发给对方，或
- 让对方打开主页会话列表。如果只看到自己的对话，把侧边栏筛选从 **我的任务** 改成 **全部任务**（移动端是 **团队任务**）。头像可以区分是谁发起的会话。列表默认就是 **全部任务**。

对方打开的是**这个**会话——不是 Fork，也不是主页输入框里新开的一条。

### 4. 接着做

进入会话后，对方可以：

- 阅读 Agent 已经进行过的完整对话
- 查看当前的 [Diff](/zh/docs/diff-viewer)
- 在同一个 [Worktree](/zh/docs/worktrees) 和分支上继续改
- 发送下一条提示词，steer 同一个 [Agent Config](/zh/docs/agents)

Fork 会话是另一件事：它会把历史复制到**新的**会话里。**当前工作区**仍共用原来的文件；出现 **新 Worktree** 时，会从已提交的 `HEAD` 隔离出去。需要自己另开一条对话线时用 Fork；要把同事请进原来的会话，不要用 Fork。见 [Fork 会话](/zh/docs/session#fork-会话)。

要以团队方式并行跑多条隔离会话，见[并行 Coding Agents](/zh/docs/parallel-agents)。
如果要让一个 Agent 去协调多段对话，见 [Agent 对话控制](/zh/docs/session-orchestration)。

## 权限

| 控制项 | 作用对象 | 效果 |
| --- | --- | --- |
| 工作空间成员 | 你邀请进来的人 | 打开团队会话的前提 |
| 成员角色 | 拥有者和管理员管理成员 | 决定谁能邀请、修改或移除成员，见[修改成员权限](/zh/docs/team#修改成员权限) |
| 机器共享 | 仅机器所有者 | 未共享机器上的会话不会出现在其他成员的侧边栏 |
| 本地项目共享 | 机器所有者（会话使用本地项目时） | 同事需要同时拥有项目授权和机器授权 |
| 会话 URL | 所有者始终可用；同事仅在会话对团队可见后可用 | 复制 URL 不等于 **Share with team…** |

加入工作空间**不会**把你的笔记本暴露出去。机器在你主动共享之前都是私有的。Agent Config 可以另外共享，让同事使用同一套 CLI 配置；见 [Agent Config](/zh/docs/agents) 和[团队功能](/zh/docs/team)。

## 常见问题

### 能不能把 Claude Code 会话交给同事接着做？

可以，只要这个会话跑在 Lody 工作空间里。先邀请对方，再共享会话（以及它所依赖的机器或本地项目），然后让对方打开这个会话继续聊。这不是只读的 Claude Code 对话导出，也不是公开快照链接。

### 这和 ChatGPT 分享链接、Lore、SpecStory 一样吗？

不一样。那些产品围绕的是**可查看的记录**——快照、渲染后的 thread，或导出的历史。其中有些可以把内容灌进一次*新的* Agent 运行。Lody 交接的是团队工作空间里**已经存在的编程 Agent 会话**：同一段对话、差异和工作树。

### 同事为什么看不到这个会话？

先核对三件事：对方是否已接受工作空间邀请、机器（以及本地项目，如有）是否已共享、对方看的是 **全部任务** 而不是 **我的任务**。未共享机器上的对话不会同步到其他成员的侧边栏。

### 共享一个会话，会不会把整台机器也共享出去？

有可能。如果这台机器还没共享，**Share with team…** 会把它共享出去，同事才能打开并继续这台设备上的对话。同一台机器上的其他会话也可能一起可见。之后可以在 **设置** -> **机器** 里关掉 **共享机器**。

### 只想发一份对话记录可以吗？

可以。只需要留档时，复制单条消息，或在会话菜单里选择 **Copy as Markdown**。这不会让对方继续现场会话。见[复制对话](/zh/docs/copy-md)。
