# 工作树

工作树是 Lody 隔离和管理并发任务的基础。

## 什么是工作树？

Git 工作树是仓库的一个链接工作副本。每个工作树都有自己的工作目录和单独检出的分支，但与主仓库共享相同的 Git 历史。

## Lody 如何使用工作树

当你在 Lody 中创建任务时，它会自动：

1. **创建新分支** - 默认分支名为 `session/<shortSessionId>`（`sessionId` 的前 8 位；你也可以后续重命名）
2. **设置工作树** - 代理工作的隔离目录（每个会话一个）
3. **运行 setup 脚本** - 可选的项目级命令，例如安装依赖或复制 env 模板
4. **同步更改** - 实时更新在 Web UI 中可见

```
~/.lody/repos/<repoId>/
├── bare.git/                # Bare Git repository (shared history)
├── cache/                   # Build cache, etc.
└── worktrees/
    ├── <sessionId-1>/       # Worktree for session 1
    └── <sessionId-2>/       # Worktree for session 2
```

## 优势

### 并行执行

同时运行多个代理而不会冲突：

每个任务都有自己的工作树，代理之间的更改永远不会相互干扰。

### 干净隔离

- 任务之间没有未提交的更改混淆
- 易于审查、批准或放弃单个任务
- 每个任务简单创建 PR

<span id="automatic-cleanup"></span>

### 自动清理

手动归档与 [PR 自动归档](/zh/docs/github#自动归档已完成-pr-会话)都会让根会话的 Lody 托管工作树进入可清理状态。对话在永久删除之前仍保留于归档列表，工作目录则可能更早被移除。

| 资源 | 归档并清理之后 | 永久删除会话之后 |
| --- | --- | --- |
| 对话历史 | 保留，可恢复会话 | 删除；会话删除无法撤销 |
| Lody 托管的 worktree 目录 | 由所属机器移除 | 若仍存在，继续等待清理 |
| 本地 Git 分支与提交 | 保留，包括备份提交 | 保留；删除会话不会回收分支 |
| 待提交的非 ignored 改动 | 移除前暂存并提交到本地分支 | 对剩余工作树使用相同备份规则 |
| 被 Git 忽略的文件，如 `.env`、依赖和构建产物 | 可能随目录丢弃 | 不保证恢复 |
| 原始本地项目目录 | 不属于托管工作树清理范围 | 不属于托管工作树清理范围 |

所属机器的 daemon 只清理 Lody 数据目录下的托管工作树，且必须先完成工作区元数据同步、释放会话运行时。机器离线或移除失败时，清理可能延后。活跃或归属未知的工作树会保留；单独归档子标签页不会移除根会话共享的工作树。仓库无法解析或备份提交失败时，目录会保留并等待重试。

备份是本地 Git 提交，不是远程推送或整个目录的备份。配置的 cleanup 脚本在备份之前执行，因此它删除或修改的文件不在该保护范围内；脚本失败也不会阻止移除。归档或开启自动归档前，请把需要的 ignored 文件及脚本可能影响的文件另存到 worktree 之外。

恢复并继续已清理工作树的会话时，Lody 会从保留的本地分支重新创建工作树，并再次运行 setup 脚本；ignored 文件需要另外重建。恢复依赖所属仓库和分支仍然存在；被移除的本地项目需要重新添加。手动删除 Lody 仓库数据也会删除这些本地分支与备份，因此不等同于归档或删除会话。

## Worktree Setup 与 Cleanup 脚本

项目级脚本可以让每个新会话都以一致的方式准备工作目录。

**Setup 脚本**会在 Lody 创建 worktree 之后、Agent 收到第一条 prompt 之前运行，适合执行：

```bash
cp .env.example .env
pnpm install
```

**Cleanup 脚本**会在会话归档、Lody 从磁盘移除 worktree 之前运行，适合执行：

```bash
rm -rf node_modules
```

### 配置方式

1. 打开 **Settings** -> **Projects**。
2. 选择一个本地项目或 GitHub 仓库。
3. 打开 **Worktree setup** 和 **Worktree cleanup**。
4. 填写对应 shell 的命令，离开编辑框后会自动保存。

本地项目会显示该项目所在机器实际使用的 shell：Windows 使用 PowerShell，macOS、Linux 和 WSL 使用 Bash。
GitHub 仓库可能在不同系统的机器上运行，所以可以同时填写 Bash 和 PowerShell。

脚本会在 worktree 目录内执行。在脚本里 export 的环境变量只在脚本进程中有效；如果 Agent 进程本身需要环境变量，
请在 [Agent Config](/zh/docs/agents) 中配置。

<span id="available-environment-variables"></span>

### 可用环境变量

Setup 和 cleanup 脚本运行时，Lody 会注入这些环境变量：

| 变量                         | 说明                                        |
| ---------------------------- | ------------------------------------------- |
| `LODY_WORKSPACE_ID`          | 当前 workspace ID                           |
| `LODY_SESSION_ID`            | 当前对话/session ID                         |
| `LODY_WORKTREE_PATH`         | 当前 session worktree 的绝对路径            |
| `LODY_WORKTREE_BRANCH`       | worktree 中检出的分支                       |
| `LODY_WORKTREE_SCRIPT_PHASE` | `setup` 或 `cleanup`                        |
| `LODY_GITHUB_REPO`           | GitHub 项目的仓库全名，仅 GitHub project 有 |
| `LODY_LOCAL_PROJECT_ID`      | 本地项目 ID，仅 local project 有            |

脚本进程的当前工作目录也会设为 `LODY_WORKTREE_PATH`，所以可以直接使用 `pwd`，也可以读取显式环境变量：

```bash
echo "$LODY_SESSION_ID"
echo "$LODY_WORKTREE_PATH"
pnpm install
```
