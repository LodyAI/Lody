# 安全码

安全码是一串数字，用来确认**你和同事看到的是同一本[权限账本](/zh/docs/encrypted-workspaces-ledger)**：同样的成员、同样的设备、同样的授权。

如果和工作区其他成员、你其他设备上显示的安全码一致，说明工作区成员信息和授权信息是一致的。

## 为什么需要安全码

账本里的每条记录都有签名，服务器伪造不了。但服务器可以**给不同的人看不同版本的账本**，比如对你隐瞒「某台设备已被撤销」这条记录。只看自己这一边，是发现不了的。

两个人把各自算出的安全码拿出来一比，就能发现这种情况。

## 安全码怎么算出来

安全码是对下面这些内容整体计算出的摘要：

- 协议版本和用途
- 这个工作区和它的第一条记录（创世）
- 账本当前的位置（有多少条记录）和最后一条记录
- **当前完整的授权状态**：所有成员、角色、设备和它们的公钥

只比较最后一条记录是不够的：一份被改过的状态，可以配上一个看起来正确的最后一条记录。所以安全码把**实际的授权状态**也算了进去。

二维码里还带着账本位置，方便扫码时判断是谁落后了。

## 结果说明什么

| 结果 | 含义 | 该怎么做 |
| --- | --- | --- |
| 一样 | 你们在同一位置接受了相同的成员、设备和授权 | 不用做什么 |
| 有一方没更新 | 一边的账本比另一边旧，前面的部分相同 | 两人都刷新后再对一次 |
| 不一样 | 同一位置，内容却不同 | 先不要邀请或批准任何人，告诉工作区负责人 |

账本位置不同不代表被攻击，大多只是一边还没同步。

## 安全码不能证明什么

- **不证明对方是谁**：它只说明你们看到的记录一样。核对时要确认对方确实是你认识的那位同事。
- **不证明每条历史操作都合理**：它证明的是你们接受了同一个状态，不是说这个状态里的每一步都该发生。
- **不代表以后永远安全**：它只说明核对那一刻的那个位置一致。之后账本有了新记录，安全码会变，需要时再对一次。
- **只和邀请你的人核对，作用有限**：如果邀请你的人和服务器串通，和他对得上也说明不了问题。最好和至少另一位成员核对。

## 怎么核对

<Steps>
<Step>

两个人都在加密控制台打开「安全码与记录」，先点刷新。

</Step>
<Step>

点「和同事核对」，扫对方屏幕上的二维码。扫不了就直接逐组对数字。

</Step>
<Step>

按结果操作。当面、视频或打电话都可以；不要只通过 Lody 本身互相发送安全码。

</Step>
</Steps>
