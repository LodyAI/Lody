# 权限账本

每个端到端加密工作区都有一本**权限账本**。在加密控制台里它显示为「变更记录」。账本决定谁是成员、每个人是什么角色、哪些设备可以收到密钥。

## 账本里记什么

账本是一串按顺序排列的记录。每条记录写的是一次变更，例如：

- 创建工作区（第一条记录，叫「创世」）
- 接纳新成员、调整成员角色、移除成员
- 加入或撤销某台设备
- 更换工作区密钥
- 转移所有权

账本里记录的是**账户 ID 和设备公钥**，不记录对话、文件这些内容。名字和头像来自账号资料，不在账本里。

## 每条记录都带签名

每条记录由做这次变更的人，在**自己已授权的个人设备上签名**。签名覆盖操作本身、目标和工作区，改一个字签名就失效。

服务器只负责保存和转发记录，**手里没有任何人的签名钥匙**，所以它不能替任何人签名，也就没法偷偷加一个成员或一台设备。

## 记录首尾相连

每条记录都包含上一条记录的哈希值，从「创世」一路连下来，形成一条链。

- 删掉、插入或调换中间任何一条，后面的链就对不上，设备会发现。
- 新记录只能追加在当前链尾。两个人同时提交时，只有一个成功，另一个要刷新后重新确认。
- 生效顺序就是提交成功的顺序。例如 B 先接纳了 C，所有者再移除 B，那么 C 仍然是成员；如果移除先提交，B 之前发出的邀请就失效。

## 谁能签什么

每次变更时，设备都会按**变更前那一刻**的账本重新检查签名者有没有权限，而不是看他当初加入时的权限。

| 变更 | 谁可以签 |
| --- | --- |
| 接纳新成员 | 所有者或管理员 |
| 移除普通成员 | 所有者或管理员 |
| 移除管理员、调整角色 | 只有所有者 |
| 转移所有权 | 只有所有者；转出后原所有者变为管理员 |
| 加入自己的新设备 | 本人已授权的设备；设备全丢时用恢复文件 |
| 撤销设备 | 本人，或有管理权限的成员 |
| 更换工作区密钥 | 所有者或管理员 |

远端机器和恢复设备**永远没有管理权限**，只能收密钥和工作。

## 设备怎么验证账本

- **已有设备**：每收到一条新记录，就检查它和上一条连得上、签名正确、签名者当时有权限，三者都满足才接受。
- **新加入的设备**：不一定从第一条记录开始重放，可以接受一位所有者或管理员设备签名过的「当前状态快照」，再逐条验证之后的记录。这意味着新设备信任了那次快照的签名者。
- **发现问题时**：只要有一条记录验证不过，设备就停在最后一条可信记录上，保留证据，暂停邀请和授权，**不会自动「修复」或跳过**。已有对话照常可看。

## 撤销和更换密钥

- 撤销一台设备只影响那一台；撤销你的电脑，不会连带撤销由它批准过的手机。
- 移除成员会让他所有设备立刻失去访问。移除后建议**更换工作区密钥**：新密钥只发给仍然有效的设备，旧设备即使留着旧密钥也解不开新内容。已经下载到对方设备上的历史无法收回。

## 账本信任什么

账本让服务器**无法伪造**任何签名，但有一件事它自己做不到：保证每个人拿到的都是**同一本、最新的**账本。

当前版本假设服务器提供的账本完整、不回滚、不分叉。如果服务器故意给不同的人看不同版本，它仍然伪造不了签名，但可能对某些人隐瞒一次撤销。

这正是[安全码](/zh/docs/encrypted-workspaces-security-code)要解决的问题：和同事对一下安全码，就能发现你们看到的是不是同一本账本。
