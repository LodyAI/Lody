# セキュリティコード

セキュリティコードは、**あなたとチームメンバーが同じ[権限台帳](/ja/docs/encrypted-workspaces-ledger)**（同じメンバー、同じデバイス、同じ認可）を保持していることを確認するための数字列です。

ご自身のコードが他のメンバーやご自身の別デバイスに表示されているコードと一致していれば、ワークスペースのメンバー情報と認可情報は整合しています。

## セキュリティコードが存在する理由

台帳のすべてのレコードには署名が付与されているため、サーバーがレコードを偽造することはできません。しかし、サーバーが**人によって異なるバージョンの台帳を表示する**ことは可能です（たとえば、あるデバイスが失効されたというレコードをあなたにだけ隠す、といった場合です）。手元のコピーだけを見ていても、これを見抜くことはできません。

2 人がそれぞれ独立して算出したコード同士を比較することで、こうした食い違いを検出できます。

## コードの算出元

セキュリティコードは、以下の情報すべてをまとめて算出したダイジェストです。

- プロトコルのバージョンと用途
- ワークスペースおよび最初のレコード（ジェネシス）
- 台帳の現在の位置（レコード数）と最後のレコード
- **現在の完全な認可状態**：すべてのメンバー、ロール、デバイス、および公開鍵

最後のレコードだけを比較しても不十分です。改ざんされた状態に、一見正しそうな最後のレコードが添えられている可能性があるためです。実際の認可状態そのものをコードの算出に含めているのはこのためです。

QR コードには台帳の位置情報も含まれているため、スキャンするだけでどちらが遅れているかを判別できます。

## 比較結果の意味

| 結果 | 意味 | 対応方法 |
| --- | --- | --- |
| 一致する | 同じ位置において、同じメンバー、デバイス、認可を受け入れています | 操作は不要です |
| 一方が古い状態 | 片方の台帳が古く、その時点までの内容は一致しています | 双方で更新（再読み込み）し、もう一度比較してください |
| 一致しない | 同じ位置にもかかわらず、内容が異なります | 誰の招待・承認も行わず、ワークスペースのオーナーに連絡してください |

位置が異なること自体は攻撃ではありません。通常は、片方がまだ同期を完了していないだけです。

## セキュリティコードで証明できないこと

- **相手が誰であるか**：セキュリティコードが示すのは、双方のレコードが一致していることだけです。自分が知っているチームメンバー本人と比較していることを必ず確認してください。
- **過去のすべての変更が妥当であったこと**：同じ状態を受け入れていることは示せますが、そこに至る各手順が本来行われるべきだったかどうかまでは証明しません。
- **今後もずっと安全であること**：コードが保証するのは、その時点・その位置における状態です。新しいレコードが追加されるとコードは変化するため、重要なタイミングでは再度比較してください。
- **招待者とだけ比較した場合の十分な安全性**：招待者とサーバーが共謀している場合、その相手とコードが一致してもほとんど証明になりません。少なくとももう 1 人の別メンバーとも比較してください。

## 比較方法

<Steps>
<Step>

双方で暗号化コンソールの「セキュリティコードと履歴」を開き、更新します。

</Step>
<Step>

「チームメンバーと比較」を選択し、相手の画面に表示された QR コードをスキャンするか、数字のグループを声に出して読み合わせます。

</Step>
<Step>

比較結果に応じて対応します。対面、ビデオ通話、電話のいずれでも構いませんが、Lody 上のやり取りだけでコードを送り合わないでください。

</Step>
</Steps>
