# ワークツリー

ワークツリーは、Lody が同時実行されるタスクを分離・管理するための基盤です。

## ワークツリーとは？

Git ワークツリー（worktree）は、リポジトリにリンクされた作業コピーです。各ワークツリーにはそれぞれ別のブランチがチェックアウトされた独自の作業ディレクトリがありますが、メインリポジトリと同じ Git 履歴を共有します。

## Lody におけるワークツリーの仕組み

Lody でタスクを作成すると、以下の処理が自動的に行われます。

1. **新しいブランチを作成** - デフォルト名は `session/<shortSessionId>`（`sessionId` の先頭 8 文字。名前は変更可能です）
2. **ワークツリーをセットアップ** - エージェントが作業するための分離されたディレクトリ（セッションごとに 1 つ）
3. **セットアップスクリプトを実行** - 依存関係のインストールや環境変数テンプレートのコピーなど、プロジェクト単位の任意コマンドを実行
4. **変更を同期** - Web UI 上でリアルタイムに更新を確認可能

```
~/.lody/repos/<repoId>/
├── bare.git/                # ベア Git リポジトリ（共有履歴）
├── cache/                   # ビルドキャッシュなど
└── worktrees/
    ├── <sessionId-1>/       # セッション 1 用のワークツリー
    └── <sessionId-2>/       # セッション 2 用のワークツリー
```

## メリット

### 並列実行

タスクごとに専用のワークツリーが割り当てられるため、エージェント同士が互いの変更を上書きすることはありません。

### クリーンな分離

- 未コミットの変更がタスク間で混ざることはありません
- 個々のタスクのレビュー、承認、破棄が容易です
- タスク単位でシンプルに PR を作成できます

### 自動クリーンアップ

アーカイブすると、ルートセッションの Lody 管理ワークツリーがクリーンアップの対象になります。会話自体は完全に削除されるまでアーカイブ一覧に保持されますが、作業ディレクトリはそれより先に削除される場合があります。

| リソース | アーカイブおよびクリーンアップ後 | セッションの完全削除後 |
| --- | --- | --- |
| 会話履歴 | 保持されます（セッションは復元可能） | 削除されます（セッションの削除は元に戻せません） |
| Lody 管理ワークツリーディレクトリ | 所有マシンによって削除されます | 残存している場合はクリーンアップの対象になります |
| ローカル Git ブランチとコミット | バックアップコミットを含めて保持されます | 保持されます（削除してもブランチは回収されません） |
| 保留中の無視対象外の変更 | 削除前にローカルでステージングおよびコミットされます | 残存しているワークツリーにも同じバックアップルールが適用されます |
| `.env`、依存関係、ビルド出力などの無視対象ファイル | ディレクトリとともに破棄される場合があります | 復元の保証はありません |
| 元のローカルプロジェクトディレクトリ | 管理対象ワークツリーのクリーンアップ対象外です | 管理対象ワークツリーのクリーンアップ対象外です |

所有元のデーモンは、ワークスペースのメタデータが揃い、セッションランタイムが解放された後に、自身の Lody データディレクトリ配下にあるワークツリーのみをクリーンアップします。そのマシンがオフラインの間や削除に失敗した場合は、クリーンアップが遅延することがあります。アクティブな所有者および不明な所有者のワークツリーはそのまま維持され、子タブのみをアーカイブしてもルートセッションの共有ワークツリーは削除されません。リポジトリを解決できない場合やバックアップコミットに失敗した場合、ディレクトリは再試行のために保持されます。

バックアップはローカルの Git コミットであり、リモートへのプッシュやディレクトリ全体のバックアップではありません。設定されたクリーンアップスクリプトはバックアップより前に実行されるため、スクリプトが削除または変更したファイルはこの保護の対象外となります。スクリプトの失敗によって削除が妨げられることはありません。必要な無視対象ファイルやスクリプトの影響を受けるファイルは、アーカイブ前にワークツリーの外へ退避してください。

ワークツリーが削除されたセッションを復元して続行すると、Lody は保持されているローカルブランチからワークツリーを再作成し、セットアップスクリプトを再度実行します。無視対象ファイルは別途再作成する必要があります。復旧するには所有リポジトリとブランチが依然として存在している必要があり、削除されたローカルプロジェクトは再度追加しなければなりません。Lody のリポジトリデータを手動で削除すると、それらのローカルブランチやバックアップも同時に削除されるため、セッションのアーカイブや削除と同等ではありません。

## ワークツリーのセットアップおよびクリーンアップスクリプト

プロジェクト単位のスクリプトを使用すると、新しいセッションを毎回一貫した状態に準備できます。

**セットアップスクリプト**は、Lody がワークツリーを作成した後、エージェントが最初のプロンプトを受け取る前に実行するコマンドに使用します。例：

```bash
cp .env.example .env
pnpm install
```

**クリーンアップスクリプト**は、会話がアーカイブされた際、Lody がディスクからワークツリーを削除する前に実行するコマンドに使用します。例：

```bash
rm -rf node_modules
```

### スクリプトの設定

1. **Settings** -> **Projects** を開きます。
2. ローカルプロジェクトまたは GitHub リポジトリを選択します。
3. **Worktree setup** と **Worktree cleanup** を開きます。
4. プロジェクトで必要なシェル用のコマンドを追加し、エディターからフォーカスを外して保存します。

ローカルプロジェクトの場合、Lody はそのプロジェクトのマシンで使用されているシェルを表示します。Windows では PowerShell、macOS・Linux・WSL では Bash が使用されます。GitHub リポジトリの場合は Bash と PowerShell の両方を入力できるため、異なるマシン間でもセッションを動作させることができます。

スクリプトはワークツリーディレクトリ内で実行されます。スクリプト内でエクスポートされた環境変数はそのスクリプトプロセス内でのみ有効です。エージェント自体に環境変数が必要な場合は、[エージェント設定](/ja/docs/quickstart) で設定してください。

### 利用可能な環境変数

Lody はセットアップスクリプトおよびクリーンアップスクリプトの両方に以下の環境変数を設定します。

| 変数 | 説明 |
| --- | --- |
| `LODY_WORKSPACE_ID` | 現在のワークスペース ID |
| `LODY_SESSION_ID` | 現在の会話／セッション ID |
| `LODY_WORKTREE_PATH` | セッションワークツリーへの絶対パス |
| `LODY_WORKTREE_BRANCH` | ワークツリーでチェックアウトされているブランチ |
| `LODY_WORKTREE_SCRIPT_PHASE` | `setup` または `cleanup` |
| `LODY_GITHUB_REPO` | GitHub リポジトリのフルネーム（GitHub プロジェクトのみ） |
| `LODY_LOCAL_PROJECT_ID` | ローカルプロジェクト ID（ローカルプロジェクトのみ） |

また、スクリプトプロセスはカレントワーキングディレクトリが `LODY_WORKTREE_PATH` に設定された状態で開始されるため、コマンドでは `pwd` または明示的な環境変数のいずれかを使用できます。

```bash
echo "$LODY_SESSION_ID"
echo "$LODY_WORKTREE_PATH"
pnpm install
```
