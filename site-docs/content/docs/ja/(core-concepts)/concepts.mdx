# コンセプトと用語集

Lody の大部分は、どの画面でも同じように配置された少数のオブジェクトで構成されています。このページを一度読んでおくと、各ガイドの位置づけが把握しやすくなります。

## メンタルモデル

```text
workspace
├── projects / repositories
│   └── session            1 つのタスク、1 つの会話、1 つのブランチ / ワークツリー
│       ├── round          1 回のエージェントターン + その変更内容
│       ├── side chat      メインタスクを中断しないフォークされた質問用チャット
│       └── pull request   レビュー後の任意の GitHub ハンドオフ
├── agent configs          ランタイム + 認証情報 + マシン
│   └── agent roles        保存されたマシン + 設定 + モデル + 権限
└── teammates              共有セッションは閲覧可能、プライベートマシンは不可
```

ユーザーが最も多くの時間を過ごすオブジェクトはセッションです。その他の要素はすべて、セッションに入力されるもの（プロジェクト、リポジトリ、Agent Config、Agent Role）か、セッションから生み出されるもの（diff、プルリクエスト、ハンドオフ）のいずれかです。

## タスクの流れ

1. **プロジェクトまたはリポジトリを追加します。** [ローカルプロジェクト](/ja/docs/local-project)はディレクトリを表し、[GitHub リポジトリ](/ja/docs/github)はプルリクエスト、CI、およびレビュー同期を追加します。
2. **実行対象を選択します。** [Agent Config](/ja/docs/quickstart) はランタイムをマシンとその認証情報に紐付けます。[Agent Role](/ja/docs/agent-roles) は繰り返し使う組み合わせを保存します。
3. **セッションを開きます。** ホームページのコンポーザーから、プロジェクト、ブランチ、設定、モデル、権限スコープを選択します。詳細は[セッション](/ja/docs/session)を参照してください。
4. **ラウンド単位で作業します。** 各ラウンドは 1 回のエージェントターンと diff のセットです。[Diff Viewer](/ja/docs/diff-viewer) で内容を確認し、[Diff Comments](/ja/docs/diff-comments) でコメントを追加します。
5. **タスクを完了します。** プルリクエストを作成するか、ブランチを残すか、セッションをアーカイブします。詳細は[推奨ワークフロー](/ja/docs/workflow)を参照してください。

## コアオブジェクト

| 用語 | 概要 | 詳細 |
| --- | --- | --- |
| **Workspace（ワークスペース）** | メンバー、共有マシン、セッション、設定をまとめるチーム単位のコンテナです。 | [チーム機能](/ja/docs/team) |
| **Project / repository（プロジェクト / リポジトリ）** | セッションが作業対象とするコードです（ローカルディレクトリまたは GitHub リポジトリ）。 | [ローカルプロジェクト](/ja/docs/local-project) · [GitHub 連携](/ja/docs/github) |
| **Session（セッション）** | 1 つの会話、1 つのブランチ、そして通常は 1 つのワークツリーを持つ 1 つのタスクです。 | [セッション](/ja/docs/session) |
| **Round（ラウンド）** | 1 回のエージェントターンと、それによって生成されたファイル変更です。 | [Diff Viewer](/ja/docs/diff-viewer) |
| **Worktree（ワークツリー）** | 2 つのセッションが同じリポジトリを競合せずに編集できるよう分離されたチェックアウトです。 | [ワークツリー](/ja/docs/worktrees) |
| **Agent Config** | ランタイム（Claude Code、Codex、Kimi、ACP など）と、その認証情報および実行マシンの組み合わせです。 | [Agent Config](/ja/docs/quickstart) · [CLI ランタイムの種類](/ja/docs/cli-runtimes) |
| **Agent Role** | マシン、Agent Config、モデル、推論設定、権限、および任意の指示を組み合わせた保存済みプリセットです。 | [Agent Roles](/ja/docs/agent-roles) |

## 各要素の関係

<Accordions>
<Accordion title="セッション、ラウンド、ターンの違い">
**セッション（session）**はタスク全体とその履歴を指します。**ラウンド（round）**は 1 回のエージェントターンとその diff のセットです。本ドキュメントで「ラウンドをレビューする」と記載されている場合は、次の操作へ進む前にそのターンで生成された diff を確認することを意味します。
</Accordion>
<Accordion title="Agent Config と Agent Role の違い">
**Agent Config** は「このマシンで何を実行でき、どのように認証するか」を定義します。**Agent Role** は「この種類のタスクを開始するとき、どのマシン・設定・モデル・権限を選択するか」を定義します。ロールは設定を参照しますが、設定がロールを参照することはありません。
</Accordion>
<Accordion title="Fork、Side Chat、ハンドオフの違い">
- **Fork** は会話を新しいセッションに複製し、別のアプローチを試せるようにします。
- **Side Chat** はちょっとした質問をするためにメインチャットの横に固定表示されるフォークです。
- **Handoff（ハンドオフ）** は同じセッションにチームメイトを招待します。複製は作成されません。詳細は[コーディングエージェントセッションの共有](/ja/docs/session-handoff)を参照してください。
</Accordion>
<Accordion title="並列セッションと Agent Session Control の違い">
- **並列セッション**はユーザーが起動するもので、それぞれが独自のタスクとワークツリーを持ちます。詳細は[並列コーディングエージェント](/ja/docs/parallel-agents)を参照してください。
- **Agent Session Control** は、エージェントが Lody の MCP ツールを通じて他のセッションの作成、制御（ステアリング）、結果の収集を行う仕組みです。詳細は [Agent Session Control](/ja/docs/session-orchestration) を参照してください。
</Accordion>
</Accordions>

## よく使われる用語集

| 用語 | 意味 |
| --- | --- |
| **ACP** | Agent Client Protocol の略で、Lody が多くのコーディングエージェント CLI を起動して通信するために使用するインターフェースです。詳細は [CLI ランタイムの種類](/ja/docs/cli-runtimes)を参照してください。 |
| **MCP** | Model Context Protocol の略です。Lody は組み込みの MCP ツールを公開しており、エージェントが Lody の会話やその他のリソースを操作できるようにします。 |
| **Daemon（デーモン）** | マシン上で実際にエージェントを実行するバックグラウンドの Lody CLI プロセスです。詳細は [CLI コマンド](/ja/docs/cli)を参照してください。 |
| **Permission scope（権限スコープ）** | ファイルの編集やシェルコマンドの実行など、エージェントが確認なしで実行できる範囲です。コンポーザーでセッションごとに設定します。 |
| **Context window（コンテキストウィンドウ）** | モデルが一度に保持できる会話の量です。Lody はチャット画面に残容量を表示します。詳細は[コンテキスト、トークンとクォータ](/ja/docs/usage-and-quota)を参照してください。 |
| **Handoff（ハンドオフ）** | ライブセッションにチームメイトを招待し、同じ会話、diff、ワークツリーを引き継いで作業を続けられるようにする機能です。 |
| **Orchestration（オーケストレーション）** | 1 つのエージェントが他のセッションを作成し、メッセージを送り、結果を収集する仕組みです。 |

## よくある質問

### Agent Config と Agent Role の違いは何ですか？

Agent Config は、ランタイムに認証情報と実行マシンを組み合わせたものです。Agent Role は、マシン、Agent Config、モデル、推論設定、権限、および任意の指示をあらかじめ選択して保存するプリセットであり、セッション開始時に同じ構成を再利用できるようにします。詳細は [Agent Config](/ja/docs/quickstart) および [Agent Roles](/ja/docs/agent-roles) を参照してください。

### セッションのフォーク（Fork）とハンドオフ（Handoff）の違いは何ですか？

フォークは会話を新しいセッションに複製し、自分専用のセッションを作成します。ハンドオフは既存のセッションに他のメンバーを招待し、同じライブチャット、diff、ワークツリーを共有して作業できるようにします。フォークしても元のセッションに他のユーザーが追加されることはありません。詳細は[セッション](/ja/docs/session)および[コーディングエージェントセッションの共有](/ja/docs/session-handoff)を参照してください。

### Lody を使うにはワークツリー（Worktree）を理解している必要がありますか？

ワークツリーのディレクトリを一度も開かなくても Lody を利用できます。ワークツリーが重要になるのは、複数のセッションを同時に実行するときです。それぞれのワークツリーによって、各セッションの編集内容が分離されます。詳細は[ワークツリー](/ja/docs/worktrees)を参照してください。

### 「タスク」と「セッション」は同じ意味ですか？

本ドキュメントでは同じ意味で使われています。通常、1 つのタスクは 1 つのセッション、1 つのブランチ、1 つのプルリクエストに対応します。小さなタスクのほうがうまく機能する理由は[推奨ワークフロー](/ja/docs/workflow)で説明しています。
