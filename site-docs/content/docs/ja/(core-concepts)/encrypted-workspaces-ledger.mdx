# 権限台帳

すべてのエンドツーエンド暗号化ワークスペースには**権限台帳**があります。暗号化コンソールでは変更履歴として表示されます。この台帳によって、誰がメンバーであるか、各自がどのロールを持つか、どのデバイスが鍵を受け取れるかが決まります。

## 台帳に記録される内容

台帳は順序付けられたレコードのリストであり、各レコードが1つの変更を表します。たとえば次のような変更です。

- ワークスペースの作成（最初のレコード、いわゆる「ジェネシス」）
- メンバーの承認、ロールの変更、メンバーの削除
- デバイスの追加または失効
- ワークスペース鍵の更新
- オーナー権限の移譲

記録されるのは**アカウント ID とデバイスの公開鍵**であり、会話やファイルが記録されることはありません。名前やアバターはアカウントプロフィールから取得され、台帳には含まれません。

## すべてのレコードに署名が付与されます

各レコードには、変更を行う本人が**自身の認可済み個人デバイス上で**署名します。署名は操作内容、対象、ワークスペースを対象としており、いずれかを改ざんすると署名は無効になります。

サーバーはレコードを保存して中継しますが、**誰の署名鍵も保持していません**。そのため、誰かの代わりに署名したり、メンバーやデバイスを密かに追加したりすることはできません。

## レコードはチェーンを構成します

各レコードには直前のレコードのハッシュが含まれており、ジェネシスまで一本の鎖のようにつながっています。

- レコードを削除、挿入、または並べ替えるとチェーンが壊れ、デバイスがそれを検知します。
- 新しいレコードは現在の末尾にのみ追記できます。2人が同時に送信した場合、成功するのは1人だけで、もう1人は最新の状態に更新してから再度確定する必要があります。
- 変更は確定（コミット）された順に有効になります。オーナーが B を削除する前に B が C を承認した場合、C はメンバーのまま残ります。削除が先に確定した場合、B による以前の招待は無効になります。

## 誰が何に署名できるか

すべての変更について、デバイスは署名者の権限を、参加時点で何ができたかではなく、**その変更の直前時点における台帳の状態**に照らして確認します。

| 変更内容 | 署名できる人 |
| --- | --- |
| メンバーの承認 | オーナーまたは管理者 |
| メンバーの削除 | オーナーまたは管理者 |
| 管理者の削除、ロールの変更 | オーナーのみ |
| オーナー権限の移譲 | オーナーのみ（元のオーナーは管理者になります） |
| 自分の新しいデバイスの追加 | 自身の認可済みデバイスのいずれか（すべて紛失した場合はリカバリファイル） |
| デバイスの失効 | そのデバイスの所有者、または管理権限を持つメンバー |
| ワークスペース鍵の更新 | オーナーまたは管理者 |

リモートマシンやリカバリデバイスは**管理権限を決して持ちません**。鍵を受け取って作業を実行するだけです。

## デバイスによる台帳の検証方法

- **既存のデバイス**は、直前のレコードに正しく連結されており、署名が有効で、かつ署名者がその時点で権限を持っていた場合にのみ新しいレコードを受け入れます。
- **新しく参加したデバイス**は、必ずしもジェネシスからすべて再生するわけではありません。オーナーまたは管理者のデバイスによって署名された「現在の状態」のスナップショットを受け入れ、それ以降のすべてのレコードを検証できます。これは、スナップショットの署名者を信頼することを意味します。
- **検証に失敗した場合**、デバイスは最後に信頼できたレコードで停止し、証拠を保持したうえで、招待と承認の処理を一時停止します。自動的に**修復したりスキップしたりすることは決してありません**。既存の会話は引き続き閲覧できます。

## 失効と鍵の更新

- デバイスの失効は、そのデバイスのみに影響します。ノート PC を失効させても、そのノート PC が以前承認したスマートフォンまで失効することはありません。
- メンバーを削除すると、そのメンバーのすべてのデバイスが即座に切り離されます。その後、**ワークスペース鍵を更新**します。新しい鍵は現在も認可されているデバイスにのみ配布されるため、古い鍵を持つ旧デバイスは新しいコンテンツを復号できません。ただし、すでにデバイスへダウンロード済みの履歴を取り戻すことはできません。

## 台帳が依存する前提

台帳はサーバーが署名を**偽造**することを防ぎます。一方で、全員が**同じ最新の**台帳を保持していることを台帳単体で保証することはできません。

現在のバージョンでは、サーバーがロールバックや分岐のない完全な台帳を提供することを前提としています。異なるユーザーに異なるバージョンの台帳を見せるサーバーであっても署名を偽造することはできませんが、一部のユーザーに対して失効の事実を隠すことはできてしまいます。

そのために用意されているのが[セキュリティコード](/ja/docs/encrypted-workspaces-security-code)です。チームメイトとコードを比較することで、同じ台帳を保持しているかどうかを確認できます。
