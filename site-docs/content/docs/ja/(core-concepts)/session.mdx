# セッション

セッションは Lody における最も基本的な概念です。ホームページのコンポーザーから新しいセッションを開始できます。これは Claude Code / Codex CLI における 1 つの会話に相当します。

開始前に、コンポーザー周辺のメニューからセッションを設定できます：

- リポジトリとブランチ
- エージェント設定
- モデル
- 権限スコープ

Lody はこれらの選択内容に基づいてセッションを起動します。

1 つのセッション内に複数のタブを含めることもできます。メインチャット、子チャット、ファイルプレビュー、差分ビューをすべて同じセッション内にまとめることができます。コードを読みながらチャットを続けたり、1 つのタスクを複数のレビュースレッドに分割したりしたい場合は、[セッションタブ](/ja/docs/session-tabs) をご覧ください。

チームメイトを既存のセッションに招待して同じ会話、差分、Worktree を引き継いでもらう方法については、[コーディングエージェントのセッションを共有する](/ja/docs/session-handoff) をご覧ください。以下のフォーク機能は自分用の新しいセッションを開始するものであり、元のセッションに誰かを追加するものではありません。

## セッションをフォークする

使用しているエージェントがネイティブのセッションフォークに対応している場合、完了した最新のエージェント返信の下に **Fork session** ボタンが表示されます。フォークすると、その返信までの会話履歴を引き継いだ新しいセッションが作成され、元のセッションを変更せずに別の方向へ作業を続けることができます。

Codex および Claude Code では、それ以前の完了したエージェント返信からフォークすることもできます。

Worktree フォークに対応している Git ベースのセッションでは、**Fork session** で 2 つの作成先を選択できます：

- **Current workspace** — 元のセッションとファイルや未コミットの変更を共有する新しいタブ
- **New worktree** — コミット済みの最新 `HEAD` から作成される新しい独立したセッション。未コミットおよび未追跡のファイルは元のセッションに残ります

**New worktree** が提示されない場合、フォークは現在のワークスペース上で行われます。サイドチャットは常に共有ディレクトリのパスを使用します。

フォークは、アクティブなエージェントがネイティブ対応を報告している場合にのみ利用できます。

## 右サイドバー：Browser とサイドチャット

右サイドバーには、メインの会話の横にツールを配置できます。セッションツールバーから **Browser** を開いてページを閲覧したり、サイドバーの `+` メニューからパネルを追加したりできます。

**サイドチャット**（Side Chat）は、対象となる最新のエージェント返信からフォークを作成し、右サイドバーに別チャットとして開きます。メインのセッションをそのまま維持しながら、追加の質問やレビューに関する質問をするのに便利です。サイドチャットは複数作成でき、サイドバー内で切り替えたり、不要になったら `X` ボタンで閉じたりできます。サイドチャットは、アクティブなエージェントがネイティブのセッションフォークに対応している場合に利用できます。

URL やリモートポートへのアクセス詳細については、[Lody Preview](/ja/docs/preview) をご覧ください。

## セッション一覧

左サイドバーには、チャット、GitHub Worktree、ローカルプロジェクトの会話が表示されます。
デフォルトのプロジェクト単位の整理方法に加えて、**Updated** モードに切り替えることで、すべてを更新日時順（Today、This week、Older）にグループ化することもできます。

各セッションには AI が生成したセマンティックタイトルと現在のステータスが表示されます。セッションにカーソルを合わせると、セッション情報カードにリポジトリ、ブランチ、プルリクエストのステータス、ベースブランチに対する変更行数が表示されます。

## セッション操作

サイドバー内のセッションを右クリックするとコンテキストメニューが開きます。ここから名前の変更、ピン留め、アーカイブ、セッション URL のコピー、現在のブランチ名のコピーを行えます。

ピン留めしたセッションは一覧の上部に固定されるため、重要な作業や長期にわたる作業をすぐに見つけられます。Web アプリでは、サイドバーのタスクを中クリックまたは Cmd/Ctrl+クリックすると新しいブラウザータブで開きます。

会話アクションバーおよびセッション情報コントロールには、現在のタスクに関連する操作（利用可能な場合はプロジェクト、ブランチ、プレビュー、プルリクエスト、コード変更の操作など）がまとめられています。これにより、よく使う GitHub やプロジェクトの操作を別画面へ移動せずに会話の横からすぐに行えます。

## デスクトップでのクイックセッション

`Cmd/Ctrl+Shift+N` を押すと、独立したクイックセッションウィンドウが開きます。これはシステム全体のデスクトップショートカットであるため、Lody にフォーカスが合っていないときでも動作します。コンパクトなコンポーザーからプロジェクト、エージェント、モデルを選択し、メインウィンドウを先に開かずにセッションを開始できます。

このショートカットは **Settings** -> **Keyboard** から変更できます。詳しくは [コマンドパレットとキーボードショートカット](/ja/docs/keyboard-shortcuts) をご覧ください。

## エディターでワークスペースを開く

デスクトップのセッションヘッダーにある **Open in** を使うと、現在の Worktree またはプロジェクトディレクトリを起動できます。組み込みランチャーには VS Code、Xcode、Sublime Text などの対応エディターが含まれています。

**Settings** -> **General** -> **Path launchers** では、デフォルトのランチャーを選択したり、カスタムシェルコマンドを追加したりできます。カスタムテンプレートではセッションフォルダーの引数として `{path}` を使用する必要があり、現在のデスクトップにのみ保存されます。

エディターですでに開いているプロジェクトを開いた場合は、新しいウィンドウを開くのではなく既存のウィンドウにフォーカスします（Zed などの場合）。

## セッションをアーカイブする

一覧のセッションにカーソルを合わせる（モバイルではタップする）と、右下にアーカイブボタンが表示されます。これをクリックするとセッションがアーカイブされます。

アーカイブされたセッションはアーカイブ一覧に移動し、会話履歴は保持されます。所有マシンは完全削除の前に Lody 管理下の Worktree ディレクトリを回収することがあり、その際はローカルブランチを保持し、保留中の無視対象外の（non-ignored）変更を先にコミットします。無視対象（ignored）のファイルは破棄される場合があり、クリーンアップスクリプトによってバックアップ前にファイルが変更されることもあります。アーカイブする前に、必要なファイルは Worktree の外に保存してください。保持期間、復旧要件、保護境界については、[Worktree の保持と復旧](/ja/docs/worktrees#自動クリーンアップ) をご覧ください。ローカルプロジェクトディレクトリで直接実行されているセッションは、管理下 Worktree のクリーンアップによってそのディレクトリが削除されることはありません。

## セッションのアーカイブを解除する

左サイドバーの右下にあるアーカイブ一覧ボタンをクリックして、アーカイブ済みセッションを開きます。検索や並び替えでセッションを見つけ、復元ボタンをクリックするといつでもアクティブな一覧に戻してチャットを続けられます。

## セッションを削除する

左サイドバーの右下にあるアーカイブ一覧ボタンをクリックして、アーカイブ済みセッションを開きます。セッションの横にある削除ボタンをクリックすると、そのセッションと会話履歴が完全に削除されます。この操作は元に戻せません。残っている管理下 Worktree は [同じバックアップルール](/ja/docs/worktrees#自動クリーンアップ) に従ってクリーンアップの対象となりますが、ローカルの Git ブランチとコミットは保持されます。

プロジェクトを選択していないセッションでは、削除により Lody 管理下のチャット作業ディレクトリとその中のすべてのファイルもバックアップや復旧なしで削除されます（アーカイブでは空のディレクトリのみが回収されます）。

## 一括復元と削除

会話にカーソルを合わせて先頭のチェックボックスをクリックすると、複数選択モードに入ります。その後、その他の操作から一括選択を行い、右上のコントロールから一括復元または削除を選択できます。
