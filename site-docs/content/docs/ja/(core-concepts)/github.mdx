# GitHub 連携

デスクトップとモバイルのどちらでもスムーズに作業できるよう、Lody では GitHub 連携をプロダクトの中核機能として位置づけています。対象リポジトリに Lody GitHub App をインストールすると、どのデバイスからでもプロジェクトをクローンし、Issue や PR のコンテキストを取得して、よりスムーズなワークフローを利用できます。

## セットアップ

**Settings** -> **GitHub** -> **Manage** を開くと、GitHub App のインストールページへ移動します。
Lody にアクセスを許可したいリポジトリを選択してから、Lody に戻ってください。選択したリポジトリが **Repositories available to add to workspace** に表示されるので、現在のワークスペースに必要なものを追加します。

Lody では、1 つのリポジトリを複数のワークスペースで共有できます。他のワークスペースでは、すでに GitHub App がインストールされているリポジトリをそのまま選択して追加できます。

### 許可済みリストにリポジトリが表示されない場合

アクセスを許可したはずのリポジトリが **Authorized Repositories** に表示されない場合、GitHub App のインストール時にそのリポジトリが漏れている可能性があります（たとえば、リポジトリを選択する前に **Install** をクリックした場合や、管理者の承認が必要な Organization に属している場合など）。

最も簡単な対処方法は、認証を最初からやり直すことです。

1. [github.com/settings/installations](https://github.com/settings/installations)（個人用リポジトリの場合）、または Organization の **Settings → GitHub Apps → Lody → Configure** ページを開きます。
2. **Lody** GitHub App をアンインストールします。
3. Lody に戻り、**Settings → GitHub → Manage** を開いてアプリを再インストールします。この際、Lody にアクセスさせたいすべてのリポジトリを選択してください。

再インストールが完了したら Settings ページに戻ります。リポジトリが一覧に表示され、ワークスペースに追加できるようになります。

## 個人の GitHub アカウント連携

GitHub App のインストールによって Lody にリポジトリへのアクセス権が付与されます。個人のアカウント連携はそれとは別の任意設定であり、PR のコメント投稿、レビュー操作、マージをご自身の GitHub ユーザー名義で実行したい場合にのみ有効にします。利用するには、**Settings** -> **GitHub** で **Act as you for PRs, comments, and merges** をオンにし、ご自身の GitHub アカウントを認証してください。

認証が完了すると、Settings ページに連携済みの GitHub アカウントが表示されます。これによって Lody がアクセスできるリポジトリが変わるわけではなく、リポジトリへのアクセス権は引き続き GitHub App のインストール設定に基づきます。Lody に再びワークスペースの GitHub App 名義のみを使わせたい場合は、後からいつでもこのオプションをオフに戻せます。

## 会話で使用するリポジトリの選択

ホームページのコンポーザー左上にあるリポジトリセレクターから、ワークスペースに追加済みのリポジトリを選択します。すると Lody にそのリポジトリのブランチ一覧が表示され、作業を開始するブランチを選べるようになります。

会話を作成すると、Lody は CLI マシン上でリポジトリをクローンして初期化し、選択したブランチから新しい [Worktree](/ja/docs/worktrees) を作成します。各会話はそれぞれ独立したブランチ上で実行されるため、他の会話に影響を与えることはありません。

## Issue または Pull Request から開始する

ホームページでリポジトリを選択した後、`@` を入力してメンションメニューを開き、**Issues** または **Pull Requests** を選択すると、現在のリポジトリの項目をメンションできます。

<MentionPreview locale="ja" kind="issue" />

上下の矢印キーで項目を選び、Enter キーを押して確定します。Lody は選択した項目を `#<number>` としてコンポーザーに挿入し、そのコンテキストをプロンプトに組み込むため、エージェントは `Fix #12` や `Review the implementation in #56` のようなタスクを処理できます。

## PR ステータスと CI の同期

セッションが GitHub PR にリンクされると、Lody のセッション UI 上に PR 番号、open/closed/merged ステータス、および CI の状態が表示されます。実行中、成功、失敗といったチェック結果も Lody 内で更新されるため、ブランチの準備ができているかを確認するたびに GitHub へ切り替える必要はありません。

すでに PR が存在するブランチで作業を続けた場合も、Lody がその PR を自動的に検出し、セッションへ紐づけようとします。

## Lody からの PR 操作

リンクされたセッションの上部にある PR バッジをクリックすると、PR パネルが開きます。このパネルから、Lody を離れることなく PR のタイトル、説明文、ブランチ、CI、コメント、レビューを確認できます。

ドラフト PR の場合は、PR パネルに **Ready for review** アクションが表示されます。PR の準備が整いマージ可能な状態になれば、Lody 上からそのままマージでき、GitHub 側にブランチが残っている場合はマージ後にブランチを削除することも可能です。

## PR セッションでのコミットとプッシュ

PR にリンクされた GitHub ベースのセッションでは、エージェントのターンが終了するたびに Lody がワークスペースを確認します。未コミットの変更やまだプッシュされていないローカルコミットがある場合、Lody はエージェントに対してそれらをコミットして PR ブランチへプッシュするよう依頼できます。

セッション UI から手動で **Commit & Push** を実行したり、レビューコメントへの対応がさらに必要な場合に **Fix PR Comments** を使用したりすることも可能です。

## レビューコメントの同期

[Diff Comments](/ja/docs/diff-comments) では、PR にリンクされたセッションで **Sync to GitHub** を有効にすることで、新しい行コメントを GitHub へ公開できます。

また、既存の GitHub PR レビューの行コメントも Lody の差分ビューに表示され、Lody から送信した返信は GitHub に投稿されます。これにより、コードレビュー、変更内容の確認、エージェントによる後続作業を 1 か所にまとめることができます。
