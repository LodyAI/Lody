# 初めてのセッション

[クイックスタート](/ja/docs/quickstart)では、Lody のインストールと接続までを案内しています。このページでは、そこで扱っていない部分、つまり空のコンポーザーから始めてレビュー済みの結果を得るまでの、1 つの完結したセッションの流れを解説します。ここで行う操作はすべてローカルプロジェクト上で完結し、GitHub の利用や複数エージェントの同時実行は必要ありません。

<Callout type="info" title="始める前に">
- Lody がインストールされ、サインイン済みであること。まだの場合は、先に[クイックスタート](/ja/docs/quickstart)を完了してください。
- プロジェクトを 1 つ追加してあること（通常のローカルディレクトリで問題ありません）。[ローカルプロジェクト](/ja/docs/local-project)を参照してください。
- そのマシン上で **Test** に合格した Agent Config が 1 つあること。[Agent Config](/ja/docs/quickstart) を参照してください。
</Callout>

## 1 セッションで収まる小さなタスクを選ぶ

セッションとは、1 つのタスクについて 1 つのエージェントと行う 1 つの会話のことです。タスクが小さければ結果を素早くレビューでき、エージェントもタスクをやり切るのに十分なコンテキストを保てます。最初のタスクとしては、次のようなものが適しています。

- 「アプリのバージョンを返す `/health` エンドポイントを追加してください。」
- 「`src/parser.test.ts` で失敗しているテストを修正し、原因を説明してください。」
- 「パッケージ全体で `fetchUser` を `getUser` にリネームし、呼び出し元も更新してください。」

最初のセッションで機能領域全体をまとめて依頼するのは避けましょう。1 つのセッションに収まらなくなってきた場合は、[推奨ワークフロー](/ja/docs/workflow)で作業を分割する方法を確認してください。

<Callout title="1 セッション、1 タスク" type="idea">
以降のドキュメントも、この習慣を前提にしています。1 つのセッションで無関係な 2 つの作業が始まってしまった場合は、最初のセッションを長く引き延ばすのではなく、そのセッションを止めて 2 つ目のセッションを新しく始めてください。
</Callout>

## 1 つのセッションの流れを体験する

<Steps>
<Step>

### 1. ホームページのコンポーザーから始める

Lody を開き、ホームページのコンポーザーを使います。送信する前に、次の項目を選択してください。

- **プロジェクト**（Git プロジェクトの場合はブランチも）
- **Agent Config** と**モデル**
- 安心して許可できる**権限スコープ**

続いて、対象のファイルや期待する挙動、および成功をどう判断するかを含めてタスクを記述します。

```text
{ "status": "ok", "version": <package version> } を返す /health エンドポイントを追加してください。
status フィールドと version フィールドを検証するテストを 1 つ追加してください。他のルートは変更しないでください。
```

</Step>
<Step>

### 2. ラウンドの進行を見守る

Lody がセッションを作成し、エージェントの作業をストリーミング表示します。**ラウンド（round）**とは、エージェントの 1 ターン分の応答と、それによって生じたファイル変更をまとめた単位です。ラウンドの実行中は、次の操作を行えます。

- 完了を待たずに追加のメッセージを送り、実行中のタスクを[**誘導（steer）**](/ja/docs/claude-codex-capabilities#実行中タスクのステアリング)する
- エージェントがネイティブなフォークに対応している場合は、メインのタスクを中断せずに [**Side Chat**](/ja/docs/session#右サイドバーbrowser-とサイドチャット) で質問する
- エージェントが誤った方向に進んでいる場合はターンを停止する

</Step>
<Step>

### 3. diff をレビューする

ラウンドが終了すると、返信に変更されたファイルと追加・削除された行数が表示されます。いずれかのファイルをクリックして [diff タブ](/ja/docs/diff-viewer)で開くか、**Files** および **Changes** サイドバーを使って会話全体の変更内容を確認できます。

</Step>
<Step>

### 4. 次のラウンドを依頼する

同じセッションのまま作業を続けます。追加の指示は 1 回につき 1 つの内容に絞ってください。

```text
テストは通っていますが、リクエスト時に毎回 package.json からバージョンを読み込んでいます。
代わりにモジュール定数で一度だけ読み込むように変更し、レスポンス形式はそのまま維持してください。
```

「進行の確認、レビュー、追加指示」のサイクルは、タスクに必要なだけ何度でも繰り返せます。会話が長くなりすぎたり、エージェントが文脈を見失ったりした場合は、短い要約を添えて新しいセッションを始めてください。

</Step>
<Step>

### 5. 結果の扱い方を決める

変更内容に問題がなければ、いくつかの選択肢があります。

- **ブランチをそのまま残す。** セッションから現在のブランチ名をコピーし、普段お使いのエディタからテストやプッシュを行います。
- **ローカルで開く。** デスクトップ版では、**Open in** を使ってお使いのエディタでワークツリーを開けます。
- **プルリクエストを作成する。** GitHub セッションの場合は、会話の上部にある **Create PR** を使います。Lody が PR をセッションに紐付け、CI ステータスを同期します。これが[推奨ワークフロー](/ja/docs/workflow)の出発点です。
- **セッションをアーカイブする。** 作業が完了したら、サイドバーからアーカイブします。アーカイブするとワークツリーは回収されますが、ブランチと会話履歴は保持されるため、後からいつでも復元できます。[セッションのアーカイブ](/ja/docs/session#セッションをアーカイブする)を参照してください。

</Step>
</Steps>

## 初めてのセッションでよくある失敗

<Accordions>
<Accordion title="一度に多くを頼みすぎる">
長く複数の要件を詰め込んだプロンプトは、エージェントの作業とレビューの両方を難しくします。それぞれがレビュー可能な 1 つの変更を生み出す単位でセッションを分割してください。[並列コーディングエージェント](/ja/docs/parallel-agents)を参照してください。
</Accordion>
<Accordion title="プロジェクトや Agent Config を選び忘れる">
プロジェクトが未選択または誤っていると、エージェントは意図しないディレクトリで作業してしまいます。送信前に、コンポーザーでプロジェクト、ブランチ、Agent Config、モデルを確認してください。
</Accordion>
<Accordion title="最後になってからまとめてレビューする">
ラウンド単位の diff は読みやすく、コメントも付けやすいのが特徴です。ラウンドごとにレビューすることで、誤った方向性の変更が全体に広がるのを防げます。
</Accordion>
<Accordion title="アーカイブをまったくしない">
終了したセッションにもワークツリーは残ります。作業がマージされたり中止されたりしたらアーカイブし、マシンがディスク容量を回収できるようにしましょう。
</Accordion>
</Accordions>

## よくある質問

### 最初のセッションに GitHub は必要ですか？

いいえ、不要です。GitHub を使うとプルリクエスト、CI ステータス、レビューコメントの同期が利用できるようになりますが、ローカルプロジェクトのセッションだけでもチャット、ファイル編集、diff 表示、レビューをすべて完結できます。[ローカルプロジェクト](/ja/docs/local-project)を参照してください。

### 「ラウンド（round）」とは何ですか？

ラウンドとは、エージェントの 1 ターン分の応答と、その間に生成されたファイル変更を合わせたものです。Lody はラウンドごとに diff の要約を提示するため、最後に巨大な diff を一度に読むのではなく、継続的にレビューを進められます。[Diff ビューアー](/ja/docs/diff-viewer)を参照してください。

### 指示していない箇所をエージェントが変更した場合はどうすればよいですか？

該当ファイルの diff を開き、コメントを残すか同じセッション内で追加の指示を送って修正させてください。タスクと無関係な変更であれば、その変更を元に戻すよう指示し、セッションの焦点を絞った状態に保ちましょう。

### 実行中のセッションを停止できますか？

はい、できます。コンポーザーにある停止コントロールを使って、現在実行中のターンをキャンセルしてください。停止したセッションは一覧に残り、新しいメッセージを送ることで作業を続けられます。

### アーカイブしたセッションはどこへ移動しますか？

サイドバー右下のアーカイブ一覧へ移動します。会話履歴とブランチはそのまま保持され、セッションを復元するとワークツリーが再作成されます。[セッションのアーカイブ](/ja/docs/session#セッションをアーカイブする)を参照してください。
