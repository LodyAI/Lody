# Codex または Claude Code からの移行

`codex` や `claude` CLI の使用をやめる必要はありません。Lody は[エージェント設定（Agent Config）](/ja/docs/quickstart)を通じてそれらの同じランタイムを実行し、その周囲にワークスペース機能（独立したワークツリー、複数セッションの同時実行、リアルタイムの差分レビュー、チームへの引き継ぎ、モバイルアクセス）を追加します。

<Callout title="概要">
- サブスクリプション、API キー、マシン側のログイン情報はそのまま維持されます。
- セッションは Lody における 1 つの CLI 会話に相当し、Agent Config はその背後で動作するランタイムです。
- Lody が追加するのはワークスペース層（並列ワークツリー、レビュー、共有、オーケストレーション）です。
</Callout>

## 変わらない点

- **ランタイム:** Lody は同じエージェントプロセスを起動するため、モデルや CLI 本来の動作が置き換わることはありません。
- **認証情報:** Lody はマシン上にすでにあるサブスクリプションログインや環境設定をそのまま使用します。詳しくは [Agent Config](/ja/docs/quickstart) をご覧ください。
- **リポジトリの規約:** エージェントは引き続きプロジェクト内で実行されるため、`AGENTS.md`、`CLAUDE.md`、その他のプロジェクト指示ファイルもそのまま機能します。
- **ターミナル:** ちょっとした単発タスクであれば、CLI を直接実行するのも引き続き良い選択肢です。

## 概念の対応表

| 従来の操作 | Lody での対応 | 備考 |
| --- | --- | --- |
| ターミナルでの `claude` や `codex` | [Agent Config](/ja/docs/quickstart) を用いた[セッション](/ja/docs/session) | 同じランタイムに GUI、モバイル、チーム層を追加 |
| 1 つのリポジトリチェックアウト | セッションごとに 1 つの[ワークツリー](/ja/docs/worktrees) | セッション同士が同じファイルで衝突しなくなります |
| プロンプトとそれによる編集 | [ラウンド](/ja/docs/diff-viewer) | Lody は各ラウンドの後に差分を表示します |
| `--resume` や `resume` | サイドバーからセッションを再度開く | 会話、ブランチ、ワークツリーが一体で保持されます |
| 手動での `git diff` レビュー | [Diff Viewer](/ja/docs/diff-viewer) と [Diff Comments](/ja/docs/diff-comments) | 行単位でコメントし、GitHub PR に同期できます |
| 1 度に 1 つのターミナル | 複数の[並列セッション](/ja/docs/parallel-agents) | 各タスクに専用のブランチとワークツリーが割り当てられます |
| スラッシュコマンドとモード | ランタイムが公開する[スラッシュコマンド](/ja/docs/slash-commands) | Lody がランタイムの対応状況を自動検出します |
| チームへのスクリーンショットやトランスクリプト共有 | [セッションの引き継ぎ](/ja/docs/session-handoff) | 実行中のライブセッションにチームメイトを招待できます |

各組み込みプロバイダーがサポートしているオプションの ACP および Lody 拡張機能については、[ACP と拡張機能のサポート状況](/ja/docs/acp-feature-support)マトリックスをご覧ください。

## 移行チェックリスト

<Steps>
<Step>

### 1. Lody をインストールしてサインインする

[クイックスタート](/ja/docs/quickstart)の手順に従ってください。デスクトップアプリ、モバイルアプリ、またはリモートマシン上の CLI のいずれからでも始められます。

</Step>
<Step>

### 2. 既存のログイン情報をそのまま使う

**Settings** -> **Agent Config** を開き、使用する各ランタイムの設定を追加します。ほとんどの場合、新しい認証情報は不要です。Lody はマシン上にすでに存在するサブスクリプションログインや環境設定を使用します。

</Step>
<Step>

### 3. プロジェクトを追加する

すでに作業しているディレクトリに対して[ローカルプロジェクト](/ja/docs/local-project)を追加するか、プルリクエストや CI のために [GitHub リポジトリ](/ja/docs/github)を連携します。そのローカルプロジェクトですでに Codex や Claude Code を実行していた場合、Lody は既存の履歴をインポートして継続できます。詳しくは[コードエージェント履歴の同期](/ja/docs/local-project#sync-code-agent-history-codex-claude-code-and-more)をご覧ください。

</Step>
<Step>

### 4. 小さなセッションを 1 つ実行する

CLI で 1 回で終わる程度のタスクを使い、[最初のセッション](/ja/docs/first-session)を試してみてください。プロジェクト、Agent Config、モデルが想定通りになっているか確認します。

</Step>
<Step>

### 5. 繰り返す構成を保存する

同じマシン、設定、モデル、指示で同じ種類のタスクを毎回開始する場合は、毎回すべてを選び直す代わりに [Agent Role](/ja/docs/agent-roles) として保存しておけます。

</Step>
<Step>

### 6. 必要に応じてワークスペース層を追加する

PR や CI のために GitHub を連携したり、2 つの小さなタスクで[並列セッション](/ja/docs/parallel-agents)を試したり、[セッションの引き継ぎ](/ja/docs/session-handoff)でチームメイトを招待したりできます。これらは 1 つずつ段階的に取り入れられます。

</Step>
</Steps>

## CLI の方が適している場面

<Callout type="info" title="適材適所でターミナルを使い分ける">
レビュー履歴を残す必要のない単発のちょっとした編集、エージェント自体のデバッグ、あるいは Lody デーモンを実行したくないマシンでの作業では、CLI を直接使うのが適しています。Lody が最も力を発揮するのは、ワークツリー、レビュー可能な差分、チームメイトとの協働、あるいは別デバイスからの操作が役立つタスクです。
</Callout>

## よくある質問

### Lody は Codex や Claude Code CLI を置き換えるものですか？

いいえ。Lody はそれらのランタイム（および他のランタイム）を起動し、その周囲にワークスペース機能を追加するツールです。CLI も引き続きサポートされた作業方法であり、同じマシンで両方を併用できます。

### API キーやサブスクリプションを移行する必要がありますか？

いいえ。一般的なケースでは、Lody はマシン上にすでにあるサブスクリプションログインや環境設定を使用します。Lody にどのランタイムを起動するかを知らせるために [Agent Config](/ja/docs/quickstart) を追加するだけでよく、認証情報を Lody に移行する必要はありません。

### リポジトリの AGENTS.md や CLAUDE.md は引き続き使えますか？

はい。エージェントは引き続きリポジトリ内で実行されるため、すでに読み込まれている指示ファイルはそのまま機能します。

### `codex resume` や `claude --resume` のように会話を再開するにはどうすればよいですか？

サイドバーからセッションを開いてください。Lody は会話、ブランチ、ワークツリーを一体として保持しています。ランタイムがネイティブのフォーク機能に対応している場合は、[フォーク](/ja/docs/session#fork-a-session)を作成して元のセッションを変更せずに新しい方向で続行することもできます。詳しくは[セッション](/ja/docs/session)をご覧ください。

### 同じセッションにスマートフォンから Lody を利用できますか？

はい。実行マシンがオンラインであり、同じ Lody ワークスペースにサインインしている必要があります。詳しくは[モバイルアクセス](/ja/docs/mobile)をご覧ください。
