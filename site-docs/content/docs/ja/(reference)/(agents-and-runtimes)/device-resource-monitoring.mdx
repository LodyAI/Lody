# デバイスのリソース監視

Lody では、接続されている各デバイスと、そのデバイス上に常駐しているすべての ACP セッションの現在のリソース使用状況を確認できます。このビューを使用すると、CPU やメモリを消費しているエージェントを特定してそのセッションを開いたり、会話を削除せずに ACP プロセスを停止したりできます。

**Settings -> Devices** を開き、オンラインのデバイスを選択します。ページを開くとサンプリングが自動的に開始されます。手動更新ボタンはありません。

## 常駐 ACP セッションとは

各会話は、コーディングエージェントと通信するために ACP プロセスを使用します。ターンがアイドル状態になった後もこのプロセスは常駐したままになることがあり、次のターンの開始が速くなる一方で、一定のメモリを消費し続けます。ACP セッションテーブルには、選択したデバイス上に現在エージェントプロセスが存在している会話が一覧表示されます。

これはプロセスのビューであり、保存されているすべての会話の一覧ではありません。ACP プロセスがすでに停止している会話も Lody 上には残りますが、このテーブルには表示されなくなります。

## リソースサマリー

ページ上部では、数値を誤って合算してしまわないよう、3 つのスコープに分けて表示しています。

| スコープ | CPU | メモリ |
| --- | --- | --- |
| **CLI** | Lody CLI 制御プロセス自体の CPU 使用率 | Lody CLI 制御プロセスが使用しているメモリ |
| **ACP sessions** | 常駐 ACP セッションのプロセスツリー全体で使用されている CPU の合計 | 常駐 ACP セッションのプロセスツリー全体で使用されているメモリの合計 |
| **Device info** | Lody、エージェント、OS、その他のアプリケーションを含むデバイス全体で使用されている CPU | デバイスの使用中メモリ / 実効総メモリ |

**Device info は CLI と ACP セッションの合計ではありません。** マシン上の他のすべてのプロセスも含まれます。逆に、CLI と ACP の値を見ることで、デバイス全体のリソース使用量のうち Lody が占めている割合を把握できます。

### CPU 使用率

3 つのスコープすべてで、同じマルチコア表記のルールが使用されます。

- 1 つの論理 CPU コアを完全に使い切っている場合は `100%`
- 2 つの論理コアを完全に使い切っている場合は `200%`
- 8 コアのデバイスでは、デバイス全体の実用上の最大値は約 `800%`

たとえば、1.5 コアを使用している ACP セッションは `150%` と表示されます。サンプルは短い間隔で収集され、プロセスツリーの計測方法もプラットフォームによって異なるため、デバイス全体、CLI、合算値、およびセッションごとの数値の間にわずかな差異が生じる場合があります。

### メモリ

メモリは累積割り当て量ではなく、現在の常駐フットプリント（resident footprint）を表します。正確な計測方法は OS によって異なり、Lody は利用可能な環境では cgroup による計測を使用し、それ以外の場合は該当するプロセスツリーを計測します。macOS では、physical-footprint の報告値が RSS のみを合算するツールの値と異なる場合があります。

デバイスの値は **使用中 / 実効合計** として表示されます。Lody が制約のある環境で動作している場合、「実効合計」はホストの物理搭載 RAM ではなく、コンテナーや cgroup のメモリ上限になることがあります。利用可能メモリ、キャッシュ、共有ページ、およびプラットフォームごとの計測仕様により、各行の値を手動で合算してもデバイス全体の合計値とは一致しない場合があります。

### 値が `-` と表示される理由

CPU 使用率は 2 つのサンプル間の変化量から計算されるため、監視の開始直後または CLI の再起動直後の最初のサンプルでは取得できません。また、OS がプロセスツリーに対して信頼できる計測値を提供できない場合、セッションの CPU、メモリ、またはプロセス数に `-` が表示されることがあります。まずは次の自動サンプリングをお待ちください。それでも値が取得できない場合は、デバイスがオンラインであることと、Lody CLI が最新であることを確認してください。

## ACP セッションテーブル

各行が 1 つの常駐会話に対応しています。

| 列 | 意味 |
| --- | --- |
| **Session** | 会話タイトル、ACP 名、ACP ロゴ。選択すると対応するセッションとタブが開きます。省略されたタイトルにカーソルを合わせると、完全なタイトルが表示されます。 |
| **Status** | 現在の ACP ライフサイクルまたはアクティビティの状態 |
| **Memory** | そのセッションの ACP プロセスツリーに割り当てられている現在のメモリ使用量 |
| **CPU** | そのプロセスツリーが使用している CPU（1 論理コアのフル稼働が `100%`） |
| **Processes** | 追跡対象の子プロセスを含め、現在そのセッションに紐付けられているプロセス数 |

テーブルには最大 100 件の常駐セッションが表示されます。特に Lody がプロセスツリーから所有関係を推定するプラットフォームでは、計測値がプロセスの作成や終了よりわずかに遅れて反映される場合があります。

### ステータス一覧

| ステータス | 意味 |
| --- | --- |
| **Initializing** | Lody が ACP プロセスを起動中、または接続中です |
| **Running** | エージェントが現在ターンを処理中です |
| **Waiting for permission** | 権限リクエストへの応答があるまでエージェントが一時停止しています |
| **Finalizing** | エージェントが主な作業を終え、Lody が最終処理を完了しようとしています |
| **Idle** | ACP プロセスは常駐していますが、現在ターンを処理していません |
| **Stopping** | 終了リクエストが進行中で、Lody がプロセスの終了を待機しています |
| **Failed** | 常駐セッションまたはその ACP プロセスでエラーが発生しました |

## ACP セッションのリソースを解放する

セッション行の末尾にある停止アイコンを選択すると、そのセッションの ACP プロセスを終了できます。アイドル状態のプロセスを停止する場合は、確認なしで即座に開始されます。エージェントが実行中（Running）、初期化中（Initializing）、権限待ち（Waiting for permission）、または終了処理中（Finalizing）の場合は、進行中のターンが中断されるため、Lody は確認を求めます。

ACP プロセスが終了し、デバイス監視によってそのセッションが常駐でなくなったことが確認されるまで、停止アイコンにはスピナーが表示されます。終了に失敗した場合、Lody はエラーを報告し、セッションを再度操作可能な状態のまま残します。

ACP プロセスを終了すると、以下のようになります。

- 現在のエージェントターンと追跡対象の子プロセスが停止します
- その常駐プロセスツリーが保持していた CPU とメモリが解放されます
- 会話履歴、セッションメタデータ、ブランチ、Worktree、およびプロジェクトファイルは保持されます
- セッションのアーカイブや削除は行われず、ディスク容量も回収されません

中断されたコマンドやファイル書き込みは自動的にロールバックされません。エージェントが変更を加えている最中に終了させた場合は、セッションのファイルと差分（diff）を確認してください。

## 後から会話を続ける

終了したセッションにはいつでも戻って新しいメッセージを送信できます。Lody は ACP プロセスを再度起動し、永続化されたセッションコンテキストから会話を再開します。エージェントランタイムの起動と再接続の間、再開後の最初のターンには通常より時間がかかる場合がありますが、会話とファイルはその間もそのまま利用できます。

ACP プロセスを終了すると、プロセスローカルの未保存状態は失われます。永続的なコンテキストは、保存された会話、エージェントの再開（resume）サポート、およびセッションワークスペース内のファイルから引き継がれます。作業の合間に CPU とメモリを解放したい場合はプロセス終了を使用し、セッションの表示状態を変更したい場合やディスク容量を回収したい場合にのみアーカイブまたは削除を使用してください。アーカイブ、復元、削除の動作については、[セッション](/ja/docs/session)を参照してください。

## ライブ・オンデマンドのレポート機能

リソース監視は意図的に一時的な（エフェメラルな）仕組みになっています。

- 誰かがデバイスページを閲覧している間、オンラインのデバイスはリソースのスナップショットを報告・更新します
- ページが表示されている間は自動的に更新されます
- スナップショットは期限切れになると破棄され、過去のメトリクス履歴（タイムライン）としては保存されません
- 誰も閲覧していない場合、Lody は継続的なリソースサンプリングの要求を停止します

デバイスがワークスペースと共有されている場合、そのデバイスにアクセスできるワークスペースメンバーは現在のリソース情報を閲覧できます。共有デバイス上の ACP プロセスを終了すると、そのセッションは全員に対して停止するため、他のメンバーのアクティブなターンを停止する前にセッションのステータスを確認してください。このモニターは、プロセスのコマンドラインインスペクターや OS のプロファイリングツールの代替となるものではありません。

デバイスがオフラインの場合、Lody は新しいサンプルを要求したり ACP プロセスを終了したりできません。CLI をオンラインにし、**Settings -> Devices** を開き直してから、最初のサンプルが表示されるまでお待ちください。
