# 共有リンク vs ライブハンドオフ

「セッションを共有する」という言葉には、混同しやすい 2 つの意味があります：

- **共有リンク**（あるいはスクリーンショット、Markdown エクスポート、アーカイブ）は**記録**です。他の人は何が起きたかを読むことができ、ツールによってはそのコンテキストから*新しい*エージェント実行を開始することもできます。
- **ライブハンドオフ**は、チームメイトを**同じ**コーディングエージェントセッションに招待し、そのまま会話を続けたり、差分をレビューしたり、同じワークツリーで作業を継続したりできるようにするものです。

記録の共有は、ライブの会話、リアルタイムの差分、あるいは元の作業ディレクトリへの招待ではありません。

手順とアクセスルールについては[コーディングエージェントのセッションを共有する](/ja/docs/session-handoff)、チームワークスペースについては[チーム機能](/ja/docs/team)をご覧ください。

<Callout title="定義">
スクリーンショット、トランスクリプト、共有リンク、セッションアーカイブはライブハンドオフではありません。閲覧者が実行中のセッションに参加することはなく、元のワークツリーを引き継ぐこともありません。ハンドオフには、ワークスペースのメンバーシップに加えて、セッション引き継ぎページに記載されたマシン／プロジェクトの共有ルールを満たす必要があります。誰でも開ける公開 URL ではありません。
</Callout>

## 2 つの異なる役割

| 手段 | 受け取った側ができること | 同じライブセッションか |
| --- | --- | --- |
| スクリーンショット | チャットの画像を見る | いいえ |
| Markdown / トランスクリプトのエクスポート | 静的テキストを新しいチャットに貼り付ける | いいえ — 最初からやり直しになります |
| ChatGPT 形式の共有リンク | 会話のスナップショットを読む | いいえ |
| 共有リンク / アーカイブツール（例：[Lore](https://lore.link/share) や [SpecStory](https://docs.specstory.com/cloud/session-sharing)） | レンダリングされたスレッドや保存済み履歴を閲覧する、またはそのコンテキストを**新しい**エージェント実行へフォークする | いいえ — 閲覧者が実行中のセッションや元のワークツリーに参加することはありません |
| **ライブハンドオフ** | 既存の[セッション](/ja/docs/session)を開き、会話を続け、ライブの[差分](/ja/docs/diff-viewer)をレビューし、同じ[ワークツリー](/ja/docs/worktrees)で作業を続ける | **はい** |

記録だけが必要な場合は、Lody でも[会話を Markdown としてコピー](/ja/docs/copy-md)できます。また、セッションを共有せずにセッション URL だけをコピーしても、チームへのアクセス権は付与されません（そのリンクは所有者にのみ引き続き有効です）。

このページでは特定の共有リンク製品のレビューは行いません。Lore と SpecStory は、引き継ぎページですでに言及されている「記録 / アーカイブ」カテゴリの例としてのみ挙げています。

## ライブハンドオフの実態

Lody では、セッションを開けるチームメイトは同じコンテキストから作業を続行できます：

- エージェントがすでに行っているライブの会話
- エージェントが生成したファイルの差分
- セッションのワークツリーとブランチ
- 同じ [Agent Config](/ja/docs/agents)（これにより次のプロンプトをそのまま送信できます）

チームメイトが開くのはフォークでも真新しいチャットでもなく、**その**セッションそのものです。フォークは履歴を**新しい**セッションにコピーする機能であり、会話のプライベートな分岐を作りたい場合に使用します。詳しくは[セッションをフォークする](/ja/docs/session#fork-a-session)をご覧ください。

ハンドオフはチームワークスペース向けの操作です。相手はあらかじめワークスペースのメンバーである必要があり、マシン（および該当する場合はローカルプロジェクト）が共有されている場合にのみ、セッションがチームから閲覧できるようになります。手順とエッジケースについては、[コーディングエージェントのセッションを共有する](/ja/docs/session-handoff)をご覧ください。

## 使い分けの目安

| 目的 | 適した方法 |
| --- | --- |
| 何が起きたかを*読む*だけでよい場合 | スクリーンショット、トランスクリプト、共有リンク、またはアーカイブ |
| ワークスペース外に記録を残したい場合 | スクリーンショット、トランスクリプト、共有リンク、またはアーカイブ |
| エクスポートしたコンテキストから*新しい*エージェント実行を始めたい場合 | スクリーンショット、トランスクリプト、共有リンク、またはアーカイブ |
| チームメイトに**同じ**コーディングエージェントセッションを引き継いでほしい場合 | **ライブハンドオフ** |
| （プロンプトからの再構成ではなく）現在の差分と同じワークツリーが相手に必要な場合 | **ライブハンドオフ** |
| 相手がすでに[ワークスペース](/ja/docs/team)のメンバーである（または招待できる）場合 | **ライブハンドオフ** |

異なるモデルや独立したワークツリーを使ってチームで複数の分離されたセッションを実行する方法については、[並列コーディングエージェント](/ja/docs/parallel-agents)をご覧ください。これは新しい作業を追加で開始するものであり、1 つのセッションを引き継ぐものではありません。

## 権限

ハンドオフは製品ガイドと同じルールに従います。このページで独自の公開共有リンク権限モデルが追加されるわけではありません。

| 制御項目 | 効果 |
| --- | --- |
| ワークスペースメンバーシップ | チームセッションを開くための前提条件 |
| メンバーロール | オーナーと管理者が、誰を招待・編集・削除できるかを管理します — 詳細は[メンバー権限の変更](/ja/docs/team#change-member-permissions)をご覧ください |
| マシンの共有 | 共有されていないマシン上のセッションは、他のメンバーのサイドバーに表示されません。共有できるのはデバイス所有者のみです。 |
| ローカルプロジェクトの共有 | ローカルプロジェクトの場合、チームメイトにはマシンの共有権限に加えてプロジェクトの共有権限も必要です |
| セッション URL | 所有者は常に有効です。チームメイトはセッションがチームに公開された後にのみ開けます。URL のコピーは **Share with team…** と同じではありません |

ワークスペースに参加しても、ご自身のノート PC が公開されることは**ありません**。マシンは共有するまでプライベートのまま維持されます。セッションを共有すると、そのマシンやローカルプロジェクトがワークスペース内の全員に共有される場合があり、同じデバイス上の他の会話も閲覧可能になることがあります。詳しくは[チームでのマシン公開設定](/ja/docs/team#team-machine-visibility)をご覧ください。

## よくある質問

### 共有リンクは、コーディングエージェントのセッションを引き継ぐことと同じですか？

いいえ。共有リンク、スクリーンショット、トランスクリプト、アーカイブはいずれも**閲覧用の記録**です。他の人はそれを読むことができ、一部のワークフローではそのコンテキストから*新しい*エージェント実行を開始できます。しかし、元のライブセッションに参加するわけではなく、元のワークツリーを取得することもできません。ライブハンドオフでは既存のワークスペースセッションが開かれ、チームメイトがそのまま作業を続行できます。

### チームメイトは共有リンクから私の Claude Code セッションを続行できますか？

トランスクリプト、ChatGPT 形式のスナップショット、アーカイブビューアーからは続行できません。そのセッションが Lody ワークスペース内で実行されている場合は、相手をワークスペースに招待してセッション（および必要なマシンやローカルプロジェクト）を共有し、**その**セッションを開いてもらってください。詳細は[コーディングエージェントのセッションを共有する](/ja/docs/session-handoff)をご覧ください。

### トランスクリプトの共有とライブコラボレーションの違いは何ですか？

トランスクリプトの共有は「記録を送ること」です。ライブコラボレーションとは、チームメイトが同じセッション（同じチャット、同じ差分、同じワークツリー）に参加している状態を指します。Markdown のエクスポートや URL のコピーでは、そのアクセス権は付与されません。

### トランスクリプトだけを送りたい場合はどうすればよいですか？

メッセージをコピーするか、セッションメニューから **Copy as Markdown** を選択してください。これによってライブセッションへのアクセス権が付与されることはありません。詳しくは[会話をコピーする](/ja/docs/copy-md)をご覧ください。

### 送ったセッション URL をチームメイトが開けないのはなぜですか？

セッション URL をコピーしただけではセッションは共有されません。相手がワークスペースのメンバーであること、マシン（および該当する場合はローカルプロジェクト）が共有されていることが必要であり、相手側では **My Tasks** ではなく **All Tasks** を表示している必要があります。共有されていないマシンの会話が他のメンバーのサイドバーに同期されることはありません。
