# エージェントセッション制御

Lody のエージェントは、組み込みの Lody MCP ツールを使って複数の会話をまたいで作業できます。これにより、1 つのエージェントにタスクを焦点を絞った複数の会話へ分割させ、それぞれの進捗を確認し、追加の指示を送り、完了した結果を元の会話に持ち帰らせることができます。

分離されたワークツリーや複数モデルの併用、チームでの可視性など、ご自身で複数のセッションを開始する方法については、[並列コーディングエージェント](/ja/docs/parallel-agents)をご覧ください。このページでは制御側の仕組み、つまり 1 つのエージェントが他のエージェントを調整する方法を説明します。

プライマリエージェントと Kimi、Codex、Grok を組み合わせた手順（会話のメンションや複数マシンをまたぐ作業を含む）については、[エージェント連携ワークフロー](/ja/docs/agent-collaboration/)をご覧ください。

  - ご自身で複数のタスクを立ち上げる → [並列コーディングエージェント](/ja/docs/parallel-agents)
  - 1 つのエージェントに他の会話を作成・制御させる → このページ

## 会話の中で使う

通常のプロンプトで、期待する結果と作業の分担を記述します。たとえば次のように指示します。

```text
このプロジェクトに対して 2 つのレビュー会話を作成してください。1 つは正確性、もう 1 つはテストカバレッジを確認するものです。
両方が完了したら、見つかった課題をここに要約してください。
```

エージェントは、会話の新規作成や再利用、ステータスと一定範囲の履歴の読み取り、追加指示の送信、そして必要に応じた実行中ターンのキャンセルを行えます。依頼した作業が終了状態（terminal state）に達すると、結果が依頼元の会話に返されます。

新しいセッションを作成する際、エージェントは対象マシンで利用可能な互換性のあるモデルや推論設定を選択することもできます。これらの設定が重要な場合は、次のようにプロンプトに含めてください。

```text
推論設定を high にした Codex でレビューセッションを作成し、見つかった課題をここに要約してください。
```

## PR、Issue、および複数リポジトリにまたがる修正を連携する

### Claude Code をコーディネーターとして使う

Claude Code に一連の PR や Issue を確認させ、依存関係を特定したうえで、Kimi、Codex、Grok などの他のエージェントに焦点を絞った作業を割り当てることができます。各エージェントはそれぞれ独立した会話の中で作業し、コーディネーターがフォローアップや結果の収集を行います。リポジトリへのアクセスには、各エージェントが利用できるツールと認証情報が使用されます。

```text
これらの PR と Issue を確認し、関連する作業をグループ化して依存関係を特定してください。
独立して進められる修正は Kimi に、レビューは Codex にそれぞれ別の会話で委任してください。
各エージェントの調査結果を収集し、どの変更がレビュー可能な状態になっているかを報告してください。
```

### 複数リポジトリにまたがるバグを修正する

バグがクライアント、SDK、サーバーにまたがっている場合は、影響を受けるリポジトリごとに会話を作成します。各エージェントは並行して調査や独立した変更の実装を進めつつ、共通のインターフェース仕様（コントラクト）に関する調査結果をやり取りし、依存関係のある変更を調整できます。

```text
クライアント、SDK、サーバーの各リポジトリにまたがるこのバグを調査してください。
リポジトリごとに焦点を絞ったエージェント会話を作成し、依存関係のある修正を実装する前に、
調査結果を共有してインターフェースの変更内容について合意させてください。
パッチと検証結果をここに集約してください。
```

### エージェント間でレビューと修正のループを回す

エージェントは、アクセス可能な他の Lody 会話へメッセージを送信したり、作業を委任したりできます。1 つのエージェントから別のエージェントへ直接メッセージを送るよう指示することも可能です。たとえば、レビュー担当のエージェントに特定のコミットを確認させ、指摘事項を実装担当のエージェントに送り、修正後の新しいコミットを再度レビューさせることができます。

```text
レビュー担当のエージェントに、ファイルを編集せずに実装担当エージェントの現在のコミットを確認させてください。
具体的な対応可能な指摘事項を実装担当エージェントに送り、修正を依頼してください。
更新されたコミットをレビュー担当に再確認させてください。2 ラウンド終了後、または指摘事項がなくなった時点で停止し、
私向けに結果を要約してください。
```

これらの例はあらかじめ用意された固定パイプラインではなく、プロンプトで依頼できるワークフローの一例です。対象リポジトリ、作業範囲、完了条件、レビュー回数の上限は明示的に指定してください。また、並行して進めた変更であっても、マージする前に統合チェックを実施する必要があります。

## 動作の特徴

- 各会話はそれぞれ独立したタスクとして扱われ、独自の会話履歴と実行中ターンを保持します。
- 対象マシンがオンラインであれば、作業を並行して実行できます。
- Lody は依頼元の会話との関連性を保持するため、委任した作業の完了後にエージェントが元の処理を引き継いで続行できます。
- 一時的な会話は、作業完了後にセッション一覧からアーカイブできます。

## 制限事項

セッション制御には意図的な境界が設けられています。エージェントが確認できるのは Lody が管理する会話データのみであり、無制限のバックグラウンドスケジューラーとして使用することはできません。委任されたタスクが指定の期限後に完了する場合もありますが、依頼元がすでにタイムアウト結果を受け取った後でも、その出力自体は対象の会話内に保持されます。

他のエージェントを調整するのではなく、進行中のセッションをチームメイトに引き継ぐ方法については、[コーディングエージェントセッションの共有](/ja/docs/session-handoff)をご覧ください。
