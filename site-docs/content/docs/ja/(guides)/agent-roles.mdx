# エージェントロール

**エージェントロール（Agent Role）**は、エージェントを*どのように*使うかをひとまとめにしたものです。実行先のマシンと[エージェント設定](/ja/docs/quickstart)、モデルと推論レベル、権限モード、そして任意のデフォルトの指示が含まれます。絵文字と名前を付けるだけで、これらの選択すべてをワンクリックで呼び出せるようになります。

ロールは新しいプロバイダーでも、実行中のエージェントでもありません。API キーや MCP の選択状態は保存されず、それらはエージェント設定側に保持されます。

## ロールを作成する

入り口は2つありますが、開くエディターは同じです。

- **Settings** → **Agent Roles** → `+` ボタン。
- コンポーザーの実行設定にある **Role** 行 → **New role with settings**。こちらから開くと、これから実行しようとしている設定があらかじめ入力された状態になるため、調整したばかりの構成をそのまま保存するのに最も手早い方法です。

マシンとエージェント設定を選び、そのエージェントが公開しているモデル、推論レベル、権限を選択して、必要に応じてデフォルトの指示を入力します。新しく作成したロールは、**Share with workspace** をオンにするまで自分だけのプライベートなロールになります。

## エージェントにロールの作成や更新を依頼する

進行中の Lody の会話で、エージェントに新しいロールの作成や、自分が所有するロールの名前・説明・デフォルトの指示の更新を依頼できます。エージェントは `lody_agent_role` の `create` または `update` アクションを使って確認カードを表示します。
提案されたフィールドを確認し、適用する場合は **Save** をクリックし、不要な場合はカードを閉じます。

この方法で作成された新しいロールはプライベートとなり、指定されたマシンとエージェント設定に紐付けられ、そのエージェントのデフォルトの実行設定が使用されます。更新時には、変更を依頼しなかったフィールドはそのまま保持されます。モデル、権限、共有設定などの項目は、引き続き Settings から編集できます。
また、[CLI](/ja/docs/cli#agent-role-の作成と更新) を使って、パラメーターを直接指定したり JSON ファイルを渡したりして同じ提案を送信することもできます。

## 会話を開始するときにロールを使う

コンポーザーの実行設定では、**Agent** の上に **Role** 行があります。ロールを選ぶだけで、その下にあるすべての行の設定をまとめて決められるためです。

- デスクトップでは、コンポーザー下部のフッターにある実行設定ボタンを開き、**Role** にカーソルを合わせます。一覧の横にパネルが表示され、ハイライトされたロールが実際に何を実行するかが明確に示されます。
- モバイルでは、実行設定シートを開きます。最初の行が **Role** です。

ロールを1つ選ぶと、その下の各行がロールの内容に合わせて切り替わります。そしてコンポーザーのフッターには、ロールの絵文字と名前に加えて、その設定値が小さめの文字で横に並びます。実際にチャットを開始したことがあるロールは、**Recently used** の下にも表示されます。

**None** を選ぶとロール名だけが解除され、設定値は消えません。ロールによってセットされた値は現在の自分の設定になっているため、ロールの選択を外してもそれらの値は維持されます。

フッターにロール名が表示されるのは、現在の設定がそのロールの内容と一致している間だけです。手動でモデルを変更するとロール名は消えます。フッターは、実際に実行される内容と異なるロール名を表示することはありません。

別の会話内にある空の子タブでも、この新規会話と同じルールが適用されます。マシンと作業ディレクトリは親セッションに紐付いたままですが、Role 一覧にはそのマシン上のすべてのエージェントタイプを横断してすべてのロールが表示されます。その中から1つを選ぶと、下書きがそのロールのエージェント設定に切り替わり、最初のメッセージを送信した時点で、その実行設定、指示、および参照元の来歴情報が固定されます。

## 会話の途中でロールを使う

会話がいったん作成されると、すでに特定のマシン上でエージェントが動作しているため、ロールを使って別のマシンや別のエージェントへ移動させることはできません。そのため、会話内の **Role** 行には次のような挙動があります。

- **同じタイプ**のエージェントに紐付いたロール（そのエージェントが解釈できるモデル、推論レベル、権限の値を持つロール）だけが表示されます。
- 実行設定のみが適用されます。すでに進行中の会話に、ロールのデフォルトの指示が追加されることはありません。

適用後も、各行は引き続き個別に編集できます。

## ロールをメンションする

`@` を入力して **Agent Roles** の下にあるロールを選ぶと、そのロールを使って*新しい*会話を開始するよう現在のエージェントに依頼できます。

```text
@code-reviewer check the diff on this branch and report anything that breaks
```

新しい会話は、そのロールのマシンとエージェント設定上で起動し、モデル、推論レベル、権限、デフォルトの指示があらかじめ適用された状態になります。メッセージを送信した瞬間のロールの設定内容がそのリクエストに固定されるため、後からロールを編集したり削除したりしても、すでに受け付けられた作業が変わることはありません。

メンションできるロールは、現在いる場所によって異なります。ローカルプロジェクトや通常のチャットでは同じマシン上のロールのみが候補になりますが、GitHub プロジェクトでは新しい会話がリポジトリ自体をクローンするため、アクセス権のある他のマシン上のロールも指定できます。その他のメンションの種類については、[メンション](/ja/docs/mention)を参照してください。

## 共有

ロールは共有するまでプライベートです。**Share with workspace** をオンにすると、ワークスペースのすべてのメンバーがそのロールを閲覧、メンション、実行できるようになります。ただし実行自体は引き続きロールが紐付いたマシン上で行われるため、メンバーにはそのマシンへのアクセス権限が必要です。

プライベートとは、他のメンバーが Lody を通じてそのロールを見つけたり、メンションしたり、実行したりできないことを意味します。暗号化ではないため、ロールにはもともとシークレット類を一切保存しない仕組みになっています。

## ロールを実行できない場合

ロールは1つのマシンと1つのエージェント設定に厳密に紐付けられており、別のものに勝手に置き換わることはありません。マシンがオフラインになったり、エージェント設定が削除されたりした場合、ロールは正確な理由が明記された状態で一覧（Settings およびピッカー）に残り、問題を修正するまで選択できなくなります。

ロールを編集しても、影響するのはそれ以降の利用のみです。そのロールからすでに開始された会話は、そのままの設定で実行され続けます。
