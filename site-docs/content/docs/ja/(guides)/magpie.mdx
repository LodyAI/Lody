# Magpie を接続する

Magpie がモデルプロバイダーへ接続し、Lody がエージェント設定を作成します。上流の API キーは Magpie 側に保持したままでよく、Lody にコピーする必要はありません。

## 始める前に

- Magpie と Lody デーモンを**同じサーバー**上で実行し、Magpie で少なくとも 1 つのモデルを有効にしておきます。
- Lody にサインインし、サーバーをワークスペースに接続します。手順は [CLI ログイン](/ja/docs/cli#core-commands)を参照してください。
- `import-magpie` に対応した Lody CLI を使用します。これらのコマンドは OSS のローカル専用モードではなく、クラウドワークスペースを使用します。

サーバー上でコマンドのサポート状況を確認し、デーモンを起動して、ワークスペースを特定します。

```bash
lody agent-config import-magpie --help
lody daemon start
lody workspace list
```

デーモンがすでに実行中の場合は起動をスキップしてください。以降のコマンドでは、`my-team` をご自身のワークスペース ID、名前、またはスラッグ（slug）に置き換えてください。

## すべてのプロバイダーをインポートする

```bash
lody agent-config import-magpie --workspace my-team --json
```

デフォルトでは `http://127.0.0.1:3425` に接続し、次の 7 つのプロバイダーをインポートします。

| `--targets` の値 | 設定名 |
| --- | --- |
| `claude` | Claude-magpie |
| `codex` | Codex-magpie |
| `pi` | Pi-magpie |
| `dsh` | DSH-magpie |
| `kimi` | Kimi Code-magpie |
| `grok` | Grok-magpie |
| `bub` | Bub-magpie |

このコマンドは**コマンドを実行しているマシン**にのみインポートを行います。`--machine` オプションはありません。`127.0.0.1` はお使いのコンピューターではなく、そのサーバー自身を指します。
Bub を使用するには、事前に `bub acp` コマンドと ACP プラグインがインストールされている必要があります。

### エージェントを選択する

ターゲットはカンマ区切りで指定します。たとえば、Pi と Codex のみをインポートする場合は次のように実行します。

```bash
lody agent-config import-magpie --workspace my-team --targets pi,codex --json
```

### 別のポートまたはインポートリンクを使用する

Magpie で別のポートを使用している場合は、`/v1` を含めないゲートウェイのルート URL を指定します。

```bash
lody agent-config import-magpie --workspace my-team --gateway http://127.0.0.1:4000 --json
```

Magpie のインポートリンクがある場合は、リンク全体を指定します。

```bash
lody agent-config import-magpie --workspace my-team --link 'lody://provider/import?v=1&data=…' --json
```

`--link` と `--gateway` はどちらか一方のみを指定し、併用しないでください。リンクを指定した場合、デフォルトではそのリンクが提供するすべてのターゲットが対象となり、`--targets` ではその中からのみ選択できます。
ゲートウェイには、`127.0.0.1`、`localhost`、または `[::1]` のローカル HTTP ループバックアドレスを使用する必要があります。

## 結果を確認する

JSON の `providers` 配列には、各ターゲットの `agentConfigId` と `status` が含まれます。

| ステータス | 意味 |
| --- | --- |
| `queued` | セットアップが保存されました。デーモンがランタイムのインストールまたは検証を行います |
| `preparing-runtime` / `verifying` | 既存のセットアップが準備中または検証中です |
| `awaiting-auth` | 既存のセットアップに認証が必要です |
| `created` | 設定は保存されましたが、モデルリクエストはまだ検証されていません |
| `existing` | このゲートウェイとエージェント種別の設定はすでに存在するため、そのまま保持されます |

セットアップの進行状況は Lody の **Providers** ページで確認できます。準備が完了したら、セッションを作成する際にそのサーバー上の該当プロバイダーを選択してください。
インポートが成功しても、アップストリームの推論が動作することの証明にはなりません。実際にメッセージを送信して動作確認を行ってください。

`synced: false` は、設定がローカルには保存されたものの、ワークスペースへの同期が確認できていないことを意味します。接続を復旧したうえで、インポートを再実行してください。

インポートを繰り返し実行すると、既存の設定はそのまま保持され、失敗したセットアップは元の設定を使用して再試行されます。
Pi が非対応と表示される場合は、サーバー上の Lody を更新してデーモンを再起動するか、`--targets` で `pi` を除外してください。

## モデルと設定を更新する

モデルの管理は Magpie 側で行います。Lody は以降の起動時に最新のカタログを読み込みます。すでに実行中のセッションは自動的には更新されません。
生成されたネイティブ設定は Lody が管理します。手動で行った編集は、次回の起動時に上書きされる場合があります。

デスクトップ環境で既存の Magpie インポートリンクを開くと、確認ダイアログが表示され、そのデスクトップマシンにインポートされます。サーバーへインポートするには、サーバー上で上記のコマンドを実行してください。
