# チームとコーディングエージェントのセッションを共有する

Lody における**コーディングエージェントのセッション引き継ぎ**（ハンドオフ）とは、すでに開始した**同じ**セッションをチームメイトが開き、そのまま作業を続けられる仕組みのことです。スクリーンショットや Markdown のエクスポート、あるいは経過を*読む*ことしかできない ChatGPT のような共有リンクとは異なり、ライブの会話、エージェントが生成したファイルの差分、そしてセッションの[ワークツリー](/ja/docs/worktrees)をそのまま引き継げます。

これが、一般的な「Claude Code セッションを共有する」ワークフローとの違いです。従来の方法では会話記録を公開するだけにとどまりますが、Lody では既存のセッションに直接招待するため、相手もチャットを続けながらエージェントの方向性を指示できます。

[セッション](/ja/docs/session)、[チーム機能](/ja/docs/team)、[Agent Config](/ja/docs/quickstart)、および定義の違いをまとめた[共有リンク vs ライブハンドオフ](/ja/docs/compare/share-link-vs-live-handoff)もあわせてご覧ください。

<Callout title="「続行」が意味すること">
  セッションを開けるワークスペースメンバーは、同じコンテキストのまま会話を続けることができます。
  Lody はセッションを読み取り専用のリプレイにはしません。なお、共有は引き続きマシンとプロジェクトの
  公開範囲に従います。詳しくは下記の[権限](#権限)をご覧ください。
</Callout>

## 会話記録のリンクがハンドオフではない理由

エージェントの作業を共有する方法はすでにいくつかありますが、そのほとんどは「これを見て」の段階で止まってしまいます。ハンドオフとは「この続きを引き継いで」を可能にするものです。

| 方法 | 相手が受け取るもの | 同じライブセッションか | 差分とワークツリー |
| --- | --- | --- | --- |
| スクリーンショット | チャットの画像 | いいえ | いいえ |
| Markdown / 会話エクスポート | 別の場所に貼り付けられる静的テキスト | いいえ — 新しいチャットを開始することになります | いいえ |
| ChatGPT 形式の共有リンク | 会話の読み取り専用スナップショット | いいえ | いいえ |
| **Lody** | 既存のワークスペース[セッション](/ja/docs/session) | **はい** — 開いてそのまま続行できます | **はい** — ライブの[差分](/ja/docs/diff-viewer)とセッションのワークツリー |

共有リンクとライブハンドオフの定義については、[共有リンク vs ライブハンドオフ](/ja/docs/compare/share-link-vs-live-handoff)をご覧ください。記録だけが必要な場合は、Lody でも会話を Markdown としてエクスポートできますが、それは別の機能です（[会話をコピーする](/ja/docs/copy-md)）。また、セッションを共有せずにセッション URL だけをコピーしても、チームへのアクセス権は付与されません（そのリンクは所有者に対してのみ引き続き有効です）。

## セッションを引き継ぐ手順

### 1. チームメイトをワークスペースに招待する

ハンドオフはチームワークスペース向けの操作です。相手があらかじめメンバーになっている必要があります。

1. **Settings** -> **Workspace** -> **General** を開きます。
2. **Members** セクションで **Invite Member** をクリックします。
3. 相手のメールアドレスを入力し、ロールを選択します。
4. 相手はメールから招待を承認できるほか、招待リンクをコピーして直接送ることもできます。

詳しくは[メンバーを招待する](/ja/docs/team#メンバーを招待する)をご覧ください。

### 2. セッションをチームに公開する

新しいマシンはデフォルトで**プライベート**に設定されています。セッションを実行しているリソースが共有されている場合にのみ、そのセッションがチームから閲覧できるようになります。

セッション画面から操作する場合：

1. セッションの `...` メニュー、またはデスクトップ版セッションヘッダーにある **Private** コントロールを開きます。
2. **Share with team…** を選択します（不足している権限がマシンやローカルプロジェクトの共有である場合は、ラベルが **Share device with team…** または **Share project with team…** と表示されることがあります）。
3. 内容を確認して確定します。Lody は必要なマシンと（ローカルプロジェクトの場合は）プロジェクトを共有し、リンクをコピーします。

共有できるのは**デバイス所有者**のみです。デバイスがチームアクセス用に登録されていない場合は、先に登録を済ませてください。特定のセッションを開かずに、**Settings** -> **Machines** -> **Share machine** からマシンを共有することもできます。詳しくは[チームでのマシン公開設定](/ja/docs/team#チームでのマシン公開設定)をご覧ください。

<Callout type="warn" title="共有すると複数の会話が公開される場合があります">
  セッションを共有すると、そのマシンやローカルプロジェクトがワークスペース内の全員に共有されることがあります。
  そのデバイス上の他の会話も閲覧可能になる場合があります。確定前の確認ダイアログに共有範囲が表示されますので、
  必ずご確認ください。
</Callout>

### 3. チームメイトにセッションを案内する

セッションがチームに公開されたら：

- コピーしたセッションリンクを送信するか、
- ホームページのセッション一覧を開くよう伝えてください。自分の会話しか表示されていない場合は、サイドバーのフィルターを **My Tasks** から **All Tasks**（モバイルでは **Team Tasks**）に切り替えます。各セッションを開始したユーザーはアバターで確認できます。一覧のデフォルトは **All Tasks** です。

相手が開くのは**その**セッションそのものです。フォークでも、コンポーザーから新しく作成するスレッドでもありません。

### 4. 作業を続行する

セッションに入ると、相手は次の操作を行えます：

- エージェントがすでに行っている会話の全文を読む
- 現在の[差分](/ja/docs/diff-viewer)を確認する
- 同じ[ワークツリー](/ja/docs/worktrees)とブランチで作業を続ける
- 次のプロンプトを送信し、同じ [agent config](/ja/docs/quickstart) に対して指示を出す

セッションのフォークは別の機能であり、履歴を**新しい**セッションにコピーするものです。**Current workspace** は同じファイル上に留まり、**New worktree**（選択可能な場合）はコミット済みの `HEAD` から環境を分離します。フォークは自分専用のプライベートな会話ブランチを作りたいときに使い、元のセッションにチームメイトを参加させたいときには使用しないでください。詳しくは[セッションをフォークする](/ja/docs/session#セッションをフォークする)をご覧ください。

チームで複数の独立したセッションを実行する方法については、[並列コーディングエージェント](/ja/docs/parallel-agents)をご覧ください。
1 つのエージェントから複数の会話を統括する方法については、[エージェントセッション制御](/ja/docs/session-orchestration)をご覧ください。

## 権限

| 制御項目 | 対象者 | 効果 |
| --- | --- | --- |
| ワークスペースメンバーシップ | 招待したすべてのユーザー | チームセッションを開くための前提条件 |
| メンバーロール | オーナーと管理者がメンバーを管理 | 招待、編集、削除が可能なユーザーを制御 — 詳細は[メンバー権限の変更](/ja/docs/team#メンバーの権限を変更する)を参照 |
| マシンの共有 | マシン所有者のみ | 共有されていないマシン上のセッションは、他のメンバーのサイドバーに表示されません |
| ローカルプロジェクトの共有 | マシン所有者（セッションがローカルプロジェクトを使用している場合） | チームメイトにはマシン権限とあわせてプロジェクト権限も必要です |
| セッション URL | 所有者は常に有効、チームメイトはセッションがチームに公開された後のみ有効 | URL のコピーは **Share with team…** とは異なります |

ワークスペースに参加しても、ご自身のノート PC が公開されることは**ありません**。マシンは共有するまでプライベートのまま維持されます。Agent Config は別途共有できるため、チームメイトが同じ CLI セットアップを実行できるようにすることも可能です。詳しくは [Agent Config](/ja/docs/quickstart) と[チーム機能](/ja/docs/team)をご覧ください。

## よくある質問

### Claude Code のセッションを共有して、チームメイトに作業を引き継いでもらえますか？

はい、セッションが Lody ワークスペース内で実行されていれば可能です。相手を招待してセッション（および必要なマシンやローカルプロジェクト）を共有し、そのセッションを開いてチャットを続けてもらってください。これは読み取り専用の Claude Code 会話ログエクスポートや公開スナップショットリンクではありません。

### ChatGPT の共有リンクと同じものですか？

いいえ。ChatGPT の共有リンクは**閲覧用の記録**、つまり読み取り専用のスナップショットです。一方、Lody はチームワークスペース内の**既存のコーディングエージェントセッション**そのもの（同じ会話、差分、ワークツリー）を引き継ぎます。詳しくは[共有リンク vs ライブハンドオフ](/ja/docs/compare/share-link-vs-live-handoff)をご覧ください。

### チームメイトにセッションが表示されない場合はどうすればよいですか？

次の 3 点を確認してください。相手がワークスペースの招待を承認しているか、マシン（および該当する場合はローカルプロジェクト）が共有されているか、そして相手が **My Tasks** ではなく **All Tasks** を表示しているかです。共有されていないマシンの会話が他のメンバーのサイドバーに同期されることはありません。

### 1 つのセッションを共有すると、マシン全体が共有されてしまいますか？

その可能性があります。マシンがまだ共有されていない場合、**Share with team…** を実行すると、チームメイトがそのデバイス上の会話を開いて続行できるようにマシンが共有されます。その結果、同じマシン上の他のセッションも表示されるようになる場合があります。後から **Settings** -> **Machines** で **Share machine** をオフに戻すこともできます。

### 代わりに会話記録だけを送ることはできますか？

はい。記録だけが必要な場合は、メッセージをコピーするか、セッションメニューから **Copy as Markdown** を選択してください。ただし、その方法では相手がライブセッションを続行することはできません。詳しくは[会話をコピーする](/ja/docs/copy-md)をご覧ください。
