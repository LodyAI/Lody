# 推奨ワークフロー

Lody では現在、[GitHub 連携](/ja/docs/github)と [Worktree](/ja/docs/worktrees) を中核機能として位置づけているため、これらをデフォルトのワークフローとして使用することをおすすめします。

始める前に、[クイックスタート設定](/ja/docs/quickstart)を完了してください。

## タスクを小さく分割する

エージェントにはコンテキストの上限があるため、単一の会話で大きく複雑なタスクを 1 つ進めるよりも、複数の小さなタスクを並列で実行する方が通常はうまく機能します。作業を始める前に、実装や修正を原子的な単位へ分割してください。これにより、Worktree レベルのファイル分離を活用した並列開発が可能になり、待ち時間を短縮できます。

## 並列開発

要件を分割したら、ホームページのコンポーザーで 1 つの会話につき 1 つの機能または修正内容を指示します。このワークフローでは、1 つの会話が 1 つの機能または修正に対応し、通常はそのまま 1 つの PR に対応します。マシンの性能やコンテキスト切り替えの負担が許す範囲で、いくつでも同時に会話を実行できます。分離された Worktree、異なるエージェントの併用、チームでの可視性といった背後にあるプロダクトモデルについては、[並列コーディングエージェント](/ja/docs/parallel-agents)をご覧ください。

Lody が 1 ラウンドの作業を完了すると、[通知](/ja/docs/notification)が送信されます。通知をクリックすると、該当するセッションへ移動します。コードを読むことに慣れている場合は、Lody 内で変更されたファイルを直接レビューできます。そうでない場合は、左サイドバーで該当セッションの下に表示されているブランチ名をコピーし、普段お使いの開発環境でそのブランチに切り替えてエンドツーエンドのテストを行ってください。

結果がおおむね整ったら、会話の上部にある **Create PR** をクリックします。Lody が要件と実装の要約をすべて記載した PR を作成し、会話にリンクします。その後、リンクされた PR ボタンをクリックすれば、GitHub 上の PR ページへ直接移動できます。

## AI レビューループ

Claude Code、Codex、Devin などのツールをリポジトリに連携しておくと、各 PR を詳細にレビューしてもらえます。レビューコメントが届いたら、Lody に次のように依頼できます。
`PR のコメントを取得し、各指摘が妥当かどうかを評価してください。妥当な問題であれば修正して resolved にし、そうでなければ理由を添えて返信してください。`
Lody は PR のコメントを取得して評価し、修正を適用して新しいコミットをプッシュします。これにより、明らかな問題がなくなるまで次の AI レビューラウンドが（自動で、または `@` による手動メンションで）トリガーされます。

## 完了したセッションをアーカイブする

PR がマージされたら、そのセッションの役割は完了です。関連するバグが見つかった場合を除き、同じセッションで無関係な作業を続けることはおすすめしません。完了したセッションをアクティブ一覧から取り除くには、サイドバーの[アーカイブ操作](/ja/docs/session#セッションをアーカイブする)を使用してください。

アーカイブすると、会話履歴とローカルブランチを保持したまま、Lody 管理下の Worktree ディレクトリを回収できます。必要な ignored ファイルは事前に Worktree の外へ退避してください。詳しくは [Worktree の保持と復旧](/ja/docs/worktrees#automatic-cleanup)をご覧ください。

## アーカイブ済みセッションを定期的に削除する

会話が不要になったら、[アーカイブ済みセッションを削除](/ja/docs/session#セッションを削除する)して履歴を完全に削除してください。この操作では保持されているローカルの Git ブランチやそのバックアップコミットは削除されないため、リポジトリのストレージをすべて回収するための手段ではありません。

## GitHub 以外のプロジェクト

このワークフローは GitHub 上でホストされているプロジェクトに最適です。GitHub で管理されていない作業の場合は、対象ディレクトリを[ローカルプロジェクト](/ja/docs/local-project)として追加してください。ローカルプロジェクトでもチャット、ファイル一覧、差分レビュー、モバイルからのアクセス、Lody Preview を利用できますが、GitHub 固有の PR や CI の自動化機能は利用できません。
