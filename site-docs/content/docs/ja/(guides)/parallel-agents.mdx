Lody は**マルチエージェントコーディング**のためのチームワークスペースです。複数のコーディングエージェントセッションを同時に開始でき、それぞれのセッションが独立した会話を持ちます。セッションで[ワークツリー](/ja/docs/worktrees)を使用すると（GitHub では常に使用され、ローカルプロジェクトでも利用できます）、そのセッションに専用の作業ディレクトリが割り当てられるため、複数のエージェントがファイルを並走して編集しても競合しません。

複数の Claude Code セッションを同時に実行することも、Claude Code とあわせて Codex、Kimi、Grok、DeepSeek、またはその他の [ACP](/ja/docs/cli-runtimes) ランタイムを併用することもできます。エージェントにタスクを委任させたり、コンテキストを交換させたり、互いの変更をレビューさせたりする方法については、[マルチエージェント協業ガイド](/ja/docs/agent-collaboration/)をご覧ください。

関連ページ：[Agent Config](/ja/docs/quickstart)、[チーム機能](/ja/docs/team)、[コーディングエージェントセッションの共有](/ja/docs/session-handoff)、[Agent Session Control](/ja/docs/session-orchestration)。共有リンクは記録のスナップショットであり、ライブでの引き継ぎではありません。詳しくは[共有リンク vs ライブハンドオフ](/ja/docs/compare/share-link-vs-live-handoff)をご覧ください。

## 分離されたワークツリー

ワークツリーを使用するセッションを作成すると、Lody は次の処理を行います。

1. ブランチを作成します（デフォルトは `session/<shortSessionId>`）
2. 専用のワークツリーにそのブランチをチェックアウトします
3. 必要に応じてプロジェクトのセットアップスクリプトを実行します
4. ファイルの変更をセッション UI へリアルタイムに配信します

異なるセッションのエージェントは作業ディレクトリを共有しないため、未コミットの編集はそれを加えたタスク内にとどまります。セッションごとにレビュー、破棄、または PR の作成を行えます。

<Callout title="Fork の作成先">
[Fork](/ja/docs/session#セッションをフォークする) は会話履歴を**新しい**セッションに複製します。**Current workspace**（およびサイドチャット）は元のディレクトリにとどまります。**New worktree** が表示される場合、そのフォークは最新のコミット済み `HEAD` から開始する独立したセッションになります。これまでの会話を引き継ぎつつ作業環境を分離したい場合に使用してください。履歴を複製せず、完全に新しい独立したタスクを始めたい場合は、ホームページから新しいセッションを開始してください。
</Callout>

詳細については[ワークツリー](/ja/docs/worktrees)をご覧ください。

## 複数のエージェントを 1 つのワークスペースで

各セッションでは、コンポーザーからそれぞれ独自の [Agent Config](/ja/docs/quickstart)、モデル、および権限スコープを選択できます。次のような環境を実行できます。

- マシン上のサブスクリプションログインを用いた Claude Code または Codex
- Kimi Code、DeepSeek Harness、その他の組み込みセットアップや Claude 互換セットアップ
- [ACP Registry](/ja/docs/cli-runtimes) 内の任意のランタイム、またはカスタムの ACP 起動コマンド

同じ組み合わせを頻繁に起動する場合は、マシン、設定、モデル、権限のセットを [Agent Role](/ja/docs/agent-roles) として保存しておけます。

同時に実行できるセッション数は、ホストマシンの性能と、ユーザーが実質的に追跡できる会話数によって異なります。詳しくは[推奨ワークフロー](/ja/docs/workflow)をご覧ください。

## チームでの可視性

現在何が実行中かをチーム全員で確認できると、並列作業がより進めやすくなります。

- ホームページのサイドバーフィルターは、デフォルトで **All Tasks** になっています。自分のセッションしか表示されない場合は、**My Tasks** から **All Tasks**（モバイルでは **Team Tasks**）に切り替えてください。各セッションを誰が開始したかはアバターで表示されます。
- マシンは**デフォルトでプライベート**のまま維持されます。チームメンバーがそれらの会話を開けるようにするには、マシンを共有するか、セッション上で **Share with team…** を使用してください。
- チームメンバーを既存のセッションの*内部*に招き入れ、同じチャット、差分、ワークツリーを共有するには、[コーディングエージェントセッションの共有](/ja/docs/session-handoff)の手順に従ってください。

メンバーシップ、ロール、マシン共有については、[チーム機能](/ja/docs/team)をご覧ください。

## 1 つの会話から連携する

ほとんどの並列作業では、手動でセッションを開始するだけで十分です。1 つのエージェントに作業を分割させたい場合は、[Agent Session Control](/ja/docs/session-orchestration) を使うよう指示してください。会話の作成や再利用、ステータスの確認、追加指示の送信、結果の取りまとめを行えます。委任された会話は、対象マシンがオンラインである限り並列で実行できます。

## 実践的な分割方法

[推奨ワークフロー](/ja/docs/workflow)より：

1. 作業を小さな機能追加や修正単位に分割します。
2. 項目ごとにホームページから 1 つの会話を開始します（通常は 1 PR 単位）。
3. 各エージェントの作業中に、リアルタイムの[差分](/ja/docs/diff-viewer)をレビューします。
4. GitHub と連携した作業では、変更の準備が整ったらセッションから PR を作成します。
5. 作業が完了したらセッションを[アーカイブ](/ja/docs/session#セッションをアーカイブする)し、ワークツリーが回収されるようにします。

## よくある質問

### これは Claude Code のチーム機能ですか？

いいえ。Claude Code は Lody で実行できる [Agent Config](/ja/docs/quickstart) の 1 つにすぎません。ワークスペース、分離されたワークツリー、およびチームセッション一覧は Lody が提供する機能です。複数の Claude Code セッションを実行することも、Claude Code と Kimi、DeepSeek、Codex、その他の ACP エージェントを組み合わせて使用することもできます。

### 並列実行中のエージェントは互いのファイルを上書きしますか？

各タスクが独自の[ワークツリー](/ja/docs/worktrees)を持っている場合（**New worktree** フォークやホームページから新しく開始したセッションを含む）、互いのファイルを上書きすることはありません。**Current workspace** フォークおよびサイドチャットは元のセッションのディレクトリを共有するため、互いのファイル変更を参照できます。New worktree フォークはコミット済みの `HEAD` から開始され、未コミットの編集は元のセッション側にとどまります。

### チームメンバーは実行中のすべてのエージェントを見ることができますか？

ワークスペースに共有されたマシン（およびローカルプロジェクト）上のセッションであれば閲覧でき、ホームページのフィルターが **My Tasks** に設定されている場合は **All Tasks** に切り替えることで表示できます。共有されていないマシンの会話が他のメンバーのサイドバーに同期されることはありません。詳しくは[チーム機能](/ja/docs/team)をご覧ください。

### 1 つのエージェントから他のエージェントを起動できますか？

はい、[Agent Session Control](/ja/docs/session-orchestration) を通じて可能です。1 つの会話に対して、目的を絞ったセッションの作成、他のエージェントとのメッセージ交換、進捗のフォローアップ、結果の要約を依頼できます。これは Lody の会話データの範囲に限定された仕組みであり、汎用的なバックグラウンドスケジューラーではありません。

### 新しいエージェントを開始するのではなく、ハンドオフすべきなのはどのような場合ですか？

**新しい**独立したタスクを始めたい場合は、別のセッションを開始してください。
既存のセッションをチームメンバーに**引き継いで**作業を続けてほしい場合は、[ハンドオフ](/ja/docs/session-handoff)を使用してください。
