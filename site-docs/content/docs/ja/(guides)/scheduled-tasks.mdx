# スケジュールタスク

**スケジュールタスク**は、指定した日時に、選択した Agent、モデル、権限モード、プロジェクトを使ってプロンプトを送信します。各実行は通常のチャットとして作成されるため、いつでも開いて会話を続けたり、停止したりできます。

主な活用例としては、毎朝前日にマージされたコミットを要約する、平日に毎日依存関係のセキュリティアドバイザリーを確認する、金曜日に週報の下書きを作成する、あるいは必要なときにワンクリックで実行できる手動タスクとして保存しておく、といった使い方が挙げられます。

## 実行場所

スケジュールタスクはクラウド上では実行されません。各タスクは**ご自身のマシンのいずれか 1 台**が所有・実行します。

- そのマシンでは、スケジュール機能に対応したバージョンの [Lody CLI](/ja/docs/cli) が実行されている必要があります（デスクトップアプリをご利用の場合は自動的に起動されます）。
- 時刻は**そのマシンのローカルタイムゾーン**で解釈されます（タイムゾーンの選択機能はありません）。「毎日 9:00」は、そのマシン上の 9:00 を意味します。
- マシンの電源が切れている、スリープ状態である、または CLI が起動していない場合、その時刻には実行されません。復旧後の動作については、[逃した実行](#missed-runs)をご覧ください。

スケジュールタスクの確認や管理は Web、デスクトップ、モバイルのどこからでも行えますが、実際にタスクを実行するのはそのタスクを所有するマシンのみです。

## 会話からメッセージをスケジュール送信する

既存の会話で **+ → Schedule send…** を選択し、対象マシンの時計に合わせて将来の日時を指定したら、コンポーザーのスケジュール送信ボタンを押します。この機能は 1 回限りの送信であり、新規チャットページでは利用できません。

テキスト、画像、ファイル、および参照情報は、添付ファイルの準備が完了した後にまとめて保存されます。情報バーには予約メッセージアイコンが 1 つ表示されます。クリックすると、送信予定時刻と Edit ピルが表示されます。Edit を開くと日時設定コントロールが表示され、30 分後・1 時間後・5 時間後のプリセットも選択できます。Remove time を選ぶと、下書きを失うことなく通常の送信状態に戻ります。保存に失敗した場合も下書きは保持されます。

コンポーザー上部に表示される送信待ちメッセージの概要をクリックすると、スケジュール詳細（Schedule details）が開き、メッセージ内容や送信時刻の編集、またはキャンセルを行えます。キャンセルは所有マシンからの確認応答を待ちます。すでに送信処理が確定していた場合、メッセージは送信済み（sent）として表示されます。「送信済み」とは会話にメッセージが引き渡されたことを意味し、その後の Agent の実行結果とは独立しています。

完全なメッセージ形式に対応した CLI を実行しているご自身のマシンをご利用ください。指定時刻にマシンがスリープ中またはオフラインだった場合、復帰時に 1 回だけキャッチアップ送信が行われます。会話が処理中の場合は、現在の作業が完了するのを待ってから送信されます。モデル、権限、MCP、および Role の設定は、予約が受け付けられた時点で固定されます。

## Claude のクォータリセット後に続行する

Claude がセッション上限を報告し、5 時間クォータを使い切った場合、将来のリセット時刻が取得できていれば、コンポーザー上部に **Send continue after reset** ショートカットが表示されます。1 回クリックすると、失敗したターンの実行設定を使用して、この会話内でリセット時刻の 1 秒後に文字列 `continue` をそのまま送信するようスケジュールされます。コンポーザーに入力中の下書きはそのまま保持されます。

このショートカットはエラーメッセージ内の時刻テキストではなく、プロバイダーが返すクォータのタイムスタンプを使用します。日付を推測したり、週間上限を 5 時間上限として扱ったりすることはありません。より長期のクォータが依然として使い切られた状態にある場合も、ショートカットは表示されません。保存後は、**View scheduled continue** から既存のメッセージ詳細を開いて変更やキャンセルを行えます。クリックするまで続行メッセージが自動的にスケジュールされることはありません。

## スケジュールタスクを作成する

サイドバーの **Schedules** を開き、**New schedule** を選択します（またはコマンドパレットで「New Schedule」と検索します）。エディターはコンポーザーと同じ構成になっています。

1. **名前とプロンプト（Name and prompt）** — 各実行時に Agent へ指示する内容です。
2. **Agent、モデル、権限（Agent, model and permission）** — コンポーザー下部と同じコントロールです。新しいタスクでは、チャット画面で最後に使用したマシンと Agent、およびその Agent に記憶されている設定が初期値として引き継がれます。表示されているデフォルト値はそのまま使用でき、追加で権限を選択する必要はありません。Pi のように権限セレクターを持たないプロバイダーは、独自の実行ポリシーを使用します。
3. **マシン、プロジェクト、ワークツリー（Machine, project, worktree）** — プロジェクトの指定は任意です。プロジェクトを指定しない場合、各実行はリポジトリをチェックアウトしない通常の Agent チャットとして開始されます。
4. **送信先（Send to）** と **トリガー（Trigger）** — 下記をご覧ください。

不足している項目がある場合は、修正が必要なコントロールの横に感嘆符が表示されます。保存すると一覧画面に戻ります。

## トリガー

- **スケジュール実行（On a schedule）** — **Repeat** でルールを選択し、時刻を指定します。
  - 毎日、毎平日、毎週（曜日を選択）、毎月（日付を選択）
  - 数時間ごと、数分ごと
  - 1 回のみ（日付と時刻を指定）
- **手動（Manual）** — 自動的には実行されず、**Run now** を押したときにのみ実行されます。繰り返し使うプロンプトを保存しておくのに便利です。

エディターには **Next runs** が一覧表示されるため、設定したルールを確認できます。時刻や日付は直接入力します。

## 実行結果の送信先

- **実行ごとに新しいチャット（New chat each run）**（デフォルト） — 実行するたびに独立した新しいチャットが開始されます。
- **このタスク専用の 1 つのチャット（One chat for this task）** — 前回までの文脈を引き継ぐタスク向けに、すべての実行が同じチャットに追記されます。チャットは初回実行時に作成され、**Start a new chat** を選ぶとそれ以降の実行が新しいチャットに切り替わります。
- **既存のチャット（An existing chat）** — 指定した既存のチャットに実行が追記されます。そのチャットの Agent が使用され、別途プロジェクトを選択することはできません。

## スケジュールタスクを管理する

一覧の各行には、タスク名、実行頻度、次回実行予定時刻、および実行に使用される環境が表示されます。

- 時刻指定のある行には **Pause** / **Resume** がその場に配置され、手動実行の行には **Run now** が表示されます。
- 行を右クリックすると、開く、今すぐ実行する、一時停止または再開する、**Last run** を開く、あるいは削除する（削除時は確認が表示されます）といった操作を行えます。
- 行をクリックすると右側から詳細パネルがスライド表示され、上部に一時停止・今すぐ実行・削除の各操作、下部に **Run history** が表示されます。境界線をドラッグするとサイズを変更でき、一覧の余白をクリックすると閉じます。

スケジュールタスクの編集、一時停止、削除を行えるのは作成者のみです。一時停止すると今後の実行は止まりますが、すでに開始されているチャットは個別にキャンセルする必要があります。

## Agent に設定を提案させる

Agent に「平日の毎日午前 9 時に依存関係の更新を確認して」のように伝えると、Agent が名前、プロンプト、実行ルールの下書きを作成し、チャット内に **Schedule this task?** カードを表示します。

- カードには現在の会話の Agent、権限モード、マシン、プロジェクトが使用され、作成される内容が正確に表示されます。
- **Edit** を押すと、カード上でそのまま名前、プロンプト、時間ルールを変更できます。
- **Create** でタスクを作成し、**Ignore** で破棄します。一度作成するとそのカードは編集できなくなるため、変更したい場合は Schedules ページから編集してください。

既存のタスクを修正したい場合は、「夜間レビューのプロンプトにルールを 1 つ追加して」のように Agent に変更を依頼します。現在の内容と提案された名前・時間ルール、およびプロンプトの変更行を示した **Update this scheduled task?** カードが表示されます。**Apply** で変更を保存し、**Ignore** で破棄します。カードに表示されていない項目はそのまま維持されます。提案の後に手動でタスクを編集した場合、そのカードは適用できなくなるため、Agent に新しい提案を依頼してください。

Agent ができるのはスケジュールタスクの作成や変更の「提案」のみであり、Agent 自身がタスクを直接作成・変更することは決してありません。

## 逃した実行

予定時刻にマシンがオフラインだった場合、オンラインに復帰したタイミングで、直近の逃した時刻の分として **1 回だけ** 実行されます（逃した回数分すべてが実行されるわけではありません）。

前回の実行がまだ完了していない状態で次の予定時刻になった場合、新しい実行は前回の完了を待ってから開始されます。待機状態になる実行は最大 1 件までです。

## よくある質問

### タスクに「Waiting for the schedule configuration to finish syncing」と表示されるのはなぜですか？

所有マシンが最新の設定をまだ受信していない状態です。保存後数秒間の表示であれば正常な動作です。表示が消えない場合は、そのマシンがオンラインであり、CLI が最新バージョンになっているかを確認してください。

### マシンを選択できないのはなぜですか？

スケジュールタスクは、この機能に対応した CLI を実行しているご自身のマシンでのみ動作します。対象マシンの Lody CLI をアップデートしてください。

### タスクを実行するためにコンピューターはスリープから自動復帰しますか？

いいえ。CLI はマシンが起きている間にタスクを確認・実行するため、スリープ中のコンピューターを自動で復帰させることはありません。スリープ解除後は、[逃した実行](#missed-runs)で説明しているとおり 1 回だけキャッチアップ実行が行われます。
