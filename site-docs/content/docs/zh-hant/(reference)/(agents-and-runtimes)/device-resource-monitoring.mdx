# 裝置資源監控

Lody 可以顯示每台已連線裝置以及其上每個常駐 ACP 工作階段的目前資源用量。你可以透過這個檢視畫面找出消耗 CPU 或記憶體的 Agent、開啟對應的工作階段，或在不刪除對話的情況下停止其 ACP 程序。

開啟 **設定 -> 裝置**，然後選取一台上線中的裝置。頁面會自動開始取樣；沒有手動重新整理按鈕。

## 什麼是常駐 ACP 工作階段？

每個對話都會透過一個 ACP 程序與其編碼 Agent 通訊。當一個輪次進入閒置狀態後，該程序仍可保持常駐，讓下一個輪次能更快回應，但同時也會持續佔用部分記憶體。ACP 工作階段表格會列出目前在所選裝置上仍有 Agent 程序存在的對話。

這是一個程序檢視畫面，而不是所有已儲存對話的清單。即使某個對話的 ACP 程序已經停止，該對話仍會保留在 Lody 中，只是不再顯示於此表格內。

## 資源摘要

頁面頂部將資源劃分為三個範圍，避免將彼此的數值誤加在一起：

| 範圍 | CPU | 記憶體 |
| --- | --- | --- |
| **CLI** | Lody CLI 控制程序本身 | Lody CLI 控制程序所使用的記憶體 |
| **ACP sessions** | 常駐 ACP 工作階段程序樹所使用的 CPU 總計 | 常駐 ACP 工作階段程序樹所使用的記憶體總計 |
| **裝置資訊** | 整台裝置所使用的 CPU，包含 Lody、Agent、作業系統與其他應用程式 | 裝置的已用記憶體 / 有效總記憶體 |

**裝置資訊並非 CLI 與 ACP sessions 的總和。** 它還包含機器上的其他所有程序。相對地，CLI 與 ACP 的數值能協助你判斷裝置用量中有多少屬於 Lody。

### CPU 百分比

三個範圍皆採用相同的多核心計算方式：

- 一個邏輯 CPU 核心滿載時為 `100%`
- 兩個邏輯核心滿載時為 `200%`
- 在 8 核心裝置上，實際的裝置上限約為 `800%`

例如，使用 1.5 個核心的 ACP 工作階段會顯示為 `150%`。由於系統是在短時間視窗內收集樣本，且程序樹的統計方式取決於作業系統平台，因此裝置、CLI、彙總值與個別工作階段的數值之間可能會出現微小差異。

### 記憶體

記憶體代表目前的常駐記憶體佔用量，而非累計配置量。確切的統計方式取決於作業系統：在支援的環境中 Lody 會使用 cgroup 統計，否則會量測相關的程序樹。在 macOS 上，實體記憶體佔用量（physical-footprint）的回報結果可能會與只加總 RSS 的工具所顯示的數值不同。

裝置數值會以 **已用 / 有效總量** 顯示。當 Lody 執行於受限環境時，「有效總量」可能是容器或 cgroup 的記憶體上限，而非主機實際安裝的 RAM。可用記憶體、快取、共享分頁以及平台統計方式，都可能使各列數值手動加總後與裝置總量有所差異。

### 為什麼數值可能會顯示為 `-`

CPU 用量是根據兩次取樣之間的變化量計算出來的，因此在監控剛開始或 CLI 重新啟動後的第一份樣本中無法取得該數值。當作業系統無法針對某個工作階段的程序樹提供可靠統計時，該工作階段的 CPU、記憶體或程序數也可能會顯示為 `-`。請先等待下一次自動取樣；如果數值仍無法取得，請確認該裝置處於上線狀態，且其 Lody CLI 已更新至最新版本。

## ACP 工作階段表格

每一列代表一個常駐對話：

| 欄位 | 含義 |
| --- | --- |
| **Session** | 對話標題、ACP 名稱與 ACP 圖示。選取即可開啟對應的工作階段與分頁。將游標移至被截斷的標題上可查看完整標題。 |
| **狀態** | 目前的 ACP 生命週期或活動狀態 |
| **記憶體** | 目前歸屬於該工作階段 ACP 程序樹的記憶體 |
| **CPU** | 該程序樹所使用的 CPU，其中一個邏輯核心滿載為 `100%` |
| **程序數** | 目前歸屬於該工作階段的程序數量，包含追蹤中的子程序 |

此表格最多顯示 100 個常駐工作階段。在程序剛建立或結束時，量測數據可能會出現短暫延遲，特別是在需要由 Lody 透過程序樹推估歸屬關係的平台上。

### 狀態參考

| 狀態 | 含義 |
| --- | --- |
| **正在初始化** | Lody 正在啟動或連線至 ACP 程序 |
| **執行中** | Agent 正在處理一個輪次 |
| **等待權限** | Agent 已暫停，等待權限請求獲得回應 |
| **正在收尾** | Agent 已完成主要工作，Lody 正在進行最後處理 |
| **閒置** | ACP 程序處於常駐狀態，但目前並未處理任何輪次 |
| **正在停止** | 終止請求進行中，Lody 正在等待程序結束 |
| **失敗** | 常駐工作階段或其 ACP 程序發生錯誤 |

## 釋放 ACP 工作階段的資源

選取工作階段列末端的停止圖示，即可終止該工作階段的 ACP 程序。停止閒置中的程序會直接開始，不會要求確認。若 Agent 正處於執行中、正在初始化、等待權限或正在收尾的狀態，Lody 會要求確認，因為進行中的輪次將會被中斷。

停止圖示會顯示旋轉載入圖示，直到 ACP 程序結束且裝置監控確認該工作階段已不再常駐為止。若終止失敗，Lody 會回報錯誤並保留該工作階段，以便再次嘗試。

終止 ACP 程序會：

- 停止目前的 Agent 輪次及其追蹤中的子程序
- 釋放該常駐程序樹所佔用的 CPU 與記憶體
- 保留對話歷史紀錄、工作階段中繼資料、分支、worktree 與專案檔案
- 不會封存或刪除該工作階段，也不會回收其磁碟空間

已中斷的指令或檔案寫入操作不會自動復原。如果在 Agent 正在進行變更時將其終止，請檢視該工作階段的檔案與 diff。

## 稍後繼續對話

你可以隨時回到已終止的工作階段並傳送新訊息。Lody 會重新啟動 ACP 程序，並從持久化儲存的工作階段上下文繼續對話。由於 Agent 執行環境需要重新啟動與連線，復原後的第一個新輪次可能會花較長時間，但對話內容與檔案自始至終都會完整保留。

當 ACP 程序終止時，僅存於程序本機且尚未儲存的狀態將會消失。可持久保存的上下文來自已儲存的對話、Agent 的續傳（resume）支援，以及工作階段工作區中的檔案。在工作空檔之間，可以使用終止來釋放 CPU 與記憶體；只有在需要同時變更工作階段可見性或回收磁碟空間時，才使用封存或刪除功能。關於封存、還原與刪除行為，請參閱[工作階段](/zh-hant/docs/session)。

## 即時且按需回報

資源監控刻意設計為暫時性的（ephemeral）：

- 只有在有人正在檢視裝置頁面時，上線中的裝置才會回報並重新整理資源快照
- 頁面保持開啟並可見時會自動更新
- 快照過期後即會失效，不會作為歷史指標時間軸保存
- 當沒有人檢視時，Lody 會停止請求持續的資源取樣

如果裝置已共享至工作區，有權存取該裝置的工作區成員都能看見其目前的資源資訊。在共享裝置上終止 ACP 程序會對所有人影響該工作階段，因此在停止其他成員正在進行的輪次前，請先確認工作階段狀態。此監控功能並非程序命令列檢視器，也不是作業系統級效能分析工具的替代品。

當裝置處於離線狀態時，Lody 無法請求新的取樣或終止其 ACP 程序。請先讓 CLI 恢復上線，重新開啟 **設定 -> 裝置**，並等待第一份樣本。
