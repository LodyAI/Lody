# 推薦工作流程

Lody 目前將 [GitHub 整合](/zh-hant/docs/github)與 [Worktrees](/zh-hant/docs/worktrees) 視為核心功能，因此我們建議將它們作為預設的工作流程。

開始之前，請先完成[快速開始設定](/zh-hant/docs/quickstart)。

## 將工作拆分為小型任務

由於 Agent 具有上下文限制，平行執行多個小型任務的效果，通常會優於在單一對話中推進一個龐大且複雜的任務。開始之前，請先將工作拆分為獨立的原子功能或修正項目。這樣你就能利用 worktree 層級的檔案隔離進行平行開發，進而減少等待時間。

## 平行開發

拆分需求之後，請在首頁的對話輸入框中，為每個對話描述單一項功能或修正。在此工作流程中，一個對話對應一項功能或修正，通常也就對應一個 PR。你可以依照本機效能與自身切換上下文的承受能力，同時執行任意數量的平行對話。關於背後的產品模型——包含隔離的 worktree、混用不同 Agent 以及團隊可見性——請參閱[平行編碼 Agent](/zh-hant/docs/parallel-agents)。

當 Lody 完成一輪執行後，會發送[通知](/zh-hant/docs/notification)。點擊通知即可前往對應的工作階段。如果你熟悉閱讀程式碼，可以直接在 Lody 中檢視變更的檔案；若不熟悉，則可複製左側邊欄中該工作階段下方的分支名稱，並在你習慣的開發環境中切換至該分支進行端對端測試。

當結果大致就緒後，點擊對話上方的 **Create PR**。Lody 會建立一個包含完整需求與實作摘要的 PR，並將其關聯至該對話。接著你可以點擊已關聯的 PR 按鈕，直接跳轉至 GitHub 上的 PR 頁面。

## AI Review 循環

如果你將 Claude Code、Codex、Devin 或類似工具連接至儲存庫，它們便能對每個 PR 進行詳細的 Review。收到 Review 評論後，你可以向 Lody 下達類似這樣的指令：
`擷取 PR 評論，評估每項意見是否合理；若合理則修正並標記為 resolved，否則回覆說明理由。`
Lody 會擷取 PR 評論、逐一評估、套用修正並推送新的 commit。這會觸發下一輪 AI Review（自動觸發，或透過 `@` 手動觸發），持續循環直到沒有明顯問題為止。

## 封存已完成的工作階段

當 PR 合併後，該工作階段便已完成其任務。除非出現相關的錯誤，否則我們不建議在同一個工作階段中繼續進行無關的工作。請使用側邊欄中的[封存操作](/zh-hant/docs/session#封存工作階段)，將已完成的工作階段從使用中列表移除。

封存可以在保留對話與本機分支的同時，回收託管的 worktree 目錄。請先將需要的 ignored 檔案另存至 worktree 之外；詳見 [Worktree 保留與還原](/zh-hant/docs/worktrees#自動清理)。

## 定期刪除已封存的工作階段

當你不再需要某個對話時，請[刪除已封存的工作階段](/zh-hant/docs/session#刪除工作階段)以永久移除其歷史紀錄。此操作不會刪除保留的本機 Git 分支或其備份 commit，也無法用來回收全部的儲存庫空間。

## 非 GitHub 專案

此工作流程最適合託管在 GitHub 上的專案。對於非 GitHub 託管的工作，請將該目錄新增為[本機專案](/zh-hant/docs/local-project)。本機專案仍支援對話、檔案列表、diff 審查、行動裝置存取以及 Lody Preview，但無法使用 GitHub 專屬的 PR 與 CI 自動化功能。
