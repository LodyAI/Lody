# Agent 工作階段控制

Lody Agent 可以使用內建的 Lody MCP 工具跨對話協作。這能讓你請一個 Agent 將任務拆分為多個專注的對話、檢查它們的進度、發送後續工作，並將完成的結果帶回原本的對話。

由你自己啟動多個工作階段——包含隔離的 worktree、混用模型、團隊可見性——請參閱[平行編碼 Agent](/zh-hant/docs/parallel-agents)。本頁說明的是控制路徑：由一個 Agent 來協調其他對話。

若想查看包含主 Agent、Kimi、Codex 與 Grok 的操作說明——包括對話提及（mention）與跨機器協作——請參閱 [Agent 協作工作流程](/zh-hant/docs/agent-collaboration/)。

  - 自行同時啟動多個任務 → [平行編碼 Agent](/zh-hant/docs/parallel-agents)

## 在對話中使用

在一般的提示詞中描述期望的結果與分工方式即可。例如：

```text
為這個專案建立兩個審查對話：一個檢查正確性，另一個檢查測試覆蓋率。
當兩者都完成後，在這裡彙整發現的問題。
```

Agent 可以建立或重複使用對話、讀取其狀態與有限範圍的歷史紀錄、傳送後續指示，或在適當時候取消正在執行的回合。當指派的工作達到終止狀態後，結果會回傳至發起請求的對話。

建立新工作階段時，Agent 也能從目標機器上可用的相容模型與推理選項中進行選擇。如果這些偏好設定對任務很重要，請在提示詞中一併說明，例如：

```text
使用 Codex 並搭配高推理強度設定建立一個審查工作階段，完成後在這裡彙整發現的問題。
```

## 協調 PR、Issue 與跨儲存庫修復

### 以 Claude Code 作為協調者

請 Claude Code 檢視一組 PR 或 Issue、識別彼此的依賴關係，接著將專注的任務指派給 Kimi、Codex 或 Grok 等其他 Agent。每個 Agent 都在各自的對話中運作，而協調者可以持續追蹤進度並彙整結果。儲存庫存取會使用各 Agent 可用的工具與憑證。

```text
檢視這些 PR 與 Issue、將相關工作分組並識別依賴關係。
在獨立的對話中，將可獨立進行的修復指派給 Kimi，並將審查指派給 Codex。
彙整它們的發現，並回報哪些變更已經準備好供我審查。
```

### 跨儲存庫修復 Bug

當一個 bug 橫跨用戶端、SDK 與伺服器端時，請為每個受影響的儲存庫建立一個對話。Agent 可以平行調查並實作各自獨立的變更、針對共同的介面契約交換發現，並協調具有依賴關係的變更。

```text
在用戶端、SDK 與伺服器端三個儲存庫中調查這個 bug。
為每個儲存庫啟動一個專注的 Agent 對話。讓它們交換發現，
並在實作具有依賴關係的修復前，先針對介面變更達成共識。
在這裡彙整修補程式與驗證結果。
```

### 在 Agent 之間執行審查與修復循環

Agent 可以向其他有權存取的 Lody 對話傳送訊息並委派工作。你也可以要求一個 Agent 直接傳送訊息給另一個 Agent：讓審查者檢視指定的提交、將發現的問題傳送給負責實作的 Agent，並在修復後再次審查更新後的提交。

```text
請審查 Agent 在不進行編輯的情況下，檢視實作 Agent 目前的提交。
將具體可執行的審查意見傳送給實作 Agent，並請它進行修復。
讓審查者檢查更新後的提交。最多進行兩輪，若沒有剩餘問題則提早結束，
並為我彙整結果。
```

這些範例描述的是你可以要求執行的工作流程，而非預先設定好的管線。請明確指出目標儲存庫、範圍、完成條件與審查輪數上限。平行完成的工作在準備好合併之前，仍須通過整合檢查。

## 預期行為

- 每個對話仍是獨立的任務，擁有各自獨立的歷史紀錄與進行中回合。
- 當目標機器在線上時，各項工作可以平行執行。
- Lody 會保留與發起請求對話之間的關聯，因此 Agent 能在委派工作完成後繼續處理。
- 暫時性的對話在任務完成後，可從工作階段列表中予以封存。

## 限制

工作階段控制刻意設有邊界：Agent 僅能檢視由 Lody 擁有的對話資料，且無法將其作為無限制的背景排程器使用。被委派的任務可能會在所要求的截止時間之後才完成；即使發起方已收到逾時結果，該任務的輸出仍會保留在對應的對話中。

若要將進行中的工作階段交接給隊友，而非協調其他 Agent，請參閱[分享編碼 Agent 工作階段](/zh-hant/docs/session-handoff)。
