# 排程任務

**排程任務**會在你指定的時間，使用你選定的 Agent、模型、權限模式與專案發送一段 prompt。每次執行都是一段普通的對話：你可以隨時開啟它、繼續交談，或隨時停止執行。

常見用途：每天早上彙整昨天合併的提交紀錄、每個工作日檢查相依套件的安全公告、每週五起草週報——或是保留一個手動任務，需要時只要點擊一下即可執行。

## 在哪裡執行

排程任務不在雲端執行，而是由**你自己的一台主機**負責持有並執行：

- 該主機需執行支援排程功能的 [Lody CLI](/zh-hant/docs/cli) 版本（桌面版應用程式會自動為你啟動）。
- 時間會依據**該主機的本機時區**判讀，沒有時區選擇器。「每天 9:00」即代表該主機當地時間的 9:00。
- 若主機關機、進入睡眠模式，或 CLI 未在執行中，到點時不會執行任何任務。恢復後的處理方式請參閱[錯過的執行](#錯過的執行)。

你可以在網頁版、桌面版與手機版檢視及管理排程任務，但實際執行的只有持有該任務的主機。

## 從對話中排程發送訊息

在現有對話中選擇 **+ → 排程發送…**，依照目標主機的時鐘選取未來的日期與時間，接著按下輸入框的排程發送按鈕。此入口僅會發送一次，且無法在「新對話」頁面中使用。

文字、圖片、檔案與參照會在附件準備完成後一併儲存。資訊列會保留一個排程訊息圖示，點擊即可查看發送時間與「編輯」膠囊按鈕。點擊「編輯」會開啟日期／時間控制項，並提供 30 分鐘、1 小時與 5 小時的預設選項；選擇「移除時間」則會回到一般發送模式，且不會遺失草稿。即使儲存失敗，草稿同樣會保留。

輸入框上方的待發送訊息摘要可開啟「排程詳情」，讓你在其中修改訊息內容與時間，或取消排程。取消操作會等待持有該任務的主機確認；若分派已經提交，訊息狀態便會顯示為已發送。「已發送」僅表示訊息已交給對話，與 Agent 最終的執行結果無關。

請使用你自己的主機，並搭配支援完整訊息的 CLI 版本。若主機在預定時間處於睡眠或離線狀態，恢復連線後會補發一次。若對話當下正在忙碌中，則會先完成目前的作業。模型、權限、MCP 與 Role 設定會在受理當下即鎖定。

## 在 Claude 配額重設後繼續

當 Claude 回報工作階段上限且其 5 小時配額已用盡時，若能取得未來的重設時間，輸入框上方就會出現 **重設後發送 continue** 捷徑。點擊一次即可在這段對話中排程於重設後的 1 秒鐘發送字面訊息 `continue`，並沿用該次失敗輪次的執行設定。你目前在輸入框中的草稿會完整保留。

此捷徑使用的是 provider 回傳的配額時間戳記，而非錯誤訊息中的時間文字；它不會自行推算日期，也不會將每週上限當作 5 小時上限。若仍有其他尚未恢復的長期配額已用盡，同樣不會顯示此捷徑。儲存後，點擊 **檢視已排程的 continue** 可開啟現有的訊息詳情以進行變更或取消。在你點擊之前，系統不會自動排程任何接續訊息。

## 建立排程任務

在側邊欄開啟 **排程**，然後選擇 **新增排程**（或在命令面板搜尋「New Schedule」）。編輯器的版面與對話輸入框相似：

1. **名稱與 prompt** —— 指定 Agent 每次執行時應完成的事項。
2. **Agent、模型與權限** —— 與輸入框底部的控制項相同。新任務預設會帶入你上次在對話首頁使用的主機、Agent 以及該 Agent 記住的設定。畫面上顯示的預設值即可直接使用，無須額外選擇權限；像 Pi 這類沒有權限選擇器的 provider 則會套用其自身的執行原則。
3. **主機、專案、Worktree** —— 專案為選填；若未選擇專案，每次執行都會是與 Agent 之間的純對話，不會簽出任何儲存庫。
4. **發送至**與**觸發方式** —— 詳見下文。

任何遺漏的欄位都會在對應控制項旁顯示驚嘆號提示；儲存後即會返回列表。

## 觸發方式

- **依排程** —— 在**重複**下方選擇規則，再設定時間：
  - 每天、每個工作日、每週（選擇星期幾）、每月（選擇日期）
  - 每隔幾小時、每隔幾分鐘
  - 僅一次（指定日期與時間）
- **手動** —— 不會自動執行，僅在你按下**立即執行**時才會運行。很適合用來保存會重複使用的 prompt。

編輯器會列出**接下來幾次執行**的時間，方便你確認規則是否正確。日期與時間皆為直接輸入。

## 執行內容發送至何處

- **每次執行開啟新對話**（預設）—— 每次執行都會開啟一段獨立的新對話。
- **此任務專用單一對話** —— 每次執行都會附加到同一個對話中，適合需要延續先前上下文的任務。該對話會在首次執行時建立；點擊**開啟新對話**可讓後續執行改用全新的對話。
- **現有對話** —— 每次執行會附加到你選取的對話中。系統會使用該對話的 Agent，且不會另外選擇專案。

## 管理排程任務

列表中的每一列都會顯示任務名稱、頻率、下次執行時間以及執行設定：

- 定時排程列上會直接顯示**暫停**／**繼續**按鈕；手動任務列上則會顯示**立即執行**。
- 在任一列上按右鍵可開啟編輯、立即執行、暫停或繼續、開啟**上次執行**，或刪除該任務（刪除前會先詢問確認）。
- 點擊任一列會從右側滑出任務詳情：頂部為暫停、立即執行與刪除按鈕，底部則為**執行歷程**。拖曳分隔線即可調整寬度；點擊列表空白處則可關閉面板。

僅建立者可以編輯、暫停或刪除排程任務。暫停僅會停止未來的執行；已經開始的對話必須個別手動取消。

## 讓 Agent 協助設定

只要告訴 Agent 例如「每個工作日早上 9 點幫我檢查相依套件更新」，它就會草擬好名稱、prompt 與時間規則，並在對話中顯示一張**排程此任務？**卡片。

- 該卡片會沿用目前對話的 Agent、權限模式、主機與專案，並清楚列出即將建立的內容。
- 點擊**編輯**可直接在卡片上修改名稱、prompt 與時間規則。
- 點擊**建立**即會正式建立；點擊**忽略**則放棄此提議。建立完成後便無法再透過卡片編輯——請前往排程頁面修改該任務。

若要修改既有的排程任務，只要請 Agent 協助調整即可，例如「在每晚審查的 prompt 中加入一條規則」。Agent 會顯示一張**更新此排程任務？**卡片，列出目前與提議的名稱及時間規則，以及 prompt 中變更的內容列。點擊**套用**會儲存變更，點擊**忽略**則會放棄；卡片上未列出的設定皆維持不變。若你在 Agent 提出修改建議後自行編輯了該任務，該卡片便會失效：請要求 Agent 重新提出一份修改建議。

Agent 只能提議建立或修改排程任務，絕無法自行直接建立或變更任何排程。

## 錯過的執行

若主機在預定時間處於離線狀態，恢復連線後只會針對最近一次錯過的時間點**補執行一次**——不會針對錯過的每個時段逐一補跑。

若下次預定執行時間到達時上一次執行尚未結束，新的執行會進入等待狀態，待前一次完成後再啟動；最多只會有一筆執行在排隊等待。

## 常見問題

### 任務顯示「正在等待排程設定完成同步」？

這表示持有該任務的主機尚未收到最新的設定；剛儲存後的幾秒內出現此訊息屬於正常現象。若持續顯示此狀態，請確認該主機處於連線狀態，且其 CLI 已更新至最新版本。

### 為什麼無法選擇某台主機？

排程任務只能在安裝了支援排程功能 CLI 的你自己的主機上執行。請在該主機上更新 Lody CLI。

### 電腦在睡眠狀態下會自動喚醒來執行任務嗎？

不會。CLI 只會在主機處於喚醒狀態時檢查並執行任務，不會主動喚醒睡眠中的電腦。電腦喚醒後會依[錯過的執行](#錯過的執行)所述補執行一次。
