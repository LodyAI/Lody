# 工作階段

工作階段（Session）是 Lody 中最基礎的概念。你可以從首頁的對話輸入框啟動新的工作階段，這相當於 Claude Code 或 Codex CLI 中的一次對話。

在開始之前，你可以透過輸入框周圍的選單進行設定：

- 儲存庫與分支
- Agent 設定
- 模型
- 權限範圍

Lody 會根據這些選擇啟動工作階段。

一個工作階段也可以包含多個分頁：主對話、子對話、檔案預覽和 diff 檢視都能保留在同一個工作階段中。如果你想一邊閱讀程式碼一邊繼續對話，或將一項任務拆分成多個審查討論串，請參閱[工作階段分頁](/zh-hant/docs/session-tabs)。

若要邀請團隊成員加入現有的工作階段，讓對方接著同一段對話、差異內容與 worktree 繼續進行，請參閱[共享編碼 Agent 工作階段](/zh-hant/docs/session-handoff)。下方介紹的 Fork 會為你建立一個新的工作階段，而不會將其他人加入原本的工作階段。

## Fork 工作階段

當你的 Agent 支援原生工作階段分叉功能時，最新一則已完成的 Agent 回覆下方會顯示 **分叉工作階段** 按鈕。Fork 會建立一個新的工作階段，保留截至該則回覆為止的對話紀錄，讓你在不更動原工作階段的情況下，朝不同方向繼續對話。

Codex 與 Claude Code 也支援從更早之前已完成的 Agent 回覆進行 Fork。

在宣告支援 worktree 分叉的 Git 工作階段中，**分叉工作階段** 會提供兩個目標位置：

- **目前工作區** — 建立新分頁，與來源工作階段共用檔案及未提交的變更
- **新 Worktree** — 從最新已提交的 `HEAD` 建立獨立的新工作階段；未提交與未追蹤的檔案會保留在來源工作階段

如果未提供 **新 Worktree** 選項，Fork 會保留在目前工作區中進行。側邊對話（Side Chat）一律使用共用目錄的路徑。

僅當目前使用中的 Agent 回報支援原生分叉功能時，才會顯示 Fork。

## 右側邊欄：瀏覽器與側邊對話

右側邊欄可在主對話旁保留常用工具。你可以從工作階段工具列開啟 **瀏覽器** 來瀏覽網頁，或使用側邊欄中的 `+` 選單新增面板。

**側邊對話（Side Chat）** 會從最新一則符合條件的 Agent 回覆建立分叉，並在右側邊欄以獨立對話開啟。這非常適合在不離開主工作階段的情況下追問細節或進行審查提問。你可以建立多個側邊對話、在側邊欄之間切換，並在不再需要時點擊其 `X` 按鈕關閉。當目前使用中的 Agent 支援原生工作階段分叉時，即可使用側邊對話。

關於 URL 與遠端連接埠存取的詳細說明，請參閱 [Lody Preview](/zh-hant/docs/preview)。

## 工作階段列表

在左側邊欄中，Lody 會顯示來自一般對話、GitHub worktree 與本機專案的所有對話。你可以使用預設的專案分類方式，或切換至 **Updated** 模式，依最近更新時間將所有項目分組為：Today、This week 與 Older。

每個工作階段都包含由 AI 自動產生的語意標題及目前狀態。將滑鼠游標移至工作階段上，即可在工作階段資訊卡中查看其儲存庫、分支、Pull Request 狀態，以及相較於基礎分支的行數變更。

## 工作階段操作

在側邊欄中對工作階段按右鍵，即可開啟右鍵選單。你可以從這裡重新命名、釘選、封存、複製工作階段 URL，或複製目前的分支名稱。

已釘選的工作階段會固定留在列表頂部，方便隨時找到重要或長期進行的工作。在網頁版中，使用滑鼠中鍵點擊或按住 Cmd/Ctrl 點擊側邊欄中的任務，即可在新的瀏覽器分頁中開啟。

對話操作列與工作階段資訊控制區會集中顯示與目前任務相關的操作，在可用時包含專案、分支、預覽、Pull Request 與程式碼變更等動作。這能讓常用的 GitHub 與專案操作直接留在對話旁，無須切換到獨立檢視畫面。

## 桌面版快速工作階段（Quick Session）

按下 `Cmd/Ctrl+Shift+N` 可開啟獨立的 Quick Session 視窗。這是全系統的桌面快捷鍵，因此即使 Lody 目前不是使用中視窗也能觸發。你可以透過精簡輸入框選擇專案、Agent 與模型，無須先開啟主視窗即可啟動工作階段。

你可以在 **設定** -> **鍵盤快捷鍵** 中變更此快捷鍵。請參閱[命令面板與鍵盤快捷鍵](/zh-hant/docs/keyboard-shortcuts)。

## 在編輯器中開啟工作區

在桌面版的工作階段標頭中，使用 **開啟於** 即可啟動目前的 worktree 或專案目錄。內建啟動器支援多種編輯器，包含 VS Code、Xcode 與 Sublime Text 等。

前往 **設定** -> **一般** -> **路徑啟動器**，你可以選擇預設啟動器，或新增自訂的 Shell 指令。自訂範本必須使用 `{path}` 作為工作階段資料夾的參數，且僅會儲存在目前的桌面裝置上。

若專案已在編輯器中開啟，再次開啟時會將焦點切換至現有視窗，而不會另開新視窗（例如在 Zed 中）。

## 封存工作階段

將滑鼠游標移至列表中的工作階段（或在行動版上點擊），右下角即會顯示封存按鈕。點擊該按鈕即可封存工作階段。

已封存的工作階段會移至封存列表，並保留其對話紀錄。在永久刪除之前，所屬機器可以回收由 Lody 管理的 worktree 目錄，同時保留本機分支並先提交尚未提交的非忽略（non-ignored）變更。已忽略的檔案可能會被捨棄，且清理腳本可能會在備份前更動檔案。封存前請務必將需要的檔案另存至 worktree 之外。關於清理時機、還原條件與保護邊界，請參閱[Worktree 保留與還原](/zh-hant/docs/worktrees#自動清理)。直接在本機專案目錄中執行的工作階段，其目錄不會被託管 worktree 清理機制移除。

## 取消封存工作階段

在左側邊欄的右下角，點擊封存列表按鈕即可開啟已封存的工作階段。你可以使用搜尋與排序功能找到目標工作階段，然後點擊其還原按鈕將它移回使用中列表，隨時繼續對話。

## 刪除工作階段

在左側邊欄的右下角，點擊封存列表按鈕即可開啟已封存的工作階段。點擊工作階段旁的刪除按鈕，即可永久移除該工作階段及其對話紀錄，此操作無法復原。任何尚未移除的託管 worktree 仍會依據[相同的備份規則](/zh-hant/docs/worktrees#自動清理)等待清理；本機 Git 分支與提交紀錄仍會保留。

對於未選擇專案的工作階段，刪除時也會一併移除由 Lody 管理的對話工作目錄及其中的所有檔案，且不會進行備份或提供復原；封存則僅會回收空目錄。

<img src="/_docs-assets/delete-archive.png" alt="" />

## 批次還原與刪除

將滑鼠游標移至對話項目上，並點擊前方的核取方塊即可進入多選模式。接著可點擊更多操作進行批次選取，並從右上角的控制項目中選擇批次還原或刪除。
