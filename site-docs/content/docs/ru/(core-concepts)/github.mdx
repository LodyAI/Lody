# Интеграция с GitHub

Чтобы рабочий процесс оставался плавным на компьютере и мобильных устройствах, интеграция с GitHub встроена в основу Lody. После установки GitHub App Lody для ваших репозиториев вы сможете клонировать проекты с любого устройства, получать контекст Issue и PR и работать ещё удобнее.

## Настройка

Откройте **Settings** -> **GitHub** -> **Manage**, чтобы перейти на страницу установки GitHub App.
Выберите репозитории, к которым хотите предоставить доступ Lody, а затем вернитесь в Lody. Выбранные репозитории появятся в разделе **Repositories available to add to workspace**. Добавьте нужные из них в текущее рабочее пространство.

Lody позволяет использовать один репозиторий сразу в нескольких рабочих пространствах. В других рабочих пространствах репозитории, для которых уже установлено приложение GitHub App, можно выбрать и добавить напрямую.

### Репозиторий не отображается в списке авторизованных?

Если репозиторий, которому вы выдали доступ, не появляется в разделе **Authorized Repositories**, скорее всего, он не попал в конфигурацию при установке GitHub App (например, вы нажали **Install** до выбора этого репозитория, либо он находится в организации, где требуется одобрение администратора).

Проще всего пройти авторизацию заново:

1. Откройте [github.com/settings/installations](https://github.com/settings/installations) (для личных репозиториев) или страницу настроек вашей организации **Settings → GitHub Apps → Lody → Configure**.
2. Удалите GitHub App **Lody**.
3. Вернитесь в Lody, откройте **Settings → GitHub → Manage** и установите приложение заново, на этот раз выбрав все репозитории, к которым у Lody должен быть доступ.

После завершения переустановки вернитесь на страницу настроек — репозитории появятся в списке, и их можно будет добавить в рабочее пространство.

## Личный профиль GitHub

Установка GitHub App даёт Lody доступ к репозиториям. Личный профиль настраивается отдельно и не обязателен: включайте его только в том случае, если хотите, чтобы комментарии в PR, действия ревью и слияния выполнялись от имени вашего собственного пользователя GitHub. Для этого включите параметр **Act as you for PRs, comments, and merges** в разделе **Settings** -> **GitHub**, а затем авторизуйте свою учётную запись GitHub.

После авторизации на странице настроек отобразится подключённый аккаунт GitHub. Это не меняет список репозиториев, к которым у Lody есть доступ, — он по-прежнему определяется установкой GitHub App. Вы можете отключить этот параметр позже, если захотите, чтобы Lody снова использовал только идентификатор GitHub App рабочего пространства.

## Выбор репозитория для диалога

На главной странице используйте переключатель репозитория в левом верхнем углу поля ввода, чтобы выбрать репозиторий, добавленный в рабочее пространство. После этого Lody покажет список веток в этом репозитории, чтобы вы могли выбрать точку старта.

После создания диалога Lody клонирует и инициализирует репозиторий на машине с CLI, а затем создаёт новый [Worktree](/ru/docs/worktrees) от выбранной вами ветки. Каждый диалог работает в собственной ветке и не затрагивает другие диалоги.

## Запуск из Issue или Pull Request

После выбора репозитория на главной странице введите `@`, чтобы открыть меню упоминаний, а затем выберите **Issues** или **Pull Requests**, чтобы сослаться на нужный элемент из текущего репозитория.

Используйте клавиши со стрелками вверх и вниз для выбора нужного пункта и нажмите Enter для подтверждения. Lody вставит выбранный элемент в поле ввода в виде `#<number>` и добавит его контекст в промпт, чтобы агент мог выполнять задачи вроде `Fix #12` или `Review the implementation in #56`.

## Статус PR и синхронизация CI

Когда сессия привязана к PR на GitHub, Lody отображает номер PR, его состояние (open/closed/merged) и статус CI прямо в интерфейсе сессии. Выполняющиеся, успешные и проваленные проверки обновляются в Lody автоматически, поэтому вам не нужно постоянно переключаться обратно в GitHub, чтобы проверить готовность ветки.

Если вы продолжаете работу в ветке, для которой уже создан PR, Lody также постарается определить этот PR и автоматически привязать его к сессии.

## Действия с PR в Lody

Нажмите на значок PR в верхней части привязанной сессии, чтобы открыть панель PR. В ней можно просмотреть заголовок PR, описание, ветку, статусы CI, комментарии и ревью, не покидая Lody.

Для черновиков (Draft PR) на панели отображается действие **Ready for review**. Когда PR готов и его можно слить, вы также можете выполнить слияние прямо из Lody и удалить ветку после слияния, если она всё ещё существует на GitHub.

## Коммит и отправка изменений для сессий с PR

Для сессий с поддержкой GitHub, привязанных к PR, Lody проверяет рабочее пространство после каждого хода агента. Если остались незафиксированные изменения или локальные коммиты, которые ещё не отправлены, Lody может предложить агенту зафиксировать их и отправить в ветку PR.

Вы также всегда можете запустить **Commit & Push** вручную из интерфейса сессии или использовать **Fix PR Comments**, если комментарии к ревью требуют ещё одного прохода.

## Синхронизация комментариев к ревью

В разделе [Комментарии к diff](/ru/docs/diff-comments) сессии, привязанные к PR, могут публиковать новые строчные комментарии обратно на GitHub — для этого достаточно включить **Sync to GitHub**.

Существующие строчные комментарии из ревью PR на GitHub также отображаются в diff-просмотре Lody, а ответы из Lody отправляются обратно на GitHub. Это позволяет вести ревью, изучать код и выполнять доработки с помощью агента в одном месте.
