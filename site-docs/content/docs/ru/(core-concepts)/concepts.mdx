# Основные понятия и глоссарий

Большая часть Lody строится вокруг небольшого набора объектов, которые одинаково организованы на каждом экране. Прочитайте эту страницу один раз, и ориентироваться в руководствах станет заметно проще.

## Ментальная модель

```text
workspace
├── projects / repositories
│   └── session            одна задача, один диалог, одна ветка / worktree
│       ├── round          один ход агента + внесённые им изменения
│       ├── side chat      ответвлённый вопрос, не прерывающий основную задачу
│       └── pull request   опциональная передача в GitHub после проверки
├── agent configs          среда выполнения + аутентификация + машина
│   └── agent roles        сохранённая связка: машина + конфигурация + модель + права
└── teammates              видят общие сессии, но не личные машины
```

Сессия — это объект, в котором вы проводите большую часть времени. Всё остальное либо питает её (проект, репозиторий, конфигурация агента, роль), либо создаётся на её основе (diff, pull request, передача сессии).

## Путь задачи

1. **Добавьте проект или репозиторий.** [Локальный проект](/ru/docs/local-project) — это каталог на диске; [репозиторий GitHub](/ru/docs/github) добавляет pull request, CI и синхронизацию ревью.
2. **Выберите, что будет запускаться.** [Конфигурация агента](/ru/docs/quickstart) (Agent Config) привязывает среду выполнения к машине и её учётным данным. [Роль агента](/ru/docs/agent-roles) (Agent Role) сохраняет часто используемую комбинацию.
3. **Откройте сессию.** В поле ввода на главной странице выберите проект, ветку, конфигурацию, модель и область разрешений. Подробнее см. в разделе [Сессии](/ru/docs/session).
4. **Работайте раундами.** Каждый раунд — это ход агента плюс diff. Проверяйте изменения в [просмотрщике diff](/ru/docs/diff-viewer) и оставляйте [комментарии к diff](/ru/docs/diff-comments).
5. **Завершите задачу.** Создайте pull request, оставьте ветку или отправьте сессию в архив. Подробнее см. в [Рекомендуемом рабочем процессе](/ru/docs/workflow).

## Основные объекты

| Термин | Что это такое | Подробнее |
| --- | --- | --- |
| **Workspace** | Контейнер уровня команды: участники, общие машины, сессии и настройки. | [Командные функции](/ru/docs/team) |
| **Проект / репозиторий** | Код, с которым работает сессия — локальный каталог или репозиторий GitHub. | [Локальные проекты](/ru/docs/local-project) · [Интеграция с GitHub](/ru/docs/github) |
| **Сессия (Session)** | Одна задача с одним диалогом, одной веткой и, как правило, одним worktree. | [Сессии](/ru/docs/session) |
| **Раунд (Round)** | Один ход агента вместе с внесёнными им изменениями в файлах. | [Просмотр diff](/ru/docs/diff-viewer) |
| **Worktree** | Изолированная рабочая копия репозитория, позволяющая двум сессиям редактировать один и тот же код без конфликтов. | [Worktree](/ru/docs/worktrees) |
| **Конфигурация агента (Agent Config)** | Среда выполнения (Claude Code, Codex, Kimi, ACP и другие) вместе с её аутентификацией и машиной для запуска. | [Конфигурация агента](/ru/docs/quickstart) · [Типы сред выполнения CLI](/ru/docs/cli-runtimes) |
| **Роль агента (Agent Role)** | Сохранённый пресет, объединяющий машину, конфигурацию агента, модель, уровень рассуждений, права доступа и опциональную инструкцию. | [Роли агента](/ru/docs/agent-roles) |

## Как связаны эти элементы

<Accordions>
<Accordion title="Сессия, раунд и ход агента">
**Сессия** — это вся задача целиком и её история. **Раунд** — это один ход агента вместе с его diff. Когда в этой документации говорится «проверьте раунд», имеется в виду просмотр diff, созданного за этот ход, перед тем как продолжить.
</Accordion>
<Accordion title="Конфигурация агента (Agent Config) и роль агента (Agent Role)">
**Конфигурация агента** отвечает на вопрос: «что может запускаться на этой машине и как проходит аутентификация?». **Роль агента** отвечает на вопрос: «какие машину, конфигурацию, модель и права доступа нужно выбрать, когда я запускаю задачу такого типа?». Роли ссылаются на конфигурации; конфигурации на роли не ссылаются.
</Accordion>
<Accordion title="Форк (Fork), Side Chat и передача сессии (Handoff)">
- **Форк (Fork)** копирует диалог в новую сессию, чтобы вы могли попробовать другое направление.
- **Side Chat** — это ответвление, закреплённое рядом с основным чатом для быстрого вопроса.
- **Передача сессии (Handoff)** приглашает коллегу в ту же самую сессию и не создаёт копию. Подробнее см. в разделе [Совместный доступ к сессии агента](/ru/docs/session-handoff).
</Accordion>
<Accordion title="Параллельные сессии и управление сессиями из агента (Agent Session Control)">
- **Параллельные сессии** запускаете вы сами — у каждой своя задача и свой worktree. Подробнее см. в разделе [Параллельные агенты программирования](/ru/docs/parallel-agents).
- **Управление сессиями из агента (Agent Session Control)** — это режим, в котором агент создаёт другие сессии, управляет ими и собирает результаты через MCP-инструменты Lody. Подробнее см. в разделе [Управление сессиями из агента](/ru/docs/session-orchestration).
</Accordion>
</Accordions>

## Глоссарий терминов, которые встретятся в документации

| Термин | Значение |
| --- | --- |
| **ACP** | Agent Client Protocol — интерфейс, который Lody использует для запуска и взаимодействия со множеством CLI-агентов для программирования. Подробнее см. в разделе [Типы сред выполнения CLI](/ru/docs/cli-runtimes). |
| **MCP** | Model Context Protocol. Lody предоставляет встроенные MCP-инструменты, чтобы агент мог взаимодействовать с диалогами Lody и другими ресурсами. |
| **Демон (Daemon)** | Фоновый процесс Lody CLI, который непосредственно запускает агентов на машине. Подробнее см. в разделе [Команды CLI](/ru/docs/cli). |
| **Область разрешений (Permission scope)** | Объём действий, которые агент может выполнять без подтверждения — например, редактировать файлы или выполнять команды в оболочке. Задаётся для каждой сессии в поле ввода. |
| **Контекстное окно (Context window)** | Объём диалога, который модель может удерживать за один раз. Lody отображает оставшуюся ёмкость в чате. Подробнее см. в разделе [Контекст, токены и квоты](/ru/docs/usage-and-quota). |
| **Передача сессии (Handoff)** | Приглашение коллеги в активную сессию, чтобы он мог продолжить тот же диалог, работать с теми же diff и тем же worktree. |
| **Оркестрация (Orchestration)** | Сценарий, при котором один агент создаёт другие сессии, отправляет им сообщения и собирает результаты. |

## Часто задаваемые вопросы

### В чём разница между конфигурацией агента (Agent Config) и ролью агента (Agent Role)?

Конфигурация агента — это среда выполнения вместе с её аутентификацией и машиной для запуска. Роль агента — это сохранённый пресет, который задаёт машину, конфигурацию агента, модель, уровень рассуждений и права доступа, а также опциональную инструкцию, чтобы вы могли повторно использовать одну и ту же настройку при запуске сессии. Подробнее см. в разделах [Конфигурация агента](/ru/docs/quickstart) и [Роли агента](/ru/docs/agent-roles).

### В чём разница между форком сессии и её передачей (handoff)?

При форке диалог копируется в новую сессию, владельцем которой являетесь вы. При передаче сессии другой человек приглашается в существующую сессию, и вы оба видите один и тот же живой чат, diff и worktree. Форк никого не добавляет в исходную сессию. Подробнее см. в разделах [Сессии](/ru/docs/session) и [Совместный доступ к сессии агента](/ru/docs/session-handoff).

### Нужно ли разбираться в worktree, чтобы пользоваться Lody?

Вы можете пользоваться Lody, ни разу не открывая каталог worktree. Он становится важным, когда вы запускаете несколько сессий одновременно: именно отдельный worktree изолирует правки разных сессий друг от друга. Подробнее см. в разделе [Worktree](/ru/docs/worktrees).

### Является ли «задача» тем же самым, что и сессия?

В рамках этой документации — да: одна задача обычно соответствует одной сессии, одной ветке и одному pull request. В [Рекомендуемом рабочем процессе](/ru/docs/workflow) объясняется, почему небольшие задачи работают лучше.
