# Рабочие деревья (Worktrees)

Рабочие деревья (worktree) лежат в основе того, как Lody изолирует параллельные задачи и управляет ими.

## Что такое worktree?

Git worktree — это связанная рабочая копия вашего репозитория. У каждого worktree есть собственный рабочий каталог с отдельной переключённой веткой, но при этом общая история Git с основным репозиторием.

## Как Lody использует worktree

Когда вы создаёте задачу в Lody, система автоматически:

1. **Создаёт новую ветку** — имя по умолчанию `session/<shortSessionId>` (первые 8 символов `sessionId`; ветку можно переименовать)
2. **Настраивает worktree** — изолированный каталог, в котором работает агент (по одному на сессию)
3. **Запускает скрипт настройки** — необязательные команды на уровне проекта, например установку зависимостей или копирование шаблонов переменных окружения
4. **Синхронизирует изменения** — обновления в реальном времени отображаются в веб-интерфейсе

```
~/.lody/repos/<repoId>/
├── bare.git/                # Чистый (bare) Git-репозиторий (общая история)
├── cache/                   # Кэш сборки и т. д.
└── worktrees/
    ├── <sessionId-1>/       # Worktree для сессии 1
    └── <sessionId-2>/       # Worktree для сессии 2
```

## Преимущества

### Параллельное выполнение

Каждая задача получает собственный worktree, поэтому агенты никогда не перезаписывают изменения друг друга.

### Чистая изоляция

- Незафиксированные изменения разных задач не смешиваются
- Удобно проверять, принимать или отклонять отдельные задачи
- Простое создание PR для каждой задачи

### Автоматическая очистка

Архивирование делает управляемый Lody worktree корневой
сессии доступным для очистки. Диалог остаётся в списке архива
до безвозвратного удаления; рабочий каталог может быть удалён раньше.

| Ресурс | После архивирования и очистки | После безвозвратного удаления сессии |
| --- | --- | --- |
| История диалога | Сохраняется; сессию можно восстановить | Удаляется; удаление сессии необратимо |
| Управляемый Lody каталог worktree | Удаляется машиной-владельцем | Подлежит очистке, если всё ещё существует |
| Локальная ветка Git и коммиты | Сохраняются, включая резервный коммит | Сохраняются; удаление не удаляет ветку |
| Незафиксированные неигнорируемые изменения | Индексируются и коммитятся локально перед удалением | То же правило резервного копирования применяется к оставшимся worktree |
| Игнорируемые файлы, такие как `.env`, зависимости и артефакты сборки | Могут быть удалены вместе с каталогом | Гарантия восстановления отсутствует |
| Исходный локальный каталог проекта | Не затрагивается очисткой управляемых worktree | Не затрагивается очисткой управляемых worktree |

Демон-владелец очищает только worktree внутри своего каталога данных Lody после завершения обработки
метаданных рабочего пространства и освобождения среды выполнения сессии. Очистка может быть отложена,
пока эта машина находится офлайн или если удаление завершилось с ошибкой. Активные и неизвестные
владельцы не затрагиваются; архивирование только дочерней вкладки не удаляет общий worktree её корневой
сессии. Если репозиторий не удаётся разрешить или резервный коммит не выполняется, каталог сохраняется
для повторной попытки.

Резервная копия представляет собой локальный Git-коммит, а не отправку в удалённый репозиторий или
полное резервное копирование каталога. Настроенный скрипт очистки запускается до создания резервной
копии, поэтому удалённые или изменённые им файлы не попадают под эту защиту; сбой скрипта не
предотвращает удаление. Перед архивированием сохраните нужные игнорируемые файлы и все файлы,
затрагиваемые скриптом, за пределами worktree.

Когда вы восстанавливаете и продолжаете сессию, чей worktree был удалён, Lody воссоздаёт его из
сохранённой локальной ветки и снова запускает скрипт настройки. Игнорируемые файлы нужно создать
заново отдельно. Для восстановления требуется, чтобы исходный репозиторий и ветка по-прежнему
существовали; удалённый локальный проект необходимо добавить заново. Ручное удаление данных
репозитория Lody также удаляет эти локальные ветки и резервные копии, поэтому оно не эквивалентно
архивированию или удалению сессии.

## Скрипты настройки и очистки worktree

Скрипты на уровне проекта позволяют единообразно подготавливать каждую новую сессию.

Используйте **скрипт настройки** (setup script) для команд, которые должны выполняться после создания
worktree в Lody и до того, как агент получит первый запрос, например:

```bash
cp .env.example .env
pnpm install
```

Используйте **скрипт очистки** (cleanup script) для команд, которые должны выполняться при архивировании
диалога до того, как Lody удалит worktree с диска, например:

```bash
rm -rf node_modules
```

### Настройка скриптов

1. Откройте **Настройки** -> **Проекты** (**Settings** -> **Projects**).
2. Выберите локальный проект или репозиторий GitHub.
3. Откройте разделы **Настройка worktree** (**Worktree setup**) и **Очистка worktree** (**Worktree cleanup**).
4. Добавьте команды для нужной вашему проекту оболочки и выйдите из редактора для сохранения.

Для локальных проектов Lody показывает оболочку, используемую на машине этого проекта. Windows использует
PowerShell; macOS, Linux и WSL используют Bash. Для репозиториев GitHub вы можете заполнить поля как для
Bash, так и для PowerShell, чтобы сессии работали на разных машинах.

Скрипты запускаются в каталоге worktree. Переменные окружения, экспортированные внутри скрипта,
существуют только для процесса этого скрипта; если переменная окружения нужна самому агенту, задайте
её в разделе [Конфигурация агента](/ru/docs/quickstart).

### Доступные переменные окружения

Lody задаёт следующие переменные окружения как для скриптов настройки, так и для скриптов очистки:

| Переменная                   | Описание                                                       |
| ---------------------------- | -------------------------------------------------------------- |
| `LODY_WORKSPACE_ID`          | Идентификатор текущего рабочего пространства                   |
| `LODY_SESSION_ID`            | Идентификатор текущего диалога/сессии                          |
| `LODY_WORKTREE_PATH`         | Абсолютный путь к worktree сессии                              |
| `LODY_WORKTREE_BRANCH`       | Ветка, переключённая в worktree                                |
| `LODY_WORKTREE_SCRIPT_PHASE` | `setup` или `cleanup`                                          |
| `LODY_GITHUB_REPO`           | Полное имя репозитория GitHub (только для проектов GitHub)     |
| `LODY_LOCAL_PROJECT_ID`      | Идентификатор локального проекта (только для локальных проектов) |

Процесс скрипта также запускается с текущим рабочим каталогом, установленным в `LODY_WORKTREE_PATH`,
поэтому команды могут использовать как `pwd`, так и явную переменную окружения:

```bash
echo "$LODY_SESSION_ID"
echo "$LODY_WORKTREE_PATH"
pnpm install
```
