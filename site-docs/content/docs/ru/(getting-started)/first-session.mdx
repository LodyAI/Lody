# Ваша первая сессия

В разделе [Быстрый старт](/ru/docs/quickstart) описана установка и подключение Lody. На этой странице разобрано то, что остаётся за его рамками:
одна полная сессия — от пустого поля ввода до проверенного вами результата. Всё описанное здесь
работает в локальном проекте, без GitHub и без одновременного запуска нескольких агентов.

<Callout type="info" title="Перед началом">
- Lody установлен, и вы вошли в систему. Если ещё нет, сначала пройдите [Быстрый старт](/ru/docs/quickstart).
- У вас добавлен один проект — подойдёт обычный локальный каталог. Подробнее см. в разделе [Локальные проекты](/ru/docs/local-project).
- У вас есть один Agent Config, проверка **Test** для которого успешно прошла на этой машине. Подробнее см. в разделе [Agent Config](/ru/docs/quickstart).
</Callout>

## Выберите задачу, достаточно небольшую для одной сессии

Сессия — это один диалог с одним агентом об одной задаче. Когда задача небольшая, вы можете быстро
проверить результат, а у агента достаточно контекста, чтобы довести её до конца. Хорошие примеры первых задач:

- «Добавьте эндпоинт `/health`, который возвращает версию приложения».
- «Исправьте падающий тест в `src/parser.test.ts` и объясните причину».
- «Переименуйте `fetchUser` в `getUser` по всему пакету и обновите места вызова».

Не просите в первой сессии реализовать сразу целый функциональный раздел. Когда задачи перерастут рамки одной сессии,
в разделе [Рекомендуемый рабочий процесс](/ru/docs/workflow) показано, как разбивать работу.

<Callout title="Одна сессия — одна задача" type="idea">
Вся остальная документация опирается на эту привычку. Если в рамках одной сессии агент начинает заниматься двумя несвязанными вещами,
остановите её и начните вторую сессию вместо того, чтобы раздувать первую.
</Callout>

## Пошаговый разбор одной сессии

<Steps>
<Step>

### 1. Начните из поля ввода на главной странице

Откройте Lody и воспользуйтесь полем ввода на главной странице. Перед отправкой выберите:

- **проект** (и ветку, если это Git-проект);
- **Agent Config** и **модель**;
- **область разрешений**, с которой вам комфортно работать.

Затем опишите задачу, указав нужный файл или поведение, а также критерии, по которым вы будете оценивать успешность результата.

```text
Add a /health endpoint that returns { "status": "ok", "version": <package version> }.
Add one test that asserts the status and version fields. Do not change other routes.
```

</Step>
<Step>

### 2. Наблюдайте за раундом

Lody создаст сессию и начнёт транслировать работу агента. **Раунд** — это один ход агента плюс внесённые им
изменения в файлах. Пока выполняется раунд, вы можете:

- отправить уточнение, чтобы [**направить (steer)**](/ru/docs/claude-codex-capabilities#корректировка-steer-запущенной-задачи) текущую задачу,
  не дожидаясь её завершения;
- задать вопрос в [**Side Chat**](/ru/docs/session#правая-боковая-панель-browser-и-side-chat), не прерывая
  основную задачу, если агент поддерживает нативное ветвление;
- остановить ход, если агент движется в неверном направлении.

</Step>
<Step>

### 3. Проверьте diff

Когда раунд завершится, в ответе отобразятся изменённые файлы и количество добавленных и удалённых строк.
Нажмите на любой файл, чтобы открыть его на [вкладке diff](/ru/docs/diff-viewer), или воспользуйтесь боковыми панелями **Files** и **Changes**,
чтобы просмотреть изменения за весь диалог.

</Step>
<Step>

### 4. Запросите следующий раунд

Продолжайте работу в той же сессии. Старайтесь, чтобы каждое уточнение касалось только одной вещи:

```text
The test passes, but the version is read from package.json at request time.
Read it once in a module constant instead, and keep the response shape the same.
```

Вы можете повторять цикл «наблюдение, проверка, уточнение» столько раз, сколько нужно для решения задачи. Если диалог становится
слишком длинным или агент теряет нить рассуждений, начните новую сессию с кратким резюме.

</Step>
<Step>

### 5. Решите, что делать с результатом

Когда изменения выглядят как нужно, у вас есть несколько вариантов:

- **Оставить ветку.** Скопируйте имя текущей ветки из сессии и протестируйте или отправьте (push) её из своего
  редактора.
- **Открыть локально.** В десктопном приложении используйте **Open in**, чтобы открыть worktree в вашем редакторе.
- **Создать pull request.** В сессии с GitHub нажмите **Create PR** над диалогом. Lody привяжет PR
  обратно к сессии и синхронизирует статус CI. С этого шага начинается
  [рекомендуемый рабочий процесс](/ru/docs/workflow).
- **Архивировать сессию.** Когда работа завершена, архивируйте сессию на боковой панели. При архивировании
  worktree освобождается, но ветка и диалог сохраняются, так что вы сможете восстановить сессию позже. Подробнее см. в разделе
  [Архивирование сессий](/ru/docs/session#архивирование-сессий).

</Step>
</Steps>

## Частые ошибки в первой сессии

<Accordions>
<Accordion title="Слишком масштабный запрос за один раз">
Длинные многосоставные промпты усложняют и работу агента, и последующую проверку. Разбивайте работу на сессии,
каждая из которых даёт одно изменение, готовое к ревью. Подробнее см. в разделе [Параллельные кодинг-агенты](/ru/docs/parallel-agents).
</Accordion>
<Accordion title="Невыбранный проект или Agent Config">
Если проект не выбран или выбран неверно, агент будет работать не в том каталоге. Перед отправкой проверьте
проект, ветку, Agent Config и модель в поле ввода.
</Accordion>
<Accordion title="Проверка только в самом конце">
Небольшие diff по каждому раунду легко читать и комментировать. Проверка каждого раунда не даёт ошибочному
направлению распространиться на все изменения.
</Accordion>
<Accordion title="Отказ от архивирования">
Завершённые сессии продолжают удерживать свои worktree. Архивируйте их, когда работа влита или отменена,
чтобы освободить место на машине.
</Accordion>
</Accordions>

## Часто задаваемые вопросы

### Нужен ли GitHub для первой сессии?

Нет. GitHub добавляет pull request, статус CI и синхронизацию комментариев к ревью, но в сессии локального проекта можно
вести диалог, редактировать файлы, просматривать diff и проводить ревью полностью самостоятельно. Подробнее см. в разделе
[Локальные проекты](/ru/docs/local-project).

### Что такое «раунд»?

Раунд — это один ход агента плюс изменения файлов, выполненные за этот ход. Lody подводит итог каждого раунда
в виде diff, чтобы вы могли проверять изменения поэтапно, а не читать один большой финальный diff. Подробнее см. в разделе
[Просмотр diff](/ru/docs/diff-viewer).

### Что делать, если агент изменил то, о чём его не просили?

Откройте diff нужного файла, оставьте комментарий или отправьте уточнение в той же сессии, чтобы агент
всё исправил. Если изменение не относится к задаче, попросите агента откатить его и держите сессию
сфокусированной на цели.

### Можно ли остановить запущенную сессию?

Да. Нажмите кнопку остановки в поле ввода, чтобы отменить текущий ход. Остановленная сессия останется в
списке, и вы сможете продолжить её новым сообщением.

### Куда попадает архивированная сессия?

Она перемещается в список архива в правом нижнем углу боковой панели. Диалог и ветка
сохраняются, а при восстановлении сессии worktree создаётся заново. Подробнее см. в разделе
[Архивирование сессий](/ru/docs/session#архивирование-сессий).
