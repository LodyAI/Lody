# Быстрый старт

Lody работает везде, где вы работаете: нативные приложения для macOS, Windows и Linux, мобильные приложения для iOS и
Android, любой браузер, а также CLI, который можно запустить на удалённом сервере.

```bash
npx lody daemon start
```

## Запуск из десктопного приложения

- Скачайте установщик для вашей платформы со [страницы загрузки](/ru/download) и установите его.
- На macOS или Linux его также можно установить с помощью [Homebrew](https://formulae.brew.sh/cask/lody):
  ```bash
  brew install --cask lody
  ```
- При первом запуске Lody откроет браузер для регистрации или входа в аккаунт.
- Десктопное приложение также запускает на вашей машине локальный [демон CLI](/ru/docs/cli#daemon-mode) Lody. Именно
  CLI является процессом, в котором фактически работают агенты.

## Запуск из CLI

### Предварительные требования

- Node.js 22.23.4+ (22.x), 24.22.1+ (24.x) или 26.12.1+ (26.x) с поддержкой Node-API 10+

### Запуск

```bash tab="Демон (рекомендуется)"
npx lody daemon start
```

```bash tab="На переднем плане"
npx lody login
npx lody start
```

`npx lody daemon start` сначала проверяет, удаётся ли подключиться к Lody и выполнен ли вход на этой машине. Если вход
не выполнен, команда сразу запускает процесс авторизации по коду устройства (device code flow): открывает страницу входа
в браузере (на машине без графического интерфейса вместо этого выводит ссылку) и ожидает, пока вы не завершите вход, а
затем переходит в фоновый режим. Тем же способом подключается и удалённая машина — выполните эту команду по SSH на
сервере, в облачной ВМ или на другой рабочей станции, и эта машина появится в вашем рабочем пространстве.

Демон перезапускает CLI при неожиданном завершении. Если у вас вообще нет доступа к браузеру, запустите его напрямую
командой `npx lody daemon start --auth <cli_token>`. Посмотреть и сгенерировать `cli_token` можно в десктопном
приложении в разделе **Settings** -> **Account** -> **CLI Token**. Команда `npx lody login` по-прежнему доступна, если
вы предпочитаете выполнять вход отдельным шагом.

<Callout title="Использование десктопного приложения только для удалённого управления">
По умолчанию десктопное приложение запускает встроенный локальный CLI, чтобы выполнять агентов на этом компьютере. Если
вы хотите управлять только агентами на других машинах, откройте **Settings** -> **General** -> **Startup** и отключите
**Run local agent**.

После отключения десктопное приложение перестанет управлять этим CLI и сохранит его выключенным при следующем запуске.
Агенты, работающие на других машинах, не будут затронуты.

</Callout>

## Добавление проекта

### Добавление локального проекта

<Tabs items={['Десктоп', 'Мобильное приложение', 'CLI']}>
<Tab value="Десктоп">
Воспользуйтесь кнопкой в правом верхнем углу раздела **Settings** -> **Projects**. Выберите нужную машину, и Lody покажет
список её каталогов, чтобы вы могли выбрать один из них в качестве корня проекта.
</Tab>
<Tab value="Мобильное приложение">
Воспользуйтесь кнопкой в правом верхнем углу раздела **Projects**. Выберите нужную машину, и Lody покажет список её
каталогов, чтобы вы могли выбрать один из них в качестве корня проекта.
</Tab>
<Tab value="CLI">
Выполните `npx lody project add <path>`, где `<path>` — корневой каталог проекта.
</Tab>
</Tabs>

### Подключение репозитория GitHub

В веб-приложении нажмите **Settings** в левом нижнем углу, затем **GitHub Integration** -> **Manage**, чтобы разрешить
доступ к вашим репозиториям GitHub. После этого Lody перенаправит вас обратно, чтобы вы могли выбрать репозитории для
добавления в рабочее пространство. [Подробнее](/ru/docs/github)

## Настройка агентов

Lody поставляется со встроенными ACP-провайдерами, включая Claude Code, Codex, Grok, Kimi Code, Devin, Pi, DeepSeek
Harness, Bub и Dimcode. Вы также можете подключить собственных ACP-агентов и любые CLI из
[реестра ACP](https://agentclientprotocol.com/get-started/registry). Добавляйте и настраивайте их в разделе
**Settings** -> **Agents** в десктопном или мобильном приложении.

[Claude Code и Codex](/ru/docs/claude-codex-capabilities) поддерживаются командой Lody напрямую, поэтому предоставляют
возможности, выходящие за рамки протокола ACP.

Для использования встроенного Dimcode сначала установите ACP-совместимый CLI на целевую машину и убедитесь, что команда `dimcode acp` доступна в PATH. Обновлением его версии вы управляете самостоятельно — Lody не скачивает и не обновляет его. После установки новой версии обновите провайдер в разделе Settings. Подробнее см. в [руководстве по установке Dimcode](https://www.dimcode.dev/en/docs/getting-started/).

### Часто задаваемые вопросы

<Accordions>
  <Accordion title="Нужного мне агента нет в списке">
     Вы можете подключить собственного ACP-агента. Перейдите в **Settings** -> **Agents** в десктопном или мобильном
     приложении, выберите **Custom Agent** и укажите команду запуска и аргументы.
  </Accordion>
  <Accordion title="Агент выбран, но самой новой модели нет в списке">
      Lody обновляет конфигурацию каждого агента при запуске приложения и при начале новой беседы. Если ожидаемая
      модель отсутствует, попробуйте нажать кнопку обновления в настройках агента. Если модель вышла совсем недавно,
      возможно, потребуется подождать, пока Lody добавит её поддержку.
  </Accordion>
</Accordions>

## Не удаётся подключиться? Сбросьте локальный кэш

Если после обновления версии приложение показывает устаревшие данные или не загружается, откройте **Settings** ->
**Cache & storage** и нажмите **Clear local cache**. Это удалит локальный кэш Lody для всех рабочих пространств
(офлайн-копии, кэши синхронизированных данных и кэши изображений) и перезагрузит приложение. Ваш аккаунт и
синхронизированные данные в безопасности и загрузятся заново автоматически, а вход в систему сохранится. В мобильном
приложении та же опция находится на странице Settings.
