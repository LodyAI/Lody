# Переход с Codex или Claude Code

Вам не нужно отказываться от CLI `codex` или `claude`. Lody запускает те же самые среды
выполнения через [конфигурации агента (Agent Config)](/ru/docs/quickstart) и добавляет поверх
них слой рабочего пространства: изолированные worktree, несколько сессий одновременно, просмотр
diff в реальном времени, передачу работы команде и доступ с мобильных устройств.

<Callout title="Коротко о главном">
- Ваши подписки, API-ключи и авторизация на машине остаются на своих местах.
- Сессия — это эквивалент одного диалога в CLI в Lody, а Agent Config — среда выполнения за ней.
- Дополнения Lody — это уровень рабочего пространства: параллельные worktree, ревью, совместный доступ и оркестрация.
</Callout>

## Что остаётся прежним

- **Среда выполнения.** Lody запускает тот же процесс агента; платформа не подменяет модель и
  собственное поведение CLI.
- **Ваша аутентификация.** Lody использует авторизацию по подписке или конфигурацию окружения,
  которые уже настроены на машине. Подробнее см. в разделе [Agent Config](/ru/docs/quickstart).
- **Соглашения вашего репозитория.** `AGENTS.md`, `CLAUDE.md` и остальные инструкции проекта
  продолжают работать, потому что агент по-прежнему запускается в каталоге проекта.
- **Ваш терминал.** Для быстрой разовой задачи прямой запуск CLI по-прежнему остаётся отличным выбором.

## Сопоставление понятий

| К чему вы привыкли | В Lody | Примечания |
| --- | --- | --- |
| `claude` или `codex` в терминале | [Сессия](/ru/docs/session) с [Agent Config](/ru/docs/quickstart) | Та же среда выполнения плюс графический интерфейс, мобильный доступ и командный слой |
| Одна рабочая копия репозитория | Отдельный [worktree](/ru/docs/worktrees) на каждую сессию | Сессии больше не конфликтуют из-за одних и тех же файлов |
| Запрос и внесённые им правки | [Раунд](/ru/docs/diff-viewer) | Lody показывает diff после каждого раунда |
| `--resume` или `resume` | Повторное открытие сессии из боковой панели | Диалог, ветка и worktree остаются связанными |
| Ручной просмотр `git diff` | [Просмотр diff](/ru/docs/diff-viewer) и [комментарии к diff](/ru/docs/diff-comments) | Комментируйте строки и синхронизируйте их с PR в GitHub |
| Один терминал за раз | Несколько [параллельных сессий](/ru/docs/parallel-agents) | Каждая задача получает собственную ветку и worktree |
| Слэш-команды и режимы | Предоставляемые средой выполнения [слэш-команды](/ru/docs/slash-commands) | Lody определяет, какие команды поддерживает среда выполнения |
| Скриншоты или расшифровки диалога для команды | [Передача сессии](/ru/docs/session-handoff) | Пригласите коллегу прямо в активную сессию |

Какие дополнительные возможности ACP и расширений Lody поддерживает каждый встроенный провайдер,
смотрите в матрице [Поддержка функций ACP и расширений](/ru/docs/acp-feature-support).

## Чек-лист перехода

<Steps>
<Step>

### 1. Установите Lody и войдите в систему

Следуйте руководству [Быстрый старт](/ru/docs/quickstart). Вы можете начать с десктопного
приложения, мобильного приложения или CLI на удалённой машине.

</Step>
<Step>

### 2. Сохраните существующий способ входа

Откройте **Settings** -> **Agent Config** и добавьте конфигурацию для каждой среды выполнения,
которую используете. В большинстве случаев новые учётные данные не нужны: Lody использует
авторизацию по подписке или конфигурацию окружения, которые уже есть на машине.

</Step>
<Step>

### 3. Добавьте свои проекты

Добавьте [локальный проект](/ru/docs/local-project) для каталога, в котором вы уже работаете,
или подключите [репозиторий GitHub](/ru/docs/github) для pull request и CI. Если вы уже
запускали Codex или Claude Code в этом локальном проекте, Lody может импортировать и продолжить
существующую историю. Подробнее см. в разделе
[Синхронизация истории агентов](/ru/docs/local-project#sync-code-agent-history-codex-claude-code-and-more).

</Step>
<Step>

### 4. Запустите одну небольшую сессию

Пройдите [Ваша первая сессия](/ru/docs/first-session) с задачей, которую можно выполнить за один
подход в CLI. Убедитесь, что выбраны ожидаемые проект, Agent Config и модель.

</Step>
<Step>

### 5. Сохраните повторяющуюся конфигурацию

Если вы постоянно запускаете однотипные задачи с одной и той же машиной, конфигурацией, моделью
и инструкциями, сохраните их как [роль агента (Agent Role)](/ru/docs/agent-roles), чтобы не
выбирать все параметры заново каждый раз.

</Step>
<Step>

### 6. Подключайте уровень рабочего пространства по мере необходимости

Подключите GitHub для PR и CI, попробуйте [параллельные сессии](/ru/docs/parallel-agents) на двух
небольших задачах или пригласите коллегу с помощью [передачи сессии](/ru/docs/session-handoff).
Эти возможности можно внедрять постепенно, по одной.

</Step>
</Steps>

## Когда CLI по-прежнему подходит лучше

<Callout type="info" title="Оставьте терминал для подходящих задач">
Используйте CLI напрямую, когда нужно сделать одну быструю правку без истории ревью, когда вы
отлаживаете самого агента или на машине, где вы не хотите запускать демон Lody. Lody приносит
наибольшую пользу, когда задаче нужны worktree, удобный просмотр diff, участие коллеги или второе
устройство.
</Callout>

## Часто задаваемые вопросы

### Заменяет ли Lody CLI Codex или Claude Code?

Нет. Lody запускает эти и другие среды выполнения, добавляя вокруг них рабочее пространство.
CLI остаётся поддерживаемым способом работы, и на одной машине можно использовать оба варианта.

### Нужно ли переносить свои API-ключи или подписку?

Нет. В обычном сценарии Lody использует авторизацию по подписке или конфигурацию окружения,
уже настроенную на машине. Вы добавляете [Agent Config](/ru/docs/quickstart), чтобы Lody знал,
какую среду выполнения запускать; переносить учётные данные в Lody не нужно.

### Могу ли я продолжать использовать AGENTS.md и CLAUDE.md моего репозитория?

Да. Агент по-прежнему работает внутри вашего репозитория, поэтому файлы инструкций, которые он
уже читает, продолжают действовать.

### Как возобновить диалог, как в `codex resume` или `claude --resume`?

Откройте сессию из боковой панели. Lody хранит диалог, ветку и worktree вместе. Когда среда
выполнения поддерживает нативный форк, вы также можете создать
[форк](/ru/docs/session#fork-a-session), чтобы продолжить работу в новом направлении, не
изменяя исходную сессию. Подробнее см. в разделе [Сессии](/ru/docs/session).

### Могу ли я использовать Lody с телефона для той же самой сессии?

Да. Машина выполнения должна находиться в сети и быть авторизована в том же рабочем
пространстве Lody. Подробнее см. в разделе [Мобильный доступ](/ru/docs/mobile).
