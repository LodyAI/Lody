# Поддержка возможностей ACP и расширений

Эта страница предназначена для пользователей, переходящих с Codex, Claude Code или другого ACP-агента, которые хотят узнать, какие возможности сохраняются при переходе. Здесь объясняется, что такое ACP, как Lody расширяет этот протокол и что поддерживает каждый встроенный провайдер. Если вы ещё не подключили среду выполнения, начните с разделов
[Переход с Codex или Claude Code](/ru/docs/from-codex-claude-code) или [Конфигурация агента](/ru/docs/quickstart).

## Что такое ACP

[Agent Client Protocol](https://agentclientprotocol.com/) (ACP) — это открытый протокол взаимодействия между клиентом (приложением, которым вы пользуетесь) и агентом, выполняющим работу. Lody выступает в роли ACP-клиента. Он запускает ACP-сервер провайдера, согласовывает возможности на этапе `initialize`, а затем обменивается промптами, потоковыми обновлениями, вызовами инструментов, запросами разрешений и событиями жизненного цикла сессии по этому единому соединению.

ACP охватывает общее ядро, поэтому два ACP-агента всё равно могут отличаться по набору необязательных функций: изображения, встроенный контекст, возобновление или ветвление сессии, транспорты MCP, уточняющие запросы (elicitation) и другое. Именно поэтому Lody согласовывает возможности, а не исходит из предположений об их наличии. Базовый набор работает для каждого встроенного провайдера: текстовые промпты, потоковые обновления, вызовы инструментов, запросы разрешений, отмена операций, а также обратные вызовы Lody к файловой системе и терминалу.

## Как Lody расширяет ACP

Собственные возможности Lody описаны в [`acp-extension-core`](https://github.com/LodyAI/acp-extension-core) — независимом от провайдера контракте поверх ACP v1. Таким функциям, как потоковая передача событий субагентов, учёт использования ресурсов, лимиты запросов, долгосрочные цели и сжатие контекста, требуется стабильное общее описание, поэтому каждая из них версионируется и объявляется независимо в `_meta.lody`:

- агент объявляет реализуемые им возможности в `InitializeResponse.agentCapabilities._meta.lody`;
- клиент объявляет собственные возможности в `InitializeRequest.clientCapabilities._meta.lody`;
- отсутствие ключа означает, что вторая сторона не поддерживает эту функцию, а поддержка одной функции никогда не подразумевает поддержку другой.

Публичные адаптеры `acp-extension-*` преобразуют интерфейс каждой среды выполнения в этот контракт, благодаря чему клиент Lody получает единую структуру данных независимо от того, какой провайдер находится по ту сторону соединения. Пользовательский ACP-агент или агент из реестра может реализовать те же ключи. Точный формат полезных нагрузок описан в
[каталоге возможностей](https://github.com/LodyAI/acp-extension-core#capability-catalog).

### Справочник по возможностям расширений

Столбцы `Lody:` описывают возможности, которые объявляет провайдер. За каждым столбцом стоят следующие функции на стороне провайдера:

- **события субагентов** — адаптер передаёт в потоковом режиме снимки состояния, прогресс и вывод дочерних агентов по `_lody/subagents/event`.
- **заголовок сессии** — адаптер генерирует заголовок и отправляет его как стандартное обновление `session_info_update` с тегом `_meta.lody.titleSource`.
- **использование** — учёт контекста и токенов в стандартном `usage_update` с разбивкой итоговых значений по моделям.
- **лимиты** — снимки квот по `_lody/rate_limits/update` с необязательным запросом `_lody/rate_limits/get`.
- **ветвление от хода** — `session/fork` может указать исторический ход, от которого нужно выполнить ветвление.
- **корректировка (steering)** — дополнительные указания можно передавать в выполняющийся в данный момент ход через `_lody/session/steer` или `_meta.lody.steer`.
- **задачи** — фоновые или запланированные задачи, о которых сообщается в рамках обычного жизненного цикла вызова инструмента с помощью `_meta.lody.task`.
- **субагенты** — жизненный цикл субагента, а также необязательные запросы списка, отмены и вывода.
- **цель** — долгосрочная цель сессии, сохраняющаяся за пределами одного промпта, с действиями установки, приостановки, возобновления и очистки.
- **сжатие** — сжатие контекста и повторные попытки, передаваемые как жизненный цикл инструмента с `_meta.lody.activity`.

Примечания:

1. **Задачи:** Claude Code, Codex, Kimi Code и DeepSeek Harness объявляют фоновые задачи; Grok объявляет запланированные задачи. Ни один из них не объявляет оба типа сразу.
2. **Субагенты:** Claude Code и Codex объявляют только жизненный цикл, но не запросы списка, отмены или вывода.
3. **Задачи Grok** поддерживаются только как запланированные задачи.
4. **Заголовок сессии Kimi Code** объявляется только в том случае, если установленный движок Kimi поддерживает собственную функцию заголовков; в противном случае Lody генерирует заголовок самостоятельно.
5. **Ввод изображений в DeepSeek Harness** зависит от выбранной модели. Адаптер включает эту возможность только тогда, когда активная модель объявляет поддержку ввода изображений.
6. **MCP в Dimcode:** Dimcode объявляет поддержку Streamable HTTP и SSE, но сообщает, что stdio MCP не поддерживается.

В столбце `ACP: MCP` значение `HTTP+SSE` означает, что провайдер объявляет оба транспорта, а `HTTP` — что он объявляет только HTTP. Stdio MCP является обычной базовой возможностью ACP; исключение составляет Dimcode в примечании 6. Столбцы стандартного ACP для `Devin` и `Grok` отражают поведение их официальных сред выполнения, тогда как столбцы Lody показывают возможности, добавляемые прокси-слоем совместимости Lody. `Bub` и `Dimcode` — это внешние ACP-серверы, запускаемые Lody; их строки отражают то, что эти серверы объявляют самостоятельно, включая реализуемые ими расширения Lody.

Приведённая выше информация о поддержке отражает объявления возможностей, поставляемые с адаптерами Lody и внешними ACP-серверами. Lody считывает результат согласования при запуске сессии, поэтому обновление провайдера может изменить отображаемые в приложении возможности раньше, чем обновится эта страница. Независимое версионированное сравнение стандартных реализаций ACP см. в [ACP Wall](https://github.com/wibus-wee/acp-wall).
