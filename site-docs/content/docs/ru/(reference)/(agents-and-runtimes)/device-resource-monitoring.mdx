# Мониторинг ресурсов устройства

Lody может показывать текущее потребление ресурсов для каждого подключённого устройства и каждой
резидентной сессии ACP на нём. Используйте этот раздел, чтобы найти агента, который потребляет
CPU или память, открыть его сессию или остановить процесс ACP без удаления диалога.

Откройте **Настройки -> Устройства** и выберите устройство в сети. Страница начнёт собирать
показатели автоматически — кнопки ручного обновления нет.

## Что такое резидентная сессия ACP?

Каждый диалог использует процесс ACP для взаимодействия со своим агентом разработки. Этот процесс
может оставаться резидентным в памяти после перехода хода в режим простоя: это ускоряет следующий
ход, но продолжает занимать часть памяти. В таблице сессий ACP перечислены диалоги, чьи процессы
агентов в данный момент присутствуют на выбранном устройстве.

Это представление процессов, а не список всех сохранённых диалогов. Диалог, чей процесс ACP уже
остановлен, остаётся в Lody, но больше не отображается в этой таблице.

## Сводка по ресурсам

В верхней части страницы разделены три области учёта, чтобы их показатели нельзя было случайно сложить друг с другом:

| Область | CPU | Память |
| --- | --- | --- |
| **CLI** | Сам управляющий процесс Lody CLI | Память, используемая управляющим процессом Lody CLI |
| **Сессии ACP** | Суммарный CPU, используемый деревьями процессов резидентных сессий ACP | Суммарная память, используемая деревьями процессов резидентных сессий ACP |
| **Сведения об устройстве** | CPU, используемый всем устройством, включая Lody, агентов, ОС и другие приложения | Используемая память / эффективный общий объём памяти устройства |

**Сведения об устройстве — это не сумма показателей CLI и сессий ACP.** В них также учитываются все
остальные процессы на машине. Напротив, значения для CLI и ACP помогают определить, какая доля
нагрузки на устройство приходится именно на Lody.

### Процент загрузки CPU

Во всех трёх областях используется единое многоядерное соглашение:

- одно полностью загруженное логическое ядро CPU соответствует `100%`
- два полностью загруженных логических ядра — `200%`
- на 8-ядерном устройстве практический максимум для устройства составляет около `800%`

Например, сессия ACP, использующая 1,5 ядра, покажет `150%`. Небольшие расхождения между показателями
устройства, CLI, суммарными значениями и данными отдельных сессий возможны, поскольку замеры
собираются за короткие интервалы, а учёт деревьев процессов зависит от платформы.

### Память

Показатель памяти отражает текущее резидентное потребление, а не накопительный объём выделений. Точный
метод подсчёта зависит от операционной системы: Lody использует учёт через cgroup там, где он доступен,
а в остальных случаях измеряет соответствующее дерево процессов. В macOS отчётность по физическому
объёму памяти (physical footprint) может отличаться от значений, которые показывают инструменты,
суммирующие только RSS.

Значение для устройства отображается в формате **используется / эффективный общий объём**. Если Lody
работает в ограниченной среде, «эффективным общим объёмом» может быть лимит памяти контейнера или
cgroup, а не вся установленная оперативная память хоста. Из-за доступной памяти, кэшей, разделяемых
страниц и особенностей учёта на конкретной платформе сумма значений по строкам при ручном подсчёте
может отличаться от общего показателя устройства.

### Почему значение может отображаться как `-`

Потребление CPU вычисляется по разнице между двумя замерами, поэтому оно недоступно при первом замере
после запуска мониторинга или перезапуска CLI. Сессия также может показывать `-` для CPU, памяти или
числа процессов, если операционная система не может предоставить надёжные данные учёта по её дереву
процессов. Сначала дождитесь следующего автоматического замера; если значение по-прежнему недоступно,
убедитесь, что устройство в сети и на нём установлена актуальная версия Lody CLI.

## Таблица сессий ACP

Каждая строка соответствует одному резидентному диалогу:

| Столбец | Значение |
| --- | --- |
| **Сессия** | Название диалога, имя ACP и логотип ACP. Нажмите на строку, чтобы открыть соответствующую сессию и вкладку. Наведите курсор на обрезанное название, чтобы увидеть его полностью. |
| **Статус** | Текущее состояние жизненного цикла или активности ACP |
| **Память** | Текущий объём памяти, отнесённый к дереву процессов ACP этой сессии |
| **CPU** | Загрузка CPU этим деревом процессов, где одно полностью занятое логическое ядро равно `100%` |
| **Процессы** | Количество процессов, отнесённых в данный момент к сессии, включая отслеживаемые дочерние процессы |

В таблице отображается до 100 резидентных сессий. Измерения могут кратковременно отставать от создания
или завершения процессов, особенно на платформах, где Lody оценивает принадлежность по дереву процессов.

### Справочник статусов

| Статус | Значение |
| --- | --- |
| **Инициализация** | Lody запускает процесс ACP или подключается к нему |
| **Выполняется** | Агент активно обрабатывает ход |
| **Ожидание разрешения** | Агент приостановлен до получения ответа на запрос разрешения |
| **Завершение** | Агент закончил основную работу, и Lody выполняет финальную обработку |
| **Простой** | Процесс ACP резидентен, но в данный момент не обрабатывает ход |
| **Остановка** | Выполняется запрос на завершение процесса, и Lody ожидает его выхода |
| **Ошибка** | В резидентной сессии или её процессе ACP произошёл сбой |

## Освобождение ресурсов сессии ACP

Нажмите на значок остановки в конце строки сессии, чтобы завершить её процесс ACP. Остановка процесса
в состоянии простоя начинается без подтверждения. Если агент выполняется, инициализируется, ожидает
разрешения или завершает работу, Lody запросит подтверждение, поскольку активный ход будет прерван.

На значке остановки отображается индикатор загрузки до тех пор, пока процесс ACP не завершится и
мониторинг устройства не подтвердит, что сессия больше не резидентна. Если завершение не удалось,
Lody сообщит об ошибке и оставит сессию доступной для повторной попытки.

Завершение процесса ACP:

- останавливает текущий ход агента и его отслеживаемые дочерние процессы
- освобождает CPU и память, удерживаемые этим деревом резидентных процессов
- сохраняет историю диалога, метаданные сессии, ветку, worktree и файлы проекта
- не архивирует и не удаляет сессию, а также не освобождает занимаемое ею место на диске

Прерванная команда или запись в файл не откатываются автоматически. Проверьте файлы и diff сессии,
если вы завершили работу агента в момент, когда он активно вносил изменения.

## Продолжение диалога позже

Вы можете вернуться к остановленной сессии в любой момент и отправить новое сообщение. Lody снова
запустит процесс ACP и возобновит диалог из сохранённого контекста сессии. Первый новый ход может
занять больше времени, пока среда выполнения агента запускается и переподключается, но сам диалог
и файлы остаются доступными всё это время.

Локальное несохранённое состояние процесса исчезает при завершении процесса ACP. Долговременный
контекст обеспечивается сохранённым диалогом, поддержкой возобновления у агента и файлами в рабочей
области сессии. Используйте завершение процесса для освобождения CPU и памяти между периодами
активной работы; архивирование или удаление применяйте только тогда, когда нужно также изменить
видимость сессии или освободить место на диске. Подробнее об архивировании, восстановлении и удалении
см. в разделе [Сессии](/ru/docs/session).

## Оперативная отчётность по запросу

Мониторинг ресурсов намеренно сделан эфемерным:

- устройство в сети передаёт и обновляет снимки ресурсов только тогда, когда кто-то просматривает его страницу
- страница обновляется автоматически, пока остаётся открытой на экране
- снимки устаревают и не сохраняются в виде исторической ленты метрик
- когда никто не наблюдает за страницей, Lody прекращает запрашивать постоянные замеры ресурсов

Если устройство предоставлено для общего доступа в рабочем пространстве, участники с доступом к этому
устройству могут видеть текущую информацию о его ресурсах. Завершение процесса ACP на общем устройстве
затрагивает эту сессию для всех, поэтому проверяйте статус сессии перед тем, как остановить активный
ход другого участника. Монитор не является инспектором командной строки процессов и не заменяет
инструменты профилирования операционной системы.

Когда устройство не в сети, Lody не может запросить новый замер или завершить его процессы ACP.
Подключите CLI к сети, заново откройте **Настройки -> Устройства** и дождитесь первого замера.
