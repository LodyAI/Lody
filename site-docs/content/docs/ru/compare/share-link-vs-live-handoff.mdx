# Ссылка на сессию или живая передача

Два распространённых значения фразы «поделиться сессией» легко перепутать:

- **Ссылка на сессию** (как и скриншот, экспорт в Markdown или архив) — это **запись**. Другой человек сможет прочитать, что происходило; некоторые инструменты позволяют запустить *новый* прогон агента из этого контекста.
- **Живая передача** (live handoff) приглашает коллегу в **ту же** сессию агента разработки, чтобы он мог продолжить общение в чате, просматривать diff и работать в том же worktree.

Запись не является приглашением в живой диалог, живые diff или исходный рабочий каталог.

Инструкция и правила доступа: [Передача сессии агента разработки](/ru/docs/session-handoff). Командное рабочее пространство: [Командные функции](/ru/docs/team).

<Callout title="Определение">
Скриншот, стенограмма, ссылка на сессию или архив сессии не являются живой передачей. Просматривающие не присоединяются к вашей запущенной сессии и не наследуют исходный worktree. Для передачи требуется членство в рабочем пространстве, а также соблюдение правил общего доступа к машине и проекту со страницы передачи сессии — это не публичный URL, который может открыть кто угодно.
</Callout>

## Две разные задачи

| Задача | Что может сделать получатель | Та же живая сессия? |
| --- | --- | --- |
| Скриншот | Посмотреть изображение чата | Нет |
| Экспорт в Markdown / стенограмму | Вставить статичный текст в новый чат | Нет — он начинает заново |
| Ссылка на сессию в стиле ChatGPT | Прочитать снимок диалога | Нет |
| Инструменты ссылок / архивов (например, [Lore](https://lore.link/share) или [SpecStory](https://docs.specstory.com/cloud/session-sharing)) | Просмотреть отрендеренную ветку переписки или сохранённую историю либо ответвить этот контекст в **новый** запуск агента | Нет — зрители не присоединяются к запущенной сессии или исходному worktree |
| **Живая передача** | Открыть существующую [сессию](/ru/docs/session), продолжить общение, просматривать живые [diff](/ru/docs/diff-viewer) и продолжать работу в том же [worktree](/ru/docs/worktrees) | **Да** |

В Lody по-прежнему можно [скопировать диалог как Markdown](/ru/docs/copy-md), если вам нужна только запись. Копирование URL сессии без предоставления общего доступа к самой сессии также не даёт команде прав доступа — ссылка продолжает работать только для владельца.

Эта страница не является обзором каких-либо продуктов для создания ссылок на сессии. Lore и SpecStory упомянуты исключительно как примеры категории записей и архивов, уже указанной на странице передачи сессии.

## Что на самом деле представляет собой живая передача

В Lody коллега, который может открыть сессию, продолжает её из того же самого контекста:

- живой диалог, который уже ведёт агент
- diff файлов, созданные агентом
- worktree и ветка сессии
- та же [конфигурация агента](/ru/docs/agents), чтобы он мог отправить следующий запрос

Он открывает именно **эту** сессию — не ответвление (fork) и не совершенно новый чат. Создание fork копирует историю в **новую** сессию; используйте его, когда вам нужна приватная ветка диалога. Подробнее: [Создание форка сессии](/ru/docs/session#fork-a-session).

Передача сессии — это действие в рамках командного рабочего пространства. Другой человек уже должен быть его участником, а сама сессия видна команде только тогда, когда к машине (и локальному проекту, если он используется) открыт общий доступ. Пошаговая инструкция и особые случаи: [Передача сессии агента разработки](/ru/docs/session-handoff).

## Когда что использовать

| Цель | Что выбрать |
| --- | --- |
| Кому-то нужно только *прочитать*, что произошло | Скриншот, стенограмма, ссылка на сессию или архив |
| Вам нужна запись за пределами рабочего пространства | Скриншот, стенограмма, ссылка на сессию или архив |
| Вы запускаете *нового* агента на основе экспортированного контекста | Скриншот, стенограмма, ссылка на сессию или архив |
| Коллега должен продолжить **ту же** сессию агента разработки | **Живая передача** |
| Ему нужны текущие diff и тот же worktree (а не восстановленный из текста запрос) | **Живая передача** |
| Он уже является (или может стать) участником [рабочего пространства](/ru/docs/team) | **Живая передача** |

Чтобы запускать несколько изолированных сессий командой — с разными моделями и отдельными worktree — см. [Параллельные агенты для разработки](/ru/docs/parallel-agents). Это запускает дополнительные задачи, а не передаёт одну сессию.

## Права доступа

Передача сессии подчиняется тем же правилам, что и руководство по продукту. Эта страница не вводит отдельную модель прав для публичных ссылок.

| Элемент управления | Эффект |
| --- | --- |
| Членство в рабочем пространстве | Необходимо, чтобы кто-либо мог открывать командные сессии |
| Роль участника | Владельцы и администраторы управляют тем, кто может приглашать, изменять или удалять участников — см. [Изменение прав участников](/ru/docs/team#change-member-permissions) |
| Общий доступ к машине | Сессии на машине без общего доступа не появляются на боковых панелях других участников. Открыть доступ может только владелец устройства. |
| Общий доступ к локальному проекту | Для локального проекта коллегам требуется разрешение на доступ как к проекту, так и к машине |
| URL сессии | Доступен владельцу всегда; коллегам — только после того, как сессия станет видимой для команды. Копирование URL — это не то же самое, что **Share with team…** |

Присоединение к рабочему пространству **не** открывает доступ к вашему ноутбуку. Машины остаются приватными, пока вы сами не откроете к ним доступ. Предоставление доступа к сессии может открыть доступ к её машине и/или локальному проекту для всех участников рабочего пространства; при этом другие диалоги на этом устройстве также могут стать видимыми. Подробнее: [Видимость машин в команде](/ru/docs/team#team-machine-visibility).

## Часто задаваемые вопросы

### Является ли ссылка на сессию тем же самым, что и передача сессии агента разработки?

Нет. Ссылка на сессию, скриншот, стенограмма или архив — это **запись для просмотра**. Человек может её прочитать, а в некоторых сценариях — запустить *нового* агента из этого контекста. Но он не присоединяется к исходной живой сессии и не получает исходный worktree. Живая передача открывает существующую сессию рабочего пространства, чтобы коллега мог продолжить её.

### Может ли коллега продолжить мою сессию Claude Code по ссылке на сессию?

Не по стенограмме, снимку в стиле ChatGPT или просмотрщику архива. Если сессия запущена в рабочем пространстве Lody, пригласите коллегу, откройте общий доступ к сессии (и к нужной машине или локальному проекту), а затем попросите его открыть именно **эту** сессию. Подробнее: [Передача сессии агента разработки](/ru/docs/session-handoff).

### В чём разница между отправкой стенограммы и совместной работой в реальном времени?

Отправка стенограммы — это передача записи. Совместная работа в реальном времени означает, что коллега находится в той же самой сессии: тот же чат, те же diff, тот же worktree. Экспорт в Markdown или копирование URL не предоставляют такой доступ.

### Что делать, если мне нужно отправить только стенограмму?

Скопируйте сообщение или выберите **Copy as Markdown** в меню сессии. Это не даёт доступа к живой сессии. См. [Копирование диалогов](/ru/docs/copy-md).

### Почему коллега не может открыть отправленный мной URL сессии?

Копирование URL сессии не открывает к ней общий доступ. Коллега должен быть участником рабочего пространства, к машине (и локальному проекту, если он есть) должен быть открыт общий доступ, а искать задачу ему нужно в разделе **All Tasks**, а не **My Tasks**. Машины без общего доступа никогда не синхронизируют свои диалоги с боковыми панелями других участников.
