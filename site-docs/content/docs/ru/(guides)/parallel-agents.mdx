Lody — это командное рабочее пространство для **мультиагентной разработки**: вы запускаете
сразу несколько сессий агентов для разработки, каждая со своей историей общения. Когда сессия
использует [worktree](/ru/docs/worktrees) — для GitHub это происходит всегда, а для локальных
проектов доступно как опция — она также получает собственный рабочий каталог, поэтому агенты
могут изменять файлы параллельно и не конфликтовать друг с другом.

Запускайте несколько сессий Claude Code или используйте Claude Code одновременно с Codex, Kimi,
Grok, DeepSeek или другой средой выполнения [ACP](/ru/docs/cli-runtimes). Чтобы агенты могли
делегировать задачи, обмениваться контекстом и проверять изменения друг друга, воспользуйтесь
[руководством по совместной работе агентов](/ru/docs/agent-collaboration/).

См. также: [Конфигурация агента](/ru/docs/quickstart), [Командные функции](/ru/docs/team),
[Передача сессии агента разработки](/ru/docs/session-handoff) и
[Управление сессиями агентов](/ru/docs/session-orchestration). Ссылка на сессию — это статичная
запись, а не живое продолжение работы: подробнее см. в разделе
[Ссылка на сессию или передача управления](/ru/docs/compare/share-link-vs-live-handoff).

## Изолированные worktree

Когда вы создаёте сессию с использованием worktree, Lody:

1. Создаёт ветку (по умолчанию `session/<shortSessionId>`)
2. Переключается на неё в выделенном worktree
3. При необходимости запускает скрипт настройки проекта
4. Передаёт изменения файлов в интерфейс сессии в реальном времени

Агенты в разных сессиях не имеют общего рабочего каталога, поэтому незакоммиченные правки
остаются привязанными к той задаче, в рамках которой были сделаны. Вы можете просмотреть
изменения, отменить их или открыть PR отдельно для каждой сессии.

<Callout title="Назначения при создании Fork">
[Fork](/ru/docs/session#создание-форка-сессии) копирует историю переписки в **новую** сессию. Вариант
**Current workspace** (и Side Chat) остаётся в исходном каталоге. Если доступен вариант
**New worktree**, такое ответвление создаёт независимую сессию от последнего закоммиченного
состояния `HEAD` — используйте его, когда нужна изоляция без потери контекста беседы. Если вам
нужна новая изолированная задача без копирования истории, запустите новую сессию с главной
страницы.
</Callout>

Подробнее: [Worktrees](/ru/docs/worktrees).

## Несколько агентов в одном рабочем пространстве

Для каждой сессии в окне ввода запроса можно выбрать собственную
[конфигурацию агента](/ru/docs/quickstart), модель и набор разрешений. Вы можете запускать:

- Claude Code или Codex через авторизацию по подписке на этой машине
- Kimi Code, DeepSeek Harness и другие встроенные или совместимые с Claude конфигурации
- Любую среду выполнения из [реестра ACP](/ru/docs/cli-runtimes) или собственную команду запуска ACP

Если вы часто используете одно и то же сочетание машины, конфигурации, модели и разрешений,
сохраните его как [роль агента (Agent Role)](/ru/docs/agent-roles).

Максимальное число одновременно запущенных сессий зависит от ресурсов хост-машины и того,
за сколькими диалогами вы можете эффективно следить — см.
[Рекомендуемый рабочий процесс](/ru/docs/workflow).

## Видимость для команды

Параллельная работа идёт проще, когда вся команда видит, какие задачи уже запущены.

- На главной странице фильтр боковой панели по умолчанию установлен на **All Tasks**. Если
  кто-то видит только свои сессии, переключите фильтр с **My Tasks** на **All Tasks** (в
  мобильном приложении — **Team Tasks**). Аватары показывают, кто запустил каждую сессию.
- Машины остаются **приватными по умолчанию**. Предоставьте общий доступ к машине (или
  используйте **Share with team…** в сессии), если коллеги должны иметь возможность открывать эти
  диалоги.
- Чтобы подключить коллегу *внутрь* уже существующей сессии — к тем же чату, diff и worktree —
  следуйте инструкции [Передача сессии агента разработки](/ru/docs/session-handoff).

Участники, роли и общий доступ к машинам: [Командные функции](/ru/docs/team).

## Координация из одного диалога

В большинстве случаев для параллельной работы достаточно запускать сессии вручную. Если же вы
хотите, чтобы один агент сам разделил задачу, попросите его использовать
[Управление сессиями агентов](/ru/docs/session-orchestration): создавать или переиспользовать
диалоги, проверять их статус, отправлять уточнения и собирать результаты. Делегированные диалоги
могут выполняться параллельно, пока целевая машина находится в сети.

## Практическое разделение задач

Из [рекомендуемого рабочего процесса](/ru/docs/workflow):

1. Разбейте работу на небольшие функции или исправления.
2. Запускайте по одному диалогу с главной страницы на каждую задачу (обычно один PR).
3. Просматривайте [diff](/ru/docs/diff-viewer) в реальном времени по мере работы каждого агента.
4. Для проектов на базе GitHub создайте PR прямо из сессии, когда изменения будут готовы.
5. [Архивируйте](/ru/docs/session#архивирование-сессий) сессию после завершения работы, чтобы освободить
   её worktree.

## Часто задаваемые вопросы

### Это командная функция Claude Code?

Нет. Claude Code — это лишь одна из [конфигураций агента](/ru/docs/quickstart), которую можно
запустить в Lody. Рабочее пространство, изолированные worktree и командный список сессий
обеспечивает сама платформа Lody. Вы можете запускать несколько сессий Claude Code или
комбинировать Claude Code с Kimi, DeepSeek, Codex и другими ACP-агентами.

### Могут ли параллельные агенты перезаписать файлы друг друга?

Нет, если у каждой задачи есть собственный [worktree](/ru/docs/worktrees) — в том числе при
создании fork с параметром **New worktree** или запуске новой сессии с главной страницы.
Ответвления **Current workspace** и Side Chat используют общий каталог с исходной сессией,
поэтому агенты в них видят изменения файлов друг друга. Fork с параметром **New worktree**
стартует от закоммиченного состояния `HEAD`, а незакоммиченные правки остаются в исходной
сессии.

### Видят ли коллеги по команде всех запущенных агентов?

Они видят сессии на машинах (и в локальных проектах), к которым открыт общий доступ для рабочего
пространства — достаточно переключить фильтр на главной странице на **All Tasks**, если выбран
**My Tasks**. Машины без общего доступа никогда не синхронизируют свои диалоги в боковые панели
других участников. Подробнее см. в разделе [Командные функции](/ru/docs/team).

### Может ли один агент запускать других?

Да, с помощью [Управления сессиями агентов](/ru/docs/session-orchestration). Попросите агента в
одном диалоге создать узконаправленные сессии, обмениваться сообщениями с другими агентами,
отправлять им уточнения и подводить итоги. Эта возможность ограничена данными диалогов Lody —
это не универсальный фоновый планировщик.

### Когда стоит передать сессию вместо запуска нового агента?

Запускайте новую сессию, если вам нужна **новая** изолированная задача.
[Передавайте сессию](/ru/docs/session-handoff), когда коллега должен **продолжить** работу в уже
существующей сессии.
