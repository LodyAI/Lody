# Рекомендуемый рабочий процесс

В Lody [интеграция с GitHub](/ru/docs/github) и [Worktrees](/ru/docs/worktrees) сейчас являются базовыми возможностями, поэтому мы рекомендуем использовать их как рабочий процесс по умолчанию.

Перед началом работы выполните [быструю настройку](/ru/docs/quickstart).

## Разбивайте работу на небольшие задачи

Поскольку у агентов есть ограничения на размер контекста, параллельный запуск нескольких небольших задач обычно работает лучше, чем выполнение одной крупной и сложной задачи в рамках одного диалога. Перед началом работы разделите задачу на атомарные функции или исправления. Это позволит использовать изоляцию файлов на уровне worktree для параллельной разработки и сократит время ожидания.

## Параллельная разработка

После разбиения требований опишите в поле ввода на главной странице по одной функции или исправлению для каждого диалога. В этом рабочем процессе один диалог соответствует одной функции или исправлению — как правило, одному PR. Вы можете запускать столько параллельных диалогов, сколько позволяют ресурсы вашей машины и ваша способность переключаться между контекстами. Подробнее о продуктовой модели, лежащей в основе этого подхода — изолированных worktree, сочетании разных агентов и видимости для команды — читайте в разделе [Параллельные агенты программирования](/ru/docs/parallel-agents).

Когда Lody завершает раунд, он отправляет [уведомление](/ru/docs/notification). Нажатие на уведомление переводит вас к соответствующей сессии. Если вам удобно читать код, проверьте изменённые файлы прямо в Lody. Если нет — скопируйте имя ветки под этой сессией на левой боковой панели и переключитесь на неё в вашей привычной среде разработки для сквозного тестирования.

Когда результат в целом готов, нажмите **Create PR** над диалогом. Lody создаст PR с полным описанием требований и сводкой по реализации и привяжет его к диалогу. После этого вы сможете нажать на кнопку привязанного PR, чтобы сразу перейти к нему на GitHub.

## Цикл ИИ-ревью

Если вы подключите к своему репозиторию Claude Code, Codex, Devin или аналогичные инструменты, они смогут подробно проверять каждый PR. Когда появятся комментарии к ревью, вы можете написать Lody примерно следующее:
`Fetch PR comments, evaluate whether each point is valid, fix valid issues and mark them resolved, otherwise reply with reasoning.`
Lody получит комментарии к PR, оценит их, внесёт исправления и отправит новый коммит. Это запустит следующий раунд ИИ-ревью (автоматически или вручную через `@`), и так до тех пор, пока не останется очевидных проблем.

## Архивируйте завершённые сессии

После слияния PR сессия выполнила свою задачу. Если не обнаружится связанная с ней ошибка, мы не рекомендуем продолжать в той же сессии работу над другими задачами. Используйте [действие архивирования](/ru/docs/session#archive-sessions) на боковой панели, чтобы убрать завершённые сессии из списка активных.

Архивирование позволяет освободить управляемый каталог worktree, сохраняя при этом диалог и локальную ветку. Предварительно сохраните нужные игнорируемые файлы за пределами worktree; подробнее см. в разделе [Хранение и восстановление worktree](/ru/docs/worktrees#automatic-cleanup).

## Периодически удаляйте архивированные сессии

Когда диалог вам больше не нужен, [удалите архивированную сессию](/ru/docs/session#delete-sessions), чтобы безвозвратно стереть её историю. Это действие не удаляет сохранённую локальную ветку Git и её резервные коммиты и не предназначено для полного освобождения дискового пространства репозитория.

## Проекты не на GitHub

Этот рабочий процесс лучше всего подходит для проектов, размещённых на GitHub. Для проектов, не связанных с GitHub, добавьте каталог как [локальный проект](/ru/docs/local-project). Локальные проекты по-прежнему поддерживают чат, список файлов, просмотр diff, мобильный доступ и Lody Preview, однако автоматизация PR и CI, специфичная для GitHub, в них недоступна.
