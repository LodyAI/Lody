# Подключение Magpie

Magpie подключается к провайдерам моделей. Lody создаёт конфигурации агентов. Храните API-ключи вышестоящих провайдеров в Magpie — копировать их в Lody не нужно.

## Перед началом работы

- Запустите Magpie и демон Lody на **одном и том же сервере**, при этом в Magpie должна быть включена хотя бы одна модель.
- Войдите в Lody и подключите сервер к вашему рабочему пространству. См. [вход через CLI](/ru/docs/cli#core-commands).
- Используйте версию Lody CLI с поддержкой `import-magpie`. Эти команды работают с облачными рабочими пространствами, а не с локальным режимом OSS.

На сервере проверьте поддержку команды, запустите демон и найдите ваше рабочее пространство:

```bash
lody agent-config import-magpie --help
lody daemon start
lody workspace list
```

Пропустите запуск демона, если он уже запущен. Замените `my-team` ниже на ID, название или slug вашего рабочего пространства.

## Импорт всех провайдеров

```bash
lody agent-config import-magpie --workspace my-team --json
```

По умолчанию команда подключается к `http://127.0.0.1:3425` и импортирует семь провайдеров:

| Значение `--targets` | Название конфигурации |
| --- | --- |
| `claude` | Claude-magpie |
| `codex` | Codex-magpie |
| `pi` | Pi-magpie |
| `dsh` | DSH-magpie |
| `kimi` | Kimi Code-magpie |
| `grok` | Grok-magpie |
| `bub` | Bub-magpie |

Команда выполняет импорт только на **машину, на которой она запущена**. Параметра `--machine` нет. Адрес `127.0.0.1` относится к этому серверу, а не к вашему компьютеру.
Для Bub требуются заранее установленная команда `bub acp` и плагин ACP.

### Выбор агентов

Перечислите нужные цели через запятую. Например, чтобы импортировать только Pi и Codex:

```bash
lody agent-config import-magpie --workspace my-team --targets pi,codex --json
```

### Использование другого порта или ссылки для импорта

Если Magpie работает на другом порту, передайте корневой URL шлюза без `/v1`:

```bash
lody agent-config import-magpie --workspace my-team --gateway http://127.0.0.1:4000 --json
```

Если у вас есть ссылка для импорта из Magpie, передайте её целиком:

```bash
lody agent-config import-magpie --workspace my-team --link 'lody://provider/import?v=1&data=…' --json
```

Используйте либо `--link`, либо `--gateway`, но не оба параметра одновременно. При использовании ссылки по умолчанию выбираются все цели, предлагаемые этой ссылкой; параметр `--targets` позволяет выбрать только из них.
Шлюз должен использовать локальный loopback-адрес HTTP: `127.0.0.1`, `localhost` или `[::1]`.

## Чтение результата

В JSON-массиве `providers` для каждой цели указаны `agentConfigId` и `status`:

| Статус | Значение |
| --- | --- |
| `queued` | Настройка сохранена; демон установит или проверит среду выполнения |
| `preparing-runtime` / `verifying` | Существующая настройка подготавливается или проверяется |
| `awaiting-auth` | Существующая настройка требует аутентификации |
| `created` | Конфигурация сохранена; запросы к моделям ещё не проверены |
| `existing` | Конфигурация для этого шлюза и типа агента уже существует и сохранена без изменений |

Отслеживать ход настройки можно на странице **Провайдеры** (Providers) в Lody. Когда всё будет готово, выберите этого провайдера на сервере при создании сессии.
Успешный импорт не гарантирует, что инференс на стороне вышестоящего провайдера работает. Отправьте сообщение, чтобы проверить это.

Значение `synced: false` означает, что конфигурация сохранена локально, но синхронизация с рабочим пространством не подтверждена. Восстановите подключение и повторите импорт.

Повторный импорт сохраняет существующие конфигурации и перезапускает неудачные настройки с их исходной конфигурацией.
Если Pi не поддерживается, обновите Lody на сервере и перезапустите его демон или исключите `pi` с помощью `--targets`.

## Обновление моделей и конфигурации

Управляйте моделями в Magpie. Lody считывает актуальный каталог при последующих запусках; уже запущенные сессии автоматически не обновляются.
Сгенерированной нативной конфигурацией управляет Lody. Ручные правки могут быть перезаписаны при следующем запуске.

На десктопе открытие существующей ссылки для импорта из Magpie вызывает диалоговое окно подтверждения и выполняет импорт на эту десктопную машину. Чтобы выполнить импорт на сервер, запустите приведённые выше команды непосредственно на сервере.
