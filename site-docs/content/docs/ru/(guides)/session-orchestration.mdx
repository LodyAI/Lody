# Управление сессиями из агента

Агенты Lody могут использовать встроенные инструменты Lody MCP для работы в нескольких диалогах. Это позволяет попросить одного агента разбить задачу на отдельные специализированные диалоги, проверять их прогресс, отправлять дополнительные инструкции и возвращать готовые результаты в исходный диалог.

Самостоятельный запуск нескольких сессий — с изолированными worktree, разными моделями и видимостью для команды — описан в разделе [Параллельные агенты программирования](/ru/docs/parallel-agents). На этой странице рассматривается сценарий управления: один агент координирует остальных.

Подробный разбор сценария с основным агентом, Kimi, Codex и Grok — включая упоминания диалогов и работу на разных машинах — приведён в руководстве [Сценарии совместной работы агентов](/ru/docs/agent-collaboration/).

## Использование в диалоге

Опишите ожидаемый результат и распределение работы в обычном запросе. Например:

```text
Create two review conversations for this project: one for correctness and one for test coverage.
When both finish, summarize the findings here.
```

Агент может создавать или переиспользовать диалоги, проверять их статус и ограниченную историю, отправлять дополнительные инструкции или при необходимости отменять выполняющийся ход. Результаты возвращаются в исходный диалог после того, как запрошенная работа переходит в завершённое состояние.

При создании новой сессии агент также может выбирать совместимую модель и параметры уровня рассуждений из доступных на целевой машине. Укажите эти предпочтения в своём запросе, если они важны, например:

```text
Create a review session with Codex using the high reasoning setting, then summarize the findings here.
```

## Координация PR, issue и исправлений в нескольких репозиториях

### Использование Claude Code в роли координатора

Попросите Claude Code проанализировать набор PR или issue, определить зависимости и затем поручить конкретные задачи другим агентам, таким как Kimi, Codex или Grok. Каждый агент работает в собственном диалоге, а координатор может запрашивать уточнения и собирать результаты. Доступ к репозиториям осуществляется с помощью инструментов и учётных данных, доступных самим агентам.

```text
Go through these PRs and issues, group related work, and identify dependencies.
Delegate independent fixes to Kimi and reviews to Codex in separate conversations.
Collect their findings and report which changes are ready for my review.
```

### Исправление ошибки в нескольких репозиториях

Если ошибка затрагивает клиент, SDK и сервер, создайте отдельный диалог для каждого затронутого репозитория. Агенты могут параллельно исследовать проблему и вносить независимые изменения, обмениваться выводами об общем контракте и координировать зависимые правки.

```text
Investigate this bug across the client, SDK, and server repositories.
Start a focused Agent conversation for each repository. Have them exchange findings
and agree on the interface changes before implementing dependent fixes.
Collect the patches and verification results here.
```

### Цикл ревью и исправлений между агентами

Агенты могут отправлять сообщения и делегировать задачи в другие доступные диалоги Lody. Вы также можете попросить одного агента напрямую написать другому: например, поручить агенту-ревьюеру проверить конкретный коммит, передать замечания агенту-разработчику, а затем повторно проверить обновлённый коммит после исправления.

```text
Ask the review Agent to inspect the implementing Agent's current commit without editing it.
Send actionable findings to the implementing Agent and ask it to fix them.
Have the reviewer check the updated commit. Stop after two rounds, or earlier if no findings remain,
and summarize the result for me.
```

Эти примеры описывают рабочие процессы, которые вы можете запросить у агента, а не преднастроенные пайплайны. Явно указывайте целевые репозитории, область работ, критерии завершения и ограничение на число раундов ревью. Параллельно выполненные изменения всё равно требуют интеграционных проверок перед слиянием.

## Особенности работы

- Каждый диалог остаётся независимой задачей со своей историей и активным ходом.
- Задачи могут выполняться параллельно, если целевая машина находится в сети.
- Lody сохраняет связь с исходным диалогом, поэтому агент может продолжить работу после завершения делегированной задачи.
- Временные диалоги можно отправить в архив из списка сессий после завершения работы.

## Ограничения

Управление сессиями намеренно ограничено: агент может просматривать только данные диалогов, принадлежащих Lody, и не может использовать этот механизм как неограниченный фоновый планировщик. Делегированная задача может завершиться уже после запрошенного крайнего срока; её результат всё равно сохранится в соответствующем диалоге, даже если инициатор уже получил ответ об истечении времени ожидания.

Чтобы передать активную сессию коллеге вместо координации других агентов, обратитесь к разделу [Совместный доступ к сессии агента](/ru/docs/session-handoff).
