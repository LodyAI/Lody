# 첫 번째 세션

[빠른 시작](/ko/docs/quickstart)에서는 Lody를 설치하고 연결하는 방법을 다룹니다. 이 페이지에서는 그다음 단계인
빈 컴포저(입력창)에서 시작해 결과를 검토하기까지, 하나의 세션을 처음부터 끝까지 완주하는 과정을 설명합니다.
여기에 나오는 모든 내용은 GitHub 없이도, 여러 에이전트를 동시에 실행하지 않아도 로컬 프로젝트만으로 동작합니다.

<Callout type="info" title="시작하기 전에">
- Lody가 설치되어 있고 로그인한 상태여야 합니다. 아직이라면 [빠른 시작](/ko/docs/quickstart)을 먼저 진행하세요.
- 프로젝트를 하나 추가해 두어야 합니다. 일반 로컬 디렉터리여도 괜찮습니다. [로컬 프로젝트](/ko/docs/local-project)를 참고하세요.
- 해당 머신에서 **Test**를 통과한 Agent Config가 하나 있어야 합니다. [Agent Config](/ko/docs/quickstart)를 참고하세요.
</Callout>

## 한 세션에 알맞은 작은 작업 고르기

세션은 하나의 작업에 대해 하나의 에이전트와 나누는 하나의 대화입니다. 작업 규모가 작으면
결과를 빠르게 검토할 수 있고, 에이전트도 작업을 끝까지 마칠 충분한 컨텍스트를 유지할 수 있습니다. 첫 세션에 적합한 작업 예시는 다음과 같습니다.

- "앱 버전을 반환하는 `/health` 엔드포인트를 추가해 주세요."
- "`src/parser.test.ts`에서 실패하는 테스트를 수정하고 원인을 설명해 주세요."
- "패키지 전체에서 `fetchUser`의 이름을 `getUser`로 바꾸고 호출부도 업데이트해 주세요."

첫 세션부터 기능 영역 전체를 한꺼번에 요청하지 마세요. 하나의 세션으로 감당하기 어려울 만큼 작업이 커지면
[권장 워크플로](/ko/docs/workflow)에서 작업을 나누는 방법을 확인할 수 있습니다.

<Callout title="하나의 세션, 하나의 작업" type="idea">
이 문서의 나머지 내용도 이 습관을 바탕으로 합니다. 한 세션에서 서로 관련 없는 두 가지 일을 하기 시작했다면,
기존 세션을 계속 이어 나가기보다 작업을 멈추고 두 번째 세션을 새로 시작하세요.
</Callout>

## 한 세션 단계별로 살펴보기

<Steps>
<Step>

### 1. 홈 페이지 컴포저에서 시작하기

Lody를 열고 홈 페이지의 컴포저를 사용하세요. 메시지를 보내기 전에 다음 항목을 선택합니다.

- **프로젝트**(Git 프로젝트인 경우 브랜치 포함)
- **Agent Config**와 **모델**
- 원하는 **권한 범위**

그런 다음, 수정할 파일이나 동작, 그리고 성공 여부를 판단할 기준을 포함해 작업을 작성하세요.

```text
Add a /health endpoint that returns { "status": "ok", "version": <package version> }.
Add one test that asserts the status and version fields. Do not change other routes.
```

</Step>
<Step>

### 2. 라운드 지켜보기

Lody가 세션을 생성하고 에이전트의 작업 과정을 실시간으로 스트리밍합니다. **라운드(round)**는 하나의 에이전트 턴과
그 과정에서 생성된 파일 변경 사항을 합친 단위입니다. 라운드가 실행되는 동안 다음 작업을 할 수 있습니다.

- 작업이 끝날 때까지 기다리지 않고 후속 메시지를 보내 실행 중인 작업의 방향을 [**조정(steer)**](/ko/docs/claude-codex-capabilities#steer-a-running-task)하기
- 에이전트가 네이티브 포크(forking)를 지원하는 경우, 기본 작업을 중단하지 않고 [**Side Chat**](/ko/docs/session#right-sidebar-browser-and-side-chat)에서 질문하기
- 에이전트가 잘못된 방향으로 가고 있다면 현재 턴을 중지하기

</Step>
<Step>

### 3. diff 검토하기

라운드가 끝나면 응답에 변경된 파일과 추가·삭제된 줄 수가 표시됩니다.
파일을 클릭해 [diff 탭](/ko/docs/diff-viewer)에서 열거나, **Files** 및 **Changes** 사이드바를 사용해
대화 전체의 변경 내역을 살펴볼 수 있습니다.

</Step>
<Step>

### 4. 다음 라운드 요청하기

같은 세션에서 계속 진행합니다. 각 후속 요청은 한 가지 작업에만 집중하도록 작성하세요.

```text
The test passes, but the version is read from package.json at request time.
Read it once in a module constant instead, and keep the response shape the same.
```

작업에 필요한 만큼 "지켜보기, 검토하기, 후속 요청하기" 과정을 반복할 수 있습니다. 대화가 길어지거나
에이전트가 맥락을 놓치기 시작하면, 간단한 요약과 함께 새 세션을 시작하는 편이 좋습니다.

</Step>
<Step>

### 5. 결과 처리 방법 결정하기

변경 사항이 만족스럽다면 다음 중 하나를 선택할 수 있습니다.

- **브랜치 유지하기.** 세션에서 현재 브랜치 이름을 복사해 사용 중인 에디터에서 직접 테스트하거나 푸시합니다.
- **로컬에서 열기.** 데스크톱 앱에서는 **Open in**을 사용해 사용 중인 에디터에서 worktree를 바로 엽니다.
- **Pull Request 생성하기.** GitHub 세션인 경우 대화 상단의 **Create PR**을 사용합니다. Lody가
  PR을 세션에 다시 연결하고 CI 상태를 동기화합니다. 이것이 [권장 워크플로](/ko/docs/workflow)의 시작점입니다.
- **세션 보관(Archive)하기.** 작업이 끝나면 사이드바에서 세션을 보관합니다. 보관하면 worktree 공간은
  회수되지만 브랜치와 대화 내용은 유지되므로 나중에 다시 복원할 수 있습니다.
  [세션 보관](/ko/docs/session#archive-sessions)을 참고하세요.

</Step>
</Steps>

## 첫 세션에서 자주 하는 실수

<Accordions>
<Accordion title="한 번에 너무 많은 작업을 요청하기">
여러 요구사항이 섞인 긴 프롬프트는 에이전트 작업과 코드 리뷰를 모두 어렵게 만듭니다. 각 세션이 검토 가능한
하나의 변경 사항만 만들도록 작업을 나누세요. [병렬 코딩 에이전트](/ko/docs/parallel-agents)를 참고하세요.
</Accordion>
<Accordion title="프로젝트나 Agent Config를 선택하지 않기">
프로젝트가 비어 있거나 잘못 선택되어 있으면 에이전트가 엉뚱한 디렉터리에서 작업하게 됩니다. 메시지를 보내기 전에
컴포저에서 프로젝트, 브랜치, Agent Config, 모델을 꼭 확인하세요.
</Accordion>
<Accordion title="마지막에만 한꺼번에 검토하기">
라운드 단위의 diff는 부담 없이 읽고 코멘트를 남기기 좋습니다. 매 라운드마다 검토하면 잘못된 방향의 수정이
전체 변경 사항으로 번지는 것을 막을 수 있습니다.
</Accordion>
<Accordion title="완료한 세션을 보관하지 않기">
완료된 세션도 계속 worktree를 유지합니다. 작업이 병합되거나 중단되었다면 세션을 보관해
머신의 디스크 공간을 회수하세요.
</Accordion>
</Accordions>

## 자주 묻는 질문

### 첫 세션에 GitHub가 필요한가요?

아니요. GitHub를 연결하면 Pull Request, CI 상태, 리뷰 코멘트 동기화 기능을 함께 쓸 수 있지만, 로컬 프로젝트 세션만으로도
대화, 파일 편집, diff 확인, 변경 사항 검토까지 모두 독립적으로 진행할 수 있습니다.
[로컬 프로젝트](/ko/docs/local-project)를 참고하세요.

### "라운드(round)"란 무엇인가요?

라운드는 하나의 에이전트 턴과 그 동안 생성된 파일 변경 사항을 뜻합니다. Lody는 각 라운드를 diff로 요약해 주므로,
마지막에 커다란 diff 하나를 한꺼번에 읽는 대신 단계별로 계속 검토할 수 있습니다.
[Diff 뷰어](/ko/docs/diff-viewer)를 참고하세요.

### 에이전트가 요청하지 않은 부분을 수정했다면 어떻게 해야 하나요?

해당 파일의 diff를 열어 코멘트를 남기거나 같은 세션에서 후속 요청을 보내 에이전트가 바로잡도록 하세요.
작업과 무관한 변경 사항이라면 되돌려 달라고 요청해 세션의 초점을 유지하는 것이 좋습니다.

### 실행 중인 세션을 중지할 수 있나요?

네. 컴포저의 중지 버튼을 사용해 현재 실행 중인 턴을 취소할 수 있습니다. 중지된 세션은 목록에 그대로 남아 있으며,
새 메시지를 보내 이어서 진행할 수 있습니다.

### 보관된 세션은 어디로 이동하나요?

사이드바 오른쪽 하단의 보관함 목록으로 이동합니다. 대화 내용과 브랜치는 그대로 보존되며,
세션을 복원하면 worktree가 다시 생성됩니다. [세션 보관](/ko/docs/session#archive-sessions)을 참고하세요.
