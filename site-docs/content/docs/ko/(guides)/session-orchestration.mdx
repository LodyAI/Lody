# 에이전트 세션 제어

Lody 에이전트는 기본 제공되는 Lody MCP 도구를 사용해 여러 대화를 넘나들며 작업할 수 있습니다. 이를 통해 하나의 에이전트에게 작업을 목적별로 나눈 여러 대화로 분할하고, 각 진행 상황을 확인하며, 후속 작업을 지시하고, 완료된 결과를 원래 대화로 다시 모아 오도록 요청할 수 있습니다.

격리된 워크트리(worktree), 혼합 모델 사용, 팀 공개 설정 등 여러 세션을 직접 시작하는 방법은 [병렬 코딩 에이전트](/ko/docs/parallel-agents)에서 다룹니다. 이 페이지에서는 제어 흐름, 즉 하나의 에이전트가 다른 에이전트들을 조율하는 방법을 설명합니다.

기본 에이전트와 Kimi, Codex, Grok을 함께 활용하는 전체 과정(대화 멘션 및 여러 머신에 걸친 작업 포함)은 [에이전트 협업 워크플로](/ko/docs/agent-collaboration/)를 참고하세요.

<Callout title="어떤 페이지를 보면 되나요?">
  - 여러 작업을 직접 시작하려면 → [병렬 코딩 에이전트](/ko/docs/parallel-agents)
  - 하나의 에이전트가 다른 대화를 만들고 제어하게 하려면 → 이 페이지
  - 진행 중인 세션을 팀원에게 넘기려면 → [코딩 에이전트 세션 공유](/ko/docs/session-handoff)
</Callout>

## 대화에서 사용하기

원하는 결과와 작업 분담 방식을 일반 프롬프트로 설명하면 됩니다. 예를 들면 다음과 같습니다.

```text
이 프로젝트에 대해 두 개의 리뷰 대화를 만들어 줘. 하나는 정확성 검토용이고, 다른 하나는 테스트 커버리지 검토용이야.
둘 다 완료되면 발견된 내용을 여기에 요약해 줘.
```

에이전트는 대화를 새로 생성하거나 기존 대화를 재사용하고, 상태와 제한된 범위의 대화 기록을 읽으며, 후속 지시를 전달하거나 필요한 경우 실행 중인 턴(turn)을 취소할 수 있습니다. 요청한 작업이 종료 상태(terminal state)에 도달하면 결과가 요청한 대화로 반환됩니다.

새 세션을 만들 때 에이전트는 대상 머신에서 사용할 수 있는 호환 모델과 추론(reasoning) 옵션 중에서 선택할 수도 있습니다. 이러한 설정이 중요한 경우 다음과 같이 프롬프트에 원하는 옵션을 함께 적어 주세요.

```text
추론(reasoning) 설정을 high로 지정한 Codex 리뷰 세션을 만들고, 완료되면 발견된 내용을 여기에 요약해 줘.
```

## PR, 이슈 및 여러 저장소에 걸친 수정 조율하기

### Claude Code를 조율자로 사용하기

Claude Code에게 여러 PR이나 이슈를 살펴보고 의존성을 파악한 뒤, Kimi, Codex, Grok 같은 다른 에이전트에게 각기 초점을 맞춘 작업을 할당하도록 요청할 수 있습니다. 각 에이전트는 독립된 대화에서 작업하며, 조율자 에이전트가 후속 지시를 보내고 결과를 취합합니다. 저장소 접근에는 각 에이전트가 사용할 수 있는 도구와 자격 증명이 그대로 활용됩니다.

```text
이 PR들과 이슈들을 살펴보고, 관련 있는 작업을 묶어 의존성을 파악해 줘.
서로 독립적으로 처리할 수 있는 수정은 Kimi에게, 리뷰는 Codex에게 각각 별도의 대화로 위임해 줘.
각 에이전트의 결과를 모아 내가 리뷰할 준비가 된 변경 사항이 무엇인지 보고해 줘.
```

### 여러 저장소에 걸친 버그 수정하기

버그가 클라이언트, SDK, 서버에 걸쳐 있는 경우, 영향을 받는 저장소마다 대화를 하나씩 만들 수 있습니다. 에이전트들은 병렬로 원인을 조사하고 독립적인 변경 사항을 구현하면서, 공통 인터페이스 계약(contract)에 대한 조사 결과를 주고받고 의존성이 있는 수정 작업을 조율할 수 있습니다.

```text
클라이언트, SDK, 서버 저장소 전반에서 이 버그를 조사해 줘.
저장소마다 전담 에이전트 대화를 하나씩 시작하고, 의존성이 있는 수정을 구현하기 전에
조사 내용을 교환해 인터페이스 변경 사항에 먼저 합의하도록 해 줘.
패치와 검증 결과는 여기에 모아 줘.
```

### 에이전트 간 리뷰 및 수정 반복 실행하기

에이전트는 접근 가능한 다른 Lody 대화로 메시지를 보내고 작업을 위임할 수 있습니다. 또한 한 에이전트에게 다른 에이전트에게 직접 메시지를 보내도록 요청할 수도 있습니다. 예를 들어 리뷰 담당 에이전트가 특정 커밋을 검토한 뒤, 발견된 문제를 구현 담당 에이전트에게 전달하고, 수정이 끝난 뒤 업데이트된 커밋을 다시 리뷰하게 할 수 있습니다.

```text
리뷰 에이전트에게 파일을 수정하지 말고 구현 에이전트의 현재 커밋을 검토하라고 요청해 줘.
조치가 필요한 지적 사항을 구현 에이전트에게 전달해 수정을 요청하고,
수정된 커밋을 리뷰 에이전트가 다시 확인하도록 해 줘. 최대 2라운드까지만 진행하되 남는 문제가 없으면 더 일찍 멈추고,
최종 결과를 나에게 요약해 줘.
```

이 예시들은 미리 구성된 고정 파이프라인이 아니라 프롬프트로 요청할 수 있는 워크플로를 보여줍니다. 대상 저장소, 작업 범위, 완료 기준, 리뷰 횟수 제한을 명확하게 지정해 주세요. 병렬로 진행한 작업도 병합하기 전에 통합 검증을 거쳐야 합니다.

## 동작 방식

- 각 대화는 고유의 대화 기록과 활성 턴(active turn)을 가진 독립적인 작업으로 유지됩니다.
- 대상 머신이 온라인 상태일 때 작업을 병렬로 실행할 수 있습니다.
- Lody는 요청한 대화와의 연결 관계를 유지하므로, 위임된 작업이 완료된 후 에이전트가 이어서 작업을 계속할 수 있습니다.
- 임시로 생성한 대화는 작업이 끝나면 세션 목록에서 보관(archive)할 수 있습니다.

## 제한 사항

세션 제어에는 의도적인 경계가 설정되어 있습니다. 에이전트는 Lody가 소유한 대화 데이터만 조회할 수 있으며, 이를 무제한 백그라운드 스케줄러처럼 사용할 수는 없습니다. 위임된 작업은 요청된 제한 시간(deadline) 이후에 완료될 수도 있으며, 요청 측이 이미 시간 초과(timeout) 결과를 받았더라도 해당 작업의 출력은 그 대화 안에 그대로 남아 있습니다.

다른 에이전트를 조율하는 대신 진행 중인 세션을 팀원에게 넘기려면 [코딩 에이전트 세션 공유](/ko/docs/session-handoff)를 참고하세요.
