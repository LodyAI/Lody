# 권장 워크플로

Lody는 현재 [GitHub 연동](/ko/docs/github)과 [워크트리](/ko/docs/worktrees)를 핵심 기능으로 다루고 있으므로, 이를 기본 워크플로로 사용하는 것을 권장합니다.

시작하기 전에 [빠른 시작 설정](/ko/docs/quickstart)을 완료하세요.

## 작업을 작게 나누기

에이전트에는 컨텍스트 제한이 있으므로, 하나의 대화에서 크고 복잡한 작업 하나를 밀어붙이는 것보다 여러 작은 작업을 병렬로 실행하는 편이 일반적으로 더 잘 작동합니다. 시작하기 전에 작업을 원자적인 기능이나 수정 단위로 나누세요. 이렇게 하면 워크트리 수준의 파일 격리를 활용해 병렬로 개발할 수 있어 대기 시간을 줄일 수 있습니다.

## 병렬 개발

요구사항을 나눈 뒤, 홈 페이지 컴포저에서 대화 하나당 하나의 기능 또는 수정 사항을 설명하세요. 이 워크플로에서는 하나의 대화가 하나의 기능이나 수정 사항, 즉 보통 하나의 PR에 대응합니다. 머신 성능과 컨텍스트 전환을 감당할 수 있는 범위 내에서 원하는 만큼 많은 대화를 병렬로 실행할 수 있습니다. 격리된 워크트리, 다양한 에이전트 혼합 사용, 팀 가시성 등 이 방식의 바탕이 되는 제품 모델은 [병렬 코딩 에이전트](/ko/docs/parallel-agents)를 참고하세요.

Lody가 한 라운드를 마치면 [알림](/ko/docs/notification)을 보냅니다. 알림을 클릭하면 해당 세션으로 이동합니다. 코드를 읽는 데 익숙하다면 Lody 안에서 변경된 파일을 바로 검토하세요. 그렇지 않다면 왼쪽 사이드바의 해당 세션 아래에 있는 브랜치 이름을 복사한 뒤, 선호하는 개발 환경에서 그 브랜치로 전환해 엔드투엔드(end-to-end) 테스트를 진행하세요.

결과가 어느 정도 준비되면 대화 상단의 **Create PR**을 클릭하세요. Lody가 전체 요구사항과 구현 요약을 담은 PR을 생성하고 대화에 연결해 줍니다. 이후 연결된 PR 버튼을 클릭하면 GitHub의 해당 PR로 바로 이동할 수 있습니다.

## AI 리뷰 루프

Claude Code, Codex, Devin 등의 도구를 리포지토리에 연결하면 각 PR을 상세하게 리뷰해 줍니다. 리뷰 코멘트가 달리면 Lody에 다음과 같이 요청할 수 있습니다.
`PR 코멘트를 가져와 각 지적이 타당한지 평가해 주세요. 타당한 문제는 수정하고 resolved로 표시하고, 그렇지 않으면 이유를 설명하는 답글을 달아 주세요.`
그러면 Lody가 PR 코멘트를 가져와 평가하고, 수정 사항을 적용한 뒤 새 커밋을 푸시합니다. 이렇게 하면 명백한 문제가 남지 않을 때까지 (자동으로 또는 `@`를 통한 수동 호출로) 다음 AI 리뷰 라운드가 트리거됩니다.

## 완료된 세션 보관하기

PR이 병합되면 해당 세션의 역할은 끝납니다. 관련된 버그가 나타나지 않는 한, 같은 세션에서 무관한 작업을 계속 이어가는 것은 권장하지 않습니다. 사이드바의 [보관 작업](/ko/docs/session#archive-sessions)을 사용해 완료된 세션을 활성 목록에서 제거하세요.

보관하면 대화 내용과 로컬 브랜치는 유지하면서 관리형 워크트리 디렉터리를 회수할 수 있습니다. 필요한 무시된(ignored) 파일은 먼저 워크트리 외부에 저장해 두세요. 자세한 내용은 [워크트리 보존 및 복구](/ko/docs/worktrees#automatic-cleanup)를 참고하세요.

## 보관된 세션 주기적으로 삭제하기

대화가 더 이상 필요하지 않다면 [보관된 세션을 삭제](/ko/docs/session#delete-sessions)하여 기록을 영구적으로 제거하세요. 이 작업은 보존된 로컬 Git 브랜치나 백업 커밋을 삭제하지 않으므로, 리포지토리의 모든 저장 공간을 회수하는 수단은 아닙니다.

## GitHub 이외의 프로젝트

이 워크플로는 GitHub에 호스팅된 프로젝트에 가장 적합합니다. GitHub 기반이 아닌 작업의 경우 해당 디렉터리를 [로컬 프로젝트](/ko/docs/local-project)로 추가하세요. 로컬 프로젝트에서도 채팅, 파일 목록, diff 검토, 모바일 액세스, Lody Preview를 모두 지원하지만, GitHub 전용 PR 및 CI 자동화 기능은 사용할 수 없습니다.
