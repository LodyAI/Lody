# 예약 작업

**예약 작업**은 사용자가 지정한 시간에 선택한 Agent, 모델, 권한 모드, 프로젝트 설정으로 프롬프트를 전송합니다. 모든 실행은 일반 대화로 시작되므로, 언제든지 대화를 열어 이어가거나 중단할 수 있습니다.

주요 활용 예로는 매일 아침 전날 병합된 커밋 요약하기, 평일마다 의존성 보안 권고 확인하기, 금요일마다 주간 보고서 초안 작성하기 등이 있으며, 필요할 때 클릭 한 번으로 실행할 수 있는 수동 작업으로 저장해 둘 수도 있습니다.

## 실행 위치

예약 작업은 클라우드에서 실행되지 않습니다. 각 작업은 **사용자 본인의 머신 중 하나**가 소유하며 실행합니다.

- 해당 머신에서는 예약 기능을 지원하는 버전의 [Lody CLI](/ko/docs/cli)가 실행되고 있어야 합니다(데스크톱 앱이 대신 실행해 줍니다).
- 시간은 **해당 머신의 로컬 시간대**를 기준으로 해석되며, 별도의 시간대 선택기는 없습니다. "매일 9:00"은 그 머신의 시각 기준 9:00를 의미합니다.
- 머신이 꺼져 있거나, 절전 상태이거나, CLI가 실행 중이 아니면 해당 시각에 작업이 실행되지 않습니다. 이후 어떻게 처리되는지는 [놓친 실행](#놓친-실행)을 참고하세요.

웹, 데스크톱, 모바일 어디에서나 예약 작업을 보고 관리할 수 있지만, 실제 실행은 해당 작업을 소유한 머신에서만 이루어집니다.

## 대화에서 메시지 예약 전송하기

기존 대화에서 **+ → Schedule send…**를 선택하고 대상 머신의 시계 기준으로 미래 날짜와 시간을 지정한 뒤, 작성기의 예약 전송 버튼을 누릅니다. 이 기능은 1회성 전송으로 동작하며 새 채팅 페이지에서는 사용할 수 없습니다.

텍스트, 이미지, 파일, 참조 항목은 첨부 파일 준비가 성공적으로 완료된 후 함께 저장됩니다. 정보 표시줄에는 예약된 메시지 아이콘이 하나 표시됩니다. 이 아이콘을 클릭하면 전송 예정 시간과 Edit 버튼을 확인할 수 있습니다. Edit을 열면 30분, 1시간, 5시간 프리셋이 포함된 날짜/시간 설정 컨트롤이 나타나며, Remove time을 선택하면 작성 중인 초안을 잃지 않고 일반 전송 모드로 돌아갑니다. 저장에 실패한 경우에도 초안은 유지됩니다.

작성기 위에 표시되는 대기 중인 메시지 요약을 클릭하면 Schedule details가 열려 메시지 내용과 시간을 수정하거나 예약을 취소할 수 있습니다. 취소 요청은 소유 머신의 확인을 기다립니다. 이미 전송 처리가 확정된 경우에는 메시지가 전송됨(sent)으로 표시됩니다. 여기서 전송됨이란 Agent의 최종 실행 결과와는 별개로 메시지가 대화에 전달되었음을 뜻합니다.

전체 메시지를 지원하는 CLI가 설치된 본인 소유의 머신을 사용하세요. 요청된 시각에 머신이 절전 상태이거나 오프라인이었다면, 다시 연결될 때 보완 실행으로 한 번 전송됩니다. 대화가 이미 작업 중이라면 현재 작업이 끝난 뒤에 전송됩니다. 모델, 권한, MCP, Role 설정은 예약이 수락된 시점의 값으로 고정됩니다.

## Claude 할당량 초기화 후 계속하기

Claude가 세션 한도를 보고하고 5시간 할당량이 소진된 경우, 향후 초기화 시각을 확인할 수 있다면 작성기 위에 **Send continue after reset** 바로 가기가 표시됩니다. 한 번 클릭하면 실패한 턴의 실행 설정을 그대로 사용하여 해당 초기화 시각 1초 뒤에 이 대화로 `continue`라는 메시지를 그대로 전송하도록 예약됩니다. 작성기에 입력 중이던 초안은 그대로 유지됩니다.

이 바로 가기는 오류 메시지에 적힌 시각 텍스트가 아니라 제공자가 반환한 할당량 타임스탬프를 사용합니다. 날짜를 추론하거나 주간 한도를 5시간 한도로 취급하지 않습니다. 더 긴 기간의 할당량이 여전히 소진된 상태인 경우에도 바로 가기는 표시되지 않습니다. 저장한 뒤에는 **View scheduled continue**를 클릭해 기존 메시지 세부 정보를 열어 변경하거나 취소할 수 있습니다. 사용자가 클릭하기 전까지는 계속하기 메시지가 자동으로 예약되지 않습니다.

## 예약 작업 만들기

사이드바에서 **Schedules**를 열고 **New schedule**을 선택합니다(또는 명령 팔레트에서 "New Schedule"을 검색합니다). 편집기는 작성기와 같은 형태로 구성되어 있습니다.

1. **이름 및 프롬프트(Name and prompt)** — 각 실행마다 Agent가 수행할 작업 내용입니다.
2. **Agent, 모델 및 권한(Agent, model and permission)** — 작성기 하단과 동일한 컨트롤입니다. 새 작업은 채팅 시작 화면에서 마지막으로 사용한 머신과 Agent, 그리고 해당 Agent에 기억된 설정으로 시작됩니다. 표시된 기본값은 바로 사용할 수 있으며, 별도로 권한을 추가 선택할 필요는 없습니다. Pi처럼 권한 선택기가 없는 제공자는 자체 실행 정책을 사용합니다.
3. **머신, 프로젝트, 워크트리(Machine, project, worktree)** — 프로젝트는 선택 사항입니다. 프로젝트를 지정하지 않으면 각 실행은 저장소를 체크아웃하지 않은 일반 Agent 대화로 진행됩니다.
4. **전송 대상(Send to)** 및 **트리거(Trigger)** — 아래 설명을 참고하세요.

누락된 항목이 있으면 해당 항목을 수정할 수 있는 컨트롤 옆에 느낌표가 표시됩니다. 저장하면 목록 화면으로 돌아갑니다.

## 트리거

- **예약 일정에 따라(On a schedule)** — **Repeat**에서 규칙을 고른 뒤 시간을 지정합니다.
  - 매일, 평일마다, 매주(요일 선택), 매월(날짜 선택)
  - 몇 시간마다, 몇 분마다
  - 한 번만(날짜와 시간 지정)
- **수동(Manual)** — 자동으로 실행되지 않으며 **Run now**를 눌렀을 때만 실행됩니다. 자주 재사용하는 프롬프트를 저장해 두기에 편리합니다.

편집기에 **Next runs** 목록이 표시되므로 설정한 규칙을 미리 확인할 수 있습니다. 시간과 날짜는 직접 입력합니다.

## 실행 결과 위치

- **실행할 때마다 새 채팅(New chat each run)** (기본값) — 실행할 때마다 별도의 새 대화를 시작합니다.
- **이 작업용 채팅 하나(One chat for this task)** — 이전 맥락을 이어가야 하는 작업을 위해 모든 실행을 동일한 대화에 이어서 추가합니다. 대화는 첫 실행 시 생성되며, **Start a new chat**을 누르면 이후 실행이 새 대화로 전환됩니다.
- **기존 채팅(An existing chat)** — 선택한 기존 대화에 실행을 이어서 추가합니다. 해당 대화의 Agent가 사용되며, 별도의 프로젝트는 선택하지 않습니다.

## 예약 작업 관리

목록의 각 행에는 작업 이름, 실행 주기, 다음 실행 예정 시각, 실행 환경이 표시됩니다.

- 예약 시간이 설정된 행에는 **Pause** / **Resume**이 행에 바로 표시되며, 수동 작업 행에는 **Run now**가 표시됩니다.
- 행을 마우스 오른쪽 버튼으로 클릭하면 열기, 지금 실행, 일시 중지 또는 재개, **Last run** 열기, 삭제(삭제 전 확인을 거침) 메뉴를 사용할 수 있습니다.
- 행을 클릭하면 오른쪽에서 세부 정보 패널이 슬라이드되어 열리며, 상단에는 일시 중지, 지금 실행, 삭제 버튼이, 하단에는 **Run history**가 표시됩니다. 구분선을 드래그해 크기를 조절할 수 있고, 목록의 빈 공간을 클릭하면 닫힙니다.

예약 작업의 편집, 일시 중지, 삭제는 작성자만 할 수 있습니다. 일시 중지하면 이후의 실행만 중단되며, 이미 시작된 대화는 별도로 취소해야 합니다.

## Agent에게 설정 맡기기

Agent에게 "평일 오전 9시마다 의존성 업데이트 확인해 줘"처럼 요청하면 Agent가 이름, 프롬프트, 실행 규칙의 초안을 작성한 뒤 대화에 **Schedule this task?** 카드를 표시합니다.

- 이 카드에는 현재 대화의 Agent, 권한 모드, 머신, 프로젝트가 그대로 적용되며, 실제로 생성될 내용이 정확히 나열됩니다.
- **Edit**을 누르면 카드 위에서 바로 이름, 프롬프트, 시간 규칙을 수정할 수 있습니다.
- **Create**를 누르면 작업이 생성되고, **Ignore**를 누르면 취소됩니다. 한 번 생성된 뒤에는 카드를 더 이상 수정할 수 없으므로 Schedules 페이지에서 작업을 변경하세요.

이미 만들어 둔 작업을 수정하려면 Agent에게 변경을 요청하세요(예: "야간 리뷰 프롬프트에 규칙 하나 추가해 줘"). 그러면 현재 설정과 제안된 이름 및 시간 규칙, 프롬프트에서 변경된 줄을 보여 주는 **Update this scheduled task?** 카드가 표시됩니다. **Apply**를 누르면 변경 사항이 저장되고 **Ignore**를 누르면 버려집니다. 카드에 표시되지 않은 나머지 항목은 그대로 유지됩니다. 제안이 표시된 이후에 작업을 직접 수정한 경우에는 해당 카드를 더 이상 적용할 수 없으므로, Agent에게 새로운 제안을 요청하세요.

Agent는 예약 작업의 생성이나 변경을 제안할 수만 있으며, 직접 작업을 생성하거나 수정할 수는 없습니다.

## 놓친 실행

예약된 시각에 머신이 오프라인 상태였다면, 머신이 다시 온라인 상태가 되었을 때 가장 최근에 놓친 시각에 대해서만 **한 번** 실행됩니다(놓친 횟수마다 모두 실행되지는 않습니다).

다음 실행 시각이 되었을 때 이전 실행이 아직 진행 중이라면, 새 실행은 이전 실행이 끝날 때까지 대기했다가 시작됩니다. 대기할 수 있는 실행은 최대 한 건입니다.

## 자주 묻는 질문

### 작업에 "Waiting for the schedule configuration to finish syncing"이라고 표시되는 이유는 무엇인가요?

소유 머신이 아직 최신 구성을 전달받지 못한 상태입니다. 저장한 직후 몇 초 동안 이 상태가 표시되는 것은 정상입니다. 상태가 계속 유지된다면 해당 머신이 온라인 상태인지, CLI가 최신 버전인지 확인하세요.

### 머신을 선택할 수 없는 이유는 무엇인가요?

예약 작업은 해당 기능을 지원하는 CLI가 설치된 본인 소유의 머신에서만 실행됩니다. 해당 머신의 Lody CLI를 업데이트하세요.

### 작업을 실행하기 위해 컴퓨터가 절전 모드에서 깨어나나요?

아니요. CLI는 머신이 깨어 있는 동안에만 작업을 확인하고 실행하며, 절전 상태의 컴퓨터를 깨우지는 않습니다. 깨어난 후에는 [놓친 실행](#놓친-실행)에서 설명한 대로 한 번만 보완 실행됩니다.
