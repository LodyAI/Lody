# 에이전트 역할

**에이전트 역할(Agent Role)**은 에이전트를 *어떻게* 사용할지를 하나로 묶어 둔 것입니다. 실행되는 머신과 [에이전트 설정](/ko/docs/quickstart), 모델과 추론 수준, 권한 모드, 그리고 선택 사항인 기본 지침까지 포함됩니다. 이모지와 이름을 붙여 두면 이 모든 선택을 클릭 한 번으로 불러올 수 있습니다.

역할은 새로운 프로바이더도, 실행 중인 에이전트도 아닙니다. API 키나 MCP 선택 상태는 저장하지 않으며, 해당 정보는 에이전트 설정에 그대로 유지됩니다.

## 역할 만들기

진입점은 두 곳이지만, 열리는 편집기는 같습니다.

- **Settings** → **Agent Roles** → `+` 버튼.
- 입력창(composer)의 실행 설정에 있는 **Role** 행 → **New role with settings**. 이 경로로 열면 지금 바로 실행하려는 설정이 미리 채워져 있으므로, 방금 조정한 구성을 그대로 저장하는 가장 빠른 방법입니다.

머신과 에이전트 설정을 고른 뒤, 해당 에이전트가 제공하는 모델, 추론 수준, 권한을 선택하고 필요하면 기본 지침을 입력합니다. 새로 만든 역할은 **Share with workspace**를 켜기 전까지 본인에게만 보이는 비공개 상태입니다.

## 에이전트에게 역할 생성 또는 업데이트 요청하기

진행 중인 Lody 대화에서 에이전트에게 새 역할을 만들거나, 본인이 소유한 역할의 이름, 설명 또는 기본 지침을 업데이트해 달라고 요청할 수 있습니다. 에이전트는 `lody_agent_role`의 `create` 또는 `update` 액션을 사용해 검토 카드를 표시합니다.
제안된 필드를 확인한 뒤 **Save**를 클릭해 적용하거나 카드를 닫습니다.

이 방식으로 새로 만든 역할은 비공개 상태이며, 지정한 머신과 에이전트 설정에 바인딩되고 해당 에이전트의 기본 실행 설정을 사용합니다. 업데이트할 때는 변경을 요청하지 않은 필드는 그대로 유지됩니다. 모델, 권한, 공유 설정 등 나머지 항목은 Settings에서 계속 편집할 수 있습니다.
직접 파라미터를 넘기거나 JSON 파일을 사용해 [CLI](/ko/docs/cli#create-and-update-agent-roles)로도 동일한 제안을 제출할 수 있습니다.

## 대화를 시작할 때 역할 사용하기

입력창의 실행 설정에서 **Role** 행은 **Agent** 위에 위치합니다. 역할을 선택하면 그 아래의 모든 항목이 한꺼번에 채워지기 때문입니다.

- 데스크톱에서는 입력창 푸터의 실행 설정 버튼을 열고 **Role**에 마우스를 올립니다. 목록 옆에 패널이 열려 강조 표시된 역할이 정확히 무엇을 실행하는지 보여 줍니다.
- 모바일에서는 실행 설정 시트를 엽니다. **Role**이 첫 번째 행에 있습니다.

역할을 하나 선택하면 아래 행들이 해당 역할에 맞게 바뀝니다. 입력창 푸터에는 역할의 이모지와 이름이 표시되고, 그 옆에 작은 글씨로 설정 값이 함께 나타납니다. 실제로 대화를 시작하는 데 사용한 역할은 **Recently used** 아래에도 표시됩니다.

**None**을 선택하면 설정 값은 남고 역할 이름만 지워집니다. 역할이 채워 둔 값은 이제 현재 설정이 되었으므로, 역할을 해제해도 값은 그대로 유지됩니다.

푸터에 역할 이름이 표시되는 것은 현재 설정이 그 역할의 설정과 일치하는 동안뿐입니다. 모델을 직접 변경하면 이름은 사라집니다. 푸터는 실제로 실행될 설정과 다른 역할을 표시하지 않습니다.

다른 대화 안에 있는 빈 하위 탭(child tab)에도 이 새 대화 규칙이 동일하게 적용됩니다. 머신과 작업 디렉터리는 부모 세션에 그대로 연결되어 있지만, Role 목록에는 에이전트 유형과 무관하게 해당 머신의 모든 역할이 포함됩니다. 하나를 선택하면 초안이 해당 역할의 에이전트 설정으로 전환되며, 첫 메시지를 보낼 때 실행 설정, 지침, 출처(provenance) 정보가 고정됩니다.

## 대화 도중에 역할 사용하기

대화가 한 번 생성되면 이미 특정 머신에서 에이전트가 실행 중이므로, 역할로 대화를 다른 머신이나 에이전트로 옮길 수 없습니다. 따라서 대화 내부의 **Role** 행은 다음과 같이 동작합니다.

- 현재 에이전트가 모델, 추론 수준, 권한 값을 이해할 수 있도록 **같은 유형**의 에이전트에 바인딩된 역할만 표시합니다.
- 실행 설정만 적용하며, 이미 진행 중인 대화에는 역할의 기본 지침이 추가되지 않습니다.

적용한 뒤에도 모든 행은 계속 개별적으로 편집할 수 있습니다.

## 역할 멘션하기

`@`를 입력하고 **Agent Roles** 아래에서 역할을 선택하면, 현재 에이전트에게 해당 역할로 *새* 대화를 시작해 달라고 요청할 수 있습니다.

```text
@code-reviewer check the diff on this branch and report anything that breaks
```

새 대화는 해당 역할의 머신과 에이전트 설정에서 시작되며, 모델, 추론 수준, 권한, 기본 지침이 이미 적용된 상태로 열립니다. 메시지를 보낸 시점의 역할 정의가 그 요청에 그대로 고정되므로, 나중에 역할을 수정하거나 삭제해도 이미 수락된 작업에는 영향을 주지 않습니다.

멘션할 수 있는 역할은 현재 위치에 따라 달라집니다. 로컬 프로젝트나 일반 채팅에서는 같은 머신에 있는 역할만 선택할 수 있지만, GitHub 프로젝트에서는 새 대화가 저장소를 직접 클론하므로 권한이 있는 다른 머신의 역할에도 접근할 수 있습니다. 다른 멘션 유형은 [멘션](/ko/docs/mention)을 참고하세요.

## 공유

역할은 공유하기 전까지 비공개입니다. **Share with workspace**를 켜면 워크스페이스의 모든 멤버가 해당 역할을 보고, 멘션하고, 실행할 수 있게 됩니다. 다만 역할은 여전히 지정된 머신에서 실행되므로, 멤버들에게도 해당 머신에 대한 접근 권한이 있어야 합니다.

비공개란 다른 멤버가 Lody를 통해 그 역할을 찾거나, 멘션하거나, 실행할 수 없다는 뜻입니다. 암호화 기능을 의미하는 것은 아니므로, 역할에는 애초에 어떤 비밀 정보(secret)도 저장하지 않습니다.

## 역할을 실행할 수 없는 경우

역할은 하나의 머신과 하나의 에이전트 설정에 정확히 바인딩되며, 조용히 다른 것으로 대체되지 않습니다. 머신이 오프라인 상태가 되거나 에이전트 설정이 삭제되면, 해당 역할은 Settings와 선택 목록에 정확한 사유가 표시된 상태로 남아 있으며 문제를 해결하기 전까지 선택할 수 없습니다.

역할을 편집하더라도 이후의 사용에만 영향을 줍니다. 이미 해당 역할로 시작된 대화는 기존 설정 그대로 계속 실행됩니다.
