Lody는 **멀티 에이전트 코딩**을 위한 팀 워크스페이스입니다. 각자 독립된 대화를 가진 여러 코딩 에이전트 세션을 동시에 시작할 수 있습니다. 세션이 [worktree](/ko/docs/worktrees)를 사용하면 — GitHub에서는 항상 사용되며 로컬 프로젝트에서도 지원됩니다 — 해당 세션만의 작업 디렉터리가 생성되므로, 여러 에이전트가 충돌 없이 동시에 파일을 변경할 수 있습니다.

여러 개의 Claude Code 세션을 실행하거나, Claude Code와 함께 Codex, Kimi, Grok, DeepSeek 또는 다른 [ACP](/ko/docs/cli-runtimes) 런타임을 나란히 사용할 수 있습니다. 에이전트가 작업을 위임하고, 컨텍스트를 교환하며, 서로의 변경 사항을 리뷰하도록 하려면 [멀티 에이전트 협업 가이드](/ko/docs/agent-collaboration/)를 참고하세요.

[에이전트 설정](/ko/docs/quickstart), [팀 기능](/ko/docs/team), [코딩 에이전트 세션 공유](/ko/docs/session-handoff), [에이전트 세션 제어](/ko/docs/session-orchestration)도 함께 확인해 보세요. 공유 링크는 실시간 이어받기가 아닌 기록용입니다 — 자세한 내용은 [공유 링크 vs 실시간 핸드오프](/ko/docs/compare/share-link-vs-live-handoff)를 참고하세요.

## 격리된 worktree

worktree를 사용하는 세션을 생성하면 Lody는 다음 작업을 수행합니다:

1. 브랜치를 생성합니다 (기본값: `session/<shortSessionId>`)
2. 전용 worktree에 해당 브랜치를 체크아웃합니다
3. 선택적으로 프로젝트 설정 스크립트를 실행합니다
4. 파일 변경 사항을 세션 UI로 실시간 스트리밍합니다

서로 다른 세션의 에이전트는 작업 디렉터리를 공유하지 않으므로, 커밋되지 않은 수정 사항은 해당 작업을 수행한 세션에만 남아 있습니다. 세션별로 변경 사항을 리뷰하거나, 되돌리거나, PR을 열 수 있습니다.

<Callout title="포크 대상 선택">
[포크(Fork)](/ko/docs/session#fork-a-session)는 대화 기록을 **새** 세션으로 복사합니다. **Current workspace**(및 Side Chat)는 원본 디렉터리를 그대로 유지합니다. **New worktree** 옵션이 제공되는 경우, 해당 포크는 최신 커밋 `HEAD`에서 시작하는 독립된 세션이 됩니다 — 대화 맥락을 유지하면서 격리된 작업 환경이 필요할 때 사용하세요. 복사된 대화 기록 없이 완전히 새로운 격리 작업을 시작하려면 홈 페이지에서 새 세션을 시작하세요.
</Callout>

자세한 내용: [Worktrees](/ko/docs/worktrees).

## 하나의 워크스페이스에서 여러 에이전트 실행하기

각 세션은 컴포저(composer)에서 자체적인 [에이전트 설정](/ko/docs/quickstart), 모델, 권한 범위를 선택할 수 있습니다. 다음과 같은 구성을 실행할 수 있습니다:

- 머신의 구독 로그인을 통한 Claude Code 또는 Codex
- Kimi Code, DeepSeek Harness 및 기타 내장 또는 Claude 호환 설정
- [ACP 레지스트리](/ko/docs/cli-runtimes)의 모든 런타임 또는 사용자 지정 ACP 실행 명령

동일한 구성을 자주 시작한다면 머신, 설정, 모델, 권한의 조합을 [에이전트 역할(Agent Role)](/ko/docs/agent-roles)로 저장해 재사용하세요.

동시에 실행할 수 있는 세션 수는 호스트 머신의 성능과 실제로 관리하고 확인할 수 있는 대화 수에 따라 달라집니다 — 자세한 내용은 [권장 워크플로](/ko/docs/workflow)를 참고하세요.

## 팀 가시성

팀원이 이미 어떤 작업이 실행 중인지 볼 수 있으면 병렬 작업이 훨씬 수월해집니다.

- 홈 페이지에서 사이드바 필터는 기본적으로 **All Tasks**로 설정되어 있습니다. 본인 세션만 보인다면 **My Tasks**에서 **All Tasks**(모바일에서는 **Team Tasks**)로 전환하세요. 아바타를 통해 누가 각 세션을 시작했는지 확인할 수 있습니다.
- 머신은 **기본적으로 비공개** 상태를 유지합니다. 팀원이 해당 대화를 열 수 있어야 할 때는 머신을 공유하거나 세션에서 **Share with team…**을 사용하세요.
- 팀원을 기존 세션 *내부*로 초대해 동일한 채팅, diff, worktree를 함께 보게 하려면 [코딩 에이전트 세션 공유](/ko/docs/session-handoff)를 참고하세요.

멤버십, 역할 및 머신 공유: [팀 기능](/ko/docs/team).

## 하나의 대화에서 작업 조율하기

대부분의 병렬 작업은 세션을 직접 시작하는 것만으로 충분합니다. 한 에이전트가 작업을 나누어 처리하도록 하려면 [에이전트 세션 제어](/ko/docs/session-orchestration)를 사용하도록 요청하세요. 대화를 생성하거나 재사용하고, 상태를 확인하며, 후속 지시를 보내고, 결과를 모아올 수 있습니다. 이렇게 위임된 대화들은 대상 머신이 온라인 상태인 동안 병렬로 실행될 수 있습니다.

## 실전 작업 분할 예시

[권장 워크플로](/ko/docs/workflow)를 바탕으로 한 예시입니다:

1. 작업을 작은 기능이나 수정 단위로 나눕니다.
2. 항목당 하나의 홈 페이지 대화를 시작합니다(보통 PR 하나에 해당).
3. 각 에이전트가 작업하는 동안 실시간 [diff](/ko/docs/diff-viewer)를 리뷰합니다.
4. GitHub 기반 작업의 경우, 변경 사항이 준비되면 세션에서 바로 PR을 생성합니다.
5. 작업이 완료된 후 세션을 [아카이브](/ko/docs/session#archive-sessions)하여 worktree를 회수합니다.

## 자주 묻는 질문

### 이것은 Claude Code의 팀 기능인가요?

아닙니다. Claude Code는 Lody에서 실행할 수 있는 [에이전트 설정](/ko/docs/quickstart) 중 하나일 뿐입니다. 워크스페이스, 격리된 worktree, 팀 세션 목록은 모두 Lody가 제공합니다. 여러 개의 Claude Code 세션을 실행하거나, Claude Code와 Kimi, DeepSeek, Codex 또는 다른 ACP 에이전트를 함께 사용할 수 있습니다.

### 병렬 에이전트가 서로의 파일을 덮어쓰나요?

**New worktree** 포크나 새 홈 페이지 세션을 포함해 각 작업이 고유한 [worktree](/ko/docs/worktrees)를 사용하는 경우에는 덮어쓰지 않습니다. 반면 **Current workspace** 포크와 Side Chat은 원본 세션의 디렉터리를 공유하므로 서로의 파일 변경 사항을 볼 수 있습니다. New worktree 포크는 커밋된 `HEAD`에서 시작하며, 커밋되지 않은 수정 사항은 원본에 그대로 남습니다.

### 팀원이 실행 중인 모든 에이전트를 볼 수 있나요?

워크스페이스에 공유된 머신(및 로컬 프로젝트)의 세션을 볼 수 있으며, 홈 페이지 필터가 **My Tasks**로 설정되어 있다면 **All Tasks**로 전환하면 됩니다. 공유되지 않은 머신의 대화는 다른 멤버의 사이드바에 절대 동기화되지 않습니다. 자세한 내용은 [팀 기능](/ko/docs/team)을 참고하세요.

### 한 에이전트가 다른 에이전트를 시작할 수 있나요?

네, [에이전트 세션 제어](/ko/docs/session-orchestration)를 통해 가능합니다. 하나의 대화에서 특정 작업에 집중된 세션을 생성하고, 다른 에이전트와 메시지를 주고받으며, 진행 상황을 확인하고 요약하도록 요청할 수 있습니다. 이 기능은 Lody 대화 데이터 범위 내에서 동작하며, 범용 백그라운드 스케줄러는 아닙니다.

### 다른 에이전트를 시작하는 대신 언제 세션을 핸드오프해야 하나요?

**새로운** 격리된 작업을 원할 때는 다른 세션을 시작하세요.
팀원이 기존 세션을 **이어서 진행**해야 할 때는 [핸드오프](/ko/docs/session-handoff)하세요.
