# 세션

세션은 Lody의 가장 기본적인 개념입니다. 홈 페이지 작성기(composer)에서 새 세션을 시작할 수 있으며,
이는 Claude Code / Codex CLI에서의 대화 하나와 같습니다.

세션을 시작하기 전에 작성기 주변 메뉴에서 다음 항목을 설정할 수 있습니다.

- 저장소 및 브랜치
- 에이전트 설정
- 모델
- 권한 범위

Lody는 선택한 설정을 바탕으로 세션을 시작합니다.

하나의 세션에는 메인 채팅, 하위 채팅, 파일 미리보기, diff 보기 등 여러 탭을 함께 둘 수 있습니다. 코드를 읽으면서 대화를 이어가거나, 하나의 작업을 여러 리뷰 스레드로 나누고 싶다면 [세션 탭](/ko/docs/session-tabs)을 참고하세요.

팀원을 기존 세션에 초대하여 동일한 대화, diff, 워크트리(worktree)를 이어서 작업하게 하려면 [코딩 에이전트 세션 공유](/ko/docs/session-handoff)를 참고하세요. 아래에서 설명하는 포크(Fork)는 사용자를 위해 새 세션을 시작하는 기능이며, 기존 세션에 다른 사람을 추가하지는 않습니다.

## 세션 포크

사용 중인 에이전트가 네이티브 세션 포크를 지원하면, 가장 최근에 완료된 에이전트 답변 아래에 **Fork
session** 버튼이 표시됩니다. 포크하면 해당 답변까지의 대화 기록을 담은 새 세션이 생성되며, 원본 세션을
변경하지 않고 다른 방향으로 대화를 이어갈 수 있습니다.

Codex와 Claude Code에서는 이전의 완료된 에이전트 답변에서도 포크할 수 있습니다.

워크트리 포크를 지원하는 Git 기반 세션에서는 **Fork session**이 두 가지 대상을 제공합니다.

- **Current workspace** — 원본과 파일 및 커밋되지 않은 변경 사항을 공유하는 새 탭을 엽니다.
- **New worktree** — 가장 최근에 커밋된 `HEAD`를 기준으로 독립적인 새 세션을 만듭니다. 커밋되지
  않은 파일과 추적되지 않은 파일은 원본에 남습니다.

**New worktree** 옵션이 제공되지 않는 경우 포크는 현재 워크스페이스에서 생성됩니다. 사이드 채팅(Side Chat)은
항상 공유 디렉터리 경로를 사용합니다.

포크 기능은 활성 에이전트가 네이티브 포크 지원을 보고할 때만 사용할 수 있습니다.

## 오른쪽 사이드바: 브라우저 및 사이드 채팅

오른쪽 사이드바에는 메인 대화 옆에 도구를 열어둘 수 있습니다. 세션 도구 모음에서 **Browser**를 열어
웹 페이지를 탐색하거나, 사이드바의 `+` 메뉴를 사용해 패널을 추가할 수 있습니다.

**Side Chat**은 포크 가능한 가장 최근 에이전트 답변을 포크하여 오른쪽 사이드바에 별도의 채팅으로 엽니다.
메인 세션을 그대로 유지하면서 후속 질문이나 리뷰 질문을 할 때 유용합니다. 여러 개의 사이드 채팅을 만들고
사이드바에서 전환할 수 있으며, 더 이상 필요하지 않으면 `X` 버튼으로 닫을 수 있습니다. 사이드 채팅은
활성 에이전트가 네이티브 세션 포크를 지원할 때 사용할 수 있습니다.

URL 및 원격 포트 접근에 대한 자세한 내용은 [Lody 미리보기](/ko/docs/preview)를 참고하세요.

## 세션 목록

왼쪽 사이드바에는 채팅, GitHub 워크트리, 로컬 프로젝트의 대화가 표시됩니다.
기본 프로젝트별 정렬을 사용하거나, **Updated** 모드로 전환해 모든 세션을 최신순(오늘, 이번 주, 이전)으로
묶어서 볼 수 있습니다.

각 세션에는 AI가 생성한 의미 기반 제목과 현재 상태가 표시됩니다. 세션 위에 마우스를 올리면
세션 정보 카드에서 저장소, 브랜치, Pull Request 상태, 기본 브랜치 대비 변경된 줄 수를 확인할 수
있습니다.

## 세션 작업

사이드바에서 세션을 마우스 오른쪽 버튼으로 클릭하면 컨텍스트 메뉴가 열립니다. 여기에서 이름 변경,
고정, 보관, 세션 URL 복사, 현재 브랜치 이름 복사를 실행할 수 있습니다.

고정된 세션은 목록 상단에 유지되므로 중요하거나 오래 진행 중인 작업을 쉽게 찾을 수 있습니다.
웹 앱에서는 사이드바의 작업을 마우스 가운데 버튼으로 클릭하거나 Cmd/Ctrl-클릭하여 새 브라우저 탭에서 열 수 있습니다.

대화 작업 표시줄과 세션 정보 컨트롤은 사용 가능한 경우 프로젝트, 브랜치, 미리보기, Pull Request,
코드 변경 등 현재 작업과 관련된 동작들을 한곳에 모아 제공합니다. 덕분에 별도 화면으로 이동하지 않고도
대화 옆에서 자주 쓰는 GitHub 및 프로젝트 작업을 바로 처리할 수 있습니다.

## 데스크톱 빠른 세션

`Cmd/Ctrl+Shift+N`을 누르면 독립 실행형 빠른 세션(Quick Session) 창이 열립니다. 시스템 전역
데스크톱 단축키이므로 Lody 창에 포커스가 없어도 작동합니다. 간결한 작성기에서 프로젝트, 에이전트,
모델을 선택한 뒤 메인 창을 먼저 열지 않고도 세션을 시작할 수 있습니다.

이 단축키는 **Settings** -> **Keyboard**에서 변경할 수 있습니다. 자세한 내용은
[명령 팔레트 및 키보드 단축키](/ko/docs/keyboard-shortcuts)를 참고하세요.

## 에디터에서 워크스페이스 열기

데스크톱 세션 헤더의 **Open in**을 사용하면 현재 워크트리나 프로젝트 디렉터리를 열 수 있습니다.
기본 제공 런처에는 VS Code, Xcode, Sublime Text 등 지원되는 에디터가 포함되어 있습니다.

**Settings** -> **General** -> **Path launchers**에서 기본 런처를 선택하거나 사용자 지정 셸 명령을
추가할 수 있습니다. 사용자 지정 템플릿에는 세션 폴더 경로 인자로 `{path}`를 반드시 포함해야 하며,
해당 설정은 현재 데스크톱에만 저장됩니다.

이미 에디터에 열려 있는 프로젝트를 다시 열면 새 창을 여는 대신 기존 창으로 포커스가 이동합니다(예: Zed).

## 세션 보관

목록에서 세션 위에 마우스를 올리면(모바일에서는 탭하면) 오른쪽 아래에 보관 버튼이 나타납니다.
이 버튼을 클릭하면 세션이 보관됩니다.

보관된 세션은 보관 목록으로 이동하며 대화 기록은 유지됩니다. 소유 머신은 영구 삭제 전에 Lody가
관리하는 워크트리 디렉터리를 회수할 수 있으며, 이 과정에서 먼저 로컬 브랜치를 유지하고 무시되지
않은 대기 중인 변경 사항을 커밋합니다. 무시된(ignored) 파일은 삭제될 수 있으며, 정리 스크립트가
백업 전에 파일을 변경할 수도 있습니다. 보관하기 전에 필요한 파일은 워크트리 외부에 저장하세요.
시점, 복구 요구 사항, 보호 범위에 대한 자세한 내용은 [워크트리 보존 및 복구](/ko/docs/worktrees#automatic-cleanup)를
참고하세요. 로컬 프로젝트 디렉터리에서 직접 실행 중인 세션은 관리형 워크트리 정리에 의해 해당
디렉터리가 삭제되지 않습니다.

## 세션 보관 해제

왼쪽 사이드바 오른쪽 아래의 보관 목록 버튼을 클릭해 보관된 세션을 엽니다.
검색과 정렬을 사용해 세션을 찾은 뒤 복원 버튼을 클릭하면 활성 목록으로 다시 이동하여 언제든
대화를 이어갈 수 있습니다.

## 세션 삭제

왼쪽 사이드바 오른쪽 아래의 보관 목록 버튼을 클릭해 보관된 세션을 엽니다.
세션 옆의 삭제 버튼을 클릭하면 세션과 대화 기록이 영구적으로 삭제되며, 이 작업은 되돌릴 수 없습니다.
남아 있는 관리형 워크트리는 [동일한 백업 규칙](/ko/docs/worktrees#automatic-cleanup)에 따라 정리
대상이 되며, 로컬 Git 브랜치와 커밋은 유지됩니다.

프로젝트를 선택하지 않은 세션의 경우 삭제 시 Lody가 관리하는 채팅 작업 디렉터리와 내부의 모든 파일도
백업이나 복구 없이 함께 삭제됩니다(보관 시에는 빈 디렉터리만 회수됩니다).

## 일괄 복원 및 삭제

대화 위에 마우스를 올리고 앞쪽의 체크박스를 클릭하면 다중 선택 모드로 전환됩니다. 그런 다음
더 보기 작업을 클릭해 일괄 선택한 뒤, 오른쪽 위의 컨트롤에서 일괄 복원 또는 삭제를 선택하세요.
