# 워크트리

워크트리는 Lody가 동시 작업을 격리하고 관리하는 기반입니다.

## 워크트리란 무엇인가요?

Git 워크트리(worktree)는 리포지토리의 연결된 작업 사본입니다. 각 워크트리는 별도의 체크아웃된 브랜치를 가진 자체 작업 디렉터리를 가지지만, 메인 리포지토리와 동일한 Git 히스토리를 공유합니다.

## Lody의 워크트리 사용 방식

Lody에서 작업을 생성하면 다음 단계가 자동으로 수행됩니다.

1. **새 브랜치 생성** - 기본 이름은 `session/<shortSessionId>`입니다(`sessionId`의 처음 8자이며, 이름을 변경할 수 있습니다)
2. **워크트리 설정** - 에이전트가 작업하는 격리된 디렉터리입니다(세션당 하나)
3. **설정 스크립트 실행** - 의존성 설치나 환경 변수 템플릿 복사 등 선택적인 프로젝트 수준 명령어입니다
4. **변경 사항 동기화** - 웹 UI에서 실시간 업데이트를 확인할 수 있습니다

```
~/.lody/repos/<repoId>/
├── bare.git/                # 베어 Git 리포지토리 (공유 히스토리)
├── cache/                   # 빌드 캐시 등
└── worktrees/
    ├── <sessionId-1>/       # 세션 1용 워크트리
    └── <sessionId-2>/       # 세션 2용 워크트리
```

## 장점

### 병렬 실행

각 작업마다 자체 워크트리를 가지므로 에이전트가 서로의 변경 사항에 영향을 주지 않습니다.

### 깔끔한 격리

- 작업 간에 커밋되지 않은 변경 사항이 섞이지 않습니다
- 개별 작업을 쉽게 검토, 승인 또는 폐기할 수 있습니다
- 작업별 PR 생성이 간편합니다

### 자동 정리

루트 세션을 보관(Archive)하면 Lody가 관리하는 해당 세션의 워크트리가 정리 대상이 됩니다. 대화는 영구 삭제 전까지 보관 목록에 남아 있지만, 작업 디렉터리는 그보다 먼저 삭제될 수 있습니다.

| 리소스 | 보관 및 정리 후 | 세션 영구 삭제 후 |
| --- | --- | --- |
| 대화 히스토리 | 유지됨 (세션 복원 가능) | 삭제됨 (세션 삭제는 되돌릴 수 없음) |
| Lody 관리 워크트리 디렉터리 | 소유 머신에 의해 삭제됨 | 아직 남아 있는 경우 정리 대상이 됨 |
| 로컬 Git 브랜치 및 커밋 | 백업 커밋을 포함해 유지됨 | 유지됨 (삭제 시 브랜치는 회수되지 않음) |
| Git 무시 대상이 아닌 대기 중 변경 사항 | 삭제 전 로컬에 스테이징 및 커밋됨 | 남아 있는 워크트리에 동일한 백업 규칙 적용 |
| `.env`, 의존성, 빌드 출력 등 무시된 파일 | 디렉터리와 함께 폐기될 수 있음 | 복구 보장 없음 |
| 원본 로컬 프로젝트 디렉터리 | 관리형 워크트리 정리 대상에서 제외됨 | 관리형 워크트리 정리 대상에서 제외됨 |

소유 데몬은 워크스페이스 메타데이터가 완료되고 세션 런타임이 해제된 후에만 자신의 Lody 데이터 디렉터리 아래에 있는 워크트리를 정리합니다. 해당 머신이 오프라인 상태이거나 삭제에 실패하면 정리가 지연될 수 있습니다. 활성 상태이거나 소유자를 알 수 없는 항목은 그대로 유지되며, 하위 탭만 보관하더라도 루트 세션의 공유 워크트리는 삭제되지 않습니다. 리포지토리를 확인할 수 없거나 백업 커밋에 실패하면 재시도를 위해 디렉터리가 보존됩니다.

이 백업은 원격 푸시나 전체 디렉터리 백업이 아니라 로컬 Git 커밋입니다. 설정된 정리 스크립트는 백업 전에 실행되므로, 스크립트가 삭제하거나 변경한 파일은 이 보호 범위에서 제외됩니다. 스크립트가 실패하더라도 삭제는 중단되지 않습니다. 보관하기 전에 필요한 무시된 파일과 스크립트의 영향을 받는 파일을 워크트리 외부에 저장해 두세요.

워크트리가 삭제된 세션을 복원하여 계속 진행하면 Lody가 보존된 로컬 브랜치에서 워크트리를 다시 생성하고 설정 스크립트를 다시 실행합니다. 무시된 파일은 별도로 다시 생성해야 합니다. 복구하려면 소유 리포지토리와 브랜치가 여전히 존재해야 하며, 삭제된 로컬 프로젝트는 다시 추가해야 합니다. Lody 리포지토리 데이터를 수동으로 삭제하면 해당 로컬 브랜치와 백업도 함께 삭제되므로, 세션을 보관하거나 삭제하는 것과는 다릅니다.

## 워크트리 설정 및 정리 스크립트

프로젝트 수준 스크립트를 사용하면 모든 새 세션을 일관되게 준비할 수 있습니다.

Lody가 워크트리를 생성한 후 에이전트가 첫 번째 프롬프트를 받기 전에 실행해야 하는 명령어에는 **설정 스크립트(setup script)**를 사용하세요. 예를 들면 다음과 같습니다.

```bash
cp .env.example .env
pnpm install
```

대화가 보관될 때 Lody가 디스크에서 워크트리를 제거하기 전에 실행해야 하는 명령어에는 **정리 스크립트(cleanup script)**를 사용하세요. 예를 들면 다음과 같습니다.

```bash
rm -rf node_modules
```

### 스크립트 구성

1. **Settings** -> **Projects**를 엽니다.
2. 로컬 프로젝트 또는 GitHub 리포지토리를 선택합니다.
3. **Worktree setup**과 **Worktree cleanup**을 엽니다.
4. 프로젝트에 필요한 셸의 명령어를 추가한 다음, 편집기에서 벗어나 저장합니다.

로컬 프로젝트의 경우 Lody는 해당 프로젝트의 머신에서 사용하는 셸을 표시합니다. Windows는 PowerShell을 사용하고, macOS, Linux 및 WSL은 Bash를 사용합니다. GitHub 리포지토리의 경우 서로 다른 머신에서도 세션이 동작할 수 있도록 Bash와 PowerShell을 모두 입력할 수 있습니다.

스크립트는 워크트리 디렉터리에서 실행됩니다. 스크립트 내부에서 내보낸 환경 변수는 해당 스크립트 프로세스 동안만 유지됩니다. 에이전트 자체가 환경 변수를 필요로 하는 경우 [에이전트 설정](/ko/docs/quickstart)에서 설정하세요.

### 사용 가능한 환경 변수

Lody는 설정 스크립트와 정리 스크립트 모두에 대해 다음 환경 변수를 설정합니다.

| 변수 | 설명 |
| --- | --- |
| `LODY_WORKSPACE_ID` | 현재 워크스페이스 ID |
| `LODY_SESSION_ID` | 현재 대화/세션 ID |
| `LODY_WORKTREE_PATH` | 세션 워크트리의 절대 경로 |
| `LODY_WORKTREE_BRANCH` | 워크트리에 체크아웃된 브랜치 |
| `LODY_WORKTREE_SCRIPT_PHASE` | `setup` 또는 `cleanup` |
| `LODY_GITHUB_REPO` | GitHub 리포지토리 전체 이름 (GitHub 프로젝트 전용) |
| `LODY_LOCAL_PROJECT_ID` | 로컬 프로젝트 ID (로컬 프로젝트 전용) |

스크립트 프로세스는 현재 작업 디렉터리가 `LODY_WORKTREE_PATH`로 설정된 상태로 시작되므로, 명령어에서 `pwd` 또는 명시적 환경 변수를 모두 사용할 수 있습니다.

```bash
echo "$LODY_SESSION_ID"
echo "$LODY_WORKTREE_PATH"
pnpm install
```
