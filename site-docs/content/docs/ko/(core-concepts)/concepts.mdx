# 개념 및 용어집

Lody의 대부분은 모든 화면에 동일한 방식으로 배치된 소수의 핵심 객체로 구성됩니다. 이 페이지를 한 번 읽어 두시면 이후 가이드의 맥락을 훨씬 쉽게 파악할 수 있습니다.

## 기본 구조 (멘탈 모델)

```text
workspace
├── projects / repositories
│   └── session            하나의 작업, 하나의 대화, 하나의 브랜치/워크트리
│       ├── round          에이전트 1턴 + 해당 턴에서 만든 변경 사항
│       ├── side chat      메인 작업을 중단하지 않고 분기(fork)해서 묻는 질문
│       └── pull request   리뷰 후 선택적으로 진행하는 GitHub 전달
├── agent configs          런타임 + 인증 정보 + 머신
│   └── agent roles        저장된 머신 + 설정 + 모델 + 권한
└── teammates              공유된 세션은 볼 수 있지만 개인 머신은 볼 수 없음
```

사용자가 가장 많은 시간을 보내는 대상은 세션입니다. 그 밖의 모든 요소는 세션에 입력되는 요소(프로젝트, 리포지토리, Agent Config, 역할)이거나 세션에서 만들어지는 결과물(diff, Pull Request, 핸드오프)입니다.

## 작업의 흐름

1. **프로젝트 또는 리포지토리를 추가합니다.** [로컬 프로젝트](/ko/docs/local-project)는 로컬 디렉터리를 의미하며, [GitHub 리포지토리](/ko/docs/github)를 연결하면 Pull Request, CI, 리뷰 동기화 기능이 추가됩니다.
2. **실행할 대상을 선택합니다.** [Agent Config](/ko/docs/quickstart)는 런타임을 머신 및 해당 머신의 인증 정보와 연결합니다. [Agent Role](/ko/docs/agent-roles)은 자주 사용하는 조합을 저장해 둔 설정입니다.
3. **세션을 엽니다.** 홈 화면의 입력창(composer)에서 프로젝트, 브랜치, 설정, 모델, 권한 범위를 선택합니다. 자세한 내용은 [세션](/ko/docs/session)을 참고하세요.
4. **라운드 단위로 작업합니다.** 각 라운드는 에이전트 1턴과 그 결과인 diff로 이루어집니다. [Diff Viewer](/ko/docs/diff-viewer)로 변경 사항을 검토하고 [Diff Comments](/ko/docs/diff-comments)로 코멘트를 남깁니다.
5. **작업을 마무리합니다.** Pull Request를 생성하거나 브랜치를 유지하거나 세션을 보관(archive)합니다. 자세한 내용은 [권장 워크플로](/ko/docs/workflow)를 참고하세요.

## 핵심 객체

| 용어 | 설명 | 더 알아보기 |
| --- | --- | --- |
| **워크스페이스 (Workspace)** | 멤버, 공유 머신, 세션, 설정을 담는 팀 단위 컨테이너입니다. | [팀 기능](/ko/docs/team) |
| **프로젝트 / 리포지토리** | 세션이 작업하는 코드 대상(로컬 디렉터리 또는 GitHub 리포지토리)입니다. | [로컬 프로젝트](/ko/docs/local-project) · [GitHub 연동](/ko/docs/github) |
| **세션 (Session)** | 하나의 대화, 하나의 브랜치, 그리고 보통 하나의 워크트리를 가지는 단일 작업 단위입니다. | [세션](/ko/docs/session) |
| **라운드 (Round)** | 에이전트 1턴과 그 턴에서 생성된 파일 변경 사항입니다. | [Diff Viewer](/ko/docs/diff-viewer) |
| **워크트리 (Worktree)** | 두 세션이 같은 리포지토리를 충돌 없이 동시에 편집할 수 있도록 격리된 체크아웃입니다. | [워크트리](/ko/docs/worktrees) |
| **Agent Config** | 런타임(Claude Code, Codex, Kimi, ACP 등)과 인증 정보, 실행 머신을 하나로 묶은 구성입니다. | [Agent Config](/ko/docs/quickstart) · [CLI 런타임 유형](/ko/docs/cli-runtimes) |
| **Agent Role** | 머신, Agent Config, 모델, 추론(reasoning) 수준, 권한, 선택적 지침을 조합해 저장한 프리셋입니다. | [Agent Roles](/ko/docs/agent-roles) |

## 각 요소의 관계

<Accordions>
<Accordion title="세션 vs. 라운드 vs. 턴">
**세션(session)**은 작업 전체와 그 기록을 말합니다. **라운드(round)**는 에이전트 1턴과 그에 따른 diff를 함께 일컫습니다. 이 문서에서 "라운드 리뷰하기"라고 표현할 때는 다음 단계로 넘어가기 전에 해당 턴이 생성한 diff를 확인한다는 의미입니다.
</Accordion>
<Accordion title="Agent Config vs. Agent Role">
**Agent Config**는 "이 머신에서 무엇을 실행할 수 있고 어떻게 인증하는가?"에 대한 답입니다. **Agent Role**은 "이런 종류의 작업을 시작할 때 어떤 머신, 설정, 모델, 권한을 선택해야 하는가?"에 대한 답입니다. Role은 Config를 참조하지만, Config는 Role을 참조하지 않습니다.
</Accordion>
<Accordion title="Fork vs. 사이드 챗 vs. 핸드오프">
- **Fork**는 대화를 새 세션으로 복사하여 다른 방향을 시도해 볼 수 있게 합니다.
- **사이드 챗(Side Chat)**은 간단한 질문을 위해 메인 채팅 옆에 고정해 두는 Fork입니다.
- **핸드오프(Handoff)**는 복사본을 만들지 않고 같은 세션에 팀원을 초대하는 기능입니다. 자세한 내용은 [코딩 에이전트 세션 공유](/ko/docs/session-handoff)를 참고하세요.
</Accordion>
<Accordion title="병렬 세션 vs. Agent Session Control">
- **병렬 세션(Parallel sessions)**은 사용자가 직접 여러 세션을 시작하는 방식으로, 각 세션이 고유한 작업과 워크트리를 가집니다. 자세한 내용은 [병렬 코딩 에이전트](/ko/docs/parallel-agents)를 참고하세요.
- **Agent Session Control**은 에이전트가 Lody의 MCP 도구를 통해 다른 세션을 생성하고, 조종(steer)하며, 결과를 수집하는 기능입니다. 자세한 내용은 [Agent Session Control](/ko/docs/session-orchestration)을 참고하세요.
</Accordion>
</Accordions>

## 자주 등장하는 용어집

| 용어 | 의미 |
| --- | --- |
| **ACP** | Agent Client Protocol의 약자로, Lody가 다양한 코딩 에이전트 CLI를 실행하고 통신할 때 사용하는 인터페이스입니다. 자세한 내용은 [CLI 런타임 유형](/ko/docs/cli-runtimes)을 참고하세요. |
| **MCP** | Model Context Protocol의 약자입니다. Lody는 에이전트가 Lody 대화 및 기타 리소스를 다룰 수 있도록 기본 내장 MCP 도구를 제공합니다. |
| **데몬 (Daemon)** | 머신에서 실제로 에이전트를 실행하는 백그라운드 Lody CLI 프로세스입니다. 자세한 내용은 [CLI 명령어](/ko/docs/cli)를 참고하세요. |
| **권한 범위 (Permission scope)** | 파일 편집이나 셸 명령어 실행 등 에이전트가 사용자 확인 없이 수행할 수 있는 작업 범위입니다. 입력창에서 세션별로 설정합니다. |
| **컨텍스트 윈도우 (Context window)** | 모델이 한 번에 유지할 수 있는 대화량입니다. Lody는 채팅 화면에 남은 용량을 표시합니다. 자세한 내용은 [컨텍스트, 토큰 및 할당량](/ko/docs/usage-and-quota)을 참고하세요. |
| **핸드오프 (Handoff)** | 진행 중인 세션에 팀원을 초대하여 동일한 대화, diff, 워크트리를 이어서 작업하게 하는 기능입니다. |
| **오케스트레이션 (Orchestration)** | 하나의 에이전트가 다른 세션을 생성하고, 메시지를 보내고, 결과를 수집하도록 하는 작업 방식입니다. |

## 자주 묻는 질문

### Agent Config와 Agent Role의 차이는 무엇인가요?

Agent Config는 런타임과 해당 런타임의 인증 정보 및 실행 머신을 묶은 설정입니다. Agent Role은 머신, Agent Config, 모델, 추론 수준, 권한에 선택적 지침까지 함께 선택해 저장해 둔 프리셋으로, 세션을 시작할 때 동일한 구성을 재사용할 수 있게 해 줍니다. 자세한 내용은 [Agent Config](/ko/docs/quickstart)와 [Agent Roles](/ko/docs/agent-roles)를 참고하세요.

### 세션을 Fork하는 것과 핸드오프하는 것의 차이는 무엇인가요?

Fork는 대화를 내가 소유한 새 세션으로 복사합니다. 반면 핸드오프는 기존 세션에 다른 사람을 초대하여 두 사람이 동일한 실시간 채팅, diff, 워크트리를 함께 보며 작업할 수 있게 합니다. Fork는 원래 세션에 아무도 추가하지 않습니다. 자세한 내용은 [세션](/ko/docs/session)과 [코딩 에이전트 세션 공유](/ko/docs/session-handoff)를 참고하세요.

### Lody를 사용하려면 워크트리를 이해해야 하나요?

워크트리 디렉터리를 직접 열어 보지 않고도 Lody를 사용할 수 있습니다. 워크트리는 여러 세션을 동시에 실행할 때 중요해지며, 각 세션의 편집 내용이 서로 섞이지 않도록 분리해 주는 역할을 합니다. 자세한 내용은 [워크트리](/ko/docs/worktrees)를 참고하세요.

### "작업(task)"은 세션과 같은 의미인가요?

이 문서에서는 그렇습니다. 보통 하나의 작업이 하나의 세션, 하나의 브랜치, 하나의 Pull Request에 해당합니다. 왜 작은 단위의 작업이 더 효과적인지는 [권장 워크플로](/ko/docs/workflow)에서 설명합니다.
