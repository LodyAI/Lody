# 권한 원장

모든 종단 간 암호화 워크스페이스에는 **권한 원장(permission ledger)**이 있습니다. 암호화 콘솔에서는 변경 기록으로 표시됩니다. 원장은 누가 멤버인지, 각 멤버의 역할이 무엇인지, 그리고 어떤 기기가 키를 받을 수 있는지를 결정합니다.

## 원장이 기록하는 내용

원장은 각각 하나의 변경 사항을 설명하는 레코드의 순서가 정해진 목록입니다. 예를 들면 다음과 같습니다.

- 워크스페이스 생성(첫 번째 레코드, "제네시스(genesis)")
- 멤버 승인, 역할 변경, 멤버 제거
- 기기 추가 또는 폐기
- 워크스페이스 키 교체
- 소유권 이전

원장에는 **계정 ID와 기기 공개 키**만 기록되며, 대화나 파일은 절대 기록되지 않습니다. 이름과 아바타는 계정 프로필에서 가져오며 원장에 포함되지 않습니다.

## 모든 레코드는 서명됩니다

각 레코드는 변경을 수행하는 사람이 **자신의 승인된 개인 기기에서** 서명합니다. 서명에는 작업 내용, 대상, 워크스페이스가 포함되므로 어느 하나라도 변경되면 서명이 무효화됩니다.

서버는 레코드를 저장하고 중계할 뿐 **누구의 서명 키도 보유하지 않으므로**, 다른 사람 대신 서명하거나 몰래 멤버 또는 기기를 추가할 수 없습니다.

## 레코드는 체인을 이룹니다

각 레코드는 이전 레코드의 해시를 포함하며, 이는 맨 처음 제네시스 레코드까지 이어집니다.

- 레코드를 하나라도 삭제, 삽입하거나 순서를 바꾸면 체인이 끊어지며, 기기가 이를 감지합니다.
- 새 레코드는 현재 체인의 끝에만 추가할 수 있습니다. 두 사람이 동시에 제출하면 한 명만 성공하고, 다른 한 명은 새로고침한 뒤 다시 확인해야 합니다.
- 변경 사항은 커밋된 순서대로 적용됩니다. 소유자가 B를 제거하기 전에 B가 C를 초대해 승인되었다면 C는 멤버로 남습니다. 반대로 제거가 먼저 커밋되면 B가 이전에 보낸 초대는 더 이상 유효하지 않습니다.

## 작업별 서명 권한

모든 변경 사항에 대해 기기는 서명자가 처음 참여했을 때의 권한이 아니라, **해당 변경 직전 시점의 원장 상태를 기준으로** 서명자의 권한을 확인합니다.

| 변경 사항 | 서명 가능 대상 |
| --- | --- |
| 멤버 승인 | 소유자 또는 관리자 |
| 멤버 제거 | 소유자 또는 관리자 |
| 관리자 제거, 역할 변경 | 소유자만 가능 |
| 소유권 이전 | 소유자만 가능; 이전 소유자는 관리자가 됩니다 |
| 본인 새 기기 추가 | 본인의 승인된 기기 중 하나; 모두 분실한 경우 복구 파일 |
| 기기 폐기 | 해당 기기의 소유자 또는 관리 권한이 있는 멤버 |
| 워크스페이스 키 교체 | 소유자 또는 관리자 |

원격 머신과 복구 기기는 **관리 권한을 절대 갖지 않으며**, 키를 수신해 작업을 수행할 뿐입니다.

## 기기가 원장을 검증하는 방식

- **기존 기기**는 새 레코드가 이전 레코드와 연결되어 있고, 서명이 유효하며, 해당 시점에 서명자에게 권한이 있는 경우에만 수락합니다.
- **새로 합류한 기기**가 항상 제네시스부터 다시 재생하는 것은 아닙니다. 소유자나 관리자의 기기가 서명한 "현재 상태" 스냅샷을 수락한 뒤, 그 이후의 모든 레코드를 검증할 수 있습니다. 즉, 스냅샷 서명자를 신뢰해야 합니다.
- **검증에 실패하면** 기기는 마지막으로 신뢰한 레코드에서 멈추고, 증거를 보존한 채 초대 및 승인 작업을 일시 중지합니다. 자동으로 **복구하거나 건너뛰는 일은 절대 없습니다**. 기존 대화는 계속 읽을 수 있습니다.

## 키 폐기 및 교체

- 기기를 폐기하면 해당 기기에만 영향을 미칩니다. 노트북을 폐기하더라도 그 노트북이 이전에 승인했던 휴대폰까지 함께 폐기되지는 않습니다.
- 멤버를 제거하면 해당 멤버의 모든 기기가 즉시 차단됩니다. 그 후에는 **워크스페이스 키를 교체**해야 합니다. 새 키는 여전히 승인된 기기에만 전달되므로, 이전 키를 가진 기존 기기는 새 콘텐츠를 복호화할 수 없습니다. 이미 기기에 다운로드된 기록은 회수할 수 없습니다.

## 원장이 전제하는 조건

원장은 서버가 어떤 서명도 **위조**하지 못하도록 막아 줍니다. 다만 원장 자체만으로는 모든 사람이 **동일한 최신** 원장을 보유하고 있는지 보장할 수 없습니다.

현재 버전은 서버가 롤백되거나 분기(fork)되지 않은 완전한 원장을 제공한다고 가정합니다. 서버가 서로 다른 사람에게 다른 버전의 원장을 보여 주더라도 서명을 위조할 수는 없지만, 일부 사용자에게 폐기 사실을 숨길 수는 있습니다.

이를 확인하기 위해 [보안 코드](/ko/docs/encrypted-workspaces-security-code)가 있습니다. 팀원과 코드를 비교하면 서로 동일한 원장을 보유하고 있는지 확인할 수 있습니다.
