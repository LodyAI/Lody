# 보안 코드

보안 코드는 **사용자와 팀원이 동일한 [권한 원장](/ko/docs/encrypted-workspaces-ledger)**, 즉 동일한 멤버, 동일한 기기, 동일한 권한 정보를 가지고 있음을 확인하는 숫자 문자열입니다.

본인의 코드가 다른 멤버나 사용자의 다른 기기에 표시되는 코드와 일치하면, 워크스페이스의 멤버 및 권한 정보가 일관되게 유지되고 있다는 뜻입니다.

## 필요한 이유

모든 원장 레코드에는 서명이 포함되어 있어 서버가 레코드를 위조할 수는 없습니다. 하지만 서버가 **서로 다른 사용자에게 서로 다른 버전의 원장을 보여 줄 수는 있습니다**. 예를 들어 특정 기기의 권한을 회수한 레코드를 사용자에게만 숨기는 경우입니다. 자신의 사본만 확인해서는 이러한 조작을 알아차릴 수 없습니다.

두 사람이 각자 독립적으로 계산한 코드를 비교하면 이러한 차이를 밝혀낼 수 있습니다.

## 계산에 포함되는 항목

보안 코드는 다음 항목을 모두 함께 요약한 다이제스트입니다.

- 프로토콜 버전과 용도
- 워크스페이스와 첫 번째 레코드(제네시스)
- 원장의 현재 위치(레코드 수)와 마지막 레코드
- **현재의 전체 권한 상태**: 모든 멤버, 역할, 기기 및 공개 키

마지막 레코드만 비교하는 것으로는 충분하지 않습니다. 변조된 상태라도 겉보기에는 정상적인 마지막 레코드를 가질 수 있기 때문입니다. 실제 권한 상태가 코드 계산에 포함되는 이유가 바로 이 때문입니다.

QR 코드에는 원장의 위치 정보도 함께 담겨 있으므로, 스캔을 통해 어느 쪽이 뒤처져 있는지 바로 확인할 수 있습니다.

## 비교 결과의 의미

| 결과 | 의미 | 대처 방법 |
| --- | --- | --- |
| 일치함 | 동일한 위치에서 동일한 멤버, 기기, 권한을 수락한 상태 | 별도 조치 불필요 |
| 한쪽이 구버전임 | 한쪽 원장이 이전 시점의 상태이며, 해당 지점까지의 내용은 모두 동일함 | 양쪽 모두 새로고침 후 다시 비교 |
| 서로 다름 | 동일한 위치이나 내용이 다름 | 아무도 초대하거나 승인하지 말고 워크스페이스 소유자에게 알리기 |

위치가 다르다고 해서 반드시 공격을 받은 것은 아닙니다. 보통은 한쪽이 아직 동기화되지 않았을 뿐입니다.

## 증명할 수 없는 것

- **상대방이 누구인지**: 보안 코드는 양측의 레코드가 일치한다는 사실만 보여 줍니다. 실제로 알고 있는 팀원과 비교하고 있는지 확인하세요.
- **과거의 모든 변경 사항이 타당했는지**: 양측이 동일한 상태를 수락했다는 점을 보여 줄 뿐, 그 과정의 각 단계가 적절했는지까지는 보장하지 않습니다.
- **앞으로도 계속 안전한지**: 보안 코드는 해당 시점의 특정 위치만을 검증합니다. 새 레코드가 추가되면 코드가 바뀌므로, 중요한 순간에는 다시 비교해야 합니다.
- **초대한 사람과만 비교했을 때의 신뢰성**: 자신을 초대한 사람과 서버가 공모했다면 그 사람과의 코드 일치는 큰 의미가 없습니다. 최소한 다른 멤버 한 명 이상과도 비교하세요.

## 비교 방법

<Steps>
<Step>

두 사람 모두 암호화 콘솔에서 보안 코드 및 기록(Security code & history)을 열고 새로고침합니다.

</Step>
<Step>

팀원과 비교(Compare with a teammate)를 선택하고 상대방 화면의 QR 코드를 스캔하거나, 숫자 그룹을 소리 내어 읽어 확인합니다.

</Step>
<Step>

결과에 따라 조치합니다. 직접 만나서 확인하거나 영상 통화, 전화 모두 가능하지만, Lody 자체를 통해서만 서로 코드를 주고받지는 마세요.

</Step>
</Steps>
