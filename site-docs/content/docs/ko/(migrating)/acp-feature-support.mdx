# ACP 및 확장 기능 지원

이 페이지는 Codex, Claude Code 또는 다른 ACP 에이전트에서 넘어오면서 어떤 기능들이 그대로 이어지는지 확인하려는 사용자를 위한 문서입니다. ACP가 무엇인지, Lody가 이를 어떻게 확장하는지, 그리고 각 기본 제공 프로바이더가 무엇을 지원하는지 설명합니다. 아직 런타임을 연결하지 않으셨다면 [Codex 또는 Claude Code에서 넘어오기](/ko/docs/from-codex-claude-code) 또는 [에이전트 설정](/ko/docs/quickstart)부터 살펴보세요.

## ACP란 무엇인가요?

[Agent Client Protocol](https://agentclientprotocol.com/)(ACP)은 사용자가 사용하는 앱인 클라이언트와 실제 작업을 수행하는 에이전트 간의 오픈 프로토콜입니다. Lody는 ACP 클라이언트로 동작합니다. 프로바이더의 ACP 서버를 실행하고 `initialize` 단계에서 지원 기능을 협상한 뒤, 하나의 연결을 통해 프롬프트, 스트리밍 업데이트, 도구 호출(tool call), 권한 요청, 세션 수명 주기 이벤트를 주고받습니다.

ACP는 공통 핵심 기능만을 다루기 때문에, 두 ACP 에이전트라도 이미지, 임베디드 컨텍스트(embedded context), 세션 재개(resume) 또는 포크(fork), MCP 전송 방식(transport), 사용자 입력 요청(elicitation) 같은 선택적 기능에서는 차이가 날 수 있습니다. 그렇기 때문에 Lody는 기능을 미리 가정하지 않고 협상 절차를 거칩니다. 텍스트 프롬프트, 스트리밍 업데이트, 도구 호출, 권한 요청, 작업 취소, 그리고 Lody의 파일시스템 및 터미널 콜백 같은 기본 기능은 모든 기본 제공 프로바이더에서 동일하게 동작합니다.

## Lody의 ACP 확장 방식

Lody 고유의 기능은 ACP v1 위에 구축된 프로바이더 중립적 계약인 [`acp-extension-core`](https://github.com/LodyAI/acp-extension-core)에 정의되어 있습니다. 서브에이전트 이벤트 스트리밍, 사용량 집계, 속도 제한(rate limit), 지속형 목표(durable goal), 컨텍스트 압축(compaction) 같은 기능에는 안정적인 공통 명세가 필요하므로, 각 기능은 `_meta.lody` 아래에 개별적으로 버전이 지정되어 선언됩니다.

- 에이전트는 구현한 기능을 `InitializeResponse.agentCapabilities._meta.lody`를 통해 알립니다.
- 클라이언트는 자체 지원 기능을 `InitializeRequest.clientCapabilities._meta.lody`를 통해 알립니다.
- 특정 키가 누락되어 있으면 상대방이 해당 기능을 지원하지 않음을 의미하며, 한 기능의 지원 여부가 다른 기능의 지원을 의미하지는 않습니다.

공개 `acp-extension-*` 어댑터는 각 런타임을 이 계약 형식에 맞게 변환하므로, Lody 클라이언트는 연결 뒤에 어떤 프로바이더가 있든 동일한 구조로 데이터를 읽습니다. 커스텀 ACP 에이전트나 레지스트리 ACP 에이전트도 동일한 키를 구현할 수 있습니다. 정확한 페이로드 명세는 [기능 카탈로그(capability catalog)](https://github.com/LodyAI/acp-extension-core#capability-catalog)를 참고하세요.

### 확장 기능 레퍼런스

`Lody:` 열은 프로바이더가 선언하는 기능을 나타냅니다. 각 열에 해당하는 프로바이더 측 기능은 다음과 같습니다.

- **서브에이전트 이벤트 (subagent events)** — 어댑터가 `_lody/subagents/event`를 통해 하위 에이전트의 스냅샷, 진행 상황, 출력을 스트리밍합니다.
- **세션 제목 (session title)** — 어댑터가 제목을 생성하여 `_meta.lody.titleSource` 태그가 포함된 표준 `session_info_update`로 전송합니다.
- **사용량 (usage)** — 모델별 합계를 포함한 컨텍스트 및 토큰 사용량을 표준 `usage_update`로 집계합니다.
- **속도 제한 (rate limits)** — `_lody/rate_limits/update`를 통해 할당량 스냅샷을 전달하며, 선택적으로 `_lody/rate_limits/get` 쿼리를 지원합니다.
- **턴 기준 포크 (fork at turn)** — `session/fork`에서 포크할 이전 턴을 지정할 수 있습니다.
- **스티어링 (steering)** — `_lody/session/steer` 또는 `_meta.lody.steer`를 통해 진행 중인 턴에 지침을 주입할 수 있습니다.
- **태스크 (tasks)** — 백그라운드 작업 또는 예약된 작업을 `_meta.lody.task`와 함께 일반 도구 호출 수명 주기로 보고합니다.
- **서브에이전트 (subagents)** — 서브에이전트 수명 주기 관리와 함께 선택적으로 목록 조회, 취소, 출력 조회 쿼리를 지원합니다.
- **목표 (goal)** — 단일 프롬프트를 넘어 유지되는 지속형 세션 목표(durable session goal)로, 설정(set), 일시 중지(pause), 재개(resume), 초기화(clear) 동작을 지원합니다.
- **컨텍스트 압축 (compaction)** — 컨텍스트 압축 및 재시도를 `_meta.lody.activity`와 함께 도구 수명 주기로 보고합니다.

참고:

1. **태스크:** Claude Code, Codex, Kimi Code, DeepSeek Harness는 백그라운드 태스크를 선언하고, Grok은 예약된 태스크를 선언합니다. 두 가지를 모두 선언하는 프로바이더는 없습니다.
2. **서브에이전트:** Claude Code와 Codex는 수명 주기만 선언하며, 목록 조회·취소·출력 쿼리는 지원하지 않습니다.
3. **Grok 태스크**는 예약된 태스크만 지원합니다.
4. **Kimi Code 세션 제목**은 설치된 Kimi 엔진이 제목 기능을 지원할 때만 선언되며, 그렇지 않은 경우에는 Lody가 직접 제목을 생성합니다.
5. **DeepSeek Harness 이미지 입력**은 선택한 모델에 따라 다릅니다. 활성 모델이 이미지 입력을 지원하는 경우에만 어댑터가 해당 기능을 활성화합니다.
6. **Dimcode MCP:** Dimcode는 Streamable HTTP와 SSE는 지원한다고 선언하지만, stdio MCP는 미지원으로 보고합니다.

`ACP: MCP` 열에서 `HTTP+SSE`는 프로바이더가 두 전송 방식을 모두 선언함을 의미하고, `HTTP`는 HTTP만 선언함을 의미합니다. Stdio MCP는 일반적인 ACP 기본 사양이며, Dimcode만 참고 6에 해당하는 예외입니다. `Devin`과 `Grok`의 표준 ACP 열은 공식 런타임 기준을 반영하고, Lody 열은 Lody 호환성 프록시가 추가하는 기능을 보여줍니다. `Bub`과 `Dimcode`는 Lody가 실행하는 외부 ACP 서버로, 해당 행에는 직접 구현한 Lody 확장을 포함해 각 서버가 자체적으로 선언하는 기능이 반영되어 있습니다.

위 지원 정보는 Lody 어댑터 및 외부 ACP 서버에 기본 포함된 기능 선언을 기준으로 작성되었습니다. Lody는 세션 시작 시 협상 결과를 읽어오므로, 프로바이더가 업데이트되면 이 페이지가 갱신되기 전이라도 앱에 표시되는 지원 항목이 달라질 수 있습니다. 표준 ACP 구현체들의 버전별 독립 비교 자료는 [ACP Wall](https://github.com/wibus-wee/acp-wall)을 참고하세요.
