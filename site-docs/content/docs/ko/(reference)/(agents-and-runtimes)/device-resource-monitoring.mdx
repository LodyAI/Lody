# 디바이스 리소스 모니터링

Lody는 연결된 각 디바이스와 해당 디바이스에 상주하는 모든 ACP 세션의 현재 리소스 사용량을 보여줍니다. 이 화면에서 CPU나 메모리를 많이 사용하는 에이전트를 찾거나, 해당 세션을 열거나, 대화를 삭제하지 않고 ACP 프로세스만 중지할 수 있습니다.

**Settings -> Devices**를 연 다음 온라인 상태인 디바이스를 선택하세요. 페이지가 자동으로 샘플링을 시작하므로 별도의 수동 새로고침 버튼은 없습니다.

## 상주 ACP 세션이란 무엇인가요?

각 대화는 코딩 에이전트와 통신하기 위해 ACP 프로세스를 사용합니다. 이 프로세스는 턴이 유휴 상태가 된 후에도 계속 상주할 수 있는데, 이를 통해 다음 턴을 더 빠르게 시작할 수 있는 대신 메모리를 계속 일부 사용하게 됩니다. ACP 세션 테이블에는 선택한 디바이스에 현재 에이전트 프로세스가 존재하는 대화 목록이 표시됩니다.

이 목록은 저장된 모든 대화의 목록이 아니라 프로세스 보기입니다. ACP 프로세스가 이미 중지된 대화는 Lody에 그대로 남아 있지만, 이 테이블에는 더 이상 표시되지 않습니다.

## 리소스 요약

페이지 상단에는 수치가 실수로 합산되지 않도록 세 가지 범위가 구분되어 표시됩니다.

| 범위 | CPU | 메모리 |
| --- | --- | --- |
| **CLI** | Lody CLI 제어 프로세스 자체의 CPU 사용량 | Lody CLI 제어 프로세스가 사용하는 메모리 |
| **ACP 세션 (ACP sessions)** | 상주 ACP 세션 프로세스 트리가 사용하는 총 CPU | 상주 ACP 세션 프로세스 트리가 사용하는 총 메모리 |
| **디바이스 정보 (Device info)** | Lody, 에이전트, OS 및 기타 애플리케이션을 포함해 전체 디바이스가 사용하는 CPU | 디바이스의 사용 중인 메모리 / 유효 전체 메모리 |

**디바이스 정보(Device info)는 CLI와 ACP 세션의 합계가 아닙니다.** 여기에는 머신에서 실행 중인 다른 모든 프로세스도 포함됩니다. 반대로 CLI와 ACP 값은 전체 디바이스 사용량 중 Lody가 차지하는 비중을 파악하는 데 도움이 됩니다.

### CPU 백분율

세 범위 모두 동일한 멀티 코어 표기 기준을 사용합니다.

- 논리 CPU 코어 1개를 완전히 사용하는 경우 `100%`
- 논리 코어 2개를 완전히 사용하는 경우 `200%`
- 8코어 디바이스의 경우 실질적인 디바이스 최대치는 약 `800%`

예를 들어 코어를 1.5개 사용하는 ACP 세션은 `150%`로 표시됩니다. 짧은 시간 창(window) 동안 샘플을 수집하고 프로세스 트리 집계 방식이 플랫폼마다 다르기 때문에 디바이스, CLI, 전체 합산 값과 세션별 값 사이에 약간의 차이가 발생할 수 있습니다.

### 메모리

메모리는 누적 할당량이 아니라 현재 상주 중인 메모리 사용량(resident footprint)을 나타냅니다. 정확한 집계 방식은 운영체제에 따라 다릅니다. Lody는 사용 가능한 경우 cgroup 집계를 사용하고, 그렇지 않으면 관련 프로세스 트리를 측정합니다. macOS에서는 physical-footprint 기반 보고 값이 RSS만 합산하는 도구에 표시되는 값과 다를 수 있습니다.

디바이스 값은 **사용 중 / 유효 전체(used / effective total)** 형식으로 표시됩니다. Lody가 제한된 환경에서 실행되는 경우 "유효 전체"는 호스트에 장착된 물리적 RAM이 아니라 컨테이너 또는 cgroup 메모리 제한치일 수 있습니다. 가용 메모리, 캐시, 공유 페이지 및 플랫폼별 집계 방식으로 인해 각 행을 수동으로 합산한 값이 디바이스 전체 값과 다를 수 있습니다.

### 값이 `-`로 표시되는 이유

CPU 사용량은 두 샘플 간의 변화량으로 계산되므로 모니터링을 시작하거나 CLI를 재시작한 직후 첫 번째 샘플에서는 표시할 수 없습니다. 또한 운영체제가 해당 세션의 프로세스 트리에 대한 신뢰할 수 있는 집계 정보를 제공하지 못하는 경우에도 CPU, 메모리 또는 프로세스 수가 `-`로 표시될 수 있습니다. 먼저 다음 자동 샘플이 수집될 때까지 기다려 보시고, 그래도 값이 계속 표시되지 않으면 디바이스가 온라인 상태인지와 Lody CLI가 최신 버전인지 확인하세요.

## ACP 세션 테이블

각 행은 상주 중인 하나의 대화를 나타냅니다.

| 열 | 의미 |
| --- | --- |
| **세션 (Session)** | 대화 제목, ACP 이름 및 ACP 로고입니다. 선택하면 해당 세션과 탭이 열립니다. 잘린 제목 위에 마우스를 올리면 전체 제목을 확인할 수 있습니다. |
| **상태 (Status)** | 현재 ACP 수명 주기 또는 활동 상태입니다. |
| **메모리 (Memory)** | 해당 세션의 ACP 프로세스 트리에 할당된 현재 메모리입니다. |
| **CPU** | 해당 프로세스 트리가 사용하는 CPU이며, 논리 코어 1개를 완전히 사용하는 경우 `100%`로 표시됩니다. |
| **프로세스 (Processes)** | 추적 중인 자식 프로세스를 포함해 현재 해당 세션에 속한 프로세스 수입니다. |

이 테이블에는 상주 세션이 최대 100개까지 표시됩니다. 특히 Lody가 프로세스 트리에서 소유권을 추정하는 플랫폼에서는 프로세스 생성이나 종료가 측정값에 반영되기까지 잠깐의 지연이 발생할 수 있습니다.

### 상태 참조

| 상태 | 의미 |
| --- | --- |
| **초기화 중 (Initializing)** | Lody가 ACP 프로세스를 시작하거나 연결하고 있습니다 |
| **실행 중 (Running)** | 에이전트가 현재 턴을 활발히 처리하고 있습니다 |
| **권한 대기 중 (Waiting for permission)** | 권한 요청에 대한 응답이 올 때까지 에이전트가 일시 중지되어 있습니다 |
| **마무리 중 (Finalizing)** | 에이전트가 주요 작업을 마쳤으며 Lody가 최종 처리를 완료하고 있습니다 |
| **유휴 상태 (Idle)** | ACP 프로세스가 상주하고 있지만 현재 턴을 처리하고 있지는 않습니다 |
| **중지 중 (Stopping)** | 종료 요청이 진행 중이며 Lody가 프로세스 종료를 기다리고 있습니다 |
| **실패 (Failed)** | 상주 세션 또는 해당 ACP 프로세스에서 오류가 발생했습니다 |

## ACP 세션의 리소스 해제하기

세션 행 끝에 있는 중지 아이콘을 선택하면 해당 세션의 ACP 프로세스를 종료합니다. 유휴 상태의 프로세스를 중지할 때는 확인 절차 없이 바로 시작됩니다. 에이전트가 실행 중이거나, 초기화 중이거나, 권한 대기 중이거나, 마무리 중인 경우에는 진행 중인 턴이 중단되므로 Lody가 확인을 요청합니다.

ACP 프로세스가 종료되고 디바이스 모니터링에서 해당 세션이 더 이상 상주하지 않음을 확인할 때까지 중지 아이콘에 스피너가 표시됩니다. 종료에 실패하면 Lody가 오류를 보고하며, 세션은 다시 시도할 수 있는 상태로 남습니다.

ACP 프로세스를 종료하면 다음과 같이 동작합니다.

- 현재 에이전트 턴과 추적 중인 자식 프로세스를 중지합니다
- 해당 상주 프로세스 트리가 점유하고 있던 CPU와 메모리를 해제합니다
- 대화 기록, 세션 메타데이터, 브랜치, 워크트리(worktree) 및 프로젝트 파일은 그대로 유지합니다
- 세션을 보관하거나 삭제하지 않으며 디스크 공간을 회수하지도 않습니다

중단된 명령어나 파일 쓰기 작업은 자동으로 롤백되지 않습니다. 에이전트가 변경 사항을 활발히 적용하는 도중에 종료한 경우 세션의 파일과 diff를 직접 검토하세요.

## 나중에 대화 이어서 진행하기

종료된 세션으로 언제든 다시 돌아와 새 메시지를 보낼 수 있습니다. Lody가 ACP 프로세스를 다시 시작하고 저장된 세션 컨텍스트에서 대화를 이어서 진행합니다. 에이전트 런타임이 시작되고 다시 연결되는 동안 첫 번째 새 턴은 시간이 조금 더 걸릴 수 있지만, 대화 내용과 파일은 그동안에도 계속 유지됩니다.

ACP 프로세스가 종료되면 프로세스 로컬에 저장되지 않은 상태는 사라집니다. 지속적인 컨텍스트는 저장된 대화, 에이전트의 재개(resume) 지원, 그리고 세션 워크스페이스의 파일에서 제공됩니다. 활성 작업 사이의 유휴 시간 동안 CPU와 메모리를 해제하려면 프로세스 종료를 사용하고, 세션 표시 여부를 변경하거나 디스크 공간을 회수하려는 경우에만 보관 또는 삭제를 사용하세요. 보관, 복원 및 삭제 동작에 대해서는 [세션](/ko/docs/session)을 참고하세요.

## 실시간 온디맨드 보고

리소스 모니터링은 의도적으로 일시적(ephemeral)으로 동작합니다.

- 누군가 디바이스 페이지를 보고 있을 때만 온라인 디바이스가 리소스 스냅샷을 보고하고 새로고침합니다
- 페이지가 화면에 표시되어 있는 동안 자동으로 업데이트됩니다
- 스냅샷은 만료되며 과거 지표 타임라인으로 보관되지 않습니다
- 아무도 보고 있지 않을 때는 Lody가 지속적인 리소스 샘플 요청을 중지합니다

디바이스가 워크스페이스에 공유되어 있는 경우 해당 디바이스에 접근할 수 있는 워크스페이스 멤버는 현재 리소스 정보를 볼 수 있습니다. 공유 디바이스에서 ACP 프로세스를 종료하면 모든 사용자에게 해당 세션이 영향을 받으므로, 다른 멤버의 활성 턴을 중지하기 전에 세션 상태를 확인하세요. 이 모니터는 프로세스 명령줄 검사기나 운영체제 프로파일링 도구를 대체하는 용도가 아닙니다.

디바이스가 오프라인 상태일 때는 Lody가 새 샘플을 요청하거나 ACP 프로세스를 종료할 수 없습니다. CLI를 온라인 상태로 만든 뒤 **Settings -> Devices**를 다시 열고 첫 번째 샘플이 수집될 때까지 기다리세요.
