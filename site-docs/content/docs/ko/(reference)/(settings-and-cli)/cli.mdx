# CLI 명령어

`lody`는 다음 두 가지 역할을 합니다:

- `lody start` 또는 `lody daemon start`로 시작하는 로컬 런타임 프로세스
- 워크스페이스, GitHub 저장소, 세션, 머신 및 에이전트 설정을 관리하기 위한 일회성 CLI

Lody가 처음이라면 먼저 [빠른 시작](/ko/docs/quickstart), [세션](/ko/docs/session),
[에이전트 설정](/ko/docs/quickstart), [CLI 런타임 유형](/ko/docs/cli-runtimes)을 읽어보세요.

## 도움말 및 파라미터 확인

정확한 플래그와 위치 인수는 내장 도움말 출력이 기준이 됩니다.

```bash
lody --help
lody session --help
lody session create --help
lody agent-config update --help
```

모든 명령어에서 다음 패턴을 사용할 수 있습니다:

| 범위                | 명령어                            |
| ------------------- | ---------------------------------- |
| 최상위 개요         | `lody --help`                      |
| 명령어 그룹         | `lody <group> --help`              |
| 특정 하위 명령어    | `lody <group> <subcommand> --help` |

## 핵심 명령어

| 명령어        | 기능                                       | 도움말 명령어        |
| ------------- | ------------------------------------------ | -------------------- |
| `lody`        | 최상위 도움말 및 사용 가능한 명령어 표시   | `lody --help`        |
| `lody login`  | 로그인 및 현재 머신 등록                   | `lody login --help`  |
| `lody logout` | 로컬 자격 증명 삭제                        | `lody logout --help` |
| `lody start`  | 현재 터미널에서 Lody CLI 실행              | `lody start --help`  |

로컬 런타임과 직접 통신하는 명령어는 일반적으로 포그라운드에서 `lody start`가 실행 중이거나
백그라운드에서 `lody daemon start`가 실행 중이어야 합니다:

- `lody session create`
- `lody session chat`
- `lody session cancel`
- `lody agent-config refresh-capabilities`

### `--auth`를 사용한 비대화형 로그인

기본적으로 `lody login`은 브라우저에서 디바이스 인증(device-authorization) 흐름을 엽니다. 헤드리스 머신
(CI 러너, 원격 서버, 컨테이너)에서는 브라우저를 여는 대신 미리 생성한 CLI
토큰을 전달하여 인증할 수 있습니다:

```bash
lody login --auth <token>
lody start --auth <token>          # 한 번에 로그인하고 런타임 시작
```

- `--auth <token>`은 데스크톱 또는 웹 앱의
  **Settings → Account → CLI Token**에서 생성한 **CLI 토큰**을 사용하여 인증합니다. **Create token**을 클릭하고
  짧은 메모(예: `CI runner`, `home server`)를 추가한 뒤, 대화상자를 닫기 전에 토큰을 복사하세요.
  토큰은 한 번만 표시됩니다.
- 토큰은 같은 패널에서 언제든지 폐기할 수 있습니다. 폐기하면 해당 토큰을 사용 중이던 모든 CLI가
  즉시 비활성화됩니다.
- `--auth`는 대화형 로그인과 동일하게 `--machine-name <name>` 플래그를 지원하므로 기본 호스트 이름을
  재정의할 수 있습니다.
- `lody login`에서 `--auth`를 생략하면 대화형 디바이스 인증 흐름으로 대체됩니다. 기존 세션이 없는 환경에서
  `lody start`에 `--auth`를 생략하면 런타임이 별도로 로그인하도록 안내합니다.

토큰은 비밀 관리자나 `LODY_AUTH` 환경 변수 등 비공개 위치에 보관하세요.
이 토큰은 사용자가 속한 워크스페이스에 대해 대화형 로그인과 동일한 접근 권한을 부여합니다.

## 제품 분석

클라우드 환경(데스크톱, 웹, 모바일 및 CLI)은 기본적으로 최소한의 제품 사용 횟수와 민감 정보가 제거된 오류를 공유하며, 이는 Settings → About → **Share app usage data**의 단일 계정 단위 스위치로 제어됩니다. 이 설정을 끄면 데스크톱, 웹, 모바일, 계정 측 분석 및 로그인된 클라우드 CLI 프로세스 전반에서 수집이 중단됩니다.

모든 클라우드 CLI 프로세스에서는 환경 변수에 `LODY_DISABLE_USAGE_SHARING=1`(또는 `DO_NOT_TRACK=1`)을 설정하여 분석을 비활성화하는 로컬 강제 재정의(hard override)를 적용할 수도 있습니다.

로컬 빌드는 PostHog를 비활성화합니다. 클라우드 CLI에서 분석이 활성화된 경우, 개인 프로필을 생성하지 않고 최소한의 등록된 이벤트 이름, 이벤트 시각, 무작위 프로세스 식별자, 개략적인 `platform` / `cli_type` / 정규화된 내장 `agent_type` 메타데이터(커스텀 에이전트의 경우 `other`) 및 라이브러리 메타데이터만 전송합니다. 자동 오류에는 고정된 유형과 코드가 포함됩니다. 명령어 인수, 머신 ID, 저장소 경로, 커스텀 에이전트 이름 및 오류 메시지는 이러한 요청에서 제외됩니다.

## 데몬 모드

`lody daemon start`는 Lody CLI를 백그라운드에서 실행하여 터미널 창을 열어 두지 않고도 데스크톱, 웹,
모바일 클라이언트에서 사용할 수 있도록 유지합니다. 이 명령어는 원격 머신을 연결할 때도 사용됩니다.
서버나 다른 워크스테이션에서 SSH를 통해 실행하면 해당 머신이 워크스페이스에 연결됩니다.

백그라운드로 전환하기 전에 `lody daemon start`는 Lody에 연결할 수 있는지와
현재 머신이 로그인되어 있는지 확인합니다:

- 로그인되어 있고 연결 가능한 경우: 데몬을 시작합니다.
- 로그인되어 있지 않은 경우(또는 저장된 자격 증명이 거부된 경우): 디바이스 인증 흐름을 시작하여
  브라우저에서 로그인 링크를 열고(브라우저가 없으면 링크를 출력함), 데몬 모드로 들어가기 전에 사용자가 로그인을
  완료할 때까지 기다립니다. 연결된 터미널이 없는 환경(CI, 스크립트 기반 SSH 명령 등)에서는
  브라우저를 기다리지 않고 실패하며 `lody login` 또는 `--auth <cli_token>` 사용을 안내합니다.
- Lody에 연결할 수 없는 경우: 동기화할 수 없는 데몬을 남겨 두지 않고 연결 오류와 함께 중지됩니다.
  그래도 시작하려면 `--skip-auth-check`를 전달하거나, 비대화형으로 로그인하려면 `--auth <cli_token>`을 전달하세요.

| 명령어                | 기능                                            |
| --------------------- | ----------------------------------------------- |
| `lody daemon start`   | 백그라운드 데몬 시작                            |
| `lody daemon status`  | 런타임, 머신 및 연결 상태 표시                  |
| `lody daemon logs`    | 최근 로그 출력(기본 50줄)                       |
| `lody daemon stop`    | 백그라운드 데몬 중지                            |
| `lody daemon restart` | 실행 중이면 데몬을 중지한 뒤 다시 시작          |

자주 쓰는 예시:

```bash
lody daemon start
lody daemon status
lody daemon logs --lines 100
lody daemon restart
lody daemon stop
```

데몬 로그는 `~/.lody/logs` 아래에 기록됩니다. 시작에 실패하거나 UI가 CLI에 연결할 수 없을 때
`lody daemon logs`를 사용하세요. 디버깅 중에 실시간 포그라운드 출력이 필요하다면 대신 `lody start`를 사용하세요.

## 워크스페이스 명령어

이후 명령어에서 정확한 워크스페이스 ID 또는 슬러그가 필요할 때 워크스페이스 명령어를 사용하세요.

| 명령어                | 기능                           | 도움말 명령어                |
| --------------------- | ------------------------------ | ---------------------------- |
| `lody workspace list` | 접근 가능한 워크스페이스 목록 조회 | `lody workspace list --help` |

### workspace list

`lody workspace list`는 `ID`, `Name`, `Slug` 열이 포함된 표를 출력합니다.
`--workspace <idOrSlug>`를 받는 명령어를 실행하기 전에 사용하세요.

```bash
lody workspace list
lody workspace list --json
```

## GitHub 명령어

Settings → GitHub에서 이미 워크스페이스에 연결된 저장소가 무엇인지 확인하려면
GitHub 명령어를 사용하세요.

| 명령어             | 기능                                       | 도움말 명령어             |
| ------------------ | ------------------------------------------ | ------------------------- |
| `lody github list` | 워크스페이스에 연결된 GitHub 저장소 목록 조회 | `lody github list --help` |

### github list

`lody github list`는 워크스페이스에 이미 추가된 저장소를 출력합니다. GitHub App이 접근할 수 있는
모든 저장소를 보여 주는 것이 아니라 현재 해당 워크스페이스에 연결된 저장소만 표시합니다.

```bash
lody github list --workspace my-team
lody github list --workspace my-team --json
```

주요 파라미터:

- `--workspace <idOrSlug>`: 대상 워크스페이스를 선택합니다
- 기본 출력은 저장소 ID, 전체 이름, 공개 여부가 담긴 읽기 쉬운 표입니다
- `--json`: 자동화를 위한 구조화된 저장소 데이터를 반환합니다

정확한 플래그 확인:

```bash
lody github list --help
```

## 프로젝트 명령어

프로젝트 명령어는 나중에 세션 생성 시 선택할 수 있도록 로컬 프로젝트 등록을 관리합니다.

| 명령어                    | 기능                           | 도움말 명령어                |
| ------------------------- | ------------------------------ | ---------------------------- |
| `lody project add [path]` | 로컬 프로젝트 디렉터리 등록    | `lody project add --help`    |
| `lody project list`       | 등록된 로컬 프로젝트 목록 조회 | `lody project list --help`   |
| `lody project delete`     | 등록된 로컬 프로젝트 삭제      | `lody project delete --help` |

선택자 없이 `lody project list`를 실행하면 로컬 데몬을 통해 현재 머신의 프로젝트를 읽습니다.
클라이언트에서 데몬을 실행하지 않고 워크스페이스 머신에 등록된 프로젝트를 확인하려면
클라우드 카탈로그 경로를 사용하세요:

```bash
lody project list --workspace <id|slug|name> [--machine <id|name>] --json
```

`--machine`이 없으면 워크스페이스 카탈로그에는 여러 머신에 걸쳐 권한이 부여된 로컬 프로젝트와
활성화된 GitHub 저장소가 모두 포함됩니다. `--kind local` 또는 `--kind github`를 사용하여 한 종류만 선택할 수 있으며,
`--machine`을 지정하면 해당 머신의 로컬 프로젝트로 결과가 제한됩니다. `--catalog`는
명시적인 워크스페이스 선택자 없이 워크스페이스 카탈로그를 선택합니다. 오픈 소스 로컬 플랫폼에서는
클라우드 I/O를 수행하지 않으므로 원격 목록 조회를 사용할 수 없습니다.

### 리소스 검색 및 페이지네이션

워크스페이스 머신, 프로젝트, 에이전트 설정, 역할(Role) 및 MCP 목록은 기본적으로 20개 항목을 반환합니다.
동일한 필터와 함께 `--limit`(1–100), `--query`, `--cursor`를 사용하거나 `--all-pages`를 사용하세요.
JSON은 `items`, `hasMore`, 선택적 `nextCursor`와 리소스별 배열 별칭(alias)을 반환합니다.
이들은 안전한 요약 정보이며, MCP 연결 값과 에이전트 실행 자격 증명은 제외됩니다.

```bash
lody agent-role list --workspace my-team --all-pages --json
lody agent-role get ROLE_ID --workspace my-team --json
lody agent-config get AGENT_ID --workspace my-team --json
lody mcp list --workspace my-team --json
lody operation list --workspace my-team --session SESSION_ID --state active --json
lody session list --workspace my-team --query parser --machine-id MACHINE_ID --agent-config-id AGENT_ID --agent-role-id ROLE_ID
```

역할 세부 정보에는 프롬프트 접두사가 포함되며, 목록에는 읽을 수 있는 비활성화 상태의 역할도 사유와 함께 유지됩니다.
작업(Operation) 목록은 요청자 세션 및 인증된 사용자 범위로 제한하여 이 머신의 저장소를 읽으며,
`--state`, `--limit`, `--cursor`를 지원합니다. 다른 머신의 저장소는 집계하지 않습니다.
세션 역할 필터는 생성 출처(provenance)를 기준으로 일치시킵니다. Lody MCP는 이에 대응하는
읽기 전용 `lody_catalog` 액션(`machines`, `projects`, `agent_configs`,
`agent_roles`, `mcp_servers`)과 `lody_operation` 도구를 제공합니다.

최신 기준의 정확한 플래그는 항상 내장 도움말을 확인하세요:

```bash
lody project add --help
lody project list --help
lody project delete --help
```

## 에이전트 역할 생성 및 업데이트

CLI와 MCP는 새 역할을 생성하거나 본인이 소유한 역할의 변경 사항을 제안할 수 있습니다. 제안은
활성 대화에 검토 카드로 표시됩니다. Lody에서 **Save**를 클릭하여 적용하거나
카드를 닫아 카탈로그를 변경하지 않은 채로 둘 수 있습니다. 명령어가 성공하면 저장된 역할이 아니라
대기 중인 제안을 보고합니다.

```bash
lody agent-role create --name "Reviewer" --description "Review code" \
  --prompt-prefix "Find actionable bugs" \
  --machine-id MACHINE_ID --agent-config-id CONFIG_ID --session SESSION_ID

lody agent-role update ROLE_ID --name "Code reviewer" \
  --description "" --prompt-prefix "Focus on correctness" --session SESSION_ID
```

| 옵션                     | 생성     | 업데이트                 |
| ------------------------ | -------- | ------------------------ |
| `--name <name>`          | 필수     | 선택                     |
| `--description <text>`   | 선택     | 선택; `""`로 지우기      |
| `--prompt-prefix <text>` | 선택     | 선택; `""`로 지우기      |
| `--machine-id <id>`      | 필수     | 지원 안 함               |
| `--agent-config-id <id>` | 필수     | 지원 안 함               |

업데이트에는 최소 하나의 필드가 필요합니다. 생략된 필드는 변경되지 않고 유지됩니다. 새 역할은 비공개이며
바인딩된 에이전트의 기본 실행 구성을 사용합니다. 모델, 권한, 공유
및 기타 설정은 역할 편집기에서 변경하세요.

활성 대화를 선택하려면 `--session`을 사용하거나 `LODY_SESSION_ID`를 설정하고,
워크스페이스가 모호한 경우 `--workspace <id-or-slug>`를 사용하세요. 재시도할 때는 동일한 입력과 함께
`--request-id <id>`를 재사용하세요. 결과는 기존 제안의 처리 결과를 반환합니다.

JSON 파일도 지원됩니다:

```bash
lody agent-role create --file role.json --session SESSION_ID
lody agent-role update ROLE_ID --file patch.json --session SESSION_ID
```

생성 파일에는 `name`, `machineId`, `agentConfigId`가 포함되며 선택적으로 `description`과
`promptPrefix`를 포함할 수 있습니다. 업데이트 파일에는 변경된 `name`, `description` 또는
`promptPrefix`만 포함합니다. `--file`은 직접 지정하는 역할 필드 옵션과 함께 사용할 수 없습니다.
Markdown에 저장된 지침의 경우 대신 `--prompt-prefix "$(cat reviewer.md)"`를 전달하세요.

`role.json`:

```json
{
  "name": "Reviewer",
  "machineId": "MACHINE_ID",
  "agentConfigId": "CONFIG_ID",
  "description": "Review code",
  "promptPrefix": "Check correctness.\nReport actionable bugs."
}
```

`patch.json`:

```json
{
  "description": "",
  "promptPrefix": "Focus on correctness.\nExplain each finding."
}
```

파일에는 위에 표시된 camelCase 키를 사용하는 단일 UTF-8 JSON 객체가 포함되어야 합니다.
업데이트 파일은 패치 객체 그 자체여야 합니다. `patch`로 감싸지 말고, 역할 ID는
명령어 인수로 전달하세요. 재시도 ID는 `--request-id`로 전달합니다. JSON 문자열의 줄 바꿈에는 `\n`을 사용하며,
주석과 후행 쉼표(trailing comma)는 유효한 JSON이 아닙니다.

모든 필드 값은 문자열입니다. 생성 시에는 `name`, `machineId`, `agentConfigId`가 필수입니다.
업데이트 시에는 지원되는 필드가 최소 하나 이상 필요합니다. 생략된 업데이트 필드는 변경되지 않으며,
`""`는 설명 또는 지침을 지우고 `null`은 거부됩니다. 이름은 비어 있지 않고
멘션 가능해야 하며 공백 제거 후 최대 60자여야 합니다. 설명은 최대
140개의 유니코드 코드 포인트까지 허용되며, 지침은 공백 제거 전 최대 32,768자까지 허용됩니다.
머신/설정 ID는 비어 있지 않아야 하며 공백 제거 후 최대 128자여야 합니다.
지원되지 않는 필드는 거부됩니다.

MCP는 `lody_agent_role` 액션 `create`와 `update`를 통해 동일한 확인 흐름을 제공합니다.
`create`는 `requestId`와 위의 생성 필드를 받으며, `update`는
`requestId`, `roleId`, 그리고 변경된 텍스트 필드를 담은 `patch`를 받습니다.
저장된 역할이 어떻게 사용되는지는 [에이전트 역할](/ko/docs/agent-roles)을 참고하세요.

## 데스크톱 앱 명령어

| 명령어                 | 기능                                                    | 도움말 명령어                 |
| ---------------------- | ------------------------------------------------------- | ----------------------------- |
| `lody app [path]`      | 디렉터리가 준비된 새 채팅 화면으로 데스크톱 앱 열기     | `lody app --help`             |
| `lody app reset-cache` | 다음 실행 시 데스크톱 앱의 로컬 캐시 초기화             | `lody app reset-cache --help` |

### 멈춘 데스크톱 창 복구하기

데스크톱 창이 응답하지 않거나, 재시작한 뒤에도 동일한 오류 상태로 다시 열리는 경우
로컬 캐시가 원인일 수 있으며 **Settings → Clear cache**에 접근해 복구할 수 없는 상황일 수 있습니다.
이럴 때는 대신 터미널에서 동일한 복구를 예약하세요:

```bash
lody app reset-cache          # 복구 가능한 캐시 초기화; 로그인 유지
lody app reset-cache --hard   # 모든 로컬 데이터 삭제 및 로그아웃
lody app reset-cache --cancel # 위의 두 요청 중 하나 취소
```

이 명령어는 요청만 기록하며, 앱이 다음에 시작될 때 이를 적용하므로 **데스크톱 앱을 완전히 종료한 뒤
다시 실행하세요**. 어떤 데이터도 외부로 전송되지 않으며, 로그인이나 실행 중인 데몬도
필요하지 않습니다.

`lody app reset-cache`는 계정, 설정, 전송되지 않은 Shortcut 초안을 유지하고 워크스페이스에서
대화를 다시 다운로드합니다. `--hard`는 그 후에도 앱이 계속 멈춰 있을 때만 사용하세요. 로그인된
세션과 로컬 환경설정까지 함께 제거됩니다. 적용되지 않은 요청은 하루가 지나면 만료됩니다.

## 세션 명령어

세션 명령어는 웹 이외의 환경에서 Lody를 사용하는 주요 워크플로입니다.

사용하기 전에:

- `session create`, `session chat`, `session cancel`은 현재 머신에서 `lody start` 또는 `lody daemon start`가 실행 중이어야 합니다
- `session list`, `history`, `observe`, `show`, `rename`, `archive`, `restore`, `delete`는 로그인과 워크스페이스 접근 권한만 있으면 됩니다
- 워크스페이스 ID 또는 슬러그가 필요하면 [`lody workspace list`](#workspace-commands)를 사용하세요
- `sessionId`는 위치 인수로 전달하거나 `LODY_SESSION_ID`를 통해 전달할 수 있습니다

| 하위 명령어            | 기능                                       | 로컬 런타임 필요 여부 | 도움말 명령어                 |
| ---------------------- | ------------------------------------------ | --------------------- | ----------------------------- |
| `lody session create`  | 현재 머신에 새 세션 생성                   | 예                    | `lody session create --help`  |
| `lody session chat`    | 기존 로컬 세션에 새 턴 전송                | 예                    | `lody session chat --help`    |
| `lody session cancel`  | 로컬 세션에서 실행 중인 턴 취소            | 예                    | `lody session cancel --help`  |
| `lody session list`    | 워크스페이스의 세션 목록 조회              | 아니요                | `lody session list --help`    |
| `lody session history` | 표시 가능한 대화 기록 읽기                 | 아니요                | `lody session history --help` |
| `lody session observe` | 영구 저장된 세션 상태 조회 및 추적         | 아니요                | `lody session observe --help` |
| `lody session show`    | 세션 메타데이터 표시                       | 아니요                | `lody session show --help`    |
| `lody session rename`  | 세션 이름 변경                             | 아니요                | `lody session rename --help`  |
| `lody session archive` | 활성 목록에서 세션 보관 처리               | 아니요                | `lody session archive --help` |
| `lody session restore` | 보관된 세션 복원                           | 아니요                | `lody session restore --help` |
| `lody session delete`  | 보관된 세션 영구 삭제                      | 아니요                | `lody session delete --help`  |

### session create

GitHub 저장소 또는 등록된 로컬 프로젝트에 연결된 세션을 생성합니다.

```bash
lody session create --workspace my-team --agent-config codex --repo owner/repo "Fix the failing test"
```

주요 파라미터:

- `--workspace <idOrSlug>`: 대상 워크스페이스를 선택합니다
- `--agent-config <idOrName>`: [에이전트 설정](/ko/docs/quickstart)에서 에이전트 설정을 선택합니다
- `--agent-role <idOrName>`: 워크스페이스 에이전트 역할에서 세션을 생성합니다. 역할의 머신, 에이전트 설정, 실행 구성이 `--machine`, `--agent`/`--agent-config`, `--mode`, `--model`, `--config-option`을 덮어씁니다(무시된 플래그는 경고로 표시됩니다)
- `--repo <owner/repo>`: GitHub 저장소를 연결합니다
- `--local-project <id|name|path>`: 이전에 등록된 로컬 프로젝트를 연결합니다
- `--repo`와 `--local-project`는 함께 사용할 수 없습니다
- `--branch <name>`: 시작 브랜치를 선택합니다
- `--mode <modeId>` 및 `--model <modelId>`: ACP 선택 항목을 재정의합니다
- `--env KEY=VALUE`: 여러 번 반복 지정할 수 있으며, 이후 재개(resume)를 위해 세션과 함께 저장됩니다
- 프롬프트 입력은 위치 텍스트, `--prompt`, `--prompt-file` 또는 표준 입력(stdin)을 통해 전달할 수 있습니다

정확한 플래그 확인:

```bash
lody session create --help
```

### session chat

현재 머신에 있는 기존 세션에 또 다른 사용자 턴을 전송합니다.

```bash
lody session chat <sessionId> "continue from the last patch"
LODY_SESSION_ID=<sessionId> lody session chat --prompt "continue from the last patch"
```

주요 파라미터:

- `sessionId`는 위치 인수 또는 `LODY_SESSION_ID`로 전달할 수 있습니다
- 프롬프트 입력은 위치 텍스트, `--prompt`, `--prompt-file` 또는 표준 입력(stdin)을 통해 전달할 수 있습니다
- `--mode <modeId>` 및 `--model <modelId>`: 이번 턴의 ACP 선택 항목을 재정의합니다

정확한 플래그 확인:

```bash
lody session chat --help
```

### 입력 첨부 파일

`create`와 `chat` 모두 반복 가능한 `--attach <path>`를 지원합니다:

```bash
lody session create --machine remote --prompt "Analyze the data" --attach ./data.csv
lody session chat <sessionId> --prompt "Use this screenshot too" --attach ./screen.png
```

경로는 명령어를 실행하는 머신에서 현재 디렉터리를 기준으로 읽습니다.
메시지를 전송하기 전에 모든 첨부 파일 준비가 완료되어야 합니다. 하나라도 실패하면
전송이 중단됩니다. 비어 있지 않은 최대 8개의 파일(각 최대 100 MiB)을 지원합니다.
이미지 크기 제한 내의 지원되는 이미지는 시각 입력으로 유지되며, 더 큰 이미지는 파일로 전달됩니다.
첨부 파일이 있는 경우 텍스트는 선택 사항입니다. `--prompt-file`은 여전히 프롬프트 텍스트를 읽습니다.
독립 실행형 CLI 명령어를 다시 실행하면 새 메시지가 전송됩니다.

### session cancel

로컬 세션에서 현재 실행 중인 턴을 취소합니다.

```bash
lody session cancel <sessionId>
```

취소에 실패하면 명령어는 0이 아닌 종료 코드로 종료됩니다. 정확한 플래그 확인:

```bash
lody session cancel --help
```

### session list

워크스페이스의 세션 목록을 조회합니다. 기본적으로 활성 세션만 표시합니다.

```bash
lody session list --workspace my-team
lody session list --workspace my-team --archived
lody session list --workspace my-team --all --limit 50 --json
```

주요 파라미터:

- `--archived`: 보관된 세션만 표시합니다
- `--all`: 활성 세션과 보관된 세션을 모두 포함합니다
- `--limit <count>`: 결과 개수를 제한합니다
- 기본 출력은 읽기 쉬운 표이며, `--json`은 구조화된 데이터를 반환합니다

정확한 플래그 확인:

```bash
lody session list --help
```

### session history

한 세션의 표시 가능한 대화 기록을 읽습니다. 이 명령어는 의도적으로 내부 추론(reasoning),
도구 호출 및 기타 사용자에게 표시되지 않는 항목을 숨깁니다.

```bash
lody session history <sessionId> --limit 20
lody session history <sessionId> --all --reverse
lody session history <sessionId> --jsonl
```

주요 파라미터:

- `--limit <count>`: 가장 최근의 표시 가능한 턴 N개를 반환합니다
- `--all`: 표시 가능한 전체 대화 기록을 반환합니다
- `--reverse`: 최신순으로 출력합니다
- `--json` 및 `--jsonl`: 자동화에 유용합니다

정확한 플래그 확인:

```bash
lody session history --help
```

### session observe

작업을 전송하거나 읽지 않음(unread) 상태를 변경하지 않고 기존 세션에 연결합니다.
이 명령어는 현재 클라우드 로그인과 워크스페이스 접근 권한을 사용하며, 로컬 전용 데몬
연결은 지원하지 않습니다.

```bash
lody session observe <sessionId> --json
lody session observe <sessionId> --jsonl --follow
lody session observe --workspace my-team --all --jsonl --follow
```

`--follow`가 없으면 스냅샷을 출력하고 종료합니다. Follow를 사용하려면 `--jsonl`이 필요합니다.
`history --jsonl`과 달리 이후 턴을 받기 위해 계속 연결된 상태를 유지합니다. 워크스페이스 모드에서는
`--workspace`와 `--all`이 모두 필요하며, 위치 인수로 세션 ID를 받는 것을 거부하고 `LODY_SESSION_ID`를 무시합니다.

JSONL 이벤트는 `snapshot`, `ready`, `session.changed`, `turn.started`,
`turn.finished`, `session.removed`입니다. 성공한 각 이벤트에는 `version: 1`,
`streamId`, `sequence`, `observedAt`(Unix 밀리초), `workspaceId`가 포함됩니다.
`turn.finished`에는 사용자 ID, 선택적 어시스턴트 ID, 그리고
`outcome: completed | failed | canceled`가 포함됩니다. 초기 스냅샷에는 빠른 작업의 결과도
읽을 수 있도록 `latestTurn`이 포함되며, 이전 턴들은 이벤트로 재전송되지 않습니다.

세션 스냅샷은 `source: persisted | metadata`와
`freshness: synced | unavailable`을 구분합니다. 워크스페이스 `ready`는 모든 히스토리 룸을 여는 것이 아니라
카탈로그 열거가 완료되었음을 의미합니다. 메타데이터만 있는 세션은 `state: unknown`이 됩니다.
과거의 유휴(idle) 룸은 열리지 않은 채로 남으며, 해당 히스토리만 변경되는 경우는
워크스페이스 follow 범위에 포함되지 않습니다. 필요할 때는 개별적으로 연결하세요. 완료 확인에는
영구 저장된 턴 증거가 필요하며, 메타데이터 유휴 상태나 Presence 손실만으로는 충분하지 않습니다.
Freshness는 확인된 읽기 상태를 의미할 뿐 에이전트가 현재 온라인 상태임을 보장하지는 않습니다.

시퀀스(Sequence)는 하나의 실행 중인 프로세스 내에서 순서를 매기며, 다른 프로세스에서 재개하거나
재전송을 보장하지 않습니다. 재시작 후에는 스냅샷과 히스토리를 다시 대조하세요. 일반 스트리밍 텍스트는
생략됩니다. 구조화된 진단은 stderr로 출력되며, 명령어 오류는 기존 CLI 오류 형식을 사용합니다.
Ctrl+C를 누르면 실행을 취소하지 않고 관찰만 중지합니다.

```bash
lody session observe --help
```

### session show

상태, 머신, 워크스페이스 바인딩, 대화 기록 개수 등 세션 메타데이터를 표시합니다.

```bash
lody session show <sessionId>
lody session show <sessionId> --json
```

정확한 플래그 확인:

```bash
lody session show --help
```

### session rename

세션 이름을 변경합니다.

```bash
lody session rename <sessionId> "New title"
LODY_SESSION_ID=<sessionId> lody session rename --title "New title"
```

`LODY_SESSION_ID`를 사용하는 경우 제목이 명시적인 세션 선택자로 오해되지 않도록
`--title`을 사용하는 것이 좋습니다.

정확한 플래그 확인:

```bash
lody session rename --help
```

### session archive

세션을 보관하여 활성 목록에서 숨기되 복구 가능하게 유지합니다.

```bash
lody session archive <sessionId>
```

정확한 플래그 확인:

```bash
lody session archive --help
```

### session restore

보관된 세션을 다시 활성 목록으로 복원합니다.

```bash
lody session restore <sessionId>
```

이 명령어는 보관된 세션에서만 작동합니다. 정확한 플래그 확인:

```bash
lody session restore --help
```

### session delete

보관된 세션을 영구적으로 삭제합니다. 이 명령어는 워크트리 및 런타임 리소스를
제거할 수 있도록 머신 측 정리 작업도 대기열에 등록합니다.

```bash
lody session delete <sessionId>
```

이 명령어는 보관된 세션에서만 작동합니다. 정확한 플래그 확인:

```bash
lody session delete --help
```

## 머신 명령어

머신 명령어를 사용하면 워크스페이스에 어떤 머신이 등록되어 있고 현재 온라인 상태인지
확인할 수 있습니다.

| 명령어              | 기능                         | 도움말 명령어              |
| ------------------- | ---------------------------- | -------------------------- |
| `lody machine list` | 워크스페이스의 머신 목록 조회 | `lody machine list --help` |

### machine list

```bash
lody machine list --workspace my-team
lody machine list --workspace my-team --online-only
lody machine list --workspace my-team --json
lody machine list --workspace my-team --json --include-acp-capabilities
```

기본 표는 머신 식별 정보와 가용성을 보여 줍니다. JSON은
`onlineStatus: online | offline | unknown`을 유지하며, presence 정보를 확인할 수 없는 경우를 offline으로 보고하지 않습니다.
`--include-acp-capabilities` 및 `--include-agents`는 기존 상세 출력을 유지하며
디렉터리 페이지네이션/필터 플래그와 함께 사용할 수 없습니다. 페이지네이션된 기능 조회에는 `agent-config list/get`을 사용하세요.

- 기본적으로 온라인 및 오프라인 머신이 모두 표시됩니다
- 최근 하트비트가 있는 머신으로 목록을 필터링하려면 `--online-only`를 사용하세요
- `--json`은 페이로드 크기를 줄이기 위해 기본적으로 `acpCapabilities`를 생략합니다
- JSON 출력에 기능 캐시가 필요하면 `--include-acp-capabilities`를 전달하세요

이 명령어는 `agent-config refresh-capabilities`를 실행하기 전에 유용합니다.

정확한 플래그 확인:

```bash
lody machine list --help
```

## 에이전트 설정 명령어

에이전트 설정 명령어는 [에이전트 설정](/ko/docs/quickstart)에 있는 웹 UI의 동작 대부분을 그대로 제공합니다.

사용하기 전에:

- 선택자(selector)는 ID 또는 이름을 받습니다
- 여러 설정이나 머신이 같은 이름을 공유하는 경우 CLI는 명시적인 ID를 요구합니다
- `refresh-capabilities`는 현재 CLI에서 현재 머신에 대해서만 작동합니다

| 하위 명령어                              | 기능                                      | 도움말 명령어                                   |
| ---------------------------------------- | ----------------------------------------- | ----------------------------------------------- |
| `lody agent-config list`                 | 워크스페이스의 설정 목록 조회             | `lody agent-config list --help`                 |
| `lody agent-config show`                 | 단일 설정 표시                            | `lody agent-config show --help`                 |
| `lody agent-config create`               | 새 설정 생성                              | `lody agent-config create --help`               |
| `lody agent-config import-magpie`        | 로컬 Magpie 제공자 가져오기               | `lody agent-config import-magpie --help`        |
| `lody agent-config update`               | 기존 설정 업데이트                        | `lody agent-config update --help`               |
| `lody agent-config delete`               | 설정 삭제                                 | `lody agent-config delete --help`               |
| `lody agent-config refresh-capabilities` | 지원되는 모드, 모델 및 옵션 새로고침      | `lody agent-config refresh-capabilities --help` |

### agent-config list

```bash
lody agent-config list --workspace my-team
```

설정 식별 정보, 머신 및 가용성을 표시합니다. JSON에는 에이전트 유형, 설명
및 지원되는 모델/실행 설정도 포함됩니다. 목록을 좁히려면 `--machine`, `--query` 및 페이지네이션을 사용하세요.

### agent-config show

```bash
lody agent-config show <idOrName>
LODY_AGENT_CONFIG_ID=<id> lody agent-config show
```

설정 필드를 읽기 쉬운 형식이나 JSON으로 표시합니다.

### agent-config create

내장 또는 레지스트리 에이전트 런타임용 설정을 생성합니다.

```bash
lody agent-config create \
  --workspace my-team \
  --agent-type codex \
  --name "Codex Default" \
  --env OPENAI_API_KEY=... \
  --prompt "Always run tests before finishing"
```

주요 파라미터:

- `--agent-type <type>`은 필수입니다
- `claude`와 `codex`는 내장 런타임으로 처리됩니다
- 그 밖의 모든 에이전트 유형은 레지스트리 런타임으로 처리됩니다
- `--env KEY=VALUE`는 여러 번 반복할 수 있습니다
- `--env-file <path>`는 파일에서 환경 변수를 불러옵니다
- `--prompt` 또는 `--prompt-file`은 기본 프롬프트 접두사를 설정합니다

정확한 플래그 확인:

```bash
lody agent-config create --help
```

### agent-config import-magpie

명령어를 실행하는 서버에서 지원되는 모든 에이전트 또는 선택한 일부 에이전트에 대해 Magpie 제공자를 가져옵니다:

```bash
lody agent-config import-magpie --workspace my-team --json
```

설정, 옵션 및 결과 상태는 [Magpie 연결](/ko/docs/magpie)을 참고하세요.

### agent-config update

기존 설정을 제자리에서(in place) 업데이트합니다.

```bash
lody agent-config update <idOrName> --name "Codex CI"
lody agent-config update <idOrName> --env OPENAI_API_KEY=... --unset-env OLD_KEY
lody agent-config update <idOrName> --prompt ""
```

주요 파라미터:

- `--name`: 표시 이름을 업데이트합니다
- `--description ""`: 설명을 지웁니다
- `--env` 및 `--env-file`: 새 환경 변수 값을 병합합니다
- `--unset-env KEY`: 하나 이상의 환경 변수를 제거합니다
- `--prompt ""`: 기본 프롬프트 접두사를 지웁니다

정확한 플래그 확인:

```bash
lody agent-config update --help
```

### agent-config delete

```bash
lody agent-config delete <idOrName>
```

ID 또는 고유한 이름으로 단일 설정을 삭제합니다.

### agent-config refresh-capabilities

현재 머신에 있는 한 에이전트 설정의 캐시된 기능을 새로고침합니다.

```bash
lody agent-config refresh-capabilities <idOrName> --workspace my-team
```

다음과 같은 경우에 사용하세요:

- 코딩 CLI를 설치하거나 업그레이드한 후
- 에이전트 설정의 환경을 변경한 후
- 머신에서 사용 가능한 모델이나 모드를 업데이트한 후

주요 파라미터:

- `--machine <idOrName>`: 기본값은 현재 머신입니다
- 선택한 머신은 온라인 상태여야 합니다
- CLI는 현재 원격 머신 새로고침을 거부하므로 이 명령어는 현재 머신에서 사용하세요
- 자동화를 위해 `--json`과 `--jsonl`을 지원합니다

정확한 플래그 확인:

```bash
lody agent-config refresh-capabilities --help
```

## 자주 쓰는 예시

```bash
# 사용할 워크스페이스 ID 또는 슬러그 찾기
lody workspace list

# 해당 워크스페이스에 이미 연결된 GitHub 저장소 확인
lody github list --workspace my-team

# 해당 워크스페이스의 에이전트 설정 확인
lody agent-config list --workspace my-team

# 백그라운드에서 로컬 데몬 시작
lody daemon start

# 일시적인 디버깅에는 포그라운드 모드가 유용합니다
lody start

# GitHub 저장소에서 세션 생성
lody session create \
  --workspace my-team \
  --agent-config codex \
  --repo owner/repo \
  "Fix the failing tests"

# 최근의 표시 가능한 대화 기록 턴 읽기
lody session history <sessionId> --limit 20

# 머신 목록을 확인하고 현재 머신의 기능 새로고침
lody machine list --workspace my-team --online-only
lody agent-config refresh-capabilities codex --workspace my-team
```
