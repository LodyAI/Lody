# Agent Session Control

Lody Agents can use the built-in Lody MCP tools to work across conversations. This lets you ask one
Agent to split a task into focused conversations, check their progress, send follow-up work, and
bring the completed results back to the original conversation.

Starting several sessions yourself — isolated worktrees, mixed models, team visibility — is covered
in [Parallel Coding Agents](/docs/parallel-agents). This page is the control path: one Agent
coordinates the others.

For a walkthrough with Claude Code, Kimi, Codex, and Grok—including conversation mentions and
cross-machine work—see [Agent Collaboration Workflows](/docs/agent-collaboration/).

## Use it in a conversation

Describe the outcome and the division of work in a normal prompt. For example:

```text
Create two review conversations for this project: one for correctness and one for test coverage.
When both finish, summarize the findings here.
```

The Agent can create or reuse conversations, read their status and bounded history, deliver a
follow-up instruction, or cancel a running turn when appropriate. Results return to the requesting
conversation after the requested work reaches a terminal state.

When creating a new session, the Agent can also select from the compatible model and reasoning
options available on the target machine. Include those preferences in your prompt when they matter,
for example:

```text
Create a review session with Codex using the high reasoning setting, then summarize the findings here.
```

## Coordinate PRs, issues, and cross-repository fixes

### Use Claude Code as the coordinator

Ask Claude Code to inspect a set of PRs or issues, identify dependencies, then assign focused work
to other Agents such as Kimi, Codex, or Grok. Each Agent works in its own conversation, and the coordinator
can follow up and collect the results. Repository access uses the tools and credentials available
to the Agents.

```text
Go through these PRs and issues, group related work, and identify dependencies.
Delegate independent fixes to Kimi and reviews to Codex in separate conversations.
Collect their findings and report which changes are ready for my review.
```

### Fix a bug across repositories

When a bug spans a client, SDK, and server, create a conversation for each affected repository.
The Agents can investigate and implement independent changes in parallel, exchange findings about
the shared contract, and coordinate dependent changes.

```text
Investigate this bug across the client, SDK, and server repositories.
Start a focused Agent conversation for each repository. Have them exchange findings
and agree on the interface changes before implementing dependent fixes.
Collect the patches and verification results here.
```

### Run a review and fix loop between Agents

Agents can send messages and delegate work to other accessible Lody conversations. You can also
ask one Agent to message another directly: have a reviewer inspect a specific commit, send findings
to the implementing Agent, then review the updated commit after the fix.

```text
Ask the review Agent to inspect the implementing Agent's current commit without editing it.
Send actionable findings to the implementing Agent and ask it to fix them.
Have the reviewer check the updated commit. Stop after two rounds, or earlier if no findings remain,
and summarize the result for me.
```

These examples describe workflows you can request, not preconfigured pipelines. Make the target
repositories, scope, completion criteria, and review limit explicit. Parallel work still needs
integration checks before its changes are ready to merge.

## What to expect

- Each conversation remains an independent task with its own history and active turn.
- Work can run in parallel when the target machine is online.
- Lody preserves the relationship to the requesting conversation, so the Agent can continue after
  the delegated work completes.
- Temporary conversations can be archived from the session list once their work is complete.

## Limits

Session control is deliberately bounded: an Agent can inspect only Lody-owned conversation data and
cannot use it as an unbounded background scheduler. A delegated task may finish after its requested
deadline; its output remains in that conversation even when the requester has already received a
timeout result.

To hand a live session to a teammate instead of coordinating other agents, see
[Share a Coding Agent Session](/docs/session-handoff).
