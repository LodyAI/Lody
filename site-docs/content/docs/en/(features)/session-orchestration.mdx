# Agent Session Control

Lody Agents can use the built-in Lody MCP tools to work across conversations. This lets you ask one
Agent to split a task into focused conversations, check their progress, send follow-up work, and
bring the completed results back to the original conversation.

Starting several sessions yourself — isolated worktrees, mixed models, team visibility — is covered
in [Parallel Coding Agents](/docs/parallel-agents). This page is the control path: one Agent
coordinates the others.

These tools are available when **Developer mode** and the **Tasks** beta are on
(**Settings** -> **About**). Without that gate, a normal conversation cannot create or drive other
sessions this way.

## Use it in a conversation

Describe the outcome and the division of work in a normal prompt. For example:

```text
Create two review conversations for this project: one for correctness and one for test coverage.
When both finish, summarize the findings here.
```

The Agent can create or reuse conversations, read their status and bounded history, deliver a
follow-up instruction, or cancel a running turn when appropriate. Results return to the requesting
conversation after the requested work reaches a terminal state.

When creating a new session, the Agent can also select from the compatible model and reasoning
options available on the target machine. Include those preferences in your prompt when they matter,
for example:

```text
Create a review session with Codex using the high reasoning setting, then summarize the findings here.
```

## What to expect

- Each conversation remains an independent task with its own history and active turn.
- Work can run in parallel when the target machine is online.
- Lody preserves the relationship to the requesting conversation, so the Agent can continue after
  the delegated work completes.
- Temporary conversations can be archived from the session list once their work is complete.

## Limits

Session control is deliberately bounded: an Agent can inspect only Lody-owned conversation data and
cannot use it as an unbounded background scheduler. A delegated task may finish after its requested
deadline; its output remains in that conversation even when the requester has already received a
timeout result.

To hand a live session to a teammate instead of coordinating other agents, see
[Share a Coding Agent Session](/docs/session-handoff).
