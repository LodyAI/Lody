# Mentions

Lody enhances the input box with mention support. Type `@` to open the mention menu, where you can
choose conversations, files, Issues, Pull Requests, Skills, or Agent Roles. `$` remains a direct
shortcut for Skills.

## Conversation Mentions

Type `@`, choose **Sessions**, and select another conversation to reference it. Ask the current agent
to contact that session, read relevant context, exchange findings, or request a review. For example,
mention an implementation session and ask the current agent to review its latest commit and send
its findings back.

The referenced session can use another agent or run on another connected machine. Access still
follows workspace permissions, and the target machine must be online to run work. A mention
identifies the session; include an instruction describing what context to exchange or work to do.

See [Agent Session Control](/docs/session-orchestration/) for the available operations, or follow
the [multi-agent collaboration guide](/docs/agent-collaboration/) to exchange context and request
reviews across agents and machines.

## File Mentions

Type `@` and choose **Files**. Keep typing to fuzzy-match by filename or file path. Use the up and
down arrow keys to select, then press Enter to confirm. Mentioned files are sent to the coding
agent as full-path prompt context.

## Issue and Pull Request Mentions

After selecting a repository on the home page, type `@` to open the mention menu, then choose
**Issues** or **Pull Requests** to mention one from the current repository.

<MentionPreview locale="en" kind="issue" />

Use the up and down arrow keys to select, then press Enter to confirm. Lody writes the selected
item into the composer as `#<number>` and injects its context into the prompt, so the agent can
handle tasks like `Fix #12` or `Review the implementation in #56`.

## Skill Mentions

Type `$` to browse Skills available from the selected project and agent machine. Continue typing to
filter by name, then select a Skill with the arrow keys and `Enter`.

Lody keeps a readable `$skill-name` token in the composer. When you send the message, it adds the
corresponding `SKILL.md` path so the agent can load and follow those instructions.

See [Skills](/docs/skills) for discovery locations, project and global scope, and offline behavior.
