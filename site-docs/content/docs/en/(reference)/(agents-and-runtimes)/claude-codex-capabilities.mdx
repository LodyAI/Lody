# Claude & Codex Capabilities

Lody detects runtime capabilities from the selected Agent Config and exposes supported Claude Code
and Codex features directly in the conversation UI.

If a capability is missing after changing an agent setup, refresh that Agent Config's capabilities
from **Settings** -> **Agent Config**, or run `lody agent-config refresh-capabilities <idOrName>` on
the machine that owns the config.

## Claude Code

### Steer a Running Task

While Claude Code is working, use **Steer** to change direction without stopping the active task and
starting over. Set **Settings** -> **General** -> **Queued message behavior** to **Guide** to steer
messages you send while the agent is busy, or choose **Steer** on the first queued message. Lody keeps
the message pending until Claude Code confirms that it has applied the new instruction, then continues
streaming the response into the steered turn.

Steering the main task does not automatically cancel Claude Code background tasks. Claude Code decides
whether those tasks still fit the new direction, so you can redirect the main work without losing
useful parallel progress.

### Fast Mode

Some Claude Code configs expose a Fast Mode toggle — a lightning-bolt (⚡) button in the mode
selector below the composer. Turn it on for an accelerated response profile; the tooltip spells out
the tradeoff (roughly 2.5× faster at a higher cost per token). The toggle only appears when the
selected config advertises the option, and your choice is remembered per session and applied to the
next message you send.

### Background Tasks

When Claude Code spins work off into background tasks — subagents or background shell commands — Lody
shows a task panel inline in the conversation:

- While tasks are running, the panel stays expanded with a spinner and a **"Waiting on N background
  tasks"** header, so the chat isn't blocked while they work.
- Each row shows the task's actor (the subagent type, workflow name, or `Bash` / `Task`), an
  optional description, and the tool it is currently running.
- When everything finishes, the panel collapses to a **"N background tasks"** summary that you can
  expand to review each task, including the tokens and tools it used.

The panel reports progress only — it doesn't let you cancel individual tasks.

### Scheduled Tasks

Claude Code can also schedule future runs and keep the session alive to handle them. A panel above
the composer shows **"Session will continue · N scheduled tasks pending"**; expand it to see each
entry:

- The next fire time with a live countdown (**"in 5 min"**, **"firing now…"**).
- A type label — **Wakeup** for a one-off resume or **Scheduled** for a cron run — plus a
  **Recurring** badge when the schedule repeats.
- An optional summary describing what will run.

One-off wakeups clear from the list shortly after they fire; recurring schedules stay and roll to
their next time. The panel is read-only.

## Codex

### Steer a Running Task

You can also use **Steer** while Codex is working. Set **Queued message behavior** to **Guide**, or
choose **Steer** on the first queued message. Codex adds the instruction to the same active turn
instead of cancelling it or creating a separate Codex turn. Lody moves the conversation forward only
after Codex confirms that it has committed the steer.

A steer may remain **Pending** briefly while Codex reaches a point where it can apply the instruction.
It uses the active turn's model, mode, and configuration. If the queued message requests different
settings, Lody leaves it pending so you can keep those settings and use **Interrupt and send now**
instead.

### Goals

Codex Goals let a session carry a visible task objective and progress state. Enable the feature in
Codex first with:

```bash
codex features enable goals
```

After that, Lody can show the goal status in the conversation and session UI. Each goal run
also reports its elapsed time and token usage, so you can see at a glance how much was spent on
reaching the objective.
