# Connect Magpie

Magpie connects to model providers. Lody creates the agent configurations. Keep upstream API keys in Magpie; you do not need to copy them into Lody.

## Before you start

- Run Magpie and the Lody daemon on the **same server**, with at least one model enabled in Magpie.
- Sign in to Lody and connect the server to your workspace. See [CLI login](/docs/cli#core-commands).
- Use a Lody CLI that supports `import-magpie`. These commands use cloud workspaces, not the OSS local-only mode.

On the server, check command support, start the daemon, and find your workspace:

```bash
lody agent-config import-magpie --help
lody daemon start
lody workspace list
```

Skip daemon startup if it is already running. Replace `my-team` below with your workspace ID, name, or slug.

## Import all providers

```bash
lody agent-config import-magpie --workspace my-team --json
```

By default, this connects to `http://127.0.0.1:3425` and imports seven providers:

| `--targets` value | Configuration name |
| --- | --- |
| `claude` | Claude-magpie |
| `codex` | Codex-magpie |
| `pi` | Pi-magpie |
| `dsh` | DSH-magpie |
| `kimi` | Kimi Code-magpie |
| `grok` | Grok-magpie |
| `bub` | Bub-magpie |

The command only imports to the **machine running it**. There is no `--machine` option. `127.0.0.1` refers to that server, not your computer.
Bub requires a preinstalled `bub acp` command and ACP plugin.

### Select agents

Separate targets with commas. For example, import only Pi and Codex:

```bash
lody agent-config import-magpie --workspace my-team --targets pi,codex --json
```

### Use another port or an import link

For a different Magpie port, pass the gateway root URL without `/v1`:

```bash
lody agent-config import-magpie --workspace my-team --gateway http://127.0.0.1:4000 --json
```

If you have a Magpie import link, pass the full link:

```bash
lody agent-config import-magpie --workspace my-team --link 'lody://provider/import?v=1&data=…' --json
```

Use either `--link` or `--gateway`, not both. With a link, the default is all targets offered by that link; `--targets` can only select from them.
The gateway must use a local HTTP loopback address: `127.0.0.1`, `localhost`, or `[::1]`.

## Read the result

The JSON `providers` array contains each target's `agentConfigId` and `status`:

| Status | Meaning |
| --- | --- |
| `queued` | Setup is saved; the daemon will install or verify the runtime |
| `preparing-runtime` / `verifying` | An existing setup is preparing or verifying |
| `awaiting-auth` | An existing setup needs authentication |
| `created` | Configuration is saved; model requests are not yet verified |
| `existing` | A configuration for this gateway and agent type already exists and is preserved |

Check setup progress on Lody's **Providers** page. Once ready, select that provider on the server when creating a session.
A successful import does not prove that upstream inference works. Send a message to verify it.

`synced: false` means the configuration is saved locally but workspace synchronization is unconfirmed. Restore connectivity and rerun the import.

Repeated imports preserve existing configurations and retry failed setups with their original configuration.
If Pi is unsupported, update Lody on the server and restart its daemon, or exclude `pi` with `--targets`.

## Update models and configuration

Manage models in Magpie. Lody reads the latest catalog on subsequent launches; running sessions do not update automatically.
Lody manages the generated native configuration. Manual edits may be overwritten on the next launch.

On desktop, opening an existing Magpie import link shows a confirmation dialog and imports to that desktop machine. To import to a server, run the commands above on the server.
