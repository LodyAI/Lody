最近 Lody 在 GitHub 上的 Star 数抵达了 1,000。感谢每一位点下星星的朋友！

我觉得，里程碑值得一支像样的庆祝视频，而整支视频，从画面到声音，都是代码渲染出来的，所以这篇文章我打算来讲讲它是怎么做出来的，分享一下思路。

## 为什么用代码做视频

我们使用的是 [Remotion](https://remotion.dev)，使用它的原因是，视频里的每一帧都是一个 React 组件在某一时刻的渲染结果。这意味着视频可以享受代码的一切好处，比如版本管理、参数化、组件复用，以及 60fps 下每一帧都精确可控。

运镜不对？改个数字重新渲染，几十秒后就有一支新片子，而不是继续在时间轴上重新拖半天。同时，它也对 AI 友好，AI 可以直接生成 React 组件，或者在渲染前生成 JSON 数据，只需要在 React 里渲染出来就行。

## 一、重绘 GitHub，而不是使用截图

我觉得，我们不应该用真实截图

首先，在推进镜头下，位图分辨率始终有限，让 AI 来截图就会容易出现截图一放大就糊成一片的边界情况，而且画面里的任何东西都没法动。

所以我们整个页面是用 DOM 重绘的 —— tab 栏、按钮、文件列表、About 侧栏，图标全部来自 GitHub 官方的 octicons

同时，重绘还有一个额外的好处：元素可以自由组装动效。大家都能看到，在开场时，页面的每个区块从上方落下、带着轻微过冲"贴"进自己的位置，就像界面在你我眼前组装起来。

这个的核心就是一个不到十行的小函数：

```tsx
const dock = (delay: number): React.CSSProperties => {
  const s = spring({frame: frame - delay, fps, config: {damping: 14, mass: 0.9, stiffness: 160}});
  return {
    opacity: interpolate(s, [0, 0.45], [0, 1], {extrapolateRight: 'clamp'}),
    transform: `translateY(${interpolate(s, [0, 1], [-80, 0])}px)`,
  };
};
```

每个区块铺一个 `...dock(n)`,n 从上到下错开几帧，页面就有了呼吸感。

对于光标点击 Star 按钮的位置，我们将按钮在 3D 空间里斜放着，同时把页面坐标穿过同一套旋转投影矩阵算回屏幕坐标，这样光标永远精确落在按钮中心了

## 二、镜头感

"像镜头拍的"和"像 PPT 在动"的区别，大半在景深和运动的连续性。

景深用最简单的实现那就是一整块模糊加一个清晰窗口，但是那样边缘会有一条生硬的边界。于是我们叠了三层板子，最底下一层整幅重模糊，中间一层轻模糊覆盖一块宽羽化区域，而最上面一层锐利核心只留在焦平面附近。三层都用很宽的软 mask，模糊量就随着离焦距离渐变开了：

<img src="/_docs-assets/1k-video/dof.png" alt="三层景深板" />

> 严格意义来说，渐进模糊的景深是光学成像的结果，应该是一个卷积核，而不是简单的线性渐变。但考虑到社交媒体上视频的分辨率和码率，简单渐变这已经足够了。

对于连续性，我们的页面在运镜结束后有一个轻微的"呼吸"摆动，第一版的写法是摆动项在运镜结束那一帧生效，但是那一刻 sin 的值不是 0，镜头便不易察觉地"咯噔"了一下，一眼看就像是卡了一帧。

对于呼吸感，我们需要让正弦从零交叉点开始，再乘一个淡入淡出的包络：

```tsx
const breathe =
  Math.sin((frame - 92) / 55) * 0.9 *
  interpolate(frame, [92, 122, 266, 296], [0, 1, 1, 0], {
    extrapolateLeft: 'clamp',
    extrapolateRight: 'clamp',
  });
```

这样，摆动从静止里慢慢出来，在拉远之前又悄悄收掉。

## 三、声音也是渲染出来的

配乐不是随便垫的一条罐头配乐。这里我们使用了一个无版权音乐作为垫底，我们选定的曲子是 A 大调，于是接下来我们所有音效都需要按 A 大调体系用代码合成了，比如：数星时的 riser 沿五声音阶，1,000 的瞬间是 A 大调的钟，confetti 使用的是同调的一点竖琴泛音。
