你在 Claude Code 会话里做了一个小时。Agent 已经吃过仓库上下文、走过死胡同，修到一半。这时同事需要接手。

常见做法是发一张截图、导出对话，或丢一条 ChatGPT 式分享链接。这些只能让对方**看**发生过什么，不能让对方打开**同一个**会话接着往下做。

这篇文章要讲的就是这件事：如何把 Claude Code 会话当成交接交出去，而不是留一份纪念品。

## 为什么「发一条分享链接」不算交接

大多数「分享 Claude Code session」的做法，发布的是一份记录：

- **截图**只截到对话的一角。对方没法搜索、没法续写，也看不到 Agent 实际改过的文件。
- **Markdown / 对话导出**是静态文本。对方可以贴进新对话，指望模型把上下文拼回来。他们是在重来。
- **ChatGPT 式分享链接**是只读快照。适合「你看一下」，不适合「下一条你来」。
- **[Lore](https://lore.link/share) 式链接**会把 thread 渲染出来——提示词、工具调用、改过的文件——也可以灌进一次**新的** Agent 运行。原来的会话仍停在原来的运行环境，同事并没有加入它。

这些都不会把同事放进现场对话、同一份差异、同一个 Worktree。如果对方还得把任务重新讲一遍，交接已经失败了。

## 「接着同一个会话做」是什么意思

在 Lody 里，[编程 Agent 会话交接](/zh/docs/session-handoff/)指的是：工作空间里的同事打开你已经在跑的那个会话，接着往下做。

对方拿到的是：

- 现场[对话](/zh/docs/session)
- Agent 产出的文件 [Diff](/zh/docs/diff-viewer)
- 这次会话的 [Worktree](/zh/docs/worktrees) 和分支
- 同一个 [Agent Config](/zh/docs/agents)——包括 Claude Code——所以对方可以直接发下一条提示词

这不是 Fork，也不是主页输入框里新开的一条。对方打开的是**这个**会话。

如果只需要留档，Lody 仍然可以把对话[复制成 Markdown](/zh/docs/copy-md)。只复制会话 URL、却没有把会话共享给团队，也不会授予访问权限——这条链接对所有者仍然有效。

## 常见做法对比

| 做法 | 对方拿到什么 | 是否同一个现场会话 |
| --- | --- | --- |
| 截图 | 对话的一张图 | 否 |
| 对话记录 / Markdown 导出 | 可以粘到别处的静态文本 | 否——只能新开对话 |
| ChatGPT 式分享链接 | 只读的对话快照 | 否 |
| [Lore](https://lore.link/share) | 渲染好的 thread，可查看或 fork 进**新的** Agent 会话 | 否——原会话仍停在原来的运行环境 |
| **Lody** | 工作空间里已有的[会话](/zh/docs/session) | **是**——打开后接着聊 |

Lore 对自己的定位是诚实的：它是查看器，有时也能用蒸馏过的上下文开一次*新的*运行。Lody 做的是另一件事——把人请进已经存在的那个会话。

完整对比（含 SpecStory 和权限模型）见[共享并交接 Agent 会话](/zh/docs/session-handoff/)。

## 如何在 Lody 里交接一个 Claude Code 会话

交接发生在团队工作空间里。会话必须已经在 Lody 工作空间里，对方必须已经是成员。下面的步骤和产品文档一致；权限边界以那一页为准。

### 1. 先把同事请进工作空间

1. 打开 **设置** -> **工作区** -> **通用**。
2. 在 **成员** 一节点击 **邀请成员**。
3. 填写对方的邮箱，并选择角色。
4. 对方可以从邮件接受邀请，你也可以复制邀请链接手动发给对方。

详见[邀请成员](/zh/docs/team#邀请成员)。

### 2. 让团队看得到这个会话

新机器默认是**私有的**。只有会话所依赖的资源被共享之后，这个会话才会对团队可见。

在会话里：

1. 打开会话的 `...` 菜单，或桌面端会话标题栏上的 **Private（私有）** 控件。
2. 选择 **Share with team…（与团队共享）**。如果缺的是机器或本地项目授权，文案可能是 **Share device with team…** 或 **Share project with team…**。
3. 确认。Lody 会共享所需的机器；若会话用的是本地项目，也会共享该项目，然后复制一条链接。

只有**设备所有者**可以共享。如果这台设备还没有登记团队访问，需要先完成登记。也可以不打开某个会话，直接在 **设置** -> **机器** 里打开 **共享机器**。见[团队机器可见性](/zh/docs/team#团队机器可见性)。

共享会话时，可能会把对应机器和/或本地项目共享给工作空间里的所有人。这台设备上的其他对话也可能随之可见。确认框会先说明范围。

### 3. 把对方带到这个会话

会话对团队可见之后：

- 把复制好的会话链接发给对方，或
- 让对方打开主页会话列表。如果只看到自己的对话，把侧边栏筛选从 **我的任务** 改成 **全部任务**（移动端是 **团队任务**）。头像可以区分是谁发起的会话。列表默认就是 **全部任务**。

对方打开的应当是**这个**会话——不是 Fork，也不是输入框里新开的一条。

### 4. 对方接着做

进入会话后，对方可以阅读完整对话、查看当前 Diff、在同一个 Worktree 和分支上继续改，并向同一个 Claude Code（或其他）Agent Config 发送下一条提示词。

Fork 是另一件事：它会把历史复制到**新的**会话里，并共用原来的机器和工作目录。需要自己另开一条对话线时用 Fork；要把同事请进原来的会话，用共享。见 [Fork 会话](/zh/docs/session#fork-会话)。

如果要让一个 Agent 去协调多段对话，见 [Agent 对话控制](/zh/docs/session-orchestration)。

## 同事看不到这个会话时

先核对三件事：对方是否已接受工作空间邀请、机器（以及本地项目，如有）是否已共享、对方看的是 **全部任务** 而不是 **我的任务**。未共享机器上的对话不会同步到其他成员的侧边栏。

加入工作空间**不会**把你的笔记本暴露出去。机器在你主动共享之前都是私有的。Agent Config 可以另外共享，让同事使用同一套 CLI 配置；见 [Agent Config](/zh/docs/agents) 和[团队功能](/zh/docs/team)。

## 只想发一份记录时

如果同事只需要看发生过什么，复制单条消息，或在会话菜单里选择 **Copy as Markdown**。那是对话记录，不是交接。见[复制对话](/zh/docs/copy-md)。
