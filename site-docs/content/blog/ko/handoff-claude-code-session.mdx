Claude Code 세션에서 한 시간을 보냈습니다. 에이전트는 이미 저장소 컨텍스트, 시행착오의 막다른 길, 그리고 절반쯤 작성된 수정 사항까지 모두 파악하고 있습니다. 이제 팀원이 여기부터 작업을 이어받아야 하는 상황입니다.

보통은 스크린샷을 보내거나, 대화 기록을 내보내거나, ChatGPT 스타일의 공유 링크를 붙여 넣어 전달합니다. 이런 방법으로는 무슨 일이 있었는지 **읽을** 수는 있습니다. 하지만 상대방이 **같은** 세션을 열어서 작업을 계속 이어갈 수는 없습니다.

이 글은 바로 그 간극에 대해 다룹니다. Claude Code 세션을 단순한 기념품이 아니라 실질적인 핸드오프로 공유하는 방법입니다.

## 공유 링크가 핸드오프가 아닌 이유

대부분의 "Claude Code 세션 공유" 워크플로는 기록을 게시하는 데 그칩니다:

- **스크린샷**은 대화의 일부분만 보여줍니다. 다음 사람은 내용을 검색하거나 이어갈 수 없고, 에이전트가 실제로 변경한 파일도 볼 수 없습니다.
- **Markdown / 대화 기록 내보내기**는 정적인 텍스트일 뿐입니다. 새 채팅에 붙여 넣고 모델이 컨텍스트를 재구성해 주기를 바랄 수는 있지만, 결국 처음부터 다시 시작하는 셈입니다.
- **ChatGPT 스타일의 공유 링크**는 읽기 전용 스냅샷입니다. "이것 좀 보세요" 용도로는 괜찮지만, "다음 턴부터는 당신이 진행하세요" 용도로는 쓸 수 없습니다.
- **[Lore](https://lore.link/share) 스타일의 링크**는 프롬프트, 도구 호출, 수정된 파일 등 스레드를 렌더링해 주고 **새로운** 에이전트 실행의 시드로 삼을 수 있습니다. 하지만 원래 세션은 실행되었던 그 자리에 남습니다. 팀원이 그 세션에 합류하는 것은 아닙니다.

이 중 어떤 것도 팀원을 실제 진행 중인 대화, 동일한 diff, 동일한 worktree 안으로 데려다주지 못합니다. 팀원이 작업을 다시 설명해야 한다면 그 핸드오프는 이미 실패한 것입니다.

## 같은 세션을 이어간다는 것의 의미

Lody에서 [코딩 에이전트 세션 핸드오프](/ko/docs/session-handoff/)는 워크스페이스 팀원이 여러분이 이미 시작한 세션을 직접 열어 그대로 이어가는 것을 의미합니다.

팀원은 다음을 그대로 이어받게 됩니다:

- 실시간 [대화](/ko/docs/session)
- 에이전트가 생성한 파일 [diff](/ko/docs/diff-viewer)
- 세션 [worktree](/ko/docs/worktrees)와 브랜치
- Claude Code를 포함한 동일한 [에이전트 설정](/ko/docs/quickstart) — 따라서 바로 다음 프롬프트를 보낼 수 있습니다

이것은 포크(fork)도 아니고 새로운 컴포저(composer) 스레드도 아닙니다. 말 그대로 **바로 그** 세션을 여는 것입니다.

단순한 기록만 필요할 때는 Lody에서도 여전히 [대화를 Markdown으로 복사](/ko/docs/copy-md)할 수 있습니다. 또한 세션을 공유하지 않고 세션 URL만 복사해서 전달하면 접근 권한이 부여되지 않으며, 해당 링크는 소유자에게만 계속 작동합니다.

## 일반적인 방법들과의 비교

| 방법 | 상대방이 받는 것 | 동일한 실시간 세션 여부 |
| --- | --- | --- |
| 스크린샷 | 대화 화면 이미지 | 아니요 |
| 대화 기록 / Markdown 내보내기 | 다른 곳에 붙여 넣을 정적 텍스트 | 아니요 — 새 채팅을 시작해야 함 |
| ChatGPT 스타일 공유 링크 | 읽기 전용 대화 스냅샷 | 아니요 |
| [Lore](https://lore.link/share) | 조회하거나 **새로운** 에이전트 세션으로 포크할 수 있는 렌더링된 스레드 | 아니요 — 원래 세션은 실행된 곳에 그대로 남음 |
| **Lody** | 기존 워크스페이스 [세션](/ko/docs/session) | **예** — 열어서 바로 이어갈 수 있음 |

Lore는 자신의 역할을 분명히 합니다. 뷰어이자, 때로는 정제된 컨텍스트로부터 *새로운* 실행을 시작하는 수단입니다. Lody는 이와 다른 역할을 합니다. 기존 세션에 누군가를 초대하는 것입니다.

SpecStory 및 권한 모델을 포함한 전체 비교 내용은 [코딩 에이전트 세션 공유](/ko/docs/session-handoff/)에서 확인할 수 있습니다.

## Lody에서 Claude Code 세션을 핸드오프하는 방법

핸드오프는 팀 워크스페이스에서 이루어지는 작업입니다. 세션이 Lody 워크스페이스 안에 있어야 하고, 상대방 역시 해당 워크스페이스의 멤버여야 합니다. 아래 단계는 제품 가이드와 동일하며, 모든 권한 예외 사례를 확인하고 싶다면 해당 페이지를 참고하세요.

### 1. 워크스페이스에 팀원 초대하기

1. **Settings** -> **Workspace** -> **General**을 엽니다.
2. **Members** 섹션에서 **Invite Member**를 클릭합니다.
3. 이메일을 입력하고 역할을 선택합니다.
4. 상대방이 이메일에서 초대를 수락하거나, 초대 링크를 복사해 직접 전달할 수 있습니다.

자세한 내용: [멤버 초대](/ko/docs/team#invite-members).

### 2. 팀에게 세션 공개하기

새 머신은 기본적으로 **비공개(private)** 상태로 유지됩니다. 세션이 실행되는 리소스가 공유되어야만 팀원에게 세션이 표시됩니다.

세션 화면에서 다음을 진행하세요:

1. 세션의 `...` 메뉴 또는 데스크톱 세션 헤더의 **Private** 컨트롤을 엽니다.
2. **Share with team…**을 선택합니다(부족한 권한에 따라 **Share device with team…** 또는 **Share project with team…**으로 표시될 수 있습니다).
3. 확인을 누릅니다. Lody가 필요한 머신과 로컬 프로젝트(해당하는 경우)를 공유한 뒤 링크를 복사합니다.

**기기 소유자**만 공유할 수 있습니다. 기기가 팀 접근용으로 등록되어 있지 않다면 먼저 등록하세요. 특정 세션을 열지 않고도 **Settings** -> **Machines** -> **Share machine**에서 머신을 공유할 수 있습니다. [팀 머신 공개 설정](/ko/docs/team#team-machine-visibility)을 참고하세요.

세션을 공유하면 해당 머신 및/또는 로컬 프로젝트가 워크스페이스의 모든 멤버에게 공유될 수 있으며, 그 기기의 다른 대화도 함께 표시될 수 있습니다. 확인을 누르기 전 확인 대화상자에서 공유 범위를 안내합니다.

### 3. 팀원에게 세션 안내하기

세션이 팀에게 공개된 후에는 다음 중 한 가지 방법으로 안내합니다:

- 복사된 세션 링크를 보냅니다. 또는
- 홈 화면의 세션 목록을 열도록 안내합니다. 본인 대화만 보인다면 사이드바 필터를 **My Tasks**에서 **All Tasks**(모바일에서는 **Team Tasks**)로 전환하면 됩니다. 각 세션을 누가 시작했는지는 아바타로 표시되며, 목록의 기본값은 **All Tasks**입니다.

팀원은 포크나 컴포저의 새 스레드가 아니라 **바로 그** 세션을 열어야 합니다.

### 4. 팀원이 작업 이어가기

세션에 들어오면 전체 대화를 읽고, 현재 diff를 검토하고, 동일한 worktree와 브랜치에서 계속 작업하며, 동일한 Claude Code(또는 다른) 에이전트 설정으로 다음 프롬프트를 보낼 수 있습니다.

포크(Fork)는 다른 도구입니다. 동일한 머신과 디렉터리에서 기록을 **새로운** 세션으로 복사합니다. 대화의 개인 분기가 필요할 때는 포크를 사용하고, 팀원이 원본 세션에 직접 참여하길 원할 때는 공유를 사용하세요. [세션 포크하기](/ko/docs/session#fork-a-session)를 참고하세요.

하나의 에이전트에서 여러 대화를 조율하려면 [에이전트 세션 제어](/ko/docs/session-orchestration)를 참고하세요.

## 팀원에게 세션이 보이지 않는 경우

세 가지를 확인해 주세요. 워크스페이스 초대를 수락했는지, 머신(및 로컬 프로젝트가 있다면 프로젝트)이 공유되었는지, 그리고 **My Tasks**가 아니라 **All Tasks**를 보고 있는지 확인합니다. 공유되지 않은 머신의 대화는 다른 멤버의 사이드바에 동기화되지 않습니다.

워크스페이스에 참여한다고 해서 여러분의 노트북이 노출되지는 **않습니다**. 머신은 직접 공유하기 전까지 비공개로 유지됩니다. 팀원들이 동일한 CLI 설정으로 실행할 수 있도록 에이전트 설정은 별도로 공유할 수 있습니다. [에이전트 설정](/ko/docs/quickstart)과 [팀 기능](/ko/docs/team)을 참고하세요.

## 기록만 필요한 경우

팀원이 지금까지의 진행 내용만 읽으면 된다면 메시지를 복사하거나 세션 메뉴에서 **Copy as Markdown**을 사용하세요. 이것은 핸드오프가 아니라 대화 기록입니다. [대화 복사하기](/ko/docs/copy-md)를 참고하세요.
