Lody 最近在 GitHub 上達到了 1,000 顆星。感謝每一位按下星星的朋友！

這樣的里程碑值得擁有一支像樣的慶祝影片，而這支影片的每一幀畫面與每一個聲音，全都是透過程式碼渲染出來的。因此，我們想藉這篇文章介紹它的製作過程，並分享背後的設計思路。

## 為什麼要用程式碼做影片

我們選用了 [Remotion](https://remotion.dev)，因為在其中影片的每一幀都是一個 React 元件在特定時間點的渲染結果。這代表影片能享有程式碼的所有優勢：版本控制、參數化、元件複用，以及在 60fps 下精確到每一幀的控制力。

運鏡感覺不對？改個數字重新渲染，幾十秒後就能得到新版剪輯——不必在時間軸上繼續拖曳微調半小時。同時它對 AI 也很友善：AI 可以直接產出 React 元件，或輸出 JSON 資料再交由 React 渲染。

整支影片的結構很簡單：

<img src="/_docs-assets/1k-video/timeline.png" alt="影片結構時間軸" />

前 7 秒是在 GitHub 儲存庫頁面上的 3D 運鏡：鏡頭推進、游標點擊 Star，數字一路攀升至 1,000；最後 6 秒則落回 Lody 自己的水彩世界收尾。

以下是我們覺得最有意思的幾個工程故事。

## 1. 重繪 GitHub，而不是使用截圖

從一開始，我們就覺得不應該使用真實截圖。

在鏡頭推進時，點陣圖的解析度始終有限——如果讓 AI 去截圖頁面，很容易碰到一放大就整個糊掉的極端情況。而且截圖裡的任何元素都動不了。

因此我們用 DOM 重繪了整個頁面——分頁列、按鈕、檔案清單、About 側邊欄——圖示則全部取自 GitHub 官方的 octicons。

重繪還有一個額外的好處：元素可以動起來。在開場時，頁面的每個區塊從上方落下，帶著輕微的過衝（overshoot）「停靠」定位，彷彿介面就在你眼前自行組裝起來。

這段效果的核心是一個不到十行的函式：

```tsx
const dock = (delay: number): React.CSSProperties => {
  const s = spring({frame: frame - delay, fps, config: {damping: 14, mass: 0.9, stiffness: 160}});
  return {
    opacity: interpolate(s, [0, 0.45], [0, 1], {extrapolateRight: 'clamp'}),
    transform: `translateY(${interpolate(s, [0, 1], [-80, 0])}px)`,
  };
};
```

在每個區塊上展開 `...dock(n)`，由上而下將 `n` 錯開幾幀，整個頁面就有了呼吸感。

至於游標點擊 Star 按鈕的動作：由於按鈕在 3D 空間中是傾斜擺放的，我們將頁面座標通過同一套旋轉投影矩陣反算出螢幕座標——讓游標永遠精準落在按鈕正中央。

## 2. 鏡頭感

「像攝影機拍出來的」與「會動的 PowerPoint」之間的差別，多半在於景深與動態的連續性。

最簡單的景深做法是整張模糊加上一個清晰視窗，但那樣會留下生硬的邊界。於是我們疊了三個圖層：最底層是全畫面重度模糊，中間層是覆蓋大範圍羽化區域的輕度模糊，最上層則是僅存在於焦平面附近的銳利核心。三層都搭配寬幅的柔邊遮罩（soft mask），讓模糊程度隨著離焦距離漸進衰減：

<img src="/_docs-assets/1k-video/dof.png" alt="三層景深圖層" />

> 嚴格來說，漸進式景深是光學成像的結果——它應該是一個卷積核（convolution kernel），而不是單純的線性漸層。但考量到社群媒體上影片的解析度與位元率，簡單的漸層已經綽綽有餘。

至於連續性：在運鏡結束後，頁面會有一個細微的「呼吸」擺動。第一版的寫法是讓擺動在鏡頭停下的那一幀立刻生效——但正弦波在那一刻並不在零點上，於是畫面出現了一絲幾乎難以察覺的「頓挫」，看起來就像掉了一幀。

修正的方法是讓正弦波從過零點（zero crossing）開始，再乘上一個淡入／淡出的包絡線：

```tsx
const breathe =
  Math.sin((frame - 92) / 55) * 0.9 *
  interpolate(frame, [92, 122, 266, 296], [0, 1, 1, 0], {
    extrapolateLeft: 'clamp',
    extrapolateRight: 'clamp',
  });
```

如此一來，擺動便會從靜止中緩緩浮現，並在鏡頭拉遠前悄悄收斂消失。

## 3. 聲音也是渲染出來的

配樂並不是隨便套一首罐頭音樂墊底。我們選用了一首免版稅樂曲作為基底——這首曲子是 A 大調，因此後續所有音效都用程式碼在 A 大調的音階體系內合成：數字攀升時的 riser 音軌沿著五聲音階上揚，抵達 1,000 那一刻是 A 大調的鐘聲，而彩帶飛舞的閃耀聲則用了同調性的豎琴泛音。
