Lody 是 Coding Agent 的協作工作區。它將分散在不同成員、Agent 與機器上的對話、執行狀態及程式碼變更集中到同一個空間。團隊成員可以開啟彼此的對話繼續討論，也可以從瀏覽器或手機向線上機器發起任務，並在任務執行期間補充指令。

Lody 的 CLI 與本地桌面用戶端現已開源，原始碼位於 [github.com/lodyai/lody](https://github.com/lodyai/lody)。

但我們想解決的問題不僅止於此。

軟體系統的複雜度並不只存在於程式碼之中。一段程式碼可能源自某條業務規則、一次正式環境事故、某位重要客戶的相容性需求，或是一項後來已不復存在的技術限制。隨著專案演進，這些決策層層累積，最終形塑出系統如今的樣貌。程式碼保留了結果，卻不一定能保留產生這個結果的原因。

這些原因散落在設計文件、Pull Request、Issue、會議、Agent 對話以及團隊成員的記憶中。當有人接手某個模組、審查變更或準備重構時，困難之處往往不只是讀懂程式碼本身，而是要還原背後的業務規則、領域概念、設計權衡與歷史決策。

我們希望 Lody 能成為軟體團隊與 Coding Agent 共用的理解層：將對話、程式碼、任務、文件與過往決策串聯起來，讓團隊得以追溯系統為何演變成今天的樣貌，並判斷新的變更可能會影響哪些既有約束。

對話只是理解專案的起點。Lody 將圍繞這份理解發展任務管理、文件與程式碼審查等能力。未來，我們也希望探索外掛機制，讓使用者能自訂適合自家團隊的工具，將這些工具中的資料與其他專案脈絡連結起來，並在團隊之間保持同步。

## Lody 的同步方式

Lody 採用基於 Loro Stack 建構的本地優先同步引擎。大多數協作狀態都透過 [Loro](https://loro.dev/) 與 [Flock](https://www.npmjs.com/package/@loro-dev/flock-wasm) 來表示，並經由 Loro Streams 在裝置之間同步。Loro 與 Flock 皆基於 CRDT，允許各個複本獨立變更，並在重新連線後進行合併。

我們選擇 CRDT，最主要的原因是希望專案脈絡能夠做到 [local-first](https://www.inkandswitch.com/essay/local-first/)：每台裝置都擁有一份可直接使用的本地複本，並在網路恢復後同步變更。

應用程式可以被替換，但資料的生命週期應當比應用程式更長久。Agent 與工具會不斷演變，團隊所累積的專案脈絡不應該隨之消失。開放的資料格式與實作，也能降低這些脈絡被鎖在單一應用程式中的風險。

Loro 的通用資料結構也能表達評論、富文本文件、白板等工具所需的協作狀態。這讓同一套同步引擎有機會支援各種不同的互動形式，也為未來的社群外掛提供共同的資料基礎。

Lody 目前尚未支援端對端加密，跨裝置協作仍須依賴 Lody 的託管同步服務。我們已經完成端對端加密工作區的第一版設計。

我們的方向，是讓團隊與 Agent 共同累積的專案脈絡最終仍由團隊自己掌控。
