你在一個 Claude Code 工作階段中花了一小時。Agent 已經掌握了儲存庫上下文、踩過的死胡同，以及寫到一半的修復程式。接著，團隊成員需要從這裡接手。

常見的做法是傳一張截圖、匯出對話紀錄，或貼上一條 ChatGPT 風格的分享連結。這些方式只能讓對方**閱讀**發生過什麼，卻無法讓對方打開**同一個**工作階段繼續往下做。

這就是這篇文章要談的落差：如何把 Claude Code 工作階段當作工作交接分享出去，而不只是一份紀念品。

## 為什麼分享連結不算交接

大多數「分享我的 Claude Code 工作階段」工作流程，本質上只是發佈一份紀錄：

- **截圖**只看得到對話的一角。接手的人無法搜尋、無法接續對話，也看不到 Agent 實際修改過哪些檔案。
- **Markdown／對話紀錄匯出**只是靜態文字。對方可以把它貼進新的對話裡，期盼模型能重新拼湊出上下文——這等同於重新開始。
- **ChatGPT 風格的分享連結**是一份唯讀快照。適合「你看一下這個」，但不適用於「下一輪換你接手」。
- **[Lore](https://lore.link/share) 風格的連結**會把討論串（包含提示詞、工具呼叫、更動過的檔案）渲染出來，也能用來啟動一次**新的** Agent 執行。但原本的工作階段仍留在原本的執行環境中，團隊成員並沒有加入它。

上述做法都無法讓團隊成員直接進入進行中的對話、查看同一份 Diff，並在同一個 Worktree 中接手。如果對方還得重新向 Agent 解釋一次任務，這場交接就已經失敗了。

## 「接續同一個工作階段」代表什麼

在 Lody 中，[Coding Agent 工作階段交接](/zh-hant/docs/session-handoff/)指的是：工作區裡的團隊成員直接打開你已經開始的那個工作階段，並接著往下做。

對方會取得：

- 進行中的[對話](/zh-hant/docs/session)
- Agent 產生的檔案 [Diff](/zh-hant/docs/diff-viewer)
- 該工作階段的 [Worktree](/zh-hant/docs/worktrees) 與分支
- 同一套 [Agent Config](/zh-hant/docs/quickstart)（包括 Claude Code），因此可以直接送出下一則提示詞

這不是建立分支（Fork），也不是在輸入框新開一條對話。對方打開的就是**那個**工作階段。

如果你只需要留存紀錄，Lody 依然支援[將對話複製為 Markdown](/zh-hant/docs/copy-md)。此外，單純複製工作階段 URL 而沒有將工作階段分享給團隊，並不會授予他人存取權限——該連結只會繼續對擁有者有效。

## 常見做法比較

| 做法 | 對方取得的內容 | 是否為同一個進行中工作階段？ |
| --- | --- | --- |
| 截圖 | 一張對話畫面圖片 | 否 |
| 對話紀錄／Markdown 匯出 | 可貼到其他地方的靜態文字 | 否——必須重新開啟新對話 |
| ChatGPT 風格分享連結 | 唯讀的對話快照 | 否 |
| [Lore](https://lore.link/share) | 渲染後的討論串，可檢視或 Fork 成**新的** Agent 工作階段 | 否——原工作階段仍留在原本的執行環境 |
| **Lody** | 工作區中既有的[工作階段](/zh-hant/docs/session) | **是**——打開即可接續 |

Lore 對自身的定位很坦白：它是一個檢視器，有時也能透過提煉後的上下文啟動一次*新的*執行。而 Lody 處理的是另一件事——邀請別人加入已經存在的工作階段。

完整比較（包含 SpecStory 與權限模型）請參閱[分享 Coding Agent 工作階段](/zh-hant/docs/session-handoff/)。

## 如何在 Lody 中交接 Claude Code 工作階段

交接屬於團隊工作區的操作。該工作階段必須位於 Lody 工作區中，且對方必須是工作區成員。以下步驟與產品指南一致；若想了解所有權限邊界情況，請參閱該頁面。

### 1. 先邀請對方加入工作區

1. 開啟 **設定** -> **工作區** -> **一般**。
2. 在 **成員** 區塊中點擊 **邀請成員**。
3. 輸入對方的 Email 並選擇角色。
4. 對方可以透過 Email 接受邀請，或者你也可以複製邀請連結自行傳給對方。

詳細說明：[邀請成員](/zh-hant/docs/team#invite-members)。

### 2. 讓團隊看得到這個工作階段

新增的機器預設為**私人**狀態。唯有在工作階段所依賴的資源都完成分享後，該工作階段才會對團隊可見。

在工作階段畫面中：

1. 開啟工作階段的 `...` 選單，或桌面版工作階段標題列上的 **Private（私人）** 控制項。
2. 選擇 **Share with team…（與團隊分享…）**（若缺少的是裝置或專案授權，按鈕文字可能會顯示為 **Share device with team…** 或 **Share project with team…**）。
3. 確認操作。Lody 會分享所需的機器（若使用的是本機專案，也會一併分享該專案），接著複製一條連結。

只有**裝置擁有者**可以進行分享。如果這台裝置尚未註冊團隊存取權限，請先完成註冊。你也可以不開啟特定工作階段，直接從 **設定** -> **機器** -> **分享機器** 來分享機器。請參閱[團隊機器可見性](/zh-hant/docs/team#team-machine-visibility)。

分享工作階段可能會將其所屬的機器及／或本機專案分享給工作區內的所有人，該裝置上的其他對話也可能會隨之變得可見。確認對話框會在你確認前明確列出分享範圍。

### 3. 引導對方進入該工作階段

當工作階段對團隊可見後：

- 傳送剛剛複製的工作階段連結，或
- 請對方開啟首頁的工作階段清單。如果對方只看得到自己的對話，請將側邊欄篩選條件從 **我的任務** 切換為 **全部任務**（行動版為 **團隊任務**）。每個項目旁的頭像會顯示是由誰發起的。清單預設為 **全部任務**。

對方應該打開的是**那個**工作階段——不要使用 Fork，也不要在輸入框裡新開一條對話。

### 4. 由對方接續工作

進入工作階段後，對方即可閱讀完整對話、檢視目前的 Diff、在同一個 Worktree 與分支上繼續作業，並向同一個 Claude Code（或其他）Agent Config 送出下一則提示詞。

Fork 是另一種用途的工具：它會將對話紀錄複製到同一台機器與目錄下的**新**工作階段中。當你想要替對話開一條私人分支時，請用 Fork；當你希望團隊成員直接進入原本的工作階段時，請用分享。請參閱 [Fork 工作階段](/zh-hant/docs/session#fork-a-session)。

若要透過單一 Agent 協調多個對話，請參閱 [Agent 工作階段控制](/zh-hant/docs/session-orchestration)。

## 如果對方看不到該工作階段

請先確認三件事：對方已經接受工作區邀請、對應的機器（以及本機專案，如有的話）已分享，且對方檢視的是 **全部任務** 而非 **我的任務**。未分享的機器絕對不會將其對話同步到其他成員的側邊欄。

加入工作區**不會**暴露你的筆電。在你主動分享之前，機器都會維持私人狀態。Agent Config 則可另行分享，讓團隊成員使用相同的 CLI 設定；請參閱 [Agent Config](/zh-hant/docs/quickstart) 與[團隊功能](/zh-hant/docs/team)。

## 當你只需要留存紀錄時

如果團隊成員只需要閱讀發生過什麼，直接複製單則訊息，或從工作階段選單中使用 **Copy as Markdown** 即可。這只是對話紀錄，並非交接。請參閱[複製對話](/zh-hant/docs/copy-md)。
