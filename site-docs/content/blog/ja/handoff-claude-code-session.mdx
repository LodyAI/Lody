Claude Code のセッションで 1 時間ほど作業したとします。エージェントはすでにリポジトリのコンテキストや行き詰まった箇所を把握し、途中まで書いた修正案も持っています。そして、ここから先をチームメンバーに引き継ぐ必要が出てきました。

よくある対応は、スクリーンショットを送ったり、会話ログをエクスポートしたり、ChatGPT のような共有リンクを貼ったりすることです。こうした方法では、何が起きたかを相手が**読む**ことはできても、**同じ**セッションを開いて作業を続けることはできません。

この記事で取り上げるのはまさにそのギャップです。Claude Code セッションを単なる記念品ではなく、実務の「引き継ぎ」として共有する方法を解説します。

## 共有リンクが引き継ぎにならない理由

「Claude Code セッションを共有する」ワークフローの多くは、あくまで記録を公開するものです。

- **スクリーンショット**はチャットの一部しか写せません。次の担当者は検索も続行もできず、エージェントが実際に変更したファイルも確認できません。
- **Markdown や会話ログのエクスポート**は静的なテキストにすぎません。新しいチャットに貼り付けてモデルがコンテキストを再構築してくれることを期待するしかなく、結局は最初からやり直しになります。
- **ChatGPT 式の共有リンク**は読み取り専用のスナップショットです。「これを見て」には使えても、「次のターンはお願い」には役に立ちません。
- **[Lore](https://lore.link/share) のようなリンク**は、プロンプト、ツール呼び出し、変更したファイルといったスレッドを描画でき、それを元に**新しい**エージェント実行を開始することもできます。しかし、元のセッションは元の実行環境にとどまったままであり、チームメンバーがそのセッション自体に参加するわけではありません。

これらの方法はいずれも、チームメンバーをライブの会話、同じ差分、同じ worktree の中に入れることはできません。タスクを一から説明し直さなければならない時点で、引き継ぎはすでに失敗しています。

## 「同じセッションを続ける」とはどういうことか

Lody における[コーディングエージェントのセッション引き継ぎ](/ja/docs/session-handoff/)とは、同じワークスペースのチームメンバーが、あなたがすでに開始したセッションを開いてそのまま作業を続けることを意味します。

引き継いだメンバーは次の環境をそのまま利用できます。

- ライブの[会話](/ja/docs/session)
- エージェントが作成したファイルの[差分（diff）](/ja/docs/diff-viewer)
- セッションの [worktree](/ja/docs/worktrees) とブランチ
- Claude Code を含む同じ [Agent Config](/ja/docs/quickstart)（そのまま次のプロンプトを送信可能）

これはフォーク（Fork）でも、新しいコンポーザーで立てた別スレッドでもありません。まさに**その**セッションを開くのです。

記録だけが必要な場合は、これまで通り Lody で[会話を Markdown としてコピー](/ja/docs/copy-md)できます。なお、セッションを共有せずにセッション URL だけをコピーしてもアクセス権は付与されません（そのリンクは引き続き所有者のみに有効です）。

## 主な共有方法の比較

| 方法 | 相手が得られるもの | 同じライブセッションか |
| --- | --- | --- |
| スクリーンショット | チャットの画像 | いいえ |
| 会話ログ / Markdown エクスポート | 別の場所に貼り付ける静的テキスト | いいえ — 新しいチャットを開始 |
| ChatGPT 式の共有リンク | 読み取り専用の会話スナップショット | いいえ |
| [Lore](https://lore.link/share) | 閲覧したり、**新しい**エージェントセッションへフォークしたりできる描画済みスレッド | いいえ — 元のセッションは元の実行環境に残る |
| **Lody** | ワークスペースの既存[セッション](/ja/docs/session) | **はい** — 開いてそのまま続行 |

Lore はその役割が明確です。ビューアーであり、場合によっては整理されたコンテキストから*新しい*実行を始めるための手段です。Lody が担うのはそれとは別の役割——既存のセッションにメンバーを招き入れることです。

SpecStory や権限モデルを含めた詳細な比較については、[コーディングエージェントのセッションを共有する](/ja/docs/session-handoff/)をご覧ください。

## Lody で Claude Code セッションを引き継ぐ手順

引き継ぎはチームワークスペース上の操作です。セッションが Lody ワークスペース内に存在し、相手がそのワークスペースのメンバーである必要があります。以下の手順は製品ガイドに沿ったものです。権限まわりの詳細なエッジケースを確認したい場合は、製品ガイドを参照してください。

### 1. ワークスペースにメンバーを招待する

1. **Settings** -> **Workspace** -> **General** を開きます。
2. **Members** セクションで **Invite Member** をクリックします。
3. 相手のメールアドレスを入力し、ロールを選択します。
4. 相手はメールから招待を承認できます。招待リンクをコピーして直接送ることも可能です。

詳細は[メンバーの招待](/ja/docs/team#メンバーを招待する)をご覧ください。

### 2. セッションをチームに公開する

新しいマシンはデフォルトで**プライベート**に設定されています。セッションがチームに表示されるのは、そのセッションが実行されているリソースが共有されている場合のみです。

セッション画面からの操作：

1. セッションの `...` メニュー、またはデスクトップ版セッションヘッダーにある **Private** コントロールを開きます。
2. **Share with team…** を選択します（不足している権限に応じて、ラベルは **Share device with team…** または **Share project with team…** と表示される場合があります）。
3. 確認します。Lody が必要なマシン（ローカルプロジェクトの場合はそのプロジェクトも）を共有し、リンクをコピーします。

共有操作を行えるのは**デバイス所有者**のみです。デバイスがチームアクセス用に登録されていない場合は、先に登録を済ませてください。特定のセッションを開かずに、**Settings** -> **Machines** -> **Share machine** からマシンを共有することもできます。詳しくは[チームでのマシン公開設定](/ja/docs/team#チームでのマシン公開設定)をご覧ください。

セッションを共有すると、そのマシンやローカルプロジェクトがワークスペース内の全員と共有される場合があります。そのデバイス上の他の会話も表示されるようになる可能性があるため、確定前に表示される確認ダイアログで共有範囲をご確認ください。

### 3. セッションの場所を伝える

セッションがチームに表示されるようになったら：

- コピーしたセッションリンクを送るか、
- ホームページのセッション一覧を開いてもらいます。自分の会話しか表示されない場合は、サイドバーのフィルターを **My Tasks** から **All Tasks**（モバイル版では **Team Tasks**）に切り替えてください。誰が開始したかはアバターで表示されます。一覧のデフォルトは **All Tasks** です。

相手に開いてもらうのは、フォークやコンポーザーでの新規スレッドではなく、**その**セッション自体です。

### 4. 相手が作業を続行する

セッションに入ると、相手は会話全体を読み、現在の差分（diff）を確認し、同じ worktree とブランチ上で作業を続け、同じ Claude Code（またはその他の）Agent Config に対して次のプロンプトを送信できます。

なお、フォーク（Fork）は別の機能です。フォークは同じマシン・同じディレクトリ上に履歴をコピーして**新しい**セッションを作成します。会話から自分専用の分岐を作りたい場合はフォークを、元のセッションにチームメンバーを招き入れたい場合は共有を使用してください。詳細は[セッションのフォーク](/ja/docs/session#セッションをフォークする)をご覧ください。

1 つのエージェントから複数の会話を統括・連携させたい場合は、[エージェントによるセッション制御](/ja/docs/session-orchestration)をご覧ください。

## 相手からセッションが見えない場合

次の 3 点を確認してください。ワークスペースへの招待を承認済みであること、マシン（および該当する場合はローカルプロジェクト）が共有されていること、そして表示対象が **My Tasks** ではなく **All Tasks** になっていることです。共有されていないマシンの会話は、他のメンバーのサイドバーに同期されることはありません。

ワークスペースに参加しただけでは、あなたのノート PC が公開されることは**ありません**。マシンは明示的に共有するまで非公開のままです。Agent Config は別途共有できるため、チームメンバーが同じ CLI セットアップで実行することも可能です。詳しくは [Agent Config](/ja/docs/quickstart) と[チーム機能](/ja/docs/team)をご覧ください。

## 記録だけが必要な場合

チームメンバーがこれまでの経緯を読むだけでよい場合は、個別のメッセージをコピーするか、セッションメニューから **Copy as Markdown** を使用してください。これは引き継ぎではなく会話ログの記録です。詳しくは[会話のコピー](/ja/docs/copy-md)をご覧ください。
