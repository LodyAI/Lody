Lodyは先日、GitHubで1,000スターを達成しました。スターを押してくださった皆さま、本当にありがとうございます！

マイルストーンには、それにふさわしい記念動画が欠かせません。今回はその全フレームからすべてのサウンドに至るまで、すべてコードからレンダリングして制作しました。どのように作ったのか、その背景にある考え方とあわせてご紹介します。

## なぜコードで動画を作るのか

今回は [Remotion](https://remotion.dev) を採用しました。動画の1フレーム1フレームが、ある時点におけるReactコンポーネントとしてレンダリングされるためです。これにより、バージョン管理、パラメータ化、コンポーネントの再利用、60fpsでのフレーム単位の正確な制御といった、コードならではのメリットをすべて動画制作に取り込めます。

カメラワークに違和感があれば、数値を変えて再レンダリングするだけで数十秒後には新しいカットができあがります。タイムライン上で30分かけてドラッグ＆ドロップを繰り返す必要はありません。また、AIとの相性も抜群です。AIがReactコンポーネントを直接生成したり、ReactがレンダリングするためのJSONデータを出力したりできます。

動画全体の構成はシンプルです。

<img src="/_docs-assets/1k-video/timeline.png" alt="動画構成のタイムライン" />

最初の7秒間はGitHubリポジトリページ上での3Dカメラワークです。カメラが寄り、カーソルがStarをクリックして、カウンターが1,000までカウントアップします。続く最後の6秒間では、Lody独自の水彩画風の世界へと着地します。

ここからは、特に面白かった技術的なポイントをいくつかご紹介します。

## 1. スクリーンショットを使わずGitHubを描き直す

制作の最初から、実際のスクリーンショットは使うべきではないと考えていました。

カメラが寄っていくカットでは、ビットマップ画像の解像度に限界があります。AIにページのスクリーンショットを撮らせても、ズームインした瞬間に全体がぼやけて滲んでしまうケースに突き当たります。さらに、スクリーンショットの中の要素は一切動かすことができません。

そこで、タブバーやボタン、ファイル一覧、Aboutサイドバーに至るまでページ全体をDOMで描き直し、アイコンにはGitHub公式のocticonsを使用しました。

描き直したことで、要素に動きをつけられるという副産物もありました。オープニングでは、ページの各セクションが上から落ちてきて、わずかなオーバーシュートを伴いながら定位置に「ドッキング」し、インターフェースが目の前で自ら組み上がっていくような演出にしています。

その中核となっているのは、10行にも満たない関数です。

```tsx
const dock = (delay: number): React.CSSProperties => {
  const s = spring({frame: frame - delay, fps, config: {damping: 14, mass: 0.9, stiffness: 160}});
  return {
    opacity: interpolate(s, [0, 0.45], [0, 1], {extrapolateRight: 'clamp'}),
    transform: `translateY(${interpolate(s, [0, 1], [-80, 0])}px)`,
  };
};
```

各セクションに `...dock(n)` をスプレッド構文で渡し、`n` を上から順に数フレームずつずらすだけで、ページに生命感が宿ります。

Starボタンをクリックするカーソルについては、ボタンが3D空間上で傾いた状態にあるため、ページ座標を同じ回転・投影行列に通してスクリーン座標を算出しています。これにより、カーソルが常にボタンの中央へ正確に着地します。

## 2. カメラらしい質感

「カメラで撮影した映像」と「動くPowerPoint」の違いは、主に被写界深度（DoF）と動きの連続性にあります。

被写界深度を表現する最も単純な方法は、全体を大きくぼかして一部分だけシャープに切り抜くことですが、それだと境界線がくっきり残ってしまいます。そこで私たちは3枚のプレートを重ねました。一番下に画面全体を強くぼかしたプレート、真ん中に広いフェザー領域を覆う弱めのぼかしプレート、そして一番上に焦点面付近だけに存在するシャープなコアプレートを配置しています。3枚すべてに広く柔らかなマスクを適用しているため、ピントのずれに応じてボケ量がなだらかに減衰します。

<img src="/_docs-assets/1k-video/dof.png" alt="被写界深度を構成する3枚のプレート" />

> 厳密に言えば、段階的な被写界深度は光学的な現象であり、単純な線形グラデーションではなく畳み込みカーネルで表現すべきものです。しかし、SNSで再生される動画の解像度やビットレートを踏まえれば、シンプルなグラデーションでも十分すぎる効果が得られます。

連続性について言えば、カメラワークが終わったあと、ページには「呼吸」のような微かな揺らぎを加えています。最初のバージョンではカメラが停止したフレームで即座に揺らぎを開始していましたが、その瞬間のサイン波の値がゼロでなかったため、コマ落ちしたかのようなごくわずかな「引っかかり」が映像に出てしまいました。

解決策は、サイン波をゼロ交差（ゼロクロス）から開始し、フェードイン／フェードアウトのエンベロープを掛け合わせることでした。

```tsx
const breathe =
  Math.sin((frame - 92) / 55) * 0.9 *
  interpolate(frame, [92, 122, 266, 296], [0, 1, 1, 0], {
    extrapolateLeft: 'clamp',
    extrapolateRight: 'clamp',
  });
```

こうして、静止状態から自然に揺らぎが立ち上がり、カメラが引く直前に静かに収まっていきます。

## 3. サウンドもコードでレンダリング

BGMも単にストック音源を無造作に敷いただけではありません。ベースにはイ長調（Aメジャー）のロイヤリティフリー楽曲を使用し、すべての効果音もイ長調の体系に沿ってコードで合成しています。カウントアップの背後で鳴るライザーはペンタトニックスケールを駆け上がり、1,000到達の瞬間にはイ長調のベルが鳴り響き、紙吹雪のきらめきには同じ調のハープの倍音を重ねています。
