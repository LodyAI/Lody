Вы провели час в сессии Claude Code. У агента уже есть контекст репозитория, тупиковые ветки поиска и наполовину написанное исправление. И тут задачу нужно передать коллеге.

Обычно в такой ситуации отправляют скриншот, экспортируют историю переписки или скидывают ссылку для просмотра в стиле ChatGPT. Это позволяет **прочитать**, что происходило, но не даёт открыть **ту же самую** сессию и продолжить работу.

Именно об этом пробеле и пойдёт речь: как поделиться сессией Claude Code так, чтобы передать работу, а не сувенир на память.

## Почему обычная ссылка — это не передача работы

Большинство сценариев вроде «поделиться сессией Claude Code» просто публикуют запись:

- **Скриншот** показывает лишь фрагмент чата. Следующий разработчик не сможет выполнить по нему поиск, продолжить диалог или увидеть, какие файлы агент реально изменил.
- **Экспорт в Markdown / историю переписки** — это статичный текст. Коллега может вставить его в новый чат и надеяться, что модель восстановит контекст. По сути, всё начинается с нуля.
- **Ссылка в стиле ChatGPT** — это снимок только для чтения. Подходит для «посмотри сюда», но бесполезна для «теперь твой ход».
- **Ссылка в стиле [Lore](https://lore.link/share)** отображает тред — промпты, вызовы инструментов, затронутые файлы — и может послужить основой для **нового** запуска агента. Но исходная сессия остаётся там, где была запущена. Коллега к ней не подключается.

Ни один из этих способов не помещает коллегу в живой диалог, к тем же diff и в тот же worktree. Если ему приходится заново объяснять задачу агенту, передача работы уже не удалась.

## Что значит продолжить ту же сессию

В Lody [передача сессии агента разработки](/ru/docs/session-handoff/) означает, что участник рабочего пространства открывает уже начатую вами сессию и продолжает работу прямо в ней.

Он получает:

- живой [диалог](/ru/docs/session)
- [diff](/ru/docs/diff-viewer) файлов, подготовленных агентом
- [worktree](/ru/docs/worktrees) и ветку сессии
- ту же [конфигурацию агента](/ru/docs/quickstart) — включая Claude Code, — чтобы можно было отправить следующий промпт

Это не форк и не новый тред в окне ввода. Коллега открывает именно **эту** сессию.

Lody по-прежнему умеет [копировать диалог в Markdown](/ru/docs/copy-md), если вам нужна только запись. Копирование URL сессии без предоставления доступа к самой сессии также не даёт прав другим пользователям — ссылка продолжит работать только для владельца.

## Сравнение привычных подходов

| Подход | Что получает коллега | Та же живая сессия? |
| --- | --- | --- |
| Скриншот | Картинка с фрагментом чата | Нет |
| Экспорт истории / Markdown | Статичный текст для вставки в другое место | Нет — приходится начинать новый чат |
| Ссылка в стиле ChatGPT | Снимок диалога только для чтения | Нет |
| [Lore](https://lore.link/share) | Отрендеренный тред, который можно просмотреть или форкнуть в **новую** сессию агента | Нет — исходная сессия остаётся там, где была запущена |
| **Lody** | Существующая [сессия](/ru/docs/session) в рабочем пространстве | **Да** — открывайте и продолжайте |

Lore честно решает свою задачу: это инструмент просмотра и иногда способ запустить *новый* прогон из выжимки контекста. Lody решает другую задачу — приглашает коллегу прямо в существующую сессию.

Полное сравнение, включая SpecStory и модель прав доступа, приведено в руководстве [Совместный доступ к сессии агента разработки](/ru/docs/session-handoff/).

## Как передать сессию Claude Code в Lody

Передача работы выполняется внутри командного рабочего пространства (workspace). Сессия должна находиться в рабочем пространстве Lody, а ваш коллега должен быть его участником. Шаги ниже соответствуют руководству по продукту — обратитесь к нему, если вам нужны подробности обо всех граничных случаях с правами доступа.

### 1. Пригласите коллегу в рабочее пространство

1. Откройте **Settings** -> **Workspace** -> **General**.
2. В разделе **Members** нажмите **Invite Member**.
3. Введите его email и выберите роль.
4. Коллега может принять приглашение из письма, либо вы можете скопировать ссылку-приглашение и отправить её самостоятельно.

Подробнее: [Приглашение участников](/ru/docs/team#приглашение-участников).

### 2. Сделайте сессию видимой для команды

Новые машины по умолчанию остаются **приватными**. Сессия становится видна команде только тогда, когда открыт доступ к ресурсам, на которых она запущена.

Из самой сессии:

1. Откройте меню `...` в сессии или нажмите на индикатор **Private** в заголовке сессии в десктопном приложении.
2. Выберите **Share with team…** (если не хватает прав на конкретный ресурс, пункт может называться **Share device with team…** или **Share project with team…**).
3. Подтвердите действие. Lody откроет доступ к нужной машине и, для локального проекта, к самому проекту, после чего скопирует ссылку.

Делиться доступом может только **владелец устройства**. Если устройство ещё не зарегистрировано для командного доступа, сначала зарегистрируйте его. Вы также можете открыть доступ к машине через **Settings** -> **Machines** -> **Share machine**, не заходя в конкретную сессию. Подробнее см. в разделе [Видимость машин для команды](/ru/docs/team#видимость-машин-в-команде).

Предоставление доступа к сессии может открыть доступ ко всей машине и/или локальному проекту для всех участников рабочего пространства. Другие диалоги на этом устройстве также могут стать видимыми. Перед подтверждением в диалоговом окне отображается точная область доступа.

### 3. Направьте коллегу в нужную сессию

Когда сессия станет видна команде:

- отправьте скопированную ссылку на сессию или
- попросите коллегу открыть список сессий на главной странице. Если он видит только свои диалоги, переключите фильтр на боковой панели с **My Tasks** на **All Tasks** (в мобильном приложении — **Team Tasks**). Аватары показывают, кто именно запустил каждую сессию. По умолчанию в списке выбран фильтр **All Tasks**.

Коллеге нужно открыть именно **эту** сессию — а не делать форк и не создавать новый тред в окне ввода.

### 4. Коллега продолжает работу

Оказавшись в сессии, он сможет прочитать всю историю диалога, посмотреть текущие diff, продолжить работу в том же worktree и той же ветке и отправить следующий промпт той же конфигурации агента Claude Code (или другого агента).

Форк (fork) — это другой инструмент: он копирует историю в **новую** сессию на той же машине и в той же директории. Используйте форк, когда вам нужна личная ветка диалога. Используйте общий доступ (share), когда хотите подключить коллегу к исходной сессии. Подробнее: [Форк сессии](/ru/docs/session#создание-форка-сессии).

О том, как координировать несколько диалогов из одного агента, читайте в разделе [Управление сессиями агента](/ru/docs/session-orchestration).

## Если коллега не видит сессию

Проверьте три вещи: коллега принял приглашение в рабочее пространство, к машине (и локальному проекту, если он используется) открыт общий доступ, а в фильтре выбрано **All Tasks**, а не **My Tasks**. Диалоги с машин без общего доступа никогда не синхронизируются в боковые панели других участников.

Присоединение к рабочему пространству **не** открывает доступ к вашему ноутбуку. Машины остаются приватными, пока вы сами не поделитесь ими. Конфигурациями агентов можно делиться отдельно, чтобы коллеги запускали ту же настройку CLI — см. [Конфигурация агента](/ru/docs/quickstart) и [Командные функции](/ru/docs/team).

## Когда нужна только запись

Если коллеге нужно просто прочитать, что происходило, скопируйте сообщение или выберите **Copy as Markdown** в меню сессии. Это просто история переписки, а не передача работы. Подробнее: [Копирование диалогов](/ru/docs/copy-md).
