# Adopt the published Roost 0.3.0 pair

Status: proposed
Type: process
Translation: current

[中文](2026-10-24-roost-0.3.0-adoption.zh.md)

## Abstract

The Roost consumer stack requires APIs absent from the previously pinned 0.2.0
packages. The coordinated SDK, Native wrapper and six platform packages are now
published as 0.3.0. Pin that exact pair at the first new-API consumer (#1791) and
inherit one dependency commit through its descendants. Registry-based validation
replaces local candidate links; prior benchmark results remain historical.

## Scope and acceptance

Update the shared SDK catalog, CLI Native pin/publication guard, eight exact
release-age exceptions and lockfile together. Preserve every unrelated dependency and existing PR's
runtime changes. Keep the seven-day quarantine for other releases. The published
Native release accepts fresh/v10 only; this adoption adds no migration, legacy
reader, automatic deletion, deployment or publication action.

Before pushing, verify a frozen registry install, actual Native package/capability
provenance, owning integration tests and the existing root checks/format/docs gates.
Preserve draft state and review bases while restacking. Update obsolete release
blockers in PR descriptions using the observed validation results.

The two already-reviewed packed-history test adaptations from #1800 move into
this dependency commit so #1791 can validate the published packed layout. They
check decoded, nonempty history and exact receipts rather than compressed SQL
row counts; production code is unchanged. #1800 retains its explanatory notes.
At this first consumer, the frozen install, CLI typecheck and all 88 backend
contract tests pass. The registry darwin-arm64 addon SHA-256 matches the final
Roost 0.3.0 CI artifact.

Complete-stack frozen installation and root `pnpm check` pass, including CLI
4,559 passed / 4 existing skips, components 5,962, shared 1,610, Electron tests
and all boundary gates. Root formatting passes without unrelated edits; docs
report zero errors, 71 existing warnings and no protected topics. CLI compilation
passes at a 2 GiB V8 heap; its initial full build stops at the stale hardcoded
Native 0.2.0 publication guard. After updating that one literal, the failed bundle
gate/runtime smokes and remaining WASM-copy stage pass on the same compiled
output. Desktop CLI staging contains Native 0.3.0, and the complete Electron
main/preload/renderer build passes. No benchmark is rerun or relabeled.
