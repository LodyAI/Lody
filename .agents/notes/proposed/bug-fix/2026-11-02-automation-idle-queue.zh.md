# 自动化续接的队列激活

Status: proposed
Translation: current

[English](2026-11-02-automation-idle-queue.md)

## 摘要

自动化条件满足后，续接可能一直留在空闲会话的队列中：宿主写入队列项时没有发布激活空闲派发监听器所需的元数据信号。现在 Session action 在写入队列后发布控制文档 frontier 和水位。交接中断后，对账会为已有队列项重新发布信号，沿用原输入身份，不重复入队。用户遇到的现象与该缺口一致，但未能读取其具体的队列回执。

## 所有权和恢复

Session 派发监听器会释放空闲会话的订阅，并依据元数据重新激活；它无法观察未订阅房间中的单独队列写入。自动化 Session 适配器负责提交，因此与渲染端一样发布带因果依据的队列信号。frontier 在队列项写入后捕获，即使元数据先于控制文档到达，监听器也能保留信号。[队列信号顺序决定](../../implemented/bug-fix/2026-10-27-queue-signal-before-content.zh.md)仍保留其独立的设计理由。

稳定的回执和轮次身份保持不变。如果队列接纳后写入或刷新信号失败，现有账本对账会找到同一队列项并再次发送信号。重复提交也先按 operation 检查已有队列项。队列项仍在等待时，后续对账可能再次发送信号；这会增加元数据写入，但无需把未经确认的发布视为成功。现有 Session 的停止、接纳、权限和取消所有者继续生效。

适配器仍是连接尚未迁移的 Repo 和 Session 所有者的已登记 Promise 边界；迁移这些所有者不属于本次修复。没有增加新的生命周期、重试循环或跨会话扫描。

## 验证与限制

合成 Session authority 测试覆盖条件匹配、空闲激活，以及信号持久化失败后不重复入队的恢复。真实派发监听器测试先让空闲会话退出监听，再通过自动化适配器提交，观察到队列清空且只派发一次；测试注入权限和接纳边界。由于工作区同步失败，未能读取原用户事故的回执，因此这些测试不能证明该事故的具体原因。安装的桌面程序尚未使用本次修改重新构建或验收。
