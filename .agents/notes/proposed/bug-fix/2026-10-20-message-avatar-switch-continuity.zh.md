# 会话切换时的消息头像连续显示

Status: proposed
Translation: current
PR: https://github.com/LodyAI/Lody/pull/1736

[English](2026-10-20-message-avatar-switch-continuity.md)

## 摘要

切回会话时，即使图片字节已经缓存，消息头像也可能短暂显示占位图。一个小范围本地
修复现在会预加载稳定头像实际使用的缓存 blob，并消除通过 effect 延迟更新来源的
额外阶段。同一 Chromium 隔离实验中，首次切回 blob 从占位图变为立即显示已加载
图片，前后均只有一次头像 HTTP 请求。解码异步进行且仅针对实际使用的头像，缓存
读取和首次显示不等待，启动也不会解码所有已存头像。发送者资料暂缺仍是另一条尚未
解决的条件；本笔记为该调查保留提案状态，没有将线上现象归因到唯一原因。

## 职责与本次范围

`lib/avatar-cache.ts` 拥有按 URL 索引、跨会话共享的渲染进程内存缓存，以及
`lody-avatar-image-v2` CacheStorage 持久缓存。超过 24 小时后的读取先返回旧图，
再后台校验；字节不变则保留现有 URL。导航不会清理该缓存。缓存键、TTL 和图片字节
更新策略均不变。

`hooks/use-stable-avatar-src.ts` 在冷挂载时保留首次使用的原始 URL，同时填充缓存。
现在它在填充完成或实际使用恢复条目时，请求预加载这个本地 blob。条目保留一个采用
异步解码的离屏 `Image`，供后续挂载复用。已预热条目的替换也会预热新条目。仅启动
恢复不会解码所有已存图片。首次显示和缓存读取均不等待解码；预加载不抓取远程 URL。
没有增加定时器、订阅、用户资料缓存或会话 DOM 保留。

Hook 还将输入身份与解析结果一起保存。新来源、移除来源和刚取得的来源在渲染时直接
派生当前值。因此来源变化不会提交上一个用户的图片，也不需要等待 effect 才选择已经
可用的图片。后台状态更新继续遵循原有来源清理边界。

`UserAvatar` 仍然将图片就绪和坏图占位交给 `@lody/ui` 与 Base UI 1.7.0。
它的同步 `complete` / `naturalWidth` 路径可以复用已预热图片。完全冷的图片、尚未
完成的预加载或浏览器内存压力淘汰，仍可能需要正常加载占位。

[发送者身份决策](../../implemented/feature/2026-09-08-chat-sender-identity.md)和
[UI 头像迁移](../../implemented/feature/2026-09-13-ui-avatar-kbd.md)仍然适用。
本修复不改变身份或头像外观。

## 合成浏览器证据

实验基于 `4cc74cae8` 及工作区已有的无关改动，使用 Node 24.14.0 和无界面的
Chromium 145.0.7632.6。临时 Vite 页面导入生产 `UserAvatar`、稳定来源 Hook、
缓存和 UI 原语。唯一头像是本地生成的合成 SVG，不涉及产品数据或外部图片服务器。

| 状态                                                                      | 修复前：立即／下一帧 | 修复后：立即／下一帧 |
| ------------------------------------------------------------------------- | -------------------- | -------------------- |
| 原始 URL 已加载、blob 字节已缓存；切到没有头像的界面后返回，首次使用 blob | 占位／占位           | 已加载／已加载       |
| 同一个 blob 已解码，资料就绪，再次返回                                    | 已加载／已加载       | 已加载／已加载       |
| blob 仍然热缓存且已解码，但返回时缺少资料                                 | 占位／占位           | 占位／占位           |
| 为该已挂载头像补上资料                                                    | 占位／已加载         | 已加载／已加载       |

前后两次实验各只有一次头像 HTTP 请求到达本地服务器。第一次返回前，原始 URL
已经加载；每次实验内的两次返回复用同一个缓存 blob URL。样本观察绘制前的 DOM
可用状态，不是像素呈现测量，也不保证延迟帧数。已解码的热返回在修复前就能立即
显示，不能说每次 Base UI 重新挂载都会闪。

## 生命周期与 Effect 评估

稳定来源 Hook 触发预加载，共享缓存条目拥有图片及解码。组件卸载会阻止其本地更新，
但不终止其他头像可能使用的共享图片。沿用已有的条目替换、对象 URL 延迟撤销和内存
清理职责释放资源。解码拒绝被处理，保留已有占位。每个实际使用的缓存头像保留一个
图片对象；解码像素是否继续保留仍由浏览器控制。UI 交接前不增加新的等待。

Effect 功能／修复评估：本次是在已有 Promise 缓存中修正浏览器适配和 React 来源
派生。完整原生单元还需改变抓取、后台校验、持久化和应用所有权，超出这个小范围行为
修复，因此延后迁移，不增加运行时或依赖，也不改变迁移台账。

## 尚待调查的用户资料路径

`ai-gui/index.tsx` 先通过 `auth:getUserById` 解析发送者。缺少 `user.image` 时，
图片缓存没有查询键。认证适配器共享活跃查询，但查询源注册表和 Hook 内保留快照
不是跨所有卸载的持久资料缓存。`SessionChatInterface` 也会为待发送消息订阅当前
用户资料，因此已有的同用户订阅可能保住结果；不能假定每次切换都缺资料，必须观察。

如果匹配部署版本的录制确认资料缺失，再评估用已有账户／工作区范围内身份提供初始
来源，并保留权威更新、删除以及账户／工作区失效逻辑。不将本次补丁扩展成通用过期
查询缓存，不放宽过期访问数据的保护。本地修复没有改变查询；确实缺资料时保留占位。
