# PR 观测发布与 webhook 关联独立

Status: proposed
Translation: current
PR: https://github.com/LodyAI/Lody/pull/1192

[English](2026-10-01-pr-observation-association.md)

## 摘要

托管工作区可以通过机器 GitHub 凭据发现同分支 PR，却因 webhook 关联被拒绝而
继续显示 Create PR。本修正提议独立发布已验证的观测，并保留托管关联重试。
仓库、分支和机器归属校验继续生效，摘要不授予托管详情或修改权限。
发布契约的变化仍待人工审查；生产验收及服务端拒绝的精确原因尚未验证。

## 证据与决策

当前 main 仍以关联成功作为发现结果发布的前提。报告对应的
[PR #1177](https://github.com/LodyAI/Lody/pull/1177) 处理其他缺陷。
只读诊断发现反复关联拒绝、所属会话 PR 列表为空，且调度目标的仓库和 head
分支与 PR 一致。检查时没有仓库级 cooldown。这能定位阻塞的客户端发布门控，
但不能证明服务端拒绝原因或最初创建 PR 使用的凭据。GitHub App 仓库列表
不能单独证明实际个人凭据是否具备读取权限。

把托管 webhook 关联保留为独立的幂等效果。成功确认仅保存在工作区运行时；
已发布元数据不等于 webhook 已关联。拒绝及传输失败仍发布经验证的胜出 PR，
同时保留发现目标的重试资格。失败时清除旧上下文指纹，让新发布的终态 PR
在重启后仍能重试。既有配额、尝试间隔和凭据冷却继续生效。关联后重新读取
所属元数据；机器、仓库、分支或存在性变化时拒绝发布旧结果。

本决策部分替代[本地 PR 观测记录](../../implemented/feature/2026-09-24-local-github-pr-observation.zh.md)
中的托管关联优先约定。保留旧门控会持续复现本问题。直接写生产元数据或创建
重复业务 PR 只能掩盖根因。服务端授权改动无法在公共仓库内实现或验证，也不属
本补丁范围。代价是摘要可能可见而 webhook 关联仍不可用；详情和修改操作
继续执行各自的授权校验。
