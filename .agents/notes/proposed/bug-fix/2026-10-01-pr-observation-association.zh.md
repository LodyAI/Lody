# PR 观测发布与 webhook 关联独立

Status: proposed
Translation: current
PR: https://github.com/LodyAI/Lody/pull/1192

[English](2026-10-01-pr-observation-association.md)

## 摘要

托管工作区可以通过机器 GitHub 凭据发现同分支 PR，却因 webhook 关联被拒绝而
继续显示 Create PR。本修正提议独立发布已验证的观测，并保留托管关联重试。
仓库、分支和机器归属校验继续生效，摘要不授予托管详情或修改权限。
发布契约的变化仍待人工审查；生产验收及服务端拒绝的精确原因尚未验证。

## 证据与决策

当前 main 仍以关联成功作为发现结果发布的前提。报告对应的
[PR #1177](https://github.com/LodyAI/Lody/pull/1177) 处理其他缺陷。
只读诊断发现反复关联拒绝、所属会话 PR 列表为空，且调度目标的仓库和 head
分支与 PR 一致。检查时没有仓库级 cooldown。这能定位阻塞的客户端发布门控，
但不能证明服务端拒绝原因或最初创建 PR 使用的凭据。GitHub App 仓库列表
不能单独证明实际个人凭据是否具备读取权限。

最终再次核对 main `993cb8c8c`：在已测试的 `93545f01b` 基线之后合并了 #1177
（All Changes 基准／图片模态焦点）和 #1187（搜索文档），两者都没有改动 PR
发现发布或 info-bar 动作门控；开放 PR 中未发现其他 B08 实现。本分支保留已测试基线。

把托管 webhook 关联保留为独立的幂等效果。成功确认仅保存在工作区运行时；
已发布元数据不等于 webhook 已关联。拒绝及传输失败仍发布经验证的胜出 PR，
同时保留发现目标的重试资格。失败时清除旧上下文指纹，让新发布的终态 PR
在重启后仍能重试。既有配额、尝试间隔和凭据冷却继续生效。关联后重新读取
所属元数据；机器、仓库、分支或存在性变化时拒绝发布旧结果。

本决策部分替代[本地 PR 观测记录](../../implemented/feature/2026-09-24-local-github-pr-observation.zh.md)
中的托管关联优先约定。保留旧门控会持续复现本问题。直接写生产元数据或创建
重复业务 PR 只能掩盖根因。服务端授权改动无法在公共仓库内实现或验证，也不属
本补丁范围。代价是摘要可能可见而 webhook 关联仍不可用；详情和修改操作
继续执行各自的授权校验。

发布观测让关联被拒的场景进入右侧 PR 标签页，因此标签页的失败呈现属于
同一修正。详情加载失败或身份未确认时改为降级而非死胡同：标签页保留已记录的
仓库与 PR 号，失败仍以该 surface 既有的 danger 通知条呈现——红色标题说明
加载失败，正文声明已找到此分支的 PR 并可前往 GitHub 查看，只提供仍然可用
的两条路径——在 GitHub 打开，或带进行中反馈地重试加载。原始错误以小字
内联保留——仓库身份未确认时，该文案本身就是已核实的原因，说明了谁能修复
（重新连接，或在仓库被移除、更名时交由工作区管理员核实）；错误为 GitHub
404 时再加一句留有保留的提示——可能只是 Lody GitHub App 没有该仓库的访问
权限，并给出安装页链接作为用户实际可执行的修复入口。曾评估居中的
`StatusPage` 框架后放弃：其插画词汇没有匹配「已找到但不可达」的图
（`missing` 的镜片语义是「找不到」，与已找到的标题相悖），而行内通知条
保持了标签页原有框架与上下文。详情未加载时不渲染任何修改入口：评论框仅在
已有 PR 详情时出现，草稿保存在视图层、加载失败不会清空，`postComment` 在
无法投递时改为拒绝而非静默返回。通知条只断言一次已记录的观测，不断言
webhook 关联或写权限。

## 验证

合成调度测试以托管及 ambient 凭据复现关联失败，检查 PR/CI 元数据发布，
并覆盖重试、恢复、终态重启及上下文变化。五个回归用例在未修改的 main 实现上
失败。组件测试从精简 owner 元数据走到 PR 选择和 root/child 动作门控。
没有提交捕获的对话或生产夹具。

隔离浏览器验收使用真实 Session info bar、PR 选择和动作门控，关闭托管修改能力。
把同一 ambient 凭据／关联拒绝夹具在 `93545f01b` 与补丁上生成的元数据，分别交给
全新的 Playwright context，以 1000 × 640、英语、浅色主题渲染。修改前无 PR，显示
Create PR，展开菜单含 Create Draft PR；修改后显示 draft #55、精简 CI 失败状态和
Commit & Push，不再显示创建入口或托管修改入口。两张图仅含合成的 `owner/repo`、
`feat/x` 和 +12/−3 数据；外部 HTTP 与 WebSocket 目的地均被阻断。
before/after Playwright 用例通过，截图上传到发起请求的 Lody 对话，不提交图片。

`pnpm --dir packages/components exec playwright test tests/e2e/session-info-bar-observation.spec.ts --workers=1`；

进行中重试、可见的逐字错误、无评论框）以及草稿在加载失败后的保留；

在 jsdom 下运行；两个错误 story 另在全新 Playwright context 中以 480 × 720
