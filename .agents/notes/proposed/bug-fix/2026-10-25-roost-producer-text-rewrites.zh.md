# Roost 生产端重排时保留已有正文

## 摘要

Lody 的 Roost 生产端会在标签解析拆分条目、或恢复状态中累计追加补丁改变数组位置时，重新写入未改变的正文。本修复保留已有节点，用现有 ContentOps 表达重排，并在持久化前核对完整目标。使用正式发布的 Roost 0.3.0 进行隔离混合负载对照后，数据库总页数从 3,048 降到 2,080 KiB；累计追加 CPU 和耗时略降，追加 p95 增加 0.024 ms。读取逻辑和数据格式保持不变，新旧代码双向交叉重开均通过，无需迁移。

## 问题与修复

按数组位置进行 diff 会把解析后的 text/thought 拆分转换为重新插入正文。另一处是未变化的累计追加补丁在状态数组中移动位置，被转换为再次完整 Set 文本。这些字节没有增加对话信息。

正文规划器核对生产端追加提示、唯一保留区间和 Unicode 标量位置，先裁剪已有文本，再插入周围条目。状态规划器保留未变化的大补丁，在其周围还原目标补丁的精确顺序。不支持或收益不足的方案在任何写入前使用原有 diff。

正文每个中间步骤均保持修改前后体积预算，完整暂存结果必须等于已验证的目标。单次规划中的受限 JSON 检查和缓存只在字节长度、归一化等价时跳过重复规范编码；浮点数和不支持的表示继续使用原编码器。受保护的成本下界避免仅为估价而构造重复正文 diff。Native 继续负责内容和收据的原子提交、实际操作序号及封存校验。

本修复只改变纯生产端规划及调用点。正式 SDK 和 Native 0.3.0 已支持所用操作。版本、格式、依赖、读取逻辑均不变，不引入迁移、历史重写或投影调度变更。已封存和未封存的旧数据继续由相同读取器处理。此前的 Native 格式实验不在本变更内，也不是本次结果的依赖。

## 正式 0.3.0 对照

基线为 main `2356b8ba327086289561331da4fedf2fdd46c497`。候选只改变三个运行时文件：`roost-content-patches.ts`、`roost-message-state.ts` 和 `roost-node-session.ts` 调用点。两边加载相同的正式 SDK/Native 0.3.0，darwin-arm64 addon SHA-256 为 `1804d08998328c1ab48121160de767dec84d5f0da4fec42f6581e90ac21acea1`；共享 reducer、锁文件和测试入口一致。环境为 Node 24.22.1、pnpm 10.20.0、darwin/arm64、1,536 MiB 堆限制，WAL/FULL 持久化保证不变。

复用现有[持久化混合／恢复测试流程](../../../docs/roost-validation.md#choose-a-fixed-manual-benchmark)：`ROUNDS=10`、`CHUNKS=100`、`CHUNK_BYTES=1024`、`TOOL_BYTES=16384`、`MIXED=1`。每个全新数据库写入相同模拟内容：20 条消息、1,000 次流式批次、分片 thinking 标签、Unicode、工具／计划，以及回复中途结束并重开。按 A1–B1–B2–A2 顺序，每轮分别用独立进程写入、重开和分页。表格为每个版本两轮完整测试的中位数。

数据库总量包含 Native 与 Lody 控制库页，不含 WAL/SHM。这是全新写入的体积减幅，不表示历史数据库会自动缩小。追加 CPU／耗时覆盖 1,000 次变更批次及其控制库持久化，创建和结束有独立成本。RSS 包含进程、Worker、JS、WASM 和 Native，排除最后的全量物化校验。此短历史的最旧页仍在最新窗口内，不是长历史恢复测试。两轮数据不能证明所有场景提速；p50、p95 和全量读取中位数略升。未测 HTTP/Streams offset，也未重跑 Loro 对照。

## 验证与结论

根目录 `corepack pnpm check` 通过，其中 CLI 4,573 项测试通过、四项原有跳过；`corepack pnpm format` 和 `corepack pnpm run docs check` 通过。行为覆盖包括 Native SQLite、收据重试、Unicode 与非法标量、数值回退、精确补丁顺序、封存／导出、重开与对端导入。

12 个写入／重开／分页阶段及两个只验证正确性的跨源码重开阶段均通过，共 28 次 SQLite quick／外键检查，内容摘要一致。新代码读取旧写入端的已关闭数据，旧代码也读取新写入端的已关闭数据。测量期间源码、包和依赖链接哈希保持不变。未使用真实数据库、付费模型请求或部署。本决定保持 proposed，待审查，不据此宣称所有性能场景均验收通过。
