# E2EE 执行日志的 MVP 恢复

Status: proposed
Translation: current

[English](2026-10-27-e2ee-realtime-journal-recovery.md)

## 摘要

本机时钟错误前跳会持久写入机器级下限，使其他工作区重启后仍被拒绝；首次创建中断也可能留下
无法使用的空文件。2026-10-27 owner 撤回了此前接受的可用性限制，改为工作区时钟隔离、
对照已认证时间拒绝明显前跳，以及显式本机归档重置。当前格式的旧请求 ID 在重置后仍禁止
再次执行；结果未知不会授权接管或重放。此次只调整尚未接入产品的宿主存储，不代表 M5 派发或桌面验收。

## 决定与范围

本决定部分替代 [journal 提案](../architecture/2026-10-26-e2ee-realtime-journal.zh.md)。
撤回永久文件级 clock floor，但保留原来的理由：仅凭墙钟无法区分时间纠正和真实经过时间。
仍保留原截止时间与至多一次领取。生产尚无加密工作区；日志只支持 schema 3，不解码 schema 2，
不迁移、不导入归档、不增加另一套 wire 格式。窄范围归档例外记录在
[基础规范草案](../../../../specs/e2ee-foundations.zh.md#格式兼容性)。本改动仍以提议状态提交审核，
不批准尚未决定的实时 wire 或产品接入方案。

`trustedNow` 是可选注入函数，返回当前、独立认证的参考时间，单位为 epoch 毫秒；也可返回
`undefined`。调用方须把新鲜的已认证服务时间样本推算到当前时刻；不能把请求字节或其中的时间
当作参考。写 floor 前，若本机领先超过 600,000 ms，就返回 `clock_skew` 并提示校准时钟。
恰好十分钟可接受。通过检查时用参考时间推进，而不是领先的本机值。若已存 floor 比参考快超过
十分钟，也拒绝推进；显式重置可清除异常 floor。不引入网络、服务时间缓存、定时器或新的授权来源。

下限以 `(genesis, workspaceId)` 为键。无参考时间时，保留该工作区内的本机最大值。错误前跳
仍可能阻断该工作区的新请求，直到显式重置，但不会污染其他工作区。不静默续期，也不猜测应
回退多少时间。时钟异常不阻止读取已完成结果或响应原帧。

## 重置、归档与所有权

```text
lody e2ee journal reset --file <账号私有日志路径> [--json]
  在稳定 control SQLite 提交当前旧请求 ID 隔离和重置意图
  通过 SQLite 恢复/checkpoint 旧日志，关闭句柄
  将旧日志改名为唯一归档路径
  用新的日志身份初始化 schema 3
  清除重置意图，返回归档路径
```

重置前停止执行 owner。M5 尚未定义产品日志位置，所以要求显式路径。命令不显示在普通 CLI
帮助中，延迟加载存储，沿用一次性命令的退出/flush 路径，并跳过云端时间同步和 analytics
初始化。不访问密钥库，也不联系 daemon。桌面入口后续接入。

普通操作对稳定的相邻 `.control.sqlite` 持有共享事务；重置步骤使用排他事务。其他 owner
保留关闭失败句柄时，独立普通操作仍可继续，只有重置等待关闭确认。保留此文件：它保存已退休
当前格式请求键的 SHA-256 身份，以及待完成的归档/替换身份。这些是禁止再次执行的记录，
不是复制的可执行请求行。再次重置仍保留旧隔离；重发退休 ID 返回 `archived_request`；
曾使用过的 owner 或 permit 不能操作新日志身份，返回 `journal_reset`。归档不会被扫描为
待执行工作，不作为旧格式解码，也不自动导入。未知格式无法提供解码后的退休键；它只作为
证据保存，其行不会由此模块提交执行。

SQLite 事务不能和 OS rename 原子提交，因此先持久化重置意图。意图存在时，其他调用返回
`reset_required`。归档或替换初始化失败后，再次显式重置会继续同一意图和归档路径。改名后、
schema 提交前中断时，重试用保留的身份初始化空替换文件。仅有归档或文件缺失不会触发自动新建。

检查前允许 SQLite 正常恢复。只有版本为零且没有 schema 对象的库才视为首次创建中断。
未知版本或缺少必要结构会归档，并用类型化错误报告路径；继续使用须显式重置。原始损坏仍是
存储错误。改名前，SQLite 切换到 DELETE 模式、合并 WAL 并取得数据库排他事务；活跃原生
读写连接阻止这一步。应用不复制或删除 sidecar。已提交逻辑证据与 schema 保留，但原生恢复、
checkpoint 和日志模式可能改变物理文件。

适配器仍保持同步。此处增加 Effect 包装只会新设执行边界，不能替换尚未接入的产品 owner，
因此不声称完成迁移。事务不包含异步等待或取消点。普通关闭失败时，最多保留一个 main
句柄及其 control 锁句柄、一份待取诊断。独立 owner 仍可通过共享锁使用 SQLite，只有重置
需要排他权限。重试先关闭 main，再释放锁；清理未确认前其他
owner 不能改名。关闭失败不替换已提交结果的成功。保留时限由 owner/进程结束限定；没有后台重试。

## 故障隔离与未知结果

| 触发 | 范围与恢复 |
| --- | --- |
| 时钟异常 | 只拒绝新领取，不写 floor、不访问钥匙、不拆工作区。校准或显式重置；完成证据仍可读。 |
| 无参考且下限异常 | 只拒绝相同 genesis/工作区；显式重置提供有限的人工恢复路径。 |
| 首次创建空文件 | 原生恢复确认无提交结构后原子初始化；独立重开串行化。 |
| 未知 schema | 保留归档、报告路径、要求显式重置，不改写或解码原件。 |
| 重置中断 | 稳定意图阻止新领取；人工重试完成同一替换。 |
| 关闭失败 | 原 owner 保留 main 和共享 mutex；其他 owner 的普通操作继续，改名等待。诊断有界，显式重试清理。 |
| 开始后崩溃 | 暴露 `state: uncertain`、`outcomeStatus: unknown`；只有原活 permit 可完成。同工作区的新请求 ID 独立。 |

## 证据与限制

测试使用真实磁盘 SQLite、注入时钟和明确的 worker/子进程信号。五项核心回归先在未修改 main
上执行并全部失败，修复后通过。保留 hot journal 回滚、WAL checkpoint、COMMIT BUSY、
精确响应/结果原件、不可变身份及并发领取覆盖。新增十分钟边界/参考时间拒绝、跨工作区时钟、
空库初始化、归档证据、多次重置、退休 ID、旧 permit、中断替换、清理与改名互斥，以及 CLI
重置回执。测试不使用 sleep 或网络。

本地仅运行受影响测试与静态检查；实际命令/结果放在 PR。未验证：已认证时间的产品接线、
发送端新鲜度和查询授权、派发及 Meta/history 约束、UI、daemon 静止确认、完整 CLI 打包、
Windows/Linux 执行、断电/fsync 验收、恶意本地替换，以及存储和退休 ID 回收。control 文件和
未回收证据会增长；空间耗尽拒绝依赖工作，不删除证据。
