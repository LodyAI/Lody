## 摘要

机器归属只能证明谁控制机器，不能授权其他成员执行。拟议 MVP 通过机器所有者有效个人设备签名的完整加密策略，保留私有默认值与机器／项目开关。账本验证的绑定代次区分移除重入与原子密钥替换：移除后使用新资源，从第 1 版开始，清理旧历史既不阻碍恢复，也不复活旧授权。服务端 CAS 在同代内定序，A1 提供原语、代次证据、授权和 DTO，存储／宿主／UI 另行接入。短本地缓存无法给持续隐瞒最新 head 的服务端下的未知撤回提供时限；owner 于 2026-10-28 已确认接受信任服务端不持续隐藏新 head 的前提。

## 决定与替代方案

共享策略独立于成员账本，避免项目开关变成永久成员记录。完整策略让开启项目和机器原子生效，关闭机器时保留项目记录。CRDT 布尔值／快照签名不能证明每项设置来自机器所有者；账号共享会让服务端决定权限，默认团队可用会取消私有默认值，均不符合选定边界。

[机器身份决定](2026-10-27-e2ee-machine-ledger-binding.zh.md) 继续负责账本绑定及原子替换。本提案不新增账本记录、capability 或快照／retained-state 格式，不另立重复 note；加密工作区继续禁用普通共享界面，改用下述原生策略设置；实时／journal 职责不变。

## 代次与移除

`generation` 为当前连续原子替换链首次机器 AdmitDevice（`replaces=null`）签名公钥的小写 hex32。已验证账本永久禁止密钥复用；后续原子替换指定精确的旧有效密钥，因此保留根。撤销／移除后重新准入使用新的初始密钥，即使成员和 machineId 相同也有新代次；代次不是服务端计数、时间戳或客户端自选字符串。

`verifyMachineSharingGeneration` 接收从首次准入到当前设备的完整准入／替换链，每项为 `{record,length}`，length 是该原文在账本的一起始位置。它在真实账本中验证原文摘要的精确位置、严格递增顺序、机器／成员身份及 replaces 连续关系，返回绑定当前设备与视图的模块私有证据。所有策略操作和执行判断都需要该证据并复查当前绑定，链最多 4096 项。压缩快照／retained 视图不能猜测缺失的账本检查点，须用保留相关检查点的真实视图（通常完整重放）在当前终点核验，再供同位置压缩视图或后续视图使用。证明不可用只影响该机器共享／执行，不阻止文档读取与无关工作。

所有 DTO scope、签名正文、资源、本地日志、缓存及策略 pin 都包含代次。移除将旧代次标成永久 removed，并保留清理 cutoff／高水位，不能再提交使其 active。新代次不继承旧 pin 或授权，从 1/null 父项和私有默认值开始，恢复共享需要新的明确所有者意图。原子替换仍在同代并保留策略。这替代了清理后续写 n+1 的旧方案：仅比较 status 只能挡部分旧写入，不能让新客户端验证已删前缀，也无法单独阻止旧策略证据跨重入生效。

## 格式与职责

规范有界 CBOR 为 current-only v3：

```text
[format=3, purpose=1, workspaceIdUtf8, genesis32, machineIdUtf8,
 ownerMembership16, revision, previousFrameDigest32OrNull, sharedWithTeam,
 sortedProjectIdUtf8s, signer32, issuedAt, requestId16, generation32, sortedSessionGrants[[sessionIdUtf8, read=1]]]
```

身份字符串使用严格 UTF-8，1..256 字节，不规范化、不去 BOM。项目按字节排序、去重，最多 4096 项；展开正文最多 256 KiB。公钥保留严格 Ed25519 检查。issuedAt 为非负安全 Unix 毫秒整数，只供描述；版本为正安全整数，仅首版父摘要为空。公开 DTO hex 为小写。

复用既有 content-v0 document-update 密码学，固定资源 `machine-access:<unpadded-base64url(machineIdUtf8)>:<ownerMembershipIdHex>:<generationHex>`、docEpoch 零和签名／AAD 绑定 `lody-e2ee/machine-sharing/v3\0`。完整原始密文帧用 SHA-256 摘要，不能哈希解码状态；帧上限仍为 262287 字节。未知结果保留原文重试，不重新加密或自动重放。没有 v1 策略读取、回退或静默转换。

后端使用凭据身份、账本验证的当前代次与 `admitMachineSharingFrame`；在同一原子 mutation 中复查当前 personal／成员／机器资格与代次，比较完整 scope／status／版本／摘要，去重请求意图并插入原文与 head。旧代 pending 请求即使版本／摘要数值相同也冲突；已提交精确重试返回原收据或清理后的 removed，同 requestId 改变意图要失败。最小请求意图收据和移除 cutoff 保留；清理绑定旧代次，不能删除新代提交。版本清理后可返回 null，readHead 保留旧 removed 高水位，不能把它当可信 pin。

owner 于 2026-11-09 确认 E2EE 尚无生产数据：只支持 v3，不保留旧格式读取、迁移或重建脚本。读取及写入前只验证最新原文、当前有效所有者个人设备签名、资源／绑定／代次，以及本地最高版本 pin。较低版本或同版本不同摘要均拒绝；冷客户端可接受任意正版本，允许跳过已清除的中间策略。`previousDigest` 只用于服务端 CAS 定序，不构成客户端历史链证明。机器代次的账本准入链仍须验证，与策略历史链无关。

独立的 `sessions: [{sessionId, level: 'read'}]` 不开启机器或项目，标识采用与项目相同的有界规范编码。旧客户端拒绝 v3，v3 拒绝旧策略；先部署兼容的服务端准入，再发布客户端，不改账本格式。

个人签发设备撤销后，该策略全部授权失效。视图返回私密默认值及 `needsResign`；当前有效的所有者个人设备可在当前 head CAS 下签署明确新意图，从空项目／会话授权开始，不复制被撤销设备的正文。这替代历史正文恢复及重签保留项目的旧行为。本地保留但签发者已失效的策略只产生拒绝，不产生授权；删除历史策略 API。

## 接入与信任限制

A2 负责私有存储、设备准入、代次 CAS、收据与清理；A3 负责代次证据核验、原文／pin、实际项目解析、经认证账本／head 读取与共用 actual-start 门禁；A4 负责既有开关 UI 与已验证可见性。代理执行保留双方权限交集，缺少签名主体证据的入口继续关闭。撤回阻止新开始和后续需授权动作，不强杀已运行命令。

已观察到的撤回立即使授权失效。严格小于 15 分钟的内存缓存只约束本机经认证读取的年龄，网络 I/O 前计时并与账本／请求期限取交集；它无法约束持续隐瞒最新控制状态的服务端下的未知撤回。签名／链能发现已知回滚与分叉，不能证明全局最新 head；owner 于 2026-10-28 已确认接受信任服务端不持续隐藏新 head 的前提，这里不新增密码学新鲜度证明。重启或时钟不确定后须重新验证，失败仅影响依赖授权的动作，保留离线内容与无关工作。

缓存放行继续沿用这个窗口。缓存判断为 `machine-not-shared` 或 `project-not-shared` 时，拒绝前先做经认证的最新 head 读取，新验证的策略允许时立即放行。同一 binding（包含代次）合并并发重读，从读取开始计时，每五秒最多一次。短期限频约束请求量，也把新授权的本地延迟缩短到该窗口，不缩短撤回的新鲜度边界。

工作区 Scope 持有这项原生 Effect 读取，取消一个等待者不会取消其他等待者的读取。协调许可只用于选择读取任务，不跨网络或密码操作；其他 binding 和同成员执行仍可用。失败仅保留重试时间，不保留失败 fiber 或策略结果，沿用已接受 pin 的拒绝或既有不可用结果，绝不推进 pin 或发布授权。限频结束后由下次请求重试。失效操作同时清除协调状态，既有读取发布屏障继续拒绝迟到授权；Scope 关闭会在关闭存储前中断并收拢读取。宿主测试覆盖新授权重读、并发拒绝、限频到期和失败后拒绝的保留。

## 原生宿主所有权

`packages/e2ee-machine-sharing` 共用宿主承接原文、版本 pin、最新读取和缓存。原文、requestId 对账、回滚 pin 和内存缓存都包含账本核验的代次。宿主从本地历史选择准入／替换原文，由 core 认证每个准确位置；压缩视图可通过同一认证端点的完整本地重放核验。证据缺失只拒绝共享，同成员执行保持独立。桌面读取返回 generation，更新必须传回它，防止旧窗口意图静默开启重入机器。旧代移除为终态，新代需要明确新意图并从 revision 1 开始。策略存储只在依赖它的操作中打开；库损坏不阻断内容读取与同成员路径。SQLite 保存密文、完整 CAS 身份、请求终态和资源绑定的最高已接受版本，不保存凭据、密钥或新鲜度。本地窄开关意图用于精确重试比较。并发结果在发布缓存前原子比较持久最高版本；网络和密码操作期间不持有账号锁或数据库事务。

工作区 Scope 持有已接纳操作，包括调用方停止等待的写入，并在关闭存储前收拢它们。Stop 阻止后续发布并保留待定原文。最新读取失败只清除依赖该策略的授权；失败存储可重试打开。墙钟和单调钟都从读取之前计算严格小于十五分钟的有效期，计入全部 I/O。实际开始的 journal 写入前同步复查策略与账本代次，中间没有 await。撤回不终止已开始任务。

只读最新版本取消了原先最多 4096 个策略的遍历，也不依赖已清除的中间原文。有效签名和本地 pin 仍防止已知回滚／分叉，但无法发现服务端隐瞒的新 head。

桌面通过窄宿主/IPC 方法 `readMachineSharing`、`updateMachineSharing` 持有个人签名，真实 preload 允许列表与 CloudPlatformProvider 转发这些方法。CLI 机器托管读取策略并提供相同流程，但不能签发所有者变更；以该身份写入会返回所有权拒绝。代理调度保留双主体权限交集；显示账号 ID 不会变成签名委托证据。

原生合成密码与 SQLite 测试覆盖结果未知恢复、终态 CAS 冲突、当前签发者撤销和显式重签、项目开关、回滚/移除屏障与时钟限制。生产 CLI 装配及桌面/preload/provider 回归验证真实适配器。这些不等于后端部署、真实密钥库验证或双成员双机器产品验收。

## 成员可见性（A4）

加密工作区会跳过普通的机器与项目可见性查询，所以在这次改动之前，成员只能看到自己的机器，无法在 Owner 已共享的机器上发起 turn。`useEncryptedSharedMachines` 按账号和工作区各维护一个 store，供可见索引的所有使用方共用。对已同步、属于其他成员的每台机器，它读取宿主经验证的 `readMachineSharing` 视图；只有当 core 没有给出 `deniedReason`、且视图为已共享、最新、未被移除、可用时，才视为可用。因此 Guest 排除和撤回都由 core 判定，从不依据服务端机器表或显示用的账号 ID。签名策略中的 `projects` 成为该机器的可见项目；不选项目的对话只需要机器可见。

读取最多同时进行两个，不阻塞其他工作区，也不阻塞可见索引的其他来源。同一机器的新读取会取代旧读取。账本变化、`online`、窗口重新可见以及每 10 分钟的定时器都会刷新视图，满足 owner 批准的"未知撤回小于 15 分钟"的上限。拒绝、移除或读取失败时立即移除访问。这些都是宿主 IPC 读取，不是 Streams 订阅。

加密共享机器只开放选择和执行。它们不进入 Convex 背书的授权集合，因此启动时的能力探测永远不会在其他成员的机器上启动 agent。`withoutEncryptedSharedMachines` 还把它们排除在自动 agent 配置迁移、Bug 报告日志收集和 Memory provider 设置之外，这些功能会用到受限的机器 RPC 或写入机器的目录。

owner 于 2026-11-09 替代原 A4「全部历史可见」决策，以及 2026-09-14 session-header-share-control note 的访问条交互。两种工作区现在都默认私密。机器所有者始终可见并可管理其机器上的会话；已共享机器及本地项目保留编辑权；独立的权威会话授权只开放历史只读。会话作者（`SessionMeta.userId`）不授予管理权。授权只适用于其绑定机器，包含子会话跟随根会话；opened-by 来源不授予权限。

共同的 platform `sessionAccess` 端口由普通工作区 owner 控制的机器行，或 E2EE v3 签名会话授权支持。普通模式通过 Convex 订阅刷新；E2EE 订阅机器／代次／版本提示后重读已验证策略。深链接强制重读机器策略。会话授权不扩展执行索引。私密会话只是界面隐藏，成员仍持有内容密钥，不是密码学私密。

独立历史阅读器没有输入框、执行控件或管理写入，保留置顶／未读、Markdown 复制及在新会话中引用。`useSessionActions` 为管理操作重新读取 Repo 实际目标及当前授权；旧回调不能绕过撤销或 Meta 机器变化。置顶／未读采用独立且范围受限的偏好路径。机器托管历史仍需单独授权的读取路径，不能从会话授权推导机器执行权。[会话访问 Spec 草稿](../../../../specs/session-access.zh.md) 记录完整契约及后续阶段。确定性测试是实现证据，不代表两名成员的真实产品验收。

## 发送端撤回闸门

加密发送在写入任何元数据、回执或历史之前先准备 dispatch。已验证的拒绝 `e2ee_machine_not_shared` 会让发送以"未发送"失败，composer 保留草稿。策略无法验证、宿主没有策略读取能力、超时或传输失败都属未知：输入照常写入，由接收机器决定。这项检查在写入之前运行，而不是事后修复。

已验证的撤回必须保持已知。宿主从资源的已接受 pin 推导它：pin 绑定工作区、genesis、机器、所有者和 generation，只随更新的已验证 head 推进；失败、回滚或过期的刷新都不会改写它。`knownDenial` 在本地重新打开 pin 住的策略。拒绝使用本地保留的当前策略；当前已失效的签发设备也只产生拒绝，不恢复历史授权。`authorize` 返回该拒绝而不是未知失败，桌面端的 prepare 在任何网络读取之前先检查它。只有更新的已验证读取（可见索引刷新或设置视图）才能解除。renderer 也会在本运行时内记住每个已验证的撤回，直到之后某次 prepare 成功。对这类机器，超过 200 ms 期限的 prepare 会被拒绝；对其他机器仍按未知处理：轮次照旧写入，若迟到的结果是已验证撤回，则把该轮次改为 `canceled`。这一步使用提交时的 `onlyAwaitingStart` 守卫，已被机器认领的轮次保持其自身结果。该守卫只保护本副本的提交：并发的离线副本仍可能合并覆盖 `canceled`。这种取消是尽力而为，不是全局撤回证明；这种情况仍由机器侧 owner 批准的窗口兜底。排队行没有历史轮次可结算，同样依赖该窗口。

策略存放在服务器的共享存储中，不在机器同步的工作区数据里；执行检查复用严格小于 15 分钟的已认证授权，缓存拒绝采用上述五秒重读规则。机器尚未观察到的撤回属于 owner 批准的未知窗口。宿主测试固定了两半：新鲜授权在未观察到的撤回下仍然有效，而宿主自己的已验证读取会立即拒绝。发送端已知撤回的发送会在写入前被拒绝；无法验证的发送端仍依赖该窗口。

重新配对的机器开启一个没有策略的新代际。因此，已认证读取发现当前代际没有 head 或其已移除时，就是私有默认：属于已知拒绝（`machine-not-shared`），而不是未知结果。此前成员的 prepare 报告的是未知结果，桌面边界把它映射成了 `invalid-ledger`；现在桌面把真正无法验证的策略映射为 `sharing_unavailable`。由于缓存和 pin 都按代际划分，所有者之后在新代际里重新共享时，同一进程会读取并放行。

## 接收机器上的项目范围

成员在共享机器上只被授予项目 P1，却可能在未共享项目 P2 上执行：CLI 在记录本轮项目之前就申领了执行，门禁收不到项目，只检查了机器开关。现在申领会授权本轮能触及的每一个本地项目，在机器上于创建任何 worktree、进程或提示词之前解析。该集合合并请求、已同步的会话元数据、存活进程自身由机器持有的配置、子标签的父会话，以及 Project group 成员（包括未固定的仓库成员可能使用的每个本地副本）；任意一个未共享即拒绝。额外来源只会增加需检查的项目，因此成员编辑同步元数据无法移除存活进程实际使用的项目。目录只按 ID 从本机注册表取得，不接受任何请求给出的路径、工作目录或 worktree 路径，因此不存在调用方可控的子目录或符号链接逃逸。同成员执行不变。

两处后续修复补上了独立复审发现的问题。恢复不再在授权之后重新读取同步元数据：它按已授权的项目、Project group 和父会话启动；create 与恢复在进程启动前还会重新计算一次范围，拒绝已授权集合之外的任何项目。注册表行是同步数据，任何成员都能写入；在加密工作区中，只有当行的 `rootPath` 仍然哈希回其项目 ID（本机按注册时的规范根目录生成）时才有效，因此被改写的路径会解析为不存在，而不能把已授权项目重定向到其他目录。注册、根目录对账和这项校验都通过 `localProjectsLegacy` 使用原生 `realpath` 规范化，因此大小写不敏感卷上的磁盘实际大小写每次哈希都相同；非原生的 Effect 路径层从不生成 ID，也不得用于这项校验。

会话管理器在准备目录时还会重新读取同步的 Project group 和父会话项目，这次读取发生在申领之后。现在每一次这样的读取都经过 `SessionConfig.authorizeExecutionInputs`：它针对实际使用的快照重新计算范围，并在解析任何成员或准备目录之前拒绝已授权集合之外的项目。

无项目会话（`kind: 'none'`、Lody 管理的聊天目录或托管 GitHub 克隆）只需要机器开关。draft 版基础 Spec 规定缺省项目为私有、"实际本地项目"需要各自的开关，而开启项目会同时开启其机器；因此机器开关允许不触及任何已注册本地项目的工作。项目开关决定成员可以在哪里开始工作；agent 没有沙箱，所以它不是文件系统隔离边界。白皮书把按目录隔离列为未来工作。
