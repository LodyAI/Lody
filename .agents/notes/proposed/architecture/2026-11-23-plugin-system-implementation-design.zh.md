## 摘要

本文将规范性文档 [Lody 插件系统规范](../../../../specs/plugin-system.zh.md) 以及 [插件架构收敛与 E2EE 工作区边界](2026-11-22-plugin-architecture-and-e2ee-boundaries.zh.md) 中的架构边界决策，转化为覆盖 `@lody/plugin-sdk`、`@lody/shared`、`apps/cli`、`@lody/components`、`apps/electron` 与 `apps/mobile-capacitor` 的仓库级工程实施蓝图。守护进程侧的所有 OS 子进程（`PluginHost` 与 `DevPluginCompiler`）均严格收敛至通用 Effect 进程边界 [`packages/shared/src/node/process.ts`](../../../../packages/shared/src/node/process.ts) 并由原生 Effect v4（`4.0.2`）`Scope` 托管；客户端渲染、原始状态快照读取、永久保留的 `SessionCreationReceipt` 幂等回执与 E2EE 执行签名则直接复用现有的 `ai-gui`、`sidebar-surface`、`vscode-theme`、Loro/Flock、`sessionData`/Roost 与 `e2ee-execution-intent` 模块所有者，不引入任何平行状态存储。整体交付按依赖顺序拆解为四个纵向闭环的 Stacked PR（`PR-1` 至 `PR-4`）：其中 `PR-2` 即跑通覆盖 Desktop Electron 与 Web 的完整交互插件纵向闭环，`PR-3` 在此之上叠加原始快照、机器侧工作流与有根 E2EE 派生。当前实施证据见[规范 §17.4](../../../../specs/plugin-system.zh.md)。

## 2. 原生 Effect v4 生命周期与故障隔离契约

遵循 [`packages/shared/src/node/AGENTS.md`](../../../../packages/shared/src/node/AGENTS.md) 与 [`scripts/check-cli-process-boundary.mjs`](../../../../scripts/check-cli-process-boundary.mjs)，`apps/cli` 严禁直接导入 `node:child_process` 或调用 `process.kill` / `child.kill`。为此，在 [`packages/shared/src/node/process.ts`](../../../../packages/shared/src/node/process.ts) 的 `NodeProcessApi` 中新增 `spawnIpcChild`（并在 `process-testing.ts` 的内存进程表中提供等价桩实现），返回受 `Scope` 约束的句柄 `{ pid, send, messages: Stream<unknown, ProcessIpcError>, exit, ringBuffer }`。**通用 `process.ts` 完全不感知任何插件业务协议：** 其 `Scope` 终结器仅执行纯粹的 OS 进程树终止（`terminateTree`：`SIGTERM -> 2000 ms waitUntilGone -> SIGKILL -> 剔除僵尸进程的 OS 进程表核验` + `ProcessReleaseFailed` 恢复租约）；应用层的 `{ type: "shutdown", graceMs: 2000 }` IPC 帧完全由上层 `PluginHost` 在关闭子 `Scope` 前自行发送。

`PluginHost` 与 `DevPluginCompiler` 均采用原生 Effect `4.0.2` 服务编写（`Context.Service`、`Layer.effect`、`Effect.fn`、`Schema.TaggedError`、`PubSub`、`Deferred`、`Ref`、`Clock`），逐项落实 [`cli-effect-ts.md#behavior-contract`](../../../docs/cli-effect-ts.md) 与 [`failure-containment.md`](../../../docs/failure-containment.md)：

| 契约维度                                                          | `PluginHost`（`apps/cli/src/plugins/workflow/plugin-host.ts`）                                                                                                                                                                                                                                                                                                                                                                                                                                                           | `DevPluginCompiler`（`apps/cli/src/plugins/workflow/dev-plugin-compiler.ts`）                                                                                                        |
| ----------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **1. 触发源（Trigger）**                                          | 守护进程启动（非 `--safe-mode` 下自动拉起已启用插件）、显式 CLI/RPC `enable` / `reload` / `disable` / `remove`，或 `machine.js` / `manifest` 发生变更的 `--dev` 重编译。                                                                                                                                                                                                                                                                                                                                                 | 显式执行 `lody plugin link --dev`、`pack`，或受监听插件源码目录触发去抖（`150 ms`）文件变更。                                                                                        |
| **2. 所有权与 FIFO 串行化**                                       | 守护进程根 `Scope` 持有 `PluginHost`；每个运行中的 `machine` 插件独占一个子 `Scope.Closeable`。鉴于 Effect `4.0.2` 的 `Semaphore` 在立即重入时不保证 FIFO，按 `pluginId` 隔离的生命周期变迁采用**自管 `Ref`/`Deferred` FIFO 队列**，在严格保序执行 `disable` / `remove` 的同时将积压的重复 `--dev` `reload` 合并为最新一次构建。                                                                                                                                                                                         | `PluginHost` 子 `Scope` 按需持有编译子进程租约。基于 `Clock` 的空闲计时器（实现自定义有界窗口，如开发态默认 `30 s`，支持 `TestClock` 确定性推进）在无排队/运行中构建时自动关闭编译 `Scope`，使常驻编译器内存归零。 |
| **3. 取消与协议分层回收**                                         | 关闭插件子 `Scope` 前，`PluginHost` 先中止宿主 `AbortController`，经 `handle.send` 发送 `{ type: "shutdown", graceMs: 2000 }`（不提前调用 `child.disconnect()`），并将 `handle.exit` 与 `2000 ms` `Clock` 计时器竞速；若超时仍未退出，关闭子 `Scope` 交由 `process.ts` 的 `terminateTree`（`SIGTERM -> 2000 ms -> SIGKILL -> waitUntilGone`）强制回收。守护进程退出时对全部插件回收施加总超时上限，杜绝失控子进程阻塞退出。                                                                                              | 取消或被新构建取代时立即中断当前编译 Fiber；若 `esbuild` 子进程无响应，关闭其 `Scope` 即经 `terminateTree` 强制清理整棵进程树。                                                      |
| **4. `clientDigest` 与 `instanceId` 解耦及 Drain-Before-Respawn** | `instanceId` 专用于标识 **`MachinePluginInstance` 子进程运行代次**，**唯有当 `PluginHost` 实际派生新的 `machine` OS 子进程时才递增**。仅修改 `client.tsx`、主题或 CSS 只会更新 `clientDigest` 并热替换各客户端，**绝不重启 `machine` 子进程或轮换 `instanceId`**。当确实需要重派生 `machine` 子进程时，旧 OS PID 存活期间绝不启动替代进程；若 `Scope.close` 抛出 `ProcessReleaseFailed`，`PluginHost` 保留其恢复租约并令后续 `enable` / `reload` 等待 `lease.retryTermination` 直至 `waitUntilGone` 确认旧进程彻底消失。 | 编译产物先写入临时目录，仅在编译成功后原子提交新 `clientDigest` 与产物目录（绝不持有或修改 `instanceId`）；编译失败保留旧有效产物并将结构化诊断推送至 `Plugin Inspector`。           |
| **5. 规范超时上限与零自动重试**                                   | 严格执行规范第 9.3 节时限：`init -> ready` 为 **`10_000 ms`（`10 s`）**；`start`（`machine.onStart`）、`query`、`mutation`、`attachment-*` 与 `event` 均为 **`30_000 ms`（`30 s`）**；`defineTool` 为 **`600_000 ms`（`10 min`）**。握手超时、异常退出或协议违规直接置为 `Faulted`，**自动重试次数为 `0`** 且**绝不缓存失败的启动 Fiber**。崩溃或超时将未决 `mutation` / `tool` 结算为 `PluginCallError { code: "outcome_unknown" }`，未决 `query` 立即报错且不重放。                                                    | 编译器崩溃或语法/打包错误直接令当次构建失败并返回文件/行号诊断；守护进程侧文件监听器保持存活，开发者保存修复后即可触发下一轮编译。                                                   |
| **6. 爆炸半径隔离**                                               | 纯客户端、主题、纯 Skill 与 `sound-effects` 插件占用 `0` 个后端子进程。插件 `A` 的崩溃、CPU 死循环或 `--max-old-space-size=256` V8 OOM 仅终结 `A` 自身 PID，守护进程、活跃 ACP 会话与插件 `B` 零受累。                                                                                                                                                                                                                                                                                                                   | `esbuild` 运行在 `DevPluginCompiler` 独立子进程内，原生打包器崩溃或内存溢出绝不污染守护进程堆空间。                                                                                  |

## 3. 数据面、UI 挂载稳定性、产物分发与 E2EE 门禁接线

### 3.1 共享 `lodyCommands` 注册表、双层读取、托管存储、事件游标与 `machine.service`

- **共享类型化宿主命令注册表（`lodyCommands`，稳定性分级）：** 规范化 `LodyCommandDescriptor<S, TInput, TOutput>` 定义于 `packages/shared/src/commands/host-commands.ts`（Tier-1 核心会话/元数据/定时任务命令，以及基于 [`status-view/command.ts`](../../../../packages/shared/src/status-view/command.ts) 的 shell-coupled / experimental 侧边栏分流命令）。第一方 UI（[`use-session-actions.ts`](../../../../packages/components/src/hooks/use-session-actions.ts)）与插件 `lody.execute` / `useLodyCommand` / `ctx.lody.execute` 共用 `workspace-command-executor.ts` / `daemon-command-executor.ts`，SDK 侧 `sessions.*` 别名统一收口至单一 `lody.execute` 线协议操作码。每次 `host_call` 携带 `contextId`（`callId` / `eventId` / `"start"` / `"service"`）以便守护进程绑定源 `ActorContext`（登录/RPC 成员、活跃 `ToolExecutionContext` 所属人或经核验的 `DeclaredWorkflowGrant` 工作流主体——拒绝无主体的 `sessionMarkRead` 等个人偏好写入）并校验 `manifest.permissions`（`sessions.write`、`sessions.approve`、`workflow.autonomous`、`unstable.rawState`）。
- **双层读取模型（`lodyQueries` + `annotations` / Tier-2 `lody.unstable.readSnapshot`）：** Tier-1 归一化 `lodyQueries` 与跨端同步 `<= 4 KiB` 实体 `annotations`（`sessionSetAnnotation` / `projectSetAnnotation`）直接挂接 Loro/Flock 与 [`session-data`](../../../../packages/shared/src/session-data/AGENTS.md) / Roost，零平行 Domain Store。Tier-2 `lody.unstable.readSnapshot` / `useUnstableLodySnapshot` 要求显式 `manifest.permissions: ["unstable.rawState"]`，仅按白名单投影公开顶层领域集合（绝不黑名单过滤导出内部 CRDT 原文档），强制要求 `collection`/`path` 或有界 `turnIds`/`limit` 切片，并施以 `512 KiB` 硬上限。
- **宿主托管作用域存储（`storage`）、本地事件游标、永久 `SessionCreationReceipt` 与长驻 `machine.service`：**
  - `ctx.storage`（守护进程本地 SQLite）与 `lody.storage`（客户端用户/工作区偏好）在 E2EE 托管域内提供原子 `get` / `set` / `delete` / CAS `update`，彻底消除手写 `.tmp` 文件锁样板代码。
  - `SessionCreationReceiptStore` 无 TTL 永久持久化 `(workspace_id, caller_user_id, canonical_target_key, plugin_id, request_id) -> { payload_sha256, session_id, business_key? }`；会话归档后释放 `businessKey` 唯一约束同时永久保留 `requestId` 历史。
  - `PluginHost` 将规范化 `MachineHostEventMap` 信封（含 `session.archived` 与 `session.interaction.resolved`）写入本地 SQLite 有界序号表，使 `{ resumeFromCursor: true }` 在重启后按序重放遗漏事件而无 `onStart` 全扫超时风险；`onStart` 不阻塞读查询；`machine.service(ctx)` 持有贯穿插件运行期直至 `shutdown` 的 `AbortSignal`，原生支撑 Slack/Telegram/飞书审批桥接与 Webhook。超出 `16 KiB`（`<= 2 MiB`）的 `defineTool` 输出由宿主自动溢出至托管回合产物存储并保留内联摘要。

### 3.2 来源归属（`npm` vs `local`）、路由化自定义页面、三层自定义设置与 `blockId` 状态保护

- **钉死 `npm` 零机冷启动、`owner_machines` 同步与多机动态客户端路由：** 公开发布的 `npm` 包（精确版本 + SRI `integrity` + `clientDigest` 存于加密 `WorkspacePluginEntry`）在 Web 端 `0` 机器在线时直接冷启动（托管 IndexedDB → 直连 CORS `.tgz` 经浏览器 `DecompressionStream('gzip')` 解包 → 回退 `plugin/bundle-chunk`，获批前零外网请求，严格核验 `integrity` + `clientDigest`，跨标签页经同托管 `BroadcastChannel` 同步）。可选 `machineSync: "owner_machines"` 仅同步至安装者自有机器（绝不安装到协作者机器、绝不跨机复制 `secret` 或静默签发 `DeclaredWorkflowGrant`）；`local` / `--dev` / GitHub CLI 安装严格绑单机、永不自动同步。多机去重后的工作区主客户端实例按 `target.machineId` 动态转发 `useQuery` / `useMutation` / `lody.execute` / `openProject` / `openSession`，不再绑死单机。
- **路由化自定义页面与三层自定义设置：** 以 TanStack Router 一等路由替代模态 `PluginScreenOutlet` `<Dialog>`：`screens` 挂载于 `/$workspaceName/p/$pluginId/$screenId`（`nav: "sidebar"` 统一收纳至宿主 Apps/Plugins 侧边栏分区，URL search params 经 `lody.screens.setParams` 同步），`project.pages` 挂载于 `/$workspaceName/projects/$machineId/$projectId/p/$pluginId/$pageId`，`session.panels` 作为同步至 `?panel=` 的右侧 Split Pane（移动端退化为 Bottom Sheet），并配齐 5 态冷启动 URL 解析器（`resolving`、`untrusted`、`source_offline`、`disabled`/`not_installed`、`safe_mode`）。`settings.pages.add` 支持 `workspace`（`0` 机器在线可用）、`machine`（兼容 `installation`）与 `project`（直接内嵌 Project Settings），配合宿主托管的 `<PluginSecretField />`（只写不读）、`<PluginConfigForm />` 与 `lody.settings.open(...)`。
- **命令面板、签名前 `beforeSend`、可叠加 `enhance` 匹配器与保态 `blockId`：** 新增 `commands.register`、`composer.slashCommands.add`、客户端签名前 `composer.beforeSend`（个人设备在 `memberInput` 签名前可见地增强提示词）、`lody.ui`（`toast` / `confirm` / `openExternalUrl` / `copyToClipboard`）及 `session.headerActions` / `messages.actions` / `statusBar.items` 轻量槽位。[`markdown-renderer.tsx`](../../../../packages/components/src/components/ai-gui/markdown-renderer.tsx) 以 `${sessionId}:${blockId}:${winner.pluginId}:${winner.id}` 保持流式组件状态；[`tool-call-detail.tsx`](../../../../packages/components/src/components/ai-gui/tool-call-detail.tsx) 区分 `"replace"` 唯一胜出（配“查看原始输出”开关）与可叠加 `"enhance"` 渲染器；托管样式表挂载于 `@layer lody-plugin`。

### 3.3 五道 E2EE 运行时安全门禁接线

1. **非访客执行门禁：** 在 [`packages/shared/src/e2ee-rpc.ts`](../../../../packages/shared/src/e2ee-rpc.ts) 中将 `method.startsWith('plugin/')` 纳入 `isE2eeFeatureMethod`，保持 `E2EE_READ_QUERY_METHODS` 不变，使 `plugin/query`、`plugin/mutate`、`plugin/control` 与 `plugin/attachment-*` 强制走非 Guest `authorizeExecution`（`< 15 min` 账本新鲜度）。
2. **机器所有者与 `MachineSharing` 作用域门禁：** 守护进程 RPC 分发接入 [`@lody/e2ee-machine-sharing`](../../../../packages/e2ee-machine-sharing/AGENTS.md)：`machine` 级处理器、跨 Desktop/Web/Mobile 的远程 `plugin/control`（`inspect`/`enable`/`disable`/`reload`/`configure-many`/`set-secret`/`resolve-proposal`/`manage-workflow-grant`，解除仅限本地传输的人为限制）、`owner_machines` 同步归属、`DeclaredWorkflowGrant` 签发与撤销、`devSessionNonce` 与 `acpProviders` 限定机器所有者；协作者仅在 `MachineSharing` 同时授权该机器及全部绑定项目时可调用 `project` / `session` 处理器并写入非敏感 `scope: "project"` 配置。
3. **双模型 `e2eeIntent`（`SignedTurnOrigin` vs `DeclaredWorkflowGrant`）：** 客户端交互写入（`sessionCreate`、`sessionSend`、`sessionRespondInteraction`、`sessionFork`、`scheduleRunNow`）与机主远程 `plugin/control` 变更在客户端 `composer.beforeSend` 之后签发 `E2EE_INTENT_KIND.memberInput`（`1`）。**模型 A（`ToolExecutionContext`）：** 写入时核验驱动回合在运行时仍活跃且匹配本地 `sessionData` 中已存 `originTurn`，签发 `derivedFrom` `machineInput`（`kind = 2`，有效 `MachineSharing`、同机、20 跳上限）；已结束历史回合不再授权新成员派生。**模型 B（`machine_event` / `machine_startup` / `machine_service`）：** 要求具备 `manifest.permissions`（`workflow.autonomous` + `sessions.write`/`sessions.approve`）及经核验、未撤销的机主签名 `DeclaredWorkflowGrant` 覆盖 `(workspace_id, machine_id, plugin_id, op, target_project_id, role_id)`，以已声明工作流主体执行。无根查询与变更处理器返回 `forbidden`。
4. **Iroh 传输帧预算与已校验 `npm` 归档：** `plugin/query` 与 `plugin/mutate` 限制序列化载荷 `<= 256 KiB`（单帧 `1 MiB` `purpose 8`）；`plugin/bundle-chunk` 以 `256 KiB` `purpose 9` 分页流式传输 `<= 4 MiB` 客户端产物，直连 `npm` `.tgz` 下载仅在信任批准后执行，均在写入托管缓存或执行 `import()` 前核验 SRI `integrity` 与 `clientDigest` SHA-256。
5. **托管目录绑定、白名单投影与静态明文分享兜底：** 守护进程 `ctx.dataDir`、`ctx.storage`、`SessionCreationReceiptStore`、`DeclaredWorkflowGrant` 存储、本地事件游标表与客户端远程产物及信任 IndexedDB 缓存（含跨标签页 `BroadcastChannel`）统一挂载在 `<account>/<workspace>/<genesis>/<signing-key>/plugins/` 下并随成员移除或设备吊销原子擦除；Tier-2 快照采用白名单域投影；静态明文分享页面禁用 `ClientPluginHost` 脚本执行，仅渲染内置原始输出兜底卡片。
