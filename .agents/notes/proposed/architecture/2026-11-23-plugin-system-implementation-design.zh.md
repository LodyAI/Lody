## 摘要

本文将规范性文档 [Lody 插件系统规范](../../../../specs/plugin-system.zh.md) 以及 [插件架构收敛与 E2EE 工作区边界](2026-11-22-plugin-architecture-and-e2ee-boundaries.zh.md) 中的架构边界决策，转化为覆盖 `@lody/plugin-sdk`、`@lody/shared`、`apps/cli`、`@lody/components`、`apps/electron` 与 `apps/mobile-capacitor` 的仓库级工程实施蓝图。守护进程侧的所有 OS 子进程（`PluginHost` 与 `DevPluginCompiler`）均严格收敛至单一 Effect 进程边界 [`packages/shared/src/node/process.ts`](../../../../packages/shared/src/node/process.ts) 并由原生 Effect v4（`4.0.2`）`Scope` 托管；客户端渲染、原始状态快照读取与 E2EE 执行签名则直接复用现有的 `ai-gui`、`sidebar-surface`、`vscode-theme`、Loro/Flock、`sessionData`/Roost 与 `e2ee-execution-intent` 模块所有者，不引入任何平行状态存储。整体交付按依赖顺序拆解为四个可独立合入、各自闭环验证的 Stacked PR（`PR-1` 至 `PR-4`），并明确临时 Legacy 门面的退出条件。本文不直接提交生产运行时代码，四个 PR 切片均有待按本蓝图依次实施。

## 2. 原生 Effect v4 生命周期与故障隔离契约

遵循 [`packages/shared/src/node/AGENTS.md`](../../../../packages/shared/src/node/AGENTS.md) 与 [`scripts/check-cli-process-boundary.mjs`](../../../../scripts/check-cli-process-boundary.mjs)，`apps/cli` 严禁直接导入 `node:child_process` 或调用 `process.kill` / `child.kill`。为此，在 [`packages/shared/src/node/process.ts`](../../../../packages/shared/src/node/process.ts) 的 `NodeProcessApi` 中新增 `spawnIpcChild`（并在 `process-testing.ts` 的内存进程表中提供等价桩实现），返回受 `Scope` 约束的句柄 `{ pid, send, messages: Stream<unknown, ProcessIpcError>, exit, ringBuffer }`，其 `Scope` 终结器统一执行 `IPC shutdown 帧 -> 有界优雅等待 -> terminateTree（SIGTERM -> waitUntilGone -> SIGKILL -> 剔除僵尸进程的 OS 进程表核验）`。

`PluginHost` 与 `DevPluginCompiler` 均采用原生 Effect `4.0.2` 服务编写（`Context.Service`、`Layer.effect`、`Effect.fn`、`Schema.TaggedError`、`PubSub`、`Deferred`、`Ref`、`Clock`），逐项落实 [`cli-effect-ts.md#behavior-contract`](../../../docs/cli-effect-ts.md) 的六项生命周期契约与 [`failure-containment.md`](../../../docs/failure-containment.md) 的爆炸半径防线：

| 契约维度                               | `PluginHost`（`apps/cli/src/plugins/workflow/plugin-host.ts`）                                                                                                                                                                                                                                                                   | `DevPluginCompiler`（`apps/cli/src/plugins/workflow/dev-plugin-compiler.ts`）                                                                                                        |
| -------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **1. 触发源（Trigger）**               | 守护进程启动（非 `--safe-mode` 下自动拉起已启用 `machine` 插件）、显式 CLI/RPC `enable` / `reload` / `disable` / `remove`，或 `--dev` 文件监听编译完成回调。                                                                                                                                                                     | 显式执行 `lody plugin link --dev`、`pack`，或受监听插件源码目录触发去抖（`150 ms`）文件变更。                                                                                        |
| **2. 所有权与 FIFO 串行化**            | 守护进程根 `Scope` 持有 `PluginHost`；每个运行中的 `machine` 插件独占一个子 `Scope.Closeable`。鉴于 Effect `4.0.2` 的 `Semaphore` 在立即重入时不保证 FIFO，按 `pluginId` 隔离的生命周期变迁采用**自管 `Ref`/`Deferred` FIFO 队列**，在严格保序执行 `disable` / `remove` 的同时将积压的重复 `--dev` `reload` 合并为最新一次构建。 | `PluginHost` 子 `Scope` 按需持有编译子进程租约。基于 `Clock` 的空闲计时器（`1000 ms`，支持 `TestClock` 确定性推进）在无排队/运行中构建时自动关闭编译 `Scope`，使常驻编译器内存归零。 |
| **3. 取消与有界回收**                  | 关闭插件 `Scope` 会触发宿主 `AbortController`，发送 `{ type: "lifecycle/shutdown" }`（经 `Clock` 限时 `2000 ms`），随后交由 `process.ts` 的 `terminateTree`（`2000 ms` `SIGTERM` -> `SIGKILL` -> `waitUntilGone`）兜底。守护进程退出时对全部插件回收施加总超时上限，杜绝失控子进程阻塞退出。                                     | 取消或被新构建取代时立即中断当前编译 Fiber；若 `esbuild` 子进程无响应，关闭其 `Scope` 即经 `terminateTree` 强制清理整棵进程树。                                                      |
| **4. 代际交接与 Drain-Before-Respawn** | 旧 OS PID 存活期间**绝不**派生替代进程。若 `Scope.close` 抛出携带未决恢复租约的 `ProcessReleaseFailed`，`PluginHost` 会将该租约保留在对应 `pluginId` 状态槽中，任何后续 `enable` / `reload` 必须先等待 `lease.retryTermination` 直至 `waitUntilGone` 确认旧进程彻底消失，从根源杜绝 `ctx.dataDir` 并发写损坏。                   | 新编译产物先写入临时目录，仅当编译成功后才原子切换 `current` 元数据并递增 `instanceId` / 更新 `clientDigest`；编译失败保留旧运行实例并将结构化诊断推送至 `Plugin Inspector`。        |
| **5. 故障恢复（零自动重试）**          | 启动握手超时（`5000 ms`）、子进程异常退出或单次调用超时（查询/变更 `15_000 ms`、工具 `60_000 ms`、事件 `5000 ms`）直接将该插件置为 `Faulted`，**自动重试次数为 `0`**，且**绝不缓存失败的启动 Fiber**。未决 `mutation` / `tool` 统一结算为 `PluginCallError { code: "outcome_unknown" }`，未决 `query` 立即报错且不重放。         | 编译器崩溃或语法/打包错误直接令当次构建失败并返回行列号诊断；守护进程侧文件监听器保持存活，开发者保存修复后即可触发下一轮编译。                                                      |
| **6. 爆炸半径隔离**                    | 纯客户端、主题、纯 Skill 与 `sound-effects` 插件占用 `0` 个后端子进程。插件 `A` 的崩溃、CPU 死循环或 `--max-old-space-size=256` V8 OOM 仅终结 `A` 自身 PID，守护进程、活跃 ACP 会话与插件 `B` 零受累。                                                                                                                           | `esbuild` 运行在 `DevPluginCompiler` 独立子进程内，原生打包器崩溃或内存溢出绝不污染守护进程堆空间。                                                                                  |

## 3. 数据面、UI 挂载稳定性、产物分发与 E2EE 门禁接线

### 3.1 零平行存储的 `lodyQueries` 与按需懒物化快照

- **类型化查询（`lodyQueries`）：** `ClientPluginHost` 与 `PluginHost` 直接在现有工作区 Loro/Flock 文档读取器及 [`packages/shared/src/session-data`](../../../../packages/shared/src/session-data/AGENTS.md) / Roost 窄查询索引上解析全部 18 个类型化查询描述符（含 `sessions` 上的 `sessionIds`、`agentRoleId`、`updatedAfter` 增量过滤，以及 `sessionTurns` 上的 `userTurnId` / `stopReason`），绝不维护第二份平行 Domain Store。
- **按需脱离句柄的只读快照（`useLodySnapshot` / `readSnapshot`）：** 订阅直接挂载引用计数的底层 Loro 房间或活跃 `sessionData` 增量监听器并仅做脏标记失效；**唯有当已挂载组件或 `readSnapshot` 调用方实际读取脏版本时**，才对请求范围执行 `structuredClone` + 递归 `Object.freeze` 懒物化，并在返回前剥离密钥字段与非本插件的私有 `businessKey`。
- **守护进程重启增量对账（`machine.onStart`）：** 守护进程启动并在所有已启用 `machine` 插件完成 IPC 注册握手后、开放实时 `machine.events` 投递前，对每个插件调用一次 `onStart(ctx)`；结合 `ctx.dataDir` 持久日志、`lodyQueries.sessions({ updatedAfter })` + `sessionTurns` 历史对账以及 `SessionCreationReceiptStore`（按 `(plugin_id, idempotencyKey)` 索引的 `24 h` TTL 幂等账本），确保停机期间错过的回合在保留原始 `ProjectRef` 与 `parentSession` 的前提下幂等恢复。

### 3.2 客户端 UI 挂载接线与 `MessageBlockRenderProps.blockId` 状态保护

- **ESM 模块加载与 `Trusted Dev Session`：** `ClientPluginHost` 按 `(pluginId, clientDigest)` 幂等调和 `plugin/catalog`。`DevPluginCompiler` 将 `client.tsx` 打包为浏览器标准 ESM，并将 `react`、`react/jsx-runtime`、`zod`、`@lody/ui` 与 `@lody/plugin-sdk/*` 外置映射到宿主冻结模块表。在远程 Web/Desktop 连接下，发布态插件按 `(workspace_id, machine_id, plugin_id, clientDigest)` 逐版本显式确认信任；而 `devMode: true` 插件提供显式 **“信任当前开发会话（Trust Dev Session）”** 开关，在标签页内存 / `sessionStorage` 中绑定 `(workspace_id, machine_id, plugin_id, devSessionNonce)`（顶部常驻 **“Dev Session Active · Revoke”** 撤销徽章，且在 `devSessionNonce` 轮换或清单能力扩容时立即失效重询）。
- **保态流式 `messages.renderBlock` 与通用 `tools.matchRender`：** [`markdown-renderer.tsx`](../../../../packages/components/src/components/ai-gui/markdown-renderer.tsx) 为回合内每个围栏代码块分配确定性 `blockId = "${turnId}:block:${ordinal}"`，并以 `${sessionId}:${blockId}:${winner.pluginId}:${winner.id}` 作为 React key 渲染 `PluginMessageBlockSurface`。流式 Token 追加与围栏闭合仅**原位更新** `code` 与 `streaming` 属性而不卸载已挂载组件实例，完整保留表单输入、图表缩放与选中状态，同时遵循 [`ai-gui/AGENTS.md`](../../../../packages/components/src/components/ai-gui/AGENTS.md) 不向插件子树注入 `useSessionSearchBlock`。`PluginMessageBlockSurface` 与包裹 [`tool-call-detail.tsx`](../../../../packages/components/src/components/ai-gui/tool-call-detail.tsx) 的 `PluginToolCallSurface` 均在宿主壳层头部渲染不可伪造的切换按钮（`"View Raw Markdown"` / `"View Raw Output"`）及 `SurfaceErrorBoundary` 异常降级兜底。
- **三层正交 `sidebar` 与双层 `themes` / `styles`：** [`loro-app-sidebar.tsx`](../../../../packages/components/src/components/loro-app-sidebar.tsx) 基于 [`sidebar-surface.ts`](../../../../packages/components/src/components/sidebar-surface.ts) 组合 `sidebar.sections`、`sidebar.panels` 与单赢家 `sidebar.replace`，并在整栏接管时于宿主窗口顶栏保留原生侧边栏一键切回入口；`themes` 接入 [`vscode-theme-dom.ts`](../../../../packages/components/src/lib/vscode-theme/vscode-theme-dom.ts)，`styles` 挂载带 `data-lody-plugin="<plugin_id>"` 属性的受控 `<style>` 节点并在停用/卸载时原子移除。

### 3.3 五道 E2EE 运行时安全门禁接线

1. **非访客执行门禁：** 在 [`packages/shared/src/e2ee-rpc.ts`](../../../../packages/shared/src/e2ee-rpc.ts) 中将 `method.startsWith('plugin/')` 纳入 `isE2eeFeatureMethod`，同时保持 `E2EE_READ_QUERY_METHODS` 不变，使 `plugin/query`、`plugin/mutate` 与 `plugin/attachment-*` 强制走非 Guest `authorizeExecution`（要求 `< 15 min` 账本新鲜度）。
2. **机器所有者与 `MachineSharing` 作用域门禁：** 守护进程 RPC 分发接入 [`@lody/e2ee-machine-sharing`](../../../../packages/e2ee-machine-sharing/AGENTS.md)：`machine` 级处理器、插件安装/启停/重载/配置写入、`devSessionNonce` 与 `acpProviders` 严格限定本机所有者；协作者仅在 `MachineSharing` 同时授权该机器及请求涉及的全部项目时可调用 `project` / `session` 处理器。
3. **`SignedTurnOrigin` 与 `e2eeIntent` 派生签名：** 客户端 `sessions.create` / `send` / `respondInteraction` 经 [`e2ee-execution-intent.ts`](../../../../packages/shared/src/e2ee-execution-intent.ts) 签发 `E2EE_INTENT_KIND.memberInput`（`1`）。守护进程侧 `ToolExecutionContext`、`MachineEventContext` 与 `MachineStartupContext` 直接在本地 `sessionData` 中核验 `originTurn: { session, userTurnId }` 对应的人类签名 `memberInput` 记录（强制执行 20 跳派生上限与单机规则）后签发 `E2EE_INTENT_KIND.machineInput`（`2`）；无根查询与变更处理器无签名权，调用即以 `forbidden` 拒绝。
4. **Iroh 传输帧预算：** `plugin/query` 与 `plugin/mutate` 将序列化载荷限制在 `256 KiB` 以装入单个 `1 MiB` `purpose 8` 帧；`plugin/bundle-chunk` 以 `256 KiB` `purpose 9` 分页流式传输 `<= 4 MiB` 的客户端产物，并在写入托管缓存或执行 `import()` 前完整校验 `clientDigest` SHA-256。
5. **托管目录绑定与静态明文分享兜底：** 守护进程 `ctx.dataDir` 与客户端远程产物缓存统一挂载在 `<account>/<workspace>/<genesis>/<signing-key>/plugins/` 下并接入既有 E2EE 吊销/擦除钩子；静态明文分享页面禁用 `ClientPluginHost` 第三方脚本执行，仅渲染内置原始输出卡片。
