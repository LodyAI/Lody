# Plugin architecture convergence and E2EE workspace boundaries

Status: proposed
Translation: current

[简体中文](2026-11-22-plugin-architecture-and-e2ee-boundaries.zh.md)

## Abstract

Reviewing the [Lody Plugin System Spec](../../../../specs/plugin-system.md) across runtime failure containment, Agent Workspace product plasticity, and E2EE authorization boundaries converged on **a lean, fail-stop per-plugin subprocess runtime (`child_process.fork`, Drain-Before-Respawn, zero auto-retry, `clientDigest` + `instanceId`, `contextId`-bound `host_call`) paired with full no-fork Agent Workspace extensibility**:

- **Workspace-vs-machine client ownership & multi-machine deduplication** (client-only plugins mount once per workspace and stay alive when machines sleep; multi-machine companion UIs deduplicate workspace-wide contributions);
- **Canonical Client + Machine Host Events (with local monotonic cursor resume) + long-lived `machine.service`** alongside **Command Palette, Slash Commands, client pre-signing `composer.beforeSend`, `lody.ui` primitives, and lightweight Session/Message/StatusBar slots**;
- **Universal `tools.matchRender` (`replace` + additive `enhance`) and `messages.renderBlock`** with mandatory `"View Raw Output"` host toggles and `@layer lody-plugin` CSS isolation;
- **Two-tier read model & host-managed storage**: Tier-1 normalized `lodyQueries` + synced `annotations` + atomic custody-scoped `storage`, paired with an opt-in Tier-2 **`lody.unstable.readSnapshot` / `useUnstableLodySnapshot` allowlist-projected, path-scoped, `<= 512 KiB` escape hatch** so heavy customizers never fork Lody without freezing internal Loro/Roost schemas or risking denylist leaks;
- **Explicit `manifest.permissions` (`sessions.write`, `sessions.approve`, `workflow.autonomous`, `unstable.rawState`) and Dual-Model E2EE authorization**: live-turn `SignedTurnOrigin` derivation (`ToolExecutionContext`) strictly separated from machine-owner-signed `DeclaredWorkflowGrant` for post-turn events, restart recovery, and background bridges.

## Core convergence decisions

### 1. Keep the runtime engine lean: per-plugin subprocesses, Drain-Before-Respawn, and Fail-Stop

Aligned with [`.agents/docs/failure-containment.md`](../../../../.agents/docs/failure-containment.md) and Paseo's external subprocess boundary:

- **One dedicated `child_process.fork` subprocess per enabled `machine` plugin** (`0` subprocesses for client-only, sound, theme, or skill-only plugins): every crash, hang, or V8 OOM attributes unambiguously to one `pluginId`, eliminating canary workers.
- **Drain-Before-Respawn and serialized lifecycle queue:** All `enable` / `reload` / `disable` / `remove` transitions per `pluginId` execute serially; stopping enforces `shutdown → 2s SIGTERM → 2s SIGKILL` and **never spawns a replacement PID until the old OS PID emits `close`**, preventing `ctx.dataDir` races.
- **Bounded-idle `--dev` compiler subprocess & `clientDigest` + `instanceId`:** Development `esbuild` runs in an on-demand child process reaped after bounded inactivity (e.g., `30 s` default) and on daemon shutdown; `ClientPluginHost` reconciles solely by `clientDigest = SHA-256(client.js + assets/)` while `PluginHost` tracks a monotonic runtime `instanceId`.
- **Single-layer flat IPC (`contextId`-bound `host_call`) and zero automatic retry:** Every `host_call` carries `contextId` (`callId` / `eventId` / `"start"` / `"service"`) and routes command mutations over a single `lody.execute` wire op. Unexpected exit or timeout settles in-flight `mutation` / `tool` calls as `outcome_unknown` and `query` calls as errors with `0` automatic retries, quarantining the plugin in `Faulted` until explicit `reload`. Oversized `defineTool` outputs (`16 KiB .. 2 MiB`) auto-spill to host-managed turn artifact storage instead of failing after execution.

### 2. Full Agent Workspace plasticity with explicit stability tiers

- **Canonical Host Events (`lody.events.on` & `machine.events.on`), Event Cursor Resume & Long-Lived `machine.service`:** Covers `session.archived` and `session.interaction.resolved` alongside turn/tool/waiting events; bounded queues prevent slow tool handlers from blocking control events; local SQLite event cursor (`resumeFromCursor: true`) + host-managed atomic `ctx.storage` eliminate 200-line hand-rolled file-locking and full-history recovery scans; `machine.service(ctx)` runs beyond the `30 s` `onStart` timeout so Slack/Telegram/Feishu approval bridges and webhooks work natively.
- **High-Leverage Client Surface (`commands`, `composer.slashCommands`, pre-sign `composer.beforeSend`, `lody.ui`, lightweight slots):** Adds Command Palette registration, actionable `/slash` commands, visible personal-device pre-signing prompt hooks (preserving E2EE integrity), `toast`/`confirm`/`openExternalUrl`/`copyToClipboard`, and session header / message footer / status-bar slots.
- **Universal Tool Call Matchers (`replace` + additive `enhance`) & Message Block Renderers:** `"replace"` selects one deterministic winner (with host `"View Raw Output"` toggle and `SurfaceErrorBoundary`), while `"enhance"` renderers compose additively; `messages.renderBlock` preserves mounted state via deterministic `blockId = "<turnId>:block:<ordinal>"` and respects [`ai-gui`](../../../../packages/components/src/components/ai-gui/AGENTS.md) invariants.
- **Two-Tier Workspace Data & Appearance (`themes` / `@layer lody-plugin` `styles`; Tier-1 `lodyQueries` + `annotations` + `storage` / Tier-2 `lody.unstable.readSnapshot`):** Tier-1 normalized queries, synced `<= 4 KiB` entity `annotations`, and host-managed `storage` cover mainstream plugins without per-row RPCs or `localStorage` leaks; Tier-2 `lody.unstable.readSnapshot` / `useUnstableLodySnapshot` preserves zero-wall deep customization behind explicit `unstable.rawState` permission, allowlist-only domain projections (no denylist raw-CRDT dumps), mandatory path/window scoping, and a `512 KiB` hard cap.
- **Complete Workflow Composition (`agentRoles`, `skills`, `mcpServers`, conditional managed `acpProviders`):** Core bundles Roles, Skills, and out-of-daemon `stdio` MCP servers ([`apps/cli/src/agent/AGENTS.md`](../../../../apps/cli/src/agent/AGENTS.md)); `acpProviders` bridges declaratively into Lody's existing managed ACP extension contract (`LodyAI/acp-extension-core` and `acp-session-start-gate.ts`) instead of duplicating a Node-only launcher.

### 3. Source provenance (`npm` vs `local`), Web-first pages & settings, DX & Propose-Confirm UX

- **Pinned `npm` vs `local` Provenance, Owner-Machine Sync & Dynamic Multi-Machine Routing:** Published `npm` packages (`exactVersion` + SRI `integrity` + `clientDigest` stored in encrypted `WorkspacePluginEntry`) give Web browsers zero-machine-online cold-start via CORS-enabled `.tgz` fetch (zero pre-trust external network requests, falling back to `plugin/bundle-chunk` behind firewalls or for private packages) and optional `machineSync: "owner_machines"` restricted strictly to machines owned by the installer (never cross-member, never copying machine secrets or silently minting `DeclaredWorkflowGrant`). Local/dev/GitHub-CLI installs stay strictly bound to one machine and never auto-sync. Deduplicated workspace-level primary client instances dynamically route RPCs and navigation by `target.machineId` rather than pinning to one machine.
- **Route-Backed Custom Pages & Three-Scope Custom Settings:** `screens` (`/$workspaceName/p/$pluginId/$screenId` + `nav: "sidebar"`), `project.pages` (project route), and `session.panels` (right-side Split Pane synced to `?panel=`) replace modal-only `<Dialog>` mounting and define a 5-state cold-start URL resolver (`resolving`, `untrusted`, `source_offline`, `disabled`/`not_installed`, `safe_mode`). `settings.pages.add` supports `workspace` (`0` machines online), `machine`, and `project` (embedded in Project Settings), paired with host-managed `<PluginSecretField />` (write-only to target Keychain), `<PluginConfigForm />`, and `lody.settings.open(...)`; Machine Owner remote `plugin/control` (including `set-secret` and `resolve-proposal`) works from Web/Mobile over E2EE-authorized `MachineRpc` instead of being local-only.
- **Declarative `manifest.config` (including `scope: "project"`), `manifest.permissions` & `onboarding`:** High-privilege operations (`sessions.write`, `sessions.approve`, `workflow.autonomous`, `unstable.rawState`) must be declared explicitly and disclosed on install; `sdk` uses real SemVer range matching and marks volatile sidebar-triage commands as shell-coupled/experimental.
- **Agent-Assisted Authoring via Propose-Confirm (`lody_plugin` MCP):** Modeled on [`schedules/AGENTS.md`](../../../../apps/cli/src/lib/schedules/AGENTS.md) (`schedule_proposal.ts`) and `lody_agent_role`, Agents propose installation/enablement via idempotent chat cards gated on human confirmation (`LODY_AGENT_SESSION_ID` is documented honestly as a cooperative CLI guardrail, not a security boundary against a shell-capable agent).

## Encrypted (E2EE) workspace boundaries

In E2EE workspaces ([`specs/e2ee-foundations.md`](../../../../specs/e2ee-foundations.md)), plugins enforce five architectural boundaries:

1. **Guest (`read`) vs Non-Guest execution gate:** Per [`e2ee-rpc.ts`](../../../../packages/shared/src/e2ee-rpc.ts) and [E2EE read queries](../../implemented/architecture/2026-10-28-e2ee-read-queries.md), `plugin/query`, `plugin/mutate`, `plugin/control`, and `plugin/attachment-*` stay outside `E2EE_READ_QUERY_METHODS` and require non-Guest `authorizeExecution` (`<15 min` ledger freshness).
2. **Machine owner vs per-project `MachineSharing`:** Per [`specs/e2ee/machine-sharing.md`](../../../../specs/e2ee/machine-sharing.md) and [`packages/e2ee-machine-sharing/AGENTS.md`](../../../../packages/e2ee-machine-sharing/AGENTS.md), plugin lifecycle, remote `plugin/control` (`enable`/`disable`/`reload`/`set-secret`/`resolve-proposal`/`manage-workflow-grant`), `owner_machines` sync targeting, `DeclaredWorkflowGrant` issuance/revocation, `machine`-scoped secrets/calls, and workflow provider configuration remain machine-owner-only; collaborators invoke `'project'` / `'session'` handlers (and write non-secret `scope: "project"` config) only while `MachineSharing` grants the machine and all bound projects.
3. **Dual-Model Signed Execution Intent (Live-Turn Derivation vs Owner-Signed Workflow Grant):** Per [`e2ee-execution-intent.ts`](../../../../packages/shared/src/e2ee-execution-intent.ts), [signed execution intent](../../implemented/architecture/2026-11-10-e2ee-signed-execution-intent.md), and [shared-member derivation](../../implemented/architecture/2026-10-31-e2ee-shared-member-derivation.md):
   - Client interactive writes (`create` / `send` / `respondInteraction`, after any client `composer.beforeSend` hook) and remote Machine Owner `plugin/control` state changes sign `memberInput` (`kind = 1`).
   - **Model A (In-Turn Derivation):** Daemon `ToolExecutionContext` verifies the driving turn is live and matches stored human-signed `originTurn` in local `sessionData`, signing `derivedFrom` `machineInput` (`kind = 2`, 20-derivation cap, single-machine rule). Historical turns never authorize new member derivations once inactive.
   - **Model B (Autonomous Workflow Grant):** Out-of-turn daemon contexts (`session.turn.completed`, `onStart` recovery, `machine.service` bridges) require `manifest.permissions` (`workflow.autonomous` + `sessions.write` / `sessions.approve`) AND a verified, unrevoked, machine-owner-signed `DeclaredWorkflowGrant` scoped to `(workspace_id, machine_id, plugin_id, op, project, role)`; execution runs under the workflow principal and rejects personal `prefer` writes. Un-rooted `query`/`mutation`/`attachmentSource` calls reject session writes with `forbidden`.
4. **256 KiB single-frame Iroh fast path, pinned `npm` Web cold-start & Core 4 MiB paged bundles:** Per [E2EE Iroh transport](../../implemented/architecture/2026-11-10-e2ee-iroh-transport.md), `MAX_PLUGIN_RPC_REQUEST_BYTES` (`256 KiB`) fits one 1 MiB `purpose 8` frame and `MAX_PACKED_CLIENT_BUNDLE_BYTES` (`4 MiB`) pages over `256 KiB` `purpose 9` chunks; pinned `npm` `.tgz` downloads occur only after user trust approval (metadata disclosed from encrypted `WorkspacePluginEntry`) and verify SRI `integrity` + `clientDigest` SHA-256 before caching or `import()`.
5. **Custody isolation, allowlist projection, and plaintext share fallback:** Daemon `ctx.dataDir`, `ctx.storage`, `SessionCreationReceipt`, `DeclaredWorkflowGrant`, local event cursor ring, and Core Web/Desktop remote bundle & trust IndexedDB caches (plus cross-tab `BroadcastChannel`) bind to `<account>/<workspace>/<genesis>/<signing-key>` ([`apps/cli/src/lib/e2ee/AGENTS.md`](../../../../apps/cli/src/lib/e2ee/AGENTS.md), [`specs/e2ee/client-custody.md`](../../../../specs/e2ee/client-custody.md), [`specs/e2ee/desktop-custody.md`](../../../../specs/e2ee/desktop-custody.md)) and wipe on member removal or device revocation; Tier-2 snapshots use allowlist-only projection; static plaintext shares ([plaintext share consent](../../implemented/feature/2026-10-28-e2ee-share-plaintext-consent.md)) render built-in fallbacks without uploading `ctx.dataDir` or executing third-party `client.js`.

## Rejected alternatives

1. **Shared `PluginWorker` + canary fault workers + silent read-only retries:** Rejected in favor of OS subprocess isolation and deterministic Fail-Stop.
2. **Forcing post-turn / restart workflows through live-turn `SignedTurnOrigin` derivation:** Rejected because ended turns are inactive by definition; replaced by explicit owner-signed `DeclaredWorkflowGrant` separated from in-turn `ToolExecutionContext` derivation.
3. **Binding client-only UX plugins to single machine daemons or mounting duplicate per-machine instances:** Rejected because offline machines broke themes/sounds/pages and multi-machine workspaces produced duplicate effects; replaced by pinned `npm` workspace distribution (with `local` staying single-machine) plus deduplicated multi-machine dynamic RPC routing.
4. **Using raw GitHub Release download URLs as the primary Web cold-start source:** Rejected because GitHub release redirects (`objects.githubusercontent.com`) omit browser CORS headers; retained for machine-local CLI installs while standardizing cross-device Web cold-start and `owner_machines` sync on pinned `npm` `.tgz` packages.
5. **Rendering `screens`, `project.pages`, and `session.panels` inside one global `<Dialog>` or exposing plaintext secrets to custom settings JS:** Rejected because Web custom pages require real URLs/history/Split Panes and custom settings need write-only `<PluginSecretField />` + `workspace | machine | project` bindings without leaking secrets to client JS.
6. **Denylist-filtered raw CRDT dumps in Tier-1 Core:** Rejected because internal schema evolution would break the 1.0 ecosystem and new sensitive fields would leak silently; replaced by Tier-1 normalized queries/annotations + opt-in Tier-2 allowlist-projected, path-scoped `lody.unstable.readSnapshot`.
7. **Forcing every workflow plugin to hand-roll atomic temp-file locking and full-history `onStart` scans under a `30 s` timeout:** Rejected in favor of host-managed atomic `storage` and local SQLite event cursor resume (`resumeFromCursor`).
8. **`machine.beforeSessionTurn` silent post-signing prompt mutation or treating `LODY_AGENT_SESSION_ID` as a security boundary:** Rejected because post-signing mutation breaks E2EE integrity (replaced by client pre-sign `composer.beforeSend`), and env vars are cooperative guardrails rather than security boundaries against shell-capable agents.
