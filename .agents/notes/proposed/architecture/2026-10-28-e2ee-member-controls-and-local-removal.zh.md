## 摘要

产品移除不能等待新密钥才能撤权。原生成员管理提交普通记录，复用现有设置中的密钥更新入口。设备凭据明确确认整成员移除后，先停止并等待该工作区运行结束，再自动删除其托管本地数据。原设备核对与持久标记防止旧响应删除重新加入后的实例；这只保护诚实客户端，不是安全擦除，也不代表生产验收完成。

## 决定与职责

2026-10-27 owner 决定允许 Owner/Admin 移除成员，禁止 Admin 移除 Owner/Admin，禁止移除 Owner；仅 Owner 调整 Admin。UI 遵循这些权限，真正授权仍来自原生已验证账本。普通成员操作使用独立 SQLite 提交日志，不占换代日志。HTTP 前保留原文，恢复时读回同一字节，仅在已验证历史持久化后确认消费。tag10 前先声明 capability 1；旧 tag8 原子 API 保持独立。

移除保持 epoch/承诺，rotationRequired 仅提示。其余成员继续使用保留的 epoch，管理员在设置中完成密钥更新；换代失败不撤销移除、不阻塞发送。设置入口与红点由既有密钥更新实现负责，本 PR 不增加第二套换代流程。

凭据端点区分整成员移除与单设备撤销。目录/历史的通用拒绝或网络错误不得删除数据。宿主先核对发起请求的账号、工作区、创世、公钥和凭据仍对应当前本地身份，再保存终结标记、停止新运行，并在网络锁外等待工作区结束。账号协调器关闭该独立身份拥有者后取得既有独占身份租约才删除；其他进程繁忙则保留标记重试。新身份不得被删除；renderer 没有任意删文件或导出密钥接口。

已接纳的成员操作使用宿主自有的有界 history/ingest，不在注销/关闭等待该操作时重新获取账号锁。Renderer 先停止自身运行，再独立清理本窗口 repo/游标及账号/工作区的待发送输入、高水位记录；全部独立存储成功前保留清理标记和单个范围内重试任务；删除不加入全局运行结束凭据，繁忙或失败不得阻止随后打开其他工作区，只有复用相同数据库的后继等待对应清理。CLI 先禁止内容操作，等待执行和文档运行结束，再通过身份租约与配对互斥清理 custody、runtime 和托管 Loro 数据。保留用户项目目录与其他工作区。新邀请/成员实例生成新设备密钥，拒绝旧成员实例配对。保留公开信任钉和很小的清理标记。离线副本只能在客户端得知移除后清理，其他已停止窗口的独立缓存在打开时自清理；不收回恶意副本、备份或既有外部副作用。

## 替代方案与组合

等待换代违背移除可用性；只按工作区编号删除会误删后来重新加入的实例；把所有无权限响应当移除会在单设备撤销、账号或网络失败时丢数据；复用换代日志会把普通成员调整绑到尚未完成的换代。

本独立分支基于公开 main，验证时临时覆盖 [24-A](https://github.com/LodyAI/Lody/pull/1979) 的 core 文件，覆盖不提交进本 PR。后端采用该 core 并返回精确成员移除错误后才能验收产品。本分支组合已合入的 [#1980](https://github.com/LodyAI/Lody/pull/1980) 设置实现，已验证其管理状态看到移除提示、两套日志独立等待关闭；共享加入接线仍需组合 review。旧 Spec 的强制原子移除和暂停发送文字按明确 MVP 决定修订，仍为 draft，不标记批准。

## 证据与限制

行为测试使用真实 crypto/原生 SQLite、确定性失败注入和完成信号，覆盖普通角色/移除记录、旧 epoch 可用、丢 ACK 后重开复用原字节、原实例清理、凭据限定的删除信号、独占租约重试、成员历史请求期间关闭，以及 IndexedDB 删除被阻塞后其他工作区仍可用、机器执行拥有者结束后清理、新成员新钥、按范围删 IndexedDB、确认框与终结 UI。新增原生成员管理和清理测试对基线先 RED，再在本实现与 24-A 覆盖下 GREEN。最终受影响测试数量和静态检查记录在 PR。

既发内容 token 按当前寿命自然过期（最多 15 分钟），主动废止 token 和断开已有长连接留作后续。真实钥匙串、Windows ACL/原生 ABI、安装应用重启、两个物理成员/设备、线上云端/gateway token 行为及 M5 执行尚未验收。未合入、部署、采用 gitlink 或发版。
