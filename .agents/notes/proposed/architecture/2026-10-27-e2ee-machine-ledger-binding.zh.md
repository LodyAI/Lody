# 权限账本中的机器身份绑定

Status: proposed
Translation: current

[English](2026-10-27-e2ee-machine-ledger-binding.md)

## 摘要

实时授权需要通过已验证账本确定产品 machineId 与设备签名公钥的关系，机器目录不能提供这份信任。Owner 已批准在账本 v1 冻结前扩展现有机器 AdmitDevice 记录，并在同一条记录里原子替换同一 machineId 的旧钥。替换保留历史身份，并保留 rotationRequired 以提示管理员更新密钥；它不得阻止新内容封装或工作区使用。机器持钥证明覆盖同一严格 UTF-8 ID，跨配对会话复用由现有凭证绑定证明拒绝。实现与独立向量遵循这些已批准的冻结前选择；部署、远端配对和完整换代屏障仍不属于本草稿。

## 已批准的边界

批准设备的记录签名覆盖 machineId、新设备公钥和明确的被替换签名公钥；首次登记则不指定旧钥。不新增操作、能力码或 tag9 声明。同一工作区的一个 machineId 同时至多属于一台有效设备。替换必须指向那台当前机器，machineId、成员实例都相同，沿用现有个人设备接纳与撤销权限。Owner/Admin 身份不能接管其他成员的机器。历史签名钥与加密钥仍永久不可复用。

同一次状态转换移除旧有效设备并登记新设备。全部校验必须在两项修改之前完成。历史保留旧身份；撤销或移除成员只释放有效 machineId 的占用。原子替换设置 rotationRequired，普通接纳不得清除已有提示。Owner 在 2026-10-27 的 MVP 决定保留账本状态和当前格式，但该标记仅作提示：管理员应完成密钥更新，发送继续。本 PR 不增加发送门禁，也不依赖禁止 seal 的行为。通用提示权限规则直接采用 main 已合入的 [#1956](https://github.com/LodyAI/Lody/pull/1956)，不在本 PR 重新实现或增加发送门禁；固定代次交接仍是单独的 PR20-C 责任。

客户端只从真实的已验证账本视图取得 machineId 到公钥的映射。服务端投影仅反映验证结果。创建、追加、恢复继续在一个结算事务中提交投影、凭证和检查点。确定会失败的存储就绪检查也要放在预约/CAS 之前，不能让已成功追加的记录首次在结算时遇到无法完成的策略检查。

## 格式与采用顺序

这是 owner 明确批准的冻结前 tag4 格式修改。旧开发机器记录按 current-only 拒绝，需要重建工作区，不新增旧格式读取或迁移。快照状态、保留状态和状态摘要的格式及用途域当前为版本 4，同时保留已声明 capability。设备表保存历史种类和有效状态，机器表保存每份历史绑定；恢复时重建仅含有效设备的唯一索引。独立 Python/PyNaCl v1 向量已重新生成，覆盖机器接纳与原子替换。Owner 另已批准机器使用自身签名私钥对包含 machineId 的持钥消息签名，验证时从接纳记录重建消息。个人设备的持钥字节不变；CLI 准备阶段须生成新的机器证明。跨会话复用继续由现有 bindingSignature 校验。sessionId 是一次性配对上下文，不加入持钥消息或永久账本记录。回归边界是 possession 与 bindingSignature 的整套配对材料，跨会话复用必须失败；另行验证 machineId 篡改、持钥证明与接纳记录的 machineId 不一致，以及跨工作区复用均被拒绝。个人设备的持钥格式保持逐字节不变。

Owner 批准采用严格 UTF-8 字节串，长度 1–256 字节，不做归一化。编码拒绝孤立 UTF-16 surrogate，不能替换后继续；解码拒绝非法或非规范 UTF-8，保留开头 BOM 作为身份数据。严格 UTF-8 是一一对应，合法字符串的精确比较等同字节比较。本地 socket 只修改机器字段的字节限制，不改变账号和工作区 ID 限制。新机器记录为 `[4,1,签名公钥,加密公钥,持钥签名,machineId字节,被替换公钥或null]`；possess/v2 消息末尾增加同一 machineId 字节。个人和恢复设备记录与证明不变。

服务端部署前必须先采用新公开 core。私有功能分支不能夹带 gitlink 更新；本地组合验证要分别记录 core 候选。采用不兼容 codec 之前，需要处理旧开发工作区及尚未结算的原写入；不得跳过验证、删除未决 writer，或把旧机器静默视为未绑定的新设备。

CLI 指令文件保留全部约束，把解释移到本 Note。Fleet PR poller 有独立于工作区 cloud port 的托管 GitHub 端口，仅关闭后者不能阻止仓库和分支信息外泄。旧 catalog v1 schema 会丢弃 `contentMode`，缓存未知 mode 可能导致离线按明文重开。SQLite 原生恢复可在应用校验前修改物理文件，即使应用最终拒绝该格式。已接受的文件级 clock floor 在时钟错误前跳后，可能跨工作区和重启持续使新请求过期，直到时间追上。这些仍是现有契约；压缩指令不改变产品行为。

## 当前验证

替换回归确认 rotationRequired 仍为 true 时，新设备保留当前写入和 seal 权限，旧钥失去写权限。全量重放、快照和保留状态来源都采用 #1956 的通用规则；原生 CLI 和真实 HTTP 的换代提示覆盖来自该 main 变更，真实安装设备和固定代次交接验收仍独立进行。

core 回归覆盖 UTF-8 边界、BOM、不归一化、证明替换、旧格式拒绝、同成员原子替换、分支隔离、历史钥不可复用、三种视图来源、损坏/重复快照绑定，以及异步签名等待期间的字段捕获。CLI 和 Electron 回归保留原字节、拒绝跨会话材料、保留中断后的 A→B 激活，并比较已验证的机器 ID。后端验证正常/丢失 ACK 的替换结算，在 CAS 前拒绝无效候选；旧凭证保留证据，但在结算后立即失效。

真实 Lab 工作流曾暴露命令复制漏字段：WorkspaceControl 只复制旧字段。现已在等待之前保管 machineId 和被替换公钥，实际 SDK/SQLite 消费链覆盖首次接纳、原子替换及 rotationRequired。组件消费测试同步冻结向量的新位置、head 和有效机器数，endpoint 校验未放宽。jsdom 消费链另验证编码器输出先拥有化到当前 realm，再做原有严格校验；非法 UTF-8、长度与相等限制不变。最终验证数量与候选指纹记录在交付说明中；这些结果不代表真实网关、钥匙串、安装包或产品验收。

原作者的 ACP 锁对齐修复现已进入 main。路径不重叠的 rebase 后，冻结安装通过；本功能未修改依赖声明、锁文件、ACP 源码或 gitlink。Rebase 保留已审查的产品补丁，受影响范围验证与后续 CI 结果记录在 [PR #1940](https://github.com/LodyAI/Lody/pull/1940)。Owner 已授权复用精确树专项与独立审查证据；完整套件交给 CI，已停止的本地整仓检查不计通过。发布 draft 不授权 ready、合入或部署。
