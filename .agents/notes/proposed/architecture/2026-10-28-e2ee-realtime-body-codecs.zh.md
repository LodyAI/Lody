# M5 实时正文候选编解码

Status: proposed
Translation: current

[English](2026-10-28-e2ee-realtime-body-codecs.md)

## 摘要

已有实时加密原语和宿主执行 journal 尚未定义产品请求、响应正文。本次在 RPC 包内实现
请求、响应、错误及 presence 的候选二进制正文，以独立 Python 向量和有界解码验证。
不选择资源编码，不开放产品通道，不写入持久格式。产品采用仍需批准具体格式 revision，
并接通两条路径共用的实际执行入口；测试通过不代表加密 RPC 已可用。

## 责任与候选决定

公开 main `76a4f28e8f22c0b405e57b731fb0a1e49c42d8a3` 已有 content v0 实时用途
原语、账本签名机器绑定和持久执行 journal。
[原语决定](2026-10-26-e2ee-realtime-content-primitives.zh.md) 明确把产品正文留给接线层。
因此纯正文编解码归 RPC 包，不扩大 sealDocument，也不向 core 加入产品 DTO。
本次无生命周期、I/O 或依赖变化，无需 Effect 迁移。普通工作区原有封装和启动不变。

[M5 帧草案](https://github.com/LodyAI/Lody/pull/1894) 提供字段顺序：版本零、固定
16 字节 ID、安全 u64 时间戳、text16 方法／错误码、bytes32 方法内容，以及响应的
摘要／类型／u32 序号。响应分为进度、最终成功、最终错误；错误内容还须通过嵌套
code/detail 编解码。参数、结果和错误 detail 是原样字节，归经授权的方法 codec
校验，不做 JSON 归一化。

候选上限把 1 MiB 解释为**完整加密 RPC 帧**，为现有 content v0 留出 143 字节。
这比草案表格中的“明文 1 MiB”更严格，须在 PR-25S 对齐。Presence 保留草案的
64 KiB 正文上限和最多 60 秒的正 TTL。编码与解码都拒绝非法大小、版本、整数、
类型和文本。复制前按剩余有界视图检查声明长度；返回字节独立持有内存，包括输入是
带偏移的 Node Buffer 时。错误诊断不含输入值。

严格二进制解析保留候选签名字节，并在方法派发前拒绝歧义；宽松 JSON 外壳不适合
这个责任。若直接降低 core 通用内容上限，会误伤文档内容，因此只在这里限制候选实时帧。

## M5 剩余工作与独立交付

```text
方法 DTO 字节 -> 正文 codec -> 已有用途 8/9 加密
             -> 保留原帧 -> 加密 Streams（iroh 后置）
             -> 验证权限 -> 共用实际启动 claim
Meta/history ------------> 同一业务意图与 claim
```

- PR-25：本次只完成正文切片。已有加密向量覆盖用途／上下文／签名者隔离，目标授权
  仍归接线。
- PR-25S 可独立修正与评审草案：删除无 machineId 的旧机器记录及 rotationRequired
  阻断发送／执行的旧说法；当前记录必须绑定 machineId，换代提示不阻塞内容。更新旧
  代码审计，保留持久回退。延迟目标已更新为比普通派发慢最多 1 秒，替代旧计划的 200ms。
- PR-26a：将已有 journal 接到真正 agent-start 入口和持久 Meta/history 路径，绑定
  同一 userTurnId／业务意图；执行前由机器经认证读最新账本，仅内存缓存，最多从读取
  开始算 15 分钟，重启不恢复、不信请求方时钟。只在接收层去重或保存投递 ACK 不够。
- PR-26b：依赖合入 main 后采用，完成发送原件保存、加密 Streams 控制／派发和持久
  回退；结果未知时查询，不重放。PR-27 随后接文件／history 等查询，按读权限检查；
  PR-28 presence 可以并行。
- PR-26c 后置加速：可信原生宿主内复用工作区设备 Ed25519 身份，审查签名域隔离；
  建连不拖慢可用的 Streams。不新增 renderer 私钥导出或任意签名接口。

各实现从 main 分支，避免深 PR 栈。草案修正期间，执行／新鲜度、presence、原生
可行性可独立推进。私有服务改动与采用单独交付；本次不修改后端或 gitlink。

产品采用前，owner 须批准具体字节与上限解释。草案的 machineId 仅限 1–128 字节
可打印 ASCII，与账本的 1–256 字节严格 UTF-8 冲突；推荐对原始 UTF-8 字节确定一种
无损、唯一的 ASCII 资源编码。本模块刻意不提供 scope helper。本次不回退、迁移或
写入任何格式。

## 证据与限制

`tests/fixtures/generate-e2ee-wire.py` 用独立的 Python struct/hashlib 生成合成固定
向量。所属测试覆盖原字节、全部向量截断、多余字节、未知版本／类型、超长／伪造长度、
整数／文本／身份边界、完整帧大小、presence TTL 和内存所有权。临时多允许一字节后，
完整帧边界测试失败；恢复后 24 个 codec 测试通过。RPC 包 181 个测试通过，3 个真实
网关集成用例跳过；core 已有实时测试 19 个通过。受影响包类型检查、类型感知 lint、
公开边界、格式及文档检查通过。本次按受影响范围检查，未运行根目录全量 check。

本次没有认证传输、发送 outbox、机器新鲜度缓存、派发 claim、结果查询、真实网关、
原生 iroh、打包平台、canary 或延迟验收。本 Note 和帧 Spec 仍为提案，测试结果不批准它们。
