# Plugin system implementation design and stacked PR plan

Status: proposed
Translation: current

[简体中文](2026-11-23-plugin-system-implementation-design.zh.md)

## Abstract

This note translates the normative [Lody Plugin System Spec](../../../../specs/plugin-system.md) and the boundary rationale in [Plugin architecture convergence and E2EE workspace boundaries](2026-11-22-plugin-architecture-and-e2ee-boundaries.md) into a concrete repository implementation blueprint across `@lody/plugin-sdk`, `@lody/shared`, `apps/cli`, `@lody/components`, `apps/electron`, and `apps/mobile-capacitor`. Every daemon-side OS subprocess (`PluginHost` and `DevPluginCompiler`) routes exclusively through the single Effect process boundary in [`packages/shared/src/node/process.ts`](../../../../packages/shared/src/node/process.ts) under native Effect v4 (`4.0.2`) `Scope` ownership, while client rendering, raw snapshot reads, and E2EE signing reuse existing `ai-gui`, `sidebar-surface`, `vscode-theme`, Loro/Flock, `sessionData`/Roost, and `e2ee-execution-intent` owners with zero parallel stores. Delivery splits into four dependency-ordered stacked pull requests (`PR-1` through `PR-4`), each shippable and testable on its own with explicit temporary legacy-facade deletion rules. No production runtime code is shipped in this note; all four PR slices remain unimplemented pending execution.

## 2. Native Effect v4 lifecycle & failure-containment contract

Per [`packages/shared/src/node/AGENTS.md`](../../../../packages/shared/src/node/AGENTS.md) and [`scripts/check-cli-process-boundary.mjs`](../../../../scripts/check-cli-process-boundary.mjs), `apps/cli` MUST NOT import `node:child_process` or call `process.kill` / `child.kill` directly. Instead, `NodeProcessApi` in [`packages/shared/src/node/process.ts`](../../../../packages/shared/src/node/process.ts) gains `spawnIpcChild` (modeled identically in `process-testing.ts`), returning a scoped Effect handle `{ pid, send, messages: Stream<unknown, ProcessIpcError>, exit, ringBuffer }` whose `Scope` finalizer runs `ipc shutdown frame -> bounded grace wait -> terminateTree (SIGTERM -> waitUntilGone -> SIGKILL -> zombie-excluded OS table check)`.

`PluginHost` and `DevPluginCompiler` are authored as native Effect `4.0.2` services (`Context.Service`, `Layer.effect`, `Effect.fn`, `Schema.TaggedError`, `PubSub`, `Deferred`, `Ref`, `Clock`) satisfying the six questions in [`cli-effect-ts.md#behavior-contract`](../../../docs/cli-effect-ts.md) and the blast-radius invariants in [`failure-containment.md`](../../../docs/failure-containment.md):

| Contract Dimension                       | `PluginHost` (`apps/cli/src/plugins/workflow/plugin-host.ts`)                                                                                                                                                                                                                                                                                                                                                                  | `DevPluginCompiler` (`apps/cli/src/plugins/workflow/dev-plugin-compiler.ts`)                                                                                                                                                                                                          |
| ---------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **1. Trigger**                           | Daemon startup (for enabled `machine` plugins unless `--safe-mode`), explicit CLI/RPC `enable` / `reload` / `disable` / `remove`, or watcher-triggered `--dev` rebuild completion.                                                                                                                                                                                                                                             | Explicit `lody plugin link --dev`, `pack`, or debounced (`150 ms`) source file change under watched plugin directories.                                                                                                                                                               |
| **2. Owner & FIFO Serialization**        | Daemon root `Scope` owns `PluginHost`; each running `machine` plugin owns a child `Scope.Closeable`. Because Effect `4.0.2` `Semaphore` does not preserve FIFO on immediate reacquisition, per-`pluginId` lifecycle transitions use an **owned `Ref`/`Deferred` FIFO turn queue** that coalesces redundant pending `--dev` `reload` requests to the latest trailing build while keeping `disable` / `remove` strictly ordered. | `PluginHost` child `Scope` owns an on-demand compiler worker lease. A `Clock`-backed idle timer (`1000 ms`, deterministic under `TestClock`) closes the compiler `Scope` when no build is queued or running, dropping resident compiler memory to `0 B`.                              |
| **3. Cancellation & Bounded Teardown**   | Closing a plugin `Scope` aborts its host `AbortController`, sends `{ type: "lifecycle/shutdown" }` (`2000 ms` grace via `Clock`), and delegates escalation to `process.ts` `terminateTree` (`2000 ms` `SIGTERM` -> `SIGKILL` -> `waitUntilGone`). Daemon shutdown bounds total plugin teardown so uncooperative children never hang exit.                                                                                      | Canceling or superseding a `--dev` build interrupts the in-flight compile fiber; if the `esbuild` subprocess stops responding, closing its `Scope` reaps the tree via `terminateTree`.                                                                                                |
| **4. Handoff & Drain-Before-Respawn**    | Replacement **never** spawns a new OS PID while the prior instance is still alive. If `Scope.close` surfaces `ProcessReleaseFailed` carrying an unresolved recovery lease, `PluginHost` retains that lease in the per-`pluginId` state slot and blocks any successor `enable` / `reload` on `lease.retryTermination` until `waitUntilGone` succeeds, preventing concurrent writes to `ctx.dataDir`.                            | A newly compiled bundle writes to a staging directory and atomically swaps `current` metadata + monotonic `instanceId` / `clientDigest` only after compile succeeds; compile errors preserve the prior running `instanceId` and publish structured diagnostics to `Plugin Inspector`. |
| **5. Failure Recovery (`0` Auto-Retry)** | Startup handshake timeout (`5000 ms`), uncaught child exit, or per-call timeout (`15_000 ms` query/mutate, `60_000 ms` tool, `5000 ms` event) transitions the plugin to `Faulted` with **`0` automatic retries** and **never caches a failed startup fiber**. In-flight `mutation` / `tool` calls settle with `PluginCallError { code: "outcome_unknown" }`; in-flight `query` calls fail fast without re-dispatch.            | Compiler crash or syntax/bundle error fails the single build attempt with structured location diagnostics; the file watcher stays alive in the daemon so saving a fix triggers the next build cleanly.                                                                                |
| **6. Containment**                       | Client-only, theme, skill-only, and `sound-effects` plugins spawn `0` subprocesses. A crash, infinite CPU loop, or `--max-old-space-size=256` V8 OOM in plugin `A` affects only `A`'s PID, leaving the daemon, ACP sessions, and plugin `B` untouched.                                                                                                                                                                         | `esbuild` runs out-of-daemon in `DevPluginCompiler`'s child process; native bundler panics or OOMs never touch the daemon heap.                                                                                                                                                       |

## 3. Data plane, UI mount stability, bundle streaming & E2EE gate wiring

### 3.1 Zero-parallel-store `lodyQueries` & lazy raw snapshots

- **Typed queries (`lodyQueries`):** `ClientPluginHost` and `PluginHost` resolve all 18 typed query descriptors directly against existing workspace Loro/Flock room readers and [`packages/shared/src/session-data`](../../../../packages/shared/src/session-data/AGENTS.md) / Roost narrow query indices (including incremental `sessionIds`, `agentRoleId`, and `updatedAfter` filters on `sessions`, plus `userTurnId` / `stopReason` on `sessionTurns`). No second in-memory Domain Store is introduced.
- **Lazy detached snapshots (`useLodySnapshot` / `readSnapshot`):** Subscriptions attach ref-counted listeners to the underlying Loro room or active `sessionData` projection and invalidate lazily; a detached `structuredClone` + recursive `Object.freeze` projection is materialized **only when a mounted hook or `readSnapshot` caller reads a dirty revision**, redacting secret fields and foreign plugin `businessKey` entries before returning.
- **Restart reconciliation (`machine.onStart`):** After all enabled `machine` plugins complete their IPC registration handshake on daemon startup, `PluginHost` invokes `onStart(ctx)` once per plugin before opening live `machine.events` delivery, pairing `ctx.dataDir` journal recovery with `lodyQueries.sessions({ updatedAfter })` + `sessionTurns` reconciliation and `SessionCreationReceiptStore` (`24 h` TTL SQLite/JSON ledger keyed by `(plugin_id, idempotencyKey)`) so missed turns recover idempotently with original `ProjectRef` and `parentSession`.

### 3.2 Client UI integration & `MessageBlockRenderProps.blockId` stability

- **ESM module loading & `Trusted Dev Session`:** `ClientPluginHost` reconciles `plugin/catalog` entries by `(pluginId, clientDigest)`. `DevPluginCompiler` bundles `client.tsx` as browser ESM with `react`, `react/jsx-runtime`, `zod`, `@lody/ui`, and `@lody/plugin-sdk/*` externalized onto a host-frozen module map. On remote Web/Desktop connections, release plugins require one-time user trust per `(workspace_id, machine_id, plugin_id, clientDigest)`, whereas `devMode: true` plugins expose an explicit **"Trust Dev Session"** toggle storing `(workspace_id, machine_id, plugin_id, devSessionNonce)` in ephemeral tab memory / `sessionStorage` (showing a persistent **"Dev Session Active · Revoke"** badge and immediately invalidating on `devSessionNonce` rotation or manifest capability escalation).
- **Stateful `messages.renderBlock` & universal `tools.matchRender`:** [`markdown-renderer.tsx`](../../../../packages/components/src/components/ai-gui/markdown-renderer.tsx) assigns each fenced code block its deterministic turn-scoped `blockId = "${turnId}:block:${ordinal}"` and renders `PluginMessageBlockSurface` keyed by `${sessionId}:${blockId}:${winner.pluginId}:${winner.id}`. Streaming token appends and fence closure update `code` and `streaming` props **in place** without unmounting the component instance, preserving interactive form/zoom/selection state while bypassing `useSessionSearchBlock` per [`ai-gui/AGENTS.md`](../../../../packages/components/src/components/ai-gui/AGENTS.md). Both `PluginMessageBlockSurface` and `PluginToolCallSurface` (wrapping [`tool-call-detail.tsx`](../../../../packages/components/src/components/ai-gui/tool-call-detail.tsx)) render a non-spoofable host header toggle (`"View Raw Markdown"` / `"View Raw Output"`) and `SurfaceErrorBoundary` fallback.
- **Three-layer `sidebar` & two-tier `themes` / `styles`:** [`loro-app-sidebar.tsx`](../../../../packages/components/src/components/loro-app-sidebar.tsx) composes `sidebar.sections`, `sidebar.panels`, and single-winner `sidebar.replace` over [`sidebar-surface.ts`](../../../../packages/components/src/components/sidebar-surface.ts) while retaining a persistent host chrome escape button when replaced; `themes` feed [`vscode-theme-dom.ts`](../../../../packages/components/src/lib/vscode-theme/vscode-theme-dom.ts) and `styles` mount `<style data-lody-plugin="<plugin_id>">` nodes removed atomically on disable/unload.

### 3.3 Five E2EE runtime gates

1. **Non-Guest execution gate:** In [`packages/shared/src/e2ee-rpc.ts`](../../../../packages/shared/src/e2ee-rpc.ts), `isE2eeFeatureMethod` adds `method.startsWith('plugin/')`, while `E2EE_READ_QUERY_METHODS` remains unchanged so `plugin/query`, `plugin/mutate`, and `plugin/attachment-*` enforce non-Guest `authorizeExecution` (`< 15 min` ledger freshness).
2. **Owner vs `MachineSharing` scope gate:** Daemon RPC dispatch consults [`@lody/e2ee-machine-sharing`](../../../../packages/e2ee-machine-sharing/AGENTS.md): `machine`-scoped handlers, plugin install/enable/reload/config writes, `devSessionNonce`, and `acpProviders` require machine-owner identity; collaborators may call `project` / `session` handlers only when `MachineSharing` grants both the machine and every referenced project.
3. **`SignedTurnOrigin` & `e2eeIntent` derivation:** Client `sessions.create` / `send` / `respondInteraction` sign `E2EE_INTENT_KIND.memberInput` (`1`) via [`e2ee-execution-intent.ts`](../../../../packages/shared/src/e2ee-execution-intent.ts). On the daemon, `ToolExecutionContext`, `MachineEventContext`, and `MachineStartupContext` verify `originTurn: { session, userTurnId }` directly against the stored human-signed `memberInput` record in local `sessionData` (enforcing the 20-hop derivation cap and single-machine binding) before signing `E2EE_INTENT_KIND.machineInput` (`2`); un-rooted query/mutation handlers have no signing authority and fail closed with `forbidden`.
4. **Iroh frame sizing:** `plugin/query` and `plugin/mutate` cap serialized payloads at `256 KiB` to fit one `1 MiB` `purpose 8` frame; `plugin/bundle-chunk` streams `<= 4 MiB` packed client bundles in `256 KiB` `purpose 9` pages and verifies full SHA-256 against `clientDigest` before custody caching or `import()`.
5. **Custody directory binding & static share fallback:** Daemon `ctx.dataDir` and client remote bundle caches live under `<account>/<workspace>/<genesis>/<signing-key>/plugins/` and register on the existing E2EE revocation/wipe hook; static plaintext share viewers disable `ClientPluginHost` bundle execution and render built-in raw fallbacks.
