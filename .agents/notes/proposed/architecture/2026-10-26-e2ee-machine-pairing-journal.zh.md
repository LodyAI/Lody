# 机器配对原件与前端接纳验证

Status: proposed
Translation: current

[English](2026-10-26-e2ee-machine-pairing-journal.md)

## 摘要

原机器准备流程在重试时重新生成公共证明，激活只检查机器公钥，没有记住批准它的个人前端。现有同用户本机 socket 现在把宿主前端公钥和配对会话传到准备与激活。受 Scope 管理的本地日志保存准确上下文、证明及接纳记录，接收器安装密钥前由 core 认证完整原始账本。这只是远端配对的宿主准备，不是远端命令或凭证协议；未来命令的独立认证、机器服务身份与位置规则仍未解决。

## 职责与生命周期

`pairing-journal.ts` 是原生 Effect 所有者，直接由 `prepareCliE2eeMachineLegacy`、`workspace-legacy.ts` 的激活与现有运行实例路径使用。独立 SQLite 互斥库保护单工作区的签名及持久读回，持锁期间不做网络操作。Scope 等已进入的原生准备结束后关闭数据库和保管资源。公共证明离开宿主前先保存准确上下文与原件。中断或结果未知不删除原件；没有假设前端尚未签名的取消或退休入口。

信任来源是 `e2ee-local-pairing.mts`：Electron 主进程通过现有同系统用户 socket 传自己的签名公钥。将来远端接口仅传入 expected 字段不等于独立认证。prepare/activate 严格要求前端公钥，activate 还要求原会话，半升级明确拒绝。core 既有持钥证明与凭证绑定签名格式不变。

激活从日志读回账号、机器、工作区、创世、成员、前端、会话、机器双公钥和凭证哈希。以运行实例已验证的终点重新核验完整原件，找到与实际签署前端所保留准备原件匹配的机器接纳，比较已保存接纳字节，并检查当前成员与设备。如果原前端在入账后、首次激活前中断，另一台当前有效、同成员的个人前端可沿现有同用户 socket 继续。当前会话、机器公钥与凭证保持固定，原接纳签署者和字节不变。原准备必须匹配账号、机器、工作区、创世、成员、机器双公钥、凭证哈希及持钥证明；当前前端必须是有效的同成员个人设备，只有最新已准备会话可以激活。即使机器已入账，新前端会话仍须用户明确确认；同一已确认会话可复用同意重试。这不构成可转移的远端认证证明。通过后才允许接收信封、安装钥匙和写激活标记。仅等待配对的实例只能读取账本，不能收钥。全局账本推进和个人配对成功分开：错误前端不能安装钥匙或写激活标记，但合法控制记录可以被验证保存。

Fleet 只有完整意图相同才共享在途激活；不同意图返回冲突。本地日志核验先于资源所有权变化。相同身份的健康实例用自身真实证据执行同一验证，再刷新；失败重试保留该实例。确实不同的身份仍须先等旧实例释放。全局账号锁内不等网络。

## 原件与恢复

同会话重试必须打开原机器与凭证。凭证缺失、保管损坏、权限错误或上下文变化不能生成替代品。保留 M2 已有恢复：可信本机前端发起全新会话，严格确认机器原件缺失后可准备新候选，再经新的明确审批和真实接纳、收钥后激活。旧日志与按签名公钥分开的运行证据保留。后续会话跟随当前受保护身份，不重新钉回最早证明。生成替代原件前先持久固定准备阶段归属；设备/凭证写入、签名或公共材料发布中断后，原会话可继续同一 core 原件；相同账号、机器、工作区、创世字节和成员的新可信会话也可接管尚未发布的准备阶段，前端与会话编号可改变。同一事务把旧行的 `creating` 整数标为 `-1`（已被接管），把新行标为 `1`，不改上下文、材料、接纳记录、密钥或凭证。沿用版本 3，不增加迁移。后继会话继承未完成阶段，不拿替代原件与更早已发布的身份比较。旧会话在保管访问前和材料发布前均被拒绝，包括同一宿主内晚完成的签名，不能重新抢回或覆盖当前身份；跨进程仍由 SQLite 互斥库排他。已发布材料不参与接管。已完成旧行保持原样。当前身份指针与材料在同一事务发布，不按会话行首次插入顺序猜测；指针发布失败不留下半完成材料。未发布的早期实验数据库版本保留原件并明确拒绝，不推断迁移。仍绑定旧公钥的凭证会在生成新设备前明确拒绝，不删除或覆盖来强行恢复。原件检查沿用 core node-custody 当前的 `${genesis}.machine.device` 和 `device-credential-${genesis}.sealed` 路径，恢复回归固定这些接入假设。

没有采用“每次返回新证明”（会丢原件）、“已有密钥就代表预期前端批准”（会话可被冒用）、“先停所有健康实例再验证”（确认回包丢失后的失败重试会断开健康工作区）。不新增密码算法、签名用途、token 权限或机器共享规则。

## 验证与限制

合成真实密码学/存储回归覆盖首次及替代准备阶段接管、同范围检查、接管事务回滚、接管后晚到签名、跨进程互斥、收到保管已保存的明确 IPC 信号后进程退出，以及准确重试、上下文替换、凭证与机器原件缺失、新会话恢复、凭证写前/后与签名及 SQLite 材料发布故障后重开原生 Scope、局部保管丢失不创建新设备、错误激活目标、另一同成员前端继续首次激活且保留机器钥和凭证、其他成员或已撤销前端及晚到旧会话拒绝、新会话明确确认、接纳原件写入失败后下一正常调用恢复、已存接纳损坏、67 条账本跨页检查点、半升级拒绝、准确意图并发及健康实例恢复。交接另附实际测试与构建结果。真实钥匙串、远端传输、一次性凭证签发/取消、位置查询、部署及 M5 执行不在本次范围。不能复用会升级为长期账号 API key 的旧配对兑换流程。

CLI 上下文将机器配对放在独立段，便于与尚未接产品的 M5 journal 说明组合。这只调整文档位置：机器准备／激活不认证实时请求，journal 不授予执行权限，两者均不提供尚未交付的统一 epoch／新鲜度屏障。

同系统用户的控制通道只对精确匹配原 context、且 generation 为 -1 的请求返回 `prepare-superseded`。主进程先核对机器、会话、当前账号和读取者，再在事务里归档三项原件均为空的桌面未签申请。用户下一次点击重试才准备新会话，仍须明确批准。普通错误、超时、会话变化、已暂存材料或已签名的申请不重置；归档失败保留原回执与清理原因，下次可重试。CLI 保留旧 context 和全部原件。真实 A/B/A 宿主和严格 socket 回归覆盖 B 只准备后失联、归档回滚、迟到回执与已签状态拒绝。
