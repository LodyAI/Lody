# 对话结束后再归档

Status: proposed
Translation: current

[English](2026-10-12-session-archive-after-settlement.md)

上游：[LodyAI/Lody#1521](https://github.com/LodyAI/Lody/issues/1521)。

## 摘要

原归档立即写入 `isArchived`，守护进程随后终止运行中的工作。等待工作树清理不等于等待对话结束。本次实现分离持久化归档意图与已归档状态，等待整个组及排队工作、输出收尾完成。手动确认保留直接归档，PR 自动归档始终等待。行为测试通过，但工具和公开 ACP 子模块缺失阻碍完整仓库验证，本记录在验证和评审完成前保留 proposed。

## 实现与决定

所有手动入口统一使用取消、直接归档、完成后归档弹窗，合并原侧栏二次点击和快捷键确认。统一确认避免将无法获取的运行状态视为空闲。批量归档记录去重目标并集。接受等待请求保留页面；直接归档保留取消待发送项、释放运行时及关闭终端。

拥有者守护进程运行 `SessionArchiveCoordinator`。目标确认就绪后，准备阶段获取现有 rewrite barrier，再次检查工作并发布带代次的确认。根拥有者持久化可恢复提交决定，各目标拥有者写入 `isArchived`，复用原运行时释放和工作树 GC。独立取消请求 ID 墓碑抵御过期请求对象写回。提交前发现的新后代加入请求并重新准备。离线拥有者不能证明空闲，参与机器必须声明 `deferredSessionArchive` 能力。

就绪检查覆盖运行和创建、dispatch 请求、输出和用量持久化、全部后端队列项、共享 pending activation 判定、活动 Goal 和已知本地待发送项。仅对明确目标复用持久化 Goal 查询，不扫描历史文档发现候选。待发送 ID 仅在交付或明确取消后移除。固定版本图标库没有合适的待归档图标，因此绘制静态 Lucide 风格归档箱加时钟，独立显示在 Working/Waiting 旁，提供取消和直接归档覆盖操作。Story 渲染真实图标与弹窗，文案中英双语。

PR 自动归档保留启动/恢复基线、拥有者/能力/设置限制，并以有上限的退避重试写入。PR URL/状态证据变化时取消请求。CLI 归档默认等待，支持 `--immediate` / `--cancel-pending`；MCP 提供 wait / immediate / cancel，即使目标是当前自身对话也立即返回。

## 替代方案与限制

仅在界面等待无法应对窗口关闭。idle 不是结束证据，收尾和晋升可能仍在继续。不支持的守护进程不会静默降级为中断式归档。

元数据写入可恢复，但不是跨离线副本事务。组屏障覆盖已知同步目标；未知离线输入和提交后新建后代不在原子成员保证内。各拥有者写入归档前再次检查迟到工作，允许迟到 activation 先完成。附件准备期间失去界面会保留未解决的已知 blocker，需要取消请求，不能推断已完成。阻塞队列项需完成或明确移除。发布准备屏障后，发送入口拒绝新输入。本地项目移除保留独立的直接归档行为；工作树保留和清理策略不变。

现有关系和工作树生命周期 Spec 保持 draft，补充准入边界。未创建新 Spec。实现 PR：[LodyAI/Lody#1522](https://github.com/LodyAI/Lody/pull/1522)。

## 验证

协调器测试覆盖整组等待、全部队列状态、晋升/收尾空档、活动 Goal/未知元数据、附件 blocker 跨重启、离线拥有者、屏障后二次检查、取消墓碑、新后代、PR 失效和部分提交恢复。界面测试覆盖真实弹窗按钮、确认前不写入、直接归档、持久化等待/取消和既有侧栏行为。共享类型及翻译键检查通过。组件/CLI 类型检查仍受缺失依赖影响。`pnpm check` 因缺少 corepack 停止；边界/文档检查报告缺少公开 ACP 子模块。这些是验证限制，不代表完整检查通过。

最终定向验证：5 个测试集共 112 项通过。Chromium 验证了真实弹窗在桌面和 375px 窄屏的布局及直接归档选择。改动文件 lint/格式、翻译键、平台边界及 CLI 进程边界检查通过。恢复操作先撤销部分归档请求，避免再次归档。文档检查仅报告 82 个既有 ACP 子模块链接缺失，没有新增文档错误。
