# Roost 按位置索引分页

## 摘要

Lody 原来的按位置读取会从头部向后解析中间历史；上一轮读取 1,000 条历史中
最旧 20 条需要 885 ms。本地试验在现有已认证派生索引里增加不含正文的位置映射，
只读取所选消息的物理片段。每格两个新进程样本中，万条前缀的最旧页中位数从
8,320 降到 10.3 ms，读页后的进程 RSS 从 590 降到 445 MiB。
所属行为测试通过；同目录六轮写入交叉对照没有复现之前的 CPU 增幅。
当前仍是本地提案，尚未合入或部署。

## 范围与决策

本实验承接[Native 发布边界](2026-10-23-roost-native-publication-boundary.zh.md)，
沿用[固定验证流程](../../../docs/roost-validation.md)。范围仅为 Lody 本地派生索引
及读取器。Loro 对照、Roost 正文格式、seal、wire 和持久化设置保持固定。不打开、
迁移或删除生产数据；本地实验不授权部署或发布。

现有 dispatch 行已保存逻辑位置、业务身份及有序物理片段引用。在同一投影增加
“位置到业务 ID”的键，复用已有原子 puts/checkpoint 边界。新 checkpoint 版本认证
这些键已完整，不保留旧 checkpoint reader。重建与其他投影表一同清理、恢复位置表，
完成后才发布标记。

普通文字追加不重写位置映射；新增成员增加短映射，分支替换沿用既有 generation
生命周期。索引开销以 SQLite 页分配和创建/结束耗时实测，不根据载荷大小推算。

## 读取与失败合同

仅在 checkpoint 完整且匹配权威游标和数量时使用位置索引。批量读取位置和行，
校验身份及位置，再按顺序加载全部物理片段，遵守 SDK 请求上限。返回或缓存正文前
重查 marker、事件游标和历史 generation；仅修改索引的 generation 替换未必推进
事件游标。复用既有有界正文缓存，不把旧正文装进最新窗口或另建无界历史副本。

投影缺失或损坏不代表历史变短。范围查询保留现有有界分页，不要求部分副本拉齐
全部历史，也不调用 dispatch 的完整索引重建。已有 dispatch 修复仍由原写队列拥有。
过期观察沿用有限重试预算；存储和数据不完整错误只影响被等待的读取，不退出共享
owner，也不改变写入成功语义。

既有 Effect 投影并发许可及归属保持不变。完整迁移会将周围 Promise/SDK owner 链
引入本次读取优化，因此暂缓；不改变 Effect 依赖或迁移台账事实。

## 验证计划

扩展既有真实 Native suites，覆盖无需加载沿途历史页的冷范围读取、后继片段、
generation/游标/索引竞争、位置行缺失或损坏、重建中断、分支替换和部分副本/缺索引
行为。竞争使用显式注入，不使用时间 sleep。

基线和候选使用独立 clone、相同已构建 SDK/Native 及固定的 Loro 源码。保留既有
durable 业务输入，测新进程重开/分页、追加 CPU 与延迟、创建/结束、逻辑数据库增长、
WAL 及 RSS 轨迹；另比较百条、千条、万条已准备历史的位置读取。保持资源上限，
保留失败阶段，不把性能断言放进普通 CI。

## 结果与验收边界

实现已在本地完成，决策仍为 **proposed**。本单元已开 Draft #1845，叠加在前置 Native 提交优化 #1839 之后，尚未合入、部署或用于清理现有数据。运行时代码只改 Lody；依赖前面的共享正文与 Native 提交结果栈，
但本单元没有新增 Roost SDK、Native、正文格式或线协议变更。
单靠已发布的 npm 0.2.0 不能验证前置栈。

相同 checkpoint 下的位置映射消除了随历史长度增长的正文遍历。它没有使用有损摘要、
改变 seal 或信任未校验缓存。完整索引不可用时仍走现有分页读取。
没有增加旧正文格式读取器或迁移。早于 version 2 的位置 checkpoint 不受认证；
现有 dispatch 修复会重建派生索引，不删除权威历史。

### 固定前缀读页

每个后端、每个前缀取 **两个**新进程样本的中位数，并明确列出最旧页的范围。
各进程先打开最新窗口，再依次读取最旧、中部、四分之一位置的 20 条消息。
后两个位置可能被首次读取预热，因此原始 `coldMs` 只表示该位置第一次调用，
不代表相互独立的冷历史读取。例如 100 条前缀的基线中部已经命中缓存（0.59 ms），
而候选首次读中部为 22.54 ms。两边后续读取都会缓存。

Roost 种子还显式准备了完整派生索引。这种最终消息导入没有重放流式编辑历史，
也不能证明两者批量导入代价相同。

### 混合写入差异的隔离

首次独立目录对照中候选混合写入偏慢。每边增加四次纯写入，保留全部样本后，
六轮追加 CPU 中位数为 1.058 → 1.172 s（+10.8%），p95 为
1.535 → 1.844 ms（+0.310 ms）。没有删除样本或直接把差异定性为噪声。

单独加计数的诊断显示，1,000 次追加内的工作完全相同：1,000 次 Native `writeBatch`、
60 次 `indexRead`、1,000 次 dispatch 计划、零条 dispatch 行变更、零次行查找。
索引计划总耗时分别为 3.25 / 2.98 ms。该负载只有 20 条逻辑消息，全部位于 40 条
窗口内，没有进入新索引正文读取路径。诊断耗时不计入性能表。

进一步在**同一工作目录、同一依赖**下进行每边六轮 A–B–B–A 交叉对照，
每次使用新进程和新库，只替换两份运行时代码，最后在 `finally` 恢复。
两边的内容、重试和 SQLite 检查都通过。追加 CPU 为 0.955 → 0.946 s，
p50 为 0.515 → 0.530 ms，p95 为 1.357 → 1.341 ms，累计追加墙钟时间为
684.7 → 708.5 ms。RSS 为 528.3（+201.5）→ 526.1（+198.7）MiB。
原来的增长没有在这组对照稳定复现，因此不能认定已证实结构性写入回退，
也不等于证明所有机器都零回退。没有为追逐样本修改写入或降低持久化保证。
暂不合入。

### 正确性与复现

四个所属真实 Native 测试套件共 **134 项通过**。新增覆盖重开后与全量参考一致的
所选正文、封存后恢复的状态覆盖层、读取期间远端状态变化、不推进事件游标的纯索引
世代切换、缺失/错位/未认证映射、局部副本缺失边界，以及中断重建。
返回对象仍与内部缓存隔离。

另一次有意删除最终世代检查的消融运行中，竞争测试返回旧分支并失败；随后逐字节恢复
该检查。中断重建新增断言曾把内存缓存 checkpoint 当成无缓存读取，修正后先断言
range 拒绝旧缓存标记，再清掉缓存检查不完整标记；没有为了错误断言修改运行时语义。

主矩阵共完成 **99 个阶段、165 次关闭后 SQLite 检查**，测量阶段没有失败。
另有八次独立目录混合写入、十二次同目录混合写入，以及两次计数诊断。
