# Lody Automations：受限条件与持久 Session 动作

Date: 2026-10-25
Updated: 2026-10-27
Status: proposed
Translation: current

[English](2026-10-25-session-automation-coordinator.md)

## 摘要

Lody 需要在 Agent 闲置、额度不足或退出后保留已受托工作。Automations 由本地 Workspace
Owner 持久化条件与动作回执，每次 Session 注册在接受时固定继续会话的目标。外部 JS
通过受限 `ctx` 观察组合条件，事件到动作的策略、授权、调度与恢复归 Lody 内部代码。
Session/Inbox 继续拥有资源执行。实现以合成来源、解释器、队列与执行链验证为依据，
不声称验证过真实 Provider 缓存/额度或所有平台的打包行为。

## 架构与替代方案

输入依据是 EDA-001 v2 RFC，其 API 示例表达语义而非强制命名。调用面明确为可编程
等待条件与内部动作策略，不公开业务条件枚举、授权图、Handler DSL 或通用命令执行器。
Session 注册后可以退出；`false` 继续等待，`{resumeText, payload?}` 请求一次同 Session
继续。Workspace 是运行时与存储 Owner，不是事后推断的继续目标。

[模块指南](../../../../apps/cli/src/automations/README.md) 统一维护 API 与实现导航。
公开等待入口、原生 Session 设置与内部事件/动作契约分离。内部规则保留显式的
Session/Project/Workspace 作用域和冻结身份，程序不能扩大注册 Session 的权限或换目标。

| 替代方案             | 判断及依据                                                                      |
| -------------------- | ------------------------------------------------------------------------------- |
| 不修改               | 现有 Schedules 无法在 Agent 退出后保留任意条件、原生未完成工作身份与准入证据    |
| 替换 Schedules       | 不采用；重复任务的时区、错过时刻与重叠行为已有 Owner                            |
| 公开动作图或业务 DSL | 不采用；调用者需要 JS 条件，继续/归档/压缩策略由 Lody 决定                      |
| 默认 shell 执行      | 删除；进程隔离不能限制 daemon 凭证、文件与网络权限                              |
| 新建执行/队列 Owner  | 不采用；复用 Session 准入、Inbox、队列提升、Stop 与释放证明                     |
| 独立 Timer 调度器    | 无需；已接受回执保存 `notBefore`，等待保存下次检查/过期时间，现有运行时负责唤醒 |

真实缺口是私有持久账本、有界 JS 解释器与读取桥、来源证据及现有 Owner 的协调。
这些能力不替换业务资源的所有权，Cradle POC 也不是 API 或信任边界的依据。

## Agent 渐进式说明

调用方不应猜测 `ctx` 的方法，也不应反复查阅独立手册。内置 Lody MCP Server 通过
Skills 扩展发布 Automations 技能的 frontmatter 和完整文件清单。MCP Host 调用
`skills/list` 发现条目，将名称和描述放入原生技能目录，再由技能加载路径校验并激活
通过 `resources/read` 获取的内容。普通资源读取本身不等于激活技能，产品自定义的
发现或读取工具也不能替代这条集成路径。

技能入口指向独立的观察与设置参考。命令与参数 schema 来自执行时使用的 Zod 契约，
CI 示例复用已有可执行示例。生产和开发产物都内嵌文本；技能包不授予执行权限，未知
URI 不会转化为文件或网络读取。

ACP 通过既有 `mcpServers` 传递连接配置。发现、校验和激活由 Agent 的 MCP Host
按标准 Skills 扩展负责。协议不要求私有 ACP 能力、目录缓存、原生插件注入或面向模型
的读取工具；将这些机制放入 ACP 启动链会让 Lody 多拥有一条消费路径，因此删除这层
桥接。[MCP 指南](../../../../apps/cli/src/mcp/README.md#skills-over-mcp) 维护交付契约与
Host 兼容性边界。本次变更不包含 Code Mode 或第三方技能安装。

MCP 已连接不等于原生 Skills 已支持。使用合成 stdio Server 测试 Codex 0.160.1 和
Claude Agent SDK 0.3.293 时，初始化阶段均未观察到 Skills 扩展发现请求。Codex 对话
将公开的技能作为普通 MCP 资源读取并遵循其内容；Claude 对话因未登录而无法验证。
[MCP 指南](../../../../apps/cli/src/mcp/README.md#skills-over-mcp)记录测试范围与限制。
原生自动发现仍未确认；本地技能目录和 SDK 插件属于不同接入路径。

## 条件、来源与准入

`ctx` 提供绑定的 Session/Workspace 身份、时间与授权读取。适配器提供 Session/组状态、
关联 PR、Workflow Run、去敏额度和作用域内事实。JS 自己组合条件，读取资源不是预定义
业务谓词。程序没有 Node、环境变量、文件系统或任意网络的环境能力。来源凭证留在原
Owner，读取重新检查身份与取消状态。

CI 复用现有 PR Poller、凭证解析器和额度/冷却 Owner，按当前 HEAD 查询并保留 Run/Attempt
身份与缺口。首次观察建立基线，但已满足的条件可以直接完成。等待以及尚未送达的继续
请求保留观察需求，包括已关闭 PR。Actions 拒绝有独立仓库冷却，不影响普通 PR 观察。
乱序结果不能回退 attempt。

Host 证据与 JS 结果分开提交。准备和接受输入前重新执行 JS，排队后仍检查来源和权限。
HEAD、当前 PR 关联或 attempt 改变会使旧工作失效；同 attempt 内其他任务完成本身不会
使身份失效。原生 Prompt 提交前由 Session Owner 核验执行目录 HEAD，Project 成员使用
既有且经过路径校验的工作树目录。Guest payload 不能伪造这些权限依据。

动作到期时，从持久回执写入去重的 `timer.due` 事实。重启恢复到期资格，不创建第二个
Invocation。Timer 只证明时间经过；仍须通过当前额度证据或显式开启的有界恢复尝试，
并执行正常准入。缺失观察保持 unknown。

## 生命周期与恢复契约

- **触发：**来源观察或持久截止时间唤醒本地运行时。注册先固定作者与 Session。
  中断后可以重查，结果、证据和继续身份在同一事务中接受。
- **Owner：**Fleet 保留 Workspace 运行时，原生 Effect 拥有 Worker、有界读取与协调；
  现有 Session/Inbox Owner 提交实际副作用。
- **取消：**先撤销准入，再中断并等待准确的检查或输入 Owner，保留无关工作；过期后不接受迟到结果。
- **交接：**稳定的 Invocation/Session/Turn ID 和提交栅栏先于副作用。忙碌目标进入队列，
  不清除 Stop，不替换不可用目标。
- **恢复：**中断的检查重试，不确定提交协调同一输入。Legacy 原始调用保持所有权并等待结束，
  不因超时遗弃。连续五次检查错误成为可查看的失败，原生副作用不确定时保持阻塞。

原生 Effect 4.0.2 单元是运行循环、解释器 Worker 和读取桥。Fleet/Session/Repo 的 Legacy
适配器在上游迁移前保留，包一层 Effect 不等于迁移完成。私有启动快照与凭证指纹不进入
队列历史或工具可见 Activity。本地自动化不会发起认证的产品云请求。

## 原生策略

设置默认关闭，只影响后续观察；关闭会撤销新提交资格，取消用于已接受输入。
策略派发始终是 Lody 内部代码。

- **额度恢复：**结构化耗尽结果在释放前保留原生会话、启动绑定、输入与工具边界。
  所有已观察窗口参与判断，局部快照不能擦除已耗尽的周窗口。新输入使旧工作失效，
  未确认释放或未解决工具副作用阻止继续。
- **合并归档：**既有 PR 事实触发整个 Session 组的完成判断，包括子 Session、队列、Goal、
  原生工作与自动化。准入屏障保护重查，根节点最后写入，部分进度通过协调恢复。
- **闲置压缩：**上下文达到阈值，原始闲置 Turn、有限截止时间和原生 `/compact` 能力仍须有效。
  新输入或过期使维护失效。缓存寿命是操作者估计，不是 Provider 证据或折扣保证。

## 验证与限制

验证使用锁定依赖的独立 checkout；嵌套工作树没有安装模块。合成测试覆盖来源解析与额度隔离、
受限读取、异步 JS、结果/证据持久化、重启、取消、过期、旧 HEAD/重跑、队列丢失回执及使用
合成原生传输的真实 Session 执行。构建产物 Worker 的加载与清理独立于解释器测试验证。
这些自动化测试不启动真实 Claude、查询 Provider 额度或发送 Prompt。

Skills 验证覆盖现代 HTTP 发现、stdio 构建产物、资源字节与摘要、未知 URI 拒绝，
以及可执行注册/CI 示例。测试使用标准 MCP 客户端与真实服务端 Handler；不证明原生
Agent 已自动获得摘要、激活技能或完成模型选择。这些自动化测试不启动真实 Claude
或模型回合；独立 Host 探针及其限制见上文。

来源采用轮询，具有明确的新鲜度和缺口边界。当前适配器不开放任意外部服务；新来源必须
在既有 Owner 定义授权与观察契约。真实 Provider 缓存/额度和所有平台 Electron 打包仍未验证。
文档检查存在既有缺失引用与大小错误；这些检查不证明 RFC 符合性，也不构成本提案的批准。
