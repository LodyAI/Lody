# 加密附件密钥与不透明中转分块

Status: proposed
Translation: current

[English](2026-10-28-encrypted-attachments.md)

## 摘要

加密工作区需要支持文件与图片，上传路径必须保护原始内容。每次上传使用随机文件密钥和有认证的有界分块，秘密清单仅存入加密会话内容。文件密钥独立于 epoch，换代后历史附件仍可读，也无需修改控制账本。实现仍待审核；后端部署与打包设备验收另行完成。附件沿用已有中转保留期，已下载的明文和密钥无法收回。

## 决定

每次上传尝试生成新的 256 位 AES-GCM 密钥。每块明文最多 4 MiB，增加 128 位认证标签后独立存储。96 位 IV 由八个零字节和从零开始的 32 位块序号组成；每文件独立密钥避免跨文件重复 nonce，失败后不复用密钥。认证数据采用 UTF-8 JSON 元组，依次包含域 `lody-encrypted-attachment-v1`、预期工作区、来源会话、随机资源 ID、类别、总长度、原名、MIME、固定块大小与序号。

版本一秘密清单保存密钥、资源 ID、类别、长度、原名、MIME 与有序块 ID。加密且签名的会话内容保护清单；每块认证自己的位置及整文件上下文。读取拒绝错误上下文、乱序、重复或缺失引用、篡改与长度不符。机器写入私有临时文件，完整下载并核对明文 hash 后才改名；预览可只认证有界前缀。

文件密钥独立于 epoch。保留历史会话的解密能力，也保留历史文件密钥，换代无需重传附件。epoch 派生方案需要每次读取选择历史 epoch 密钥并增加原生加密操作；独立文件密钥复用已有受保护会话边界，epoch 秘密继续留在宿主。秘密清单不得进入中转元数据、URL、授权 token 或诊断。

## 归属与失败恢复

已有待发送 owner 在失败后保留源 Blob，复用已成功附件的完整回执，全部准备完才提交消息。文件失败尝试留下的无引用密文块沿用中转到期清理，失败图片分块保持图片存储生命周期；提前清理需要额外的持久上传清单和回收协议。未完成草稿仍受已有页面内存生命周期限制。

本机文件回填先把完整加密清单随中转回执持久化，再发布历史引用。重启复用原回执；损坏或未加密的回执拒绝用于加密历史，源文件保留。普通回填保持原有容错。原生保存只在认证流读取成功后打开分享，失败时删除部分缓存。继续复用已有发送资源取消和回填授权代次；这些 Promise／Legacy 消费者不足以独立完成原生 Effect 生命周期迁移。

## 云端边界与取舍

可选云端协议在既有设备凭据认证的内容 token 响应中增加附件专用授权。独立加密文件入口在每次请求核验当前成员、设备和工作区，Guest 只能读取；恢复设备和旧版凭据无法使用。已准入请求可能在撤权期间完成；已下载文件和密钥仍留在本地。token 有效期最多十五分钟，不是设备凭据或加密密钥。

中转仅接收不透明块 ID、固定二进制文件名、通用 MIME、密文长度与密文 hash。图片缩略图和文件预览在客户端解密，不经过服务端图片转换。文件分块沿用现有文件桶及 90 天保留期；图片分块使用独立密文图片入口和原图片桶生命周期，账户删除清理覆盖两者。100 MiB 文件最多 25 次请求。普通工作区维持原图片／文件路径；公开本地组合仍没有带认证的云端能力。

此决定部分替代[功能可用性决定](../../implemented/bug-fix/2026-10-27-e2ee-feature-availability.zh.md)的附件限制，其余功能约束继续独立生效。

## 验证边界

`packages/shared/tests/encrypted-attachment.test.ts` 覆盖上下文、篡改、顺序、长度、重试和历史转换。既有附件准备、图片缓存、CLI 输入／图片下载和回填测试覆盖消费边界。合成测试不代表已部署鉴权、移动真机保存或两台已安装桌面验收。
