# 以独立签名控制账本开始 E2EE 实现

Status: proposed
Translation: pending

## 摘要

当前原型已有单链权限、真实密码学、持久 outbox 和 Streams SDK 密钥交付，但生产
准入仍未接入。新加 `ControlFreshnessLease` 将已认证的观察绑定到精确链头与原始
绝对期限，避免接收、缓存或重建对象时重新起算 15 分钟；到期、登出或时钟失效
使该实例永久失效。它只实现本地守卫，不另造凭证协议，也不把普通读取或本机时钟
当作可信证明。另补 SDK fetch 入口的流式限长及整个请求截止，避免 SDK 已缓冲
整包后才拒绝超限。生产观察认证、可信时间、服务端长连接截止及真实端验收仍须落实。

### 恢复文件包装

新增显式空设备恢复主进程接口：原生选择只返回账号与文件定位 ID，不保留秘密句柄；
调用方取回密文后重新选择文件，校验定位 ID、当前账号、认证加密及身份公私钥，
通过既有空库恢复原子写入。已有身份始终拒绝覆盖；账号切换不返回成功，选择后
切号在写入前拒绝并清理文件秘密。两次选择避免把文件秘密交给 renderer 或为其
维护长期秘密 token，代价是多一次明确选择。服务端描述在解密前不可信，恢复成功
也不证明最新版本、Org 权限或设备资格。设置页已接导入入口：读取匹配账号/定位 ID
的备份后显式确认，取消不报成功，原生恢复返回匹配身份后才显示本机保存完成。
页面不创建身份、不接触文件秘密；真实对话框和云端完整往返仍待验收。

共享 UI 的 `cloudOperations.e2eeRecovery` 已声明认证后的 availability/put/get，
沿用 `cloudAccount` 能力和现有云端适配器，不导入私有后端类型或新增 HTTP 客户端。
可用性由服务端显式开关及账号删除状态决定。Electron 账号设置现接入保存、上传、
精确版本/密文回读、原生重选验证及独立保管确认，不依赖已有 Org；本地组成不发
云端请求。导出携带主进程绑定的公开账号 ID，服务端与实际会话比较，防止异步切号
把旧账号密文传入新账号；该字段不能指定上传归属。上传失败保留同一份密文重试。
组件类型检查与 5 项 DOM 行为测试通过，覆盖错密文、取消、重试、确认顺序、切号
和本地模式。确认仅是本次页面状态，尚未持久记录；真实 UI、Storybook、云端完整
往返及独立新设备恢复仍待验收，不据此标记备份产品流程完成。

恢复文件新增独立、无网络的包装层：随机 32 字节钥与定位 ID 保存在文件，
认证加密绑定调用方期望的身份指纹和材料版本。复用固定 XChaCha20-Poly1305，
不引入密码/KDF、文件 URL 或第二套套件。材料保持有界不透明字节，身份模块
仍须校验其公私钥配对；解密不证明备份已上传、成员仍有效或版本最新。
真实密码库互操作及篡改/错上下文/格式边界已覆盖，文件保存与回读确认 UI 已初步接线。
用户身份层现有独立格式和公钥指纹：恢复不仅解密，还通过严格 Ed25519 签名和
X25519 协商核对公私钥配对，拒绝设备包与已认证但错配的秘密。返回不可导出句柄，
显式生成的私密材料仍须由应用安全保存；没有自动覆盖、成员恢复或隐式生成新设备。
新增独立用户身份 SQLite 适配器，与设备数据库/包装域分开；先完成系统包装回读再
原子保存，空库才允许显式恢复，备份方法只输出密文。复用既有 SQLite 排他锁与
Electron 安全存储守卫，不复制旧设备身份；合成 AES 系统端口验证真实落盘、
跨实例恢复、锁定失败、格式隔离与不覆盖。
Electron 主进程新增显式用户身份 create/load IPC，只返回公钥与指纹；账户和认证域
由主进程绑定，排队后及异步返回前复核会话。本地模式在认证前拒绝，不随登录
自动创建用户身份，也没有私钥或恢复文件通用 IPC。真实用户库 keychain、恢复 UI
及加密 Org 产品流程仍未验收。
用户服务现通过真实主进程 Vite 配置内存打包，再执行产物验证 SQLite 创建、
重新加载、锁定拒绝、解锁保留原身份和重复创建拒绝。同一 7 项包装测试在宿主
Node 与安装的 Electron 内置 Node 均通过；系统包装使用合成 AES 端口，未接触
真实用户数据或 Keychain。这证明该服务的打包运行边界，不是 GUI/恢复流程验收。
用户身份 IPC 与打包切片后的全仓 `pnpm check` 已完成，退出 0：核心 237 项、
Electron main 111 项与 renderer 4 项通过，包含全仓类型、lint、翻译键和边界检查。
默认跳过的网络集成不计入验收；此结果不代表生产 CAS、备份 UI 或真机已完成。
后续导出切片新增受限 Auth IPC：主进程生成恢复文件，经原生保存选择，以 `wx+`
拒绝覆盖，0600 新建、sync 并回读同一文件句柄，再输出身份备份密文与公开定位信息。
不返回文件秘密或路径，不上传、不声明已备份；取消与会话切换不返回密文，已有
文件不被替换。保存后封装失败可能留下未配套的文件，重新选择验证和云端回读仍须
由完整恢复流程完成。核心 239 项及 Electron 主进程类型通过；这晚于上面的全仓检查。
接口核对参考 [Node 文件标志](https://nodejs.org/api/fs.html#file-system-flags) 和
[Electron 原生对话框](https://www.electronjs.org/docs/latest/api/dialog)，本地检索 CLI
被代理权限拒绝后查官方文档；未以网络文件系统的排他性或真实磁盘断电作为已验保证。
重新选择验证已接原生打开对话框：读取至多 257 字节，仅接纳 1–256 字节普通文件，
以 nofollow/nonblock 打开；依据主进程现有身份而非备份自报身份完成解密和公私钥
配对校验。只返回公开匹配信息、不写身份；文件秘密和解密材料用后清理。调用前
复制密文，选择后及密码学返回前复核账号。测试覆盖真实文件成功、取消、错文件、
错版本、篡改、目录/符号链接及切换账号；尚无真实对话框/UI 或跨平台文件系统验收。

### SDK 缓冲前边界

`createBoundedStreamsFetch` 为控制/历史桥/发钥的一次性请求提供显式 opt-in。
同步准入回调发生在 SDK 凭证等待之后，返回原始截止、失效信号与检查函数；
在网络前、响应头后和读取块前后复核。实际字节累计而非信任 Content-Length，
超限/过期/撤权都取消上游并令响应出错；拒绝重定向，不新增自动重试或协议格式。
这比 SDK `arrayBuffer()` 后限长更早，但不能限制 native fetch 已分配的单个块，
也不替代生产网关的强制截止。Node 流取消契约参见
[官方 Web Streams 文档](https://nodejs.org/docs/latest-v22.x/api/webstreams.html#readablestreamdefaultreadercancelreason)。
测试使用真实 SDK、签名控制记录、可控响应流与 fake timers，验证不完整响应
不保存游标，过期凭证不发出请求；服务端已提交而响应过期时，保留原文 pending，
新授权会话核对已提交记录，不重复追加。此边界没有自动接入产品或签发凭证。

### 固定截止守卫

使用已确认的总 15 分钟上限，而非新增默认邀请期限。调用者提供已核验观察的
原始时间及更短的截止时间，为时钟、传递和实际执行保留预算；类没有续期 API。
相较每次创建 `now + TTL`，绝对期限不会因重试或进程重建自动延长。精确 head/length
不覆盖未经证明的新状态，已知撤权须主动 invalidate；各操作的角色/设备验权不变。
测试用显式时钟，覆盖到期边界、重建、时钟倒退/失败、错 Org/检查点与输入修改，
并将守卫用于真实 Org/HPKE 准备、接收及延迟发送检查。没有生产签名证明或 JWT
集成；不能将这些局部测试记作完整撤权验收。此前 SDK 切片的全仓 `pnpm check`
已重新完成，退出码 0；该结果不自动覆盖这次新增守卫。

### 发送 outbox 背景

本轮补发送 outbox：精确密文先原子落盘，再验证当前权限并发出；断线重启不重签
或重加密。历史信封签名与当前发送/接收资格同时核对，落盘期间撤权阻止发送。
只有读回原密文才记为 observed，不把服务端保存当成收件人解锁。核心类型检查
与 206 项测试通过，包含真实 SQLite、HPKE、断线/丢回执、接收落盘恢复、写盘
失败、撤权、篡改 outbox 和远端错包。生产传输与凭证门槛仍未接入，未重跑全仓
或独立安全审计；收件安装、恢复 UI 与真机验收继续在清单中。

### 接收存储背景

本轮增加可选 Node 接收密钥存储：持久保存原始 HPKE 信封，利用已安全保存的设备
私钥恢复，不再复制一份 OS 包装代次密钥。先验权解包、原子保存密文，再验权复核；
重启仍通过 `OrgKeyExchange` 检查当前资格，不能凭磁盘记录恢复成员身份。
相对二次包装少了一套密码接口；代价是恢复依赖目标私钥与历史账本可用，不能充当
丢失全部设备后的备份。密文 outbox、产品运行时安装与恢复 UX 仍待接入。
本轮核心类型检查与 203 项测试、类型感知 lint、格式、公开边界和文档检查通过。
真实 SQLite/HPKE 覆盖重建实例恢复、重复信封不改首份、属性顺序规范化、错目标/私钥、
撤权、SQL 拒写、磁盘签名篡改，以及保存后的刷新失败保留密文再恢复。
测试设备私钥是合成非导出句柄，不把此项记作本轮系统密钥环或真实设备验收。

### 发钥授权背景

本轮增加 `OrgKeyExchange`，将实际 v3 账本状态与已有 HPKE 信封、代次承诺组合。
发送前后重新追赶并验权；接收同时验证历史发件资格与当前收件资格，避免无关链头
变化让异步信封失效。`readAtHead` 先完整追赶，再重放所需历史前缀，不信任存储中的
权限快照；代价是重复重放，而不是新的可信缓存。新鲜度仍需应用显式保证，
准备密文不等于已发送，解密也不等于安全落盘；outbox、实际传输和接收存储尚未接通。
本轮核心类型检查与 199 项测试、类型感知 lint、公开边界和文档检查通过。
新增真实签名/HPKE 组合覆盖未入账、错承诺、历史发送者降级、当前收件者撤权、
发/收密码计算后的撤权、在途取消、本人恢复复制与机器拒绝、换代前后延迟信封；
历史状态查询覆盖重启、坏后继页、离线及落盘失败。没有生产调用、完整应用验收
或新的独立安全审计；测试中的新鲜度检查仍是显式合成会话，不是生产 15 分钟证明。

### 异步申请背景

当前异步加入切片：申请者独立签署身份与首台设备，不绑定可变链头；指定的
Owner/Admin 在最新状态批准，取消与批准按 CAS 顺序消费一次性申请。
与原完整记录多签相比，普通链头推进不再要求申请者重新签名；代价是增加独立
同意证据验证和消费状态。有效期无默认值，生产必须在原子准入处验时，不能让
历史重放使用今天的时钟。SQLite 断线恢复、消费防重放、身份/设备签名和权限
变更已有行为验证；加密托管、实际批准后发钥、UI 与生产准入仍未接入。
当前切片核心类型检查及 190 项测试、类型感知 lint、公开边界检查通过。
有效期测试改为两个独立准入实例并只向前推进时钟；不是通过倒退时钟让过期申请复活。
新增 SQLite 测试覆盖原文 pending 恢复和消费墓碑；未运行新一轮全仓或独立安全审计。

### 权限切片背景

最新权限切片（2026-09-12）：按已确认的小团队规则，v3 去掉独立管理密钥和备份
承诺，Owner 移交只需双方有效管理设备签名，前任默认 Admin。设备登记显式携带
canManage，与当前用户角色取交集；机器不得管理。Owner/Admin 可发布换代，
但移除成员、任免 Admin 和移交仍 Owner-only。相对额外密钥/四签，这减少保管

旧 v1/v2 签名及旧锚点 SQLite 日志原样拒绝，不重解释或迁移。核心类型检查及
177 项测试通过，包含 Admin 降级/撤设备后的旧头及新签名拒绝、机器与受限设备
管理拒绝、Owner/Admin 同头 CAS、旧账本 pending/committed 保留，以及转让后的
Admin 独自发布和 SQLite 恢复。未重跑全仓检查或独立安全审计。

## 新权限目标与迁移边界

最新产品决定替换下文历史原型中的设备依赖：设备直接绑定用户，角色随用户变化，
撤设备仅撤明确目标，不连带后代。Admin 可在接纳成员后自行发已有当前密钥，
无需 Owner 在线；最新决定允许 Owner/Admin 换代，各端均可确认后跳过强推荐备份。
二维码注册申请与机器一次性配对、位置/公钥摘要确认成为明确交互目标。

此前实现其中的扁平设备策略：移除 parent、祖先查找和 device/identity 两套授权
分支；同一 Org 内本人有效个人设备可撤本人任一设备，只删除目标。角色仍从用户
当前状态读取，不新建设备角色缓存。身份根仍参与新成员确认，不替代有效个人设备。
机器不管理、仅当前 Org 撤设备、无额外签名及前任 Admin 已确认；异步邀请、
Admin 发钥和备份交互尚未实现，不以这次权限切片宣称整个新流程已完成。

此前扁平化将 genesis/action 域升为 v2；本轮权限变化进一步升为 v3。

## 决策与取舍

公开 main `eade9041f3f25c2c53fcc391392c27968747bb66` 没有本控制账本的现成
Spec 或活动 Note。新增包不改变 CRDT 文档同步，不把 Org 权限塞进传输库。
相对于带并发合并规则的 DAG，单流 CAS 让客户端只需顺序验证；代价是控制操作
必须在线提交，且全局最新视图依赖后端。该包也不试图自行实现 MLS。

选择显式数组编码而非任意对象规范化，限制标识符与负载大小，并绑定全部签名者。
选择 Web Crypto 签名与哈希、固定版本 noble-ed25519 严格验签，不手写曲线算法。
控制验签使用无传递依赖的 noble-ed25519；内容层另引入固定 noble-ciphers 2.1.1，
不新增手写密码原语；可选 Streams 入口声明已固定版本的 SDK。
签名仍可使用原生不可导出私钥。
每次重放而非直接信任缓存权限，牺牲大账本
性能，换取这一阶段较小的持久化安全表面。`ownerManagedTeamPolicy` 是显式的
首版配置，不会自动启用；范围现已确认：Admin 邀请普通成员，Owner 最终移除成员
并换代，所有用户自行撤销本人设备，无需 Owner 审批。
策略与通用链验证分开，Owner 管理密钥不能替代活跃个人设备资格，Machine 不能
治理。初版曾区分父设备委托与身份根独立授权；随后以直接用户归属替代这一区分。
同一成员实例的设备墓碑和全历史成员实例防止旧资格复活；显式重新加入可以保留
当前用户身份/物理设备，但不能继承旧实例的其他设备。管理钥全历史去重，移交不影响内容访问。
完整行为见[协议草案](../../../../specs/e2ee-control-log.zh.md)。

原型目前仍采用同一控制记录的完整多方签名，CAS 冲突需要重新收集签名。
后续产品决定已明确异步邀请：用接收者公钥加密签名消息，对方稍后签名接受，
无关链头推进不要求重复确认；最终当前权限验证和 CAS 入账仍不可省略。接入前需
实现独立签名证据与提交包装，保留持钥证明、实例/权限绑定、防重放和到期检查；
当前原型尚未满足，不以放松验签来伪装完成。备份摘要仍只是声明，真实验证在端侧。
撤权设置换代标志；下述新增 Owner 发布动作可清除发布义务，但收件人列表仍只表示
资格，不能触发未经确认的密钥释放，也不表示所有设备或传输已完成切代。

## 本地持久层与流适配边界

选择 `node:sqlite` 的 EXCLUSIVE locking mode，贯穿一次完整操作保留文件锁；
每次保存独立提交。这样不需要维护租约/心跳/过期抢锁，也不会因远端丢响应而回滚
已经保存的 pending。代价是 SQLite 同步 IO、网络等待期间持锁、竞争者立即报 busy；
只适用于专用本地文件，Node 子入口不传染浏览器通用包。设置 EXTRA 同步和可用
平台上的 fullfsync；没有在磁盘上保存私钥，文件不是加密保险库。依赖 SQLite 与
文件系统的锁/同步保证，而非声称代码测试证明硬件耐久。

此前流接口复核确认：SDK 只有每页 `payload + nextOffset`，把页尾复制给各条
记录会在仅保存第一条后跳过后继。当时先以多记录页测试确认旧接口不兼容，再改为
`StoredPage` 和 `ControlReadPage`：全页验证后原子保存页尾和原文，坏页保留前一
完整页及 pending；未读到 `upToDate` 不返回最新快照、不提交 CAS。

`StreamsControlStream` 现在使用 SDK 0.7.0 的独立 `/append-cas`，写入四字节
大端长度加规范 wire；跨 HTTP 页的残帧组合至完整边界，不计算不透明偏移。
无普通 append 后备，也不让 SDK 自动重试不确定写入；丢响应/错误 ACK/501 依靠
原文 outbox 和验证读回来判定。测试使用真实 SDK、真实签名和合成 HTTP 对端，
覆盖 409 标记及 412 mismatch、分帧、无效后续记录、保存前后失败和中途 410。
SQLite 页级格式升为 v2，实际 v1 文件拒绝后仍保留原 schema 与 payload。
测试不连接生产；SDK 先缓冲响应体，生产调用者仍须限制体积/时限，并核验 CAS
部署、新鲜度和专用控制准入。本地适配成功不等于这些前提已满足。

首版范围进一步收敛：不做跨流封存/截止证明，以可信服务端 JWT 控制云端访问，
并明确旧凭证与在途请求仍有残留窗口。JWT 到期不回收旧内容密钥，未来内容保密
仍需 Owner 换代；设备签发/续签必须核验当前账本资格与持钥，不能仅依靠账号登录。
控制流必须有独立准入验证，不能用普通文档 token 写入；坏链停止、不提供修复。
总撤权窗口现已确定为成功提交后的最多 15 分钟，覆盖云端继续访问与机器新执行，
而非为 JWT、投影缓存、连接及执行各分配 15 分钟。已知撤权立即拒绝，派生凭证
不得延长原证明；已发生副作用和 Owner 换代时长不在此承诺内。具体期限/主动
失效是工程选择，经过验证的恢复路径保留。
这是已选首版范围及仍待实现的边界，不是已经验证的后端能力或完整协议批准。
此前首版权限/范围确认只修改现有文档；当时重跑本包类型检查、62 项测试及原有有限顺序模型，
没有为 JWT 范围改写或删除测试。通过结果不覆盖真实 JWT 签发/失效、网关或恢复。
