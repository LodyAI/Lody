# 按会话存储定时消息

Status: proposed
Translation: current

[English](2026-10-27-session-scoped-scheduled-messages.md)

## 摘要

每条一次性定时消息单独创建文档和 Registry 条目，会给会话内功能增加长期保留成本。建议每个会话首次使用时创建一份持久化 Loro 文档，按 ID 存放消息请求和执行回执。固定执行机器接受修改并可靠提交发送，消息队列 UI 合并普通消息和定时消息。本提案替代[先前方案](../feature/2026-10-27-scheduled-messages.zh.md)的存储选择，通用周期 Schedule 保持原样。移除可见条目不等于清除历史或物理存储，后两者仍需验证仓库删除和压缩能力。

## 数据与职责

建议文档名为 `smq-<sessionId>`，与可执行的 `mq` 列表分开。文档保存协议版本、固定执行机器、按 requestId 存储的不可变请求，以及按 messageId 存储的已接受消息和执行回执。请求包含操作、预期版本、完整内容和发送配置、UTC 发送时间；每个版本作为完整值提交，避免并发修改把内容和时间拼成混合版本。附件只保存引用。复用会话发现机制推导文档 ID，执行端启动也检查未打开的会话；不新增逐消息 Registry。若添加发现提示，它只能加速发现，必须能通过扫描所属会话修复。

只有固定机器可以接受请求和发送，每个会话只有一个有效执行者；首版不自动切换执行机器。校验工作区、会话权限和新协议能力，旧执行端不支持时禁用功能。CRDT 本身不能证明作者身份，必须接入并验证现有经过认证的请求处理和身份校验。保留现有加密内容能力限制。

## 同步与执行

客户端先把唯一请求持久化，随后通过现有 repo 本地传输或云端 Streams 同步。执行端追平当前同步状态、校验消息和附件后，把请求处理与到期发送串行化，先在 SQLite 账本持久化决定，再同步回执；崩溃恢复时补写缺失回执。请求重试沿用 requestId，不能变成第二次创建。

只有执行端接受才算预约生效，上传完成不代表接受。编辑和取消携带已接受版本，版本不符返回冲突。新修改被接受前，旧版本仍然有效，界面必须明确表达。发送决定先在账本固定版本、完整消息和稳定的 turn/dispatch ID，再走现有 prepared-session 提交路径。取消先被接受则不提交；发送决定先提交则拒绝后续编辑取消。提供商结果不明确时不能盲目新建一次发送，保留现有恢复行为，必要时显示结果待确认。“已发送”指已可靠交给会话，不代表 agent 已完成。

到期后参与现有会话发送仲裁，等待普通队列和会话空闲，不中断正在执行的 turn。定时消息按时间再按稳定 ID 排序，不允许拖拽。执行机器离线会延迟；恢复并完成同步后，已接受的消息满足条件时补发一次。首次送达执行端时已经过期的新请求拒绝并要求重选时间；已接受预约允许补发。失败保持可见，永久错误不静默循环重试。

## 界面与回收

保留紧凑的消息队列 UI：普通消息在前、定时消息在后，时间作为 inline 前缀，移动端使用更多菜单和时间选择 modal。区分等待执行端、已预约、到期等待会话、发送中、已发送、取消中、已取消、失败。编辑待接受时同时说明新请求值与旧版本仍生效。

共享文档不设置从创建时开始的 TTL，避免误删其他未来预约。建议终态详情保留七天，之后从当前状态移除正文和已完成请求详情，保留最小消息/request ID 和最终决定，拒绝离线重放；消息 ID 永不复用。附件在取消或发送决定可靠持久化前保持引用，已发送附件由会话历史接管。CRDT 删除不清除 oplog 和远端快照。首版不能承诺物理存储有界：历史压缩、终态账本清理和会话删除时彻底清除，必须另行验证能阻止旧离线状态重放的机制；验证之前保留最小回执并明确剩余增长。

## 兼容、取舍与验收

通用 Schedule 保留原有 once/existing_session 能力，不静默转换既有预约。未发布的测试数据明确取消后重建；若已有发布数据，迁移必须保证单执行端转移，避免两个引擎各发送一次。不能把未来消息直接放入普通 mq 列表，旧消费者会提前发送。在同一文档增加独立根容器也可行，但会耦合生命周期，需要审计旧版本整文档写入行为。首版推荐独立会话文档，代价是每个实际使用功能的会话多一个同步房间。

已核对 HEAD 原有 once/existing_session 能力，以及当前 Schedule 创建无 TTL、删除保留定义并写 Registry tombstone 的行为。本文件仅为设计提案，没有修改执行代码或完成行为验证。实现前需对齐所属 Spec 和协议契约。验收覆盖真实双副本同步、并发编辑、取消与发送竞争、执行端离线、各崩溃恢复点、未打开会话发现、旧端能力拒绝、附件保留、清理后离线重放和防止重复提交。
