# 工作区的加密临时在线状态

Status: proposed
Translation: current

[English](2026-10-28-encrypted-ephemeral-presence.md)

## 摘要

加密工作区目前关闭云端在线状态，因为普通 presence 通道会暴露机器和会话状态。
本改动在现有临时 SDK 通道上，用用途 7 的加密签名保护原有的小型状态记录，
同时让持久文档和普通工作区保持独立。主机检查当前设备成员资格、工作区与房间、
机器与查看者身份、有效期和有界的重放记录，非法状态只在 presence 内丢弃。
正文编解码依赖公开草稿 [#1990](https://github.com/LodyAI/Lody/pull/1990)，仅在本地叠加验证。
该依赖与真实网关、双设备验证仍待完成；这里不声称已部署或通过安装版产品验收。

## 职责与取舍

```text
本地状态 -> 限量合并的加密桥 -> 主机用途 7 签名
         -> 原有 ephemeral POST/SSE -> 主机认证和准入 -> 到期清除的状态
加密文档 -----------------------------------------> 独立的持久 SDK 通道
```

- Core 的 `makePresenceContentBinding` 通过真实且连续的账本判断权限，
  在加解密前后检查当前非 Guest 的个人或机器设备；读密钥前验证签名，
  检查 epoch 承诺并清除自有密钥和明文。open 回调只能临时借用明文。
- RPC 主机入口直接使用依赖的正文编解码，不复制格式；独立固定 genesis 和
  `presence:<workspaceId>`。机器和会话状态必须匹配当前机器设备；
  个人查看状态的用户标识来自已验证成员的密码学 ID，不能采用调用者的云端用户标签。
  这些 ID 只是展示引用，不构成新的身份目录。
- 正文保留原始产生时间，最多 60 秒到期。未来、过期、格式错误、错误用途或上下文、
  伪造、无权限的帧均拒绝。递增序号与时间下限防止删除后的状态复活，包括旧实例的消息。
  重放记录仅在当前接收者的内存中；全新的接收者可以加载仍有效的临时状态。
  不增加持久 presence 历史或执行去重日志。
- 每个接收者最多保留 4096 个逻辑键的重放下限，持续到已认证的有效期结束。
  满额时丢弃新键，不驱逐仍有效的保护。原生窗口由 main 提供独立弱引用上下文，
  不接受 renderer 自选接收者身份。
- 加密桥最多排队 128 个不同键，合并同键状态、优先发送心跳，最多每秒四帧。
  状态 JSON 最多 4096 字节，另加 41 字节正文头和 143 字节加密开销。
  排队到过期的状态丢弃；加密失败只等待下一次心跳或状态变化。
  SDK 仍是唯一 POST/SSE 队列，重试使用原始密文。
- 已认证的到期时间同时进入原有新鲜度判断和清理定时器。
  已验证账本变化会清除缓存的远端状态并拒绝晚到的投影，不清除本地产生的状态。
  普通 presence 的传输、房间、认证、90 秒 TTL 和正文保持原样。
  UI 提示由原生主机的明确能力状态控制。

## 失败隔离与 Effect 边界

坏帧、缺密钥或签名失败只结束当前 presence 操作，继续接收后续状态，文档加密仍可使用。
桌面 presence 只在短准入锁内借用工作区，加密在锁外执行；暂停的 presence 密钥读取
不能占住文档的准入锁。加密临时通道连接失败仅记录有界警告，不能撤销已连接的持久同步。
不增加工作区就绪等待或全局重试循环。

现有原生 CLI 工作区和每代 Scope 继续持有 SDK 和 token。Legacy 入口取得共用的
Promise 加密桥，并把实际清理注册在这一代 Scope 中。退出时同步停止发布和导入权限、
取消定时器，然后等待已开始的真实加密工作完成才销毁 store。
释放失败仍由原有 registry 保留原 owner；renderer 使用相同的停止顺序。
Core 加密及其准入、等待释放保持原生 Effect。跨运行时 SDK 回调桥的完整原生改写暂缓，
其调用者仍是现有 Promise SDK 和 renderer；这不改变原生 presence owner 的分类，
也不声称上层运行时迁移已完成。

继续关闭 presence 是安全的，但缺少当前在线信息。把加密状态写进持久文档会混合
可丢弃状态与持久恢复责任；沿用临时通道保留独立的失败范围。
这里只部分替代[文档集成记录](2026-10-22-e2ee-m2-product-integration.md)中关于 presence 的禁用。

## 证据与限制

确定性测试使用合成的真实账本、签名、密钥、注入时间和假定时器。
覆盖只发送密文、到期边界、跨上下文与伪造帧、签名中撤销、序号与实例重放、
有界发布、不回传远端状态、停止晚到加密、账本失效以及坏 presence 后文档仍独立可用。
桌面原生夹具使用合成的认证存储和真实加密、SQLite，不使用用户钥匙串。
临时移除到期与重放检查会使三项边界用例失败，恢复后通过；暂停原生密钥读取时，
文档仍能完成加解密而 presence 保持等待。受影响检查和最终修订记录在 draft PR 中。真实网关的启动与广播、安装版双设备、
各平台密钥保管与打包、生产交付仍未验证。公开正文格式仍是草稿；本记录不批准其 Spec 或依赖。
