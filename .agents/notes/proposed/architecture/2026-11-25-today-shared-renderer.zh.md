# 轻量每日笔记窗口复用桌面渲染进程

Status: proposed
Translation: current

[English](2026-11-25-today-shared-renderer.md)

## 摘要

当前桌面每日笔记独立窗口会加载常规渲染入口，并启动一个工作区运行时。同源的 Electron 子窗口可以由来源渲染进程挂载笔记界面，复用已有的实时笔记缓存。隔离实验验证了跨窗口直接访问对象，以及 Electron 的子窗口生命周期选项。产品里的工作区运行时、编辑器和窗口生命周期仍需集成验证。

## 提案

若发起打开操作的渲染进程已具有目标工作区访问权限，由它将每日笔记挂到一个受控的子窗口文档，复用工作区作用域和 `todayPages` 缓存。立即打开指定日期，已有日期索引时直接使用。第一个消费者仍可能需要按笔记文档前缀初始化索引。子窗口无需启动应用路由和第二套工作区运行时。会话引用菜单和转为任务等功能可按需加载。

子窗口需绑定来源运行时的账户、工作区和生命周期。切换工作区、退出登录或来源渲染进程丢失会使绑定失效。如果关闭来源窗口后笔记仍须可编辑，就需要明确保留已授权的运行时，或把所有权交给另一个匹配的运行时。独立渲染进程也可通过窄接口复用日期和页面状态，但编辑和持久化需要明确协议。评估这项替换时，[现有独立路径](../../implemented/architecture/2026-11-25-today-window-local-open.zh.md)可处理没有匹配来源的打开请求。

## 证据与限制

隔离的 Linux arm64 Electron 实验打开了一个同源的 `about:blank` 子窗口。两个窗口共用一个渲染进程，子窗口能修改主窗口读取的同一个 JavaScript Map。默认情况下销毁主窗口会关闭子窗口。设置 `outlivesOpener: true` 后，子窗口可以继续读写实验中的 Map。这验证了浏览器层的机制。产品仍需验证 React 提供者、跨窗口通信、编辑时的选区与输入法、双窗口同时编辑、工作区绑定失效、关闭主窗口，以及重启后确认编辑内容已持久化。
