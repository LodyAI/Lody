# A bounded playable E2EE tutorial

Status: proposed
Translation: current

[中文](2026-09-16-e2ee-playable-tutorial.zh.md)

## Abstract

The independent E2EE demo exposes real workflows but its flat controls do not teach their meaning. A full town game would add rendering work and unintegrated protocol scenarios beyond a one-week target. The proposal is four levels on one pixel-art stage, with a technical lens driven by the same real execution evidence. This reduces whitepaper coverage rather than faking missing capabilities; delivery and usability remain unverified.

## Decision and trade-off

The owning [tutorial specification](../../../../specs/e2ee-playable-tutorial.md) contains scripts, source labels, acceptance criteria, and the sole progress table. Keep SVG/CSS and React instead of Three.js/free movement; preserve existing free experiments. Compare public-note divergence without claiming to execute full malicious snapshot endorsement. Demonstrate bounded file recovery without claiming long-lived recovery delivery. Actual errors and unknown outcomes take precedence over story animation.

This adds a teaching layer to the [independent demo](../architecture/2026-09-16-e2ee-independent-demo.md), not a protocol replacement. The earlier nine-level/full-game direction is deferred. Same-page actors are teaching roles, not isolated devices; server/teaching notes cannot become independently checked. Local experiments must not weaken host admission.

## Evidence and limits

Reference source baseline is `d20c2f25`. This is a design-only change: no game, security model, performance, or all-age usability verification is claimed. The spec's A1–A10 and five-day plan define future validation. No PR or implementation approval is inferred from writing the document.
