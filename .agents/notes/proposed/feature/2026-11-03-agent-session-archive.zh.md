# Agent 会话归档同步

Status: proposed
Translation: current

[English](2026-11-03-agent-session-archive.md)

## 摘要

Lody 归档对话会释放运行时，但提供方的原生会话可能仍出现在历史列表中。本改动通过可选的 Core 能力，将已提交的归档和恢复状态同步到保存的精确原生 ID 和所属 Provider。Codex 提供可恢复的原生归档，Claude 明确提供较弱的标题标记。不支持或同步失败会显示提示，Lody 文档清理仍继续。历史补归档和持久化同步状态界面不在本次范围内。

## 所有权与顺序

`MessageHandler` 观察已提交的归档元数据，合并清理期间到达的状态变化。`SessionManager` 按 Lody Session 串行操作，修改前重新读取机器、Provider、原生 ID 和目标状态。归档在运行时终止后执行，冷恢复先加入同一队列、解除归档，再启动会话。已删除记录、其他机器、缺少原生身份或过期状态均不授权原生修改，不用标题或目录猜测身份。

短生命周期 ACP 连接使用现有启动解析器、保存的 Provider 环境、Codex 账号配置和进程使用凭据。连接只初始化并调用协商的 Core 请求，不创建或加载会话、不请求权限、不启动模型轮次。启动与请求共享 30 秒取消预算，现有 ACP 所有者在完成前终止进程树。元数据检查后、请求发送前再次检查取消。清理失败保留错误，独立的 Lody 文档清理继续，后续状态变化可重试。

## 能力与替代方案

Core `sessionArchive` v1 声明 `mode: native` 或 `mode: title-marker`，归档与恢复幂等，保留原生身份及历史。原生存储语义归适配器所有，Codex 复用会话索引中的原生操作，Claude 复用兼容 AIR 的标题写入器，但不启用 AIR 协商。标题标记不承诺从 Claude Code 的恢复选择器隐藏会话。能力缺失或未知时明确提示只归档了 Lody，原生失败与成功写入标题标记使用不同提示。

另建 Codex app-server 客户端会重复适配器逻辑，也阻碍其他 agent 接入；声明 AIR 能力会引入另一个客户端的专属协议；直接修改 transcript 或 SQLite 会绕过提供方所有权。所选的窄 Core 扩展避免这些问题，但不宣称实现 ACP 归档 RFD #2161 的完整列表和状态保证。SDK 与适配器完整支持该标准后，应改用标准 ACP。

现有会话编排和 ACP 启动仍使用 Promise，本改动复用已登记的共享进程边界，不将跨越尚未迁移依赖的包装称作 Effect 迁移。Core 和适配器提交作为配套 PR 依赖，适配器暂时锁定 LodyAI 官方仓库的 Core 提交，待契约发布后再切回版本依赖。

## 验证边界

Lody 测试覆盖原生、标题标记、不支持三种协商结果，精确请求身份、过期元数据、串行顺序、保存的 Provider、失败后的文档清理，以及成功和取消后的真实子进程退出。适配器测试覆盖原生操作和持久化的 Claude 标题标记，包括未知会话和协议路由。合成原生存储集成验证 Codex，不产生模型轮次。其他适配器可通过声明契约接入，但本次不推测或实现其原生归档语义，因此较大的功能请求继续保持开放。
