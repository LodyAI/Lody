# 团队邀请与加入界面

Status: proposed
Translation: current

[English](2026-10-28-e2ee-team-joining-ui.md)

## 摘要

个人设备配对和普通组织成员关系不足以组成完整的加密团队加入流程。已批准的 MVP 采用定向邮箱邀请，由在线且合格的管理员设备自动签入；共享链接则逐个显式批准。界面保留待处理进度，区分成员签入和密钥送达，并复用现有席位费用说明。单个申请或可选目录故障不影响其他成员和普通工作区；尚未完成安装包与真实服务验收。

## 决定与边界

- 邮箱邀请和可撤销共享链接默认 48 小时过期。原生主进程生成签名 KeyPackage，链接本身不授予成员身份。默认邀请 Member，仅 Owner 能升级为 Admin。邀请数量上限与席位政策仍由服务端复用普通机制。
- 邀请固定值跨登录、桌面深链和切换 token 保留。先恢复原生待处理原件，再处理来源过期。提交失败、断网、写入结果不明和发钥延迟显示可续做状态，不替换原申请。
- 全局后台签入仅针对目录中显示 Owner/Admin 的加密工作区，再核验实际个人设备账本角色。只有邮箱申请会自动处理。每个成员失败相互隔离；原生 reader 依据原账号和 owner 标记借用与归还。
- 加密账号目录只提供导航和展示资料，不决定设备权限。可选目录故障不能卸载健康的普通工作区。返回已确认的普通路由时，即使故障中路由重新挂载，也会清理加密选择；未知加密目标保持拒绝访问。
- 原生团队运行时与已认证服务分别审查。本 UI PR 独立基于 main，携带可选协议声明以独立构建；旧主进程显示升级提示。原生 PR 合入后 rebase 应删除重叠声明。此分支没有叠入其他 PR。
- 设置中提供邀请、逐项申请审批、撤销邀请和 Owner 升级成员。待处理链接申请复用 PR20-D 的设置提醒，按已验证管理设备、账号和工作区隔离；队列失败不能隐藏换代提醒。成员移除与换代由另一工作流负责。

## 证据与限制

所属测试覆盖普通与加密路由、响应丢失或来源过期后的原进度恢复、链接显式批准、仅邮箱自动签入、单成员失败隔离、断网恢复、可选目录故障、reader 清理和现有席位费用说明。真实 Storybook 组件提供窄屏与桌面宽度截图，包括深色等待和展开设备公钥的状态；预览数据为合成数据。

这是 owner 已批准方向的 draft 实现。尚未验证真实邮件、Stripe 扣费、安装包深链、系统钥匙串、双账号端到端加入或跨平台行为。浏览器预览不代表安装包验收。不改变已保存账本或密文格式。
