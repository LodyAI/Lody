# 桌面多窗口的简化实现

Status: proposed
Translation: current

[English](2026-09-10-desktop-windows.md)

## 摘要

多窗口要求旧有主窗口操作按来源分配，否则会出现串导航、关错窗口和重复通知。
本轮复用现有窗口工厂、页面及 CLI，所有开窗交互走一个入口。
后台归属使用 Web Locks 自动释放，不增加选主 IPC、心跳或独立窗口管理类。
实现已写入当前分支；按用户要求移除拖出开窗，托管多工作区仍待实机验收。

## 决策

- 主进程只登记产品窗口并验证 IPC 来源。内嵌浏览器按来源窗口持有，辅助窗口真正关闭。
- 主窗口保留已有存储；辅助窗口独立保存布局与 Repo 缓存，避免多份快照覆盖同一数据库。
- 不删除辅助窗口缓存：窗口销毁不证明待同步写入已完成。应用级清缓存会关闭其他窗口。
- 侧栏隐藏只暂停预取与侧栏子树；不卸载 Task Index。工作区后台检查使用一把互斥锁。
- 拖出开窗因原生事件风险和复杂度暂不实现；删除拖拽 IPC、令牌、原生事件监听和落点定位，恢复原有提及拖拽。
- 只添加能验证状态、释放和安全边界的测试，不添加按钮回调参数或源码字符串断言。
- 右键开窗入口只在 Electron 且工作区有 slug 时包一层 `ContextMenuTrigger`，不再用 `disabled`
  关掉它：Radix 的禁用触发器会把 `data-disabled` 印到被 `asChild` 包裹的菜单项上，
  而共享菜单样式把该属性渲染成 `pointer-events-none`，导致 Web 端工作区切换项整排不可点击。
- 工作区选择器用底部修饰键提示和右键菜单补足开窗入口的可发现性，不增加更多按钮。
  会话菜单按整理、复制/分享、导航、归档排列；展开/收起子会话属于列表整理，放在首项，
  前往来源会话仍留在导航组。低频开窗位于倒数第二项，归档最后。
  三种侧栏列表共用相同顺序，来源会话菜单片段不再自行插入分隔线，避免空组。

## 验证与限制

- 移除拖出开窗前，构建、类型检查、静态/公共边界及文档检查通过；修复后完整 `NODE_ENV=test pnpm test:ci`
  通过，其中组件 3321 项、Electron 104 项。macOS 窗口验收 8 项通过。
- 移除后提交前复测：完整 `NODE_ENV=test pnpm check`、`pnpm format` 通过；未重跑构建和原生 E2E。
- 隔离的 macOS Electron 验收验证了快捷点击、右键开窗、输入焦点、重载布局隔离、
  非法目标拒绝、双向消息同步、唯一后台归属和关闭来源窗口后继续控制 Agent。
- 托管模式下的多工作区、Windows/Linux 和性能收益未实测。
- 删除涉及 MainLayout 的源码字符串扫描测试；新增测试只断言辅助窗口导航不会污染主窗口历史。
- 全量检查发现无 DOM 的 Electron 模拟会触发 `location` 读取错误，已增加环境判断；
  对应恢复与导航的 26 项测试复跑通过。
- 该回归由浏览器路径缺少覆盖造成：原有工作区右键菜单测试只跑 Electron 分支。
  已在同一套件补一项浏览器用例，断言工作区行不带 `data-disabled` 且点击仍会切换。
