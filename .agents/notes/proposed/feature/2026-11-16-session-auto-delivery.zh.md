# 会话自动交付：按用户要求由 Lody 推动 PR 例行步骤

日期：2026-11-16
Status: proposed
Translation: current

[English](2026-11-16-session-auto-delivery.md)

## 摘要

修法商定后，用户反复输入同样的后续指令：开 PR、跑不跑测试、修 CI、解冲突、合入。
自动交付让用户在对话中途把这套例行步骤交给 Lody：从信息栏、会话自动化菜单开启，或
直接对 agent 说。本地 Host 观察 PR 轮询器，逐个发送现有的快捷动作请求；所有 GitHub
改动仍由 agent 完成。它按会话和 PR 显式开启、有次数上限，停下时给出可见原因而不是
重试。

## 决定

- **Lody 按事件逐步推动，而不是一段长指令。** 开场就描述整套流程的提示词，正是
  [2026-11-11 提示词决定](../../implemented/simplification/2026-11-11-agent-prompts-without-workflow.zh.md)
  去掉的流程文字，agent 也容易忘记或自己轮询 CI。现在每一步发送对应按钮本来就会发
  的请求，前加一行来源说明。合入请求只多一个 agent 无法自行对应到这条消息的事实：
  检查通过的 head 提交。
- **在对话中途开启，而不是新建会话时。** 修法商定后由用户决定；新建会话时选策略的
  方案被用户否决。用户在对话里提出时，agent 可以用现有的 `lody_automation configure`
  自行开启，不需要再次确认。
- **合入是给 agent 的请求，不是守护进程的改动。** CLI 的 PR 访问只做观察，本地摘要
  路径不开放任何改动。把合入放进守护进程会改变这条边界；agent 用 `gh` 合入也会遵守
  仓库规则。代价是每次合入多一个很短的 turn。
- **有上限、如实显示。** 每次开启内每类修复三次，每个 head 一次合入。请求后没有推送
  新提交、需要审查、分支落后、PR 关闭或为草稿、合入没有成功，都会停下，并把会话放进
  在侧边栏的会话行上标出。这防止了促成 2026-11-11 决定的那种无人看管的长链。
- **沿用同一套自动化机制。** 自动交付是与合并后归档并列的第四个会话策略。每一轮读取
  PR checkpoint（现在包含 CI 和合入状态），发布一个确定性的 `session.delivery.step`
  事件，策略把它映射为带 `session.group.settled` 条件和当前 head 守卫的
  `agent.invoke`。进度保存在 ledger checkpoint 中；界面读取只在状态转换时写入的
  `SessionMeta.autoDelivery`。
- **不是回到 turn 结束后自动提交。**
  [2026-09-12 upkeep 决定](../../implemented/architecture/2026-09-12-pr-branch-upkeep-without-auto-commit.zh.md)
  否决了用户没有选择的、由 turn 结束驱动的提交 turn。自动交付在用户开启前不发任何
  请求；工作区有未推送内容时只等待，不替用户推送。

## 备选方案

- 新建会话时选择交付策略、项目默认值和本地测试级别：用户选择在对话中途决定，否决了
  这一方案；测试级别在对话里说即可。
- 识别 `until … sleep` 循环并接管：不在本次范围；等 CI 现在由 Lody 负责，消除了轮询
  的主要理由。
- 由守护进程用轮询器凭据合入：理由见上。

## 限制

- 加密工作区没有注册 PR 轮询器，因此拒绝该设置；菜单会说明原因。
- 在多个仓库都有 PR 的会话会以 `multiple_prs` 停下。
- 停下的交付只由会话行自己的标记显示。侧边栏的进行中 / 稍后 / 已完成分组（[侧边栏状态视图](../../../../specs/sidebar-status-view.zh.md)）刻意不按实时状态重排，所以停下的会话不会被挪动；被推迟或已完成的会话只有在该行可见时才看得到标记。
- 验证是合成的：ledger 测试驱动请求顺序、上限、守卫和请求文字。没有在真实仓库、
  GitHub 账号或桌面端运行。
