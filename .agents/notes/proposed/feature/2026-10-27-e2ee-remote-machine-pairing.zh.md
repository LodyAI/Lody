## 摘要

远端机器需要桌面明确批准，但不应获得账号 API key。本候选接入签名限时命令、公钥材料摘要核对、与账本提交共用的取消边界，以及独立机器服务凭据的激活。机器复用已保存证明，并在安装当前密钥前对照原命令核验批准它的前端。独立启动模式只连接该加密工作区。此处交付产品流程候选，真实安装包、平台和已部署服务验收另行进行。

## 信任与持有者

用户将桌面命令传到预期机器。签名覆盖账号、工作区与创世、发起个人设备、成员实例、随机会话、端点、期限和一次性秘密。原命令是独立可信输入，中继回复不能改写这些固定值。两端对完整机器公钥材料、凭据绑定、保护方式和会话范围计算同一摘要。独立授权点击将显示摘要与保存材料核对；文件保管会在批准前披露。

桌面运行时使用已有的逐工作区身份持有者，串行操作独立的远端批准 journal。每次远端 IPC 查找都明确选择工作区，不创建账号 control 身份；身份重置会连同该工作区一起归档远端 journal。本机配对继续使用自己的表。preload 只放行四个具名远端配对接口；真实 bridge 测试覆盖这层入口和 main 的工作区/同意边界。远端 journal 在网络前保存原命令与签名入账原文，只有服务端终态与本机已验证历史，或明确证明没有 writer 预约的取消回执，才能允许归档；后者也覆盖已签名但派发失败的情况。首次服务端 begin 断网且命令过期时，重试会获得可退役的终态回执。新会话始终重新确认。已入账机器通过原有凭据、持钥证明和本次会话凭据签名确认，不再创建账本记录。

CLI 准备和装钥复用现有 custody 持有者。命令持有轮询，取消会中止 HTTP 和等待；原生存储操作结束后才释放其 Scope。断网保留全部原件，同一命令可继续。已经提交的入账不能因取消或期限到达而撤回。后端 writer 事务预留配对会话，验证提交结果后，将投影、服务凭据激活与会话结果一起提交。未知结果只复用原请求和原文。

入账会先以 `admitted` 状态可见，此时机器还没有任何密钥。批准的桌面先追加记录，随后其账本刷新执行 key round，经 mailbox 下发当前 epoch 密钥。之后任一持有当前密钥的已批准桌面再次刷新，都会继续这次下发。机器只有在装好密钥后才自己报告 `ready`，因此命令无法等到 `ready` 再激活。改为：入账后若缺钥（`e2ee_waiting_for_key`），命令继续轮询，退避最长 15 秒，共等待 10 分钟。其他激活错误仍为终态。原先第一次缺钥就退出，普通的下发延迟就会中止配对；若该桌面随后关闭，同一命令重试也无法完成，直到某个已批准桌面再次刷新该工作区。命令现在会明确说明这一点，而不是报告通用失败。

## 服务访问与运行

机器在准备时生成并保护逐工作区随机凭据，中继只收到其哈希。后端在入账验证完成，或用户明确确认同一有效设备后，激活此凭据的机器服务权限。它不是 Better Auth API key。每次窄接口调用都从该授权取得账号，再检查工作区和创世、绑定的有效设备/机器/成员、账号与工作区删除围栏，以及投影与检查点一致性。它不能登录普通账号接口或管理工作区。

服务凭据不设定时到期，撤销、原子替换或移除成员使后续设备请求立即失败。内容 token 仍最多 15 分钟。机器发现只返回绑定的加密工作区，并将撤权状态交给 Fleet。`lody start --paired-workspace <account/workspace>` 先验证设备对路由信息的签名，再重开已保存的受保护凭据和激活标记，关闭普通目录启动，使用没有普通传输、账号 API key、账单、云端 GitHub、通知和遥测能力的受限 cloud port。配对成功自动进入此模式，终端也打印重启命令。加密 RPC/执行继续受独立通道实现限制，配对不会开启明文回退。

## 位置

只有私有 Worker 读取可信 `request.cf` 国家/城市，再通过现有服务签名通道转发完整请求。客户端位置字段和 IP 头不能成为依据。后端不保存原始 IP，不请求第三方。位置有长度限制，明确标为估算；未知或 VPN/中继位置如实显示。完成、取消、冲突和定时过期均清除位置；正在对账的提交在过期后保留原始证据，但删除位置。

## 被撤销机器的重新配对

core 永远不会重新准入设备历史中出现过的 key，因此在停机期间被撤销的机器不得再次提供旧身份。在新的 offer 之前，若该工作区的身份已知被撤销，CLI 会退休它：依据守护进程根据其自身凭据收到的精确 `e2ee_device_revoked` 写下的设备绑定 `revoked-device.json`，或配对时用保留凭据探测得到的同一精确答复。原设备文件改名保留作为历史证据，不删除也不复用，现有替换路径随后生成新的签名和加密身份。其他探测结果均属未知，保留原身份。与成员移除不同，成员资格、内容和其他工作区都不受影响。若桌面仍收到复用的历史 key，会报告 `e2ee_pairing_key_revoked` 而不是 `invalid-input`，页面提示需要新身份。本地配对没有云端探测，依赖该回执。测试使用真实 core 重放检查、桌面远程配对和 CLI offer 路径以及合成云端答复；未声称做过打包后的双机运行。

## 依赖与验证范围

合入 main 的依赖提供 machineId/持钥证明/替换编码、工作区身份隔离、换代收钥和安全恢复错误码。此流程直接使用这些约定，包括逐设备授权的暂存密钥读取；撤销终止访问，投影恢复故障继续返回错误。不再使用依赖覆盖，也不回退格式。后端仍需通过独立私有 gitlink 变更采用本 PR 新增的远端配对 DTO 入口。

具体行为测试和 head 记录在 draft PR。合成密码学/SQLite、确定性后端 handler 和 Worker 签名转发测试，不代表真实钥匙串、两台实体机器、网关部署、安装包构建或产品验收。此工作不合入、不部署。已有 Promise 命令/custody 兼容层继续作为临时应用边界，本变更不宣称完成 Fleet 或工作区 Effect 迁移。
