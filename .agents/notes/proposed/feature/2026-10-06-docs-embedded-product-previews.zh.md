# 文档内嵌真实产品预览

Status: proposed
Translation: current
Language: [English](2026-10-06-docs-embedded-product-previews.md)

## 摘要

文档截图比它描述的产品界面老化得更快：会话页仍在使用旧版多行会话列表截图，
其中分支和 diff 信息直接显示在行内；而产品早已改为单行列表，并把这类信息移进
会话详情卡。本变更在 `components/docs-replica/` 下新增站点自有、仅用于展示的
预览组件，用合成 mock 数据在两种语言和明暗主题下渲染，注册为
`SessionListPreview`，并替换过期的会话列表截图；归档和删除截图仍然相符，因此保留。
该副本是拷贝的产品 markup，而不是直接引用产品组件，所以仍可能漂移，产品外观明显
变化时需要重新拷贝。

## 问题

- 文档图片是静态的，容易过期。会话列表截图已经不正确：它展示多行行内分支和
  diff，而产品现在渲染单行，并把这些信息移到会话详情悬停卡中。
- 截图无法跟随读者的明暗主题，深色图片可能出现在浅色文档页里。
- 每次界面变化都需要重新截图、提交位图资源，漏掉一次就会静默发布错误界面。
- 站点不能直接引用产品组件：独立副本规则和 `scripts/app-boundary.mjs` 会把
  产品专用模块、provider 和包挡在公开构建之外。

## 决策

- 新增 `components/docs-replica/session-list-preview.tsx`，从产品当前的
  `session-list.tsx` 拷贝 markup 和 class，做成仅展示的副本。它只接受 `locale`，
  自行构造合成数据，不引用任何产品代码。
- 用现有的 `.lody-app-preview` token 作用域渲染，使其跟随站点明暗主题。
- 在 `components/mdx.tsx` 中注册为 `SessionListPreview`，替换中英文会话页里的
  `<img src="/_docs-assets/session-list.png" />`，并删除不再使用的资源。
- 按当前的单行会话行建模；由于静态文档页无法复现产品的悬停行为，将会话详情卡
  作为列表旁的固定面板展示。卡片包含仓库、工作树分支、机器、PR 状态、CI 结论和
  ±行数，与周边正文承诺的信息一致。
- 保留归档与删除截图；它们仍然相符，不在本次范围内。

## 考虑过的替代方案

1. 保留截图并重新截取。否决：下一次界面变化会再次带来同样的漂移和主题不一致。
2. 像早前落地页那样，通过 shim 引用真实产品组件。否决：这正是独立副本记录要
   移除的耦合；`scripts/app-boundary.mjs` 会因此让构建失败，产品 hook 或
   provider 也会让文档页面空白。
3. 做成带真实悬停行为的交互副本。暂不采用：静态图示让预渲染 HTML 保持确定性，
   无障碍面也更小。后续文档页确有需要时再加交互。
4. 在出现第二个用例前先做通用预览框架。否决：一个组件加共享 token 作用域已经
   足以验证模式；等第二个预览出现时再抽公共机制。

## 验证与边界

- `pnpm --filter @lody/site-docs generate`、`typecheck` 和 `test` 通过（28 个
  测试），其中包含 `scripts/app-boundary.mjs`。
- 生产构建预渲染 257 个 HTML 页面。中英文会话页的预渲染 HTML 中存在预览
  markup，被删除的段落文本和资源已不存在。
- 预览已在中英文、明暗主题、桌面和移动宽度下做过目视检查。
- 全量静态浏览器套件报告 309 个通过用例，以及变更前后相同的两个移动端
  `no-js navigation` 基线超时。
- 副本拷贝的是某一时刻的 markup，不会自动跟随产品变化。会话列表明显变化时需要
  重新拷贝，并同步更新周边文档正文。
- 本次只替换了会话列表图片。其他文档截图（归档、删除、Agent 配置、diff 等）
  仍在，可以按界面逐个转换。
