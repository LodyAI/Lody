# Codex 原生会话归档同步

Status: proposed
Translation: current

[English](2026-11-03-codex-native-session-archive.md)

## 摘要

Lody 归档对话时目前只释放运行时，对应的 Codex 线程仍可能处于活动状态。本改动通过 Codex app-server 的生命周期接口，将已提交的归档和恢复状态同步到精确对应的原生线程。所属机器解析保存的 Provider 和账号目录，原生同步失败会显示警告，同时保留 Lody 清理能力。首版覆盖内置 Codex，历史补归档和通用 Provider 能力契约另行处理。

## 所有权与顺序

`MessageHandler` 观察已提交的归档元数据，并合并清理期间到达的后续变更。`SessionManager` 按 Lody Session 串行执行原生操作，每次操作前重新读取元数据。归档在运行时终止后执行，原生冷恢复使用同一串行队列，在启动 ACP 前请求解除归档。已删除记录、其他机器、缺失的原生 ID、不支持的 Provider 或已被后续变更取代的归档状态，都不会授权原生修改。

原生进程使用选定账号的环境和进程使用凭据，不恢复执行对话，也不发起模型轮次。请求预算为 30 秒，完成或失败后由共享进程所有者在有界等待内终止进程树。释放失败时保留进程所有者的错误和账号使用记录。同步失败通过已有的 agent warning 展示，文档清理继续进行。后续归档或恢复可以重试，不缓存失败。

## 原生状态与替代方案

Codex 的 rollout 移动后，再次调用 `thread/archive` 会失败。同步器先调用 `thread/read`，核对返回的原生 ID，并将其路径与选定账号目录内的 `sessions` 和 `archived_sessions` 根目录比较。状态已经匹配时不再修改，无法识别的存储路径会报告失败，标题和工作目录均不作为线程身份。

直接更新 SQLite 或移动 rollout 会绕过原生索引和文件生命周期，因此不采用。扩展 ACP Core 和所有适配器会把本次 Codex 改动扩大为独立的协议设计。现有 daemon 编排仍基于 Promise，新传输复用共享进程的 legacy facade，不将其描述为上层生命周期迁移。

## 验证边界

合成子进程测试覆盖原生归档和恢复、重复观察、身份拒绝、失败和取消。SessionManager 的所属测试覆盖机器、Provider 和状态保护、账号目录选择、失败后的文档清理以及串行恢复。其他 Provider、早于本功能的历史归档自动对账，以及持久化成功或等待状态的界面，需要另行实现，因此关联功能请求继续保持开放。
