## 摘要

本次升级 Claude、Codex、Grok、Kimi 和 Pi，并在现有凭据和已安装运行时允许的范围内验证每个内置 provider。共发布 22 个不可变运行时产物，回读完整性校验通过后才更新清单。集成测试暴露了 Kimi 启动与删除会话的竞争问题，独立构建暴露了 Pi 打包中的绝对临时软链接，两者均已修复。应所有者要求再次核实后，Codex 继续升级至 0.156.0。Kimi/Dimcode 的认证对话和安装后的 Bub 仍未验证，本次工作不包含主分支合并或 Lody 应用发版。

## 兼容性修复

- Kimi 现有 ACP 生命周期测试复现了已删除会话在初始索引投影期间重新出现的问题。移除前现会等待准备和投影完成。完整 ACP 测试从 180 通过、1 失败变为 181 通过，所属索引测试也通过。所有者在提交前确认了 patch changeset 文案。已发布的上游 2.0.2 提交 `9d07f634` 集成于源码提交 `d4caf044fe0c3c12aa8496f9fa442643d521e479`。
- Codex 0.156.0 的未认证账号响应新增 `workspaceRouting: null`，所属快照已更新，同时保留认证失败断言。旧的项目恢复错误断言现包含实现中已有的项目路径，没有改变生产行为。
- 两次独立 Pi 构建仅有 20 个 `.bin` 软链接不同，它们被改写成了绝对临时构建路径。打包现保留相对依赖链接、排除安装时命令链接，并拒绝绝对、越界或悬空链接。5 个真实文件系统回归测试覆盖迁移后的链接和失败路径。修复后的两次独立构建均得到 SHA-256 `0942748a1ca3b6d6eb083ef4ed6717f07838b2479f8dfb7e913f47efe58ce4f2`，大小 37,201,691 字节。最终清单引用修复对象，不引用先前上传的对象；不覆盖不可变对象。

## 发布与宿主检查

所有者明确授权了任务分支推送和生产发布。遵守[产物先行流程](2026-09-17-managed-runtime-refresh.zh.md)：校验官方来源或干净提交，发布版本化对象，回读哈希和大小，再切换清单。Claude 有 8 个目标，Codex/Grok 各 6 个，Kimi/Pi 各 1 个可移植包。公共下载检查通过；Grok、Kimi、Pi 完整下载校验，Claude/Codex 公共 HEAD 大小与 R2 已校验归档一致。Kimi 干净包版本为 `2.0.2-lody.d4caf044fe0c`，SHA-256 为 `9815b2b309f842e7880385555c46bc80f77a802190c9e733398d3143272f686a`。

Pi 精确源码 `e6debc2f6aaca6f0fd3409f6dd36468a8fba8a8f` 通过 [Linux 和 Windows x64/arm64 CI](https://github.com/LodyAI/acp-extension-pi/actions/runs/35764930929)，包括 Node 22、24 下的安装包 smoke。可移植归档包含该 CI 的两个原生二进制。[草稿 PR](https://github.com/LodyAI/acp-extension-pi/pull/3) 尚未合并。

安装锁定版本 Electron 后，完整根 `pnpm check` 和 `pnpm format` 通过，其中包括 2863 个 CLI 测试（3 个跳过）、3895 个组件测试和 168 个 Electron 测试。打包修复的全部 33 个脚本测试及 lint 通过。正常宿主测试使用最终清单，而非临时候选别名。冻结安装、文档和公共边界检查通过。发布时间隔离例外仅限选定运行时包，已移除无关的间接依赖锁文件升级。未提交捕获的对话记录。

## 限制

Kimi、Dimcode 需要凭据才能验证认证对话；Bub 由用户自行安装，本机缺失。这些限制不计为端到端测试成功。平台产物完整性校验不等于每个操作系统的执行测试；只有 Pi 额外具备上述 Windows CI 证据。产物发布不代表主分支已合并或应用已发版。
