# 明确 Agent Note 的更新条件

Status: implemented
Translation: current

[English](2026-09-07-explicit-agent-note-triggers.md) | 中文

## 摘要

仅间接要求记录重要取舍，容易漏掉没有代码改动的设计结论。根说明现在直接要求非简单工作更新 Agent Note，并链接明确的触发条件和豁免范围。已有主题优先更新原记录，不同决策另建相互关联的记录。这明确了贡献者义务，但没有新增能够判断改动是否属于非简单工作的自动检查。

## 决定与范围

[Note 规则](../../AGENTS.md#when-to-write) 统一定义触发条件，包括调查、设计结论及明确禁止文件写入的任务。根说明直接展示要求，收尾流程同时检查代码 diff 和设计结论。提案在被采纳并实施前仍是提案。公开 note 保存可公开的理由，不保存私有对话原文。

根维护清单还直接列出开工前应读的 Specs、notes、docs 和 README，说明意图改变时 Spec 退回草案，以及检查通过不能代替有链接的人工批准。详细流程仍保留在原文档中。目录写入的解释性文字移到[独立说明](../../../docs/workspace-catalog-durability.md)，所有对应业务约束仍在根文件中，为清单腾出空间且不提高大小限制。

本次细化此前[文档维护提案](../../proposed/process/2026-09-05-human-reviewed-spec-maintenance.zh.md)中的 note 更新门槛，不改变其翻译、Spec 审批和历史保留规则。根说明的目录清单改为链接 README 中的仓库导航，为规则腾出空间，不删除业务约束，也不提高大小限制。

## 方案与影响

- 保留间接的“按重要性记录”：文字较少，但容易因未改代码而漏记调查结论。明确条件更便于执行和复核，代价是某些改动虽小，只要涉及实质决定也需要记录。
- 每次修改都新建 note：容易机械执行，但会重复已有决策，并增加修正错字或格式的负担。更新原记录即可满足要求；未改变决定的机械或纯局部修改仍豁免。
- 整套复制其他项目的文档政策：会同时改变归档、翻译和验证要求。本次只采用明确触发条件的写法，保留 Lody 的其他政策。

## 验证边界

文档检查覆盖链接、元数据和说明文件大小，不能判断是否履行了记录决策的义务。本次仅修改文档，不构成任何产品性能验证，也不批准此前的整体维护提案。
