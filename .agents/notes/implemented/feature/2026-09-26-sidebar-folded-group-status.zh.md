# 折叠的侧边栏分组保留其中 Session 的状态

Status: implemented
Translation: current

[English](2026-09-26-sidebar-folded-group-status.md)

## 摘要

在侧边栏折叠项目、仓库、设备或分区，会把其中所有 Session 一起藏起来，包括正在等待授权的那个；折叠因此成了漏看待办的途径。现在，折叠的分组在与行状态相同的右侧列里画一个状态标记，按行本身的优先级（等待授权 > 运行中 > 未读）选取；各状态的数量放在悬停提示和读屏标签里。这是有意的取舍：扫一眼回答"这里面有没有需要我的？"，悬停回答"有多少？"，展开回答"是哪些？"。展开的分组不画任何东西，因为它的行已经在表达。只在 jsdom 测试和 Storybook 截图中验证过，没有用户数据。

## 问题

- 在此改动之前，折叠的标题只画图标、名称和箭头。`SidebarSectionHeader` 还保留着一个 `count` 属性，但它的徽标早已删除；[侧边栏分组记录](2026-09-25-deep-sea-palette-and-sidebar-groups.zh.md)把"折叠分组的活动点"列为未完成。
- 队友的设备默认折叠，所以在那里运行的 Session 默认看不见。
- 矛盾在于信息密度与视觉负担。若标题逐一列出各状态（三个标记或数字），就等于把用户折叠掉的行又复述一遍，而这一列每行最多只画一个 14px 标记。

## 决定

- 每个折叠分组只画一个标记，由 `SidebarGroupActivityMark`（`sidebar-row-shared.tsx`）绘制。它复用行的 `SessionRowStatusIndicator`，所以手形、运行网格和未读圆点与行上的完全一样，没有新符号要学。
- 优先级就是行的优先级。`summarizeSidebarGroupActivity` 让每个 Session 只计一次，计入它那一行会画的标记，所以各数量之和就是正在请求注意的行数。与行一样，运行中高于未读：只要有东西在运行，分组就仍在忙；运行停止后未读圆点会回来。
- 标记位于标题的右端，也就是行的状态列。截图确认，折叠标题与行的标记距侧边栏边缘同为 27px。悬停操作（⋯、新对话）在它左侧淡入，标记位置不变。
- 数量（"1 个等待授权 · 2 个运行中 · 3 个未读"，为零的项省略）在每种标题上只有一个位置：
  - 项目行把它追加到已有的路径提示和 aria-label 中。
  - 设备标题把它放进已接管悬停的设备卡片，作为一行"动态"，行首是同一个标记。
  - 仓库、Chats、GitHub Worktrees、Pinned 和 Updated 的标题自己没有悬停层，所以由标记自带提示。

  同一标题上的两个悬停层会同时弹出，所以一个标题不会有第二个悬停层。

- 分组折叠期间，标记始终挂载，并运行与行相同的 `useWorkingHandOver`。最后一个运行中的 Session 结束并产生新输出时，标题播放与行相同的"运行 → 未读"过渡；运行停止且没有未读时，网格保持 1.5 秒后消失。
- 状态只覆盖折叠所隐藏的内容。项目中置顶的 Session 仍显示在 Pinned 里，所以不计入该项目。折叠的 GitHub Worktrees 分区统计所有仓库的 Session；折叠的设备统计它所有项目的 Session，子 Tab 的汇总方式与行完全相同。
- 只为折叠的分组计算，使用各列表已有的数据（`liveSessionStatuses`、行上的标志），没有新增 presence 订阅。

## 备选方案

- **在标题上显示数量**（每种状态一个数字或胶囊）：这等于恢复已被删除的计数徽标，而且胶囊在这里显得像装饰。否决。
- **每种状态一个标记并排**：三个标记会让折叠标题比被它取代的行更嘈杂，也打破了每行一个标记的状态列。否决。
- **未读时加粗或着色标签**（聊天应用的惯例）：这会引入与行不一致的第二个通道，而且无法表达运行中或等待授权。否决。
- **名称前加圆点**：侧边栏分组记录已经否决过设备名前的状态点，因为它会让分组看起来像另一类分区；前导位置还放着文件夹图标和头像。否决。
- **有待办时自动展开分组**：这会推翻用户的选择，还会让列表在指针下移动。否决。

## 验证与局限

- `tests/sidebar-local-project-row.test.tsx`：折叠的项目显示优先级最高的标记，aria-label 带有数量；标记随实时状态变化，运行结束后停在未读圆点上；展开的项目或无事发生的项目不画任何东西。
- `tests/session-list-pr-badge.test.ts`：折叠的仓库分组显示运行网格和数量；运行停止后，网格在交接窗口内保持，然后清除。
- `tests/sidebar-machine-card.test.tsx`：分区标题只在折叠时画标记，等待授权高于运行中，设备卡片列出数量。
- Storybook：`Components/Sidebar/Folded Group Status`（Folded、Side by side）已在浅色和深色主题下检查过，两种悬停层都看过。
- 未完成：
  - "Show all (N)" 行和折叠的开启者（opened-by 折叠）同样会隐藏行，它们还没有带上所隐藏内容的状态。
  - 移动端首页仍使用自己的未读计数胶囊。
