# 队列反转与直接操作

Status: implemented
Translation: current

[English](2026-09-13-queue-steer-controls.md)

## 摘要

此前若要在“排队”和“引导”间切换，必须修改持久设置；后续队列项不显示“引导”，重排也只能
从狭小的左侧把手开始。本次采用一次性反转提交命令、让每行都显示“引导”，并把消息内容区
作为拖动区域。对于没有原生带确认 steer 的 Provider，兼容路径会在取消前先把所选后续项移到
队首；如果重排失败，则不触碰当前 turn。

## 决策

- 在命令系统注册 `session.sendWithInverseQueueBehavior`，默认仅在输入框聚焦时由
  `Mod+Shift+Enter` 触发。输入框传递显式的单次提交选项；路由器只反转本次有效偏好，
  不写入设置，也不绕过活动状态保护。
- 会话允许引导时，每一行都显示“引导”。原生 steer 继续按身份生成历史并移除所选项；
  兼容路径仍只有一个队列消费者：先把所选项移到队首，再沿用取消与队列提升流程。
- 左侧序号和消息正文合并为一个支持鼠标及键盘的拖动区域。操作按钮保持在区域外；编辑器
  接管交互时禁用该行拖动。

## 备选方案与取舍

只允许队首“引导”可维持旧兼容路径假设，但用户仍必须额外重排。没有采用新的直接发送路径
来发送兼容模式下的所选项，因为这会复制 daemon 的队列提升职责并增加第二个顺序边界。
也没有让整行都可拖动，因为那会使“引导”、“编辑”和“移除”成为意外的拖动起点。

## 验证与边界

- 路由测试覆盖 prompt 活动时“排队 → 引导”和“引导 → 排队”的反转。
- 命令注册测试覆盖 Web 与 Electron 环境中的默认快捷键。
- 队列组件测试覆盖对后续项执行“引导”，并验证消息内容属于拖动区域而操作按钮不属于。
  队列 steer 测试覆盖后续项准备、已在队首的项以及过期选择。
- 组件测试使用合成指针状态；未验证物理触摸拖动和完整的 Provider-backed steer 流程。
