# 从输入区恢复已归档的会话

Status: implemented
Translation: current

[English](2026-11-03-archived-session-composer-restore.md)

## 摘要

已归档会话的输入框提示用户先恢复，但恢复操作原先藏在顶部菜单或归档列表。输入区现在在提示旁提供既有恢复操作，并在请求进行时防止重复点击。归档工作区的每个标签页都调用工作区原有的恢复处理，保留草稿和标签页关闭状态。顶部菜单仍可使用，失败时沿用既有提示。

## 决策与范围

用户比较顶部按钮与输入区入口后，更倾向于把操作放在解释无法继续聊天的位置。仅当宿主提供恢复操作时，输入区才用恢复按钮替换禁用的发送按钮。工作区把原有处理传给每个会话界面，包括子标签页和侧边聊天，避免只恢复当前子会话；本地项目可用性检查和错误提示仍由原有处理负责。

本方案基于[归档与标签页关闭独立](../bug-fix/2026-09-24-archive-independent-of-tab-close.zh.md)：恢复仍须用户明确操作，且不会更改标签页关闭状态。输入区保持挂载，以保留草稿。顶部增加按钮的方案离解释更远，因此没有采用。

## 验证

现有输入区提交测试覆盖归档时禁用输入、请求期间只发起一次恢复、草稿保留，以及恢复后按钮消失。Archived Storybook 状态使用合成数据渲染生产输入区。本记录不宣称已在原生移动端外壳验证。

另在隔离的开发版桌面应用中使用脚本模拟 Agent，创建并归档示例会话，再从归档列表打开并点击输入区恢复按钮。会话重新出现在侧边栏，输入框恢复可编辑。启动预览时须暂时移除桌面开发构建中一个已删除的自动化 worker 入口；预览后已恢复该源码入口。
