# 让分享读取页可导航，并给对话面板一个真正的底部

Status: implemented
Translation: current

[English](2026-09-14-share-reader-navigation-and-foot.md)

## 摘要

四处缺陷让匿名分享读取页更像产品的仿制品，而不是一个用来阅读已发布对话的页面：
对话树的选中行使用 `bg-accent`，而 `--accent` 并不是本项目的主题令牌，该工具类
解析不出任何背景色，于是从来没有任何一行被标记；侧栏开关直接挂载/卸载对话树，
而被卸载的元素无法做过渡，因此它只会闪现并把正文横向挤开；每次切换对话都会重新
拉取一份按设计就不可变的历史，于是在树里走回头路又要再等一次；面板底部则是产品
输入框的复制品，inert 且 `aria-hidden`，两个真实动作浮在它上面，在一个只有正文
的页面上占掉约 150px。现在对话树用 `foreground` 给当前面板所属的根对话着色，
侧栏保持行挂载、关闭时 `inert` 并对宽度做动画，已完成的读取会在一个 `StaticShare`
的生命周期内保留在内存中，底部则是一行简短的动作区。该缓存只在内存中、只覆盖历史
——附件在每次切换时仍会重新读取，刷新后一切不保留。

## 决策

### 对话树根本没有选中态

`session-share-page.tsx` 用 `bg-accent` 标记选中行、用 `hover:bg-accent/50` 标记悬停。
`--accent` 在本仓库中没有任何定义：`packages/configs/tailwind-preset.cjs` 把该工具类映射为
`hsl(var(--accent) / <alpha-value>)`，而 `components/tasks/task-body-editor-surface.tsx`
中已有注释写明“`--accent` 不是应用令牌”。未定义的自定义属性会让声明在计算值阶段失效，
`background-color` 因此回落到 `transparent`：这一行自对话树上线起，在两种主题下都套着
一条什么也画不出来的规则。

现在该行以读取页自身 `foreground` 的 10% 着色并配同色边框，这正是应用侧栏标记选中会话行
所用的形态（那里是 `bg-sidebar-foreground/10`）；未选中的标题降为 `text-muted-foreground`，
让被标记的那一行读起来是“当前位置”，而不是若干等价行之一。`aria-current="page"` 原本就正确，
未做改动，缺的只是可见的那一半。

这个标记的含义值得说明，因为对话树和标签栏命名的是不同的东西。树中是独立对话，子 Tab 由
面板内的 `tab-pill-strip.tsx` 命名。因此树标记的是 `panes.root`——当前面板所属的那个对话，
选中一个子 Tab 会让该树条目保持点亮，而不是清空树的选中态。

### 条件渲染的元素做不了动画

侧栏原本写作 `{hasTree && treeVisible && <nav …>}`。收起时 React 会卸载该元素，于是没有任何
盒子可供过渡，正文在一帧之内直接跳进空出来的位置。

现在只要 `hasTree`，`nav` 就始终挂载，裁剪内容（`overflow-hidden`），并在 `sm:w-56` 与
`sm:w-0` 之间做宽度动画。行位于一个保持自身 `w-56` 的内层列中，因此它们是从裁剪盒中滑出，
而不是在过程中回流成一字宽的窄列；右边框也随内容一起移走，不会在零宽度时留下一条 1px 的线。
收起的树带 `inert`，把 Tab 键与点击挡在这份仍在 DOM 中、却已移出视野的列表之外；
`motion-reduce:transition-none` 则为明确要求减少动效的访客关闭该动画。

### 重复读取不可变的历史

`useShareConversation` 会按 `conversationId` 新建读取器，并在每次变化时重置为 loading 快照。
已发布的部署是不可变的——这正是静态分享的前提，读取者也会把所有对象固定到同一个部署——
因此一个加载过一次的对话，之后不可能给出不同答案。重新拉取只换来一个加载态。

现在已完成的读取保存在一个按对话为键的 `Map` 中，作用域是单个 `StaticShare` 对象。查表发生在
渲染期，因此重新进入时正文与该次提交一起出现，而不会先闪一下加载态。只有 `ready` 的读取可以复用：
`unavailable` 的会在返回时重试，因为这里的失败也可能只是一次瞬时网络故障，把这个判定钉死在整个
页面生命周期会让访客无路可走。新的部署、重置链接或更换凭据都会产生新的 share 对象，该 map 会在
接纳它的同一次渲染中清空——缓存不会比它所依据的授权活得更久。

这是内存，而不是读取端被禁止创建的本地持久化历史缓存：不写入任何存储，刷新后全部重新读取。

## 备选方案

暂不连同附件一起缓存。图片在每次切换对话时都会重新读取，重新进入时确实会闪出
“Loading attachment…”占位，因此从访客视角看这个修复并不完整。但单个部署上限为 256MB、
单个对象上限为 100MB，无上限的 blob 缓存可能为一个被完整浏览过的分享保留四分之一 GB 的
解码图片，还会留下一批需要按某种无人负责的时机撤销的 object URL。那需要一个明确的上限
和它自己的决策；历史本身很小、受 32 个对话的上限约束，也正是这次反馈所指的东西。

保持对话树挂载但改为对 `opacity` 做动画可以避免裁剪盒，但正文不会收回空间，而那正是收起
侧栏的目的。

为读取页单独定义一个 `--accent` 值被否决：应用一直有意不定义它，在这里补上只会让
`bg-accent` 在分享页生效，而在其它所有使用它的位置继续静默失效。

## 证据与局限

`tests/session-share-page.test.tsx` 新增三个行为用例，原有十三个保留。缓存用例驱动真实的
`SessionSharePage`，其 `readHistory` 会记录每次调用，之后被设为永不返回：在访问第二个对话
并返回后，没有发出第三次读取，Markdown 导出立即可用并复制出第一个对话的文本。撤掉缓存后
它会以 `['c1','c3','c1']` 失败，说明它检出的是回归，而不是在复述实现。选中态用例断言树的
`aria-current` 跟随当前面板，并在选中子 Tab 时停留在根对话上。侧栏用例断言行保持挂载、
收起后的 `nav` 带 `inert`。

jsdom 不计算样式，因此没有测试能看出 `bg-accent` 什么也没画、或者侧栏是否在滑动。这些是在
Chromium 中对照新增的 `Sharing/SessionShareReader` stories 复核的——它们只用 props 驱动
`SessionShareSurface`，不涉及分享客户端：明暗两种主题、1280px 与 390px、带树、单对话，
以及正文仍在加载的状态。在那里测得：被标记的行解析出真实的 `oklab(… / 0.1)` 背景，而未选中行
是 `rgba(0,0,0,0)`；`nav` 带有 `width 0.2s cubic-bezier(0,0,0.2,1)`，收起过程中宽度在
165→95→51→24→8→0px 之间过渡；关闭后它带 `inert`。底部动作行在 1280px 下实测 67.75px（`border-top-width: 0px`），
原先的仿输入框约为 152px。它与正文之间不画分隔线：不透明背景已经够用，一条边框会被
读成第二条标签栏。

`tsgo --noEmit`、oxlint 与 `node scripts/check-i18n.mjs` 通过，`pnpm run docs check`
无 error。`@lody/components` 全量套件 476 个文件中 474 个通过；`control-plane-mirror`
与 `conversation-view-hooks` 在全量并行负载下撞上 5s 默认超时，单独运行通过，且两者都
不引用本次改动涉及的任何内容。未运行完整的 workspace `pnpm check`。

局限：如上所述，附件读取未做缓存。缓存没有淘汰策略——它只受 manifest 的 32 个对话上限约束，
一个包含 32 份大历史的分享在全部访问过之后会把它们都留在内存里。未验证任何托管部署；
stories 与测试使用的都是合成 fixture。

`packages/components/src/components/sharing/AGENTS.md` 现为 8185 字节，而门限是 8192 字节。
它在本次改动之前就已越过 7000 字节的分流警告，下一位贡献者在新增规则前必须先把一个主题移出去。

本文取代[读取页布局笔记](2026-09-09-session-share-dialog-and-reader-layout.zh.md)中描述的面板底部；
该笔记关于对话框的决策不变。
