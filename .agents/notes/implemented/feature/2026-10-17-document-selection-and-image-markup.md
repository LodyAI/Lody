# Document selections and image markup in chat

Status: implemented
Translation: current

[中文](2026-10-17-document-selection-and-image-markup.zh.md)

## Abstract

Session file previews can now stage selected PDF/Office text, spreadsheet cells, or a screenshot region with a comment in the session's chat composer. Existing screenshot attachments can be marked up before sending, replacing their original draft image only after acceptance. Source names, page/slide/cell locations and comments expand through the existing text-draft path; images use the existing attachment path. Reading controls share one compact toolbar; feedback opens beside its highlighted source instead of replacing the preview. This implements selection feedback without introducing a new persisted input type. The references are captured context snapshots, not durable document anchors that can reopen the exact source range after the file changes.

## Decision and ownership

The [binary preview](../../../../packages/components/src/components/sessions/session-file-binary-preview.tsx) and CSV preview entry opt into `DocumentSelectionSurface` only with a matching chat callback. PDF and DOCX text use native selection; page intersections provide location labels. PPTX reports mounted slide identities. XLSX uses its worker-backed bounded selection reader and records worksheet/A1 range; CSV uses its existing bounded rows. These extend the [Office viewer decision](2026-09-29-session-office-and-table-viewers.md), [PDF controls decision](2026-09-29-session-pdf-viewer-controls.md), and [spreadsheet controls decision](2026-10-09-spreadsheet-preview-controls.md).

[Document selection helpers](../../../../packages/components/src/lib/document-selection.ts) own context formatting, visible-region geometry and capture. SnapDOM is already installed; its clipped capture reads the authorized preview DOM/canvases, excludes the selection overlay and disables capture caching. A visual correction removed the initial hardcoded 1× rasterization and image downsampling: capture now follows the display pixel ratio, reducing that ratio only to remain within the 4 MP output budget. CSS preview size and markup stroke size remain logical dimensions. Rebuilding an auto-centered PDF reader had also shifted the crop horizontally; each intersecting PDF page is now captured in its own coordinates, retaining its DOM annotation layers, and cross-page selections compose those patches over the surrounding capture. This preserves source alignment without replacing PDF markup with a raw-canvas-only image. The capture target is the selected file preview, not a browser tab or desktop window. No Electron screenshot permission, browser capture API, additional cloud operation, dependency upgrade or protocol capability was added.

[The editor](../../../../packages/components/src/components/sessions/document-selection-editor.tsx) presents a screenshot preview, an optional comment and an explicit Add to chat action. Document selections use that feedback flow; only the separate existing-image attachment dialog opts into pen, rectangle, arrow and undo controls. The session composer owns acceptance. It stages a collapsed, editable text reference with the source path/location and optional image through the existing pasted-text spans and image draft collection. Original prompt text and references survive rejected submission. Archived, pending-send, unavailable-chat, image-capability and attachment-limit rejection leave the editor available to cancel/retry.

Selection actions share each viewer's existing reading toolbar, using the dashed-square pointer icon for region selection; image-only previews have a floating action. Native text selection opens a small anchored composer without stealing selection focus. Its retained highlights follow the source through scroll/zoom, and a typed draft hides while its source is offscreen and reappears on return. Empty feedback dismisses on an outside click; typed feedback remains until acceptance or cancellation. Cmd/Ctrl+I focuses the comment; Cmd/Ctrl+Enter stages the selection. Feedback uses space beside the selected region where it fits. PDF rotation moves into More, zoom steps move there in narrow panes, and PDF/CSV search opens below the reading row. Inspection of the installed Codex PDF module found source/region comments, with a separate markup/comment entry in its standalone image editor. Lody's pen, rectangle and arrow tools are additions for existing image attachments, with visible names and a drawing hint; they are not claimed as Codex PDF behavior.

This revision was informed by OpenSeek's recent changes: [shared anchored document feedback (#1952)](https://github.com/moonbitlang/openseek/pull/1952), [compact Office controls and search on focus (#2036)](https://github.com/moonbitlang/openseek/pull/2036), [theme integration (#2037)](https://github.com/moonbitlang/openseek/pull/2037), and [icon-only region annotations (#2040)](https://github.com/moonbitlang/openseek/pull/2040). Its diffs, including retained selection highlights and offscreen draft handling, were read as interaction references. The implementation uses Lody's own React, viewer, and composer boundaries; upstream source was not copied. OpenSeek's wider document pane default (#2035) was considered; this scope retains the user's saved Lody panel sizing and checks compact controls at narrow widths instead.

The in-session image thumbnail's markup action opens [the image dialog](../../../../packages/components/src/components/sessions/pending-image-markup-dialog.tsx) using the attachment's File. Cancel preserves the original. Acceptance replaces that one image draft, releases its old preview URL and adds a source/comment reference when a comment is provided. It does not upload or send. Landing-page and already-sent image viewers retain their existing behavior; [image export actions](../../../../specs/image-preview-actions.md) remain a separate concern.

## Lifecycle and bounds

- Trigger: native text selection, selected-cell annotation, an explicit region drag, or a draft-image markup action.
- Owner: the active file surface owns capture/preparation and its editor. The session composer owns accepted text and attachment drafts.
- Cancellation: changing file/source or hiding the surface aborts the result waiter and discards its editor. Scroll cancels an unfinished capture. Pointer cancellation/Escape cancels selection; Cancel dismisses the editor. Image source changes/unmount fence decoding and encoding results. SnapDOM has no cooperative abort API: the bounded raw capture settles independently, and aborted results are never staged.
- Handoff: Add to chat reports success only after the matching composer accepts the draft. Document images and context travel through existing send/upload acceptance. Editing an existing attachment checks that the exact original File is still owned by that session before replacement.
- Failure/recovery: capture, encoding and handoff failures remain visible without clearing the selected context. Submission failure retains the ordinary composer drafts. No second send or durable-history writer was introduced.

Selection text is limited to 50,000 characters, comments to 10,000 and screenshot canvases to 4 megapixels. Existing attachment validation still applies. Whole-image markup scales larger attachment images down to the canvas budget. Office reads, workers and virtualization remain as before; PDF transport remains ranged and its viewer canvas limit remains unchanged. These React-owned DOM interactions change no Effect orchestration unit or migration ledger entry.

## Alternatives and remaining scope

Manual clipboard/OS screenshot workflows remain available, but lose source context. A new document-reference input block would provide richer navigation and revision-aware anchors, but would require coordinated schema, replay and CLI changes. This implementation deliberately uses the current text/image input contract. It records visible screenshot coordinates as capture context, without promising to re-resolve them after zoom, navigation or source edits.

The installed Codex/ChatGPT Desktop `26.1007.71326` informed the interaction: its inspected modules keep document-specific locations, PDF region crops and image markup with prompt text. Lody uses its own preview and draft boundaries; no vendor source or captured user content was copied. Whole-desktop screenshot acquisition, OCR, document editing and annotations written back into Office/PDF files are outside this change.
