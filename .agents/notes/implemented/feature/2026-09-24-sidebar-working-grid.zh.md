# 用"共享海面"方块网格替换侧边栏的工作转圈

Status: implemented
Translation: current

[English](2026-09-24-sidebar-working-grid.md)

## 摘要

侧边栏原来用旋转的 `Loader2` 圆弧表示会话正在运行，它读起来像"加载中"，而不是"Agent 正在工作"；列表里五六个转圈还各转各的。现在的标记是 `WorkingGrid`：一个 3×3 的方块网格，随整个页面共享的一片海起伏。几道来自不同方向的长波轮流占主导，所以水流的方向会不断变化；每个方块按自己在页面上的位置取样，所以相邻行像同一片水一起运动。挂载时，每个方块在这片海 36 秒循环里的起伏被预先烘焙成一个只改 `transform` 和 `opacity` 的 Web Animation，起点固定在文档时间线上，由合成器播放，每帧不跑脚本。尚未测量：在打包后的应用里，每个标记 9 个动画图层的渲染开销。

## 问题

- 转圈的含义是"请等我"；而会话在工作的含义是"我正在替你忙"。产品希望它更安静、更贴合品牌（水母、水），同时保持专业感。
- 同一列表里多个转圈不同步，会吸引视线。作为一个整体一起运动的标记，比各自闪动的标记更安静。
- 任何替代方案都必须遵守 [spinner 笔记](../bug-fix/2026-09-13-spinner-off-svg-retina-composite.zh.md) 和 `components/shared/AGENTS.md` 已经确立的约束：Agent 运行期间不能每帧占用主线程。

## 设计

外观是和产品负责人一起，通过独立原型反复迭代确定的：像素水母和点阵"一小块海"显得太卡通或太吵；呼吸点、圆环、气泡和点击涟漪都试过并放弃了。最终保留的形态和默认值：

- 3×3 方块，圆角为方块边长的 30%，间距为方块边长的 0.35，整体 14px。方块最大为所在格子的 0.8，波谷时缩到格子的 0.45；不透明度随海面变化，最低到 0.35。
- 海面：四道平面波，分别往右下、正下、略偏左下和左下传播，长度 12～15 格（再乘以波长系数 1.3），周期 2.25～3.6 秒。每道波的强度在 12～36 秒内缓慢涨落，彼此错开，所以任何时刻大约有两道波占主导并互相干涉，主导方向不断变化。所有周期都能整除 36 秒，所以海面可以无缝循环。
- 整个页面是同一片海：方块的高度只取决于它在页面上的位置。在列表里会跳过行与行之间的那段海（"拼接"，`rowPitch = 28`），一道浪离开一个标记后会接着进入下一个。

### 第一版为什么看起来割裂

第一版的海面是两道固定方向的波，长度 3.2 和 4.4 格。拼接后相邻两行的标记相距 3 格，所以相邻标记几乎反相：在一个循环里，相邻两行中心方块的起伏相关系数是 −0.55，每个标记看起来都各跑各的。波更长能解决这个问题，但单个波谷更容易盖住全部 9 个方块。对 40 行拼接后的列表测量：

| 波长 × 下限 | 相邻行相关系数 | 整个标记低于四分之一存在感的时间 |
|---|---|---|
| 第一版（两道短波） | −0.55 | — |
| 1.0，最小 0.3 / 不透明度 0.16 | 0.54 | 9.1% |
| **1.3，最小 0.45 / 不透明度 0.35** | **0.71** | **0.1%** |
| 1.6，最小 0.45 / 不透明度 0.35 | 0.79 | 0.2% |

两条测试把默认值卡在这两种失败之间：相邻行相关系数必须大于 0.6（波长 0.6 时会失败）；标记里最亮的方块低于 0.15 的时间必须少于循环的 1.2%（波长 2.4 时会失败）。

## 实现方式

| 方案 | 结果 |
|---|---|
| rAF 循环逐帧写样式（原型的做法） | 放弃：每帧都有主线程工作和重绘，正是 spinner 修复要去掉的成本。 |
| CSS 关键帧 + 每个方块不同的 `animation-delay` | 放弃：CSS 动画从元素挂载时开始计时，不同时刻挂载的标记会落在不同的海面上。 |
| 每个方块嵌套两层正弦（第一版） | 已替换：两道固定方向正弦的乘积，无法随时间改变方向或强弱。 |
| **把每个方块在整个循环里的高度烘焙成一个关键帧动画，`startTime = 0`** | 采用：可以表达任意周期性的海面，由合成器播放，并且无论何时挂载都对齐到文档时间线。 |

每个方块在 36 秒的循环里每秒取样 10 次（361 个关键帧，样本之间线性插值；最快的那道波每个周期仍有 20 个以上的样本）。烘焙只在挂载时算几千次正弦，每帧没有开销。

`prefers-reduced-motion` 以及不支持 `Element.animate` 的引擎会显示静止的网格。超椭圆方块通过 CSS `corner-shape` 提供（Chromium 139+，Electron 39 自带 142）。

## 调参入口

Storybook 里的 `UI/WorkingGrid` 把所有参数都做成了控件（形状、亮度、缩放方式、最小尺寸、间距、波长、方向、拼接），另有一个按真实尺寸搭建的 `SidebarSimulation` story：28px 行高，行尾状态位在悬停时换成 Archive 按钮，工作中的标记旁边还有等待确认和未读标记。

## 验证

- `tests/working-grid.test.tsx`：海面无缝循环；拼接让相邻行在海面上连续；相邻行一起运动，整个标记几乎不会消失（两条都用一个应该失败的波长验证过）；9 个动画都作用在 HTML 元素上、只改 `transform`/`opacity`、是首尾相接的循环、`startTime` 固定为 0、尺寸保持在 `minScale`～`maxScale` 之间，并在卸载时取消；减少动态效果时保持静止；侧边栏行尾状态位在工作时显示网格。
- 在 Storybook 里渲染并截图检查过（`UI/WorkingGrid`，以及 `Components/LodySidebar` → All sessions working）。
- 尚未完成：在打包后的 Electron 应用里、多个会话同时运行时，做一次渲染进程 CPU 和图层的性能追踪。把网格推广到其他界面之前，应该先做这项检查。
