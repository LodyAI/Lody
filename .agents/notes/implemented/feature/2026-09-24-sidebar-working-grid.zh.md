# 用"共享海面"方块网格替换侧边栏的工作转圈

Status: implemented
Translation: current

[English](2026-09-24-sidebar-working-grid.md)

## 摘要

侧边栏原来用旋转的 `Loader2` 圆弧表示会话正在运行，它读起来像"加载中"，而不是"Agent 正在工作"；列表里五六个转圈还各转各的。现在的标记是 `WorkingGrid`：一个始终完整的 3×3 主色方块网格，上面有一道光缓慢流过。驱动它的是两道横跨页面的短波，外加一道沿列表依次点亮整个标记的长节律波；每个方块按自己在页面上的位置取样。用户在侧边栏以外阅读时，所有标记保持静止。动画通过 Web Animations 只改 `transform` 和 `opacity`，共用一个时钟，由合成器播放，每帧不跑脚本。尚未测量：在打包后的应用里，每个标记 19 个小动画图层的渲染开销，以及对真实读者的影响。

## 问题

- 转圈的含义是"请等我"；而会话在工作的含义是"我正在替你忙"。产品希望它更安静、更贴合品牌（水母、水），同时保持专业感。
- 同一列表里多个转圈不同步，会吸引视线。作为一个整体一起运动的标记，比各自闪动的标记更安静。
- 任何替代方案都必须遵守 [spinner 笔记](../bug-fix/2026-09-13-spinner-off-svg-retina-composite.zh.md) 和 `components/shared/AGENTS.md` 已经确立的约束：Agent 运行期间不能每帧占用主线程。

## 设计

外观是和产品负责人一起，通过独立原型反复迭代确定的：像素水母和点阵"一小块海"显得太卡通或太吵；呼吸点、圆环、气泡和点击涟漪都试过并放弃了。最终保留的形态和默认值：

- 3×3 方块，圆角为方块边长的 40%，间距为方块边长的 0.18，整体 12px，放在 14px 的状态位里，使用主色。
- 会涨落的完整网格：9 个方块始终都在，尺寸在格子的 0.3～0.9 之间缩放（不会缩到空），不透明度从 0.25（浅色方块）到 1（主色方块）。静止时是一个大小不一的点阵；动起来时，光和尺寸一起在上面滚动。
- 主波加小波（`waves = 1`，默认）：一道主平面波，长度 3.2 格 × 1.2，往右下传播，周期 1.9s，在外层驱动每个方块大部分的尺寸和不透明度变化。每个标记播放同一个循环、只有相位不同，所以每个标记都是上一个稍微延后的样子，这给了列表节奏感。内层叠加一道小波（`ripple = 0.3`：第二道波，4.4 格，往左下传播，2.7s），只占 30% 的变化范围，和主波干涉，让各标记相关但不完全相同。小波的波谷会从主波中扣除，所以两者合起来仍然正好落在 `minScale` / `minOpacity`。两道等强的交叉波可能波谷重合、把一个标记的所有方块同时压小；小波做不到这一点。
- `waves = 2` 保留之前的形态用于对比：两道交叉的波（3.2 和 4.4 格，1.9s 和 2.7s）分别在两层上，外加作用于整个标记的一道向下长节律波（36 格，3.6s，占 30% 的不透明度范围）。
- 浅色主题做补偿（`lightCompensation`，默认开启）。同样的参数在深色模式下显得饱满，在浅色模式下却显得小：低不透明度会让方块向背景色褪色，浅色页面的背景接近白色，所以暗而小的方块就消失了，只剩大而亮的方块；另外，同样大小的图形，深色在浅底上看起来比浅色在深底上小（光渗错觉）。浅色主题下，不透明度下限向 1 提升 35%，为正的尺寸下限向 1 提升 20%，方块绘制时放大 8%（不超过格子）。修改后，同一个 story 在两种主题下的截图里，3×3 标记都是完整的。
- 整个页面是同一片海：方块的相位只取决于它在页面上的位置。在列表里会跳过行与行之间的那段海（"拼接"，`rowPitch = 28`）：14px 的标记只占 28px 行高的一半，不拼接的话，波在相邻两行之间走过不止一个波长，相邻图标看起来毫无关系。

## 不打扰阅读

> 更新（2026-09-25）：本节描述的阅读暂停已移除，标记持续运动。见
> [移除笔记](../simplification/2026-09-25-working-grid-reading-pause-removed.zh.md)。

最初上线的形态（主色蓝、不透明度 0.16～1、尺寸 0.3～0.9、原速、所有标记都在动）下，一整列运行中的会话会不断把视线从对话里拉走。阅读类软件让界面外壳退到背景里：低对比度、默认静止、只在状态改变时有动效、强调色只留给需要读者处理的东西。余光对亮度变化和运动最敏感，大量互不相关的闪烁点也无法被大脑"习惯掉"。因此：

- 亮度和颜色，前后三轮。第一轮：不透明度 0.5～0.8、尺寸 0.55～0.9、次要灰色、0.45 倍速，产品负责人觉得静止得看不出在动。第二轮：12px 标记、方块可以缩到空（最小 -0.2），实际渲染后网格碎成零散的小点，像噪点，静止时难看，也认不出是什么；把小于 30% 尺寸的方块算作看不见时，约 29% 的时间一个标记只剩 2 个或更少的方块。第三轮：保持网格完整（尺寸 0.8～0.9），改为让光流动（不透明度 0.25～1），使用主色，速度 0.6 倍——完整、好认，但几乎看不出在动。第四轮：恢复缩放到 0.3～0.9（为正数，所以方块不会消失），速度恢复原速——有动感，但两道波加节律让各标记看起来互不相关，有时全都很小。第五轮：同样完整的网格、颜色和范围，改由单道波驱动，各标记只在相位上不同——看起来太规整，有点廉价。最终：同一道主波，上面叠一道小幅度的干涉小波。网格形状让它和未读圆点区分开。
- 一致性：单一形态的一道波，让一整列读起来是同一个运动从一个标记传到下一个，而不是约一百个互不相关的方块。
- 阅读时静止：在 `[data-working-grid-region]`（侧边栏根元素）以外的任何滚轮、按键、指针或触摸操作，都会让所有标记停在当前帧；安静 4 秒后，或指针移进侧边栏时恢复。刻意不监听 `scroll`：流式输出的对话会自己滚动。暂停和恢复是唯一涉及脚本的地方；所有标记共用一个时钟偏移，所以恢复后仍然同步。

阅读时静止这一项，保证了更显眼的最终形态不会一直拉扯读者的注意力。以上效果都没有在真人身上测量过；数字来自模拟和截图。

## 完成时的过渡动画

当一行从"工作中"变成"有未读"时，`SessionRowStatusIndicator` 会先播放一次 `WorkingGridCollapse`，再显示普通的未读圆点：网格旋转 135°，同时 9 个方块向中心聚拢并淡出（0～480ms）；然后圆点从 0.35 倍弹出到 1.75 倍，再经过 0.72、1.3、0.88、1.06 倍弹两下后稳定下来（400～1020ms）。第一版（300ms 旋转、1.3 倍弹出、只弹一小下、6 个淡出的溅射小点）放大看效果不错，但在真实的 14px 下看不清：于是放慢了旋转、加大了弹出和回弹，并去掉了在小尺寸下看不见的溅射小点。它同样只用由合成器播放的 Web Animations；切换到普通圆点靠的是圆点动画的 `finished` promise，而不是定时器。

`WorkingStatusMark` 把网格、过渡动画和圆点封装在两个开关（`working`、`unread`）后面；`SessionRowStatusIndicator` 在两种状态下都渲染它，所以它在切换过程中保持挂载。它用"渲染期间调整的 state"记住上一次的 `working`，所以过渡动画和网格消失出现在同一次提交里。只有在 `working` 变为否的那一刻 `unread` 已经为真，才会播放。这两个开关分开到达：`working` 来自会话在线状态，`unread` 来自持久化的文档元数据（`lastMessageAt` 与 `lastReadAt` 比较）；正常结束一轮时，会先写入未读、再释放在线状态，所以这个顺序成立。如果在线状态先失效（崩溃、过期），指示器会先清空，之后圆点出现时不播放过渡。重新挂载的行、或者从未在工作的行，会直接显示圆点。减少动态效果时直接显示圆点。已知的衔接问题：过渡从大小一致的方块开始，而运行中的网格方块大小不一。验证方式：在 Storybook 里暂停动画、逐帧拖动检查（`UI/WorkingGrid` → Completion；`Components/LodySidebar` → Sessions finishing）。

## 实现方式

| 方案 | 结果 |
|---|---|
| rAF 循环逐帧写样式（原型的做法） | 放弃：每帧都有主线程工作和重绘，正是 spinner 修复要去掉的成本。 |
| CSS 关键帧 + 每个方块不同的 `animation-delay` | 放弃：CSS 动画从元素挂载时开始计时，不同时刻挂载的标记会落在不同的海面上。 |
| **Web Animations，`startTime = 0`，按相位计算每个方块的延迟** | 采用：由合成器驱动，并且无论何时挂载，所有循环都对齐到文档时间线。 |

两道正弦波相加无法写成一个关键帧循环，所以每个方块嵌套两层，每层对应一道波，两层的缩放和不透明度相乘。每层只覆盖完整范围的平方根，因此两个波谷叠加时正好落在最小值上。两道波相乘和原型里的相加观感一致：波峰叠波峰最大，波谷叠波谷最小。

`prefers-reduced-motion` 以及不支持 `Element.animate` 的引擎会显示静止的网格。超椭圆方块通过 CSS `corner-shape` 提供（Chromium 139+，Electron 39 自带 142）。

## 试过并撤回的方案

上线后在 Storybook 里又试了几种海面，产品负责人最终选择回到上面的配置：

- 更柔和的默认值（圆角 20～30%、间距 0.25～0.35、方块最大为格子的 0.8），以及更短或更长的波长（0.8～1.3）和更快的波速。
- 四道强度轮流占主导的长波：相邻标记一起运动，但一个标记里的 9 个方块像一整块在动。
- 短波纹理加长涌浪：方块各不相同、整体有节律，但单个方块从来不像随机。
- 每个方块各自随机起伏，加上时不时扫过所有标记的亮带。

这些方案把每个方块在 36 秒循环里的高度烘焙成一个关键帧动画，而不是两层嵌套的正弦；如果以后要再改海面，这条路仍然可用。

## 调参入口

Storybook 里的 `UI/WorkingGrid` 把所有参数都做成了控件（形状、缩放方式、最小和最大尺寸、不透明度范围、节律占比、速度、间距、波长、方向、拼接、次要色或主色），另有一个按真实尺寸搭建的 `SidebarSimulation` story：28px 行高，行尾状态位在悬停时换成 Archive 按钮，工作中的标记旁边还有等待确认和未读标记。`Components/LodySidebar` → All sessions working 展示所有会话都在运行时的真实侧边栏。

## 验证

- `tests/working-grid.test.tsx`：延迟在任意时间线时刻都能还原出传播的波；拼接让相邻行在海面上连续；节律沿列表以很小的步长向下推进；全部 19 个动画（1 个节律、18 个方块层）都作用在 HTML 元素上、只改 `transform`/`opacity`、共用同一个起始时间、遵循速度系数、保持在尺寸和不透明度范围内，并在卸载时取消；减少动态效果时保持静止；侧边栏以外的输入会暂停所有循环，直到安静 4 秒或指针回到侧边栏，恢复后仍在同一个时钟上；侧边栏行尾状态位在工作时显示网格。
- 在 Storybook 里渲染并截图检查过。
- 尚未完成：在打包后的 Electron 应用里、多个会话同时运行时，做一次渲染进程 CPU 和图层的性能追踪。把网格推广到其他界面之前，应该先做这项检查。
