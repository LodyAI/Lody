# 新建对话页:最近 7 天

Status: implemented
Translation: current

[English](2026-10-16-home-week-tiles.md)

## 摘要

桌面端新建对话页原本是一个大标题加底部输入框。现在输入框仍在底部,上方是五个扁平格子,排成错落的 bento,与输入框同宽:最近 7 天交付的代码(带每日柱图和与前一周的对比的大格)、当前所选 provider 的套餐用量及各窗口何时重置、合并的 PR、完成工作的 Agent、用得最多的仓库。页面只放值得瞥一眼的内容:最初的九格方案经评审后被砍减。会话元数据和本机的限额客户端本来就有,所以这些格子不新增查询或写入;唯一的网络请求是 Codex reset forecast,在页面挂载时加载。后来的两次改动让这个页面说得更少:连续活跃天数从页面上移除;「现在」无事发生时用一句平静的话代替三个零。作者沙箱中未渲染也未做类型检查。

## 决策与归属

[周模型](../../../../packages/components/src/lib/home-week.ts)按本地日历读取当前用户的根会话。会话改动的行数和已合并的 PR 记在它最后活跃的那天,会话的开始记在它的创建日。存储的元数据只有这两个时刻和累计行数,所以结果是接近而非精确:长会话的行数会落在最后一天,PR 按其会话活跃的时间计,而不是 GitHub 合并的时间。用得最多的仓库是开始会话最多的那个(占比以本周全部会话为分母,所以没有仓库的会话会拉低它)。一周内既没有会话也没有改动行数时,格子照常显示、数值为零,会话元数据尚未加载的短暂时刻也一样;数据到达后数字再滚动到位。[派生 atom](../../../../packages/components/src/atoms/home-week.ts) 把会话缓存缩减为页面所需的少量行,并在内容不变时保持引用,因为运行中的 Agent 会不断改写会话元数据。

套餐用量就是输入框的用量弹层已经在读的那一条:新建页按所选模型解析所选 provider 的限额([`buildHomeWeekUsage`](../../../../packages/components/src/lib/home-week-usage.ts)),显示最短的窗口(有 5 小时窗口时就是它),附已用百分比和 provider 自己给出的重置时间。provider 的其他窗口不显示(旁边再放一条进度条只会让格子拥挤,所以页面只留下最先重置的那一个)。它是本地数据(本机限额)。格子用一个 outline 样式的选择器标明是谁的套餐,列出所选机器上所有上报了套餐的 provider;默认是输入框当前的 provider,用户选择后在本次访问内保持,只有一个 provider 时显示同样的轮廓但没有菜单。没有任何 provider 上报套餐时(其他 Agent、API key),宽格改显示会话数。若 forecast 已知某次 Codex 重置(预测或已排期),它在用量格旁边单独占一格(标题明确是 Codex 重置,含可能性和预计时间);标题旁的小图标悬停时提示:数据是来自第三方 `codex-resets.com` 的预测,打开本页时加载。把 forecast 和两条进度条挤在一个格子里每一项都被截断,和一条进度条挤在一起也只是个局促的半格,所以它是独立的格子。没有 5 小时窗口的 provider 显示它最短的那个窗口;没有 forecast 时,用量格独自横跨两列。forecast 来自第三方 `codex-resets.com`;负责人选择在页面挂载时加载,这推翻了此前「挂载时不请求」的规则,所以[该规则](../../../../packages/components/src/components/codex-reset/AGENTS.md)现在把本页列为第三个加载入口。共享 store 仍会合并请求并重新验证,非 Codex provider 不发请求。

[格子](../../../../packages/components/src/components/chat/home/week-bento.tsx)只是其 props 的图像;[宿主](../../../../packages/components/src/components/chat/home/home-dashboard-host.tsx)提供 atom、时钟、forecast 以及 Agent 的显示名和图标。格子都是显式摆位,不靠自动排布:代码量在左侧占两列两行;仓库占右上方原来用量的位置(用量移到了下文的「现在」面板),下面是合并的 PR,Agent 横跨最底一行。曾先试过让代码量卡片占三行、旁边叠三张卡片,但它的内容比那一摞矮,墙上方空出一大块;现在右侧加起来与它高度相当。bento 仍是四列,见[连续天数已移除](#连续天数已移除与安静的现在2026-10-22)。它们使用设计系统的凹陷底色,没有阴影,数字为中等字重,图表是细线,因此看起来是页面的一部分,输入框仍是唯一抬起的对象。唯一的动效是页面首次显示时数字从零滚动、柱图生长,两者在「减少动态效果」下关闭。

这替代了同一页面上被否决的三次尝试:按天一格的全年活动图(与设置里的用量日历重复,也不被喜欢)、继续上次会话的列表,以及更重的 Bento(带大号着色主格、环形图、仪表条和半年日历,太大太粗糙)。随后的九格版本排布规律且信息过多:会话开始时间图(含夜猫子占比)、最长的一次对话、最忙的一天和单独的会话数被当作无关紧要的内容去掉了。费用刻意不放:它来自托管后端,开源桌面端不调用。没有时间范围切换和分享功能,均已被拒绝。

## 现在与这一周

评审接着问:Coding Agent 产品的首屏是给什么用的?不是写了多少行,而是哪些任务在运行、哪些需要我参与、哪些刚完成、哪些值得继续。现在页面在一行之下有两块面板,默认打开**现在**;前面描述的七天卡片是**这一周**面板。这有意推翻了之前「续接会话列表」被否决的记录:那个列表是孤立的,而这个按每个会话需要什么来排序,并与运行中和刚完成的放在一起。负责人选择了它,同时让回顾内容保持一键可达。

[现在模型](../../../../packages/components/src/lib/home-now.ts)通过[派生 atom](../../../../packages/components/src/atoms/home-now.ts)读取当前用户未关闭的根会话:来自 presence 的实时状态(子标签的运行或等待计入父会话,与侧栏一致)、未读输出,以及最新 PR 的草稿状态、CI 汇总和可合并性,这些都已同步在本地。每个会话按第一个成立的原因只进一个列表:等你处理、运行中、CI 失败、完成但未读、草稿、可以合并、PR 审查中、最近三天活跃。正在运行的 Agent 即使 CI 是红的也不算「需要你」,因为它可能正在修。列表有**需要你处理**(等待、CI 失败、草稿)、**运行中**、**刚完成**和**值得继续**,各显示前几条并给出其余数量。第一版总是画出全部四个,空的就在里面写一句;下午清闲时就成了一墙空盒子,而任务很多时又反过来出问题:固定上限把其余部分藏在一个点不了的数字后面,两个一行的摆法又会把短列表撑到长邻居的高度。[布局](../../../../packages/components/src/lib/home-now-layout.ts)现在分两步分配面板高度。先是行数预算(共十二行):每个有内容的列表先得一行,剩下的按优先级分配,各自不超过上限(六、四、三、三),所以忙的时候低优先级的先让,需要你处理的永远不让。然后是两列保持平齐:用量在右列开头,各列表按优先级依次放进当前较矮的那一列,卡片高度只取决于它显示的内容。空列表不画,只有一个列表时它占满整块面板。列表没显示的部分一键可达:「显示全部」在面板自身的框内打开整个列表(见[适配窗口](#适配窗口2026-10-18))。什么都没有时,左边只显示一张「一切安静」卡片,套餐用量和重置预测留在右边。点一行用侧栏同样的路由打开会话。套餐用量放在这块面板上,因为额度用尽也是要处理的事;它的 Codex 重置预测只在这块面板显示时请求。

[这一行](../../../../packages/components/src/components/chat/home/home-dashboard.tsx)每块面板一段,末尾一个按钮。点另一段就切换面板;点已打开的那段或末尾按钮,面板收进这一行,两段都显示摘要(需要你/运行中/刚完成的数量;七颗小格和行数),这一行在标题下居中。末尾按钮会展开上次打开的面板。本轮评审之前曾让每张卡片从折角单独收进一排胶囊;页面有两块面板后,这样的交互超出了实际需要,于是换成这一个切换。动效是一次克制的 View Transition。第一版把打开的面板作为共享元素飞进那段的摘要,评审觉得太炫,所以现在不做任何缩放或飞行。第二版仍有闪烁:旧面板在新面板出现前就已淡完,中间露出空档,浏览器还对整页做了交叉淡化。现在过渡带类型(`home-board`),规则不影响别处,整页不再交叉淡化,只有三样东西在动:面板区域平滑过渡到新高度,两块面板以浏览器的叠加混合完全重叠地交叉淡化(中间不会变暗),选中段的底色胶囊滑到另一段,标题随舞台重新居中而平移;同一条曲线,约四分之一秒。没有逐帧脚本;减少动态效果(或不支持该 API)时直接切换。打开哪块是本设备的视图偏好,存在 `lody:homeBoard`(收起时为 `none`),不在缓存清理列表中。

卡片文字也太淡:标签、单位、注释和对比文字用的是 `tertiaryLabel`,在浅色模式的卡片底色上约 2.6:1。现在改为 `secondaryLabel`(约 4.6:1),已用百分比用 `label`。活动墙的空日原来是半透明的墨色底,最浅一档是半透明的 22% 蓝,两者在卡片上几乎同色;现在空日用实心中性灰,四档强度用与卡片底混合的实心蓝(38%、58%、80%、100%),蓝色只表示有活动。胶囊里的七颗小格同样处理。

标题和面板居中于输入框上方的舞台内,而不是整个页面(`web-chat-landing-screen.tsx`):窗口顶边与输入框之间是一条独立的区域,因此整体看起来略高于页面正中。早先的一版把舞台的空白按 3:2、后来按 5:3 分给上下两侧,并在收起时测量输入框高度、把整体重新对到整页正中;评审认为标题之下多了面板之后,这样看起来偏低,于是两者都改成对舞台本身做等分(见 [纵向位置](#纵向位置2026-10-19))。

## 过渡图层修正（2026-10-18）

逐帧检查并在 Chromium 中复现后确认，独立命名的滑块会在切换面板时遮住文字。滑块的 DOM `z-index: -1` 无法让提取出的 View Transition 快照排在仍留在根快照中的文字下面。同时，未命名的切换栏在舞台重新居中时直接跳到新的纵向位置，滑块再沿对角线追过去。

现在为两个按钮、始终存在的标签和折叠按钮分别命名快照，所有位置变化都使用面板和标题的 240ms 曲线。显式设置过渡图层顺序：滑块在按钮下面，标签在两者上面。按钮快照以原始尺寸交叉淡化变化的摘要，并按动画中的宽度裁切；标签保持原始尺寸，移动时始终可见。面板快照组不裁切：切换时每张画面会短暂移出该组 20–28px，若裁切，就会在画面到位前削掉最前方卡片的边缘。继续使用浏览器过渡，保留已有的面板交叉淡化和高度缓动，不新增动画循环，也不替换布局系统。

[落地页 Story](../../../../packages/components/src/stories/HomeDashboard.stories.tsx) 使用真实舞台，让面板高度变化触发纵向重新居中。[浏览器回归测试](../../../../packages/components/tests/e2e/home-dashboard.spec.ts) 将动画暂停在明确时刻，检查截图中标签的文字像素，因为仅检查 DOM 可见性无法发现快照遮字。还检查标签起始位置、双向切换、收起与展开、中途打断和减少动态效果。本地 Chrome 中的四个浏览器测试通过，覆盖 1180px 和 720px；已有 dashboard 和 week 组件测试共 21 项通过。包类型检查仍被 `loro-sidebar.tsx` 和 `home-week-usage.ts` 中已有的错误阻塞，不属于本次修正范围。

## 滑块随收展移动，行随框浮现（2026-10-18）

复查动效时发现首版有两处读法不对。展开面板时，滑块从第一帧起就停在目标段的位置上，而面板、各段和标题还在移动：因为滑块只在面板打开时才在 DOM 里，`home-pill` 快照没有旧侧，浏览器只能把新位图原地淡入。折叠时则相反：滑块在原打开面板的位置上原地淡出，而不是随自己的段落离开。两处共用一条规则：滑块只在过渡中持续存在时才保留自己的名字——切换面板时两侧都有它，其快照照旧在段之间滑行；展开或折叠时它不带名字，跟随段落自身的快照一起移动（段落本来就跟面板走同一几何变化）。折叠还要在过渡捕获旧状态之前，先在真实 DOM 上摘掉这一名字（[`home-dashboard.tsx`](../../../../packages/components/src/components/chat/home/home-dashboard.tsx) 的 `show(null)`），因为上一次渲染已经给它命了名，仅靠删除元素挡不住旧侧的独立快照。

同一复查里，「显示全部」的打开读起来拖沓：卡片隐藏的行和返回按钮要等框的弹簧开始后再过 140ms、每行再加 18ms 才出现，打开的列表有约五分之一秒明显是空的。现在这些后到的行改为 30ms 起、每行 14ms、200ms 完成，与框同时而不是在框之后；每次几行的渐次节奏本身保留。

## 适配窗口(2026-10-18)

评审发现,在矮窗口里列表都很多时,"现在"面板会崩:在「值得继续」上按了「显示全部」后,该卡片原地多长了十行,右列比左列高出约九行,左列下方留出一片空白,面板把标题顶到窗口顶端,最后几行滑到输入框下面。原因有三个,三处都改了。

- **行预算跟随窗口,但不会把它填满。** 落地页的舞台把舞台和它的居中组交给组里的内容(`LandingStageContext`,[`landing-stage.ts`](../../../../packages/components/src/components/chat/landing-stage.ts))。仪表盘可用的高度 = 舞台高度 − 组里其他内容 − 24px 留白;这个差值与仪表盘自身高度无关,所以一次就能定下来,不会追着自己的测量结果跑。切换行和它下方的间距固定为 34px,面板折叠与否可用高度都一样(若直接量面板,折叠后会多出那段间距,又被判定能放下、再折叠)。可用高度换算成每列能放的行数(一行是脚注字号的 1.9em 加 1px;卡片标题约两行),[`layoutHomeNow`](../../../../packages/components/src/lib/home-now-layout.ts) 逐步缩小预算,直到较高的一列放得下,最少每个列表一行,优先让低优先级的列表让位。最小的忙碌布局能放下后,紧凑舞台最多再留出两行高度,不把每个空余像素都换成会话行;十二行仍能容纳用量卡片和每个非空列表的一行,所以这段留白不会让最坏情况下本来能显示的面板折叠。更高的舞台仍会达到原来的自然预算。行数换算是近似的,所以布局后若面板实测仍高于可用高度,就针对该高度再逐行收回。
- **两列各自在哪结束就在哪结束。** 放置完成后,较矮的一列从它最下面的列表开始逐行多显示自己的内容,直到与较高一列齐平或没有可显示的内容。多出的空间用来放真实的行,而不是拉高卡片,所以之前"短列表被拉到长邻居高度"的否决仍然成立。显示列表最后一条隐藏行不额外占高度,因为「显示全部」那一行随之消失。拉齐可以超过列表的上限;上限只决定谁先让位。
- **「显示全部」原地撑高卡片。** 现在它在面板上、以面板自身的框打开整个列表,按面板的两栏纵向排列(若卡片原本横跨整个面板则为一栏),在框内滚动。周围什么都不动,也不会有一列比另一列长。表头末尾的按钮、Esc 或打开某个会话都会回到面板,焦点回到打开它的「显示全部」。

动效在评审中改了三轮。把面板交叉淡入成列表(沿用切换面板的 View Transition)看起来很怪:两整幅画面互相透叠,与按下的位置毫无联系。横向滑动做了一半,按所有者的方向放弃:被按的卡片长大,其余卡片带一点景深向后退。随后固定 280ms 的曲线又显得太快,而之前的交叉淡入显得拖沓。问题不在数字:所有东西同时同速运动,大面积变化和小变化用同样的时长,返回是打开的倒放,把减速变成了慢起步。[`focus-motion.ts`](../../../../packages/components/src/components/chat/home/focus-motion.ts) 现在用 Web Animations API 在真实元素上编排(不用截图,所以运动中列表就可以交互,中途再按会从当前位置折返)。打开:其余卡片朝被按的卡片缩小并淡出,同时列表的框从该卡片的裁剪区长到整个面板,内容从卡片的左上角移到面板的左上角,所以第一帧就是那张卡片本身;没有任何缩放,文字不会被拉伸。卡片原本隐藏的行和返回按钮在框大部分展开后再浮现,前八行依次出现,读起来是"同一个列表里出来了更多"。关闭是单独的动效:列表先滚回顶部,多出来的行先走,框不回弹地落回卡片,面板在它落地时回到前面。

这套动效的第一版收尾明显对不齐,还让整个面板闪了一下。原因是框是一张裁剪过的整面板画面平移到位,所以缩到卡片大小时并不是那张卡片:计数已经淡出,没有「显示全部」,自动平衡的两栏可能把别的行排在第一位,面板后退时的缩放也让测得的 client rect 有偏差。而且动画在 React 移除框之前就被取消了,未裁剪的框在面板上画了一帧。现在动效的两端都是卡片本身:框自身的位置和尺寸(inset)在卡片与面板之间移动,所以表头(标题、返回按钮,最后是位于卡片右上角的计数)在任何尺寸下都会正常排版;运动过程中行区域保持面板宽度,用显式网格排列,第一栏至少容纳卡片原有的行,宽度正好等于半宽卡片(列间距 18px:两张卡片的内边距加面板 6px 间距,减去两侧各 4px 的行外延),所以不会重排;「显示全部」的替身放在卡片最后一行下面,只在卡片尺寸时可见;卡片位置用 offset 测量(不受面板 transform 影响),关闭时在列表滚回顶部后重新测量。收尾时在同一次同步提交里移除框并显示卡片,之后才释放动画。时间用弹簧,写成 CSS `linear()` 缓动(打开:response 0.5s、damping 0.86,300ms 时约到 95%;关闭:response 0.4s、临界阻尼),不支持 `linear()` 时回退为减速曲线。Storybook 的 `ShowAllMotion` 提供弹簧参数、景深和慢放系数,方便所有者凭眼睛调;减少动态效果时直接切换。

连每个列表一行都放不下时,面板显示为折叠进切换行(`data-auto-folded`),但不改变记住的面板;窗口变高后自动展开。这种状态下从切换行打开它,仍然会显示并让舞台滚动,因为这是用户主动要求的。没有落地页舞台时(stories、测试)不限制面板。"最近 7 天"面板是固定画面,不做适配。

纯函数测试覆盖了预算缩减、两列拉齐、是否放得下的判断,以及在所有列表规模下每列都不超出可用行数。jsdom 测试覆盖了打开和关闭整个列表(返回、Esc、焦点归还、打开一行)、按给定舞台尺寸适配、紧凑舞台留白,以及自动折叠和手动打开的覆盖。Storybook 有 620px 和 380px 的落地页。加入留白后已在 Chromium 中检查 620px 的紧凑落地页;两栏完整列表的动效不在这次检查范围内。

## 纵向位置(2026-10-19)

评审觉得问候区偏低。两个原因:展开时舞台的空白按 5:3(文档写的是 3:2)分给上下两侧;收起时又测量底部输入框的高度、给舞台加等量上边距,把小巧的整体对到整页正中。两者都已去掉。现在整体在舞台(输入框上方的那条区域)内等分居中,因此无论在收起还是展开状态,标题和面板都略高于页面的几何正中,并且完全不再测量输入框高度(随之删掉了 `ambientExpanded` 属性)。代价是收起时不再让整体停在展开时的同一位置;标题的 View Transition 仍会平滑这次小幅移动。改动只是一个排版常量,并未在此在真实窗口中验证:高窗口与矮窗口下的实际观感、以及深色模式,都仍未经视觉评审。

## 卡片本身也能打开(2026-10-19)

评审问为什么点「现在」的卡片没有任何反应,而它的「显示全部」却有效:卡片才是第一眼看到的东西。现在列表卡片在还隐藏着行(`total > shown`)时,按下卡片本身就以与「显示全部」同一条 `open` 路径打开整个列表;全部可见时卡片保持不动,即只有存在切换行时卡片才可按。按某一行的语义仍然是打开该会话:在卡片上用点击目标的最近 `data-session` 或 `data-show-all` 祖先判断,既不吞掉嵌套控件,也不必再挂一个真正的「显示全部」按钮;键盘路径与焦点归还都仍是那个切换按钮。可供性只有指针光标:因为行自身的 hover 已经回应了指向,再叠一层卡片级 hover 只会显得吵。`tiles.tsx` 的 `Tile` 增加了可选的 `onPress` 和承光标的 `pressProps`;「最近 7 天」的卡片两者都不用。jsdom 补了三条覆盖:按卡片打开、按行只开会话不展开、全部可见的卡片按不开。真实窗口里那种越过行的按压判定与光标可供性仍未视觉评审。

## 控件不动(2026-10-20)

评审希望减少移动的目标:切换面板会移动切换行,tile 的 "Show all" 跟着行数到处跑,返回又是另一个角落里的独立图标。现在的规则是:指针要按的东西不随内容移动,内容只在固定的框里变化。

- **切换行。** 无论展开还是折叠,它都是标题下居中的一句话。两个分段始终带着各自的摘要(打开的那段也带,像标签页的角标);"now" 的摘要显示三个计数,为零时变淡;全为零时改为一句话,见[连续天数已移除](#连续天数已移除与安静的现在2026-10-22)。折叠控件始终在分段之后保留位置并保持可见。曾短暂试过在 dashboard 未悬停时隐藏墨色,但 owner 更喜欢常驻的操作提示,因此撤回。
- **槽位。** 打开的面板放在一个固定高度的槽里:任意列表能组成的最高 "now" 面板(`HOME_NOW_TALLEST_COLUMN`,十七行),窗口不够时取 stage 可用高度。切换面板和列表实时变化都不会让 stage 重新居中,标题和切换行保持不动,面板挂在切换行下面。第一版在折叠时也保留槽位;在真实窗口里,一行内容下面留出一大片空白,控件被甩到最右边,而完全不保留时,折叠会让整组移动半个槽位(默认字号下约 190px),位移太大;保留一半也只是把位移减半。把打开的面板整块挂在折叠时的切换行下方、让除了面板外什么都不动,面板又显得太低,贴着 composer。现在打开面板的大部分(`HOME_BOARD_HANG_SHARE`,0.7)挂在 stage 居中的内容下方,高度用负的下边距抵消(`home-dashboard.tsx` 里的 `hangPx`;`useLandingRoom` 测量时会把这个边距加回去),剩下的部分让标题和切换行上移一小段,默认字号下约 65px。只靠这个比例,在中等高度的窗口里面板仍会下沉:它一直往下挂,直到整组底部碰到留白,多出来的空间全部堆在标题上方(owner 截图里标题上方约 340px,面板下方约 110px)。现在挂出量还受平衡限制(`HOME_BOARD_MAX_TILT`):标题上方的空间最多是面板下方空间的 1.5 倍。高窗口里仍由比例决定,标题只上移一点(默认字号下 2000px 的 stage 约 70px);中等窗口里面板基本居中,标题移动更多(700px 的 stage 约 200px)。平衡和位移在这里互相牵制,冲突时优先平衡。折叠时标题和切换行略高于 stage 中线(`HOME_FOLDED_LIFT`,stage 剩余空间的 3%,700px 的 stage 约 17px):折叠的切换行下方保留两倍于此的不可见空间,作为正的下边距,和挂出用的是同一个机制;这也让展开时的位移更短。折叠页面上移之后,1.5 的限制仍让展开时的标题比折叠时高出很多,所以限制改为 2.5(`HOME_BOARD_MAX_TILT`):展开的面板稍低一点,展开时的位移也更小。挂出量也不会超过让展开时的标题停在折叠时位置所需的量:在高窗口里,折叠的上移量否则会超过面板带来的上移,展开时标题反而会往下走。现在高窗口里展开时除了面板几乎什么都不动。之后 owner 觉得两种状态都略高,上移量(原为 6%)和限制(原为 2)都各放松了一档;1000px 的 stage 展开时标题上移约 95px,700px 约 165px。折叠页面仍按 2026-10-19 的方式居中;把整个 stage 上移(上下 3:4 分配)是理解错了,已撤回。代价是高窗口里较短的 "now" 面板下面会有一些留白。
- **固定列。** 每个列表只有一个位置:左列是需要你处理、刚完成;右列是用量、运行中、值得继续。两个最长的列表分在两列,忙的时候两列都能用上。没有内容的列表只显示标题和一个淡色的 0,不再消失;"All quiet" tile 也去掉了,因为第一个 agent 开始运行时它会改变整个面板的形状。(那张卡片又回来了,见[安静的卡片回来了](#安静的卡片回来了2026-10-22)。)行预算、窗口适配和底部对齐都不变,只去掉了"放进较短的那一列",因为它会随计数变化把 tile 在两列之间挪来挪去。
- **在列表结束的地方放「Show all」。** 隐藏了行的 tile 以一整行宽的「Show all 12」结尾:左边在会话行放状态标记的位置放一个向下的箭头,文字用较淡的颜色,看起来是一个操作。之前三个版本都被否掉了:行下面的小号说明文字容易被忽略;标题角落的计数(「12 ⤢」,展开后也作为返回)离眼睛读完列表的位置太远;下一个会话的淡出预览加「+N」看起来像一个会话行,让人以为点了会打开那个会话。返回是展开后列表底部的「收起」,和点「Show all」的位置一致;Escape、打开会话和按整个 tile 仍然有效。展开的列表只覆盖它所在的那一列:从 tile 长到整列的高度,同列其余的 tile 往后退;另一列保持原样、仍可操作。列表的行按 tile 的宽度在一列里往下排,所以不会重新排版(之前铺满两列,视线要横跨整个面板)。列表在应用自己的 `ScrollArea` 里滚动,使用覆盖式滚动条,动画进行时隐藏;由于展开框始终保持所在列的宽度,动画不再需要固定行宽,也不再改动滚动容器的 overflow。收起现在是一个整体动作:展开框落回 tile、同列其余 tile 回到前面,同时开始;tile 不显示的那些行被收缩的框裁掉,并在前三分之一的时间里淡出。之前先让这些行退场,框和面板再分别延迟 40ms、100ms 跟上,看起来像东西一个接一个离开,节奏突然变慢。展开和收起共用一个弹簧(`FOCUS_TUNING`:response 0.4s,damping 0.9;约 256ms 走完 95%,超出 0.15%,约 660ms 稳定),面板后退和回来也用它:之前展开较软(0.5s,0.86)、收起较硬(0.3s,临界阻尼),看起来像两套不同的动作。曾经给收起弹簧加过的初速度也一并去掉了,因为它想解决的延迟另有原因。owner 实际看到的顺序(「收起」和多出的行先淡出,然后高度才缩小)另有原因:展开弹簧看起来在约 300ms 就结束了,实际要跑到约 870ms,在这段时间里点收起会走「把展开动画倒放」的分支,先倒放那段看不见的尾巴(框几乎不动,而行各自倒放的淡出在进行),然后才是陡峭的部分。现在转向从不倒放:读出每个部分当前的状态(框的 inset、同列的缩放和透明度、每一行的透明度),从那里开始新的动画,所有部分一起开始;收起途中再展开也一样,并且不再错开。收起时还出现过 tile 的「Show all」在动画结束后才突然出现:当初「Show all」一度被计数取代时,展开框里的替身被删掉了。现在替身放回来了,位于框内 tile 最后一行的下方:框离开 tile 时它淡出,框落回时它淡入,所以换回真正的 tile 时看不到任何东西突然出现。「收起」现在浮在框的底部,不再占高度(行在末尾为它留出空间),所以在 tile 尺寸下,行和替身拥有 tile 的全部高度。它下面垫了一条与框同色的不透明底条,顶边渐变,所以滚到它下面的行会淡出,而不是透过控件显示出来(第一版只有按钮半透明的底色,行的文字会穿过「收起」)。「Show all」在布局里占一行;对齐时也可能直接显示列表最后一行隐藏的会话,这时「Show all」就去掉了。
- **保持生动的动效。** 切换行和标题不动之后,原来的切换失去了大部分运动,显得平淡。现在由面板来表达方向(`morph.ts` 增加了第二个过渡类型):切换时,旧面板向留下的那个分段一侧漂移,新面板从被按下的分段一侧进入,与滑块的移动方向一致;展开和折叠会让 stage 重新居中,这时面板和标题、切换行作为一个整体一起移动:面板固定在切换行下方,走同一条 240ms 曲线,展开时边上移到位边淡入,折叠时随切换行下移边淡出。面板的快照没有另一端可以过渡,所以 `morph` 在更新前后测量切换行的位置,把移动距离交给 CSS(`--home-line-travel`);这两种过渡下面板的 group 不裁剪。之前三版都被否掉了,原因相同,面板和切换行的运动不一致:在最终位置原地展开(移动中的切换行从面板顶部划过)、让面板区域从切换行里长出来(像一个展开的面板)、原地淡入淡出并错开时间(仍然是两套运动)。都是短距离的平移和淡入淡出,从不缩放,错位的快照不使用叠加混合。减少动效时仍然跳过过渡。

浏览器测试现在断言切换后分段标签的位置不变;jsdom 测试覆盖固定列、空列表、「Show all」和「收起」的打开与返回、共用的槽位高度和完整摘要。以上都没有在编写环境中运行(没有 Node 运行时),新的动效和短面板下方的留白都还没有经过视觉评审。

## 安静的卡片回来了(2026-10-22)

owner 记起了「All quiet」那张卡片,想要它回来。它在 2026-10-20 被去掉,理由是「它在第一个
agent 开始运行时改变整个面板的形状」—— 确实如此:面板从一张卡片变成四张列表卡片,第一个 agent
一启动,所有卡片都挪了位。卡片还是回来了,它带来的形状变化由 owner 承担。

四个列表全空时,面板只说一次:一张卡片,一个对勾,「一切安静」,和一行「没有正在运行、也没有等
你处理的事」。安静卡片占左列,套餐用量和重置预测留在右列,那四个空列表卡片完全不画。只要有
事情发生,忙碌状态的两列就回到各自的位置,卡片消失。没有 provider 报告套餐时,安静卡片仍是面板
里唯一一张横跨整行的卡片。曾短暂试过把用量放在上方、安静卡片横跨下方,但 owner 更喜欢原来的
左右两列,因此撤回。

卡片的文案是原来那句(「All quiet」「Nothing is running or waiting on you.」),与这一行新的说法
(「All caught up」)不同:卡片陈述面板的状态,那一行陈述该怎么读这个状态。那一行不带记号 ——
owner 要求把对勾去掉。

布局算式把卡片当作自己的一种块(`{ kind: 'quiet' }`,三行,和原来一样高)。安静状态保留两列
(`quiet` 在左、`usage` 在右),忙碌状态也保留固定的两列。纯逻辑测试覆盖这种形状及周围的固定列;
jsdom 测试覆盖列位置、卡片文案,以及一旦有会话在跑,列表就回来。已在 1000×620 的 Chromium 窗口
确认左右两列的安静状态和常驻显示的 fold 图标。卡片变成四张列表卡片的状态变化仍未在真实窗口中
评审。

## 验证与局限

- 纯逻辑测试覆盖窗口、行数与对比、已合并 PR、Agent、仓库、空状态以及套餐用量的选取;jsdom 测试覆盖格子的文字、省略对比、两个用量窗口及其重置时间、provider 选择器的收起状态(菜单本身未在 jsdom 中操作)、会话数回退、forecast 行、柱数量和单复数单位。使用固定日期,但未在此运行:作者沙箱没有 Node 运行时,类型检查、lint、格式化、测试、Storybook 和文档检查都还需运行。
- 视觉重量、间距和深色对比未在真实窗口中评审;用量格的高度(两条进度条放在较矮的第一行)以及窗口很矮时的情形(格子和标题位于输入框上方,舞台区域会滚动)也未验证。
- 行数是会话的累计值,不是最终 Git diff;使用自定义配置的 Agent 显示通用名称。forecast 行与额度百分比出现在同一格里,而 provider 概览里两者是分开的;它的措辞是「重置的可能性」,不是额度数字。
- 两块面板:纯逻辑测试覆盖原因、优先顺序、列表上限和保存的面板;jsdom 测试覆盖四个列表、打开会话、用量与重置卡片、切换、收起与展开面板,以及受控的面板。jsdom 没有 View Transitions,所以变形动画和时序未评审,列表密度、中文相对时间和窄宽度下的这一行也未评审。作者沙箱没有 Node 运行时,以上都未运行。
