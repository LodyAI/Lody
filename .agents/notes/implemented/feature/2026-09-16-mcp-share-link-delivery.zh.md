# 将批准后的完整分享链接返回给 agent

Status: implemented
Translation: current

[English](2026-09-16-mcp-share-link-delivery.md)

## 摘要

过去 MCP 分享只返回待批准请求，用户需要自行发布并复制结果。现在一次明确的授权卡片
启动已有发布流程，并将完整访问 URL 返回给 agent。面向接收方加密的信箱支持换设备批准，
控制面不保存明文凭据。每次请求创建独立分享，因此既不需要另一台设备的旧凭据，
也不会改变旧链接读者能够访问的内容。

## 职责与取舍

应用负责批准、冻结和发布；CLI 负责持久保存请求专属的 RSA-OAEP 接收私钥并本地解密。
云端保存公钥和加密后的读取凭据，在部署准入时绑定密文，发布完成后才允许领取。
OAEP 标签绑定请求记录和分享域名。这是凭据交付，不是分享内容加密。
原有授权仍是发布边界，持有接收私钥不代表可以批准请求。

仅使用本机回调无法覆盖 Web 和远程机器，重启也会丢失等待结果；保存明文 URL 违反凭据边界。
加密信箱复用规范请求记录和原子 begin 操作，无需新增 daemon 控制协议或应用代写权限。
代价是本地私钥存储以及客户端和服务端配套更新。缺少新授权字段的旧请求直接过期，
不会自动获得新增能力。

复审更正：工作区成员资格不能证明 daemon 账号正代表所声明的人类发起请求。
未披露的跨账号请求会把受害者批准的凭据交给另一提交方。现在 CLI 账号、当前请求者和实际批准者
必须是同一用户，提交准入及已有请求的发布、领取路径都强制执行此规则。
CLI 在创建密钥前拒绝身份不匹配，绝不替换成机器所有者。同账号跨设备批准仍可用，
但明确不支持跨账号共享机器上的 MCP 分享。相比仅展示接收方名称，选择了拒绝不匹配的权限边界；
跨账号委托需要另行验证的同意契约。这是账号绑定，不是 Session/Turn 来源的密码学证明，
也无法收回此前已经披露的凭据。

单次调用短暂等待，然后使用相同请求 ID、用途和目标继续领取；用户仅批准一次。
接收私钥跨 MCP 重启保留。24 小时领取窗口结束、链接重置或撤销、成员身份替换后不可领取。
上传中断沿用现有放弃和重试规则，不额外持久化上传凭据。
后续导出省略已知凭据片段，包括不透明工具输出；agent 和原会话保留完整 URL。

本决定扩展[静态发布决定](../../proposed/architecture/2026-09-12-static-session-sharing.md)，
并更新仍为 draft 的[分享规范](../../../../specs/session-sharing.zh.md)。

## 验证

行为测试覆盖接收方、请求和域名绑定、历史投影、单次点击发布、重试凭据、
服务端成员与结果门禁、独立分享，以及跨批准期限边界的发布。
本次不部署云端，也不发布真实用户会话。公开源码和托管服务变更需要配套 PR。
回归测试拒绝其他工作区写成员的直接 API 请求，并覆盖旧 pending、confirmed、sealed、published
请求及其重放路径的拒绝行为。

实现：[PR #762](https://github.com/LodyAI/Lody/pull/762)。
整合保留虚拟列表外的卡片边界；测试通过显式上传信号验证滚动与确认状态更新不会中断自动发布。
