# PR 标签页改为文档式：标题优先、一行状态、线程引用所评代码

Status: implemented
Translation: current

[English](2026-09-25-pr-tab-document-layout.md)

## 摘要

侧栏 PR 标签页原先把一个 PR 的身份拆成四块：页头里带编号的状态胶囊、两行带标签的分支、
重复编号的标题，以及一行元信息。评审线程则是嵌在填充区域里的 Tailwind 描边卡片，而这个区域
又位于活动卡片之内。所有者问：是保留这种"物理化"的外观，还是改走 GitHub 或 Linear 的路线。
现在的做法是：结构取自 Linear 和 GitHub，材质沿用 `@lody/ui`。标题领起全页；一行用文字说明
状态并写出 `base ← head`，另一行说明作者、创建时间和改动规模。活动行读起来像一句话，线程会
引用它所评论的代码。只起装饰作用的胶囊都去掉了。合并操作仍在右上角，改成一个安静的连体控件，为此 `@lody/ui` 新增了 `ButtonGroup`；检查和
可合并性合为下方的一张卡片。按钮仍然是凸起的，活动仍是一张带分隔线的
卡片，这两点是组件包规则的要求。

## 问题

改动前在 `Sessions/PrTabView` 故事中观察到：

- 编号出现两次（页头胶囊和标题后面），而状态只体现为胶囊的颜色。
- 目标/源各占一行并带标签，每个分支都是一个胶囊，所以在正文出现之前，页头、分支行和标题
  读起来是三条胶囊带。
- 标题只有 1.15em，与正文里 markdown 的 `##` 差不多大。因此 PR 模板（Related issue、
  Problem 等）会与标题争夺层级，并把检查和评审挤出屏幕。
- 评审里的线程有三层边：活动卡片、3% 填充区域，以及共享的 `GitHubCommentThread`，后者仍然
  画着 Tailwind 的 `border` + `shadow-xs` 卡片。它的头部有两个装饰性图标（GitHub、气泡）、
  未翻译的 "1 comment"，还有一个与 PR 标签页自己的徽标重复的"已过期"。差异视图的草稿卡片
  通过 `className` 改写了 `Textarea` 的样式，而 `packages/components/AGENTS.md` 禁止这样做。

## 决定

信息结构取自 Linear 和 GitHub，材质沿用 Lody。

- **不采用纯 GitHub 方案。** Primer 的盒子依靠 1px 描边，而 `@lody/ui` 没有描边 token，
  边缘只能是阴影、凹槽和填充。
- **不采用纯 Linear 扁平方案。** 设置页改成扁平时，所有者以"其他层级都有材质"为由否决了。
  见[设置页节奏](2026-09-25-settings-rhythm-and-image-peek.zh.md)。
- **保留 Lody 的做法：** 按钮凸起；检查和活动各是一张带分隔线的卡片；卡片里的线程是填充区域，
  而不是第二张卡片。
- **借鉴参考方案的做法：** 标题是页面主标题（1.4em）。带文字的状态胶囊（GitHub 的做法）是
  唯一明确写出状态的地方。分支像 git 工具那样写在同一行，形如 `main ← head`；目标分支是
  改动合入的地方，所以颜色更弱。页头改为面包屑 `repo / #n`，编号只出现一次。活动行读作一句话：
  头像、**用户名**、动作、时间。只有评审结论（批准、请求更改）带颜色。正文对齐用户名，而不是
  对齐头像。
- **离开差异视图的线程会引用所评代码。** 在 PR 标签页中，线程显示 `path:line`（路径从左侧
  截断，以保住文件名），并显示 GitHub `diff_hunk` 的末尾。GitHub 在被评论的那一行截断
  diff_hunk，所以单行评论取最后四行，多行评论取整个范围（最多八行）。在差异视图中，线程就在
  所评代码旁边，因此保留评论数，不显示代码摘录。`GitHubCommentThread` 新增
  `surface: 'card' | 'inset'` 与 `showAnchor` 两个属性，并已改为 StyleX。
- **长描述会折叠。** 正文高于 22em × 1.25 时折叠到 22em，并加上渐隐遮罩和"展开"幽灵按钮。
  高度由 ResizeObserver 实测，而不是根据文字长度推测；只会多出一两行时不折叠。描述仍然随面板
  一起滚动，没有自己的滚动区。
- **操作留在顶部，理由收进一张卡片。** 原先"能不能合并"有三个答案：页头的黑色拆分按钮、
  检查卡片，以及单独的冲突/受阻提示。所有者觉得页头这组按钮"合理又不合理"，主要是太重。
  - 先试过把操作挪进下方的卡片。所有者否决了，理由是合并不该需要往下翻。
  - 最终做法：下一步操作仍在右上角，但改成一个安静的 `ButtonGroup`。命令和下拉箭头是同一个
    形状里的两段，两段都是 `secondary`，不再是黑色 `primary`。
  - 合并图标沿用检查结果的颜色（通过为绿、失败为红、运行中为琥珀色），这样不用读字，按钮本身
    就表明现在合并是否稳妥。
  - 下拉菜单里放合并方式和"关闭"。关闭从来不是下一步，所以不单独占一个按钮。
  - 检查卡片变成了合并卡片：有结论标题（可以合并、冲突、受阻、检查中、草稿、已合并、已关闭）、
    检查汇总和可展开的各项检查，取代了原来单独的提示。如果非必需的检查失败但 PR 仍可合并，
    标记用警告而不是绿色对勾。
- **`@lody/ui` 新增 `ButtonGroup`。** 原先没有这个组件，产品里所有拆分按钮都是两个相隔 2px 的
  独立按钮，这正是旧页头看起来像"两块黑砖"的原因。各段保留外侧圆角，共享一侧改成直角，用的是
  `:first-child`/`:last-child` 长写属性，它们会压过尺寸样式里的 `borderRadius` 简写。各段之间
  相隔 1px，缝隙由两段边缘相接形成，不需要描边 token。其他拆分按钮（例如信息栏里
  `pr-merge-button.tsx` 的合并按钮）这次没有迁移。
- 差异视图中的行内草稿（`SessionCommentDraft`）也改成同样的卡片：使用标准 `Textarea` 凹槽和
  取消/评论按钮，并去掉了关闭图标，因为 Esc 和取消按钮都还在。

落地页嵌入模式（`embedded`）保留带 `PullRequestBadge` 的精简条，以及同样的页头操作；标题区、
合并卡片和活动区随之变化。

## 验证

- `tests/pr-tab-view.test.ts` 覆盖了摘录的边界（单行、范围、文件级）。它还检查编号只出现
  一次、状态胶囊为 `merged`；检查评审线程位于对应评审之下，并带有路径、行号、代码摘录和评论；
  以及过期线程初始为折叠预览，点击后可以展开。另外还检查：合并操作是页头的 `ButtonGroup`，结论在卡片里；已合并且分支已删除时页头没有操作；
  存在冲突时卡片写明冲突，页头提供"解决冲突"。`packages/ui/test/button.test.tsx` 检查分组内的按钮
  带有单独按钮所没有的分段样式类。
- 在 Chromium 中通过 Storybook 截取了以下故事：开启中（CI 失败）、380px 宽的已合并、
  长正文折叠、亮色与暗色、zh_CN，以及差异视图的 `SessionComment/GitHubThread` 故事。
- 尚未验证：连接真实 GitHub PR 的 Electron 会话。故事中使用的是合成的 diff hunk。
