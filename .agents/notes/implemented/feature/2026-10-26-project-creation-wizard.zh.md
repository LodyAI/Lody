# 引导式创建项目

Status: implemented
Translation: current

[English](2026-10-26-project-creation-wizard.md)

## 摘要

此前创建多成员 Project 只有一个编辑器，它的选择器把 GitHub 仓库、本地副本和绑定机器的
文件夹混在同一个列表里，用户难以分辨两类成员如何组合、对话会在哪里运行。现在创建改为
一组逐个回答的问题：包含本地文件夹还是仅 GitHub，然后选择机器，再选择成员，最后填写
名称和说明。运行位置在选择任何成员之前确定，修改它会移除不再适用的成员。编辑时
走同样的问题，并用「上次选择」标出项目当前的答案；Composer 的项目选择器新增了「创建项目」，
并按最近使用对多成员项目排序。

## 决策

用户要求重新设计创建流程而非编辑流程，并要求在设置和侧边栏菜单之外，在 Composer 的
项目选择器里也能创建。

- `ProjectCreateWizard` 是纯展示组件。`ProjectGroupEditorDialog` 仍负责识别、直接
  选择文件夹的准备和保存，创建和所有者编辑都渲染向导，因此保存、注册和子模块自动识别
  不变。无权修改项目的人仍在 `ProjectGroupForm` 中只读查看。
- 编辑从第一个问题开始。根据已保存项目推断范围（文件夹所在机器，或持有所用副本的机器，
  本机优先）并预先选中，之前的每个答案和成员都带「上次选择」标记。确认步骤只列出成员和
  路径，去掉了使用方式标签和运行位置说明。
- 范围是向导状态而不是存储数据。`retainProjectGroupScope` 会移除范围容纳不了的成员：
  其他机器上的文件夹；仅 GitHub 时移除所有文件夹，包括因带远端而可移植的直接选择文件夹
  （否则会为一个可在任意机器运行的项目写入该目录注册）。
- 选定机器后，该机器上的 GitHub 仓库副本出现在它的文件夹列表中（`preferLocal`），
  GitHub 标签页列出所有仓库，勾选即为独立克隆。允许同一个仓库在两个标签页都勾选，只给出
  提醒：项目只保留一个成员，使用本地文件夹。向导记住第二次勾选，两个标签页可以分别取消。
  仅 GitHub 范围也会把优先使用本地副本的成员改为独立克隆。
- 列表显示全部条目；搜索只做过滤，不再要求搜索才能看到其余条目。
- 选项是可按下的凸起卡片，进度是凹槽中的墨色填充，遵循 `@lody/ui` 的拟物材质，而不是扁平描边。
- 「下一步」和「创建」是带不同 key 的独立元素。共用一个位置时 React 会复用按钮，它在
  前进的那次点击中变成 `type="submit"`，浏览器随即提交表单，跳过最后一步直接创建了项目。
- 带种子的请求（侧边栏「基于此项目创建」）直接从成员步骤开始，范围由种子推断。
- Composer 选择器按最新对话排序，但从多成员项目发起的对话（`projectRun.id`）从未被统计，
  这类项目总排在所有用过的项目之后。现在首页的最近使用索引按 id 记录它们。
- 确认步骤说明运行位置以及每个成员的使用方式：直接修改原目录、使用本地副本或每个对话独立克隆。

取舍：向导没有目录名和手动子模块位置的控件。已保存的位置会保留，识别仍会自动嵌套新成员；
原本提示「无法读取子模块，请手动设置」指向的就是这些手动控件，所有者不会再看到它。
考虑过但未采用：新增一套选择机器的
协议（现有可见机器列表和 `projectFolderSelection` 能力已足够）。直接浏览仍和以前一样
只支持当前机器。

## 验证与限制

`tests/project-group-form.test.ts` 覆盖范围保留和名称建议。
`tests/e2e/project-create-wizard.spec.ts` 在 Storybook 中驱动真实组件：选择机器、
跨标签页选择、切换机器（移除其文件夹）、切换为仅 GitHub、在确认步骤移除成员、同一仓库在两个标签页都勾选，以及前进到最后一步时
不会创建项目（按钮不带 key 时这条断言会失败），以及带标记的编辑流程。
`tests/chat-landing-derived.test.ts` 覆盖按项目 id 统计最近使用。
截图来自同一组使用合成数据的 story；没有从新建的 Project 启动端到端会话，也没有运行完整
`pnpm check`。
