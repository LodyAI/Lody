# 显式恢复本机加密身份

Status: implemented
Translation: current

PR: [#1970](https://github.com/LodyAI/Lody/pull/1970)

[English](2026-10-27-e2ee-local-identity-reset.md)

## 摘要

设备、凭证、保护资料或配对原件损坏后，加密工作区可能永久无法重新配对。显式重置会排空对应 owner，将完整本机身份目录改名为带时间戳的归档，保留证据并要求审批全新身份。桌面保管、日志和运行数据按工作区隔离；系统保护永久丢失时仍提供账号级归档。不自动降低保护等级，不撤销远端设备，不重放归档中的未发送数据。合成系统包装加真实原生存储测试证明本机行为，不代表真实钥匙串或安装包双设备验收。

## 决策与所有权

Owner 为 MVP 选择显式恢复，不兼容此前仅供开发的目录。普通重试仍遵守[配对恢复决策](../bug-fix/2026-10-27-e2ee-local-pairing-recovery.zh.md)，保留原件。重置不取消未知的远端准入，不撤销旧签名。新身份需要另一台合法设备审批。渲染器的 genesis 固定值、已观察检查点和模式证据均保留。

`lody workspace reset-identity <workspace-id> --confirm` 在发送前打印 UUID；结果未知时使用同一 `--reset-id` 重试。Fleet 核对账号、机器和加密工作区，阻止新启动及准备，等待已接纳的激活与启动，再排空对应运行实例。清理失败保留已有 owner。其他进程在整个原生身份生命周期持有共享 SQLite 租约；重置在被改名目录之外的固定兄弟文件获取独占租约。锁忙时立即、可重试地拒绝；实际关闭或进程退出释放锁，不根据 PID 或时间接管。

同卷改名保留设备、凭证、保护资料、绑定、日志、SQLite 边车和运行目录。改名前在不可变回执中记录目的地与原目录 inode；独立完成标记阻止迟到计划作用于替代目录。桌面回执位于账号目录之外，账号整体归档后仍保留。重试可完成中断的移动；已完成重置的重试直接返回回执，不停止后来已配对的身份。回执自身写入中断时显式报错，可发起新的重置恢复。不删除任何原件。归档保留期有意不设上限，等待另行授权的证据管理策略。

桌面账号协调者在 `identities/<workspaceId>` 持有独立 Scope，各自包含 KEK、设备、凭证、bootstrap 日志和运行数据。未完成创建位于 `pending/<requestId hash>`；服务端发布后整体移动。请求到工作区的回执保证创建重试仍返回原签名字节。重置在确认调用时同步绑定账号 ID 与原生认证 generation，并在取得锁、读取回执、原生 drain 和取得租约后复核；任一变化就拒绝本次归档。drain 可能已经关闭旧所有者，但新确认后可以正常重开，其他账号与工作区目录不变。工作区重置仅关闭该 owner；账号重置尝试所有独立清理后，整体归档账号目录，也包含未完成创建。原生操作在实际完成前仍由旧 Scope 持有；关闭失败不允许不安全替代。新增文件与租约叶子使用原生 Effect；迁移其余 Fleet/IPC Promise 编排会牵涉未完成 owner，另行处理。

显式机器重置还归档桌面完整旧审批行（material/request/record），保存重置 UUID，选择新同意会话，不声称撤回远端已签准入。正常准备及激活 schema 不变，归档路由独立于远端配对改动。

## 失败与界面策略

`permissions` 表示修复仅所有者访问后重试：POSIX 目录 700、文件 600，Windows 使用仅所有者 DACL。bootstrap 两处存储边界把明确的 SQLite 镜像损坏（主错误码 11/26，CORRUPT/NOTADB）分类为 `corrupt`，保留损坏字节并显示已有恢复入口；busy/locked 和其他 I/O 错误不当作损坏。KEK、选择标记、系统包装密钥和身份原件缺失或损坏时提供显式重置；其他原件仍在时禁止自动生成替代 KEK。系统保护锁定或不可用时，先引导解锁或启动 Secret Service/KWallet 并重试。原生解密失败无法区分锁定与丢失，所以同时说明重试和显式账号归档。桌面个人身份始终要求系统保护。此前采用系统保护或保护状态未知的 CLI 身份，重置后仍要求系统保护；明确原为文件保护的机器可保留原等级。普通机器首次创建仍使用此前批准的选择策略。

preload 桥显式放行两个受限重置方法，main 仍校验可信产品窗口 sender、显式确认及输入范围。原生账本打开、个人配对和本机代理准备错误旁都有恢复入口。确认说明影响范围、证据保留、未发送数据、全新审批及不撤销远端设备。保管不可用时仍能查看验证后的只读历史。真正的 genesis/模式冲突和历史连续性冲突保留原保护。旧账号共享开发目录不导入或迁移；若存在，账号归档会保留。

组合 #1964 时，`readIdentity` 按工作区目录打开，并禁止自动创建。冷读取不授予 reader，保留已有 reader，也不创建默认 control 身份。原生 `e2ee_conflict` 保留 main 的身份冲突分类，不把真正的 pin 冲突当作可修复保管故障。

验证时 [#1978](https://github.com/LodyAI/Lody/pull/1978) 仍是独立 draft，本变更尚未接入其 `local-history-recovery-required`、`trusted-pin-unavailable` 和 `restart-required`。后合入者需把前两者接入显式恢复界面，不能改变 pin 的信任来源；restart-required 仍要求重启，不能据此替换尚未释放的写入者。

## 证据与限制

真实文件和 crypto 测试分别破坏凭证、设备、KEK、选择标记和 material 日志。先证明普通配对失败，再证明显式重置保留所有剩余字节，新准备使用独立签名密钥、凭证、KEK 和日志。租约争用时拒绝归档。撤回重置实现后六个恢复用例全部失败。桌面测试用经过认证的合成系统包装加真实 crypto/SQLite，验证创建交接与原字节重试、工作区归档、兄弟工作区可用、重置幂等，以及系统保护不可用时的账号归档。界面测试要求显式确认和新的配对审批，权限修复不提供破坏性捷径。

12 条定向审查回归在撤回修复时失败，修复后通过：8 条显式信号控制的账号/generation 竞态、真实 preload 到 main 的重置、冷工作区身份读取，以及两种原生 SQLite 镜像损坏。preload 链路使用真实保管/SQLite 归档和新配对 session，并验证不可信 sender 与未确认请求被拒。检查覆盖受影响 CLI、Electron、core、shared、platform 与渲染器路径。真实系统钥匙串、Windows ACL、安装包生命周期、实体多设备及远端配对组合、生产部署仍未验证。归档可能包含未发送数据和仍有效的旧加密凭证。本变更不启用 M5 或未实现的明文通道。

组合 #1954 时保留按工作区隔离，同时让桌面桥接完整传递仅刷新账本的 `installKeys: false`。密钥收取保留 staging 与 mailbox 两条适配路径，重置不恢复旧的 epoch 发送阻塞。#1966 独立的认证目录重建与测试临时锁所有权均保留。
