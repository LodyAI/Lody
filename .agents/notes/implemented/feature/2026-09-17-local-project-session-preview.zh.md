# 本地项目使用有界的会话预览

Status: implemented
Translation: current

[English](2026-09-17-local-project-session-preview.md)

## 摘要

工作区模式原本已经将 GitHub worktree 分组限制为最近五个顶层会话，但展开的本地项目仍会渲染全部历史记录，可能占满整个侧边栏。现在本地项目也使用相同的五个根会话预览和「显示全部／收起」交互，并保证由可见根会话打开的会话仍紧跟其后。渲染层与键盘导航投影共享同一展开状态；折叠整个项目后，下次展开会恢复紧凑预览。

## 问题与决定

侧边栏存在两种项目形态的会话分组：会话运行在 worktree 中的 GitHub 仓库，以及注册为本地项目的文件夹。此前只有前者使用 `MAX_VISIBLE_SESSIONS`，导致展示多少历史记录取决于项目的存储方式，而不是用户的浏览任务。历史较长的本地文件夹会把其他项目推到可视区域之外，而等价的仓库分组仍保持紧凑。

`LocalProjectItem` 现在对 opened-by 树应用既有的顶层根节点上限，并渲染同一套已本地化的「显示全部／收起」控件。上限刻意按根节点而不是最终渲染行数计算：由 MCP 打开的会话会继续直接跟在其打开者下方，不会在任意行边界处被截断。控件状态复用 `sidebarShowFullListAtom`，并采用 `local-project:<machine>:<project>` 键，避免本地项目身份与仓库全名冲突。

键盘导航模型接收相同的展开位与上限。虽然普通焦点导航跟随 DOM 行，全局的上一个／下一个会话命令读取的是扁平化导航模型，因此它不能访问预览中隐藏的历史记录。折叠本地项目会清除其展开位，与既有仓库分组行为一致，也避免旧的「显示全部」选择在稍后意外恢复成长列表。

## 备选方案与权衡

把本地项目的独立状态保存在每一行内部可以减少父组件属性，但键盘模型随后需要第二个状态来源，可能与实际渲染列表偏离。直接复用 `machineId:localProjectId` 原始键也被否决，因为同一个 atom 还存储仓库键；显式命名空间让两个键域保持不相交。「显示全部」中的数字继续表示会话总数，以匹配既有 GitHub 控件，而是否出现该控件仍按顶层根会话数判断。

## 验证

`sidebar-local-project-row.test.tsx` 覆盖五行预览、带命名空间的切换操作，以及展开后的七行结果。`sidebar-navigation-model.test.ts` 覆盖相同的紧凑／展开投影及其「显示更多」导航项。既有 opened-by 测试继续覆盖根子关系保持与打开者折叠行为。
