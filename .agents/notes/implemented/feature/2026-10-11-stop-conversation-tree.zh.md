# 终止对话树并阻止自动重新唤醒

Status: implemented
Translation: current

[English](2026-10-11-stop-conversation-tree.md)

## 摘要

停止一个回合无法防止其他 Agent 的晚到结果再次唤醒它。
关联对话面板新增整树终止确认，持久化由用户控制的停止状态，由执行入口和完成回传共同落实。
恢复执行（包括手动执行）前必须明确恢复协作，普通消息不会意外放开旧协作。
离线机器同步后才会停止，因此这不是跨机器原子取消。

## 决策与职责

界面从权威元数据读取完整树，检查机器能力，先停止根节点、最后恢复根节点。
范围包含隐藏和归档的后代，并取消本地待发送项。CLI 在初始化和发送 prompt 前读取实时祖先，
取消精确的活动回合但保留队列，拒绝继续通过 MCP 委派，并消费晚到完成结果而不启动续接。
Agent 不能清除停止状态。范围由创建与包含关系定义；任意消息接收方不会自动加入树。

重复调用普通停止不足以解决问题，因为晚到回传会启动新回合。
考虑过用户发消息时自动恢复，但没有采用，以免意外释放旧协作；代价是持久化状态和显式恢复操作。
它补充了 [16 层限制](../bug-fix/2026-10-11-bound-agent-message-chains.zh.md)。
[编排 Spec](../../../../specs/session-orchestration.zh.md) 仍为草案。

## 证据与限制

行为测试覆盖权威树选择、不支持能力的机器拒绝、晚建后代继承、确认/取消/恢复，以及阻止完成续接重放。
