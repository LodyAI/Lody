## 摘要

原静态分享串行获取文档、复制图片、上传和检查封存条件，同时发送运行元数据及未压缩 JSON。
现在冻结时提取分享内容、省略终端输出，并复用现有 Zstd worker 压缩每份历史。
四个并发任务重叠执行独立 I/O，保留身份和完整发布要求。
上传前仍以 manifest 绑定完整包，本次没有引入逐对话上传准入或 multipart 状态。

本决策部分取代[静态分享设计](../../proposed/architecture/2026-09-12-static-session-sharing.md)
中完整保留历史的决策。当前省略、兼容和披露规则由仍为 draft 的
[分享 Spec](../../../../specs/session-sharing.zh.md)定义。

| 阶段 | 工作与约束                                                         |
| ---- | ------------------------------------------------------------------ |
| 冻结 | 四个文档并发获取，随后同步分离全部选中历史                         |
| 准备 | 先确定附件 ID，再以四并发复制；四个历史编码任务复用已有压缩 worker |
| 上传 | 同时上传四个不同的不可变对象，进度按压缩字节计算                   |
| 封存 | 同时检查四个存储对象，全部存在后才允许提交                         |

任务失败后取消同批任务，等待已启动任务结束再释放源租约。多份对话引用同一图片时仍只复制一次。
保留未知内容和不透明工具数据；运行句柄及发送/Role 配置在分享中不可用。
本次变更最初保留终端日志尾部，随后按用户“只分享命令”的决策改为完整省略类型明确的输出块
（包括退出状态），命令保持不变。工具标题与第一条终端命令完全相同时，在传输格式中省略，
读取时恢复；其他标题保留。导出校验不得在编码前恢复标题。
这不会改写本地已保存历史，也不会按启发式规则清除不透明工具数据。

格式第 2 版显式描述 Zstd，不使用 HTTP Content-Encoding，避免浏览器在校验哈希前自动解压。
小型纯 JS 解码器供读取端和可选服务集成使用；分配前检查单帧、帧长度和窗口，随后限制解压输出。
仅应用提供已有 worker 压缩器；无压缩收益的对象和图片保留原字节。仍可读取 V1。
Agent 链接继续返回普通 JSON，压缩不会扩大访问权限。

确定性测试覆盖真实编解码、异常/超限帧、稳定排序、共享图片去重、同批取消、源内容不变、
终端输出省略、传输标题去重、读取时标题恢复和封存顺序。
这些检查不能证明线上服务或原生设备性能。协调发布时应先提供服务端和读取端支持，再启用 V2 发布。
本次没有部署线上服务。
