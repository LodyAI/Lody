# 错误页与未找到页共用一个 V2 版式

Status: implemented
Translation: current

[English](2026-09-25-v2-error-pages.md)

## 摘要

Lody 的各类失败页面是在不同时期、用不同体系做出来的。React 挂载前的启动失败页是内联样式卡片，
带红色小标题、粉色错误块，主按钮是「Copy error」；404 页是 Tailwind 加一个 9xl 的「404」；
会话不存在页是灰色图标圆盘；崩溃页把一张卡片浮在页面上。现在它们都站在同一个框架 `StatusPage`
里，用 V2 的材质：不用卡片，页面底色上居中的一列。开头是一幅 Lody 窗口的小插画，动一次说明
发生了什么；接着是安抚的一句话和出路，原始错误和详情放在下方，更安静。启动失败页必须在 React 或 StyleX 都没跑起来时也能渲染，所以不能用这个组件；
它用纯 DOM 画同一列，把 V2 token 的值抄进一个限定作用域的样式表。代价是这些抄写的值可能与
`@lody/ui` 的 token 走偏，而没有测试能发现。

## 决策

- **一个框架，三种布局。** `components/status-page.tsx` 渲染插画、标题、一句说明，然后是调用方的
  内容块，居中排列。
  `window` 占满整个窗口：页面底色、自带滚动（外壳会裁掉 `#root`）以及桌面端拖拽条——否则整窗失败时，
  隐藏标题栏的窗口无法拖动。`pane` 填满一个已有底色的面板。`region` 就是原来的 section 边界：
  region 层的块，左对齐，字号更小，用 danger 语气的圆形标记代替插画。
- **安静，而不是吓人。** Owner 觉得第一版 V2「让人心慌」：红色标记、原始错误排在最前、
  红色的清除按钮。现在页面以插画代替标记开头。文案先安抚（「你的会话和文件都没有受影响」）。
  错误原文按崩溃恢复规则仍留在页面上，但放在按钮之后，用次要文字色。清除改为脚注里的低调链接，
  代价由确认对话框说明。
- **插画承载事件。** `lib/status-illustrations.ts` 保存两段 Lody 窗口的 SVG 字符串。`broken`
  里，一块内容从槽位滑出，歪着落在窗口下方，带一个小的撞击标记。`missing` 里，放大镜扫过空的
  内容区。都只动一次，之后静止；减少动态效果时完全不动。一直在动的页面会一直索取注意力。
- **不用卡片。** 失败的页面就是页面本身。旧卡片下面的晕影阴影读起来像第二层，
  也违反了层级规则：卡片是页面上的块，而不是页面。
- **出路在前。** 启动失败页的主按钮是「重新加载」，复制是次要按钮。崩溃页四步的「如果问题反复出现」
  列表是在重复上方的按钮，因此压缩成一行脚注（含 Discord 链接）和最后手段的清除按钮，
  清除仍需确认对话框。
- **每个页面说只有它知道的事。** 404 显示被请求的地址。启动失败页在代码块加载失败时说明最可能的修复办法，
  显示当前构建，在渲染进程崩溃时用单独的标题（`surface: 'recovery'`）。它跟随已保存的主题
  （`vite-ui-theme`）和语言（`lody-language`），因为 ThemeProvider 和 i18next 都还没运行。
- **启动失败页抄写 token 而不是导入。** 它是纯 DOM 加一个限定在 `.lody-boot-failure` 下的 `<style>`，
  渲染进程 CSP 本就允许。插画是用 `--si-*` 自定义属性上色的普通字符串，两个页面共用一个来源：
  React 从 token 设置这些属性，启动页样式表用抄写的字面值。导入 `@lody/ui` token 会在运行时调用 `stylex.defineVars`，
  而那恰好会抛出这个页面正在报告的错误。

## 考虑过的方案

- **把 `StatusPage` 放进 `@lody/ui`。** 暂不采用。它组合了产品行为（Electron 拖拽条），
  有三个产品调用方；做成包内原语需要自己的 token 组、gallery 条目和规则章节。
  框架只读取 `@lody/ui` 的 token，以后可以迁过去。
- **现成插画或吉祥物。** 不采用：owner 认为装饰显得廉价。插画画的是产品自己的窗口、用产品
  自己的材质，表达发生了什么，而不是营造情绪。
- **写测试解析 `colors.stylex.ts` 来锁定启动失败页抄写的值。** 不采用：那是源码字符串断言。
  走偏风险改为记录在文件头和 `lib/AGENTS.md` 中。

## 验证

`tests/boot-failure.test.ts` 渲染这个 DOM 页面，检查：替换掉已提交一半的树、按钮顺序、
诊断信息在展开前保持折叠、复制成功在按钮上确认并用假时钟复位。也检查：复制被阻止时展开诊断信息、
重新加载只在点击后发生、跟随已保存的语言和配色。崩溃页和消息列表的测试套件在新框架下保留了行为覆盖。
所有页面都通过 Storybook 在 Chromium 中截图检查，浅色和深色都有（`Pages/BootFailure`、
`Components/ErrorBoundaryFallback`、`Pages/NotFound`、`Components/SessionNotFound`、
`Sessions/MessageListErrorFallback` 以及分享页的 unsupported-content story）。在下落中途暂停的一帧确认了下落路径。
打包后的桌面端 recovery 页面和真实 macOS 窗口上的拖拽条没有实际验证。
`components/sessions/session-file-error-state.tsx` 是文件预览的提示而不是页面，保留原来的 Tailwind 卡片。
