# 点击把 Mermaid 图变成画布

Status: implemented
Translation: current

[English](2026-09-10-mermaid-click-to-activate.md)

## 摘要

把滚轮从消息中的图上收回（[前一条记录](../bug-fix/2026-09-09-mermaid-diagram-gestures.md)）之后，
缩放只能经由全屏查看器触达，而为了看清一个节点就打开全屏过于笨重。现在指针点击会就地激活该图：那一张
图变成画布，触控板捏合会围绕指针缩放、拖拽会平移，按 Escape、在别处按下或打开查看器即可释放。未加
修饰键的滚轮无论是否激活都绝不被吞掉，因此忘记自己激活过图的读者始终能滚过它——前一条记录消除的那个
陷阱不会回来。全屏入口移到该块自己的操作栏按钮上，触摸仍然打开查看器而不是获得行内捏合，因为自定义
触摸画布将不得不为查看器本就要服务的手机场景重新实现惯性平移。

## 决策

激活是一种带显式释放的指针能力，这正是嵌入式地图所采用的模式：读者主动进入画布，因此在其中捕获手势
是诚实的，而在此之前什么都不捕获。

- 只有作用于**已激活**图上的、带 ctrl 或 meta 修饰的滚轮才会被消费。其他所有滚轮保持先前行为——在
  Streamdown 的画布之上被拦截、绝不 `preventDefault()`，并以不可取消的副本重新派发，使会话自身的
  滚轮监听器仍能看到它。
- 变换写入 `<svg>`，它由 Streamdown 作为原始标记注入且从不触碰。Streamdown 自己的平移/缩放画布被
  钉在 `transform: none`，因此其仍然存活的指针 handler 既动不了任何东西，也无法与我们相争。
- 几何计算在视口坐标系中进行（`mermaid-inline-canvas.ts`）：框体矩形与图当前的矩形足以锚定捏合并钳制
  平移，布局偏移会相互抵消。先前尝试过改为建模 Streamdown 的布局，那是错的——它会把窄图居中于与消息
  同宽的框体中，任何变换都无法还原。
- 释放会重置变换。会话中的这份拷贝是预览而非已保存的视图，留在放大状态的图会被读成渲染 bug。
- 触摸不激活。`pointerType` 取自点击之前的 `pointerdown`，因为并非每个引擎的 `click` 都携带它。

键盘用户获得同一块画布：Enter 切换，方向键平移，`+`/`-` 缩放，Escape 释放。否则激活就会成为藏在一个
可聚焦控件之后的、仅限指针的能力。

## 证据与限制

`tests/markdown-mermaid-fullscreen.test.tsx` 覆盖纯几何（锚定捏合、重新居中、边缘钳制、缩放上限、
捏合可逆性）与 DOM 行为：鼠标点击会激活并为图加上描边而不打开查看器，捏合会缩放它，作用于已激活图上
未加修饰键的滚轮仍然交还给页面，拖拽会平移，Escape 恢复预览，在别处按下会释放，而触摸轻点改为打开
查看器。27 个测试通过；`packages/components` 类型检查与 lint 干净。

Chromium 通过 Playwright 驱动真实的 `MermaidStyleReview` story。静息态：无描边，300px 滚轮使容器滚动
300。激活态：描边出现（`outline: rgb(255, 199, 153) solid 2px`），同样的滚轮仍滚动 300，带 ctrl 的
滚轮把图缩放到 1.284 而不缩放窗口，60px 拖拽恰好移动 60，Escape 同时清除变换与描边，操作栏按钮以
121% 打开查看器。

限制：一次捏合之后，Chromium 会把该滚轮手势流的其余部分继续路由给消费了它的 handler，因此同一手势流
中紧接着的滚动不会移动页面；真实触控板手势在手指抬起时结束，而同一探针在任何捏合之前都能正常滚动。
未在设备上验证触摸。激活描边不得不以 `important` 内联写入：一条样式表规则（经隔离验证正确、且确实存在
于服务的 CSS 中）在 Storybook 页面里仍被某个已作用于 Streamdown 画布的东西压过；成因当时未查明，内联
写入绕开了它。静息态的光标同样来自那条未查明的规则，而非本次改动。

## 更正

对本次改动的评审发现了四个缺陷与一条过时注释；它们都在同一个 pull request 中修复，上文未查明的成因
现在也已定位。

描边的样式表规则被 `tailwind/index.css` 中全局的
`*:focus, *:focus-visible { outline: none !important }` 压过——激活会聚焦该图，而特异性赢不过
`important`。因此内联 `important` 是必要的，而不只是权宜之计。曾尝试把描边移回样式表，在找到那条规则
之前于 Chromium 中复现了失败（`outline: 0px none`）。静息态的 `zoom-in` 光标同样并非无法解释：它来自
同一文件中既有的 `.markdown-renderer [data-streamdown='mermaid'] > div` 规则，该规则现在为激活态补上了
配套的 `grab`。

这些缺陷在修复前都于 Chromium 中复现、修复后重新检查：

- 在图上普通点击会关闭查看器。平移会在滚动表面上获取 pointer capture，而 pointer capture 会把随后的
  `click` 重定向到捕获元素，因此该 click 以该表面为 target 到达，被读成点击背景。现在由「按下从哪里
  开始」决定，真正始于背景的按下仍然会关闭。
- 图处于激活态时，Escape 会在整个文档范围被响应：该分支位于焦点检查之上，因此在别处输入框中按下的
  Escape 会被 `preventDefault()`，焦点还会被拉到图上。现在每个按键都以「焦点在画布之内」为前提，用
  键盘离开即释放。
- 禁用路径恢复了属性并清空了块，却从未释放处于激活态的画布，导致其文档级监听器绑定在一个已脱离文档的
  元素上。
- observer 在每次 mutation 时都重新标记每一张图。在 Chromium 中从聚焦元素上移除 `tabindex` 会让它失焦
  （已直接验证），因此一次流式 turn 会把已激活的画布挤出键盘可达范围；`aria-label` 也被反复重写。
  现在图只标记一次。

四个测试覆盖这些行为，并逐一确认在未修复的代码上会失败。Chromium 的失焦行为超出 jsdom 的建模范围——
它不实现该失焦——因此那个测试改为观察属性 mutation，失焦本身在浏览器中验证。
