# 登录页：内嵌抖动视觉、等权的登录方式与"上次使用"标记

Status: implemented
Translation: current

[English](2026-10-17-login-inset-visual-last-used.md)

## 摘要

原登录页是一个居中的小卡片，GitHub 按钮为实心填充而其他提供方为描边，看起来像是推荐而非选择；回访用户也得不到"上次用的是哪种方式"的提示。现在页面分为两部分：左侧内嵌区域以 1-bit 有序抖动 shader 绘制 Lody 水母并配产品标语，右侧一栏把登录方式做成一组等权的次级按钮，邮箱作为下方的 ghost 入口。本设备上一次成功完成的登录方式会被标注"上次使用"，它作为设备偏好保存，只记录方式本身。进入页面时，抖动画面从中心向外逐渐显影，右栏各部分依次上浮淡入，避免页面一下子全部出现。OAuth 与邮箱视图切换时，下方内容组不再改变尺寸：CSS 为 header 和面板保留稳定轨道，视图只在轨道内交叉淡入和滑动。该视觉仅为装饰：没有 WebGL 或开启减少动态效果时，退化为纯色底面或单帧静止画面。

## 布局

- `login-page.tsx` 用 StyleX 实现外壳：左侧内嵌视觉（`radius.large`，在页面背景上混入 5% 的墨色）与右侧 360–440px 的登录栏组成网格。
- 宽度小于 860px 时上下堆叠：视觉区变为顶部区块（`clamp(200px, 42svh, 360px)`），登录栏的按钮组仍压在底部，便于拇指操作。打开邮箱表单时顶部区块收起为零高度，把空间留给输入框和软键盘。窄且高度小于 600px 的窗口（横屏手机）不显示视觉。页面按安全区留白并使用 `100dvh`，避免被原生壳或移动浏览器的工具栏遮挡。
- 登录栏上下锚定：顶部标志与视觉区域的上沿对齐，标题、登录方式与条款压在底部，与标语处于同一基线。下方内容组使用普通 CSS，最小占位为 474px。header 是三行网格：36px 返回槽、34px 标题槽，以及至少 42px 的两行说明槽；活动视图槽至少 246px，并把子元素贴底。OAuth 的 216px 登录方式列表与 246px 邮箱表单因此共享同一底边；没有返回按钮或第二行说明时，相应网格轨道仍会保留。桌面、上下堆叠和手机宽度下，OAuth 与邮箱的外部几何都完全一致，因此不存在高度测量、inline style、ResizeObserver 或高度 spring。更大的状态仍可超过最小值。邮箱登录/注册使用同一条协调 spring：Name 行展开时以负 margin 吸收父级 gap，Forgot password 行在收起时自己持有 6px 内边距，固定 header 轨道中的标题与说明同步交叉淡入。这样外部 gap 不会在挂载时突然出现，也不会等退出结束后才消失。返回控件从绝对定位的角落按钮改为标题区内的 ghost `Button`。
- 每个提供方都是 `variant="secondary" size="large"`，图标与文字从按钮边缘起排，各行天然对齐，因此去掉了原先隐藏的文字测量元素。"或"分隔线及其文案键已删除。
- 其余面板（邮箱表单、验证提示、桌面端、浏览器交接）行为与 Tailwind 内部样式不变；仅验证提示图标去掉了强调色，以保持页面中性。

## 视觉

`login-dither-visual.tsx` 对水母做光线步进，并按 8×8 Bayer 矩阵以每格 3 个 CSS 像素做阈值化。纸色与墨色取自容器计算后的 `background-color` 与 `color`（通过绘制来解析，因为 `color-mix` 会序列化为 `oklab()`），因此随主题变化。标语的实测区域（通过 `keepClearRef` 传入）不绘制抖动点，在任何尺寸下都保持可读；水母在宽画面中偏右，在方形或竖长画面中居中。入场时以 1.6 秒的径向显影逐步提高抖动密度；右栏的标志、标题、登录方式与条款用 framer-motion 依次出现，标语随后淡入。减少动态效果时两者都跳过，直接显示终态。画布按整数格子设定尺寸，以每格恰好 3px 显示，而不是拉伸铺满容器；尺寸变化时在 ResizeObserver 回调内立即重画。拉伸会让每格宽度带上随窗口变化的小数像素，拖动窗口时点阵会游动；而等到下一个动画帧再画，则会呈现一帧被清空的空白画面。文档隐藏时暂停，`prefers-reduced-motion` 下只渲染一帧，卸载时释放 WebGL 上下文。没有 `WebGLRenderingContext`（jsdom、GPU 被禁用）时不绘制任何内容。

## 上次使用

`lib/last-login-method.ts` 把 `github | google | apple | discord | email` 存入 `localStorage` 的 `lody.auth.last_login_method`。只在登录真正完成时写入：OAuth 返回（`readAndClearPendingOAuth` 解析到标记）、原生 OAuth 完成，以及邮箱登录成功。仅开始但放弃的 OAuth 尝试不会改变标记。它属于偏好：清缓存时保留，退出登录也不清除，且从不记录账号。存储抛错或值未知时不显示标记。

考虑过的替代方案：从会话推导登录方式（better-auth 不向客户端暴露当前会话由哪个提供方创建），以及使用 cookie（一个纯本地提示会随每个请求发送）。

## 验证

`tests/login-last-used-method.test.tsx` 覆盖：新设备无标记、OAuth 往返后显示标记、放弃的尝试不显示、邮箱登录成功后标记邮箱、存储值非法时不显示。Storybook 新增 `Last Used (Google)` 与 `Last Used (Email)`。定向测试的 5 个用例全部通过。使用无头 Chrome 在运行中的 Default story 上检查 1000px、850px 与 390px 三种宽度时，OAuth → 邮箱 → OAuth 切换前、中、后的几何完全一致：body 始终为 474.19px，header 为 128px，活动视图槽为 246px，标题与条款坐标不变，且 body 没有 inline height。邮箱登录切换为注册时则覆盖了刻意更大的状态：已有的姓名字段显影让普通 body 从 474.19px 经 504.45px、535.17px 连续增长到 538.19px，底边保持固定。用户录屏中的第一次邮箱模式切换暴露了动画行两侧的两个离散 CSS gap；把它们移入 spring 后，浏览器正向轨迹为 474.19px → 490.86px → 512.56px → 526.27px → 537.61px，弹性峰值 539.56px，最终落在 538.19px。反向从 538.19px 连续收敛到 474.19px。在首个 spring 仅运行 100ms 时立刻反向，会保留当前速度（521.91px → 528.22px → 474.81px），而不是重启动画或跳值。标题和提交按钮文案也在同一时间线交叉淡入。包级类型检查目前被 `loro-sidebar.tsx` 与 `home-week-usage.ts` 中已有的错误阻塞。完整包测试尝试超过了 120 秒命令上限，并在此前出现一个无关的既有侧栏宽度断言错误（期望 `-280px`，实际 `-300px`）。
