# Devbar 运行时会话采集

Status: implemented
Translation: current

Implementation: [PR #860](https://github.com/LodyAI/Lody/pull/860)

[English](2026-09-21-devbar-conversation-capture.md)

## 摘要

排查短暂的聊天闪烁需要在进入会话前准备采样，但连接浏览器调试器又需要重启已安装的
应用及其 Agent。现有运行时 Devbar 现在提供主动开启的有界会话采集和剪贴板报告，
直接在当前 renderer 中记录视口几何和生命周期观察，不读取会话内容或 React 私有结构。
它不提供像素证据、CPU 调用栈、冷缓存保证，也没有证明被报告真实会话的闪烁成因。

## 决策

扩展[现有 Devbar](2026-09-16-devbar-hub-ui.zh.md) 底栏，不增加远程调试监听器或
Hub 权限。用户在导航前开始采集，问题出现后停止；结束时展示重新隐藏和可见行为空
的次数，并提供复制操作。可用性仍由已有 Developer Mode 边界控制。启用 Devbar 会
重载 renderer，因此应在打开目标会话之前启用，而不是在冷进入失败后才启用。

DOM 采样器读取现有会话视口和虚拟行属性，纯逻辑有界记录器分类同一路由下的状态
变化：初始隐藏是正常加载；显示后隐藏、视口消失、视口替换、可见行为空和保留锚点
位移分别记录。路由变化会重置首次显示基线。Long Task 和输入种类提供相对时间，
不读取输入值或 DOM 正文。路由和行别名只在本次采集中有效，报告只保留在 renderer
内存，主动请求后才复制。[Spec](../../../../specs/desktop-devbar.zh.md#会话采集)
拥有上限、清理和导出保证。

DOM 观察避免改变 reader/virtualizer 的职责或依赖 React Fiber 内部结构，代价是
纯绘制闪烁和内部投影替换可能仍需后续专门埋点。几何变化不自动等于缺陷，增加记录器
也不意味着已经找到真实成因；参见[此前的归因修正](https://github.com/LodyAI/Lody/pull/856)。

## 验证

现有 Devbar 测试覆盖首次显示与重新隐藏、导航重置、可见行消失及重新挂载、保留锚点
位移与用户滚动的区别、事件和样本上限，以及停止后的行为。运行时适配器通过显式
帧信号、可见性信号测试，包括采样失败和资源清理。浏览器用合成 DOM 内容操作实际
开始、停止、复制按钮：两次隐藏再显示和一次可见行移除准确得到两次重新隐藏、一次
可见窗口为空，复制报告不含消息正文。156 项 Electron 测试、node/web 类型检查和
改动范围 lint 全部通过。安装版的真实冷进入仍需在此实现构建进入 Desktop 后验收。
