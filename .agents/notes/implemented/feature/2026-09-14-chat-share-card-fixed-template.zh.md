# 对话分享卡片改为单一固定模板

Status: implemented
Translation: current

[English](2026-09-14-chat-share-card-fixed-template.md)

## 摘要

对话分享卡片此前是一个外观编辑器：六种背景、五种页脚布局、三档外框内边距、三选一
的明暗、四个开关，外加一个折叠代码块的数字输入框，可达的组合接近一千种，而其中值得
发出去的只有少数几种。这些控件还掩盖了两个缺陷——默认页脚只打印 Agent 名称，整张图
上没有任何 Lody 标识；默认的二维码永远编码产品首页而不是这段对话。现在卡片是一个固
定模板，只保留两个选择——卡片印成什么配色，以及印在什么底上，两者都改不了版面——并按
分享所在的设备给出手机版与电脑版两种形态；所有区块
共用同一个水平内边距，消息一律左对齐并靠不均等的纵向节奏分组，而不再把用户消息挂在
右边；预览界面也回到"预览 + 两个动作"，不再是控制面板。卡片仍然不限高，选得多就会得
到一张很长的图——这是刻意保留的：省略用户选中的消息会让图片与用户的选择不一致，而供
人阅读的完整对话本来就应该走分享链接。

## 决策

模板唯一的变量是设备。`phone` 是 16pt 外框内的 360pt 卡片，`desktop` 是 32pt 外框内
的 560pt 卡片。两者只在行宽和边距上不同——字号是共享的，并且是固定值而不是读取用户的
对话字号设置——因此两台设备导出的卡片会以同样的字号排同样的文字。
`ChatShareImageDialog` 由 `useIsMobile()` 推导形态，不提供任何选择控件；
`formatOverride` 仅供 Story 使用。

两种卡片的内边距集中在一张 `LAYOUT` 表里，而不是散落在标签上，"电脑版更舒展"因此是
一个决定而不是许多处。标题区、对话区和署名区共用同一个 `gutter` 值——这正是旧卡片做
不到的：它在不同区块之间混用 `px-5` 与 `px-6`，又把用户消息贴到右边，于是卡片里没有
任何东西共享同一条左边界。现在所有消息左对齐——一张分享出去的图，没有哪个读者的"我"
在右边——用户提问是一块浅色底的块，回复是普通正文。原先靠对齐承担的分组信息移到了纵
向节奏上：两轮问答之间的间距，是提问与它的回复之间间距的两倍。这正是卡片可以不加
说话人标签的原因。

出处信息留在旧设计已经做对的那条相机式说明栏里——Runtime、模型、token 估算、绝对日期
——而 Lody 署名移出卡片，印在下方的背景上：它不再占用对话的高度，也不会被读成记录的
一部分。缺失品牌标识的缺陷因此一并解决，且没有为第二个标识多花卡片高度。

二维码是被移除而不是被修好的。没有任何调用方传过 `shareUrl`，所以每一张导出的卡片编
码的都是 `https://lody.ai`；一行可读的 `lody.ai` 文字用十分之一的面积说了同一件事。
移除它也移除了它带来的异步资源——导出不再需要 `assetsReady` 门禁，因为剩下的资源只有
字体和一张打包图片，而截图管线本来就会等待它们。

背景保留为可选，这一条是更正：本次改动的第一版删掉了全部六种背景、把签名渐变写死，
理由是"一个不能让卡片变好的选择只是噪音"。这个理由对其中一种是错的。`welcome` 是开
场动画浅水场景的可导出静帧，是手工搭出来的——实景是 WebGL shader，DOM 截图序列化不
了——而且它在产品里没有第二个去处，所以删掉它是销毁了一份资产，不是移除了一个选项。
它同时也是唯一的浅色底，签名现在必须为它反向用墨。`aurora`、`ocean`、`sunset` 无论
如何都还活在用量卡片里。真正成立的分界是：改变卡片**怎么读**的选择（页脚版式、内边
距、消息挂在哪一边）是这次要删掉的编辑器；只改变它**读在什么之上**的选择是审美，属
于用户。`none` 留在这一组里，签名落到说明栏左列的第二行——和用量卡片已经写明的回退方
式一致——而不是另起一条独立的横栏。

代码软换行改为无条件生效。图片没有横向滚动条，一行不换行就等于读者看不到的一行；这
是媒介的属性，不是偏好。配套的 `collapseAfter` 控件随之删除，同时删掉的还有一个
`MutationObserver`——它在每次渲染后改写 Shiki 的代码 DOM 来裁剪过高的代码块并注入
"+N 行"药丸标签，等于在和渲染器争夺并不属于它的节点。

无条件换行暴露了三件被选项矩阵掩盖的事，它们都是靠对 Story 截图发现的，而不是靠读
diff。代码块的语言标签是一块停在右上角的不透明遮罩，在 App 里可行是因为过长的首行会横
向滚动到它下面；换行之后的首行永远不滚动，于是永远被遮住。把这段让位空间放在 `pre` 而
不是代码块 body 上不是风格取舍：App 的代码样式写在 `@layer components` 里，而层内的
important 声明优先级高于未分层的 important 声明，所以组件内联 `<style>` 根本盖不掉
body 上那条 important 的 `padding-block`——但能盖掉它的普通声明。代码块的复制按钮在预
览里也是完全不透明的，会被一起拍进图片，因此卡片把它隐藏。最后，预览区的高度用的是百
分比，而百分比在 flex 子项上并不成立，滚动容器因此没有上界，长卡片会直接画到操作栏上面
——现在改为 `flex-1` 加 `min-h-0`。

预览界面照此收敛：一个明暗开关，`复制图片` 与 `导出 PNG`。它以 App 当前的外观打开，
重置写在渲染阶段的分支里而不是 effect 里，因此重新打开的对话框不会有一帧显示上一次
的配色或结果提示。在手机上，同样的预览与动作渲染在底部抽屉而不是对话框里——这是两端
在外壳上唯一的差别。

已移除控件对应的 21 个文案键在两种语言里一并删除。`chatShareCard.qrAlt` 保留：用量卡
片仍然会画二维码。

## 备选方案

给卡片设置最大高度、超出部分渐隐并标注"还有 N 条"，这一方案被提出并由需求方否决：一
张悄悄丢掉用户已选消息的图片，陈述的内容与用户的选择不一致，而产品本来就能把完整对
话发布为静态分享链接。只做一种卡片尺寸、由外围界面按设备适配的方案同样被否决，最终
选择两种图片形态，理由是贴进手机聊天窗的卡片和贴进帖子的卡片会在不同宽度下被阅读。

把背景固定成一种、由亮/暗开关挑选签名渐变，这一版实现过，随后按需求方的判断回退。它
规则上更干净，还能自动做到浅卡配浅底，但代价仍然是删掉五种背景、其中一种不可恢复，
只为省下一排色块那么宽的一个控件。

## 证据与限制

[规格草案](../../../../specs/chat-share-image.md)承载意图，已在同一改动中更新；
[用量卡片规格](../../../../specs/usage-share-image.md)里那句"对话卡片的内容形态不
可预测，因而需要大量外观控件"的过时表述也一并修正。Story 覆盖两种形态 × 两种配色、每一种需要单独判断的底
（浅色底配两种卡片配色、一种高饱和底、无底配两种卡片配色）、无标题卡片，以及一个签
名行远宽于两种卡片的代码块。

工作区类型检查、lint、i18n 键检查，以及 Code Collab、平台与公开边界三项守卫全部通过。
`@lody/components` 测试套件 476 个文件中 474 个通过；失败的两个是
`control-plane-mirror` 与 `conversation-view-hooks`，都依赖时序，单独重跑都通过，且
从本次改动触及的任何文件都到不了它们。本次改动没有自己的单元测试，也没有新增：卡
片是纯展示组件，它喂给的导出管线没有变化且仍由
[导出测试](../../../../packages/components/tests/share-image-export.test.ts)覆盖，
而断言 class 字符串或 jsdom 量出的几何值的测试并不能发现视觉回归。验证方式是对卡片各
Story 以及对话框在桌面与手机视口下的 Storybook 截图，另外在浏览器里实测了标签让位空间
和被隐藏的复制按钮。没有建立像素基线，抽屉形态也没有在真机上验证过。本记录扩展
[最初的功能记录](2026-09-08-chat-share-image.md)与
[剪贴板后续记录](2026-09-08-chat-share-image-clipboard.md)，二者均未被取代——消息选
择、元数据与截图管线都没有改变。
