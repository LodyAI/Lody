# E2EE 成员展示资料目录

Status: implemented
Translation: current

[English](2026-10-26-e2ee-member-profile-directory.md)

## 摘要

加密工作区账本此前没有连接账号资料目录，同伴只能显示编号。现在云端组合提供可选的工作区资料查询，成员、角色和核验码仍由账本决定。页面通过已验证的当前成员，将目录中的加密用户 ID 对应到成员，只显示姓名和头像。资料读取缓慢、失败或结果过期，都不会阻断账本核验或覆盖其他账号的标签。这实现的是展示契约，不代表新设备加入验收或服务端授权已经部署。

## 决策

公开云端数据仅包含工作区 ID，以及加密用户 ID、可空姓名和可空头像的资料条目，不包含账号 ID、邮箱、公钥或角色。云端适配器在完成查询时核实仍为同一个登录账号和请求工作区。独立的路由 effect 管理资料可用性、账号和工作区变化、刷新和卸载；失败时保留账本编号，下次刷新可以恢复。

页面通过已验证账本中的当前加密用户 ID 和成员 ID 对应资料。资料不能创建成员，也不能改变角色和核验状态。当前目录不含已移除成员时，其历史标签保留编号。路由不再因为本机固定了创世哈希，就把登录账号映射到创世成员：新加入的设备也可能持有同一 pin。

个人设备配对和显式账本审计仍作为独立宿主/runtime 能力留在历史页中。与目录组合时，同时保留两边的平台类型和原生操作。目录完成不控制这两个入口，也不改变其资格；genesis pin 建立本地账本连续性，不证明账号归属或创建者身份。审批权限继续由宿主及账本策略检查。

如果把资料读取放进历史加载，辅助标签查询就能使有效账本读取失败。复用普通成员目录会混淆两套权限模型。可选的平台方法保持旧组合和本地组合兼容，公开桌面仍只使用本地功能。React effect 继续拥有读取生命周期；把依赖迁入 Effect 服务会扩大范围，并不能改善这条独立读取。

## 验证与限制

行为测试覆盖伪造资料字段下的真实账本展示、不变的核验码和角色、账号和工作区迟到结果隔离、资料故障后的恢复，以及云端操作绑定。原生密钥保管、新设备加入、服务端部署和真实网关过期仍是独立验收。当前职责见[初始化导读](../../../docs/e2ee-workspace-bootstrap.zh.md)。
组合路由回归还检查资料失败时 pairing/audit 子组件继续挂载；该组合检查不替代它们各自的组件和宿主测试。
