# 由机器托管的定时任务

Status: implemented
Translation: current

[English](2026-09-24-machine-owned-scheduled-tasks.md)

PR: https://github.com/LodyAI/Lody/pull/931

## 摘要

过去的周期性 Agent 工作只是某个在线会话里的一条 cron：会话结束它就消失，其他人看不到，
也无法暂停。现在定时任务是一份工作区文档，由一台机器负责：这台机器计划时间槽，在本地账本
记录每次运行，再把一条冻结、尚未生效的用户消息交给普通派发流程，因此重启或重连都不会让同一
时间槽运行两次。用户在形似 composer 的编辑器里创建，或一键接受 Agent 提出的卡片；Agent 自己
永远不能直接创建。可选规则刻意保持很少（每天、工作日、每周、每月、每 N 小时或分钟、仅一次、
手动），并且总是按所属机器的本地时间理解。尚未验证：打包后的桌面端到端运行。

## 决策

**归属与执行。** 定义存放在 `schedule-<id>` Loro 文档；工作区 Schedule Registry Flock 是执行
闸门，并记录定义的指纹，过期或孤立的文档不会运行。所属 CLI 在一个 SQLite 事务里推进游标并
写入运行意图，然后写入 `prepared` 用户消息并提交 `latestUserMsgId`——此后由普通 watcher 负责
执行，不会换会话重试。错过策略为 `skip` 或 `run_once`；重叠最多排队一次；执行槽按 Agent 共享。
Registry 断开时暂停新交接，避免运行一个用户已在别处暂停的任务。

**运行位置。** 可以每次新建对话、固定一个任务自有对话，或发送到用户选的已有对话。自有对话的
id 由任务 id 加 `epoch` 推导且从不存储，重试或其他设备都不会建出第二个对话，“开始新对话”即
`epoch + 1`。发往对话的任务没有自己的项目；没有项目的任务就是普通对话。

**产品中不出现 cron。** 选择器把每条命名规则映射到不变的持久化 `once | interval | cron`
联合类型。无法命名的旧规则只读展示并提供“替换”，保存时原样写回。曾考虑并已移除：五字段自定义
编辑器——用户看不懂，而且反复出现有损往返。

**Agent 提议，用户创建。** `lody_schedule_propose` 只接受命名规则，并写入幂等的
`schedule_proposal` 通知；在卡片上点“创建”即完成创建，任务 id 就是提议 id。目标默认取提议所在
对话的 Agent、实际权限模式、机器和项目；点名的 Role、Agent、机器或项目只覆盖对应部分，点名
Agent 使用内置默认模式，绝不沿用另一个 Agent 的模式。

**编辑器（2026-09-24 修订）。** 名称、提示词和运行选择放在一个类似 composer 的框里：运行位置、
Agent 和项目是框底部的一排下拉，而不是四行属性。没有时区选择：CLI 在注册时把自己的 IANA 时区
写入 `MachineMeta.timeZone`（少于 50 字节），墙钟规则和一次性时间都按该时钟理解，旧 CLI 退回
使用查看者的时区。保存问题在修正它的位置用感叹号标出，而不是罗列在底部；未完成的选择在用户
尝试保存后才标出，真正的冲突立即标出，只有不属于任何控件的原因（只读、工作区加载中）放在
保存按钮旁。

## 验证与局限

确定性测试覆盖：引擎（自有对话多次运行复用同一会话、手动触发从不被计划）、周日 `0-7` 星期
范围在编辑后不丢失、无项目任务经过生产 `prepareSessionInput`、跨夏令时的机器时钟换算、保存
问题的标注位置，以及提议目标规则。Storybook 截图已在浅色与深色、中英文和窄面板下检查。
未验证：打包桌面端连接真实 daemon 的运行，以及托管端账号删除对定时任务流的清理（位于私有仓库）。
