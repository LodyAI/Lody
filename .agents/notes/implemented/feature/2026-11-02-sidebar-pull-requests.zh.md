# 侧栏聚合 Pull Request

Status: implemented
Translation: current

[English](2026-11-02-sidebar-pull-requests.md)

## 摘要

一个 Session 可以关联多个 Pull Request，但侧栏此前只显示最新的一项。侧栏现在以中性的紧凑数量表示多个关联，展开后分别显示每个 PR 的状态和目标；单个 PR 仍可直接打开。现有元数据不包含 Stack 关系或标题，因此列表不会推测这两者。

## 决定与限制

列表使用本地已有的 Session 关联及其解析后的生命周期状态，不新增 GitHub 请求。完整 URL 用来识别目标，包括不同仓库中编号相同的 PR。[折叠分组状态决定](2026-09-26-sidebar-folded-group-status.zh.md)与 PR 指示相互独立。

显示分支的双行 Session 将静止状态的 PR 指示放在第二行，活动状态和归档操作仍位于标题行；单行布局保持不变。

Stack 指示需要明确的关系数据；把数组顺序当作 Stack 会误导用户。开启「显示分支」时，PR 控件位于右下角，与分支行对齐，并与标题行的活动状态同时显示；关闭时侧栏条目隐藏 PR 控件。分支名优先收缩，为 PR 控件留出空间；增删统计仍在悬浮信息卡中。单个 PR 的状态图标在左、编号在右，不叠加 CI 标记或徽章底色；多个 PR 显示中性数量。编号和数量使用与分支元信息相同的中性前景色，PR 状态由图标表达。单行条目保留原有的活动状态优先级。PR 标题同样需要独立数据来源，Session 关联目前不提供标题。验证仅涵盖组件行为和可用的本地渲染环境，不能证明真实 GitHub 同步或真实账号下的可用性。

双行会话在 PR 后显示已有的非零增删行数。本地项目元数据和 Updated 列表使用相同的现有统计；缺少统计时不显示。空间不足时分支文字优先收缩。

行宽较窄时，增删行数让位给分支和 PR 控件；完整数值仍可在悬浮信息卡中查看。PR 控件的点击区域高于文字，但其中心与元信息行对齐。
