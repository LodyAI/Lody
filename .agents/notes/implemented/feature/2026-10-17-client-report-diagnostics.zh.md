# 报告发起客户端的诊断信息

Status: implemented
Translation: current

[English](2026-10-17-client-report-diagnostics.md)

## 摘要

Bug report 需要把发起报告的浏览器或原生应用与所选机器区分开。客户端现在会附上明确列举的环境字段，以及现有持久 Renderer 日志的一段尾部；不选择机器或连接旧 daemon 时也能上传。错误收集、脱敏和保存继续由现有日志模块统一负责，不新增 console 拦截器或第二个存储缓冲区。独立附件依赖配套托管实现，仍受现有云操作保护。

## 决策与职责

`client-build-info.ts` 负责构建常量。`client-diagnostics.ts` 明确列举系统、原生版本/厂商/型号、桌面运行时、浏览器、语言及显示字段。不遍历 window/platform 对象，不包含安装 ID、主机名或用户目录。UA 推断版本与原生版本分开：浏览器可能隐藏真实版本，厂商名称也不能证明厂商 ROM 版本。

现有[客户端日志](2026-10-16-client-bug-report-log.zh.md)负责崩溃、React 堆栈、刷新/恢复事件、48 小时/2 MiB 保留和脱敏。宿主入口使用其幂等接口提前安装。独立附件最多读取末尾 24,000 字符，日志存储最多等待一秒；存储不可用不妨碍环境信息上传。保留现有经过能力协商的机器 `clientLog` 上传，不收集任意 console 历史。

对话框创建原报告后，立即显示报告 ID 并允许关闭，再用应用会话上传客户端快照。附件进度和失败独立于报告成功状态；单独重试只上传同一报告的同一快照，不重复创建报告。上传最多等待 15 秒，覆盖响应头和响应体读取；即使底层适配器忽略 abort，取消仍会结束等待。关闭、切换账号/工作区或卸载时取消并作废当前请求，迟到响应不能替换新报告。关闭或刷新可能留下缺少附件的报告。托管实现必须绑定报告人/工作区、限制大小、检查删除保护、只完成一次并清理竞争失败的上传，从而不改变严格校验的旧 daemon RPC。

## 证据与限制

测试覆盖原生字段白名单、浏览器降级、持久日志尾部复用与大小限制、失败/卡住存储，以及附件重试。真实对话框/API 测试验证附件挂起时仍显示报告 ID，关闭按钮、右上角关闭、Escape 和遮罩均能退出，并覆盖取消、迟到响应、退出账号和卸载。API 使用假时钟验证响应头/响应体挂起及超时清理；关闭回归用例在旧 PR 提交上失败。错误收集、保存和脱敏由现有日志测试负责。托管验证归接入方负责。原生打包、真机厂商/系统信息和生产上传仍为独立验收项，本地测试不能证明它们。
