# 一个 Agent Role 跨多台机器

Status: implemented
Translation: current

[English](2026-10-14-agent-role-machine-targets.md)

## 摘要

有多台机器的用户过去只能为每台机器各建一个 Role，因为 Role 只能绑定一台机器和一个
Agent Config，而且名称必须唯一，每次修改都要手动重复。现在 Role 只保存一份共享字段
（名称、提示词、描述、emoji、可见范围），并为每台机器保存一份配置：各自的 agent、运行
配置、记忆体和可选别名。编辑器使用机器 Tab，设置列表标明每个 Role 的机器，`@` 菜单
为每个机器配置显示一行。单机 Role 保持 v1 记录结构；只有多机器 Role 使用旧客户端会
跳过的 v2 记录。[Spec 草稿](../../../../specs/agent-role-machine-targets.zh.md)等待评审。

## 问题与依据

`isAgentRole` 过去只接受 `v === 1`，`normalizeAgentRole` 只用已知字段重建记录，所以
旧客户端编辑带有额外字段的记录时，写回会丢掉这些字段。如果把多机器配置作为 v1 记录的
额外字段，任何旧客户端都可能悄悄删掉其他机器。`validateAgentRoleForm` 拒绝提及 token
已被占用的名称，迫使用户按机器复制 Role。记忆关联按机器存储
（[记忆 Spec](../../../../specs/agent-role-memory.zh.md)）。

## 设计

- **内存结构。** `AgentRole` 保留内联的 `machineId`、`agentConfigId`、`runConfig`
  作为第一份配置，并新增 `additionalTargets`。`bindAgentRoleTarget(role, machineId)`
  返回把该机器配置放到内联字段的 Role，因此输入框、会话 hook、定时任务、MCP 创建、
  schema 对齐等执行路径继续读取内联字段，只需先绑定机器。已在内联位置时原样返回，
  保持 memo 引用不变。
- **存储。** `serializeAgentRoleRow` 对单配置写 v1，对多配置写 `{ v: 2, targets }`；
  UI 目录写入和共享 Flock 写入都经过它。schema 对齐只修改存储记录中的一份配置后重新
  序列化，单机 Role 不会离开 v1。
- **提及。** 提及值为 Role id；多机器 Role 追加 `@machineId`
  （`formatAgentRoleMentionValue`）。多机器 Role 的裸 id 不解析，旧草稿保持纯文本而
  不是猜测。
- **Agent 与 CLI。** MCP 创建工具接受 `agentRoleMachineId`；CLI 使用 `--machine` 或
  配置别名。多机器 Role 未指定机器时报错并列出其机器。资源发现每份配置一行。
- **编辑器。** 机器下拉改为 Tab；记忆 Tab 并入每个机器 Tab。“添加到此机器”预选同类型
  agent（同名优先）并复制运行配置；不支持的值以已有的兼容性问题展示。显式保存时的选项
  清理只作用于当前 Tab，因为只有该 agent 的能力已加载。
- **列表。** 设置页由按机器分组改为单一列表。每行固定两行（标题行固定高度以容纳徽标）；
  机器放在右侧一列，带状态点，超过两台折叠为“+N”，或显示“全部 N 台机器”。问题和检查中
  状态标在机器上，悬停说明原因。早期版本把机器和原因作为额外行堆叠，行高不一致且内容挤在
  左侧，被负责人否决。

## 备选方案

- **复制 Role。** 改动小（编辑器已支持用预填值打开新建），但会增加需要手动同步的副本。
- **在 v1 记录旁用单独的 Flock 记录存机器配置。** 旧客户端仍能用第一份配置，但多出
  一类记录，需要处理孤儿清理与删除顺序。负责人只要求新客户端能读旧数据。
- **内存中只用配置列表。** 类型更干净，但所有调用方和测试夹具都要改；绑定机器的方式
  只影响真正选择机器的地方。
- **两步提及（先选 Role 再选机器）。** 改为每个机器配置一行，按输入框所在机器排序，
  别名可选作为显示名。

## 验证与限制

行为测试覆盖记录结构与旧记录读取、绑定、提及解析、表单保存/校验/建议、列表行、输入框
绑定、定时任务提案、v2 记录中单份配置的 schema 对齐、经真实写入器的目录写入、CLI/MCP
配置选择和资源发现。列表行与编辑器的 Storybook 状态已渲染检查。未覆盖：桌面端到端流程；
也没有让旧客户端实际读取 v2 记录，只依赖其 `v === 1` 检查。添加机器时创建记忆身份
在 Spec 中保留为待定问题。
