# 移动端新建对话复用消息页及首次发送的页面呈现

Status: implemented
Translation: current

[English](2026-10-28-mobile-new-chat-page.md)

## 摘要

移动端新建对话现在复用真实消息页的头部、返回按钮和底部输入框，把机器和项目放在
输入框上方的页内区域。它替代独立 sheet 和拥挤的底部横向控制栏，Role、Agent、Model、
Mode 仍使用共用的运行配置 Sheet。首次发送成功后保留新建页，直到会话内容真正呈现，
并在延迟挂载和 URL 修正期间持续关闭入场动画。页面本身从右侧滑入，原生应用中可从左边缘跟手右滑返回。真实组件的浏览器检查通过，iOS 开发版
已安装；原生键盘和真机发送的手感仍需用户验收。

## 决定与范围

本决定取代[先前 compose sheet 决定](2026-10-27-mobile-new-chat-compose-sheet.zh.md)
中的布局和机器锁定方案。先前工作改编自
[@natsustan](https://github.com/natsustan) 的
[#491](https://github.com/LodyAI/Lody/pull/491)，其贡献归属继续保留。

- 复用 `SessionConversationPage`、`BaseHeader`、`MobileSessionHeaderBackButton`、
  `ConversationColumn` 和进行中会话的输入框外壳。两处共用键盘偏移、安全区和过渡。
- 机器在前、项目在后，各为图标和值，不单独占用标签行。机器、项目和分支在原地展开。
  本地 Git 的 worktree 与分支共用一行，两种主题下都没有背景；直接使用本地目录时
  分支只读，因为它使用当前已检出的分支。GitHub 提供分支选择。
- Role、Agent、Model、Mode 留在 `MobileSessionRunConfig` 及其原有 Sheet。
  共用入口使用正常字重，长模型名保留开头。切换机器会清除不兼容的 Role 和本地项目，
  机器选项明确提示对 Role 的影响；草稿保留。
- 无项目显示“未选择项目”。项目组用 Folders，本地目录用 FolderOpen，GitHub 选项和
  选中入口复用桌面端的 owner 头像；加载中或失败时显示 GitHub 图标，不显示仓库描述。
  全部来源共用桌面排序：最近使用优先，再按名称和稳定标识；不再用创建时间提高未使用
  目录的优先级。搜索只过滤而不重排；未选择项目、添加目录、连接仓库保持固定位置。

## GitHub owner 图标对齐

共用头像外层改为块级 flex 布局，避免移动端项目入口中的行内基线留下额外行高。
修复前，Chromium 和 WebKit 在浅深色下都测得头像中心比项目文字高 2.5px；修复后中心重合。
已有浏览器测试检查加载中的 GitHub fallback、加载后的头像和展开选项与文本的中心对齐。

## 首次发送的职责

Landing 在会话创建接受前保留受控草稿和附件，沿用既有失败恢复与消息派发行为。
`getSessionCreationNavigation` 在 history 中记录对应会话的创建请求。
`useMobileComposerPresentation` 按会话及 history index 保留该次创建入口，
同一 history 项的 URL 替换不会丢失状态。宿主在本次创建的会话页面打开期间持续向
Drawer 传递关闭入场动画的标记。

`SessionDetail` 在 layout effect 中确认已经呈现解析完成的移动端会话内容。
只有这个确认才消费 history 请求并隐藏保留的新建页。导航 Promise 完成不能代替内容
呈现：Portal 和实际会话可能稍后才挂载。Vaul 的 `defaultOpen` 优化也只覆盖第一帧，
因此内容和遮罩明确关闭入场动画。拖动、关闭、返回及后续普通访问保持既有过渡。

## 消息呈现后的键盘收起

真机录屏暴露了固定键盘高度的浏览器检查遗漏：发送先主动让新建输入框失焦，随后又
禁用它，原生键盘因此可以在目标会话挂载完成前收起。录屏中的延迟跳变符合原生安全区事件等待渲染线程
处理后才更新的表现。代码能证明这些操作会引发键盘收起，但没有真机 CPU
性能记录来判定全部渲染开销的来源。

共用 `ChatComposer` 在移动端等待提交时保持 textarea 启用，同时阻止输入、按键和粘贴，
受控草稿仍暂时隐藏。发送按钮的指针操作保留输入焦点。进行中会话在等待时也保留同一个输入节点；
归档输入框仍禁用。首次发送通过一次性导航请求，
让挂载完成的目标输入框在源节点移除前接过已有焦点。原生 iOS 还要求键盘高度信号大于零，
因为手动隐藏键盘后 DOM 焦点可能仍在。用户已经收起键盘时，只消费请求而不聚焦。
焦点和呈现标记合并为一次 history 替换。

最终采用的行为是在发送成功后自动收起键盘。新对话的目标输入框先接过已有焦点，
再用有界的两次动画帧回调，让已提交的消息页先呈现一帧，然后失焦。进行中会话也在
接受提交后的呈现阶段使用同一操作。拒绝发送时保持输入；新的按键、输入、IME 组合、
指针、焦点、窗口/可见性变化或页面归属结束都会取消尚未执行的收起，避免打断新草稿
或其它会话。共用外壳把安全区 padding 和键盘 margin 一起过渡，避免底部安全区单独跳变。

这里沿用共用渲染器和现有页面归属，没有新增编辑器宿主或跨容器移动已聚焦的 DOM。
目标会话 UI 仍需要挂载，原生流畅度需要新一轮真机测试。

## 新建对话的默认项目

首页不再强制把输入框切成“未选择项目”。本地创建成功后，在现有 workspace/device
作用域的 landing 默认值中记录 `lastUsedProject`。普通上下文和 Agent 默认值持久化
保留这个独立字段，浏览页面、取消或被拒绝的草稿不会改写上次成功使用的目标。
从首页打开空草稿时，通过现有项目处理器恢复它；本地项目同时恢复所属机器，并清除
不兼容的 Role。从指定项目页面进入或恢复已有草稿时保留当前选择。

恢复会等待相关目录准备好，并在首次绘制前应用一次；用户手动切机器/项目或关闭页面后
会取消。只有精确可见身份才允许恢复，已删除或不可用的目标回退到无项目。明确记住的
“未选择项目”保持不变；旧版本没有此字段时使用现有最近使用排序作为可用兜底。

## 页面动效与边缘返回

此前页面出现和关闭都没有动效。现在页面复用下钻页的 `.mobile-drill-in` 关键帧从右侧推入，
返回时先向右滑出再通知宿主。首次发送呈现后由宿主隐藏页面时仍立即移除，避免离场页面遮挡会话。

原生应用中，从左边缘 `EDGE_ZONE_PX` 内开始的向右拖动会让页面跟手移动，露出下方仍挂载的
首页或项目页；超过下钻页的距离/速度阈值即提交，否则回弹。没有采用 Vaul drawer：该页面
已与会话 drawer 共享首次发送交接，再加一层 drawer 会重新引入归属问题。也没有采用
`MobileEdgeBackSwipeZone` 那样的覆盖条，因为它会吞掉左缘的机器/项目行和输入框控件点击；
拖动直接绑定在页面上，并忽略从输入框外壳开始的触摸。启用 `axis` 锁定时 use-gesture
在第一次有效移动才报告 `first`，所以边缘判断读取按下时的 `initial` 位置。Web 不挂载手势，
与其他边缘返回一致。

证据仅限 jsdom 测试经由 use-gesture 驱动触摸事件（入场、返回离场、跟手提交、回弹、
输入框/屏幕中部/Web 排除、宿主移除）以及包类型检查。原生手感尚未验证。

## 验证与限制

- 项目、目标、workspace、运行配置、提交及桌面比较器的相关套件共通过 146 项测试，
  包括既有头像缓存、项目过滤及比较器边界。
- 17 个 Chromium 场景覆盖深浅主题、320–430px 手机宽度、固定模拟 300px 键盘、延迟呈现、
  后续 URL 修正，以及 GitHub 头像等待、成功、失败状态；另有 9 个 WebKit 场景覆盖自动收起、继续输入、安全区插值和项目恢复。首次发送场景观察 45 帧，
  输入框边界、模型文案和字重不变，没有入场位移。
- 组件包类型检查、改动文件格式与 lint、画板布局检查通过。仓库文档检查仍受未初始化
  ACP 子模块的链接限制；仓库级检查结果另在 PR 中说明。
- Story 强制使用移动端布局分支，真实组件配合合成 workspace 和提交结果。画板包含
  各种项目、展开选择器、共用运行配置 Sheet、附件、长文本和短屏。
- iOS Debug `0.107.2 (20261028.6)` 已构建、签名并安装到真机；手机锁屏导致系统拒绝自动启动。隔离构建保留上一手机测试版的依赖基线，
  默认项目调整的四个产品文件均与当前工作区逐字节一致。安装成功和
  模拟布局检查不能代替原生键盘时序与首次发送手感的验收。
