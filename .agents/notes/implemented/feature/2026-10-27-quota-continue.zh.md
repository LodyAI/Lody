# Claude 额度重置后继续

Status: implemented
Translation: current
PR: https://github.com/LodyAI/Lody/pull/1973

[English](2026-10-27-quota-continue.md)

## 摘要

Claude 的会话额度耗尽后，对话可能需要等待五小时额度重置。现在由终止性的错误卡片直接提供一行快捷操作，在服务商重置时间之后的第一个整分预约一次字面消息 `continue`。该操作要求对应额度已经耗尽且具有明确的未来重置时间，不改变输入框草稿，渲染时也不会创建任务。它取代了原先输入框上方的入口，让失败原因和恢复动作处在同一张卡片内。

## 决策

- 通过 ConversationView 读取已加载的历史尾部，匹配最新用户消息之后终止性的 `chat_failed` 服务商通知。若之后已有助手回复，说明对话已恢复，不显示入口。只匹配 Claude 的会话限额前缀；单独一个 `acp_internal_error`、用户引用的文本或每周限额文案都不能授权该操作。
- 按确切 Agent 配置及模型查找额度，要求已耗尽的 18,000 秒窗口。绝对重置时间提供唯一的时间来源；排除缺失或过期时间、早于该窗口的失败，以及重置后仍然阻塞的另一额度。错误卡片可见时通过现有服务商额度刷新入口更新，不解析本地化的上午/下午文案。
- 错误卡片内的一行显示确切的定时时刻，并提供 `定时`。点击一次后在重置后的第一个整分（例如 2:30 PM 重置则 2:31 PM）向同一对话预约字面消息 `continue`，沿用失败用户消息的模型、模式、选项、记忆、MCP 选择及 Role 来源。不会重发原任务、附件或提示词前缀，也不改变输入框草稿和正在编辑的运行配置。渲染不会创建任务。
- 根据工作区、对话和重置时刻生成固定的预约、激活和创建标识。重复点击及写入结果不确定后的重试收敛到同一个预约。不同载荷会报冲突，不覆盖已经修改的预约。已有预约会把该行变成回执并打开定时详情，包括已发送或已取消状态；取消及离线补发沿用[完整定时消息约定](../../proposed/feature/2026-10-27-scheduled-messages.zh.md)。
- 保留所有权、完整消息协议和加密工作区限制。额度与历史订阅位于错误卡片内的叶组件，不在输入框或对话树中。执行归属机器端调度器，渲染端不通过计时器发消息；输入框上方不再有第二个入口。

## 证据与边界

合成数据行为测试覆盖错误卡片挂载、单个完整消息预约、冻结配置、重复点击、写入失败重试、原历史不变、缺失或过期时间、每周及其他服务商额度、过时失败、整分取整、对话已恢复、所有权及协议限制。Storybook 样例覆盖桌面、390 px 手机、保存中、已定时、暗色和中文状态，无页面错误或横向溢出。用户在界面评审中批准了方案 D。仓库不包含真实用户对话；打包客户端与真实服务商执行尚未验证。
