# 在输入框中编辑排队消息，锁只在可见时续期

Status: implemented
Translation: current
Supersedes: [排队编辑操作归属](../../archived/bug-fix/2026-10-13-queued-edit-operation-ownership.zh.md)

[English](2026-11-27-queued-message-composer-edit.md)

## 摘要

排队消息原来在行内的小输入框里编辑，只能改文字，冻结的模型、模式和 Role 也看不到。
现在编辑会把消息带进输入框的编辑模式，文字、附件和运行配置都能改。开始编辑只写入
该行已有的编辑锁，保存时在同一消息 ID 上一次替换该行。锁只在编辑显示在屏幕上时续期，
所以被遗忘的编辑最多按 CLI 的五分钟租约挡住队列。代价是用户离开更久时，回来可能发现
原内容已经发出；这时编辑变成普通草稿。

## 决策

- **编辑位置。** 由输入框而不是行来编辑：与新消息相同的提及、附件、运行配置菜单和
  Role 控件。输入框自己的草稿和 Role 选择按会话暂存，编辑结束后恢复；编辑用的运行配置
  草稿和 Role 选择使用按行区分的独立作用域。同时只编辑一行。
- **保存时一次写入。** 开始时写入 `isEditing` 和 `editingStartedAt`，CLI 已把它当作
  队首锁（`EDITING_LEASE_MS`）。内容和配置在保存时通过共享的发送准入一次写入
  （带 `queueReplace` 的 `acceptSessionUserTurn`）：记录人工输入回执、对加密内容签名、
  先准备新附件，再替换该行。本地写入不等待远端同步。
- **作者。** 没有改动的保存等同于取消。真正改动后编辑者成为作者（owner 决定），这与
  现有签名规则一致：改动的排队输入由编辑者重新签名。运行配置未改时保留冻结的 Role 版本，
  而不是改用 Role 的最新版本。
- **锁的有效期。** 只有会话正在显示且窗口可见时才续期。离开就停止，已有租约自然过期。
  仍在准备附件的保存由运行时持有，会续期直到替换写入。被编辑的行消失时结束编辑，
  内容保留为草稿。刷新会像其他输入框草稿一样丢失编辑。
- **冻结配置可见。** 每行有详情弹窗，显示完整消息和冻结的运行配置。差异小标签只在
  宽面板出现；头像只在多人工作区里有别人排队时出现。

## 考虑过的方案

- *把消息从队列弹回输入框*（Codex CLI 的做法）：不需要锁，但丢失位置，不重新提交就没了。
- *保存前完全不写入：* 用户编辑队首时 CLI 会先发出旧内容，而这正是用户最常编辑的时候。
- *离开会话就释放锁：* 去别的会话看一眼，旧内容就可能运行。
- *应用开着就一直续期：* 没注意到的编辑会无限期挡住队列。
- *租约过期时把该行改为暂停：* 后面的消息会先运行，打乱有依赖的顺序。
- *编辑后保留原作者：* 签名者和显示的作者会不一致。
- *增加“谁在编辑”字段，让刷新后的设备立即释放锁：* 为避免改动队列格式暂不采用；
  遗留的锁最多耽误五分钟。
- 被取代的行内编辑需要操作标识，防止较早的失焦保存冲掉下一行的草稿。现在同一时间只有
  一个输入框编辑，也没有失焦保存，这个竞争不再存在；本地写入仍不等待远端同步。

## 影响

改了队尾那条的配置，输入框默认配置也随之改变，因为最近一条排队消息是配置的权威来源。
多台设备编辑同一行不做特殊处理，其他设备只看到置灰的锁定行。MCP 选择不可编辑。
