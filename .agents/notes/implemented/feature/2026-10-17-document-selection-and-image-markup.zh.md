# 文档选区与图片批注发送到聊天

## 摘要

会话文件预览现可将 PDF/Office 选中文字、表格单元格或带评论的局部截图加入当前聊天输入框。已有截图附件也可在发送前批注，只有接受编辑结果才替换原图片草稿。来源文件、页码或幻灯片或单元格位置及评论通过已有文本草稿展开，图片走已有附件链路，没有增加新的持久化输入类型。阅读控件共用一条紧凑工具栏，反馈框贴在高亮来源旁，而不会替换预览。这实现了选区反馈；引用保存的是当时的上下文快照，并不提供文件变化后重新定位原选区的持久化文档锚点。

## 决策与职责

[二进制预览](../../../../packages/components/src/components/sessions/session-file-binary-preview.tsx)和 CSV 预览入口在有对应聊天回调时接入 `DocumentSelectionSurface`。PDF、DOCX 使用原生文字选择，并通过页面相交关系标注页码；PPTX 报告已挂载幻灯片的身份。XLSX 复用有界的 worker 选区读取器并记录工作表和 A1 范围，CSV 复用已有有界行数据。这扩展了 [Office 查看器决策](2026-09-29-session-office-and-table-viewers.md)、[PDF 控件决策](2026-09-29-session-pdf-viewer-controls.md)和[表格控件决策](2026-10-09-spreadsheet-preview-controls.md)。

[文档选区工具](../../../../packages/components/src/lib/document-selection.ts)负责上下文格式、可见区域几何及截图。使用仓库已有的 SnapDOM，对获授权的预览 DOM 和画布进行裁剪捕获，排除选择覆盖层并禁用截图缓存。视觉修正移除了初版写死的 1 倍栅格化和图片降采样：截图现在采用显示像素倍率，仅在需要满足 4 百万像素输出预算时降低倍率。预览尺寸和标记笔触仍使用逻辑尺寸。重建自动居中的 PDF 阅读面板还曾造成裁剪横向偏移；现在按每个相交 PDF 页面的坐标捕获，保留其中的 DOM 批注层，跨页选区再将这些页面片段合成到周围截图上。这保留了来源对齐，没有把 PDF 标记替换成只含原始画布的图片。目标限定为选中的文件预览，没有增加 Electron 截屏权限、浏览器捕获 API、云操作、依赖升级或协议能力。

[编辑器](../../../../packages/components/src/components/sessions/document-selection-editor.tsx)显示截图预览、可选评论及明确的“添加到聊天”操作。文档选区使用该反馈流程，只有独立的已有图片附件编辑对话框会显式启用画笔、矩形、箭头及撤销控件。会话输入框负责接受，将文件路径、位置及可选图片通过已有粘贴文本 span 和图片草稿加入输入框。发送被拒绝时，原提示和引用均保留。归档、正在发送、聊天不可用、图片能力及附件限制导致拒绝时，编辑器保留，用户可取消或重试。

选区入口放进各查看器已有的阅读工具栏，区域选择使用虚线框内指针图标；纯图片预览使用浮动入口。原生文字选择直接打开小型锚定评论框，不抢走原生选区焦点。保留的来源高亮会跟随滚动和缩放；已输入的草稿在来源离屏时隐藏，滚回后恢复。空反馈点击外部可关闭，已输入的反馈保留到接受或取消。Cmd/Ctrl+I 聚焦评论，Cmd/Ctrl+Enter 将选区加入输入框。反馈卡片在空间允许时放在选区侧面。PDF 旋转收入“更多”，窄面板的缩放步进也可从该菜单操作；PDF/CSV 搜索展开在阅读栏下方。检查本机 Codex PDF 模块找到了来源或区域评论，独立图片编辑器则另有标注和评论入口。Lody 的画笔、矩形、箭头是针对已有图片附件增加的工具，附有可见名称和绘制提示，不声称它们属于 Codex 的 PDF 交互。

本次修订参考 OpenSeek 最近的[文档共用锚定反馈框（#1952）](https://github.com/moonbitlang/openseek/pull/1952)、[紧凑 Office 控件与按需搜索（#2036）](https://github.com/moonbitlang/openseek/pull/2036)、[主题一致性（#2037）](https://github.com/moonbitlang/openseek/pull/2037)及[图标式区域批注（#2040）](https://github.com/moonbitlang/openseek/pull/2040)。已阅读相关 diff，包括保持选区高亮和离屏草稿的处理，作为交互参考。实现仍使用 Lody 自己的 React、查看器及输入框边界，没有复制上游源码。也评估了 OpenSeek 默认加宽文档面板的改动（#2035）；本次保留 Lody 用户保存的面板宽度，验证紧凑控件在窄宽度下的表现。

会话内图片缩略图的批注操作通过[图片对话框](../../../../packages/components/src/components/sessions/pending-image-markup-dialog.tsx)读取该附件的 File。取消保留原图；接受后只替换这一张图片草稿，释放旧预览 URL，有评论时再加入来源及评论引用，不会上传或发送。新建聊天页面和已发送图片查看器保留现有行为；[图片导出操作](../../../../specs/image-preview-actions.md)仍是独立能力。

## 生命周期与限制

- 触发：原生文字选择、批注选中单元格、显式拖动框选，或对图片草稿发起批注。
- 所有者：当前文件界面负责截图准备和编辑器；会话输入框负责已接受的文本及附件草稿。
- 取消：更换文件或来源、隐藏面板会取消结果等待并丢弃编辑器；滚动取消尚未完成的截图。指针取消及 Escape 取消选择，取消按钮关闭编辑器。更换图片来源或卸载会隔离迟到的解码、编码结果。SnapDOM 不提供协作式取消 API，因此有界的原始截图工作独立结束，被取消的结果不会加入聊天。
- 交接：只有对应输入框接受草稿后，“添加到聊天”才报告成功。文档图片和上下文沿用已有发送与上传接受链路。编辑已有附件时，替换前确认同一会话仍持有完全相同的原 File。
- 失败与恢复：截图、编码及交接失败可见，并保留所选上下文。发送失败保留普通输入草稿，没有增加第二条发送路径或持久化历史写入器。

选中文字最多 50,000 字符，评论最多 10,000 字符，截图画布最多 4 百万像素，并继续执行已有附件校验。整图批注会将更大的附件图片等比缩小至画布预算。Office 的读取、worker 和虚拟化保持原样，PDF 继续范围读取，其查看器画布预算也保持原样。这些 React 所有的 DOM 交互未改变 Effect 编排单元或迁移账本。

## 备选方案与剩余范围

手动剪贴板和系统截图仍可用，但不会保留来源上下文。新增文档引用输入块可提供更丰富的回跳和修订感知锚点，但需要协调修改 schema、回放和 CLI。本实现使用现有文本和图片输入契约；保存可见截图坐标作为捕获上下文，不承诺在缩放、导航或文件修改后重新解析这些坐标。

交互参考了本机 Codex/ChatGPT Desktop `26.1007.71326`：检查到的实现保存文档位置、PDF 局部截图，以及图片批注和提示文字。Lody 使用自己的预览和草稿边界，没有复制第三方源码或用户截图内容。全桌面截屏采集、OCR、文档编辑以及将批注写回 Office/PDF 不在本次范围内。

## 验证

使用合成文档和图片、现有输入框提交套件、显式取消信号，以及独立 Storybook 上的 Playwright 验证。接到当前 main 后，三个聚焦单元套件通过 81 项测试，PDF/Office 的 28 个浏览器用例一次运行全部通过。覆盖范围包含四项窄 Office/CSV 阅读工具栏用例和三项高清截图用例。后者把 2 倍裁剪与原始 PDF 位图进行像素比较，检查跨页对齐及接受后的 PNG 尺寸，并验证像素倍率受 4 百万像素预算约束。PDF 工具栏检查了 390/480/960 像素宽度，包含中文和深色主题；已目视检查阅读控件、锚定文字反馈和图片批注截图。控件保持在单行阅读栏，并验证了滚动期间的来源高亮与已输入草稿恢复。覆盖原生文字选择、单元格与来源位置、原始内容像素、标记与撤销、窄窗口图片对话框、取消准备、替换或取消图片编辑，以及发送被拒绝后草稿保留。PNG 断言在异步画布编码及交接被接受后才解码结果 File。浏览器 Story 使用模拟输入框接收器；真实输入框组件另行通过发送边界测试。

接到当前 main 后，`pnpm check` 通过，包含工作区类型检查、类型感知及 Effect lint、已配置的 CI 测试套件、i18n 和边界检查。套件保留原有的跳过项，组件套件的 5,444 项测试全部通过。全仓类型感知 lint 报告 15,310 条警告、零错误。`pnpm format` 及全部改动源码和语言文件的格式检查通过。文档检查报告六处指向当前不可用 Kimi/Pi 子模块文件的既有链接问题，新增 Note 无错误，没有已登记的受保护主题。会话 README 和文件界面文档解释当前行为。真实 Provider/图片上传、生产构建下 Electron 本地资源协议以及物理设备仍未验收；没有声称已合并或获得人工批准。
