# 将 OSS Loro 记录导入已有云端工作区

Status: implemented
Translation: current

[English](2026-10-12-oss-cloud-record-migration.md)

## 摘要

OSS 和云版使用隔离的身份与数据目录。云版 CLI 将冻结的 Loro 快照导入用户明确选择的已有工作区，保留完整操作历史与源数据，并禁用导入记录的执行。共享索引通过服务端条件追加写入，持久回执使丢失响应后的重试不会覆盖用户后续编辑。历史附件独立于不可变操作归档。Roost 仍不支持，未迁移真实账号。

## 决策与职责

`migrate --from-oss` 属于公共 CLI 源码，仅云版注册。源读取器在只读 SQLite 备份和附件冻结期间持有 OSS 主机租约。清单绑定部署、账号、工作区、源路径与机器身份。用户选择已有工作区，不自动创建，也不删除源数据。

ID 保持稳定，同名无冲突。无关同 ID 和删除标记阻止迁移。完整历史走 Streams 初始同步路径；实时本地更新订阅不能转发导入的其他作者操作。发布停止状态的会话元数据前，独立回读校验完整版本向量。定时任务禁用，派发指针与待执行队列清除。

## 并发与恢复

客户端先检查再写入无法保护共享 Flock 行。目标使用已锁定版本 Streams 客户端的 `appendCas`，以检查过的副本偏移量作为条件。每次尝试使用独立副本；条件失败就丢弃暂存修改，重新读取和检查。元数据发布也使用 CAS。任何上传前先确认部署支持 `append-cas`，禁止退回普通追加。不存在的索引会携带初始数据与回执原子创建。

逐行源数据哈希与对应行在同一次子 Flock 提交中写入，不放在工作区 meta。即使响应丢失、用户后来编辑或删除行，恢复也能识别回执，跳过已完成项，不再与原始快照强制比较或重放旧值。因此部分会话发布后修改配置，也不会阻断剩余迁移。

文档流在初始 PUT 中携带归属回执。创建成功但响应丢失不再遗留无法识别的空流；重试从远端验证归属。无关的既有空流仍拒绝接管。准备好的字节与本地回执保持冻结。清单和日志采用 v2，拒绝缺少历史附件和原子索引回执的未发布 v1 原型产物。

## 历史附件与取消

附件发现使用独立副本检查不可变操作边界，涵盖删除、替换的消息及旧分支。Mirror 逐字段构造的部分描述会归并；以容器切换或重复字段划分描述写入段，覆盖 Loro 合并 commit 的情况，避免采集替换过程的混合描述。所有恢复出的描述都必须通过大小、哈希校验，不能根据磁盘现存内容选择可信历史哈希；当前引用仍独立严格校验。任何远端写入前，所有发现的本地文件必须存在且通过大小、哈希验证。即使原会话已删除，也保留 fork 的 storageSessionId 归属。

当前引用通过 HistoryWriter 改写。过去操作的身份与内容不变；HEAD 文档的 `ossMigrationAttachments` 根保存全部归档文件的源引用与云端引用。旧 frontier 中的文件引用使用 HEAD 归档解析。单独验证版本向量不足以证明附件完整。

命令入口将 SIGINT/SIGTERM 接入迁移锁和 Effect 的取消信号，上传与目标清理结束后才释放锁，退出时移除监听器。Effect 负责顺序、截止时间与中断。取消传播到附件 fetch 和 Streams 请求，并等待 Promise 清理完成；清理最多等待五秒，每个网络步骤有五分钟截止时间。被取消的上传结果不能发布回执或准备文档。本地日志使用 fsync 和原子重命名。

## 边界与验证

发布不是工作区级事务，中断可能显示已经验证的子集。完成日志描述的是原始快照，不包含后来的 OSS 修改。工作区 MCP/Role 设置、临时索引、代码/worktree 和原生登录状态不搬迁；Provider 行包含其已配置环境。Roost、浅快照、未知存储类型和不支持的图片引用会在预检失败。

行为测试使用真实 Loro/Flock、SQLite 和 Streams 客户端，协议服务端为可确定注入竞争与响应丢失的内存实现。覆盖 CAS 并发插入/删除、无关写入、元数据删除标记、创建及追加响应丢失、部分发布后的编辑/删除、历史独有 fork 附件的冻结和解析、原位附件替换、系统中断信号、真实传输 fetch 的取消及虚拟时钟超时。用法见[迁移说明](../../../../apps/cli/src/lib/oss-migration/README.md)。

29 项迁移专项测试通过。移除测试环境中会话注入的 `GIT_EXEC_PATH` 后，全量 CLI 套件 4064 项通过、4 项跳过；此前无关的 `context_unreadable` 失败由该环境注入导致。云版打包在规定的 2 GB 堆上限下渲染 chunk 时内存不足，未修改的原有入口也能复现。文档检查有六处既有 Kimi/Pi 子模块缺失链接。这些检查不能替代真实云端端到端验证。

指定的独立审查通过多轮对抗探针关闭了五项问题，额外覆盖合并 commit、连续替换、fork／多分支、历史文件损坏时零上传，以及真实 SIGINT／SIGTERM 下持锁清理。受支持的完整 Loro 历史范围内未报告剩余可复现 P0/P1/P2。

命令在 Effect Scope 中获取原生 Streams token provider，仅在 SDK 边界借用既有共享 Legacy 适配器，不创建额外 runtime 或缓存。成功、失败路径均先关闭目标连接，再关闭适配器和 provider Scope。验证应覆盖与最新 main 合并后的树：旧分支单独通过类型检查，不代表能兼容合并后的原生 token API。
