# 移除启动时的路由恢复

Status: implemented
Translation: current

[English](2026-09-29-startup-chat-landing.md)

## 摘要

默认入口原本可能重新打开上次访问的对话，并把工作视图的查询参数带入新启动。
现在入口统一选择工作区的 chat landing。路由存储和生命周期监听已删除，
旧路由记录也不再影响启动占位界面。代价是取消自动返回上次工作的能力；
显式导航和指定目标的窗口继续打开原目标。

## 决策与依据

新行为由[启动意图](../../../../specs/app-startup-landing.zh.md)定义。
本地入口原本就进入 chat landing；共享登录入口有两处恢复路由的跳转，
现已一起删除，同时移除登录后的路由跟踪、存储模块，以及退出登录和
移除工作区时已无用途的清理调用。

[启动占位界面决策](../feature/2026-09-26-boot-shell-first-paint.zh.md)仍然适用，
但默认入口不再根据旧路由推断侧边栏。在工作区路径明确前只显示标志。
内联脚本与两个 Electron CSP 哈希同步修改。旧存储值不再生效，
无需迁移或增加偏好开关。

## 验证

原存储测试替换为入口导航回归测试：在两种存储中放入旧会话 URL，
覆盖缓存工作区、解析后的工作区和本地工作区入口。
启动占位界面测试验证旧路由被忽略。Electron CSP 检查通过（5 项测试），
直接执行启动脚本的 3 项断言通过，覆盖旧存储和显式工作区路径。
改动的 TypeScript 文件已使用 Oxfmt 0.65.0 格式化，`git diff --check` 通过。
