# 会话发送改为本地优先

Status: implemented
Translation: current

PR: [#1104](https://github.com/LodyAI/Lody/pull/1104)

[English](2026-09-29-local-first-session-send.md)

已被[移除会话发送日志](2026-09-29-remove-session-send-journal.zh.md)替代：下文的发件箱、后台恢复、归档暂停和退出规则均已不存在。先写本地再走网络、执行指针以及 `seen` 判定仍然保留。

## 摘要

发送日志把缺少远端回执当作发送尚未结束，即使消息已经保存在本地也会阻止归档。
现在就绪消息先写入本地历史和执行指针，发件箱在后台同步。归档暂停持久草稿，
普通退出保留已接受输入，不再等待目标确认。附件完整性和未知 guide 结果的核对
仍然保留；尚未执行打包设备验收。

## 决策与证据

本决策部分替代[延迟附件方案](../architecture/2026-09-14-deferred-attachment-send.zh.md)。
当前 [Spec](../../../../specs/session-files.zh.md) 仍为 draft。
原来的 `saved → prepared → committed → delivered` 流程在恢复本地写入之前
还会等待目标同步；执行指针在投递阶段才写入，因此本地历史需要后续投递任务
才能被 daemon 发现。

新记录跳过 `prepared`。version 4 表示本地写入意图；完成实时 SessionData
写入、执行指针及本地 flush 后，version 2 表示后台投递。核对消息身份前先合并
原始持久化副本，从其他窗口恢复投递也遵循这一点。保留 version 1–3 读取兼容，
旧客户端拒绝 version 4。仍保留发件箱，因为直接删除它会丢失跨窗口恢复所需
的副本引用及已经接受的附件源数据。

中断的写入意图若在本地历史中缺失，后台恢复仍须核对目标：该写入可能在落盘失败前
已经到达其他副本。普通发送和本地已有消息的恢复不需要这一网络前置条件。

接管时即在本地发布会话创建元数据。归档保留并暂停未完成输入，恢复后继续；
删除移除相应输入，等待写入结束后发布删除标记。启动、联网、回到前台及现有
presence 重连事件触发工作区恢复批次，不增加逐消息定时器或额外 transport。
guide 结果未知时仍禁止重放。

## 验证与限制

行为测试覆盖同步前本地执行指针、离线重试不重复追加、旧记录恢复、归档草稿
保留与恢复、归档历史只同步不 dispatch，以及带发件箱记录的删除。继续运行原有
附件、原生退出与编辑器保护测试，没有另建重复测试文件。
已使用本机可用依赖尝试 components 类型检查，但缺失依赖及 loro-repo/ACP
声明版本不匹配使完整检查无法通过。未做打包桌面/移动设备验收。
文档检查还报告了指向未初始化 ACP 子模块的链接。
五个相关测试套件共 127 项通过。`pnpm format` 通过；`pnpm check` 在 shared ACP
类型检查处停止，因为本机扩展声明缺少当前 subagent 导出。
