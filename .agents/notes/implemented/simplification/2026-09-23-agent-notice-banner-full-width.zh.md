# Agent 通知横幅改为整栏宽度并去掉标题分割线

Status: implemented
Translation: current

[English](2026-09-23-agent-notice-banner-full-width.md)

## 摘要

`AgentNoticeBanner`——`chat_failed` 与 `agent_warning` 共用的唯一界面——原本是
按内容收缩宽度的卡片，标题与详情之间还有一条细分割线。实际阅读中，它在对话
右侧平直的边线旁呈现为参差不齐的碎片，分割线又把一条两行消息切成两个盒子。
现在横幅铺满整栏宽度，标题与详情渲染为一条连续的带状区。代价正是原设计有意
接受的那一项：全宽通知与它评论的回答拥有同等的视觉权重。重新权衡后认为，这
个代价比它换来的零碎观感更小。

## 决策

提交 `3775a23c` 引入共享横幅时采用 `w-fit max-w-full`，并在标题与正文之间用
`inset 0 0.5px` 阴影画出分割线，理由是通知是从属旁白，不应与回答争夺权重，
且宽度上限能让长 payload 保持可读行长。实践中卡片位于本就窄于正文行宽的固定
对话栏内，上限几乎不生效；读者实际看到的是停在栏中部的短标签，以及把同一条
消息两行内容隔开的第二条细线。

`view.tsx` 现在以 `w-full` 渲染横幅，去掉内部规则线；详情保留水平内边距、
去掉顶部内边距，使带状区读起来连续；操作（容量重试按钮）移到标题行尾，
不再单独成行。色调描边、混合填充与图标/标签配色不变。与 fenced code block
的相似性保留在带描边的圆角块上，而非内部三段分割。

## 考虑过而未采用的方案

- 保留 `w-fit`、只去分割线：修好了两个盒子的割裂感，但留下引发本次反馈的
  右侧参差边缘。
- 仅在有操作（容量重试）时保留分割线：按变体切换几何结构没有任何阅读收益；
  操作改置于标题行尾。

## 验证

Storybook 中 `Sessions/ConversationView → ConversationWithNotices` 在真实行间
展示两种色调：修改前每张卡片停在栏内中部、标题下有可见分割线；修改后两者均
铺满整栏、成为单一带状区。已在浅色主题桌面宽度下核对；未重新评审深色主题的
色调混合，但本次没有改动任何颜色 token。

## 后续：触摸屏上的复制失败

始终展开的横幅失去了旧对话框里的复制操作。现在每个失败都带一个始终可见的
Copy error 页脚，只有标题的失败也不例外。它复用
`buildChatFailedErrorReport` 和共享剪贴板回退，并用 toast 报告写入结果。
把复制放在文本下方会多占一行控件，但避免在移动端把标题挤在复制和容量重试
两个操作之间。`CapacityRetryNotice` stories 覆盖了 agent 断开和仅标题失败；
断开场景在点击后检查剪贴板报告。

## 后续：只有复制操作时，它在手机上移到标题行

页脚能让标题保持宽松，但手机尺寸的截图显示，即使只有一行失败，它也会多占
一行垂直空间。`AgentNoticeBanner` 现在把标题、详情和页脚放进同一个可换行的
行内。低于 768px 移动端断点时，若复制是唯一的尾部操作，页脚上移到标题行尾，
详情则独占下一整行；若存在容量重试操作，标题行尾已被占用，复制仍保留页脚行，
避免把标题挤在两个操作之间；高于该断点时，详情和页脚在两种情况下都保持独立
行。该 `md` 视口断点与 `useIsMobile` 的 768px 边界一致，因此横屏手机也会得到
紧凑布局。`CapacityRetryNotice → DisconnectedOnMobile` 现在还会先断言复制按钮
位于横幅右半边且高于详情文本，再测试剪贴板内容。

`@lody/components` 类型检查和完整 Vitest 套件均通过；Storybook story 已在
390px 与 900px 视口下检查，并在 390px 检查容量重试变体仍保留页脚行。
