# Progressively migrate complex component surfaces to StyleX

Status: implemented
Translation: current

[中文](2026-10-04-complex-surfaces-stylex.zh.md)

## Abstract

Several large `@lody/components` pages still define their appearance with utility classes and inline style rules. This migration applies the existing StyleX approach to ten pages or panels while preserving their current appearance and behavior. Each component keeps semantic, module-local styles, reuses matching product surfaces and tokens, and retains exact values or dynamic styling where no equivalent exists. The first wave migrates 29 component modules; browser checks preserve text and layout in 44 sampled states, with small pixel differences recorded below. Existing primitive and wrapper overrides remain where replacing them would change the appearance.

## Decision

Use module-level `stylex.create` definitions within the component module, with names that describe semantic roles such as a selected row, muted label, or panel surface. Compose existing `@lody/ui` area surfaces and product tokens when they match the current result. Keep CSS variables, dimensions, and other values as written when the token set has no equivalent. Keep dynamic geometry and styles required by external rendering engines at their existing runtime boundary. Configure UI primitives through their documented props where they reproduce the current appearance.

The user's explicit appearance-preservation requirement takes precedence over removing existing primitive visual overrides. Retain an existing utility override when no pixel-equivalent public API exists; do not replace it with a competing caller StyleX class, change the control, or expand the design system in this wave. These exceptions include Send/Stop materials, 12/14px Spinner sizing and colors, Skeleton materials, annotation selection and Textarea fill, file-action typography, and Dialog/Drawer/Field typography or dividers. Native elements and caller layout remain migration scope. The exceptions remain follow-up primitive work, with no new token rule or public API guarantee.

Legacy wrappers whose internal utility classes override StyleX retain their original caller layout overrides, including TreeView padding, BaseHeader, ResizableHandle, DrawerContent, and horizontal scrollbars. Dialog content uses its existing public layout `style` prop to preserve zero padding and gap. These boundaries avoid changing the CSS cascade or primitive internals during this wave. Expand border and animation shorthands into supported longhand declarations: the installed StyleX 0.19 transform silently omits some shorthands. Preserve the original Tailwind color-mix expressions where an alpha replacement changes rendered pixels. Preserve the effective `cn()` result, including discarded leading classes on arbitrary font sizes in the share card.

Keep theme conditions in CSS, including `.dark`, `.dark-scope`, and the `.light-scope` exclusion. Keep hover, focus, and Radix state styling in CSS rather than adding React state. Shared tab-pill colors remain owned by `shared/tab-pill-strip.tsx`; its existing class exports derive from the same StyleX definitions used by both session strips.

The appearance and behavior remain the reference for this gradual migration. It changes styling ownership without changing product intent, so no Spec revision is required. ## Verification

Validation used separate installed baseline and candidate checkouts, with baseline commit `9bdac2851da16cdf5bae2f22d811e721ccf58afb`, the pnpm lockfile, and exact ACP contract gitlinks. Component typecheck, production Storybook build, and actual StyleX transforms for all 29 source modules pass. Scoped formatting and type-aware lint have no errors or added warnings; explicit types removed two migration warnings. The final 14 owning test suites pass all 201 tests, including annotation positioning, resize timing, selection, file actions, and tab behavior. The broader component run has 552 passing suites and one existing boot-shell storage failure: 4757 tests pass and one fails, versus 4758 passing and the same failure at baseline. The count drops by one because a utility-class-only tab-width test was removed; meaningful behavior coverage remains.

An AST comparison found no changes to hook calls and dependencies, event-handler expressions, or JSX tag topology after filtering styling declarations and attributes. Styling-only prop changes and dynamic grid-width delivery were reviewed separately. The final changes after the production build only annotate StyleX callback parameters; their compiled declarations and JavaScript match the built snapshot after type erasure and optional arrow-parenthesis normalization.

Browser comparisons render real components with synthetic fixtures, a fixed clock, loaded fonts/assets, reduced motion, forced light/dark palettes against the opposite OS preference, and desktop or 390px viewports. All 44 sampled states have equal text and zero matched-element geometry changes. Thirty screenshots have identical RGB pixels; the remaining fourteen have small pixel differences of at most 3/255 per channel, with maximum whole-image mean absolute error 0.001815/255. This is sampled component verification, not universal pixel identity, full Electron-shell coverage, authenticated integrations, exported PNG verification, or every interaction and viewport.

Code Collab import, platform boundary, and translation-key guards pass. In the primary nested worktree, docs checks retain the baseline 62 broken-submodule-link errors and 64 warnings, with no registered SHA topics. The public-boundary check also cannot resolve the absent ACP submodule workspaces there. Manifests, package composition, and those unrelated findings remain unchanged. No full root `pnpm check` or Electron build is claimed.
