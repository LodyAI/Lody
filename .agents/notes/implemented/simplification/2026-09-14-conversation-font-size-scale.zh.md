# 对话字号改为从固定档位中选择

Status: implemented
Translation: current

[English](2026-09-14-conversation-font-size-scale.md)

## 摘要

对话字号此前是一个数字输入框，每一次按键都会被夹到 9-32px 再写回输入框，于是输入框会不断改写
用户正在输入的内容：想输入 24，第一个 `2` 会立刻变成 `9`，下一次按键读到的是 `94`，最终落在 32。
想清空重填也没用，空值解析为 NaN，输入框会保留原来的数字。现在设置提供八个字号——8、12、14、
16、20、24、28、32——桌面端复用主题行的选择器，移动端复用内联选择器，行下方还有一行按所选字号
渲染的示例文字，而存储的值不再被夹进区间，而是吸附到最接近的档位。取舍是有意的：档位之间的字号不再可选，已经存过中间值（例如 13px）的用户
在首次读取时会移动到最接近的相邻档位。

## 决策与证据

`normalizeConversationFontSize` 原本在一个名字下做两件事：迁移旧的 `small`/`default`/`large`
预设，以及修复实时 `onChange` 传进来的任何值。让输入框显得与用户对抗的是第二件事：每次按键都经过
一个既限幅又取整的夹取，结果又被直接写回受控输入框。去掉自由输入就去掉了在输入边界做这种修复的
需要；该函数只保留持久化这一职责——存储中出现意外值时，仍然必须变成可渲染的东西。

吸附到最接近的档位（正中时向上取）就是这一职责的新形态。夹到新的最小值与最大值会更简单，却丢掉了
用户表达过的信息：存储的 13px 意味着"比默认小"，吸附到 12px 保留了这一点，而夹取会原样返回 13，
随后匹配不到任何一个选项，选择器将没有选中项。`CONVERSATION_FONT_SIZES` 同时是选项来源和吸附
目标，两者因此不可能各自漂移。

档位本身是刻意稀疏的。8-16 覆盖人们真正用来阅读正文的字号，2-4px 的步长并排可辨；20-32 面向
无障碍与演示场景，在那里 2px 的步长根本看不出来。旧区间从 9px 开始，这里改为提供 8px：档位表从
整数开始更易读，而两者的差别不可感知。

数字本身说明不了字号，因此两个界面都在该行下方用所选字号渲染一句示例——与终端分区早已存在的字体
预览同一形态。桌面端更进一步：把 `PreviewSelect` 的 hover 回调接到局部状态而不是设置本身，悬停
`24 px` 时示例立刻按 24px 重绘，而保存的值和触发器保持不变，未作选择就关闭菜单则恢复原样。示例使用
`conversationTextFontSizeStyle`——对话渲染器用的同一个 helper——因此预览不会与对话的真实效果漂移。

两个界面都通过 `buildConversationFontSizeChoices` 生成完全一致的标签（`14 px · 默认`），因此
桌面端与移动端的设置不会把同一个存储值描述成两样。桌面端复用 `PreviewSelect`——也就是主题行的
控件——而不是 `OptionSelector`：八个选项既不需要搜索也不需要虚拟化，而该面板本就是一列宽度一致的
220px 触发器。

同一面板里的终端字号仍保留数字输入框。它的上限是 24px，这套档位无法描述它，而它的默认值 13px
也不在档位上；给它做预设意味着再选一套档位，那是另一个决策。

## 验证

`packages/components` 类型检查、`pnpm lint` 与 `pnpm lint:i18n` 通过。两个归属测试文件通过
（11 个用例）：`tests/terminal-settings.test.ts` 锁定档位表，以及旧预设、越界值与正中值的吸附；
`tests/appearance-settings.test.tsx` 驱动桌面选择器完成展开、八个选项的确切列表、悬停预览、Esc
恢复已保存字号与提交 24px，并断言移动端该行没有数字输入框、示例按存储字号渲染。新增的
`Mobile/MobileAppearanceSettings` 已在构建出的 Storybook 中以 8px/14px/32px、浅色、深色与中文
查看过。

`Settings/AppearanceSettings` 在那里无法查看：构建版 Storybook 中它一直停在 "preparing" 且没有
任何报错，`Settings/BillingSettings` 同样如此。两者都会走到 settings 桶文件
（`settings/index.tsx`）——每个设置界面都从它导入 `settingContainerClass`，而它又反过来导入所有
设置界面——由此形成的 chunk 循环在 `vite-plugin-top-level-await` 下死锁。这早于本次改动，未作处理。
桌面布局改为通过一个临时的 Vite dev 页面直接渲染 `AppearanceSettingsView` 查看，覆盖默认状态、
展开菜单并悬停某个字号、提交后的状态、深色与中文；该页面随后已删除。

仓库全量测试未运行。外观设置没有对应的 Spec，因此没有 Spec 被更新。
