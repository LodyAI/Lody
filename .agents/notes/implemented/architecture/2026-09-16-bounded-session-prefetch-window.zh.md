# 限制所有端的会话自动预同步窗口

Status: implemented
Translation: current
PR: [#753](https://github.com/LodyAI/Lody/pull/753)

[English](2026-09-16-bounded-session-prefetch-window.md)

## 摘要

桌面端和移动端此前会把所有符合条件的未归档会话加入后台预同步，而 Web
只处理前 20 个，因此历史较多的用户可能下载大量从未打开的会话。现在所有
端都使用相同的 20 会话优先级窗口；更旧的会话仍在用户打开时通过正常前台
路径同步。其取舍是用冷门会话首次打开可能更慢，换取有上限的启动后台工作。

## 决策

协调器已经按置顶状态、当前 UI 可见性、运行中或未读活动排序，最后再按
最近活动排序。现在所有端的策略都对该排序结果应用 20 会话窗口。桌面端
仍使用与 Web 相同的 1.5 秒批间冷却，移动端仍使用 3 秒冷却，因此本次只
收窄候选范围，不改变 Worker 串行化、传输路由、快照存储、high-water 去重
或取消行为。

手动预取入口仍可请求自动窗口外的会话。更重要的是，前台获取仍不依赖后台
预取：打开会话会取消匹配的 Worker 任务，有缓存时合并快照，否则执行既有
的前台同步。因此该窗口只是缓存策略，不是访问或正确性边界。

本决策收窄了[串行预同步 Worker](2026-09-12-session-prefetch-worker.zh.md)
引入的候选策略，但不修改该记录中的 Worker 所有权或快照缓存决策。当前
预期行为记录在[后台预同步草案 Spec](../../../../specs/session-background-prefetch.zh.md)。

## 验证与限制

协调器测试分别为 Web、桌面端和移动端构造 1,000 个符合条件的会话，并
断言排队或执行中的只有优先级最高的 20 个。既有测试继续覆盖持久化
high-water 跳过、隐藏／离线暂停、手动预取、优先级排序、批次节流、取消，
以及 runtime 所属测试中的按需缓存行为。

本次没有测量窗口外会话的冷启动延迟，也不改变独立的 64 条快照缓存容量。
