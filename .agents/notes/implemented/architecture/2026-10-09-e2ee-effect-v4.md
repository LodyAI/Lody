# E2EE core and lab on Effect v4

Status: implemented
Translation: current

[中文](2026-10-09-e2ee-effect-v4.zh.md)

## Abstract

Core and lab now use Effect 4.0.2 through an isolated catalog, while other workspace
packages retain v3. Ledger operations own explicit transaction state and share one
verification/submission implementation. Lab owners retain service Contexts and
Scopes; Deferred gates and event notifications replace Promise waiters and interval
polling. Protocol and persisted formats stay unchanged. Native HTTP/CRDT callbacks
remain explicit bridges; this is neither complete source purity nor product E2EE
acceptance.

## Decision and scope

The user authorized implementation on 2026-10-09 after the proposal. Original HEAD:
`677961747047547758184e7e150146d37d973d25`. This version/lifetime decision is linked
to the earlier [Effect API migration](../../proposed/architecture/2026-09-22-e2ee-effect-api.md);
it does not close that note's outstanding product acceptance gates. Ledger and lab
Specs remain draft.

Use exact `effect: 4.0.2` in the named `e2eeEffect` catalog. The default 3.18.4 catalog
and other importers remain unchanged. A version-specific minimum-release-age exception
allows this explicitly selected release; it does not exempt future Effect versions.
The lockfile adds one v4 resolution without replacing v3.

Electron's identity services call `@lody/e2ee-core/node-identity-client`. This facade
returns Promise, crypto handles, bytes and ordinary errors, never Effect, Layer,
Context, Cause or Fiber objects. Initialization still checks the selected account
before creation, and explicit load never replaces a missing identity. Real main
bundle tests exercise the facade; Electron does not need its own v4 runtime alias.

Official sources were checked at the exact target version:
[release](https://github.com/Effect-TS/effect/releases/tag/effect%404.0.2),
[Result conversion](https://github.com/Effect-TS/effect/blob/effect%404.0.2/migration/yieldable.md),
[services](https://github.com/Effect-TS/effect/blob/effect%404.0.2/migration/services.md).
`Result` is a plain value: workflows use `Effect.fromResult`, not implicit yields.
Services use `Context.Service`; Cause inspection and fiber interruption follow v4
semantics. Mixed failure/defect/interruption reasons survive Promise boundaries as
ordinary AggregateErrors rather than mapping only the first typed failure.

## Ledger ownership and durability

`LedgerEngine` remains a bound handle with captured ports and no internal runtime.
Each exclusive operation loads durable storage, creates a transaction-local Ref,
and passes it explicitly through synchronize/sign/submit/save. The retained Ref
only stores verified prefix evidence; it is no longer the transaction's hidden
source of state. The original journal port is retained directly, including ports
implemented with prototype methods.

`save` persists first and publishes the transaction state and verified cache in one
narrow uninterruptible region. CAS and readback stay interruptible. A later error
does not roll back pages already saved. Exact pending bytes are saved before CAS;
retry never signs again and only readback establishes commitment. Only transport
uncertainty becomes Pending. Snapshot trust, length, complete state digest and
persisted prefix identity retain their existing checks.

`pure/ledger-page.ts` selects records and tracks snapshot binding/point facts without
I/O or input mutation. Unknown snapshot prefixes remain unauthenticated; suffix
verification and checkpoint publication belong to the workflow. Public legacy
`openEffect`/`readEffect` descriptions let the lab use its owner without launching
nested Promise runtimes. Legacy Promise methods still run the same descriptions.

## Lab ownership and native bridges

`LabRun` constructs inertly, builds a fresh service Context once per owner and keeps
a persistent Scope. Each operation's fiber is attached to that Scope. Close rejects
new work, interrupts active fibers and awaits finalizers idempotently. Different
owners do not share layer acquisition state. Single-call `runLabPromise` closes its
owner; resources that escape use a persistent owner instead.
Layer acquisition itself is attached to the Scope, so close also interrupts an
unfinished acquisition and releases resources acquired before it stalled.

Host startup uses native scoped acquisition for HostMeta, Riverrun, request fibers
and the HTTP listener. Listen failures and later startup failures release prior
resources. The Promise host handle closes the owning Scope. Request callbacks use
an explicit native Promise bridge; Effect cancellation propagates through an
AsyncLocalStorage AbortSignal into fetch/StreamsClient. Gateway policy remains in
the existing pure gateway helpers. Session owners await close; ledger read/resume/
intent execution uses `SessionLedger` workflows and the core's native descriptions.
Enrollment, rotation and key delivery also run under the persistent session owner.
AttackLab retains its private service owner; the attacker never receives it.

`finish` seals the public attack handle but retains private replay services until
runtime disposal. Observation and mutation actions settle at their current event
boundary before the driver can grant another honest-client permit; advancing
actions grant their own explicit permits. Only finish measurements use automatic
draining. Full replay exposed both lifetime and premature-advance mistakes during
the migration; the owner and action boundaries now preserve captured replay order.

Scheduler state belongs to a per-runtime Ref and synchronous serialized transitions.
Deferred gates and request waiters preserve explicit permits, nesting and delayed
success/error delivery. A scoped notification queue wakes the driver on requests,
completion and actor resumption. It grants no hidden permits. The driver retains
recorded identity matching, existing pull-forward/FIFO behavior and permit budgets.
The Effect Clock watchdog is separate from logical replay time. Native Promise/SDK
callbacks retain an explicit AsyncLocalStorage parent bridge. `runtime.close()`
rejects gates immediately; await `dispose()` for owner cleanup.

Remaining bridges include HTTP routing/body processing, streams-crdt/Loro/Flock
callbacks, snapshot-publication and demo backup adapters. They are not a second
verification, submission, rotation or content algorithm. A blanket `tryPromise`
around the entire lab was rejected: it would not establish resource ownership or
declared native ledger dependencies. Full conversion of these adapters is separate
from completing this version upgrade; source-style targets remain binding.

## Verification and limits

- Baseline core focused suites: 38 passed. Baseline lab scheduler/runtime/services:
  21 passed. Existing untracked `review2-*` tests already failed typechecking due to
  removed exports and old Promise-store calls. They were preserved, not rewritten.
- Tracked core/lab source, benchmark and test typechecks pass using temporary configs
  excluding only those untracked review files. Root `pnpm check` stops at those
  files; their v3 Either references also need migration if they are adopted later.
  This is not a green whole-workspace check.
- Core full tracked suite: 45 files, 535 passed, one skipped. Final focused suites
  cover mixed causes, Promise initialization, SQLite interruption and exact pending
  recovery. Lab full tracked suite: 22 files, 171 passed, including three independent
  replays, startup failure cleanup, unfinished layer acquisition and active-request
  cancellation.
- Electron main/web typechecks and seven real bundle/key-protection tests pass.
- Whole-workspace type-aware lint passes when excluding only the existing untracked
  review files (pre-existing warnings remain). Root lint stops at an unawaited close
  in one of those files; they were not changed by this work.
- Expanded Effect checks audit core pure/ports/workflows, ledger facade, and runtime
  starts/v4 imports across both packages. They do not certify native bridge purity.
  Public repository boundary passes. Docs checks have no errors; existing size/link
  warnings remain. Formatting applies only to changed/new task files to preserve
  unrelated untracked work.

Performance: same 1000 signed records, same Node 22.23.1, three warmups and ten samples
per class. `bench/effect-classes.ts --fixture=<path>` now retains synthetic public
bytes so both versions measure identical input. No timing assertion runs in CI.

| Class              | v3 median ms | v4 median ms | Change |
| ------------------ | -----------: | -----------: | -----: |
| Replay             |     1478.557 |     1444.086 | -2.33% |
| Incremental extend |        1.822 |        1.797 | -1.40% |
| Snapshot startup   |      169.717 |      167.879 | -1.08% |
| SQLite recovery    |     1480.684 |     1447.421 | -2.25% |

All classes remain within the existing 20% regression gate. These local samples do
not establish a speedup or revive the withdrawn 10k/100ms target. Tests use real
cryptography, SQLite and local Riverrun. They establish neither power-loss durability,
OS keychain acceptance nor enabled/running product E2EE.
