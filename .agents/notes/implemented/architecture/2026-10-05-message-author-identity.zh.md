# Agent 委派的消息作者身份

Status: implemented
Translation: current

[English](2026-10-05-message-author-identity.md)

## 摘要

Agent 委派消息此前使用授权用户的头像。历史现在独立保存带版本的作者快照，同时保留人类授权身份和接收方执行配置。Role 消息显示冻结的 emoji 和名称，普通 Agent 显示 Agent 身份，并单独提供来源模型详情。快照经过排队提升、操作恢复和目录删除后仍然保留，渲染不需要读取实时目录。代价是有界的元数据存储；尚未对打包后的真实 Provider 行为或渲染性能进行基准测量。

## 决策与职责

[草案 Spec](../../../../specs/message-author-identity.zh.md) 将消息角色、人类主体、作者和接收方输入配置分离。Agent 发送的输入仍是 user-role 消息，`userId` 继续承担执行授权，不替换成 Role id。人类编辑重发时，以实际编辑者创建新的人类作者。

共享作者联合类型包含 human、agent 和 system。Agent 快照仅允许来源会话/轮次、Agent 配置及展示身份、Role id/版本/名称/emoji，以及模型、推理、Fast、Plan 摘要；不复制环境变量、凭据或任意启动配置。配置模型与运行时报告的模型分别标注，未知信息保持缺失。

MCP 在请求验证后、操作接受前，从准确的活动轮次获取作者；工具参数不允许指定作者。接受操作时原子保存快照，恢复时复用。目标 Role 快照跟随自身冻结输入配置，包括排队消息提升。助手轮次在自身边界捕获身份，重新打开时保留已有快照。操作完成信封仍由 system 署名。

本地操作数据库使用独立的 `operation_authors` 扩展表，并级联删除。直接向旧操作的 `SELECT *` 行增加列，或向严格冻结配置增加字段，会破坏混合版本解码。扩展表保存来源作者和目标 Role 快照，无需修改旧格式。

界面复用仅依赖快照的展示组件，优先显示 Role emoji/名称，单人工作区同样显示。弹出详情提供来源 Agent、模型摘要和会话链接。按用户反馈，助手回复不再展示作者身份入口及其弹窗；正文保持无头像、全宽布局，保留已有配置控件。助手作者快照继续保存，用于委派来源追踪。没有作者信息的旧历史沿用原有展示，不猜测身份或重写历史。

## 替代方案与代价

仅在 UI 查询目录无法恢复目录修改后的历史身份，也无法正确描述多个 Agent 向同一目标发消息。替换 `userId` 会破坏授权，复制来源配置到接收方则会改变执行。小型冻结快照有意重复展示信息，以保留历史。捕获阶段在操作/轮次边界增加有界本地读取，操作解码读取扩展表；不增加逐 token 目录查询或网络请求。这是架构属性，并非延迟测量结论。

本决策扩展了[人类发送者展示](../feature/2026-09-08-chat-sender-identity.md)和[本地编排](2026-09-29-local-session-orchestration.md)。约束记录在 shared、MCP、编排和聊天 UI 的作用域规则中。

## 验证与限制

用户验证后的回归修正：聊天流投影遗漏了 `author`，因此即使存储和独立消息行测试通过，实际消息仍回退到用户身份。现在投影保留作者元数据，作者变化时使缓存消息失效。界面回归测试先将历史经过 ConversationView 和 buildChatStreamItems 再渲染；投影测试覆盖用户/助手作者及延迟元数据替换。两项测试在修复前均失败。

行为测试覆盖真实本地 MCP A→B→A 署名、不同来源/目标模型、目标 Role 删除、持久操作重试/重开、历史存储/重开/复制、元数据验证、人类编辑重发、队列 Role 快照，以及可见 Role 身份与详情；另检查了浏览器 Storybook 示例。全仓类型、静态、国际化、平台及公开边界检查通过。

全仓检查运行至 CLI 测试：3475 项通过、4 项跳过，现有递归原生 SSH Git 凭据用例以 `context_unreadable` 失败，使用未修改的 HEAD 模块在隔离环境复现了相同失败。补跑包测试通过，包括组件 4765 项、共享层 1272 项、Electron 199 项；文档校验无错误。未执行真实 Provider 的打包端到端测试或帧时间/存储基准。

后续验证：24 项投影/发送者测试和组件类型检查通过。全仓类型/静态检查通过；最新全仓测试停在未改动的 workspace-git-service 本地同步用例（CLI 3475 项通过、4 项跳过、1 项失败）。文档校验通过。

Role 头像修正：此前空 emoji 回退 provider 的规则与 Role 目录不一致；目录使用 getAgentRoleEmoji，默认头像为 🪼。现在存在 Role 时，快照生成和展示均使用这一共享规则。仅无 Role 时才使用 provider logo，未知 provider 使用名称首字。旧的空 emoji Role 快照也显示统一默认头像，已有明确 emoji（包括 🤖）不重写。测试将显示结果与共享 Role 默认值比较，并单独验证无 Role 时的 provider 回退。
