# Encrypted machine read queries

Status: implemented
Translation: current

[中文](2026-10-28-e2ee-read-queries.zh.md)

## Abstract

Encrypted workspaces previously stopped machine reads at the ordinary RPC gate, so remote files, diffs and history were unavailable. A closed set of machine state and file reads now reuses the signed Streams frames and shared response reader, with native read authorization and the existing method handlers. History and provider discovery remain unavailable; diff methods are available only through the write-authorized Code Collab lane because their handlers can start processes, initialize storage or flush writes. Pure reads never claim the execution journal. Large JSON outcomes use signed pages, and a separate RPC-only token lets Guests send queries without receiving document write permissions. Packaged two-device acceptance and backend deployment remain separate from these local checks.

## Decision and boundaries

This extends the [dispatch channel](2026-10-28-e2ee-streams-dispatch.md), preserving its execution claim and durable fallback. It does not supersede that decision: read results have no business execution to claim or replay. Read queries use the same LocalMachineRpcRequest DTO, request chunks, native response assembler and response reader as [Code Collab and preview](../feature/2026-10-28-e2ee-file-preview-availability.md). A separate query wire format would duplicate target binding, framing, correlation and cleanup. The fourth startRpc argument is one typed handler with request ID, expiry and cancellation context.

On the baseline, `getMachineRpcClient` rejects protected workspaces through the common `rpc` feature gate; `e2ee_rpc_unavailable` also guards missing host preparation capabilities. The production chain is cloud provider → inferred IPC proxy → preload allowlist → account/window-bound host → native preparation/response verification. Both host operations and `rpcOnly` token selection pass through that chain. No signing key crosses it.

The allowlist admits ten method names: machine status/ping/binary status, session live status, file preview/download, text open/refresh and the two existing LSP queries. Binary status only inspects cache metadata; absent/incompatible runtimes remain absent/incompatible. LSP returns its existing `lsp_not_wired` result without launching a server. Text reads use the service's read-only mode, suppressing watchers, reconciliation and publication.

Method names alone are not evidence of read-only behavior. Pi discovery installs and scans the runtime; memory list runs a provider command; local-project probes/Git state start Git; history read/watch opens a backend and flushes writes; diff reads can start Git/workers or initialize SQLite. All nine names are excluded from the read lane. Pi, memory, project probes and history are rejected by native preparation/receiving; Code Collab diffs remain in the write-authorized feature lane. A separate side-effect-free reader is required before read admission. Saves, index publication and preview leases also require write authority and execution claims; installation/authentication is not admitted by this feature RPC.

Encrypted file resolution checks durable session/parent/machine ownership before observing an existing resident path through `Session.peekHostWorkdir`, or deriving an existing chat/project/worktree path. A temporary `WorktreeManager` computes and stats paths only; no global manager, checkout, fetch or initialization is acquired. Project registrations come only from the machine sync owner's already-open Flock; unavailable registrations produce an unavailable result. The getter neither opens a Flock nor requests a sync. Even the SDK's detached Flock read was rejected here: SQLite `loadFlockDoc` may compact and write storage on a cold load. Project member resolution disables link repair. Missing directories, links and registrations stay missing. The `file/preview` Markdown discovery variant is explicitly unsupported: its shared resolver runs `git worktree list`; returning only the current-root candidate would hide ambiguity. Explicit file paths remain readable. Ordinary resolution keeps its original path. The [PR's method audit](https://github.com/LodyAI/Lody/pull/2013) records all nineteen original call chains.

Read authorization reuses the host's authenticated latest-ledger refresh and its bounded in-memory freshness lifetime, then checks active non-recovery membership and the target machine's same-member binding. Guest is a valid reader; execution still separately requires write authority. The realtime crypto binding admits active readers, while the host's closed method/action entry decides what they may request. Read queries enter neither receipt nor actual-start execution journals. Their incoming signed originals are retained in the ciphertext originals store, rejecting different bytes under the same signer/request ID. New coordination stays native Effect; existing method handlers and Repo remain Promise adapters, without claiming a migration of those services.

## Shared encoding and original retention

Purpose 8 carries the existing method and a canonical UTF-8 E2eeFeatureInput `{requestId, request:LocalMachineRpcRequest}`. Each params chunk has big-endian uint32 index/count followed by at most 256 KiB of JSON. All chunks share the secure 16-byte request ID, method, epoch and expiry. Reads expire after 60 seconds; other feature requests retain their existing deadline. The host saves all ordered length-prefixed signed frames before transmission; changed intent under a retained ID is refused. Ordinary owner-session envelopes are adapted inside the client/server process, outside this wire format.

Every purpose-9 response, including a failed method outcome, pages one LocalMachineRpcResponse JSON. Each payload has big-endian uint32 totalPages/totalBytes followed by at most 256 KiB of original JSON bytes. The body sequence is the page index; only the last page uses `success`, earlier pages use `progress`. The native host verifies the expected page count and each exact byte length, signer, epoch, ID and complete-request digest. Missing pages stay incomplete even when the last arrives first; immutable saved sequence bytes reject conflicts. JSON is decoded only after all pages exist, and IPC returns the complete DTO. Code Collab, preview and legacy method callers therefore share the same completeness checks.

Responses are bounded to 64 pages / 16 MiB; larger outcomes return `e2ee_query_too_large` with `truncated:true`, total bytes and the limit. No partial payload masquerades as success. File chunks provide the bounded recovery path. Requests retain the feature lane's 32 MiB bound. The native response owner seals all pages and saves them atomically before publishing the first. An uncertain local write retains those sealed pages for retry; reopened committed outcomes reuse identical frames. Recovered committed outcomes release their pending memory slots, so repeated uncertain commits do not exhaust later read capacity. A partial or corrupt committed outbox fails closed. No automatic collection or execution-result migration is introduced.

## Ownership and containment

A signed query starts a workspace-scoped read task, capped at 32 independently of dispatch intake. Identical active requests share the first response; retained responses replay without rerunning the handler. Reads have a 45-second work budget intersected with request expiry. Timeout/close aborts the raw handler and drains its actual settlement before releasing custody; a raw operation that ignores cancellation retains only its own slot. Authorization is checked again before publication, and incompatible epochs or revocation refuse affected sends.

Network failures, a bad response, an outbox fault or an expired read fail that query, leaving document sync, other requests and workspace startup available. Scope close drains the shared reader and admitted read tasks before releasing RPC token ownership. Retained ciphertext and public routing live in the existing originals store; the execution journal is unrelated.

RPC tokens use the existing credential-authenticated content-token operation with `rpcOnly:true`, isolated in cache identity by their restricted scope. They allow read/create/append only under the encrypted bucket's `<workspace>:e2ee-rpc:` prefix. Document tokens retain their previous Guest read-only behavior, and neither token grants snapshot writes to Guests. Current credential/role/epoch checks and the 15-minute absolute token bound remain backend responsibilities. The matching private change is independently reviewable and never changes the public gitlink.

## Verification limits

The [host tests](../../../../packages/loro-streams-rpc/tests/e2ee-native.test.ts) pin request retention, paged exact response reuse and incomplete out-of-order delivery. The [shared feature/read integration](../../../../apps/cli/src/lib/e2ee/realtime-rpc.test.ts) traverses real method serialization, encrypted Streams correlation, target signature checks and the real server read entry. [Production provider/preload coverage](../../../../packages/components/tests/cloud-platform-provider.test.tsx) pins both query operations and token purpose forwarding; [runtime authorization](../../../../apps/cli/tests/e2ee-runtime.test.ts) checks a demoted Guest on its admitted machine against execution and foreign-machine denial. The [assembled Guest query regression](../../../../apps/cli/tests/message-handler-file-preview.test.ts) traverses real Guest-signed preparation, native receiving, MessageHandler callbacks and signed responses for every admitted method, comparing machine files and injected process state. A real installer with a synthetic archive pins Pi denial before download/installation/scanning; subprocess execution is an in-memory boundary. Missing active directories, missing/stale member links and unavailable project catalogs remain unchanged. The Markdown variant is refused before Git discovery. The [catalog observation regression](../../../../apps/cli/src/lib/loro/machine-flock-sync-coordinator.test.ts) permits no storage or transport acquisition from the read path. These synthetic, deterministic boundaries do not establish WAN latency, a deployed backend or packaged two-device behavior.
