# iOS 模拟器右侧面板

Status: implemented
Translation: current

[English](2026-09-27-ios-simulator-panel.md)

## 摘要

为目标机器为 macOS 的会话增加独立 iOS 模拟器侧栏，机器 RPC 负责设备列表和准备，远端媒体复用 Quick Tunnel。同机直连、无分享、每个设备只允许一个会话控制；Lody 自有 viewer 只接收画面和受限输入。首版采用 MJPEG，没有增加前端依赖。真实本机服务冒烟已收到画面并完成清理；完整远端/移动端验收及 H.264 仍不在已验证范围内。

## 已确认需求与待审阅默认值

已确定：入口取决于当前会话的目标机器是否为 macOS；打开后通过 RPC 获取该机器全部 iOS 模拟器；用户可以选择启动；隐藏地址、前进后退和标注；保留连接状态，不提供分享；减少依赖，为后续自定义控制留出边界。

本轮已确认：同机直连；iOS 模拟器不提供分享；每台模拟器只允许一个 Lody 会话控制。远端访问仍由后台 Quick Tunnel 承载，仅供已授权的控制会话使用。

其余推荐默认值仍待审阅：

- 通过右侧面板空态和 `+` 菜单添加 `iOS 模拟器`，位置紧邻 Browser，不自动打开。每个会话最多一个模拟器面板和一个选中设备。
- 看的是目标机器，不是观看者的操作系统。macOS 离线仍保留入口和离线说明；系统信息未就绪时不猜测。协议不支持显示升级提示，不能只判断 CLI 版本。
- 同机 Electron 沿用本地直连，支持离线；仅远端访问创建 Quick Tunnel，地址始终隐藏。没有分享入口、分享 RPC、公开链接或匿名观看模式。
- 会话内浏览器和模拟器可同时运行，互不替换。切换模拟器时释放旧设备的预览和控制权，新连接只绑定新设备。
- 不自动关闭任何模拟器，包括本次启动的设备。首版只管理预览连接，关机放入后续显式设备控制。

列表态：顶部显示目标机器名及在线状态；工具区包含刷新、按名称/系统搜索、系统版本筛选。列表按 runtime 分组，行展示名称、机型、iOS 版本、启动状态、可用性和占用说明；同名设备用短 UDID 区分，完整 UDID 放详情中。不可用 runtime 的设备仍列出并说明原因。已运行设备操作为“预览”，未运行设备为“启动并预览”。列表只读检查不安装 Baguette、不启动设备、不建隧道。

桌面增加第二行控件，移动端统一放入更多菜单：Home、应用切换器、锁屏、旋转、摇一摇、设备支持的音量和操作按钮、显式 Unicode 输入、明暗模式与模拟器 Deep Link。截图可保存 PNG 或加入当前输入框草稿，绝不自动发送。适应/展开和无需依赖的设备外壳属于本地界面；外壳保留真实屏幕边界，不叠加第二个灵动岛或 Home 条。DeviceKit 外观资源经私有通道从目标 Mac 加载；按设备类型绘制的示意仅在资源缺失时回退使用。

控件独立协商 `iosSimulatorControls: 1`。文本和 Deep Link 可能含凭据，因此使用精确 origin 的 postMessage 与鉴权后的私有预览接口，不进入工作区 RPC。严格的操作/请求/控件 DTO 仅映射固定路由，命令串行执行；有界去重不保留原始输入。截图回复绑定 window/origin/operation/request，仅显式传输不超过 16 MiB 的图片；连续帧不经过 postMessage。

IPC worker 直接管理剪贴板、明暗模式、摇一摇和 Deep Link 的固定 xcrun 命令。文字通过 stdin 写入，成功后重新检查租约才按 Cmd-V。过滤环境的 worker 为 simctl stdin 明确设置 UTF-8；否则原生 pbcopy 会以编码错误拒绝中文和 Emoji。macOS 的 Foundation.Process 会创建独立进程组，终止 Baguette 不足以回收这些命令，所以不使用它相应的子进程路由。取消必须等待所属子进程 close 后再释放租约。新操作先确认原生竖屏基线，同一操作重连保留方向；显示、逆向指针坐标和截图共用旋转。

### 鼠标滚动修正

初始 viewer 只注册了指针事件，没有 wheel 监听，因此滚轮与触控板双指滚动不会产生输入。
固定页面现在将滚动增量转换为既有 `touch1-down/move/up` 协议，处理行/页单位及显示缩放。
连续滚动会在到达屏幕边缘前抬手重启，120 毫秒没有输入后结束，并在明确的指针拖动开始前
释放滚动手势。失焦、隐藏或断线会清除待执行的抬手；Ctrl-wheel 不模拟捏合。
没有增加依赖，也没有扩大原生命令入口。

`viewer.test.ts` 使用确定性的浏览器/计时器边界执行实际生成的脚本，检查滚动、指针互斥
与清理后的协议输出。模拟器测试共 27 项通过，其中 10 项属于 viewer。现有 Electron 预览
已观察到点击响应；新增滚动页面及左键拖动尚未在原生可滚动界面上完成验证。

底部上滑返回 Home 是另一个输入缺口：Baguette 要求整段触摸携带 `edge: 'bottom'`，
原 viewer 未发送，网关也会拒绝。现在从底部 7% 区域开始的指针手势会在移动、松开和取消时
保留该标记，与 Baguette 正常方向的鼠标边缘区域一致。网关仅接受这一种边缘，验证起点区域，
拒绝中途变更；强制抬手也保留标记。滚轮不携带标记。测试覆盖协议转发、清理和非法边缘切换。
原生底部手势及倒置方向尚未验证；独立 Home 控件与底部边缘手势分开处理。

iframe、外层画面容器与固定 canvas 文档禁用浏览器选择和 iOS 长按菜单，iframe/canvas
同时禁用原生 HTML 拖拽。样式覆盖 iframe 边界两侧，避免长按选中整个屏幕，不拦截指针事件，
也不影响对话区域的选择。实体 iOS Safari 的长按效果仍待设备验收。

## 架构与依赖

`SessionIosSimulatorPanel` 负责选择与状态；`SimulatorToolbar` 使用现有 React、StyleX 和 `@lody/ui`；连接 controller 处理 RPC/endpoint；一张 Lody 自有轻量 viewer 页面使用 canvas、原生 WebSocket 和浏览器解码能力。无需引入 Baguette 整套 SDK、播放器、WebRTC、状态管理库或 UI 框架。

viewer 使用专用 iframe 展示，通过同源的受限 endpoint 获取流。这样不需要把跨域 Cookie/CORS 处理散入 React，也不必让 CLI 打包第二份 React。自定义工具栏的设备操作走私有预览连接，播放器本地命令通过严格校验 origin、source、连接代际与 schema 的小型 postMessage 协议送入 viewer。跨源 iframe 内脚本由固定的 Lody 制品提供，不加载用户项目页面；关闭 annotation 注入。连续媒体帧不经过 postMessage、React state、RPC 或 Loro 文档；只有显式截图把图片返回父窗口。

CLI 上由按需启动的 Baguette 进程处理采集和输入；每个预览经 IPC worker 独立拥有一个原生进程，默认 loopback、禁用插件；避免共享进程引用计数带来的跨会话清理耦合。Lody 适配层只开放当前设备必要路由和消息。设备列表可先用 `xcrun simctl list devices --json` 读取，避免查询前就下载 Baguette；启动/采集走固定版本适配器。固定 runtime/hash 与许可声明沿用 managed-runtime 分发方式，不要求用户装 Homebrew。首版明确经过验证的 macOS/架构/Xcode/runtime 组合，unsupported 不静默替代。

## RPC 与权限

`lody_ios_simulator_preview` 独立于网页预览，提供 list/start/status/stop。严格输入不接受
身份选择器；本地专用 `ios-simulator/agent-control` 从活动调用获取用户并复用服务授权。
结果剔除 viewer URL 和预览自由文本诊断。

Agent 在 Mac 执行，用户却可能从远端观看。启动时选择 loopback 会给远端面板不可用地址，
因此准备阶段先占用并启动设备，等待第一个已授权面板的 start/status 选择传输方式。
Agent 查询不接入、不续期；取消和一小时空闲期限释放无人接入的占用，重复启动保留已经
接入的传输方式。不增加依赖或持久元数据。

复审发现 agent 替换操作后，面板恢复会查询旧 operationId。恢复现在读取会话当前状态，
准备轮询和停止仍绑定确切操作。设备选择器的刷新也能发现已经 idle 时的 agent 启动。
没有增加自动打开或持续 idle/ready 轮询。确定性测试覆盖 MCP 输入／输出、活动用户入口、
延迟接入、取消、过期、远端授权和面板恢复；新增入口尚未重复真实 agent 到原生 viewer 验收。

版本 1 能力为 `iosSimulator`。单个 `ios-simulator/control` 接受 `list`、
`start {udid}`、`status {operationId?}` 和 `stop {operationId}`；共享 schema 拒绝额外字段。
Start 立即返回 preparing 操作；status 只观察、不续期。Stop 同时承担取消准备，必须指定
准确 operationId，因此迟到命令不能停止新操作。

设备控件使用私有连接上的窄类型命令，不能提供“执行任意 Baguette CLI 参数”的 RPC。

协商通过 `MachineMeta.protocolCapabilities` 的版本化能力，os 仅控制入口。所有远端 RPC（包括设备枚举）验证调用者访问权；workspace RPC 不能证明自报 userId。沿用短时签名操作证明思路，范围绑定 workspace/machine/session、UDID、动作、operation/endpoint 和 CLI instance nonce。共享传输/本地 facade 维持相同语义，本地不强制调用云端；Cloud 授权扩展通过 platform/cloud-api port。

媒体端逐 HTTP/WS 请求检查 capability、UDID 和当前控制租约，输入消息也校验租约仍有效；只接受所属控制会话的已授权访问。不提供公开分享路由或匿名 viewer grant；没有分享功能不等于可以省略鉴权。明确把凭据送入 WS 建连，不依赖浏览器偶然附带 Referer。

## 所有权、状态与并发

- session + kind（browser / ios-simulator）分别拥有操作队列、取消、local/remote endpoint、状态与配额记录。改所有相关 key，不能只改顶层 Map；session 归档/删除时两类均清理。共享 QuickTunnelSession/cloudflared 的低层实现，不复制完整 PreviewService。
- UI 分开记录设备状态与连接状态：设备启动成功但隧道失败时显示“设备已运行，连接失败”，重试连接不重复启动。隧道连通后继续等首帧，不能先显示画面就绪。
- 已确认机器范围内每台设备只允许一个 Lody 会话控制，跨 workspace 也不能重复占用。CLI 以 UDID 为键，原子获取绑定 workspace/session 与代际的控制租约，再启动设备或建立连接；同一会话重复启动合并，设备变更按 UDID 串行。其他会话列出设备并显示“其他会话正在控制”，禁用预览，不提供抢占。由其他原生工具启动的设备可接入；此约束只协调 Lody 会话，不排斥原生工具。
- 取消或失败的启动、显式停止、切换设备、闲置过期、授权撤销、会话归档/删除和 CLI 退出均释放对应租约；先禁用旧输入并关闭旧 endpoint/socket，再允许新会话获取。租约代际防止旧清理回调释放新控制权。释放控制权不关闭 Simulator 设备；切换失败则显示可重试的空态，不自动恢复旧设备控制权。
- 隐藏、切标签、Zen 和关闭面板停止该 viewer 解码、输入与保活，不自动撤销 endpoint；重新打开先查状态。显式停止、授权撤销、会话归档/删除、CLI 退出释放 endpoint 与所属子进程。Baguette 进程按引用释放；不终止用户自己的其他服务或 Simulator 设备。
- 建议沿用一小时闲置过期，但只以前台 viewer 心跳或有效操作续期；编码器持续发帧、机器状态查询和内部探活都不续期。重连恢复解码器和关键帧；断线期间不排队触摸操作。
- 选择和工具栏偏好按 account/workspace/session/machine 保存在客户端本地；列表、视频、心跳和端点凭据不放 repo meta。CLI 内存拥有活连接，客户端通过 RPC 恢复。若需要跨客户端保存选择，后续放 session doc 小型独立字段，不复用 Browser previewConnection，也不同步 token。

## 验收与限制

先做列表→启动→首帧→交互→停止/恢复/切换的纵向实现，再补错误/恢复和跨端验收。确定性测试覆盖 OS/协议门控、目标机器路由、取消与旧响应、双面板互不替换、跨会话/跨 workspace 并发抢占只成功一次、租约释放与旧回调隔离、无分享路由、未授权访问拒绝、UDID 越权、撤销关闭 WS、后台视频不续期及 CLI 崩溃清理；新控件用 Storybook 覆盖中英文、窄屏和所有关键状态。

实际验收覆盖同机离线、已授权会话的远端 Quick Tunnel、iPhone Safari/Capacitor、慢网/断线、帧率与资源占用。H.264 的浏览器解码、背压与关键帧恢复单独验收；MJPEG 成功不代表 H.264 或公网低延迟通过。

现已实现共享协议与能力、本地/远端 RPC、精确动作签名、机器范围控制租约、可取消原生 worker、受限媒体网关、独立本地/隧道 owner，以及 UI Designer 的侧栏。Viewer 握手校验 origin、source 和 operation，回报真实帧尺寸。

### 远端延迟分析（2026-10-01；优化提议，尚未实现）

持续画面路径是 SimulatorKit → Baguette JPEG 编码/WebSocket → 模拟器网关 → 已授权 LocalPreviewProxy → cloudflared → Cloudflare 网络 → viewer WebSocket → createImageBitmap/canvas。Convex 和工作区 RPC 负责生命周期授权，不转发画面和指针移动。指针沿 WebSocket 反向传输，离散控件通过同一隧道中的私有 HTTP 发送。

固定版本 db17446e 的 streamWS 使用原始分辨率 scale=1、JPEG quality=0.5。StreamConfig 虽声明 fps=60，MJPEGStream 却没有执行限帧：每次变化的 surface 都排队编码，所以单发 set_fps 不会限制该路径。set_scale 已实现，但 Lody 目前没有发送，受限网关也不允许任意重配置。未变化的静态画面已经过滤。

网关在下游 WebSocket bufferedAmount 达到 2 MiB 后丢弃新 JPEG，但该 socket 的对端是本地代理，并非浏览器。代理的无损 pause/send/resume 适合通用网页流量，却可能让旧视频积压在下游。viewer 单个可替换待解码帧只限制收到数据后的工作。Baguette 还有 4 MiB 编码后队列，MJPEG 编码调度队列没有 latest-only 上限。这些是源码风险，并非报告中 WAN 的实测积压。

建议顺序：记录帧大小/帧率、解码绘制耗时、网关到浏览器 RTT/确认帧年龄、隧道实际协议；按显示尺寸降低远端分辨率；限制发送帧率并只保留一个可替换待发送 JPEG；用有界接收确认窗口限制发送，不能简单逐帧停等，否则帧率上限约为 RTT 的倒数；只有尺寸变化才重设 canvas，并合并 move、保留下压和抬起。若上游不变，原生编码前限帧和 latest-only 调度需更新维护的 runtime。

下一步可协商 Baguette 已有 AVCC/H.264 与浏览器 WebCodecs，保留 MJPEG 回退。固定版本已使用低延迟编码和五秒 GOP，不能照搬 JPEG 的任意丢帧：需保留配置、用 IDR 恢复、限制解码队列。本质上不需要新增 npm 依赖。WebRTC/直连属于后续网络架构变化，增加信令和 STUN/TURN 成本。隧道底层使用 QUIC 不代表 WebSocket 视频成为不可靠数据报。

验证范围：固定版本源码追踪、官方 Cloudflare 与浏览器 API 文档。没有测量报告中客户端的 RTT、吞吐、帧年龄或丢包，不声称已有性能提升；讨论中的带宽和排队耗时数字仅为示例。

### 拥塞反馈修正（2026-10-01）

最初 512 KiB 的远端窗口，在 1 Mbps 链路上就相当于数秒数据。更严重的是，
探针与媒体共用有序连接，最新探针 RTT 被排队抬高后，算法反而增大窗口和帧年龄
容限。本次修正最初实现，不扩大四项优化范围，也不更换 runtime。

远端窗口改用最小观测 RTT 和保守的单帧有效传输速率估计，上限 128 KiB，并按字节
控制发送节奏；空闲时间不积累突发额度。没有单独采用 ACK 到达间隔估算吞吐：链路
受应用发送节奏限制时，它会测到自己的限速，重复预留余量会导致吞吐持续下降。
JPEG SOF 提供实际缩放比例，接收反馈可把降采样提高到 4，以 8 FPS 为目标，缓慢
恢复画质。同机保持原始分辨率。浏览器诊断窗口独立运行，不受网关报告成批到达影响。

确定性的 FIFO 1 Mbps / 400 ms 模型覆盖持续更新、有界延迟、画质调整和最后静态帧，
不使用 sleep 或真实网络。独立测试还覆盖 RTT 膨胀、空闲、画质恢复和报告突发到达。
这些验证控制算法行为，不代表真实公网提速；JPEG 大小、传播 RTT 和回程/解码延迟
仍是限制，有效速率估计不等于链路容量实测。原生编码调度和 H.264 仍不在本次范围。
真实远端对比继续采用 README 的现场测试步骤。

### 移动端固定竖放与静止画质（2026-10-01）

移动端通过绑定的 init 握手关闭画布/外壳旋转，原生左右转操作仍改变模拟器内部方向。
同一个显示角度控制布局、上报尺寸、触摸反向映射和截图；桌面继续随设备方向转动。
这样移动竖屏页面不必容纳横放的手机，不涉及模拟陀螺仪输入。

自适应 MJPEG 暴露了静止画质恢复死锁：SeedFilter 过滤不变画面，MJPEGStream.apply
只改配置，requestSnapshot 是空操作。因此只提高分辨率不会重绘静态屏幕。网关现在
等两秒无画面/输入变化且接收窗口排空后，从绑定设备的固定 loopback 截图路由读取
一张有大小上限的高质量 JPEG。新帧、输入或配置变化淘汰延迟结果和待发截图；关闭
会等待取消完成。没有新增公开端点、租约续期、runtime 构建或依赖。静态帧使用普通
帧的确认窗口，弱网仍可能延迟；持续动画不属于静止。

H.264 是建议的下一步传输方案，本次尚未接入。固定 Baguette 的 AVCCStream 已有
avcC 配置、关键帧/增量帧、码率/缩放控制和 force_idr，但 JPEG 的任意最新帧丢弃策略
无法保持 H.264 参考链。需要 WebCodecs 配置探测、有界解码队列、丢帧/重连/配置变化
后的关键帧恢复、与绘制确认延迟分离的码率反馈，以及 MJPEG 回退。上游 FrameBacklog
在压力下也会任意丢旧块，因此只保护 Lody 下游队列还不够。当前 JPEG 字节窗口小于
完整帧时也可能退化为停等；更换编码时应一起重做，不能原样复制控制器。

依据：固定 `db17446e` 的 MJPEGStream/AVCCStream/FrameBacklog 和
[WebCodecs](https://www.w3.org/TR/webcodecs/)。移动端旋转、静止刷新及其延迟结果、关闭/
撤销有确定性测试；真实公网编码收益仍未测量。

临时 iPhone 16 / 26.2 实测确认内部横屏内容出现在保持竖放的浏览器画布中。人为延迟
绘制确认后，原生 JPEG 降至 294×640；画面停止变化后，一张真实截图恢复到 590×1278，
而活动流仍保持 scale=4。接收端收到并确认静态帧，窗口排空。这是 loopback 加反馈延迟
的功能验证，不是公网吞吐或 H.264 验收。

### 接入 H.264 传输（2026-10-01）

后续实现采用了前面建议的 H.264 路线，不修改托管 runtime，也不增加依赖。私有 viewer
仅在存在 WebCodecs 时选择 AVCC，探测实际配置；配置不支持、解码或流失败时，每个 iframe
回退一次到 MJPEG。移动端方向、输入、截图、私有能力和租约边界继续共用。MJPEG 保留
静止高清刷新；H.264 使用原生重复的小增量帧及参考画面的渐进更新。

关键差异是编码帧依赖。有界解析器接受固定 VideoToolbox 的逐行 AVC 格式，验证 SPS/PPS
并读取参考帧序号。Baguette 自身积压导致的缺帧也会使下游参考链失效，不支持的格式回退
JPEG。独立控制器按序发送编码帧，放弃过期或溢出的帧链，待未确认窗口排空后限频请求
IDR，每个 IDR 携带 avcC。浏览器按序解码，只合并已解码画面，关闭 GPU 资源，限制解码
工作，并在隐藏或断开后拦截延迟返回的配置探测。

远端 H.264 从 600 kbps、最多 2 倍降采样开始，根据 ACK 排队延迟调整码率，不用小增量帧
大小除以 RTT 推算容量。64 帧 / 64–256 KiB 的远端窗口允许跨传播延迟流水发送，安静时的
小增量帧不构成提高码率的依据。待发队列最多 64 包 / 2 MiB / 一秒；超窗口 IDR 只能单独
发送。这仍是有界的延迟与画质取舍，不承诺帧率。原生 set_fps 仅改变空闲泵，不限制忙碌
画面调度，因此没有声称修复编码前帧率。数字诊断包含编码选择、回退原因、码率、队列和恢复。

确定性测试覆盖参考缺帧与回绕、非法格式、顺序确认、拥塞、已解码画面的合并和释放、
不支持配置时回退，以及过期异步探测。临时 iPhone 16 / 26.2 加 Chromium 在 loopback
以约 30 FPS 解码 590×1278 H.264，未出现解码错误。这验证原生/浏览器兼容，不代表实际
公网速度或 Safari/iOS WebView 已验证；不支持的浏览器继续使用 MJPEG。特定远端网络的
结论仍需结合后续现场诊断及 README 测试步骤。

随后用浏览器 WebSocket 测试替身在两个方向各加入 250ms 延迟，并按下行字节数限速。
持续滚动的合成 UIKit 页面在 0.6Mbps 测试末尾约为 49–55FPS；0.3Mbps 测试调整到
251–289kbps 后约为 32–45FPS。两者均保持 590×1278、没有解码错误或回退，队列有界；
调节期间发生了关键帧恢复。这些 20/30 秒实验使用真实原生编码器和浏览器解码器，
但注入的交付条件不等于 Cloudflare/TCP 丢包、真实公网、长期稳定性或任意应用复杂度。
仍需在用户实际远端链路复测。

Git 测试隔离继承的机器配置；否则机器上的 remote URL 重写会导致一个无关的工作区身份测试失败。外层检查仍遇到已有 ACP 依赖/类型错误；文档检查仍只报告已有的 MCP AGENTS 大小超限。

### H.264 停顿恢复修正（2026-10-01）

实测反馈显示 H.264 起初正常解码，随后绘制和 ACK 停顿，最终普通断流导致
iframe 永久回退 JPEG。报告无法区分 RAF 暂停与隧道中断：网关样本也逐渐过期。
最初策略将传输失败等同于编解码失败。

现在解码输出直接释放累计传输额度，不等待 RAF。只保留最新一张解码图片，
由 RAF 或仅在可见时工作的 100 毫秒计时器绘制。传输失败或连续八秒未收到
任何消息时，退避重连 H.264 两次，耗尽后显示恢复；编解码不兼容仍回退 JPEG。
新增纯数字诊断区分收帧、解码、绘制停顿及连接结果。无需增加依赖、runtime
资源或云服务部署。

执行实际内联代码的确定性测试复现了 RAF 暂停和暂时/静默断流，验证资源和
重试有界，隐藏及旧回调不能复活连接。这些测试不代表已确定或消除了用户
真实远程网络中的所有停顿原因。

真实隔离 iPhone 16/26.2 编码器与 Chromium 测试注入了 500 毫秒往返延迟、
0.6 Mbps 传输限制并全程暂停 RAF。100 毫秒备用绘制保持 590×1278、约
8.5–9 FPS，解码约 53–57 FPS。随后屏蔽全部下行消息，静默检测触发一次
H.264 重连；恢复后分辨率保持不变、解码零错误、没有回退 JPEG。此结果
属于受控故障注入，不能据此断言真实 WAN 中断的原因。

### 容忍抖动的视频反馈（2026-10-01）

后续实测保持 H.264、没有重连或解码错误，但码率从 690 降至 150 kbps，
同时 ACK 多次回到约 333 毫秒基线。旧控制器只要经过两秒再碰到一次慢 ACK
就可能降档；原测试把单张关键帧的慢确认称为持续拥塞。合成的有序批量 ACK
回归测试复现了码率不断下降。

现在需要完整两秒、至少八次 ACK 的窗口，且 75% 为慢确认才降档。健康的
实际负载可逐步恢复画质，空闲间隔重置观察，微小静态增量仍不能证明有空余
带宽。帧数、字节和年龄上限独立约束安全。代价是容忍短暂突发后，对新出现
的持续拥塞反应稍慢。确定性测试覆盖离群值、周期性批量确认、持续拥塞及恢复。

绘制仍只保留最新画面：批量到帧时收到 30 FPS 而绘制较少，不能直接证明
渲染出错。新增 RAF/计时器绘制计数、调度等待与最大到帧间隔来区分原因。
不能仅凭这些计数就声称实际网络或渲染瓶颈已解决。

隔离原生 iPhone 16/26.2 与 Chromium 测试注入 500 毫秒 RTT 和 0.3 Mbps
下行，保持 590×1278，解码错误、回退和重连均为零。最后四个样本绘制约
22–38 FPS，码率降到 218 kbps 后恢复至 251 kbps。RAF 调度平均约 3–5 毫秒，
没有使用备用定时器。此测试验证受限链路上的调档，不等于用户实际 WAN 或
移动端渲染验收。

### 解码突发与恢复预算（2026-10-01）

后续现场数据在零解码错误下以代码 3 降级，期间发生多次独立突发。旧实现按整条连接
累计恢复次数，并在解码器达到容量时立即重置引用链。现在等待 dequeue/output 释放
容量，保持编码顺序及原有 32 包 / 2 MiB 队列上限；溢出或三秒没有解码进展仍请求
IDR。连续恢复失败最多三次，持续三秒、至少 30 个输出且间隔不超过一秒才重置预算。
单个成功输出或空闲时间不会掩盖持续失败。新增纯数值诊断区分队列溢出、输出停滞、
解码错误及协议失败。确定性测试覆盖突发排空、五次独立成功恢复、持续失败、溢出、
过期回调和清理。这修复了已确认的恢复策略问题，不能据此断言网络批量到帧的具体环节。

真实隔离 iPhone 16/26.2 与 Chromium 测试将 WebSocket 消息每 750 ms 批量投递，
持续 45 秒。超过 2,500 次提交暂停后仍保持 H.264、590×1278，恢复、降级及解码错误
均为零。刻意批量投递下，末尾样本仅绘制 2–3.5 FPS；该测试验证突发容忍，不能证明
真实远端网络已流畅。
