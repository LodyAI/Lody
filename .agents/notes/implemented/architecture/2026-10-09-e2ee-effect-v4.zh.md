# E2EE core 与 lab 升级至 Effect v4

Status: implemented
Translation: current

[English](2026-10-09-e2ee-effect-v4.md)

## 摘要

core 与 lab 通过独立 catalog 使用 Effect 4.0.2，其他工作区包保留 v3。账本操作持有明确的事务状态，验证和提交仍只有一套实现。lab 所有者保持服务 Context 与长期 Scope；Deferred 门控和事件通知替代 Promise 等待器与定时轮询。协议和持久化格式不变。原生 HTTP/CRDT 回调仍是明确的桥接；这不代表全部源码已纯化，也不代表产品 E2EE 验收。

## 决定与范围

用户在 2026-10-09 阅读提案后授权实施。原始 HEAD：`677961747047547758184e7e150146d37d973d25`。这项版本和生命周期决定关联之前的 [Effect API 迁移](../../proposed/architecture/2026-09-22-e2ee-effect-api.zh.md)，不关闭其中未完成的产品验收。ledger/lab Spec 仍为 draft。

`e2eeEffect` catalog 精确固定 `effect: 4.0.2`；默认 3.18.4 catalog 和其他消费者不变。minimumReleaseAge 的例外只允许本次明确选定的版本，不豁免未来升级。lockfile 增加一份 v4 解析，保留 v3。

Electron 的身份服务调用 `@lody/e2ee-core/node-identity-client`，只接收 Promise、密钥句柄、字节与普通错误，不传递 Effect、Layer、Context、Cause 或 Fiber。初始化仍在创建前检查所选账号，显式 load 不替换缺失身份。真实 main 打包测试执行该接口，Electron 无须自己的 v4 runtime 别名。

核查了目标版本的官方资料：[发布](https://github.com/Effect-TS/effect/releases/tag/effect%404.0.2)、[Result 转换](https://github.com/Effect-TS/effect/blob/effect%404.0.2/migration/yieldable.md)、[服务](https://github.com/Effect-TS/effect/blob/effect%404.0.2/migration/services.md)。Result 是普通值，workflow 用 `Effect.fromResult` 明确转换；服务使用 `Context.Service`，Cause 检查和 fiber 中断遵循 v4 语义。多个失败、缺陷和取消原因穿过 Promise 边界时保留为普通 AggregateError，不再只转换第一个预期错误。

## 账本状态与持久化

LedgerEngine 仍是捕获端口的句柄，不启动内部 runtime。每次独占操作读取持久存储，创建事务局部 Ref，并显式传入同步、签名、提交和保存。长期 Ref 只保留已验证前缀证据，不再作为事务的隐式状态源。事务直接持有原始 journal 端口，也支持通过原型方法实现的端口。

save 先落盘，再在同一个很窄的不可中断区域发布事务状态和已验证缓存。CAS 与读回保持可中断，后续错误不撤销已保存的页。精确 pending 字节先于 CAS 保存；重试不重签，读回才能确认提交。只有传输不确定性变成 Pending。快照信任、长度、完整状态摘要和已保存前缀身份检查保持不变。

`pure/ledger-page.ts` 无 I/O、无输入修改地选择记录并追踪快照绑定和公钥点有效性事实。未知前缀不是已验证授权；后缀验证和检查点发布属于 workflow。旧入口新增 `openEffect`/`readEffect` 描述，使 lab 使用自己的所有者，无须嵌套 Promise runtime；旧 Promise 方法仍运行同一描述。

## lab 所有权与原生桥接

LabRun 构造时不做 I/O，每个所有者只构建一次独立服务 Context，保持长期 Scope，并将操作 fiber 绑定到该 Scope。关闭拒绝新工作，中断活跃 fiber，并幂等等待清理。不同所有者不共享 Layer 获取状态。单次 runLabPromise 自动关闭所有者；会返回长期资源的调用使用持续存活的所有者。

Layer 获取过程本身也绑定到 Scope，因此关闭能中断尚未完成的获取，并释放停滞前已获取的资源。

host 用原生 Scope 获取 HostMeta、Riverrun、请求 fiber 和 HTTP listener。监听失败或启动后续失败会释放之前资源，Promise host.close 关闭所属 Scope。HTTP 请求处理器仍是明确的原生 Promise 桥接，通过 AsyncLocalStorage 中的 AbortSignal 把 Effect 取消传入 fetch/StreamsClient；网关策略继续使用现有纯函数。session 等待关闭，账本读取、恢复和意图执行通过声明依赖的 SessionLedger workflow 与核心原生描述完成；登记、轮换、发钥也使用持续存活的 session 所有者。AttackLab 的服务所有者保持私有，攻击者拿不到它。

每个 runtime 用自己的 Ref 和同步串行转换持有调度状态。Deferred 门控保留明确许可、嵌套事件和成功/失败的独立交付边界。请求、完成和恢复 actor 的通知队列唤醒 Scope 中的 driver，不增加隐藏许可。driver 保留既有身份匹配、提前选择/FIFO 和许可预算行为。Effect Clock 超时保护与逻辑重放时间分开。原生 Promise/SDK 回调继续通过明确的 AsyncLocalStorage 桥接传递父事件。runtime.close 立即拒绝门控，等待 dispose 才完成所有者清理。

finish 封闭公开攻击句柄，但私有重放服务保留到 runtime 释放。观察与修改动作先在当前事件边界完成，driver 才能放行下一次诚实客户端请求；推进动作自行授予明确许可，只有 finish 测量自动排空。完整重放在迁移中发现了提前释放和提前推进问题，现在所有者与动作边界都保持已记录的重放顺序。

剩余桥接包括 HTTP 路由和响应体处理、streams-crdt/Loro/Flock 回调、快照发布及 demo backup 适配器；它们不另写验证、提交、轮换或内容算法。没有把整个 lab 包进一个 tryPromise：那无法证明资源所有权和原生账本依赖。完整转换这些适配器与本次版本升级分开，源码风格目标仍有效。

- 使用只排除这些未跟踪文件的临时配置，已跟踪 core/lab 源码、benchmark 和测试通过类型检查。root pnpm check 在这些文件处停止；若以后采纳它们，其 v3 Either 引用也须升级，不能称整个工作区检查通过。
- core 完整已跟踪套件为 45 文件、535 项通过、1 项跳过；最终重点套件覆盖混合 Cause、Promise 初始化、SQLite 中断和精确 pending 恢复。lab 完整已跟踪套件为 22 文件、171 项通过，包括三次独立重放、启动失败清理、未完成的 Layer 获取和活跃请求取消。
- Electron main/web 类型检查及 7 项真实打包/密钥保护测试通过。仅排除已有未跟踪 review 文件时，全工作区类型感知 lint 通过，既有警告保留；root lint 在其中一个文件未等待 close 处停止，本次未修改这些文件。
- 扩展 Effect 检查覆盖 core 的纯层/端口/workflow、旧 ledger facade，以及两个包的 runtime 启动位置/v4 导入；不证明原生桥接全部纯化。公开仓库边界通过，docs check 无错误，既有大小/链接警告保留。仅格式化本任务改动和新增文件，保留无关未跟踪工作。
