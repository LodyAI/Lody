# 桌面会话共享所有权

Status: implemented
Translation: current
PR: [#1241](https://github.com/LodyAI/Lody/pull/1241)

[English](2026-10-04-shared-desktop-session-owner.md)

## 摘要

过去本地桌面打开第二窗口，需要再次导入会话文档并建立历史投影，之后才能显示内容。
现在由主进程管理的数据 renderer 持有会话文档和 UI 写入者，产品窗口通过 IPC 读取索引和
按窗口加载的投影。这移除了重复文档导入，保留现有写入校验，并在文档落盘后才确认成功。
进一步限制目录／消息的渲染范围，并在挂载路由前交接首屏数据后，严格无悬停的
3,000 条历史对照从 323/382 ms 降至 232/287 ms 显示／输入确认中位数（每种构建十次）。
这仍高于 100 ms 目标。独立 renderer 和已准备视图的内存、首次打开成本在评估中明确记录。
随后消融否决了更多预挂载、更小缓冲以及删除数据交接，本轮不宣称进一步的产品延迟改善。

## 决策与边界

数据 renderer 独立于可选预热池，在本地工作区组合时启动，使用自己的 Repo、存储和游标
命名空间。每个产品窗口仍拥有元数据、草稿、附件准备、编辑器和 ConversationView。
CLI 仍是 agent 作者；UI 命令不转换为 CLI 代写命令。云端和 Web 保持直接写入组合。

所有者复用 SessionData/HistoryWriter 写历史、WorkspaceWriter 修改队列。首次响应包含
缓存的浅目录和首屏所需的 40 条尾部内容，并在最多 50 条的范围内向前扩展到用户消息。
客户端完成这段有限尾部的加载后才暴露 store；后续正文读取按批次发送。同步完成的尾部
加载不再等待额外 idle 回调，所有者直接读取权威目录，不等待自己的 UI 投影。各视图仍需构建 O(total) 目录；完整导出和 fork 读取仍是显式操作。连接通过不透明 IPC 引用保留写入者实际捕获的
快照句柄，这张查找表不另行授予复制来源权限。句柄被回收或连接关闭时释放；回滚句柄
还会持有来源 store，直到释放为止。

主进程验证产品主 frame 与实际数据 renderer。租约、序号和所有者代次隔离旧事件与回复。
关闭一个视图只释放它的订阅；退出应用先排空已接受操作，再关闭传输。
所有者故障时拒绝未完成命令并明确结果可能已提交，绝不重放；视图用新租约重连，
使旧投影失效并读取持久状态。重连失败保持为错误，不另建一份写入者。

旧窗口快照在冷所有者建立订阅之前写入存储，已有文档则原地合并并落盘，原缓存保留；独立 Repo 不共享存储与游标检查点。
历史和队列确认等待单文档持久化，不等待全 Repo flush；队列水位也在确认前持久化。
待完成附件和编辑器草稿仍属于窗口，因此仍需要关闭保护。对应守卫现在只记录阻止类型、
数量或保存状态，不记录消息和文件内容。最初报告的关闭弹窗根因仍未确立。

本次没有选择完整 utility-process 迁移：当前 Runtime 依赖浏览器 IndexedDB 和 Electron
renderer 传输。复用它可以保留一套同步和写入实现，代价是额外 Chromium renderer。
把所有者移到不依赖 DOM 的 worker，需要先抽离这些运行时依赖；本次不宣称已完成该内存优化。

## 直接点击的渲染路径

共享文档没有消除点击后的目标渲染。同一份 3,000 条历史的性能分析发现，目录仍挂载
1,500 个刻度，消息视图也在滚动引擎选定挂载范围之前，为全部历史构建 React 元素。
现在目录只挂载视口范围与 overscan，保留完整滚动高度以及焦点、悬浮卡片锚点。
消息视图向引擎提供按行构建函数，只构建挂载计划中的行，包括原生文本选区保留的行。
初始滚动恢复与可见消息流的就绪条件保持不变，不通过提前显示未完成内容缩短数字。

附属会话窗口将初始隐藏的侧栏延后到首次展开时挂载，此后收起仍保留视图；主窗口保持
原行为。明确的目标导航在挂载路由前发起同工作区 store 获取，给缓存数据最多 50 ms
到达时间；较慢或失败的读取仍进入正常加载／错误路由。代次隔离被替换的目标，临时
store 引用即使在超时或重定向后也会释放。这从实际目标请求开始，不需要提前悬停。

随后的单因素消融中，常驻公共工作区外壳在七次探索样本中仅节省约 14 ms，却增加根路由／
作用域耦合，因此撤回。诊断构建完整移除输入框、只保留实测高度，各五次对照节省约 29 ms，
显示仍需 191 ms。这省掉了必要控件，不能证明常驻且可交互的输入框能获得同样收益。
本次没有加入虚假会话或跨会话复用草稿方案。

最初的 200 px 屏外缓冲试验虽改善探索中位数，却改变触摸滚动补偿，并在桌面滚轮位置检查中
出现 4 px 偏差。桌面 400 px 候选通过全部四项浏览器用例，但最终各十次组合对照从
219/278 ms 退化到 237/283 ms 显示／输入确认。之后只删除数据交接，测得 240/291 ms。
两者均撤回，保留现有 800 px 缓冲和有界的路由前数据交接。50 ms 是上限，不是固定睡眠；
消除此路径没有改善端到端打开。未修改的对照在不同批次也从 234 变到 219 ms，因此不能
把小样本串行差异当成稳定提升。

[消融记录](../../../../packages/components/benchmarks/window-bootstrap/README.md#ablation-decisions)
保留十组运行、被否决的补丁、对应源代码 hash 和失败启动。105 次首帧检查均通过，其中
89 次验证唯一输入；移除输入框的诊断不验证输入。这些计数含 30 次不计入统计的预热。
最终没有新增常驻视图、缓存或产品抽象。模型测试改为检查保存的阅读锚点：消息缩短使其
下一行顶到视口边缘时，重新长高仍应恢复原消息内偏移。浏览器测试先滚动虚拟目录，再点击
屏外轮次。保留这些验证改进和更完整的源代码 hash 覆盖。

单独关闭原生动画的探索实验只将显示中位数从 235.61 降至 227.47 ms（各三次），不足以
支持随产品引入原生扩展。产品保留 Electron 展示以及两帧内容就绪条件。此前预加载
90 条尾部的实验延后了挂载而没有有效收益；最终响应跟随实际首屏范围与有界用户上下文。
目录、React provider／输入框挂载和原生显示仍有成本。直接打开低于 100 ms 的目标尚未
实现，预渲染命中不能作为其证据。[直接点击评估](../../../../packages/components/benchmarks/window-bootstrap/README.md#direct-click-without-hover--2026-10-04)
记录一致构建条件、全部样本和剩余限制。74 次延迟探针的内容／输入检查全部通过，包含
21 次不计入统计的预热轮次；主要对照的两种构建均保留主干 `8872177b6`。合并后八阶段内存复测中，一个已准备视图增加 230–237 MiB；
关闭五个辅助窗口后回到仅主窗口值以上 10.11 MiB，辅助 renderer 全部退出。这一次运行
继续支持原先 250–300 MiB 的规划预算，不宣称完成了内存配对改善对照，也未覆盖不同会话的缓存保留。

## 评估

[桌面 runner](../../../../packages/components/benchmarks/window-bootstrap/README.md)使用生成的
会话、隔离 profile，以及同一份应用与 CLI 构建对比两条路径。
`LODY_SHARED_SESSION_OWNER=0` 仅用于隔离评估旧的独立文档路径，不是缓存迁移或回滚方案。
脚本已改用当前预热 IPC，释放仅供导入 fixture 的句柄，采样进程工作集，并在正常关闭
出现原生确认框时判定失败。

[完整评估](../../../../packages/components/benchmarks/window-bootstrap/README.md#shared-session-owner--2026-10-04)
记录了样本、构建 hash、复现命令与失败尝试。M4 Max / Electron 43.7.6 下，最终反向顺序
各十次复测中，立即点击到显示从 499.04 降至 379.80 ms，输入确认从 621.70 降至
468.52 ms。之前各五次对照改善为 16.9% / 15.0%，不能把 24% 当作普遍目标。
共享方案准备完成后点击，显示为 83.14 ms、输入确认为 162.29 ms（三次样本）。
含预热轮次的 70 次内容／输入／正常关闭检查全部通过。强制终止所有者后，已确认写入
和来源视图在 1,128.88 ms 内恢复。

在输入确认时采样，逐个打开关闭的进程工作集之和中位数增加 472 MiB；同时保留第五个
附属窗口时则降低 7.3%。这是打开过程中的采样，不是稳定常驻值。新 profile 的 fixture
导入至首次来源会话显示从 1.19 增至 1.98 秒，这包含旧缓存
迁移，不是整个应用启动时间。独立 renderer 的代价真实存在，多视图并存时共享文档更有价值。
两次探索性的预热命中探针在发出意图 IPC 前超时；最终脚本在悬停前聚焦来源窗口并等待元数据
更新稳定，此后两条路径均通过，但没有单独确定原取消事件的触发因素。

[空闲内存评估](../../../../packages/components/benchmarks/window-bootstrap/README.md#idle-memory-and-retention)
补充了主窗口／已准备视图的 45 秒观察和关闭后 30 秒观察，全程不强制 GC。
按 macOS physical footprint 统计 Electron 进程（不含独立 CLI/daemon），仅主窗口时旧方案
为 616.15 MiB，共享方案为 742.37 MiB；共享方案保留一个已准备的隐藏视图为 969.42 MiB，
比保留前／销毁后的主窗口采样增加约 227–236 MiB。各阶段末次采样的数据 renderer 约 131–147 MiB，空闲后的
已准备 renderer 为 203.71 MiB。这些计数器与此前进程工作集之和不同。

关闭五个附属窗口后，共享方案回到 753.93 MiB，附属 renderer 进程全部退出。两种方案均完成
八个阶段、合计 66 次 OS 采样，没有关闭确认。初步运行发现十秒后仍有自然内存回收，并遇到
进程在采样期间退出的竞争；该轮不计入最终对照。对于这个 fixture，先为一个热视图预留
250–300 MiB 额外预算是合理建议；多个隐藏视图仍未实现。本次所有窗口共享同一会话，来源
窗口保持打开；尚未测量不同会话文档、其十分钟 store 缓存宽限期和数小时保留情况。

## 验证与限制

行为测试通过 structured-clone 传输运行真实 Loro 读写器，覆盖共享所有权、独立关闭、
首次订阅期间发生编辑、旧缓存合并、跨会话快照来源、落盘失败、并发队列标识、
所有者重建、尾部编辑结果不确定、后续观察者和连接/工作区隔离。历史后台读取失败不再泄漏未处理的 Promise 拒绝。
真实桌面探针检查首次显示的内容与唯一文本输入，进程恢复评估检查已确认写入。

本轮四个针对性套件通过 132 项测试，包含 400/800 px 两种范围下各 40 个种子、每种子
60 步操作；保留的产品实现通过全部四项真实浏览器回归。此前六个所有者／渲染套件通过
75 项测试，其中所有者／客户端为 12 项；Electron 通过 199 项。
新增用例覆盖按需构建行、目录键盘导航／预览锚点保留、侧栏状态、首屏尾部就绪，以及
目标交接的超时和代次隔离。
类型检查、生产构建、lint、i18n、平台／公开仓库／导入边界检查通过。完整 `pnpm check`
运行到 components 时为 4,824 通过、1 失败，失败是未修改的 `boot-shell.test.tsx`
存储不可用回退用例，在 Node 26 环境单独重跑也失败。CLI 的 3,474 项和 shared 的 1,271 项
测试通过。评估克隆的文档检查有 6 处既有链接指向未初始化的独立 Kimi/Pi 子模块；无依赖
检出中有 62 处缺失子模块链接，没有新增文档链接错误。

嵌套检出没有依赖，验证在独立克隆中运行。既有子模块与 lockfile 不一致，需要在该克隆中
执行非 frozen 安装；其 lockfile 未复制回工作区。性能对照使用同一依赖树与 CLI 构建。
已安装产品及其 profile 未修改。

计时不包含物理输入、显示扫描输出或 IME。准备完成后的命中是理想场景，不能代表预测命中率。
打开过程的进程工作集、空闲时 macOS footprint 与诊断用 JS 堆计数分别记录，不能由此确立总体内存预算。
小样本串行测试不能确立总体 P95。旧辅助窗口缓存只能在对应命名空间打开时合并，
本次不会全局扫描或删除它们。
