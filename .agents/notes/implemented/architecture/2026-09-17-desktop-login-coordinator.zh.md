# 主进程统一协调桌面登录

Status: implemented
Translation: current

[English](2026-09-17-desktop-login-coordinator.md)

## 摘要

原来的桌面登录由 React 回调监听器驱动 renderer 事务，组织加载失败也会回滚认证。
已完成回调被重复打开时可能再次兑换已消费的授权码并触发退出，而多数失败只会静默退回登录按钮。
现在由主进程管理 PKCE attempt 和带版本号的结果，renderer 独立于工作区加载发布认证身份。
交换不再依赖 renderer 生命周期；保留的明确限制是主进程重启后需要重新发起浏览器授权。

## 决策

本改动补充[浏览器账号确认改动](../bug-fix/2026-09-15-electron-browser-signin-account-choice.zh.md)：
前者增加了手动打开链接，但没有调整桌面的回调处理。[Spec](../../../../specs/desktop-browser-login.zh.md) 定义新的客户端行为。
浏览器载荷与 Better Auth 1.5.5 的 token 接口保持兼容。Lody 生成 state/verifier，通过现有 Better Auth 客户端交换，保留其 cookie 存储钩子。
若继续使用 SDK 不透明的 requestAuth attempt 表，会出现两套管理者，因此替换其本地记录方式，不镜像或修改 SDK 内部全局状态。

主进程在 renderer 路由之前接收回调，并保留最新结果供新窗口查询。已结束的相同 state 回调无副作用；旧 state 无法替代当前 attempt。
取消和超时阻止迟到结果发布。AuthService 串行执行凭据修改操作，并在交换前后检查取消信号。
诊断不包含 token、回调 URL 或用户数据。

renderer 先订阅再查询快照，用版本号拒绝过期结果，并使先前查询失效。失败会释放暂停的查询而不清除已有身份；
交换结果不确定时查询持久会话。组织失败仍由现有工作区守卫阻止进入，并提供显式重试。主进程在认证成功后触发一次 CLI 重启。

拒绝扩大五秒 URL 去重窗口：时间窗口不能表达已完成或被替代的 attempt。
拒绝继续将组织加载放入认证事务：可恢复的资源失败不应消耗下一次登录。
跨进程重启持久化 PKCE、替换认证库均不在本次范围。

## 验证

现有回调测试改为执行真实主进程协调器，使用合成会话、可控 Promise 和假计时器，覆盖 PKCE challenge 匹配、
成功前后重复回调、旧浏览器标签、取消、超时、迟到成功和失败、等待过期、浏览器打开失败及重启恢复。
浏览器交接测试也覆盖桌面错误提示、重试和恢复交换进度，并保留账号确认覆盖。
另用 Better Auth 1.5.5 内存服务验证协调器生成的 PKCE 参数与真实 transfer/token 接口兼容，全程不访问网络。

这些测试不证明打包应用的系统协议分发或真实托管登录。仓库类型、lint、国际化、边界和文档检查均通过。
完整 `test:ci` 在沙箱外通过（沙箱内禁止监听本机端口），包含全部 137 项 Electron 测试；不代表已部署或实际账号登录。
