# 直连推送的客户端边界

Status: implemented
Translation: current

[English](2026-10-16-direct-push-client.md)

## 摘要

共享通知设置原先加载第三方 SDK，并由它管理设备身份。现在客户端通过注入的、已认证的平台操作注册原生 token 或浏览器订阅。私有原生壳负责操作系统注册与 ActivityKit，托管后端负责投递。这移除了运行时的供应商依赖，同时保留现有设置和 Electron 本地通知。通道接受请求与真机送达仍是不同的验证边界。

支持原生壳及明确开启推送、具备所需能力的浏览器。Web 使用配置的 VAPID 公钥和独立 Service Worker。

## 决策

`lib/push-notifications.ts` 管理订阅生命周期、语言、权限和安装身份。
`cloud-api-operations.ts` 定义可移植的注册 DTO，认证路由注入 mutation。
本地桌面不会安装或使用托管推送传输。原生壳实现 `window.__LODY_PUSH__`，
共享组件不导入 Capacitor 运行时代码。iOS 注册通过可移植 DTO 传递原生应用的实际 `bundleId`，
使宿主能够路由多个应用，而无需在共享代码中放置供应商凭证或配置。
宿主必须校验应用身份白名单；客户端字段不构成应用真实性证明。

权限、开启偏好与注册确认是不同状态。只有当前代次的后端保存成功后，设置页才报告注册成功。
原生宿主等待初始系统 token 及上传完成，并串行执行本地命令，不把注销排在网络上传后面。
即使认证接口或延迟登录尚未建立，退出也必须注销原生注册，并使已安排的登录任务失效。
宿主必须将订阅绑定到真实登录会话，会话撤销或过期后拒绝发送；有时限的客户端清理本身不构成授权边界。

切换账号会使旧回调失效；退出先停止本地注册，并在认证消失前尝试有时限的服务端清理。
Web 订阅使用独立 worker scope；托管 worker 校验接收账号后才显示通知和处理点击。
浏览器权限已授予不代表订阅存在。Web Locks 串行化同源订阅变更，worker 在账号写入持久存储后才确认。
即使尚未完成延迟的推送登录，退出也必须清理持久化的浏览器授权。焦点恢复与订阅变化消息会同步更新的密钥和端点；
关闭页面后的 worker 不保存会话凭证。要求新用户手势的浏览器可能需要再次手动开启通知。

保留旧 SDK 会保留第三方身份和脚本加载；在共享代码另建后端客户端则违反平台边界。
选择的接口沿用设置契约，避免这两种依赖。

## 验证

行为测试覆盖原生 token 上传、关闭订阅、迟到回调、Web 权限与显式开启条件、换钥、订阅刷新，以及推送登录前退出的清理、退出时取消延迟登录、注册失败与确认成功的区别。
真实 APNs/FCM 送达和 Xcode 编译需要私有壳的凭证和 Apple 工具链，测试不能证明真机送达。
本次不承诺自动重试或恰好一次投递。
