# 直连推送的客户端边界

Status: implemented
Translation: current

[English](2026-10-16-direct-push-client.md)

## 摘要

共享通知设置默认使用 OneSignal，仅在托管配置明确启用时使用自建注册。自建模式通过注入的、已认证的平台操作注册原生 token 或浏览器订阅。私有原生壳负责操作系统注册与 ActivityKit，托管后端负责投递。供应商接口保留现有设置和 Electron 本地通知。通道接受请求与真机送达仍是不同的验证边界。

支持原生壳及明确开启推送、具备所需能力的浏览器。Web 使用配置的 VAPID 公钥和独立 Service Worker。

## 决策

`lib/push-notifications.ts` 管理订阅生命周期、语言、权限和安装身份。
`cloud-api-operations.ts` 定义可移植的注册 DTO，认证路由注入 mutation。
本地桌面不会安装或使用托管推送传输。原生壳实现 `window.__LODY_PUSH__`，
共享组件不导入 Capacitor 运行时代码。iOS 注册通过可移植 DTO 传递原生应用的实际 `bundleId`，
使宿主能够路由多个应用，而无需在共享代码中放置供应商凭证或配置。
宿主必须校验应用身份白名单；客户端字段不构成应用真实性证明。

权限、开启偏好与注册确认是不同状态。自建模式只有当前代次的后端保存成功后，设置页才报告注册成功。
原生宿主等待初始系统 token 及上传完成，并串行执行本地命令，不把注销排在网络上传后面。
即使认证接口或延迟登录尚未建立，退出也必须注销原生注册，并使已安排的登录任务失效。
自建模式的宿主必须将订阅绑定到真实登录会话，会话撤销或过期后拒绝发送；有时限的客户端清理本身不构成授权边界。

切换账号会使旧回调失效；退出先停止本地注册，并在认证消失前尝试有时限的服务端清理。
Web 订阅使用独立 worker scope；托管 worker 校验接收账号后才显示通知和处理点击。
浏览器权限已授予不代表订阅存在。Web Locks 串行化同源订阅变更，worker 在账号写入持久存储后才确认。
即使尚未完成延迟的推送登录，退出也必须清理持久化的浏览器授权。焦点恢复与订阅变化消息会同步更新的密钥和端点；
关闭页面后的 worker 不保存会话凭证。要求新用户手势的浏览器可能需要再次手动开启通知。

恢复 SDK 是有意保留第三方身份和脚本加载的回退选择。在共享代码另建后端客户端违反平台边界，因此供应商配置仍由认证路由注入。

## 原生移动客户端

`apps/mobile` 下独立的 Swift 与 Kotlin 客户端不使用共享 Web/Capacitor 接口。
进程级通知协调器读取 `pushSubscriptions:configuration`，只有成功响应明确开启直连时
才选择自建投递，否则使用 OneSignal。查询失败不构成切换服务商的授权。
原生 OneSignal 登录将原始账号 ID 映射为 `lody-push-v2:<userId>`；载荷接收者校验与
导航仍使用原始 ID。混用两种命名空间会使有效的 SDK 订阅无法被发送端找到，
旧服务商身份不会合并到新命名空间。

直连注册使用稳定的安装 UUID 和已认证的应用登录会话。iOS 上报实际 Bundle ID，
Android 使用已配置 Firebase 项目的 token；服务商密钥只由服务端持有。
通知协调器拥有凭证快照，将清理与注册串行化，并阻止已退休账号的本地回调影响新状态。
传输超时不能证明服务端已取消或已提交；结果不明确的写入仍可能与后续服务端操作竞争。
这些客户端没有增加服务端注册代次协议。
通知失败与登录、对话可用性隔离；回到前台或认证刷新时重试注册，不重放通知。
iOS 不恢复已移除的 Live Activities。

仅切换后端不能为离线设备重新注册。系统或服务商已接受的通知可能在退出后到达，
OneSignal 不继承直连通道的服务端会话撤销保证；此限制与客户端点击归属校验必须区分。
原生检查覆盖生命周期和路由边界，真实服务商凭证、系统权限、签名及真机送达仍需平台验收。

## 验证

行为测试覆盖原生 token 上传、关闭订阅、迟到回调、Web 权限与显式开启条件、换钥、订阅刷新，以及推送登录前退出的清理、退出时取消延迟登录、注册失败与确认成功的区别。
真实 APNs/FCM 送达和 Xcode 编译需要私有壳的凭证和 Apple 工具链，测试不能证明真机送达。
本次不承诺自动重试或恰好一次投递。

## 供应商回退更新

客户端默认使用 OneSignal，只有托管配置明确启用时才使用自建注册。恢复后的
OneSignal 登录使用 `lody-push-v2:<userId>`，服务端发送须使用相同身份空间；
设备需要重新打开新版客户端，旧客户端遗留的身份不会因切换而重新接收通知。
关闭通知及退出登录会清理两种供应商。Web 未设置偏好时保留已有 OneSignal 订阅。
OneSignal 保留 SDK 管理的身份生命周期，不具备自建后端按登录会话撤销发送的保证。
