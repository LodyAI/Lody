# 每日笔记独立窗口从本地打开

Status: implemented
Translation: current

[English](2026-11-25-today-window-local-open.md)

## 摘要

每日笔记独立窗口原先每次都启动新的桌面渲染进程，并等待工作区的会话元数据扫描。
现在，匹配的工作区运行时可用后即可读取首个日期。本地桌面可以在退出工作区路由后
复用一个已经打开过的渲染进程。收到匹配的日期内容提交后显示窗口，绑定失败时重新冷开。

[共享渲染进程的子窗口](2026-11-25-today-shared-renderer.zh.md)使用这里的独立窗口路径处理降级和接管。

## 决策

本地大纲可先于会话投影显示。工作区准入、slug 和 ID 仍用于确定供给页面的运行时。
首个日期立即打开页面存储，较早的日期继续按视口加载。本地每日笔记窗口在首个日期绘制后
再订阅会话元数据，避免扫描占用首屏加载时间。

复用由用户首次打开窗口后开始，且另有产品窗口时最多保留一个渲染进程。
中立路由通过现有所有者释放页面引用、运行时和同步资源。应用启动时预热会让未使用
每日笔记的用户也承担内存开销。云端每日笔记沿用原有关闭流程。
[开发者预热池](../feature/2026-09-18-desktop-window-prewarming.zh.md)仍服务于会话和工作区窗口。

主进程根据发送窗口及当前绑定代次判断就绪。本地页面读取失败可以显示重试界面。
渲染进程若在 1.5 秒内无法绑定，主进程销毁它，再按请求的日期冷开。
关闭窗口会取消待办任务。最后一个产品窗口关闭后，产品窗口注册表会清理隐藏窗口。

## 验证

[生命周期测试](../../../../apps/electron/src/main/today-window-lifecycle.test.mjs)覆盖绑定身份、
恢复、保留上限和关闭。[作用域测试](../../../../packages/components/tests/workspace-data-scope.test.ts)
覆盖会话元数据尚未就绪时的工作区身份校验。

在 Linux arm64 和 Xvfb 下，用同一份合成工作区依次运行仅含打点的基线
（`9bd504d10`）和优化后的 Electron 与随附 CLI。每份工作区都有已保存的笔记。
冷开从请求计到首个日期绘制，每个版本取四个样本。复开从请求计到绑定日期提交后
原生窗口显示，取十六个样本。

| 会话数 | 基线冷开中位数 | 优化后冷开中位数 | 复开中位数 |
| --- | ---: | ---: | ---: |
| 0 | 1,156 ms | 1,171 ms | 41 ms |
| 300 | 1,648 ms | 1,491 ms | 48 ms |

所有复开样本为 28–71 ms。测量同时检查了请求的日期和已保存正文。
冷开仍需启动 Electron 渲染进程并加载应用包。耗时适用于本次测试主机的本地构建。
