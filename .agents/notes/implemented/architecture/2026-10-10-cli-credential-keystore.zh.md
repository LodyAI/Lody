# 将 CLI 云登录令牌放入操作系统凭据库

Status: implemented
Translation: current
PR: [#1421](https://github.com/LodyAI/Lody/pull/1421)

[English](2026-10-10-cli-credential-keystore.md)

## 摘要

CLI 过去把云登录信息，包括长期访问令牌，以 JSON 写在数据目录下。现在配置文件
保留用户资料和机器标识，并在可以打开 macOS 钥匙串、Windows 凭据管理器或 Linux
Secret Service 时，用 `@napi-rs/keyring` 再把令牌写入操作系统凭据库。默认仍在
文件中保留令牌副本：旧版 CLI 仍然要求该字段，去掉之后旧版会把这台机器视为已
登出。只有在读回同一令牌之后，`LODY_CLI_DROP_FILE_TOKEN=1` 才会删除该字段。
凭据库不可用时，文件中的登录继续有效。

## 决定

`credentials.json` 仍是版本 3。用户资料、机器标识和未知字段留在文件里。令牌
通过绑定的 `Entry` 构造函数写入，service 是 `Lody CLI`，username 是
`cloud-token.` 加上解析后数据目录的 SHA-256，因此两次安装不会共用一条记录。
这里不使用 `target`：在 macOS 上它选择钥匙串域，在 Windows 上带 target 构造
条目会写入空密码。Linux 条目要求 Secret Service，不使用内核密钥环，也不另设
一把加密密钥。

读取时，只要文件里有令牌就使用文件中的值，包括它与凭据库不同的情况；文件没有
令牌时才使用凭据库。保存和读取都会尝试把文件令牌复制进凭据库，并且只有随后读
回的值相同才算成功。失败时文件保持原样。`LODY_CLI_DISABLE_KEYSTORE=1` 会跳过
凭据库。`LODY_ELECTRON_SESSION_TOKEN` 不变：启动流程仍通过现有引导交换它，不会
把它当作已保存的令牌。

默认不删除文件中的令牌。开启删除后，只有凭据库读回一致，并且再次读取文件时
仍是同一令牌，才会写回不含令牌的文件，因此并发的新登录不会被清掉。登出和
作废当前令牌会同时清掉凭据库条目和文件。先清凭据库，进程中断时文件里仍有令牌。

文件通过以 `0600` 打开临时文件再改名发布。在 POSIX 上，数据目录创建并收紧为
`0700`。权限调整失败会记录一次，不会丢掉仍可读取的登录。在 Windows 上，`icacls`
成功时把发布后的文件限制为当前用户。

这里复用 CLI 已有的 `@napi-rs/keyring` 2.1.0。它已经在 CLI 打包中保持为外部
依赖，并随桌面应用一起放置。
[Codex 凭据库](../bug-fix/2026-10-07-codex-credential-failure-recovery.zh.md)
使用另一条记录，并且仍然没有文件回退。绑定通过 `createRequire` 加载，以免被打进包内。

## 兼容

已经带有令牌的现有文件无需额外提示即可继续使用。没有 Secret Service 或显式
关闭凭据库的机器，继续读写文件中的令牌，并只记录一次该选择。已经去掉令牌字段
的凭据文件，安装身份路径仍能从中读到机器标识。

只接受文件令牌的旧版 CLI 会把缺少该字段视为已登出。因此这个版本继续把令牌留
在文件中，直到后续版本确认降级窗口可以结束。不需要该降级兼容的环境可以设置
`LODY_CLI_DROP_FILE_TOKEN=1`。

## 验证与限制

单元测试覆盖读取顺序、校验成功后的删除、凭据库抛错或返回不同值、删除窗口期间
的读取、更新的文件令牌被保留、同时清理两个位置，以及 POSIX 权限。它们还会为
同一次安装构造两个普通条目，并确认第二次仍能读到密码；同时复现带 target 的
构造函数写入空密码的情况。Windows 访问控制由失败的限制回调覆盖。单独的 CI
任务在 macOS 和 Windows 上用真实凭据库写入、从另一个进程读回并删除。Linux
任务在 Secret Service 可用时做同样的事，否则跳过。Linux 总线存在但不响应时，
一次同步凭据库调用仍可能停住；`LODY_CLI_DISABLE_KEYSTORE=1` 会跳过它。桌面
会话存储没有改动。
