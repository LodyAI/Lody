# 轻量每日笔记窗口复用桌面渲染进程

Status: implemented
Translation: current

[English](2026-11-25-today-shared-renderer.md)

## 摘要

本地桌面从匹配工作区的主窗口打开每日笔记时，两个窗口共用主窗口的渲染进程和实时笔记缓存。
子窗口有独立的原生窗口、置顶状态和文档，通过 React Portal 挂载笔记界面。
没有匹配来源时使用独立窗口。来源关闭、重载或崩溃时，独立窗口也会接手。

## 决策

- 主窗口运行时提供页面缓存和每日笔记日期索引。子窗口获取同一份页面存储的引用，可以立即显示已有快照。
  第一个消费者仍可能需要初始化日期索引。子窗口无需启动路由、工作区准入、Repo 或全量元数据扫描。
- 主进程只允许登记过的主窗口使用一次性名称打开空白子窗口。主进程拦截子窗口导航，子文档无需新增 IPC 权限。
  置顶和全屏状态绑定原生子窗口。应用菜单操作交给来源窗口，关闭窗口快捷键关闭子窗口。
- 绑定只适用于对应的运行时和工作区。离开作用域或关闭实验功能会关闭窗口并释放页面引用。
  来源窗口关闭、重载、崩溃或子窗口首次显示失败时，由[独立窗口](2026-11-25-today-window-local-open.zh.md)
  接手最近一次选择的成员、日期和置顶状态。应用退出时无需接手。主进程不重放编辑。
  新窗口沿用每窗口独立的本地副本和同步游标。
- 两个窗口共享渲染线程和故障边界。选区、剪贴板、指针监听和弹出菜单使用子窗口文档。
  云端模式和没有匹配主窗口运行时的打开请求可走独立渲染路径。

## 证据

在 Linux arm64 和 Xvfb 下，用构建后的 Electron 和随附 CLI 打开带 300 条会话的合成工作区。
窗口 ID 不同，渲染进程 PID 相同。子窗口显示了已保存的笔记，可单独置顶，
能在自己的文档里编辑和打开菜单。主窗口关闭或重载后，独立窗口保留了修改后的笔记和置顶状态。
共享渲染进程被强制结束时，独立窗口重新打开了已保存的笔记。关闭再打开子窗口会再次复用来源进程。
关闭实验功能会关闭子窗口。来源工作区已加载时，五次打开从主进程收到请求到原生子窗口显示耗时 60–63 毫秒。
[编辑器测试](../../../../packages/components/tests/today-editor.test.ts)覆盖所属文档的选区处理。
系统输入法、macOS 和 Windows 的窗口行为仍需在对应平台验收。
