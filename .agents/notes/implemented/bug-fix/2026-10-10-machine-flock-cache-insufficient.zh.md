# 区分 Machine Flock 缓存不足与无效输入

Status: implemented
Translation: current
PR: [#1413](https://github.com/LodyAI/Lody/pull/1413)

[English](2026-10-10-machine-flock-cache-insufficient.md)

## 摘要

Machine Flock 尽力读取可以使用已有本地副本，但数据缺失不能证明当前显式指定的项目、Provider 或 ACP 选择无效。这类显式缺失携带新鲜度失败原因，以 `SYNC_UNAVAILABLE` 返回，同时保留有类型的重试语义与现有授权检查。继承设置则保持基线行为：保留兼容值、丢弃不兼容值，并在新鲜度未确认时记录警告。已接受配置在恢复时保留继承来源及目标模型上下文，避免重新校验把默认偏好变成新的显式请求，或让已接受任务陷入重试。仅补默认值的调用仍可使用，不可变的已写入 Turn 及公开输入边界保持受保护。

## 决策

[PR #487](https://github.com/LodyAI/Lody/pull/487) 在新鲜度同步失败后保留本地数据。本补充区分不确定性与当前输入无效，同时保持基线继承策略：

- 正常校验当前显式选择和访问权限。新鲜度失败后缺少所请求的条目或值，返回有类型的目录不可用错误。歧义、选项类型错误、Plan 冲突及授权失败保持原有拒绝路径。
- 继承的 mode/model/options 是偏好，不是新的显式请求。依据可读能力进行过滤，保留兼容值；未确认读取丢弃不兼容选择时记录警告。没有缓存本身不会阻断仅使用默认值的创建或聊天。
- effort/Fast 的过滤和验证使用最终目标模型。当前标量、raw 或语义模型选择优先；否则兼容的继承模型仅提供验证上下文，不变成显式选择。当前选项 map 整体替换继承 map；标量覆盖时删除被遮蔽的继承分类选项。模型相关校验不会跳过 raw 值的类型错误，自定义 Fast select 值仍走普通目录校验。
- 仅把已接受且实际有效的继承字段冻结到内部 `inheritedDispatchConfig`。重放过滤该快照，不重新读取可变历史。显式覆盖不能因为恰好等于历史值就获得继承来源。旧 `inheritedBuiltinDefaultModeId` 仍可读取，但不再生成。
- `builtinDefaultModeId` 独立标记合成的内置默认值。固定 Turn 写入前，根据能力重新推导或省略默认值。写入中断后，仅保留冻结来源能够产生的已写入标量值或选项子集（包括缺省）；过滤前使用匹配的已写入继承模型作为显式 effort 的验证上下文，完整身份校验仍拒绝其他变化。来源字段不进入公开 MCP 输入或会话历史。
- 仅 `syncMachineFlockDocsForRead` 要求严格远端确认。启用云同步的管理器需要 Streams 已附着、代次未变且报告成功；已完成的无路由或部分成功报告不能证明新鲜度。普通同步调用保留尽力而为的报告语义。路由缺失使用应用层不可用错误，不伪装成 Repo conflict。
- 穿透 cause、聚合错误和多传输报告，保留公开 Repo 错误的重试语义。明确的 `false` 优先，未知原因保持不可重试。已有 Flock 超时使用有类型原因，其他超时调用不变。
- 可重试的显式目录不确定性在接受任何 Operation 前中止批量预校验。永久或未知失败仅影响对应项，有效兄弟项继续。公开错误仅包含有长度限制的请求 id 和批量索引/标签，不输出选项值、缓存记录或传输诊断。
- 临时目录错误与 MCP 指引要求相同请求重试间隔至少五秒、总共最多三次调用，然后停止并报告。沿用同一 Operation id；收到 active handle 表示由 daemon 恢复，不是再次代理重试。该规则是指引，不是强制计数器。daemon 物化保留原有 1–30 秒退避和原始截止时间（默认 24 小时，最多可配置七天）。

没有把可重试预校验失败存成终态项，因为相同 id 重试会返回已记录失败，而不会验证新到的数据。没有统一设为可重试，因为存储、CRDT 和授权故障可能是永久问题。也没有把全部继承字段冻结为显式选择，否则缓存变化会卡住原本可通过丢弃过期偏好继续执行的任务。本修正不新增刷新调度器、授权策略或 daemon 重试预算。

## 评审修正与基线区分

早期的能力缓存断言错误阻断了仅补默认值的调用；后来的继承选择断言又把 main 的过滤/丢弃行为改成失败，甚至发生在聊天已接受之后。两者均已修正。严格报告确认仅用于目录校验，不再影响所有 Flock 调用方。默认值重放现在区分合成值与继承设置，并在物化中断后保留已写入身份。

与 main 的源码比较还发现两个本 PR 之前就存在的相邻目标模型问题：创建时过滤继承选项没有传入所选模型；仅由历史提供目标模型时，语义 effort 可能使用探测模型。现在首次校验和冻结重放都传入最终模型上下文，不放宽显式校验。能力 `cacheVersion` 仍是刷新提示，不是可读性门槛；运行时来源适用性独立判断。

rebase 保留 main 的持久协作停止屏障、因果深度指引和 CLI Role 优先级。只有当前目标授权通过后，才使用匹配的已写入模型上下文；不放宽当前显式控制不可用或不支持时的拒绝。已评估并推迟原生 Effect 迁移：本修正是已有 Promise 边界的纯选择/错误逻辑，而 Session/Loro 资源所有权依赖尚未完成。已阅读锁定的 Effect 4.0.2 参考和仓库当前迁移准则。

## 证据与验证边界

行为测试覆盖跨版本 ACP 缓存、显式临时/永久/未知故障、继承模型缺失、无缓存、非默认模式、兼容值，以及 model-a 探测快照下 model-b 的 `xhigh`；还覆盖真实非 Role MCP 混合批量、已接受聊天经过 SQLite 和协调器进入终态、来源快照恢复、默认值双向变化时的中断重放，以及身份冲突时历史不变。真实 Repo 与 Streams 适配器通过合成 HTTP 503 生成 `server_error`，经过 ACP 解析到达 MCP 输出。管理器测试区分共享传输尝试的严格与普通调用。测试使用合成数据，不访问外网，不使用真实等待。

本修订已 rebase 到 main 的 `loro-repo` 0.22.0。离线源码边界检查、非类型感知 lint、格式、空白和文档检查均通过。依赖注册表下载不完整，本地行为套件、类型检查及类型感知 lint 仍受阻；当前提交的验证依据为普通 PR CI，不声称本地通过。独立真实 Repo 0.22.0 探测确认了无路由及 HTTP 503 错误合同。前一修订的 355 项测试结果不代表当前修订结果。此前广泛套件的失败已独立在基线上复现，本记录不声称整个仓库通过。参见[实现流程](../../../docs/cli-overview.md#machine-catalog-freshness-during-session-creation)及[缓存兼容性决策](2026-09-08-acp-capability-cache-compatibility.zh.md)。
