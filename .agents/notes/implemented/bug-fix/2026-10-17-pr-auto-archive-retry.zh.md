# PR 自动归档失败后保留已观察到的待办

Status: implemented
Translation: current
PR: [#1666](https://github.com/LodyAI/Lody/pull/1666)

[English](2026-10-17-pr-auto-archive-retry.md)

## 摘要

PR 自动归档失败时，已观察到的状态变化此前会被消耗，后续元数据更新无法完成归档。
所属窗口现在保留未完成意图，并以有上限的退避间隔重试现有归档动作。
记录已接受目标的写入回执后，即使原生 Repo 观察者只提供最终恢复状态，重试也能区分
部分归档和用户主动恢复的会话树。待办仍只存在于当前设备内存中；启动和恢复不创建
新的归档意图，本地开源桌面的能力边界保持不变。

## 决策与替代方案

[#1660](https://github.com/LodyAI/Lody/issues/1660) 影响启用 GitHub 集成的共享前端
观察器。公开的本地桌面不提供此能力；没有证据证明打包桌面发生过该故障。
维持实现会保留失败后无法兑现状态变化的缺口；删除观察器会撤销已有偏好功能；
回退上一份 PR 快照则混淆观察与未完成执行，仍缺少重试触发。
因此观察器继续维护观察基线，另行保存局部待办，复用 `archiveSession` 的目标发现、
写入接受和清理能力。

```text
观察到活跃会话的 PR 状态变化 -> 待办意图 -> archiveSession
  失败 -> 一个重试计时器 -> 权威目标快照 -> 再次尝试
  成功 / 意图失效 -> 清除待办
```

现有[归档关系契约](../../../../specs/session-relations.zh.md)已经允许部分完成，以及
对已归档根会话重试。[保留边界决策](2026-10-01-archive-worktree-retention-contract.zh.md)
保持不变。仅自动归档传入的 `shouldContinue` 检查与调用方持有的 `accepted` 集合，复用动作原有的权威
目标快照和成功写入边界。任何已接受目标被恢复或移出目标集时，意图在取消暂存发送和
写入归档之前退休。手动归档保留未落盘会话的取消逻辑，不增加门槛。
原生 `WorkspaceRepoLegacy.watch` 可能将归档、恢复两条事件都重新读取为最终未归档行，
因此不能只靠界面元数据推断已接受的中间状态。

现有 PR 基线本身提供启动保护，待办身份也已经界定完成和卸载边界，因此无需额外的
初始化、失败与活跃标志。归档动作仅随运行时和 store 改变，重试直接捕获该动作即可。

## 所有权与失败隔离

触发条件是当前用户拥有的会话，其 PR 被实际观察到进入已启用的终态。
窗口为每个会话持有一个待办意图，最多执行一个归档动作。失败后等待 1 秒，间隔逐次
翻倍，最多 30 秒；无关元数据更新不会绕过退避。持续失败仍可重试，不阻止其它会话
或手动动作。

运行时、用户、会话所有者、PR 身份或状态、适用设置、可见性变化使旧待办失效。
失去所属窗口身份或卸载时清除计时器与订阅，迟到回调不能复活已退休的意图。
已经开始的写入仍遵守原有捕获运行时及目标集的语义；取消等待者不等于停止已接受写入。
恢复所有权不超出组件生命周期，不添加持久队列、就绪等待或固定尝试次数。
后台失败有明确接收方，诊断输出自身失败不会形成未处理的 Promise 拒绝。

已按 feature/fix 模式评估 Effect 4.0.2 原生迁移。现有归档动作仍编排 Promise 形式的
暂存发送及已登记的 Repo Legacy 接口；包装这条未完成的依赖链不能完成原生所有权
单元，因此延后迁移，不改变路线图中的迁移事实。

## 验证与局限

所属 `use-session-actions` 套件挂载真实观察器，使用真实归档、恢复动作、目标选择器
和暂存发送所有者，验证合并/关闭后的恢复、后代部分失败、手动恢复根会话/Tab、
持续失败隔离、退避上限、执行去重、失效边界以及启动/恢复基线。
真实原生 Repo 用例验证归档/恢复事件合并后，权威快照仍能取消重试；恢复后的新暂存
发送仍可以完成落盘。移除已接受 ID 记录后，该原生用例会再次归档已恢复根会话，
证明进度边界有实际必要性。恢复基线版本的观察器后，合并和关闭恢复用例都会失败。
夹具与故障注入均为合成数据；未进行托管写入、真实 PR 变更，
也不声称完成打包桌面的故障复现。
