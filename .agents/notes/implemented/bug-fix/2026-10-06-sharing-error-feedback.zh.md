# 按操作说明分享失败原因

Status: implemented
Translation: current

[English](2026-10-06-sharing-error-feedback.md)

## 摘要

分享操作此前几乎把所有失败都替换为同一句检查设置的提示，包括剪贴板拒绝。
现在界面将已知错误映射为本地化恢复建议，原因未知时仍说明失败操作。
发布、重置和撤销响应丢失时明确表示结果尚未确认。重试身份和凭据处理保持不变。

## 决策与依据

操作执行器用局部变量保存操作阶段，独立于 React 进度状态；发布的 `finally`
会先重置进度，再进入外层错误处理。只有已知结构化错误码和准确的本地错误
参与文案映射，不显示任意服务端载荷。图片读取增加失败上下文，保留取消原因。
配额错误未指明是哪一类上限，文案列出可能的限制及数值，不虚构具体原因。
内容和数量提示从公共 `SHARE_LIMITS` 插值，限制调整时文案随之更新。
通用对象大小错误列出适用上限，因为编码器没有说明是哪种对象。
没有结构化原因的 HTTP 错误按操作提示，不猜测是否鉴权失败。

本改动延续[分享实现说明](../feature/2026-09-09-session-sharing.zh.md)和
[分享规格](../../../../specs/session-sharing.zh.md)，不改变发布权限、重试状态或存储契约。

## 验证

Hook 测试覆盖准入、抓取、上传、提交结果不确定、剪贴板及链接管理失败，
以及安全文案和重试恢复。发布器测试覆盖图片读取失败和源资源释放。
实际执行结果及环境限制见任务结果；未复现生产环境故障。

## 图片策略细化

新建及更新分享最多包含 64 张图片，单张最多 20,000,000 字节（20 MB）。
抓取、源图片读取和发布鉴权共用此策略。读取器保留原有的 512 个附件及
单对象 100 MiB 格式边界，避免收紧发布限制后使已有链接失效；对话历史
继续保留独立的 32 MiB 上限。测试覆盖精确数量和字节边界、旧分享读取、
发布拒绝；流式读取超限保留大小超限原因。
