# 让复制的 Agent 错误保持明确的文本格式

Status: implemented
Translation: current

[English](2026-09-29-error-report-clipboard-text.md)

## 摘要

复制的 Agent 错误可能变成经过百分号编码的 `error:` URL。报告构建器和剪贴板辅助函数
原本就传递纯文本，但开头的 `Error:` 标签符合自定义 URL 协议语法。构建器现在使用
`Error details:`，使接收方无法将整份报告解析成绝对 URL。诊断字段和消息内容保留；
具体触发转换的原生环节仍未验证。

## 决策与证据

本修复延续[错误横幅的复制操作](../simplification/2026-09-23-agent-notice-banner-full-width.zh.md)。
`new URL('Error: 启动失败')` 可以解析并得到 `error:` 协议，而新报告无法通过 URL
解析。修改共享报告构建器覆盖横幅和旧对话框的调用，无需重写通用剪贴板辅助函数。
对任意剪贴板内容解码会破坏错误消息中合法编码的 URL，也无法阻止下游识别为链接。

## 验证

现有报告测试补充了新标签，以及包含中文、换行、URL 和字面百分号的合成报告。
直接运行 Node 断言验证了这些情况和仅有标题的错误，均通过。当前检出没有安装依赖，
因此无法运行 Vitest。原生剪贴板往返验证仍待完成。文档检查已运行，但报告了与本次
修改无关的仓库文档错误。
