# 归档与标签关闭正交

Status: implemented
Translation: current

[English](2026-09-24-archive-independent-of-tab-close.md)

## 摘要

此前所有已归档对话都被视为已关闭的标签，而重新打开已关闭的标签又会取消归档。
结果是从归档列表打开已归档的 Session 时显示空白草稿而不是对话本身，从已关闭列表
重新打开其主标签又会把它取消归档。现在标签可见性根据工作区的归档状态解读关闭标记：
已归档工作区显示归档时打开的标签，重新打开只清除 `isTabClosed`，恢复也从不写入关闭标记。
唯一保留的交集是有意为之：未归档工作区中的已归档子对话不进入标签栏，并以明确的
“恢复”操作提供。已归档工作区同时只用于回顾：恢复之前不显示草稿，也不提供新建对话操作。

## 决策与证据

[会话标签页共享关闭状态](../feature/2026-09-16-shared-tab-closure.zh.md) 为了让历史上
关闭即归档的子标签留在已关闭列表中，让 `isSessionTabClosed` 对所有已归档 Session
返回 true，并让 `reopenSessionTab` 调用 `restoreSession`。这两处都波及用户有意归档的
Session：已归档的根会话总是“已关闭”，路由因此回退到草稿；而回到该对话的唯一途径会将其取消归档。

`isSessionTabClosed(meta, workspaceArchived)` 现在是
`isTabClosed === true || (isArchived && !workspaceArchived)`。根会话自身就是工作区，
只看它的关闭标记。已归档根会话下的子会话（随之一起归档）重新作为标签显示，便于回顾。
`reopenSessionTab` 已删除；已关闭列表的操作只写 `isTabClosed: false`，
`restoreSession` 只写 `isArchived: false`。

历史上关闭即归档的子会话与有意归档的子会话无法区分，也不做猜测性迁移。未采用
“在未归档工作区中把已归档子会话显示为打开的只读标签”：这会让所有历史上关闭的子标签
重新出现在现有标签栏中。它们仍然隐藏，已关闭列表中对应行显示“恢复”而不是“重新打开”
（桌面弹出层和移动端标签面板均如此）。恢复先执行既有恢复检查，再清除该子会话的
关闭标记，使其回到标签栏。工具栏的“恢复会话”现在直接调用 `restoreSession`，
不再经过标签重新打开路径。

在构建出的桌面应用中逐条走查用户旅程时又发现两个问题。草稿 tab 的 id 会被记为上次激活的
tab，而旧的回退逻辑已经把 `empty` 入口物化成了草稿，所以受影响的 Session 从归档列表重新
打开时仍可能落到这个草稿上。在已归档工作区中从任何草稿发送消息，还会在已归档根会话
（其 worktree 可能已被回收）下创建一个活跃的子会话。因此已归档工作区隐藏草稿（仍保留存储），
去掉新建 tab 按钮、Alt+N 路径和移动端 New Chat 行，把草稿或 `empty` URL 解析为已打开的对话
并替换 URL，所有标签都关闭时显示主对话。未采用“归档时删除已存储草稿”：那会丢失恢复后
本可找回的输入。

根会话归档之前就已归档的子会话，在回顾该已归档根会话时仍会作为打开的标签出现；
数据无法区分这种情况。[Spec](../../../../specs/session-tab-closure.zh.md) 已更新，保持 draft。

[被挂起的 LODY-SESSION-004 断言](../testing/2026-09-18-session-004-provenance-assertion-suspended.zh.md)
等待的正是这一决定；现按原 registry 行（指纹 `44fb98c9…`）重新启用。`LODY-SESSION-002` 和
`-004` 在构建出的桌面应用上通过。一次未提交的桌面探索确认：未归档工作区中已归档的子会话
离开标签栏，并可通过“恢复”行恢复；从归档列表进入会显示对话记录、Archived 标记和禁用的输入框；
草稿、新建 tab 按钮和 Alt+N 均不可用；重新打开和关闭标签都保持归档；顶栏“恢复”保留标签；
所有标签都关闭的已归档工作区显示主对话。

标签栏测试渲染已归档工作区（打开的标签可见，已关闭标签提供“重新打开”）和未归档工作区
（已归档子会话提供“恢复”）。Tab URL 测试覆盖判定函数；会话 actions 测试基于元数据仓库
覆盖“重新打开不恢复”和“恢复不修改关闭标记”。组件类型检查通过。移动端标签面板测试
覆盖“恢复”标签和缺失的 New Chat 行。移动端未在真实应用中走查。
