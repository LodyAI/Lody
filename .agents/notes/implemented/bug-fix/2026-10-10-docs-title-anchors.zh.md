# 在保留单个 H1 的同时保留文档标题锚点

Status: implemented
Translation: current

[English](2026-10-10-docs-title-anchors.md)

## 摘要

文档模板已经渲染页面主标题，因此 MDX 组件映射会过滤正文 H1，但生成的目录仍链接到被移除的标题。
本地浏览器扫描发现 80 个文档页面缺失标题锚点。现在将已有的 H1 锚点赋给可见的页面主标题，
保留原链接，同时不恢复第二个 H1，也不修改内容标题。

## 决策与证据

`src/site-pages/docs.tsx` 读取目录中第一个 depth 为 1 的 URL，将解码后的片段作为
`DocsTitle` 的 ID。没有正文 H1 的页面继续不设置标题锚点，不能借用 H2 的 ID 导致重复。
复用生成的 slug 可避免 frontmatter 与正文标题不同带来的偏差，例如 Introduction 与 Lody。
主标题使用与 Fumadocs 正文标题一致的滚动边距。

仅删除目录中的标题项会继续破坏已有外部锚点链接；根据 frontmatter 重新生成 slug 也会改变目标。
本次修复保留[静态内容 Spec](../../../../specs/public-site-static-content.md)中既有的内容与导航意图。

## 验证

现有静态浏览器测试增加了所有文档页的单 H1 和本地锚点目标检查。
锚点测试覆盖中英文标题的直接访问和刷新，包括桌面、移动端，以及启用和禁用 JavaScript 的情况。
生产构建、TypeScript 检查、全部 56 项站点测试、258 项生产静态浏览器检查
（256 个发布页面，加链接目标及 404 检查）和全部 20 项锚点浏览器检查均通过。
仓库文档检查报告 82 个指向缺失 ACP 子模块文件的已有断链；两份新记录均没有链接或元数据错误。
提交前根目录格式化通过；`pnpm check` 因当前检出缺少 `packages/ignore` 的测试与类型依赖而中止，
其余根目录整体检查未完成。
