Status: implemented

## 摘要

预热窗口曾露出 Loading、暂时性的「会话不存在」或空白正文。现在领取时保存真实目标，等待
历史、布局及滚动恢复就绪后才显示；持久化引导保留未发送编辑。外壳与 Runtime 优化将
3,000 条历史的打开中位数从 1,139 ms 降到 431 ms。macOS 本地模式现在利用同一个可选备用窗口，
在点击前准备预测会话，领取时直接显示现有 renderer。未命中或提前点击仍需等待，
这不保证所有打开操作瞬间完成。

## 决策与证据

本次修正[窗口预热决策](../feature/2026-09-18-desktop-window-prewarming.zh.md)，
最终意图由[桌面窗口 Spec](../../../../specs/desktop-windows.zh.md) 维护。

`window-target.ts` 在导航前清除备用身份并保存真实恢复目标。准备期间暂时关闭后台节流，
让隐藏 renderer 能加载与绘制。主进程仅接受已领取 WebContents 发出的、匹配工作区与会话的
`app.windowContentReady`，随后恢复节流并显示、聚焦原生窗口。renderer 要求连续两帧出现
目标标记；对话标记须等待历史实际加载，不能只依据已知历史条目数。列表完成加载及初始滚动
恢复后另发可见信号；非空历史须同时具备两个信号。空会话仍需同步完成。
移除旧不透明遮罩：它把 Loading 变成空白窗口，并没有减少工作。主进程独立的五秒期限用于
导航或渲染失败时显示恢复界面，不冒充内容已就绪。关闭窗口取消待显示任务；窗口显示后才
创建替补，避免与目标准备争抢资源。

`RuntimeProvider` 在备用窗口仍处于中性路由时初始化隐式本地工作区，将 Repo 创建、本地元数据
同步和窗口间初始化提前到点击之前，不写入路由上下文，也不挂载会话。领取同一工作区时，
有效工作区标识不变，因此保留已就绪 Runtime 或正在进行的初始化。缺少本地身份时继续等待；
普通中性窗口和云端 Runtime 仍由路由触发初始化。备用窗口还提前加载工作区布局代码，但不挂载
布局。已加载组件直接渲染，避免已完成 Promise 经 React.lazy 仍产生首次挂起；同一次挂载固定
组件身份，防止重渲染丢失布局状态。目标历史加载与绘制仍在选择会话后进行。

`window-state.ts` 统一负责产品窗口注册与关闭清理。已领取窗口可以接替主窗口，且不会随原窗口
关闭而销毁。只有当前备用窗口拥有自身外壳就绪计时器，关闭旧的已领取窗口不能取消替补超时。

`doc-meta.ts` 区分初始化扫描与各会话的投影处理完毕。排队事件、最新完整读取及未解决或失败的
读取，只阻止自身会话的缺失判定。删除取消过期等待；Runtime 销毁阻止旧结果写回。否决全工作区
统一等待，避免无关失败让缺失会话永久 Loading。已存在会话不订阅等待状态变化，工作区外壳仍
使用初始化就绪状态。

`local-window-bootstrap.ts` 仅在本地模式通过按工作区隔离的 BroadcastChannel 交换 CRDT 元数据
与已持有的会话快照。元数据异步合并并经过 Repo/Flock 正常投影。每个 Runtime 在其生命周期内
持有独立命名的 Web Lock，枚举锁即可知道在线窗口，无需持久化成员列表或心跳；renderer 退出时
锁自动释放。会话先读磁盘，命中时不要求其他窗口重复导出。未命中时仅向枚举到的窗口请求；
没有窗口立即回退，所有已枚举窗口明确回复缺失后也立即回退。150 ms 期限仅处理枚举后退出或
停止响应的窗口。没有 Web Locks 时不请求窗口会话快照。消息上限 16 MiB；销毁时关闭通道并结束等待。

冷会话快照在 storage load 内与持久化编辑合并，先于 Repo 订阅。候选文档必须在交给 Repo 前
持久化：Repo 假定 storage 加载的版本已落盘，否则游标可能超前于文档。导入或保存失败保留原始
文档，回退到正常的实时合并。已持有文档始终原地合并，保留身份、编辑及订阅；历史读取器随后
初始化。否决先建读取器再导入，因为这会逐个重放历史事件。不额外创建 UI store、Mirror 或
守护进程连接，也不共享持久化存储和同步游标。云端与双模式 Runtime 不参与共享。

## macOS 目标准备

[预渲染视图提案](../../proposed/architecture/2026-09-23-prepared-session-surfaces.zh.md) 的第一阶段
已接入原有开发者预热选项，默认仍关闭。普通会话行悬停等待 40 ms；Command/Control 意图、
中键按下、键盘聚焦和会话菜单立即请求。在等待中的行上按修饰键，也立即提升准备优先级。
忽略触屏悬停，延迟请求重新核对虚拟化后的行身份。捕获阶段监听控件阻止冒泡的事件；
点击、失焦和可见性变化释放来源意图。

主进程用一个目标隐藏窗口替换中性备用窗口，30 秒过期；取消后保留八秒，容纳短暂离开和返回。
请求绑定来源，续期隔离旧取消信号。同来源、同工作区的意图变化复用现有 renderer，在导航前
替换绑定并撤销就绪；领取另一个目标时也可在同工作区复用。旧目标／代次的回复不能触发显示。
跨工作区或其他来源的新意图替换未领取视图；来源关闭、过期和 renderer 失败释放资源。领取后保留独立生命周期和五秒恢复期限，更新重载身份
而不重新导航。显示或未领取视图回收之后补充中性备用窗口。

renderer 的显式准备状态抑制已读回执、工作区所有权（通知、角标及后台 owner 工作）、导航自动
聚焦及外部历史刷新，同时允许完整加载和布局。主进程只在显示之后发送激活信号。内容消失或视口
变化撤销就绪；实时同步继续，本地会话数据按[共享所有者决策](../architecture/2026-10-04-shared-desktop-session-owner.zh.md)管理。
原生动画扩展仍仅用于探针，因为没有建立独立收益。

## 验证与限制

十月单槽改进沿用现有可选开关和单 renderer 上限。意图／重定向测试覆盖代次隔离、旧取消、
过期、聚焦／修饰键提升及触屏／虚拟化行。
[十月评估](../../../../packages/components/benchmarks/window-bootstrap/README.md#single-slot-intent-and-retargeting--2026-10-04)
记录实际命中率、延迟、renderer 复用和内存。释放的会话 store 仍遵循十分钟缓存策略；
一个 renderer 并不等于严格的字节预算。

M4 Max、3,000 条历史的 fixture 中，普通悬停提前 350 ms，准备命中从 0/5 提升到 5/5，
显示／输入确认中位数从 101.41/188.74 降到 24.76/97.07 ms。Command 意图提前 300 ms，
同样从 0/5 到 5/5，从 102.24/187.84 降到 33.26/96.49 ms。含预热轮次的 72 次首次显示／
输入检查全部通过。零提前量仍需 338.73/402.29 ms；已有准备窗口零提前量换目标为
218.24/274.63 ms，旧目标没有被误算为新目标的准备命中。最终八阶段内存测试中，一个准备
视图增加 224.74 MiB footprint；关闭五个附属窗口后 30 秒内回到距仅主窗口 6.61 MiB 的水平。
两轮 OS 采样失败被排除并保留记录，最终探针改为直接读取内核计数器。这些是小样本串行合成
测试，不代表总体命中率、P95 保证或长期不同会话文档的内存预算。

当前针对性回归套件通过 53 项测试，Electron 通过 199 项。components／Electron 类型检查、
生产构建、lint、i18n 和公开仓库／平台／导入边界检查通过。文档检查仍有 6 处既有链接指向
缺失的独立 Kimi/Pi 子模块，没有新增文档链接错误。

此前九月的 macOS 产品路径通过 39 项相关组件测试及 168 项 Electron 测试；components／Electron 类型检查
和 OSS 应用构建通过。真实会话行 Command-click 探针中，已准备命中的显示／输入确认中位数为
32.50／82.46 ms（十次），零提前量为 451.13／492.84 ms（五次），提前 200 ms 为
346.94／421.82 ms（五次）。最终 29 次检查（含预热）均确认隐藏期间未改变已读状态，显示时
正文可见且可插入唯一文字。命中前仍有中位数 404.42 ms 的准备。此前一轮在请求原生 show 后
超时，未记录停在哪个截图／输入阶段，原因仍未确定；增加阶段日志后完整复测通过。
