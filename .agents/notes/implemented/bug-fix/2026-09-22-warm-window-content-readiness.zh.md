Status: implemented

## 摘要

预热窗口领取后可能提前露出 Loading 或暂时性的「会话不存在」，仍被当作可销毁的备用窗口，
并在崩溃恢复时回到空白预热路由。现在领取时先清除备用身份、保存真实重载目标，再发出导航。
揭开遮罩要求匹配目标的界面就绪；判定缺失只等待该会话自身的元数据投影。
保留五秒恢复兜底。本地模式窗口复用其他窗口的元数据与已加载会话快照，
已有可读历史无需等待权威同步完成。

## 决策与证据

本次修正[窗口预热决策](../feature/2026-09-18-desktop-window-prewarming.zh.md)
之后的身份转换与揭开实现，结果见[桌面窗口 Spec](../../../../specs/desktop-windows.zh.md)。
原来的 `innerText` 检查会接受 Loading、侧栏文字和会话缺失提示。现在要求连续两帧存在
匹配会话或工作区的标记。可见对话在文档已有可读历史或空会话完成同步后发出标记；确认缺失也是合法终态。
工作区首页挂载时发出标记。五秒后仍允许访问恢复界面，导航失败也不例外。

`window-target.ts` 在发送导航事件前完成领取：清除主进程的预热标记，并复用冷启动窗口的
路径构造器更新恢复地址。`window-state.ts` 统一负责注册与关闭清理，已领取窗口可接替主窗口，
不会随前一个主窗口关闭而被销毁。只有当前备用窗口的关闭回调能清除自身就绪计时器；
已领取窗口关闭不能取消替补窗口的超时。

`doc-meta.ts` 区分初始化扫描完成与每个会话的投影处理完毕。排队事件、最新的完整元数据读取，
以及尚未解决或失败的读取，只阻止相应会话的缺失判定。后续事件可重试；删除清除未解决记录，
并停止等待已经过时的读取。Runtime 销毁时清除等待标记，旧读取完成不能修改新状态。
否决全工作区统一等待：无关文档读取失败或返回空元数据，可能让缺失会话永久 Loading。
已存在的会话不订阅等待状态变化，工作区外壳仍使用初始化就绪状态。

`local-window-bootstrap.ts` 仅在本地模式使用按工作区隔离的 BroadcastChannel。
Runtime 提供 CRDT 元数据及自身已经持有的会话文档；请求不创建 store、Mirror 或额外的
守护进程订阅。元数据异步合并并经过 Repo 的正常 Flock 投影；150 ms 响应窗口允许多个
窗口贡献元数据，不阻塞 Runtime 创建。会话读取让窗口快照与已有 eager-sync 磁盘缓存
竞争，缓存未命中不能抢先丢弃有效数据。快照上限为 16 MiB。导入合并已有副本，保留未发送
编辑；持久化存储和 Streams 游标仍按 renderer 独立。Runtime 销毁时关闭通道并结束等待。
对方窗口不可用、快照缺失、过大或损坏时，正常同步继续。

中性外壳仍占用一个 renderer；本次不保证瞬间打开，也不共享 React store、提前初始化
目标 Runtime 或消除布局与历史投影开销。云端和双模式 Runtime 不参与窗口快照共享。
空会话仍等待同步后再揭开遮罩。

## 验证与限制

确定性测试覆盖原窗口与已领取窗口关闭、恢复地址、替补窗口超时、排队及延迟元数据、
读取中删除目标、无关文档读取失败或缺失、Runtime 切换、匹配目标、连续帧及恢复期限。
窗口快照测试另外验证元数据投影、历史复用、未发送编辑合并、工作区隔离、关闭与缺失兜底，
以及慢磁盘缓存竞争。七个定向测试套件共 37 项通过，components 与 Electron 主进程／renderer 类型检查通过。
修改源码的 lint 无错误，Runtime 与对话组件有既有警告。尚未完成真实 Electron 视觉验收，
E2E 仍禁用预热池。本工作树复用本机已有依赖；`pnpm check` 在 `packages/ignore`
依赖缺失处停止；`check:public-boundary` 无法解析未初始化的 ACP 子模块。`docs check` 报告 34 条指向缺失 ACP 子模块的既有链接错误，修改文档不在其中。
