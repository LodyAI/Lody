# Better Auth 1.6 maintenance baseline

Status: implemented
Translation: current

[中文](2026-09-30-better-auth-1-6.zh.md)

## Abstract

The shared authentication packages were pinned to Better Auth 1.5.5. Upgrade the
core, API-key and Electron packages together to 1.6.33, with Convex integration
0.12.5, to adopt the maintained 1.6 fixes while respecting the adapter's supported
range. Preserve both existing runtime patches. Real-account OAuth and packaged
native-client login still require deployment validation.

## Decision and evidence

The npm `release-1.6` tag resolves to 1.6.33, released September 14, 2026.
Although `latest` is 1.7.6, Convex integration 0.12.5 declares
`better-auth >=1.6.11 <1.7.0`; choosing 1.7 would violate that contract.
See the [Convex migration guide](https://labs.convex.dev/better-auth/migrations/migrate-to-0-12)
and [1.6.33 release](https://github.com/better-auth/better-auth/releases/tag/v1.6.33).

Both workspace catalogs and lockfiles must agree. Root devDependencies pin
`@better-auth/utils` to 0.4.2, matching Better Auth 1.6.33: unconstrained peer
auto-install otherwise selects 0.5.0 and creates distinct core plugin types. API-key request handlers still
start expiry cleanup, so retain the patch removing request-time sweeps while
leaving the explicit cleanup endpoint intact. The Electron server entry still
imports Node buffer/crypto; retain the Web Crypto constant-time comparison patch.
Port only those changes, preserving upstream single-use token consumption and
mandatory S256 verification.

This complements the [desktop login coordinator](../architecture/2026-09-17-desktop-login-coordinator.md):
application-owned state/verifier and cookie hooks remain the same. No new login
coordination layer or persisted credential format is introduced. The shared client
factory preserves a concrete plugin tuple through a const generic; a widened
`BetterAuthClientPlugin[]` erases session and organization inference in 1.6. The
singleton exposes the fixed base-plugin contract, with a local assertion because
TypeScript cannot reduce Better Auth's conditional types inside the generic body.

## Validation scope

Both lockfiles pass frozen validation; patches apply and the adapter schema was
regenerated without changing the effective table shape. Repository-wide typecheck
and lint, 595 backend tests, 60 frontend auth tests, public-boundary and docs checks
passed. Workspace, Web and CLI production builds passed with a 12 GiB Node heap.
The composed build stopped at Electron packaging because the local environment
lacks `VITE_ELECTRON_UPDATE_URL`; Electron typechecks passed. A deployed OAuth
callback and packaged desktop/mobile sign-in remain unverified.

Three Git remote fixture failures were caused by session-injected URL rewrites.
With ordinary Git and no injected Git configuration, all three pass.

## Rollout

Keep the 1.5.5 patch files alongside 1.6.33 until the consuming workspace has
advanced its catalog. Merge the public upgrade first, then land the separate
consumer gitlink promotion, then merge its dependency upgrade. Removing the old
patches earlier breaks installation in the intermediate promotion.
