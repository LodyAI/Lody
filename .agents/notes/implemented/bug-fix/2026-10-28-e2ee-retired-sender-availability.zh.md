# E2EE 退役 sender 的可用性

Status: implemented
Translation: current

[English](2026-10-28-e2ee-retired-sender-availability.md)

## 摘要

合法的当前 epoch 邮箱信封可能在发送者退出成员身份后仍被返回。此前拒绝该密钥会中止 Owner
的收钥页，并挡住独立的发钥，导致新接纳的接收者没有当前密钥。现在收钥与发钥分别报告结果和
重试游标。获取阶段跳过退役及未知 sender，不安装其密钥；只有已验证退役身份允许按摘要修复，
未知身份则请求账本刷新并保留重试机会。

## 决策与边界

本修复扩展[收发钥可用性](2026-10-27-e2ee-key-maintenance-availability.zh.md)，保留仅确定无效
才拒绝摘要的约束。真正的 `VerifiedLedger` 视图在完整重放、本机保留状态和合格快照中都保留
所有已接纳设备的历史身份。历史中存在、当前设备或成员中已不存在的密钥属于退役身份，账本策略
禁止复用它。只有严格验签把信封绑定到精确的工作区、epoch、sender 和 recipient 后，才把该摘要
交给修复。服务端 sender 提示或服务端名单中的缺失都不能证明退役；路由不符仍只跳过，不拒绝。
未知公钥不会被标为退役，也不会安装密钥或保存安装任务。

`fetchAndInstall` 继续处理后续行，返回游标、有界退役诊断和刷新请求。原生轮次通过现有持久
日志排队确定性修复。桌面维护在独立发钥之后，最多请求一次已验证历史刷新，再重试原始邮箱字节。
刷新不可用不能授权安装未知密钥或拒绝它的摘要。

现有工作区 owner 串行执行有限轮次。收钥（含暂存前置步骤）、发钥与最后的报告刷新，在
`WorkspaceKeyRoundFailure` 中保留独立 Result；调用者可以观察并确认成功的一侧，使用返回
游标重试。失败阶段保留输入游标。桌面密码学修复仍检查原始 `MailboxInstallError` 诊断，普通
阶段失败不能授权拒绝。普通类型化失败被隔离；缺陷和中断继续向上传递。现有关闭排空、原生
操作结算、精确原文和存储归属保持原边界，没有新增重试定时器、写入者或资源保留期。
这些模块已采用原生 Effect v4，不改变迁移单元。

继续以收钥为前置条件会保留已复现故障。接受退役 sender 密钥、清空邮箱或拒绝未知身份都会
削弱权限或恢复能力。仅过滤后端无法保护客户端免受保留信封或恶意响应影响，因此客户端独立成立。

## 证据与限制

真实密码学与 SQLite 回归先复现了非当前 sender 阻塞整页、收钥错误阻止发钥。修复后还覆盖
未知 sender 在已验证接纳后的重试、独立发钥结果与游标保留、严格签名与 HPKE 拒绝、本地安装
失败以及原文字节保留。本地全栈证据和精确检查结果记录在 PR 中。

脚本，保留所有既有断言；它不是公开产品源码。
