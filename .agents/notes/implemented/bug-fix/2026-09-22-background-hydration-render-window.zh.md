# 后台加载不改变会话的渲染成员

Status: implemented
Translation: current
PR: https://github.com/LodyAI/Lody/pull/888

[English](2026-09-22-background-hydration-render-window.md)

## 摘要

后台事实扫描与聊天列表共用消息缓存。列表渲染所有已缓存正文，使屏幕外的单个
占位行变成多行，推移可见尾部的数字索引，导致 Virtua 暂时隐藏尚未测量的行。
现在只有阅读窗口、保留的尾部和原生文本选择决定哪些消息渲染正文，其余已加载
消息仍显示为占位行。在受控合成浏览器复现中，显示后的隐藏行采样从五次降至零次，
且全部事实计算完成。已安装桌面的根因归属与验收仍未验证。

## 决策

[窗口化读取集成](../architecture/2026-09-10-windowed-reader-integration.zh.md)
保留一个共享正文缓存和独立消费者。缓存命中不代表渲染所有权：
`useConversationStreamItems` 向 `buildChatStreamItems` 提供正文渲染条件。
事实派生、搜索索引、复制和大纲预览维持原有数据访问；即使前一条用户消息的正文
不在渲染窗口内，已加载的配置仍供 assistant 继承。

首个视口报告缩小阅读窗口时，最初的 40 条尾部消息继续持有租约，否则后台淘汰
可能在显示后把已有尾部行折回占位行。阅读较早历史时，阅读窗口之外也会保留这段
有界尾部，而不只依赖底层默认的 20 条保留量。原生选择在滚动改变窗口之前，将
保留的消息 ID 通知列表；已有租约和布局快照继续保留选中 DOM。清除选择后撤销
渲染例外。投影包装仍以相同的底层来源作为状态边界。

修改首次显示门槛或等待全部事实扫描，只会延迟显示，无法隔离这些职责。
调整 Virtua 的 `shift` 也无法把任意占位行展开映射到稳定消息键。本次均未采用。

## 证据与验证

独立浏览器复现使用生产的 reader-backed view、派生器、列表 hook、滚动 hook
和 Virtua 0.49.1。240 条消息来自合成 reader port，采用简化的不等高行，未挂载
完整会话渲染器。页面显示后，通过显式信号放行后台批次，没有人为延迟
ResizeObserver，也没有 CPU 降速。修复前，五个批次分别让相交的七行全部隐藏
一个采样帧，约 16ms；录像也捕捉到内容区域空白。修复后，全部 240 条事实完成，
显示后的隐藏行采样为零。较快的默认调度在首次显示前完成扫描，没有复现显示后
闪烁。这证明了一条充分触发机制，不代表其生产发生频率。

捕捉器的面板可见性不代表每行可见：Virtua 隐藏行仍有可测量矩形；锚点分类器
也会忽略伴随滚动位移的变化。不能只凭几何信息就断言屏幕实际绘制了重叠内容。

所属 hook 回归测试在原实现上因后台批次将占位行提升为正文而失败。修复后的
相关套件覆盖加载和淘汰、首次视口报告、阅读窗口移动、来源及投影替换、选中 DOM
保留与释放、配置继承和现有滚动行为，共 65 项通过。
`ConversationViewStream.OpenWithBackgroundFacts` 为完整列表提供显式批次控制，
仍需在依赖完整的环境中执行浏览器验证。局部 lint 无错误。组件完整类型检查被
此 checkout 缺失的工作区或依赖声明及其他基线错误阻挡；文档检查仍有原有的子模块
缺失链接。未宣称完成桌面验收，也未收录用户会话捕捉内容。
