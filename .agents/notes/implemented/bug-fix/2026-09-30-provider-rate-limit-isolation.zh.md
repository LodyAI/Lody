# 提供商级限额快照隔离

Status: implemented
Translation: current

[English](2026-09-30-provider-rate-limit-isolation.md)

## 摘要

同一机器上的多个 Codex 提供商曾显示同一份配额，因为限额链路只识别代理类型和限额
层级。现在，限额事件、Machine Flock 数据行和 UI 选择都保留所属提供商配置 ID。
旧的无归属数据只供没有提供商绑定的旧会话读取；混合版本运行时宁可暂时缺少数据，
也不把一个账户的配额错误归给另一个账户。

## 问题与归属

账户配置功能隔离了凭据、Codex 目录和启动过程，但沿用了原有 Machine Flock 键
`rateLimit / cliType / limitId`。所有内置 Codex 提供商的 `agentType` 都是 `codex`，
因此最后到达的更新会覆盖同一数据行。设置页和输入区随后按代理类型读取该行，并将其
显示在每个 Codex 账户旁边。

本产品界面的持久身份是宿主提供商配置。上游可选的 `scope.accountId` 仍按原样保留，
但不能替代宿主绑定：并非每份快照都包含它，而且启动会话所用的目录身份也不是它。

## 决策

会话限额回调把冻结的 `agentConfigId` 传到守护进程写入边界。新的 Machine Flock 行
使用 `['rateLimit', agentConfigId, cliType, limitId]`，渲染器使用的扁平键也保留配置
ID。提供商列表、新会话输入区和已有绑定会话都只读取完全匹配的配置。删除提供商或
取消已发布的提供商时，只删除该提供商自己的限额行。

读取方继续接受旧三段键。没有 `agentConfigId` 的旧会话可以读取旧行，但已有绑定的
提供商绝不回退至该数据。旧客户端忽略新增的四段键；新客户端连接旧守护进程时，可能
暂时不显示绑定提供商的配额，而不会显示另一账户的配额。键中不含凭据、上游账户 ID
或秘密。

## 验证与限制

共享包测试覆盖隔离键往返、旧键解析、两个独立提供商快照及删除清理。组件测试用不同
配额渲染两个 Codex 提供商行，并证明旧共享值不会出现在任一行。Shared、Components
和 CLI 类型检查以及目标行为测试均通过。本次修复不会猜测此前旧数据的账户归属；新
版本运行时，绑定提供商界面不再读取这些数据。

现行行为见 [Codex 账户配置](../../../../specs/codex-account-profiles.zh.md)。
