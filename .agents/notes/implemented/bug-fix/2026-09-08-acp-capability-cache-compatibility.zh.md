# 跨缓存版本保留 ACP 能力信息

Status: implemented
Translation: current

[English](2026-09-08-acp-capability-cache-compatibility.md)

## 摘要

较新的渲染进程因为缓存版本不一致，丢弃了来自较旧本地 daemon 的一次成功 GPT-6 能力探测，随后
静默地展示了静态模型列表。现在能力的可读性与刷新的新鲜度相互独立：已解析的条目继续提供可理解
的数据，而版本或来源检查仍可安排一次替换探测。运行时 override 的来源匹配保持严格，结构非法的
数据仍由既有解析边界拒绝。

## 决策

- `cacheVersion` 仍是精确匹配的新鲜度信号，使启动与显式刷新路径能把旧条目收敛到当前表示。
- UI 选择器、可用命令与运行时探测权威都消费任何成功解析的条目，包括缓存版本缺失、更旧或更新
  的条目。
- 版本专属的读取器会适配已知的不兼容字段，而不是拒绝整个条目。v7 读取器会省略 v7 之前的
  非 Codex reasoning map（其方括号后缀可能描述的是上下文窗口而非 effort），同时保留该条目的
  模型与其他能力。
- 运行时 override 的匹配仍是独立于缓存新鲜度的适用性闸门。
- 更新静态模型表被否决为修复方案，因为那只会为当前已知模型掩盖同一个失败，并让其余所有被探测
  的能力继续暴露在版本偏移之下。

## 证据与限制

本地日志显示 Codex adapter 返回了 GPT-6 并成功同步 Machine Flock 行；存储的 config 作用域行
携带缓存版本 6，而渲染进程期望版本 7。单元测试把可读性与新鲜度分开，并覆盖缺失、更旧与更新的
版本标记。这并不会让未知的未来字段变得可读：条目仍必须通过客户端的 wire 或存储 schema。参见
[兼容性契约草案](../../../../specs/acp-capability-cache-compatibility.md)。
