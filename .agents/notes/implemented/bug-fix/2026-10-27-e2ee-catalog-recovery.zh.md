# 仅从已认证在线列表重建损坏的加密发现缓存

Status: implemented
Translation: current

[English](2026-10-27-e2ee-catalog-recovery.md)

## 摘要

加密 catalog sidecar 损坏后，即使在线列表读取成功，所有加密工作区仍持续无法离线发现。现在接收完整已认证在线列表的 owner 可以归档坏文件并按当前列表重建缓存。原有绑定账号/机器的失效标记一直保留到两部分缓存成功写入。离线读取、普通修改、本地初始化和权限错误均不能授权此恢复，原始字节保留供对账。

## 决策与故障隔离

catalog 只是发现元数据，不是账本或密钥权威。不改变账本、密文、credential 格式或验签。沿用[未知模式决策](2026-10-27-e2ee-cli-review-fixes.zh.md)及[故障隔离规则](../../../docs/failure-containment.md)。

RemoteBridge 接收 Fleet 的完整已认证在线列表，在缓存时明确标记此来源；本地初始化调用方不提供该标记。在原有 native FileLocks 修改范围内，先发布失效标记，再将损坏的 `.e2ee` 文件改名归档为唯一的 `.corrupt-<uuid>`，写入新加密部分和普通部分，最后清除失效标记。恢复成功后才清除内存里旧的损坏错误。失效标记无法读取或权限错误，不会被当作可恢复的 sidecar 损坏。

归档或发布失败时，通过原有降级结果保留普通在线缓存和当前授权/撤销流程。失效标记阻止离线加密启动接受陈旧或部分发布的数据；下次已认证在线列表负责重试。归档后进程停止时，缺失 sidecar 加失效标记仍会报告不可用。不删除归档。未知 mode 仍不缓存，账号/机器检查及旧客户端 sidecar 隔离均保留，不能从损坏字节重建旧访问授权或会话。

修改边界已是 native Effect v4，沿用不可中断的文件发布与共享锁，不新增生命周期 owner 或迁移依赖。Promise 读缓存编排的迁移不能帮助此次恢复，因此留待其他工作。

## 证据与限制

真实临时文件覆盖初始离线失败、原文保留、已认证重建、本地/普通调用拒绝恢复、归档和替换写入失败、失败后重试、账号/机器变化及未知 mode 排除。真实 RemoteBridge/catalog 联调在恢复时执行当前撤销，撤回来源标记后该测试失败。新增恢复断言在旧代码失败；再次撤回归档/重建后对应恢复测试失败。测试锁限定在各自临时目录。原有失效标记清理、普通写入隔离测试继续保留。

局部测试与静态检查不证明真实云认证、断电持久性、Windows 文件行为、打包 CLI/桌面或生产验收；本任务完整仓库验证交 CI。
