# 关闭审查发现的 E2EE CLI 明文回退与清理缺口

Status: implemented
Translation: current

[English](2026-10-27-e2ee-cli-review-fixes.md)

## 摘要

对已合入的 M2 CLI 接入做代码审查时，发现加密工作区可能被当作明文处理或泄漏资源的路径。本地目录现在不缓存本客户端未实现的内容模式，离线重启守护进程时不会把它当作明文打开；`lody export` 拒绝加密工作区，`lody sync` 跳过其定时任务房间，与受限功能约定一致。一次性命令在创建文档管理器失败时会关闭已打开的加密工作区；CLI 的 E2EE 云端端口用 Zod 校验历史和信箱回复，不再直接信任或强制转换。依赖待合入机器配对改动的两项相关发现交给该代码线处理，本次不修改。

## 决定

- **目录对未知模式失败关闭。** 不带 `contentMode` 的缓存行对所有读取方（包括已发布的 v1 读取方）都表示明文。只为缺省、`plaintext`、`e2ee` 写入缓存行；未知模式不写行，并丢弃该 id 之前的行，离线启动无法选中它。在线启动本来就会以 `workspace_mode_unsupported` 拒绝。
- **导出是受限功能。** `workspaceSupports(..., 'export')` 同时约束 `--workspace`（明确拒绝）和 `--all-workspace`（跳过并提示）。在对应 E2EE 里程碑之前，导出不会把解密后的会话内容写到磁盘。
- **同步保留受保护副本、跳过定时任务。** 加密工作区仍同步元数据、会话和机器文档；没有加密通道的定时任务注册表与定时任务房间被跳过，而不是报告为失败。
- **创建失败负责清理。** 与 `Lody.create` 一致：一次性命令创建管理器失败时关闭已打开的保管、历史与刷新所有者；保留原始错误，清理失败只记录日志，不替换原错误。
- **在边界校验。** 历史页与信箱回复使用与 Electron 云端客户端一致的 schema 解析；每个信箱方法一个 schema、按方法索引，返回带类型的结果，无需强制转换。CLI 与 Electron schema 合并到 `@lody/shared` 留待 E2EE 待合入栈完成之后。
- **CLI 运行时不使用非空断言。** 缺失的 journal/缓存行变为带类型的 `storage` 失败；重叠区缺失记录视为本地证据冲突。

## 本次未修改

- 机器设备原件丢失后的重新配对：credential 文件只按 genesis 命名，而 AAD 绑定签名公钥，替换密钥无法继续。修复会改变待合入机器配对 PR（#1898）使用的保管布局，已交给该代码线。
- 本机配对在每次准备时轮换已暂存、尚未批准的会话：同一负责方。
- 刷新失败后仍以旧状态确认激活、不同密钥的并发激活：#1898 已覆盖。

## 验证

每个新测试在撤回修复时失败、恢复后通过：目录未知模式不缓存、一次性命令清理（含关闭失败）、通过真实命令执行加密工作区的 export/sync、通过真实云端端口处理畸形历史与信箱回复。CLI E2EE 运行时测试与完整 `pnpm check` 覆盖非空断言移除与格式修复。未在真实后端验证。
