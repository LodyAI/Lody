# 附件准备期间的输入框配置

Status: implemented
Translation: current

[English](2026-09-30-composer-pending-send-config.md)

## 摘要

等待附件的发送已经冻结了配置，但新打开的输入框只读取已同步的历史和队列，
因此直到上传结束前都显示 Provider 默认值。输入框现在从最新的本地暂存发送
派生临时基线，并保留用户为下一份草稿做出的显式编辑。暂存发送与写入后的
消息用同一个逻辑身份隔离草稿。此修复保持选择连续，不增加持久状态，也不
改变已冻结的发送；尚未验证打包设备上的行为。

## 决策与职责

此修复补齐了[移除发送日志](../simplification/2026-09-29-remove-session-send-journal.zh.md)后的 UI 配置衔接。
[附件 Spec](../../../../specs/session-files.zh.md#61-点击发送的边界)负责行为意图，
[运行配置说明](../../../docs/sessions-run-config.md)解释与既有选择和 Role 来源的关系。

`useSessionPendingConfig` 按会话订阅最新冻结的消息，而不是附件进度。它为
`session-chat-interface.tsx` 提供配置和 Role 来源边界。旧轮次的 runtime 基线
不能覆盖这个本地来源；配置选择仍然由输入与用户编辑纯派生。

历史消息已写入，但尚未进入渲染中的来源快照时，hook 保留冻结的消息，直到
同一个 Turn 可读。取消没有已写入消息，因此释放临时来源。新观察到的已写入
Turn 会永久取代旧本地来源；删除该 Turn 不能让旧来源复活。作用域身份同时
包括会话和待发送 store。

暂存发送与历史/队列行的 preference revision 都使用逻辑 Turn key。来源种类
转换不会消耗用户为下一份草稿做出的显式编辑，即使编辑值恰好等于发送值。
Role 与其他配置使用同一份基线和来源关系。桌面与移动端在提交禁用菜单或
配置面板时，继续显示正常的配置按钮内容。

只保留旧简化名称仍会遗漏通过 ACP config options 提供的模型，也会丢失 Role
身份。冻结整个可见输入框则会妨碍独立编辑下一份草稿。复用正常控件内容和
现有冻结消息，可以同时处理这两个边界。

## 验证与限制

行为测试扩展现有配置和控件展示测试，使用合成消息、真实待发送 store 和
可控的准备 Promise。覆盖空文档加载、续发时的 runtime 边界、历史发布延迟、
下一份草稿的显式编辑、失败与取消、多条本地暂存发送、会话切换以及已写入
Turn 的取代。展示测试覆盖仅通过 ACP options 提供的模型名称、Role 身份和
移动端配置禁用。

不宣称完成原生设备或 daemon 投递验收。组件类型检查受当前安装缺失或落后于
本 checkout 锁文件的依赖限制；文档检查存在指向未初始化 ACP 子模块的既有
断链。此改动没有新增持久化、传输协议或消息写入路径。
