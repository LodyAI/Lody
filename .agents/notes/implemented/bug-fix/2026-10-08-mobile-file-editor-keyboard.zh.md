# 移动端文件编辑器键盘布局

Status: implemented
Translation: current

[English](2026-10-08-mobile-file-editor-keyboard.md)

## 摘要

移动端全屏文件抽屉的编辑器底部可能被软键盘遮住：iOS 没有使用原生键盘底部偏移，浏览器则关闭了输入避让。现在原生 iOS 使用宿主提供的键盘偏移，其他环境使用共享抽屉的实时可视视口偏移。Vaul 不再独立调整该抽屉的高度，避免两个机制竞争。自动化测试覆盖偏移选择和恢复，尚未验证物理设备上的键盘动画。

## 决策与证据

`MobileFileViewerDrawer` 负责原生 iOS 的 CSS 底部偏移，并关闭该环境下 Vaul 的输入避让。其他环境显式启用避让；共享 `Drawer` 在原有原生路径之外，也接受浏览器显式启用。不传入该选项的浏览器调用方保持原有行为。键盘收起或 WebView 已随键盘缩小时，视口偏移归零。Monaco 现有的自动布局会跟随缩小后的编辑器容器。

如果保留 Vaul 高度调整并同时添加原生偏移，就会有两个机制控制同一布局。统一修改所有抽屉的 iOS 布局还会影响已有独立键盘处理的底部面板，因此此修复在文件界面接入原生偏移。职责说明见[移动 UI](../../../docs/ui-mobile.md#pickers-and-keyboards)。这属于布局缺陷修复，不改变编辑或持久化意图。

## 验证

现有抽屉测试使用真实共享抽屉，覆盖浏览器和原生环境的覆盖式键盘尺寸变化、收起、原生 iOS 偏移选择和 CSS 高度保持。它们不能证明物理设备上的键盘动画或光标可见性。
