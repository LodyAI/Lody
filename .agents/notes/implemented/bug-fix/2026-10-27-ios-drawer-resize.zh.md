# 原生 iOS 侧边抽屉跟随当前视口尺寸

Status: implemented
Translation: current

[English](2026-10-27-ios-drawer-resize.md)

## 摘要

原生 iOS 聊天抽屉在键盘打开时折叠或旋转后，可能保留展开屏幕的高度，导致
输入框落到较小屏幕之外。Vaul 会缓存焦点所在抽屉的初始高度，并在之后恢复
该值。共享侧边抽屉适配器现在关闭原生 iOS 上的这项高度管理，保留 CSS 尺寸
及界面已有的原生键盘补偿。其他宿主继续使用实时视口底部偏移，底部表单及
带停靠点的抽屉保留各自行为。

## 决策与证据

原生模拟器复现步骤为打开已有聊天、聚焦输入框、切换内外屏尺寸，再收起
键盘。聊天标题仍可见，输入框却落到外屏下方；返回后会话列表高度正常，
因此问题定位到侧边抽屉保留的几何状态，而非整个原生视口。

Vaul 1.1.2 的 `onVisualViewportChange` 只记录一次 `initialDrawerHeight`，
可能在窗口变化后写回旧值。此前共享适配器对缓存高度的保护排除了原生 iOS。
iOS 聊天输入框已有宿主键盘偏移，文件抽屉也显式负责底部偏移，因此保留这些
已有负责人，不再增加一层抽屉尺寸补偿。

适配器只对符合条件的左/右侧抽屉应用该规则。显式退出、停靠点及底部表单
保留原有行为。不增加按尺寸变化的重新挂载 key，避免重建抽屉时丢失焦点及
临时输入状态。这把[文件编辑器键盘决策](2026-10-08-mobile-file-editor-keyboard.zh.md)
确立的归属扩展到原生 iOS 侧边抽屉，不改变底部表单。

## 验证

现有抽屉测试使用真实 Vaul 适配器、聚焦字段和合成草稿，依次触发键盘打开、
展开、折叠和收起。修改前因缓存的行内高度失败，修改后各阶段均保留 CSS
尺寸、焦点和草稿。抽屉、移动文件查看器及移动 diff 三组测试共 33 项通过，
覆盖已有 Android/浏览器偏移行为。原生产品复验从键盘打开的宽屏聊天切回
手机布局后，收起键盘仍可见同一聊天和输入框。类型检查和静态检查通过。
手机布局之间的切换、真机及浮动键盘验收与 JSDOM 几何检查仍需分别看待。

10 月 28 日的普通 iPhone 审查发现归属切换不完整：PR、浏览器、文件列表和模拟器
portal 依赖原先 Vaul 的尺寸补偿，却没有接上原生偏移。390×852 视口中的真实
PR 评论输入框因此被 300 点键盘遮住。这些面板现在显式启用
`DrawerContent.nativeKeyboardInset`，聊天输入框继续自行避让。WebKit 回归在
修复前失败、修复后通过；反复弹出和收起键盘时，同一输入节点、未发送草稿与焦点
保持不变。独立的 Android 覆盖式/缩放式键盘和浏览器缩放检查也通过。
