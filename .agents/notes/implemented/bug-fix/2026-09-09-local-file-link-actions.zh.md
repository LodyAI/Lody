# 本地文件链接与二进制预览操作

Status: implemented
Translation: current

PR: https://github.com/LodyAI/Lody/pull/555

[English](2026-09-09-local-file-link-actions.md)

## 摘要

助手消息中的文件链接使用填充式胶囊样式，而预览成功的二进制文件却没有提供预览出错时本就可用的系统
操作。渲染层现在使用蓝色链接与对应文件类型的图标，二进制预览也会收到既有的本地「打开」与「在
访达中显示」回调。二进制提示复用「文件不可用」卡片，采用全宽堆叠的操作按钮与共享的「复制文件路径」
回调，在保留二进制专属复制的同时让侧栏两种状态保持一致。本地绝对路径得以保留；远程 shell 访问仍
不可用。报告中提到的「找不到原生应用」消息未能复现，因此绝对路径被拒是一个确认存在的独立缺陷，
而非该消息成因的证据。

## 决策与证据

[规格草案](../../../../specs/local-file-link-actions.md)记录了既定行为。More 菜单与预览回调由
`useSessionFileActions` 拥有。此前 `resolveLocalWorkspaceFilePath` 会拒绝每一个绝对路径，哪怕本地
预览已经打开过它。它现在仅在会话机器为本地时接受绝对路径；父级相对路径也只对本地目标接受；远程
穿越仍被拒绝。IPC 拒绝现在产生针对具体操作的错误，而不是未处理的 promise。Electron 既有的
`revealLocalPath` 调用 `shell.showItemInFolder`，与默认应用的启动相互独立。无需改动任何远程预览
策略或协议。

## 验证

回归覆盖检查本地产物路径、远程操作的排除与 Reveal IPC 失败。Story 渲染真实的 Markdown 与二进制
预览组件。最终执行的检查结果随交付一并提供；原生访达行为仍需在真实桌面运行时验证。

## 链接颜色细化

使用 Tailwind `text-sky-700 dark:text-sky-400`：在浅色会话中 Sky 700 相对 Blue 600 降低了色度，
而 Sky 400 在深色表面上仍然易读。这是本地的设计选择，不是 Tailwind 规定的链接颜色。
[Tailwind 颜色指南](https://tailwindcss.com/docs/colors)提供了该色板与深色变体模式。针对已渲染
Story 背景的浏览器测量给出在白色上约 5.86:1、在 #101010 上约 8.73:1（使用 canvas sRGB 转换）；
两者都超过
[WCAG 对比度指南](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)中普通文本的
4.5:1 标准。两种渲染主题都保持透明背景、零边框，并且图标与文字颜色完全一致。该后续改动只修改了
两个颜色 class。

## 系统操作失败的后续

共享路径守卫把每个未解析路径都报告为通用的打开失败，既不调用 IPC 也不记录日志。此前的绝对路径修复
仍会拒绝本地的 `../artifacts/Lody.dmg`，尽管本地预览会把该路径相对工作区解析。现在「仅本地」的守卫
会接受它。测试覆盖访达与编辑器两种派发；远程 shell 操作仍然缺席。运行中的 0.89.4 测试应用已从其
进程可执行文件与 app.asar 内打包的渲染层得到确认。重放那份打包解析器会拒绝合成的绝对路径与父级
相对 DMG 路径，同时接受工作区相对路径。打包版守卫在两种原生操作之前就返回通用 toast，且没有控制台
诊断。用户的确切文件路径仍不可得；当前工作区的补丁尚未安装进那个运行中的应用。

现在三种操作都通过同一个 handler 报告桥接缺失、IPC 被拒与返回的错误。本地控制台细节保留操作、
请求/解析后的路径、工作区/会话/机器身份、系统结果与异常栈。toast 提供针对具体原因的指引，以及一个
由用户发起的「复制错误详情」操作。Electron 保留权限/IO 错误，而不是把所有访问失败都映射为「未找到」。

VS Code 的协议兜底此前还会给文件追加一个斜杠，把它们当成目录。文件操作现在会指明文件身份，而既有的
工作区启动器继续使用目录 URL，这符合
[VS Code URL 契约](https://code.visualstudio.com/docs/configure/command-line#_opening-vs-code-with-urls)。

后续改动的验证：63 个定向组件测试与六个原生核心测试通过；组件与 Electron 主进程类型检查通过。完整
的仓库类型检查与 lint 通过。在沙箱外重试后完整的 test:ci 通过（初次尝试无法监听 loopback）：全部
445 个组件测试文件、257 个 CLI 测试文件（一个跳过）与 105 个 Electron 测试通过。i18n、文档、
Code Collab、平台与公开边界检查也通过。运行中的打包应用尚未被替换。
