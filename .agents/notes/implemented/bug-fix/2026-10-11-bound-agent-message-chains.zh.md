# 限制 Agent 消息链并抑制无意义回复

Status: implemented
Translation: current

[English](2026-10-11-bound-agent-message-chains.md)

## 摘要

Agent 对话可能因确认收到或重复回传结果而反复唤醒彼此。现有因果委派上限从
32 降为 16，同时在 MCP 指令中要求消息推进任务，并使用自动结果投递。
这会更早截断委派深度，同时保留有实际内容的后续协作。
本次没有新增跨分支的共享预算，也没有在运行时判断消息是否有意义。

## 决策与证据

本决策取代[此前链深度决策](2026-09-08-raise-async-chain-depth.zh.md)中的数值上限。
[会话编排 Spec](../../../../specs/session-orchestration.zh.md)仍为草稿。
MCP 接受检查与可执行 Operation 模型使用同一个共享常量；创建、发送、批量派发、
恢复与完成回传继续传播已有因果深度。深度达到或超过 16 后，新命令在接受前被拒绝，
错误仍不可重试。因此，正常但较长的委派任务也可能更早停止。

同一段提示同时用于 MCP 初始化指令与四个创建／发送工具的说明，禁止纯礼貌回复、
要求确认收到、冗余状态消息，以及手动重复回传平台自动投递的结果。
达到上限后，Agent 应向用户报告剩余工作，不得重试或另建对话绕过限制。
提示词不构成消息语义的强制校验；运行时现有检查仅保证链深度上限。

## 可见的上限与软上限预算（2026-11-26）

此前到达上限时没有任何提示。命令被拒只返回一句简短错误；批次深度达到 16 的自动
续跑被标记为 `depth_limited`，却不写任何历史，人类只看到一个闲置的 Session 扣着
已经完成的结果。这个检查还比目标早一层拦截：深度 15 的 Turn 可以委派，但目标的
结果永远无法自动回传。

- 续跑现在可以在深度 16 运行，只拦截更深的批次。链条仍会终止，因为深度 16 的 Turn
  不能委派。被拦下的结果保留到下一条人类输入，Coordinator 为每个被拦的 intent
  upsert 一条 `agent_warning` 提示。
- 达到上限的拒绝信息写明跳数和上限，并在调用方 Session 中为每个受限 Turn upsert
  一条提示。
- 从 `LODY_CHAIN_DEPTH_SOFT_LIMIT`（8）开始，Operation 快照带 `chainBudget`，每次
  派发回复都告诉 Agent 还剩几跳。这个警告由产品 owner 于 2026-11-26 提出；按照
  面向 Agent 文本的规则，它只陈述深度事实，不给出指令。
- 未采用的方案：只改错误文案，被拦结果仍然不可见；续跑深度只按成员计算，与 Spec
  的当前/成员规则矛盾；新增提示类型，旧客户端无法解析。复用带 `source` 的
  `agent_warning` 可在所有客户端渲染。

## 验证与限制

既有模型边界测试已更新，验证深度 15 可以接受，深度 16、17 和 32 被拒绝且状态不变。
