# 限制 Agent 消息链并抑制无意义回复

Status: implemented
Translation: current

[English](2026-10-11-bound-agent-message-chains.md)

## 摘要

Agent 对话可能因确认收到或重复回传结果而反复唤醒彼此。现有因果委派上限从
32 降为 16，同时在 MCP 指令中要求消息推进任务，并使用自动结果投递。
这会更早截断委派深度，同时保留有实际内容的后续协作。
本次没有新增跨分支的共享预算，也没有在运行时判断消息是否有意义。

## 决策与证据

本决策取代[此前链深度决策](2026-09-08-raise-async-chain-depth.zh.md)中的数值上限。
[会话编排 Spec](../../../../specs/session-orchestration.zh.md)仍为草稿。
MCP 接受检查与可执行 Operation 模型使用同一个共享常量；创建、发送、批量派发、
恢复与完成回传继续传播已有因果深度。深度达到或超过 16 后，新命令在接受前被拒绝，
错误仍不可重试。因此，正常但较长的委派任务也可能更早停止。

同一段提示同时用于 MCP 初始化指令与四个创建／发送工具的说明，禁止纯礼貌回复、
要求确认收到、冗余状态消息，以及手动重复回传平台自动投递的结果。
达到上限后，Agent 应向用户报告剩余工作，不得重试或另建对话绕过限制。
提示词不构成消息语义的强制校验；运行时现有检查仅保证链深度上限。

## 验证与限制

既有模型边界测试已更新，验证深度 15 可以接受，深度 16、17 和 32 被拒绝且状态不变。
定向 Vitest 与 CLI 类型检查未能启动：嵌套检出缺少已安装依赖，找不到 `vitest` 和 `tsgo`。
变更的 TypeScript 文件已用 Oxfmt 格式化，`git diff --check` 通过。
仓库文档检查仍被已有失效链接阻塞，其中包括缺失的 ACP 子模块文件。
完整运行时与已发布客户端验证仍待补充。
