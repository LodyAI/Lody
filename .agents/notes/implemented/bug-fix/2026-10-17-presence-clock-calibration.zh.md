# 刷新长寿命进程的服务器时间校准

Status: implemented
Translation: current

[English](2026-10-17-presence-clock-calibration.md)

## 摘要

系统校时会使长寿命进程在启动时缓存的偏移失效，重新校准的渲染进程因而拒绝该进程刚送达的全部心跳。
云端应用现在拥有原生校准循环，在启动时采样，并在每次尝试结束 30 秒后再次采样。
整数 epoch 时间戳和共享偏移保持原有语义，原生 presence 与 token 消费者也读取更新后的偏移。
准确恢复以成功取得服务器样本为条件；离线设备保留上次估值，不阻断其他工作。

## 决策与生命周期

Issue：[#1663](https://github.com/LodyAI/Lody/issues/1663)。PR：[#1667](https://github.com/LodyAI/Lody/pull/1667)。同机持续失效需要两端处于不同校准代际；
相同的旧偏移在比较新心跳时会抵消。时间偏差向前可能拒绝新状态，向后则可能让未来时间戳过久有效。
本次修复恢复时钟可比性，不放宽 freshness 判断。

CLI 在认证和检测结束后、进入服务生命周期前启动维护，启动失败和关闭都会停止它。
渲染器的 React effect 拥有维护循环，在卸载或移除云同步能力时停止。本地组合不创建循环或请求。
`startTimeSyncLegacy` 是这些 Promise/React 入口唯一的执行门；它们将来直接在应用 Scope 中组合
`maintainTimeSync` 后即可删除，无需新增 Service。

原生循环和 Legacy 入口位于同一生命周期模块。循环串行采样，30 秒后重试，
以处理系统校时、缓慢漂移和前次失败。原有 fetcher 将响应头与响应体限制在五秒内，
现在也组合应用取消信号。启动仅等待第一次**尝试**，保留原来的尽力而为语义。
fetcher 在所有退出路径上取消自己的请求控制器，释放尚未读取的非 2xx 响应体，避免周期重试不断遗留响应。
失败保留旧偏移，presence、RPC 和计划任务继续可用，并在之后重试；诊断回调失败不会停止循环。
关闭中断循环和 fetch。只读 HTTP 不存在写入者或独占资源交接；忽略取消的晚到样本被禁止发布，
不会因此阻止后继应用启动。owner 的信号防止已取消样本覆盖后继校准。
生产 owner 串行采样，一次性命令运行于独立进程，无需另设请求代际状态。
采样过程中发生墙钟跳变时拒绝该中点，避免把两个时钟时代混为一个有效样本。

`getServerNow()` 与原生 `Clock.currentTimeMillis + getServerTimeOffset()` 读取同一份刷新后的校准，
因此工作区心跳和 Streams token 端口无需各自增加纠偏机制。RPC 过期、持久日期和计划任务时刻仍为整数 epoch。

## 替代方案与限制

未校准的纯本地模式无需为这个缓存偏移故障改动，但仅启动校准会让云端组合在两个校时方向上都永久保留旧偏移。
单独的周期刷新即可恢复可比性；每秒检查跳变只会缩短恢复时间，没有独立的期限要求。
循环保留首次尝试就绪回调，因为 CLI 原先就会在发布对时间敏感的启动状态前等待。
把就绪信号放入 fetcher 会在偏移真正发布前过早报告完成。
删除偏移会重新引入设备初始时钟偏差。永久用单调计数器推进 epoch，会在单调时钟随休眠暂停的运行时丢失休眠时间；
离线时也无法普遍区分系统校时与休眠。保留墙钟 epoch 避免引入这种回归。
计时器或调度暂停仍会延迟恢复。

校时后可能要等待下一次 30 秒刷新及其请求完成，期间两端暂时不可比。离线、调度缓慢或时间服务器不可用时没有绝对准确性保证；
不猜测零偏移，不添加请求门槛，也不伪造 freshness。未验证安装后的 macOS/Windows 休眠、真实 NTP 校时或生产端点。

## 证据

共享测试使用独立校准模块、可控墙钟与单调时钟以及真实 freshness 判断，覆盖两个校时方向、
刷新失败和重试、单调时钟暂停的休眠、整数时间戳、原生 token 端口时间、请求和响应体取消、晚到样本及采样中校时。
原生工作区测试验证实际心跳采用新偏移而不替换 owner。渲染器测试检查校准后的状态、
本地模式不请求时间服务器，以及移除云能力时取消请求。
删除消融分别复现了去掉周期刷新后永久保留旧偏移、去掉采样中跳变检查后残留半次跳变误差、
去掉取消检查后晚到样本覆盖，以及去掉 abort 后遗留未读错误响应体。
取消测试显式控制时钟；直接并发调用时的先后覆盖不属于已观察到的 owner 契约。
