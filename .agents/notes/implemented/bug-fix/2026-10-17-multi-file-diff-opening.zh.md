# 保持多文件差异打开时的响应

Status: implemented
Translation: current
PR: [#1648](https://github.com/LodyAI/Lody/pull/1648)

[English](2026-10-17-multi-file-diff-opening.md)

## 摘要

打开整轮差异时，原先会同步计算中等大小的重写，并一次挂载所有文件的变更行。多文件面板现将缓存未命中的解析交给已有 Worker，按可见范围加载和挂载正文，同时保留文件名外壳、展开状态和明确焦点。前方正文增高时保持用户当前可见文件的位置，用户交互过的正文则保留挂载，使文本选择、上下文展开和批注草稿能够跨滚动保存。All Changes 保留原有有界内联批量响应，仅在相关文件可见时补读 deferred 内容。本轮限制多文件打开时的工作量，尚未实现单个巨大差异的行级虚拟化或内联批量数据的渐进解码。

## 证据与既有行为

保留[指定文件的展开决策](2026-09-27-all-changes-single-file-expansion.zh.md)：无焦点整轮差异在逻辑上全部展开，无焦点 All Changes 全部折叠，明确文件操作只展开目标。

使用当前已打补丁的 `@pierre/diffs` 1.0.10，Chromium 145 五次解析探针测得：2,000 行整体重写仅合计 83,563 个字符，解析中位数已有 279.2ms；原先的 200,000 字符门槛使其在 React 渲染期间执行。另一项单次原生渲染探针预先完成解析并初始化共享渲染 Worker，挂载 30 个各含 400 行变更的文件，产生 61,260 个 shadow DOM 节点，同步挂载 216ms，强制布局 503.8ms。这些是合成规模观察，不能当作真实桌面输入延迟。

## 实现与取舍

- `SessionConversationDiffPanel` 保留所有轻量文件外壳，通过 `useDiffViewport` 选择附近工作。一个交叉观察器追踪滚动容器及上下 600px 预加载区，首次观察前仅启动两个文件，明确焦点始终包含在内。整轮正文和 All Changes deferred 正文复用有界逐文件加载器；后者保留既有内联批量请求。
- 共享尺寸观察器在前方文件增高时保持可见文件的偏移；位于底部时以最后一个可见文件为锚，防止预加载文件展开后把目标末尾文件推到屏幕下方。仅在这一区域关闭浏览器原生锚定，避免重复补偿或锚定无关的已聚焦文件头。
- `DiffViewer` 只暂停代码正文，保留折叠和批注状态，并在暂停前记录正文高度。指针或键盘交互过的正文继续挂载，保留原生文本选择、未修改上下文展开、回复文字和草稿。这对用户已操作文件有意以额外内存换取交互状态，不限制其累计 DOM 数量。
- 多文件缓存未命中的解析不再按文件大小区分，统一使用既有共享解析 Worker。解析按序启动，进入 Worker 后才开始超时计时，已经过期的排队正文会被跳过。查看器跨暂停保留对应完整输入的解析 Promise，返回时不重复排队。请求身份使用完整输入引用或字符串，不再抽样文本，避免抽样区域之外的等长修改短暂复用旧结果。不可变整轮检查点缓存沿用现有键，并在仅重建 Provider 时保留，没有增加只按路径和长度缓存的实时缓存。
- 可见范围变化会取消排队启动，但已发出的读取直到完成才释放并发槽，同一数据源的有效结果仍能发布。数据源和批次身份隔离旧数据及迟到结果，请求完成后唤醒下一轮加载。隐藏的桌面面板不再启动新的差异或 GitHub 批注读取。
- Storybook 将锁定 Pierre 包的入口排除在依赖预打包之外，显式预打包其 CommonJS 子依赖 `lru_map`。1.0.10 将源码路径标为有副作用，实际却发布 `dist`，预打包会移除 `<diffs-container>` 注册，使原有示例正文空白。本次修正的是预览配置，没有升级依赖或替换渲染器。

仅增加 Worker 无法限制 DOM 和布局；全部折叠整轮文件会改变既有行为。锁定版本缺少行级虚拟化 API，并携带换行拆分兼容补丁，因此延后单独评估完整 Pierre 升级。React 渲染和请求 Hook 继续使用普通 TypeScript，本轮没有引入 Effect 生命周期边界。

## 归属与验证

[文件界面文档](../../../docs/sessions-file-surfaces.md)拥有当前行为说明，[会话范围规则](../../../../packages/components/src/components/sessions/AGENTS.md)约束调用方。专用 `ConversationDiffPanel` 示例使用合成 200 文件 Provider 和真实面板、查看器组件。`OpenFromChanges` 初始不挂载差异，通过合成的 Changes 按钮打开真实桌面侧栏布局及面板，并提供关闭后重开操作。它覆盖布局过渡和面板首次挂载，没有运行完整 `SessionDetail` 控制器或 Electron 数据路径；重新加载预览会重置内存中的差异缓存，供首次点击验证。单元回归覆盖可见范围、隐藏后恢复、未完成请求的结果接收、实时批次失效、完整输入身份、Worker 失败及未发送输入保留。浏览器回归覆盖点击打开、关闭后重开、代码 DOM 有界、折叠后滚动返回、末尾文件焦点、All Changes 按需展开及原有大文件滚动。

已通过 41 项相关单元测试、全部五项浏览器回归、组件类型检查、变更 TypeScript 静态检查、i18n 校验、变更文件格式检查及 `git diff --check`。在 1200×800 的 Chromium 中运行真实 200 文件面板，首屏挂载一个代码正文、4,443 个 shadow 节点；滚动到末尾时为两个正文、10,486 个节点，200 个文件名外壳始终可达。这些快照不是生产延迟基准。已检查浏览器截图中的真实差异文本、行号及分栏布局。
