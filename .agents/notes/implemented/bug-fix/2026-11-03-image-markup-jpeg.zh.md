# 图片标注附件编码为 JPEG

Status: implemented
Translation: current

[English](2026-11-03-image-markup-jpeg.md)

## 摘要

原图未超过附件限制时，标注后生成的 PNG 仍可能超限，导致输入框无法接受图片。
图片标注编辑器改为输出 JPEG，并在必要时降低编码质量，以满足原有的 5 MiB 图片限制。
透明像素会合成到白色背景上，JPEG 压缩有损。未接受标注结果而发送的图片保留原始字节
和格式，文档选区截图继续使用 PNG。

## 决策与限制

[标注工作区](../feature/2026-10-31-image-markup-workspace.zh.md)仍把图片和标记绘制到
有界画布，并只在输入框接受结果时替换草稿。共用的选区编码器仅对图片标注编辑器选择
JPEG，并根据共享图片限制检查编码后的字节数。编码会在不改变编辑器画布的前提下尝试
较低质量；失败时保留编辑器和原附件，取消仍保留原图。原有 GIF 标注已经只使用解码后的
单帧。

PNG 可以保留透明度并避免有损重编码，但即使原文件未超限，输出也可能超过限制。JPEG
以牺牲这些特性换取更小的标注图片。本次不改变普通附件的接收、上传或 Agent 传输。

一张合成的 2048 × 1792 PNG 在标注前为 3.76 MiB；WebKit 以 0.92 质量导出时得到
5.16 MiB 的 JPEG，降低质量重试后得到 4.51 MiB。因此，即使原文件和画布尺寸均在
限制内，也必须检查编码后的附件大小。

## 验证

聚焦浏览器测试覆盖图片标注、透明像素、大小限制、编码失败和取消；现有文档截图测试
检查 PNG 路径。这些测试不代表已验证真实服务商或实体设备。
