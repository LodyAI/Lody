# 预览 Agent Role 时保留提及列表的滚动位置

Status: implemented
Translation: current
PR: [#1317](https://github.com/LodyAI/Lody/pull/1317)

[English](2026-10-08-mention-detail-scroll-continuity.md)

## 摘要

聚合 `@` 搜索中，鼠标移到 Agent Role 时列表可能跳回顶部，让目标行难以选中。
候选详情栏出现或消失时，列表的祖先节点被替换，滚动容器和已注册的候选行随之重新挂载。
菜单现在保留这些祖先节点，只改变详情栏和布局样式。使用合成数据的 Chromium
复现与行为测试确认滚动位置得以保留，角色可以正常选中；尚未验证打包后的桌面应用。

## 决策与证据

`MentionTwoLevelMenuBody` 始终保留相同的列表包装节点。只有存在详情栏时才应用
详情布局样式，保留无详情菜单按内容确定的宽度。这延续了
[提及菜单界面决策](../feature/2026-09-25-composer-mention-menu-v2.zh.md)，
候选排序、可用性、插入文本与派发行为不变。

保存并恢复 `scrollTop` 会掩盖重新挂载，却仍会替换鼠标下方已注册的候选行。
稳定的祖先节点可以同时保留滚动容器和候选行。

`MainComposerAggregateRoles` 故事在真实浮动菜单中使用合成文件、Issue、PR 和角色。
Chromium 中，旧列表在悬停角色时从 `scrollTop = 152` 重置到 `0`，候选行也被替换。
修复后列表与候选行保持原节点，滚动位置保持在 `152`，点击插入 `@Code-Reviewer`。
单元测试覆盖进入、离开和再次进入预览，再分别通过鼠标或 Enter 选择角色。
现有的反向键盘导航测试在断言初始高亮前推进一次虚拟动画帧。

Playwright 视频验收对旧实现和修复后的实现重复相同的搜索、滚动、鼠标移动和点击坐标。
旧菜单重置到 `0`，点击插入 `#101`；修复后保持 `152`，插入 `@Code-Reviewer`。
两段录制都使用故事中的合成候选数据，并标出操作步骤和鼠标位置。
即使验收失败，录制程序也会恢复修复后的源码；生成的视频不纳入提交。
