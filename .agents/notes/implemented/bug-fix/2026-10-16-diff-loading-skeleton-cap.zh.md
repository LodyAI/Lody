# 限制加载中的 diff 绘制的脉动骨架屏数量

Status: implemented
Translation: current

[English](2026-10-16-diff-loading-skeleton-cap.md)

## 摘要

在 iOS 上，打开改动量非常大的会话的 diff（用户录屏中显示 `+0 −38677`）后，大约两秒页面就会白屏并重新加载应用，
每次都如此。diff 加载期间，每个改动文件都显示一张带五行脉动骨架屏的卡片，而 WebKit 会把每个脉动元素合成为独立的
图层，所以几千个文件就意味着在任何 diff 到达之前就有几千个图层。现在加载中的卡片只有会展开时才绘制骨架屏主体，
并且最多只有前三张这样的卡片绘制，其余只显示标题。在 WebKit 中测得，这消除了随文件数增长的内存；尚未在 iOS
真机上确认。

## 问题

录屏中同样的过程出现了两次：

1. 用户点击输入框上方的改动摘要（`+0 −38677`），打开 All Changes diff 面板（`mode: 'base'`）。
2. 每个文件卡片都显示五行加载骨架屏。
3. 大约两秒后页面白屏，应用重新加载，此时所有卡片仍在加载，没有任何 diff 数据被应用。

`SessionConversationDiffPanel` 为每个改动文件渲染一张卡片，没有虚拟化；没有数据的卡片渲染 `FileDiffSkeleton`：
一个标题加五行 `@lody/ui` 的 `Skeleton`。`Skeleton` 以无限循环的透明度动画脉动。在 All Changes 中，没有焦点的
卡片默认是折叠的，所以这些骨架屏主体代表的是卡片根本不会显示的内容。

## 依据

在 Playwright 的 WebKit（WPE，390×844 视口，设备缩放 3）中渲染一个合成页面，包含 N 张卡片，每张五行 12 像素高的
条。下表是 WebContent 进程增长的内存：

| 卡片数 | 静态条 | 脉动条  | 脉动 + `content-visibility: auto` |
| ------ | ------ | ------- | --------------------------------- |
| 500    | —      | +95 MB  | —                                 |
| 2,000  | +30 MB | +311 MB | +130 MB                           |
| 5,000  | +59 MB | +520 MB | —                                 |

随文件数增长的是脉动动画，而不是 DOM。iOS 用三倍于 CSS 尺寸的 GPU surface 承载合成图层，所以真机上的开销
很可能高于这次软件合成的测量。录屏里看不出崩溃时刻还有别的内存分配，但没有在真机上测量。

## 决定

`selectDiffSkeletonBodyPaths` 选择哪些加载中的卡片绘制主体：

- 只有会展开的卡片（`shouldOpenDiffFileByDefault`）：折叠的卡片没有主体可代表；
- 最多 `MAX_DIFF_SKELETON_BODIES`（3）张，按列表顺序。

其余加载中的卡片只渲染标题。因此没有焦点的 All Changes diff 在加载时不绘制任何脉动元素，有焦点时绘制一个主体，
对话 diff（所有卡片展开）无论文件数多少都只绘制三个主体。

## 未采用的方案

- **给文件块加 `content-visibility: auto`。** 测得增长减少约 60%，但仍随文件数增长。
- **在 `@lody/ui` 中增加不带动画的骨架屏变体。** 能解决开销，但为一个调用方增加了包的选项，而只显示标题已经足以
  表达正在加载。
- **虚拟化卡片列表。** 这也能限制已加载的 diff，但会大改滚动、焦点和评论定位的代码；如果之后瓶颈变成已加载的
  diff 而不是骨架屏，这是合适的下一步。

## 局限

- 修复后，超大的 diff 仍然为每个文件挂载一个标题，并在内存中保留所有已加载的 diff。All Changes 每批最多内联
  2 MB 压缩数据，但之后会立即获取所有 deferred 文件，没有总量上限。
- 修复没有在 iOS 真机上验证；崩溃原因是根据录屏时间线和 WebKit 测量推断的。

## 验证

`tests/session-conversation-diff-panel.test.tsx` 用 300 个文件和一个请求永不返回的 provider 挂载真实面板，检查：
没有焦点的 All Changes diff 不绘制骨架屏条，有焦点时绘制五条，对话 diff 绘制十五条。修复前三种情况都绘制 1,500 条。
