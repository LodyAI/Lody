# PR 关联与生命周期的独立职责

Status: implemented
Translation: current

[English](2026-10-25-multi-repository-pr-panel-loss.md)

## 摘要

整数组状态写入会删除其他仓库的 PR 关联，导致详情面板关闭和操作入口消失。
采用的方案把机器维护的关联成员／排序与逐 PR 生命周期观察分开。
共享读端按 GitHub 版本合并机器和 webhook 的独立记录；渲染端与回合结束不再发布旧数组快照。
机器离线时，托管生命周期摘要仍可更新，但状态观察没有创建关联的权限。

## 职责与收敛

协调器是唯一自动发布关联列表的来源，保留 fresh-owner、分支重校验、额度、重试及副作用
成功后才提交成功标记的约定。托管链接与摘要发布独立；CI 和可合并性仍由机器维护。
公开契约见[本机 GitHub 观察](../../../../specs/local-github-pr-observation.md)。

共享策略规范化完整仓库与 PR 身份，将 `{s,u}`（状态、提供方版本毫秒值）写入独立字段
`prLifecycle:<source>:<url>`，单条小于 50 字节。来源固定为 machine、webhook，
每个已观察 PR 仅有两个记录，不追加事件历史。扁平字段遵循 Repo 元数据存储方式，
单仓库更新不会替换其他仓库记录。

机器通过普通 `upsertDocMeta` 发布，保留本地持久化与上传事件；webhook 盲写通过新建
Flock、提供方时间戳及确定性状态 peer 处理。机器不能通过导入伪造远端 delta 发布，
否则会绕过本地更新上传订阅。来源分离也避免混用本机 HLC 时钟与提供方版本。

读端优先选择 GitHub 版本较新的观察，同版本跨来源时优先机器实时快照；仅 webhook
冲突时按 merged、closed、open、draft 的顺序确定性收敛。GitHub 秒级时间戳无法证明
同秒内的事件顺序，这是一项明确的歧义策略，不是精确事件时序。后续版本可重新打开已关闭 PR。

孤立观察不能建立关联或会话存在性。记录保留至会话清理，避免本机时间戳删除阻断后续合法
提供方版本；记录数随 PR 身份增长，不随轮询次数增长。

## 消费者与兼容

侧栏比较解析后的状态，相同状态的新版本不会触发列表重渲染。仓库行、PR 操作、归档、
任务映射、统计、通知、MCP 摘要、diff-stat 策略与轮询目标使用同一解析规则。
详情面板的实时状态只留在视图，不再持久化旧列表；不同仓库的同编号 PR 不会串写。
没有通过 UI 缓存保留已删除关联来遮盖错误写入。

旧数组保留 `{url,status}` 兼容投影。旧读端仍可使用，但离线摘要刷新需要新读端。
活动旧渲染端必须升级，新读端无法阻止旧版本继续写旧数组。
托管适配端须停止首次关联发布，使无版本的旧队列调用无害，并独立发布带版本 webhook 观察。
托管对应改动在公开仓库之外维护。

仅机器写入会损失离线摘要刷新；全量换成逐 PR 实体需要更广的排序和删除迁移；
用托管链接表重建会漏掉本机独立发现的 PR。本次职责分离不需要这些方案。

## 验证与边界

行为验证覆盖真实托管处理函数与 Flock 合并、提供方版本乱序、同编号跨仓库、孤立观察不显示、
workspace 删除、旧调用、首次生命周期初始化、过期轮询、真实 Repo 本地发布与远端投影，
以及仅状态变化的侧栏刷新。相关组件、共享、CLI、托管测试和包类型检查在隔离工作树执行。
不收录用户记录、日志或对话，不宣称已部署生产或验证重新构建的已安装桌面端。

保留现有轮询生命周期和已发布的 Promise Repo 边界，不新增 Effect 服务、恢复 owner、
时钟循环或迁移单元。本记录补充[多仓库设计](../../proposed/architecture/2026-10-16-multi-repo-projects.md)，
不改变其更广的 Project/worktree 契约。

## 终态 discovery 的重新激活

移除其它列表写入者后，仅包含仓库和分支的旧指纹会永久隐藏同分支后续创建的 PR。
终态休眠现要求已成功检查仓库、分支及 owner/子会话的最新 `lastMessageAt`。
先汇总子会话活动，再为每个 Project 仓库独立投影；复用回合完成时已有的元数据更新，
不新增 turn-end 调度回调。

target 携带派发时的活动快照，只有查询和 owner effects 成功后才提交该检查点，
不能用 writeback 时新读取的活动替代。请求期间的新活动仍需下一轮 discovery，
遵守原有额度、重试和最小间隔约束。检查点沿用独立持久化的指纹存储，target 的
成功时间被清理后仍保留。版本化编码使旧指纹进行一次补查，无需数据库迁移。
无新活动时仍停止终态查询；完全在 Lody 外创建 PR 且没有活动或上下文变化的情况，
仍需后续活动信号才能重新发现。

回归验证覆盖重启后同分支新 PR、子会话活动、多仓库成员、请求期间新活动及旧指纹失效。
