# 重试渲染器清理，不恢复已退役的工作区

Status: implemented
Translation: current

[English](2026-11-03-workspace-close-retry.md)

## 决定

RuntimeProvider 跨导航保留两个内容关闭 owner。已成功的清理不再重复执行，失败的一次尝试不作为最终结果缓存。
工作区 runtime 只重试未完成的关闭阶段，并发调用共享同一次尝试。尝试之间始终保留退役栅栏。
原生 reader 的归属和准入校验不变；同一绑定必须先排空旧 owner，才能创建后继实例。

运输层或缓存关闭失败时，先保留 Repo 供恢复，不提前销毁。当前 loro-repo 0.25.0 在等待子资源关闭之前就设置
`destroyed`，后续 destroy 调用会直接返回。因此终端销毁失败后，重试不能证明存储或写入者已经排空，必须继续阻塞；
只有进入终端销毁前的失败可重试。不能清空所有失败 Promise、忽略错误，或把 SDK 后续的空返回当作关闭成功。

首次失败只记录关闭阶段和有界白名单 cause 类别，不记录任意异常名称、消息、堆栈或身份字段。
日志失败不能改变原来的关闭结果。

## 证据与范围

合成的已准入双 epoch 原生端口驱动真实 RuntimeProvider 和 IndexedDB Repo。注入的关闭失败在旧代码上因缓存结果而 RED；
显式信号确认真实排空后，同绑定可重新打开并读回持久历史。另有运输层关闭和不确定终端销毁的反例，继续保护无重叠约束。
这些是生命周期 fixture，不是真实原生保管或产品验收。密码学、账本、grant、审批返回和派钥语义均未改变。

[原生诊断决定](2026-10-27-e2ee-recovery-diagnostics.zh.md)中的一次性 Scope 失败仍遵循原来的恢复或重启边界，该记录没有被取代。
Promise Repo 和上层 React 生命周期仍是外部依赖，本次不扩展 Effect 迁移，也没有增加后台恢复 owner。
