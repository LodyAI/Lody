# 官网 shader 占满核显

Status: implemented
Translation: current

[English](2026-10-15-site-shader-gpu-cost.md)

## 摘要

定价、下载、更新日志页的环境场和首页点云会把核显长期占满，独显用户的开销也不小。环境场每个像素每次采样要做四次完整的
domain-warp 计算，频率 15Hz。它的 GPU 时间回压依赖一个浏览器几乎不暴露的 WebGL1 计时扩展，所以从未生效。现在环境场的两个
warp 值只算一次，ridge 的两个差分点改读相邻纹素。采样节奏改由 WebGL2 计时查询或 fence 控制，呈现上限为 60fps。首页不再强制
独显，在 2× 缓冲上关闭 MSAA。两个场景在软件光栅化下都只画一帧静止画面。画面差异不超过 2/255。剩余限制：本次没有在真实核显上
测量，证据来自 SwiftShader。

## 问题

- `marketing-atmosphere.tsx` 每像素调用四次 `warped()`：`n`、`n2`，以及给 `ridge` 用的两个前向差分点，约 445 次 `sin()`。
  1080p 窗口、dpr 1.5（470 万像素）下，每次采样约 20 GFLOP 量级；每秒 15 次，足以占满常见核显。
- 采样器用 WebGL1 上的 `EXT_disjoint_timer_query` 调整间隔，而浏览器大多不暴露它，于是循环固定在 15Hz，从不退避。
- 呈现跟随显示器刷新率（很多笔记本是 120/144Hz），每帧还让合成器重新模糊画布上方的每块毛玻璃面板。
- 首页请求 `powerPreference: 'high-performance'`，会在双显卡笔记本上唤醒独显；并且在 2× 缓冲上再开 4× MSAA。两个场景都没有
  区别对待软件光栅化。

## 决策

- **拆分环境场。** 第一遍把 `n`、`n2` 以 16 位定点写入 RGBA8 目标，目标在右侧和上方各多出一个 ridge 步长。第二遍按纹素精确
  读取 `n`、`n2` 和两个差分点后着色。差分点仍是完整 `warped()` 的差值，满足 filigree 规则，因此每次采样每像素约两次
  `warped()`。步长取整到缓冲像素（1620px 时约 27px，变化 < 2%）。分配失败时保留单遍程序。
- **真正生效的回压。** 优先 WebGL2 上下文。有 `EXT_disjoint_timer_query_webgl2` 时用它；否则用 fence，并扣除廉价呈现帧后
  参考 fence 的延迟。fence 状态要在 GPU 完成后、经过一段随浏览器而异的延迟才对脚本可见，扣固定一帧会误伤快 GPU。
- **呈现。** 混合帧上限 60fps（单次采样 ≥ 25ms 后为 30fps），与屏幕当前帧相同的不重画。原有的 12ms 阈值过去从未触发，因为读不到计时器。计时生效后，它让 M2 Max 在 dpr 2 下降到约 38fps，所以阈值改为只针对被环境场跑满的 GPU。
- **软件光栅化。** 两个场景都只画一帧静止画面（与减少动态效果相同的路径），不再让每次采样耗掉所有核心数秒。
- **首页。** 交给浏览器选默认 GPU；缓冲低于 2× 时才请求 MSAA。

## 未采用的方案

- 更便宜的 hash（纯算术或预计算噪声纹理）。SwiftShader 下打包四角纹理约快 25%，真实 GPU 上大概更多，但会改变环境场调校时
  所依据的具体噪声图案。这是需要负责人做的视觉决定，不是性能捷径。
- 降低环境场分辨率、全局降低采样率，或解析梯度。前两者被 marketing-shell 规则排除；解析梯度对高频八度的权重与 0.016 步长
  不同，会改变 filigree。
- 首页滚出 hero 后暂停。固定场景在后续每个区块后面仍然可见（变暗）。

## 验证

- SwiftShader，960×540，两个时刻，深浅两种主题：重构后的单遍与旧 shader 逐位一致。拆分版每通道最多相差 2/255（均值 ≤
  0.061/255），每次采样成本约为 0.55 倍（约 400ms 对 690–780ms）。
- 无头 Chromium 打开 `/price`，把渲染器字符串伪装成硬件 GPU：走 WebGL2、拆分和时间混合路径，fence 回压在慢设备上会拉长采样
  间隔。不伪装（软件渲染）时只画两次后进入空闲：约 0.01 个 CPU 核心，之前为 1.62。
- 首页 2× 下 MSAA 开与关：地形、珊瑚和水母的 2 倍放大截图看不出差别；SwiftShader 下每帧 CPU 成本下降约 35–40%。
- 真实 GPU（M2 Max、5K Retina、Chrome Metal、dpr 2，每页 30 秒，整机 GPU 读数，空载基线 12–17%）：`/price` 36–40% →
  约 22%，`/changelog` 约 31% → 约 16%，`/download` 约 42% → 约 25%，首页 17–18% → 约 15%。WebGL2、拆分路径和 GPU 计时器
  均生效，未见画面变化。该轮使用的是 12ms 阈值（混合帧约 38fps），25ms 阈值未重新实测。
- 未测量：功耗（需 sudo）、120Hz 屏、低端核显、Safari、Firefox。
