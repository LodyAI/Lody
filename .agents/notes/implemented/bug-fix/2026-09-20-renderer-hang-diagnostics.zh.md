# 在询问用户前采集渲染线程卡顿证据

Status: implemented
Translation: current

[English](2026-09-20-renderer-hang-diagnostics.md)

## 摘要

如果渲染线程在原生警告框打开期间恢复，Wait 仍会无条件启动计时器，导致持续误报。
现在 watchdog 维护独立的当前卡顿状态，计时器和弹窗结果都遵循事件生命周期。
主进程在首次检测时采集本地 JavaScript 调用栈和 macOS 原生线程采样，以定位执行中的
代码，避免把反复弹窗当作持续阻塞的证据。采集有明确上限且尽力而为；无法还原此前
没有留下证据的历史卡顿。

## 决策与限制

纯逻辑 watchdog 保证每个窗口最多一个弹窗，恢复、导航和销毁使卡顿失效，替换了
恢复状态中旧的无响应计时器。[既有崩溃恢复决策](2026-09-16-renderer-crash-manual-recovery.zh.md)
保持有效：诊断采集不会自动重载渲染进程。

Electron 39 的 `collectJavaScriptCallStack` 能中断正在执行的 JS，而普通渲染线程
日志回调做不到。它需要启动早期的 Chromium feature 开关和 Document-Policy 响应头，
file 协议产品文档也需要。每个会话只有一个钩子，仅对受信任产品主文档启用。
不挂载调试器，不新增异常或调用栈遥测。未结束的 API 请求不会重复发起；原生线程
采样提供补充证据。

`renderer-hang.jsonl` 串行写入，按 UTF-8 字节数轮转，抓栈与恢复事件不会互相覆盖。
事件编号、PID、窗口状态、CPU/内存和用户选择帮助区分持续卡顿与已经恢复的窗口。
CPU 是进程测量值，不是根因判断。原生采样限制数量、大小、并发、时长和频率。
记录路由时去掉查询参数；调用栈文件仅作为本地诊断保存。

## 验证

确定性测试覆盖弹窗期间恢复、持续卡顿、新卡顿替换、导航、关闭、用户明确操作、
抓栈超时和并发日志轮转。Electron 包的 162 项测试通过。独立隐藏 Electron 39 探针
使用实际诊断实现，捕获了合成阻塞循环的函数名、文件行号和 macOS 原生线程采样。
这不等于已在安装的生产应用中复现；压缩后的函数名可能需要 source map 还原。
