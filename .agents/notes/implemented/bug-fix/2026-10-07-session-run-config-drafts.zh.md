# 会话运行配置草稿在切换标签后保留

Status: implemented
Translation: current
PR: [#1287](https://github.com/LodyAI/Lody/pull/1287)

[English](2026-10-07-session-run-config-drafts.md)

## 摘要

未发送的 Fast 修改原来由输入组件持有，所以切换标签会丢失。第一版修复却保留了每个访问
会话及其轮次沿革，包括从未修改配置的会话。修订后的设计只保存实际私人字段修改，在本机
发送被接受时消费对应代际。远端轮次更新默认值而不清除本机意图，因此不再需要历史识别
缓存；应用重启仍会丢失草稿。

## 决策与职责

[草案 Spec](../../../../specs/session-run-config-drafts.zh.md) 记录所选私人草稿语义。
有效配置仍是纯派生；稀疏映射按账户、工作区、会话保存修改字段。组件选择器原子和编辑
租约在卸载时释放。字段对象身份就是编辑代际，重复选择同值也会更新；不保留终身 ID
计数或每个访问会话的原子家族。

输入组件只捕获最终 inputConfig 中实际采用的代际。现有 `acceptSessionUserTurn` 边界
在本地写入或进入附件等待队列后确认。绑定作用域的回调卸载后仍可消费捕获字段，而较新
修改和程序化覆盖彼此独立。接受之前失败保留意图，等待发送转为历史不再确认一次。
这沿用[等待发送的职责约定](2026-09-30-composer-pending-send-config.zh.md)。

远端轮次从不消费本地修改，既避免无限增长的沿革集合，也解决中间已接受轮次在重挂载前
被更晚轮次遮蔽造成漏确认的问题。保留旧规则需要更多因果历史或后台观察者；TTL/LRU 则
会悄悄丢掉真实草稿。

确认删除与权威账户退出会清理草稿并使挂载编辑租约失效。稀疏启动核对处理离开期间的删除，
不保活会话文档，也不将元数据缺失视为删除。账户生命周期身份隔离退出后同账户重新登录的
延迟清理。导航和可恢复归档保留意图。Role 目录未知且有手动修改时冻结明确 None，避免
继承不实的 Role 或记忆配置。

## 验证与限制

确定性测试检查实际稀疏状态、标签切换与重挂载、明确关闭、同值新代际、远端基线变化、
延迟确认、接受前失败、删除、账户生命周期及流式更新身份。只读访问与轮次变化不保留
草稿记录；真实未发送草稿不按容量淘汰。不依赖 GC 时机、睡眠或网络竞争。

重构后的 components 套件通过了 557 个文件中的全部 4,888 项测试。随后补充了一个窄范围
旧会话提供方兼容判断，通过全部 24 项元数据测试、组件类型检查及修改文件的类型感知 lint；
此判断之后未再重跑完整套件。仓库类型感知 lint、国际化、导入、平台及公开边界检查均通过。
具体命令在 PR 中报告。沙箱完整 CI 遇到与此修复无关的 CLI 用户目录、Unix
套接字、代理和 WebRTC 限制，已在未修改的 main 上复现。不宣称已完成打包 Electron 验收。
