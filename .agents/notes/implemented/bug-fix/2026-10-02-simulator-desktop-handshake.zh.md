# 不透明桌面来源的模拟器握手

Status: implemented
Translation: current

[English](2026-10-02-simulator-desktop-handshake.md)

## 摘要

打包后的 Electron 从 `file://` 加载界面。它报告的 `window.origin` 为 `file://`，
但接收 iframe 看到的消息来源为 `null`。
模拟器查看器拒绝了这类父页面的初始化消息，因此本地操作已就绪时仍可能黑屏，
最终显示 `viewer=error`，而网页和移动端正常。桌面父页面现在向查看器的精确来源
转交专用 MessagePort，查看器将其绑定到父窗口和操作。网页保留已有的精确来源
协议。此修复需要同时更新桌面界面和 CLI。

## 边界与生命周期

```text
file 父页面 -- init + 转交端口，精确 iframe targetOrigin --> 查看器
file 父页面 <----------- 绑定端口：状态／控制／PNG ---------> 查看器
web 父页面  <----------- 原有精确来源 window 消息 ----------> 查看器
```

null 来源本身不构成授权。首次初始化必须来自精确父窗口，匹配操作 ID，包含布尔
可见状态，并且恰好转交一个端口。绑定后忽略不透明来源的窗口命令及替换端口。
操作和请求校验继续与网页共用；截图及其他回复均不使用 `*`。

界面在 iframe 加载、地址／操作更换或卸载时关闭并隔离旧端口，在重新绑定前结束
待完成命令。回环和隧道地址使用相同协议。没有采用接受 null 后通配来源回复的
方式，因为那不能安全地定位原来的父页面文档。

此修复更正了[模拟器架构记录](../architecture/2026-09-27-ios-simulator-panel.zh.md)
中的握手假设，不改变私有访问凭证和设备租约模型。

## 验证

测试执行实际内联查看器脚本：null 来源在没有合法转交端口时无法启动，绑定后可以
绘制帧并通过端口回复控制和截图。伪造窗口命令、错误操作及替换端口会被拒绝。
React 面板测试覆盖绑定状态／控制回复、刷新取消、旧消息、可见性和卸载清理；
原有网页测试保留。打包 Electron 中完整预览仍需要现场验证。

真实 Chrome 的 file 页面验证使用实际查看器脚本，通过转交端口进入 ready、收到
控制确认并取得 PNG 截图；父页面报告 `window.origin=null`。测试使用合成 JPEG
和控制响应以隔离握手问题，不能代替打包 Electron 的现场测试。

已完成验证：独立公共仓库 `pnpm check`（CLI 3,454 项通过、4 项跳过；组件 4,722 项
通过）、快速检查、格式化及文档检查通过。CLI 按要求使用 2 GiB 堆构建；Electron
界面使用其正常配置的堆大小完成构建。安全、正确性、范围／简化及独立反证复审均
未发现 P0/P1。外层 affected 检查停在公共代码与私有固定版本不一致的校验；本次
仅修改公共仓库，不提交私有 gitlink 或版本清单。

## 更正：Electron 自身来源与消息来源不同

首次补丁仅在 `window.origin === 'null'` 时创建端口。这通过了 Chrome 文件页面验证，
但打包 Electron 仍失败：Electron 43.7.6 报告自身来源为 `file://`，发出的消息来源却
序列化为 `null`。现在界面在 `location.protocol === 'file:'` 时也选择端口。接收端
准入校验和非 file 网页行为均不变。

原有 React 回归测试现在使用真实文件 URL 和 Electron 的自身来源；恢复旧条件就会
失败。使用相同 sandbox/context-isolation 配置的独立 Electron 窗口已连接实际原生
预览，进入 ready 并通过绑定端口返回 PNG。已安装产品仍需重新构建／重启界面；
已包含首次补丁的 CLI 无需进一步更新。仅验证 Chrome 不能证明 Electron 文件来源
语义正确。
