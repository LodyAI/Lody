# 表达无行数的文件变更

Status: implemented
Date: 2026-09-18
Translation: current
[English](2026-09-18-zero-line-diff-display.md)

## 摘要

当 Git 报告文件已变更、但没有新增或删除文本行时，assistant 的文件变更卡片会显示 `+0 -0`。现在卡片会保留该文件并显示“已更改”，正常的行数统计保持不变。这里使用通用文案，因为持久化的 diff 记录无法区分纯权限变更、二进制内容变更或空文件变更。

## 证据

CLI 通过 `git diff --numstat --no-renames` 计算每轮的文件变更。最小 Git 仓库实验显示，可执行位变更会输出 `0\t0\t<path>`，二进制内容变更会输出 `-\t-\t<path>`；当前解析器会把两者都归一化为数字零。过滤零行数记录会隐藏真实变更，而直接标记为权限变更则会声称 `FileDiff` 中并不存在的信息。

## 决策

`AssistantEditedFiles` 把精确的 `add: 0, del: 0` 视为无可用行数的变更，并显示本地化的通用标签。文件行与全为零的汇总共用同一渲染器，两处都不再把零新增和零删除当成有意义的行数统计。有正数新增或删除的记录，以及统计缺失的旧记录，继续使用原有展示。

## 验证

组件测试同时渲染一个无行数的文件和一个普通文本 diff，并验证两种展示。Storybook story 记录了类权限变更、类二进制变更和普通文本变更的例子，供视觉检查。
