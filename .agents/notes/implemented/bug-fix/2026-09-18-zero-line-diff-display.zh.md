# 表达无行数的文件变更

Status: implemented
Date: 2026-09-18
Translation: current
[English](2026-09-18-zero-line-diff-display.md)

## 摘要

当 Git 报告文件已变更、但没有新增或删除文本行时，assistant 的文件变更卡片会显示 `+0 -0`。现在卡片会保留该文件并显示“已更改”，正常的行数统计保持不变。这里使用通用文案，因为持久化的 diff 记录无法区分纯权限变更、二进制内容变更或空文件变更。

## 证据

CLI 通过 `git diff --numstat --no-renames` 计算每轮的文件变更。最小 Git 仓库实验显示，可执行位变更会输出 `0\t0\t<path>`，二进制内容变更会输出 `-\t-\t<path>`；当前解析器会把两者都归一化为数字零。同样的 `0/0` 还会来自空文件创建或删除、关闭重命名检测后拆开的空文件重命名，以及无法安全判断行数的未跟踪文件（例如二进制、超过大小限制、非普通文件、临时读取失败或无效路径）。未跟踪的空文本文件本身也自然是 `0/0`。

Code Collab 在缺失旧侧创建空文件、缺失新侧删除空文件，以及新旧文本完全相同的写入时，也会记录相同的形状。旧数据或不完整历史经过 `normalizeFileDiff()` 归一化时，如果 `add` 或 `del` 缺失或无效，也可能变成零。按路径合并时会保留全为零的记录，从而继续显示发生变化的文件。

过滤零行数记录会隐藏真实变更，而直接标记为权限变更则会声称 `FileDiff` 中并不存在的信息。

## 决策

`AssistantEditedFiles` 把精确的 `add: 0, del: 0` 视为无可用行数的变更，并显示本地化的通用标签。文件行与全为零的汇总共用同一渲染器，两处都不再把零新增和零删除当成有意义的行数统计。有正数新增或删除的记录，以及统计缺失的旧记录，继续使用原有展示。

## 验证

组件测试同时渲染一个无行数的文件和一个普通文本 diff，并验证两种展示。Storybook story 记录了类权限变更、类二进制变更和普通文本变更的例子，供视觉检查。CLI 回归测试覆盖数字和二进制 Git numstat 记录，以及无法读取的未跟踪文件。Code Collab 测试覆盖空文件创建、空文件删除、内容相同的写入，以及全为零的每轮文件变更持久化。
