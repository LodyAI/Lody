# 将分享请求移出对话虚拟行

Status: implemented
Translation: current

[English](2026-09-16-share-request-virtualization.md)

PR: [#755](https://github.com/LodyAI/Lody/pull/755)

## 摘要

待确认的分享请求原来位于对话第一条虚拟行中，查询订阅和编辑器状态也属于该行。
长对话恢复到底部时，这一行可能在查询返回前被卸载，导致完全不显示卡片。
会话界面现在把卡片放到消息视口下方、Virtua 外的限高滚动区域。
确定性模拟复现了旧位置丢失订阅的问题，并验证新位置能接收延迟结果、保留编辑器；
这不代表已经证明所有线上报告都源于此原因。

## 决策

`session-chat-interface.tsx` 负责挂载位置，`leadingContent` 只保留对话来源信息。
分享仍使用原有的工作区、身份和可见性门控、权威查询、人工确认及独立错误边界。
不改变后端或[分享 Spec](../../../../specs/session-sharing.md)中的发布契约。

请求区域最多占用 35vh，单独滚动，避免多个待处理请求占满消息视口。
相比保留不可见的首行，这也让审核入口出现在输入框附近。
编辑器仍由卡片组件持有，但不再因消息滚动而消失。

这是对[查询错误隔离](2026-09-14-share-request-cards-query-isolation.zh.md)的补充：
先前的修复处理查询抛错，此次修复保证订阅组件持续挂载。

## 验证与限制

`session-share-request-cards.test.tsx` 使用真实 React、Virtua 和请求卡片组件，
在 jsdom 中注入合成查询 store，以及显式的测量和滚动信号。
60 条合成消息、400px 视口和 800px 缓冲区使首行在恢复到底部后离开渲染范围，
查询结果在此后才送达。旧的首行位置会丢失订阅且不出现卡片；新的兄弟节点位置
可以显示待确认卡片、打开审核，并在确认状态变化和滚回顶部后保留编辑器。
测试没有真实等待或网络请求。

分享套件 5 项测试、已有 Virtua 滚动套件 2 项测试和组件包类型检查通过。
模拟验证了两种挂载方式，没有挂载整个会话页面；线上查询和打包客户端的视觉验收
仍未覆盖。文档检查仍会遇到当前工作树中其他未初始化 ACP 子模块的失效链接。

## 消融实验

测试文件从 273 行减至 252 行，没有删除行为用例。移除自定义的 `scrollTop`、
`scrollHeight`、`clientHeight` 后，5 项分享测试全部通过：ResizeObserver 已提供
视口尺寸，jsdom 自带的 scrollTop 足够使用。移除 `offsetParent` 模拟后，两个
虚拟化用例失败，因此保留它并改为 getter spy。清理统一放到 afterEach，先卸载
root，再恢复全局状态；删除重复卸载和重建 root、手写属性恢复及无用的兄弟包装节点，
7 项测试仍通过。

将查询订阅替换成普通快照后，新位置的延迟卡片可见性断言失败（4 项通过、1 项失败），
因此恢复订阅。初始渲染改为断言消息内容，而不是订阅数量。这些测试不测量 CSS 布局，
不能据此删除生产界面的限高或对话列容器。
