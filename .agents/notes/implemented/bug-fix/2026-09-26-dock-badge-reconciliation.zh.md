# 从工作区绝对状态纠正 Dock 角标

Status: implemented
Translation: current

[English](2026-09-26-dock-badge-reconciliation.md)

## 摘要

侧栏已无未读时，Dock 仍可能保留数量。原有上报已经替换绝对数量，但只在计数变化时触发，
清零投递失败或 renderer 遗留的贡献没有可靠的修复机会。现在 renderer 复用侧栏的父子会话
活动规则计算统一数量，变化时立即上报，每 30 秒及恢复焦点／可见时重发完整快照。
主进程在 renderer 崩溃或文档导航时移除其贡献。纠偏修复的是投递偏差，不能补齐尚未到达的
上游元数据；后台节流和休眠可能推迟间隔，原生 Dock 行为仍需桌面冒烟验证。

## 决定与证据

- `sessionListAtom` 的相等比较遗漏 `isTabClosed`。仅关闭标签时，列表保留旧的未读对象，
  直到其他参与比较的字段改变。补齐该字段，让关闭和重新打开正确传递给列表消费者。
- `workspaceBadgeAtom` 使用完整的活跃会话元数据及现有侧栏活动汇总，包含子标签与侧聊。
  当前用户拥有的每个顶层行最多计一次，权限等待优先。原有计数只检查父会话，遗漏子会话的
  未读／等待；这修正了[已关闭会话记录](2026-09-21-closed-conversation-unread.zh.md)中
  关于窗口角标的结论。
- 定时器读取当前 atom 状态，数量变化不重启计时。即使零值没有变化也必须重发，否则只监听
  变化的 effect 无法重试失败的清零。IPC 失败被捕获，下次纠偏重试当前快照。
- 主进程仍替换单个窗口的贡献，再汇总所有有效贡献。renderer 崩溃／重载不能执行 React
  清理，因此通过原生生命周期事件移除旧贡献。同文档导航保留计数。重复快照沿用已有的
  权限等待从无到有时才跳动的规则。

不引入增量计数，不修改已读回执，也不重置未读状态。
[桌面窗口 Spec](../../../../specs/desktop-windows.zh.md)保持 draft，记录纠偏契约。
标记已读所需的窗口可见性／焦点策略是独立问题，本次不修改。

## 验证

确定性回归测试驱动真实 Jotai 元数据／presence、React hook 和 `WindowBadgeService`，
注入 Dock 与 IPC 传输。覆盖关闭、重开、归档／已读、子会话等待、presence 过期、清零投递
失败、不变快照纠偏、定时截止点、可见性／焦点恢复、卸载、登出和遗留窗口贡献。
已有元数据选择器和侧栏测试继续负责列表行为。未启动原生 Electron。

使用当前源码、临时 Vitest 配置和复用的依赖，45 项定向测试全部通过。
修改代码的 lint／格式检查及平台边界检查通过。复用的依赖安装不完整，组件全量类型检查
未通过；文档／公开边界检查报告本检出缺少 ACP 子模块，均不在修改文件内。
不声明完整构建或根目录测试套件通过。
