# 移动端重命名当前选中的会话

## 摘要

移动端 Rename Chat 在选中子会话时仍把父会话传给弹窗，造成 #1900。修复复用现有
当前会话处理函数，以一个局部可用条件统一菜单、桌面工具栏、命令和执行入口。
比较解析出的元数据 ID 与选中标签 ID，可以替代草稿和待加载子标签的两个独立判断。
生产代码片段的定向实验支持这项精简，但不代表已经完成完整页面或设备验收。

## 决策与证据

在基线 `789b4e14` 上，选中草稿或待加载子标签时，`activeTabSession` 会回退到
父会话。最终条件为：

```tsx
activeTabSession?.id === activeTabSessionId &&
  !activeTabSession.isArchived &&
  (!isMobile || !hasActiveViewerTab);
```

可选链 ID 比较排除了元数据缺失、草稿、空选择和待加载子标签回退父会话的情形。
复用现有 viewer 判断：手机文件抽屉不会替代会话画面，桌面侧面 viewer 也不阻止
操作。即使展示入口已经隐藏，处理函数内部仍需要执行保护。沿用现有弹窗的目标
快照和 `updateSessionTitle` 写入链路，无需新增选择器模块、hook、memo、effect 或状态。

确定性实验转译并执行实际生产代码中的路由、目标解析、菜单构建、命令和工具栏
回调、弹窗提交及标题写入，以合成元数据承接写入。14 个场景各检查三条入口，
共 42 项检查，包含写入失败和弹窗打开后切换标签。断言检查弹窗目标和元数据
序列化后的状态。

| 变体                                       | 通过检查数 |
| ------------------------------------------ | ---------: |
| 原始 main                                  |      29/42 |
| 完整条件，或单独删除草稿／待加载判断       |      42/42 |
| 同时删除草稿、待加载判断，保留精确 ID 比较 |      42/42 |
| 最终条件删除 ID 比较，保留空值保护         |      36/42 |
| 最终条件删除手机 viewer 保护               |      39/42 |
| 最终条件删除归档保护                       |      37/42 |
| 最终条件删除执行入口保护                   |      36/42 |
| 最终条件重新把父会话作为目标               |      24/42 |

同时保留草稿、待加载两个独立判断时，删除 ID 比较也能通过这组检查。最终选择
一个 ID 比较来替代这两个判断。实验结论限于覆盖到的状态域，不能证明未来所有
会话状态的等价性。
