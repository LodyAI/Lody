# 将新建对话附件控件保留在移动端模态弹层内

Status: implemented
Translation: current

PR: [#1038](https://github.com/LodyAI/Lody/pull/1038)

[English](2026-09-27-mobile-new-chat-attachment-menu.md)

## 摘要

移动端新建对话的附件菜单可能挂载在 Vaul 模态弹层的交互边界外，导致菜单可见但无法点击。
现在弹层提供内部浮层容器，放在滚动区域外，并标记为不触发抽屉拖动。
隐藏的文件输入框也随移动端输入区挂载在弹层内。
iOS 真机文件选择器行为仍需用户验证。

## 决策与证据

`Menu.Content` 在调用方未指定容器时默认挂载到 body，原来的
`MobileNewChatSheet` 没有提供容器。这与
[移动端层级说明](../../../docs/ui-mobile.md#stacking)记录的模态边界问题一致。
本次为该弹层接入已有的 `PopupContainerProvider`，保留模态交互保护，
不通过提高 z-index 处理。浮层目标节点与滚动区域并列，避免菜单被裁切；
`data-vaul-no-drag` 防止点击菜单时触发抽屉拖动。

首页和项目页两个移动端分支共用弹层内唯一的文件输入框，桌面输入框保持原位。
文件选择仍在菜单点击时同步触发，文件分类和上传状态不变。
外部文件输入框属于额外的边界隐患，并非已经单独复现的 iOS 故障。

## 验证限制

当前检出未安装依赖，无法运行组件测试和 TypeScript 检查。
真机需验证首页和项目页的新建对话：点击 +、添加附件、选择或取消文件、再次打开选择器；
同时验证 MCP 面板及返回操作，并确认选择后新建对话弹层仍然打开。
文档检查存在原有的未检出子模块链接错误。
