# 将操作进度读写限制在相关卡片

Status: implemented
Translation: current

[English](2026-10-17-local-operation-progress.md)

## 摘要

协调器更新进度时，原先先导出整份对话预检查，实际变化时再次导出。现在只选择该操作的系统进度卡片，每张读取一次，并在原位置应用通过验证的修改。内容比较也不再将 Loro 对象键顺序差异视为变化。真实 Loro 回归测试禁止读取无关正文和导出整份历史；文档变化后仍需扫描标量索引，每张相关卡片为保留旧格式及未知字段仍需一次独立转换。

## 决策

[子代理窗口优化](2026-10-16-subagent-history-windows.zh.md)覆盖 ACP 输出，不覆盖协调器进度卡片。新的 HistoryWriter 命令复用原有进度规划和验证，不另建写入器。目录只索引卡片 id 和 system 角色；操作数量、frontiers 和未提交事务长度用于在未知写入、导入、checkout 和未提交修改后使缓存失效，不新增订阅生命周期。

每个命令对每张相关卡片最多转换一次，保留未知字段及旧内联数据，禁止全历史回退。所有修改先验证，再原位更新容器、从后向前删除重复卡片、在历史末尾追加新卡片。无变化时不提交。内容比较复用历史写入的相等判断，忽略对象键顺序。

只缓存旧预检查，仍会在文档变化后导出无关 transcript；仅删除预检查，通用写入仍与整份历史大小相关。限制到相关卡片才能同时消除两部分开销，且无需改变存储或完成语义。

## 验证

扩展现有共享操作测试，覆盖创建、重复无变化更新、终态、重复及内联卡片、兄弟容器与未知字段保留、跨副本导入、未提交结构修改，以及删除重复卡片前的验证失败。恢复旧路由后，测试以 `full history exported` 失败。共享包全部 1509 个测试通过；CLI 进度和历史存储两组 59 个测试，以及派发、Inbox、设置三组 170 个测试通过。共享包及工作区类型检查、静态边界与 lint 检查、格式化通过。文档检查仍有未初始化 Kimi/Pi 子模块造成的 6 条既有断链，无新增错误。完整 `pnpm check` 跑到 CLI 4270 个测试通过、1 个 Git transport 测试以 `context_unreadable` 失败；恢复原始源码也能复现该失败，因此不宣称仓库完整检查全绿。

合成文档含 512 轮、8.19 MB 文本，每条路径执行 20 次：实际变化的中位耗时从 8.31 ms 降至 0.46 ms，无变化从 2.69 ms 降至 0.012 ms。含标量索引扫描的首次局部读取耗时 0.88 ms。旧路径也使用修正后的内容比较，因此该实验隔离了局部读写的收益。这些本地数据不证明 daemon 或网络延迟。
