# 恢复暂时性的 GitHub 策略查询故障

Status: implemented
Translation: current

[English](2026-10-01-github-policy-recovery.md)

## 摘要

GitHub transport 在任何远端操作之前查询身份策略，包括公开依赖下载。
因此，暂时性的 broker 故障会在选择凭据之前中断 Git、UV 和继承环境的钩子子进程。
共享 runtime 现在对这项只读查询重试一次，并输出安全的故障类别。
个人、机器主人本地凭据、App 的优先级保持不变；持续故障仍然阻止执行。

## 决策和证据

本修复扩展[逐命令凭据选择](../architecture/2026-09-26-github-command-credentials.zh.md)。
连接故障、超时、broker 状态文件缺失和 HTTP 500/502/503/504 在 250 ms 后重试一次，
每次尝试传入原有的 10 秒请求超时。每次请求重读工作区 broker 状态，
两次尝试都使用 helper 最初捕获的请求者上下文。
认证拒绝、上下文撤销、成功响应中的无效策略、凭据选择及实际 Git/gh 操作不进入此重试循环。
stderr 只输出允许列表中的错误码和 HTTP 状态；异常消息与响应正文可能含有秘密。
不引入旧偏好缓存或匿名优先路径，因为这些做法可能绕过新选择的个人身份。

使用生成的 transport 和真实 Git/Make/UV 注入合成故障，确认策略 503 会阻塞公开依赖，
清除注入配置后相同依赖可以获取，而后续继承原环境的子进程再次失败。
恢复策略服务后，无需改变环境即可成功。钩子实验使用 shell 子进程，
没有执行真实 agent Stop 生命周期。

Runtime 测试覆盖恢复后的个人/本地/App 优先级、有界且脱敏的失败信息、重试之间的请求者撤销。
真实 Git 递归子模块克隆在首次查询收到 503 后轮换 broker token，
验证恢复过程会重读工作区状态并完成 checkout。
这些夹具不能确定某个已部署身份服务失败的原因。
持续的授权或服务故障仍需依据现在可见的错误类别继续调查。

修复前后的故障注入还使用相同的生成 transport 和公开依赖验证真实 Git 与 Make/UV 恢复。
旧 runtime 在有界的暂时故障场景中失败，修复后可以完成。
生成的 gh 测试验证恢复后仍优先选择个人身份，且尚未执行实际写入。
初始化固定版本的 ACP 子模块后，runtime、Git transport、broker 和 gh 四个套件的
89 个测试全部通过。gh transport 仍有已有的限制：收到响应头后就清除中止计时器，
fetch 异常被转换成空响应。因此这里只保证重试次数有界，
不保证 gh 端到端耗时有界，gh 连接错误仍可能仅提示 broker 不可用。

## 后续调查（2026-10-03）

源码检查和确定性的 VM 故障注入确认：该修复缓解重试故障，没有消除可用性依赖。
策略查询首次失败、第二次成功后可以选择机器主人本地凭据；连续两次 HTTP 500
则在本地凭据选择前停止。本次验证没有使用网络、真实计时器或用户凭据。
已部署版本和远端故障原因仍未核实。

`GitHubTokenManager.getCredentialPolicy` 每次查询都会调用云端 action。
broker 等待该调用，没有自行设置显式截止时间或合并并发查询；其 `/health`
只报告本地 HTTP 存活。一般上游异常统一变成 `policy_unavailable` HTTP 500，
单凭此状态不能区分上游授权拒绝和服务故障。重启 HTTP listener 不能证明云端
策略访问已恢复；当前实现也没有将客户端超时取消传递给上游 action。

生成的 gh 请求函数收到响应头即清除计时器。使用正文始终未完成的受控 fetch
响应，确认读取 JSON 前计时器已经被清除。这复现的是已有的截止时间缺口，
不是证明它就是某台已部署机器的故障原因。

MCP 的 `local control timed out` 来自本地 IPC 的会话控制或当前调用上下文查询，
默认截止时间为 30 秒。它不是 GitHub 凭据 broker 的响应。并发失败值得关联
daemon 与上游日志，但不能证明 broker 反复重启，也不能证明只有一个根因。

后续工作仍为建议：保留安全的上游故障分类与请求关联，补齐 gh 端到端截止时间，
单独调查 daemon/IPC 存活性。保持个人 → 机器主人本地凭据 → App 的选择顺序。
离线策略租约或显式原生认证模式需要另行设计授权及撤销语义，本次重试修复并未
实现这些方案。完成钩子也应允许报告外部阻塞，避免要求无限重试；本次没有检查
用户的钩子配置或已部署钩子的实际行为。

后续替代实现见[有序身份降级](../architecture/2026-10-03-github-identity-fallback.zh.md)；上述调查描述的是此前的重试实现。
