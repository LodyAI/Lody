# 保留已加载的用量日期详情

Status: implemented
Translation: current
PR: [#868](https://github.com/LodyAI/Lody/pull/868)

[English](2026-09-21-usage-detail-cache.md)

## 摘要

用量日期详情依赖选中日期的实时查询，因此重新查看日期时，已经加载的数字可能再次
变成加载状态，并重新连接查询。共享 Hook 现在持久化有界快照，每次成功获取后一小时
内跳过详情查询。过期数据在刷新期间继续展示，重新挂载设置或刷新页面后也能复用。
缓存仍按登录会话和工作区隔离；代价是最多一小时的客户端数据滞后。

## 决策与职责

`SettingsDataCacheProvider` 持续挂载总览查询，但原来的 `useSettingsUsageDay` 没有
按日期保留结果。可恢复查询 Hook 只保存最后一次已提交的查询快照，无法覆盖
A → B → A 的切换或设置组件重新挂载。

`usage-day-cache.ts` 负责 `lody:usageDayDetails` 的结构校验和持久化，以及应用 store
中的 atom。它为一个登录会话保存跨工作区的最多 128 个快照。Hook 在首次决定是否查询
之前读取本地缓存，再将匹配的响应及完成时间写入。每次响应把条目移到末尾；超出容量
时删除最早存入的响应。显式缓存修复包含新存储键；本地存储不可用时仍能使用内存缓存。

`useSettingsUsageDay` 在对应快照未满一小时时跳过详情查询，成功获取结果后释放订阅。
定时器在到期时刷新选中日期；重新打开过期日期同样刷新。过期不删除快照，从而避免
反复出现空白加载状态，也不需要为所有已查看日期保持订阅。永久缓存会冻结总量并遗漏
延迟上报；每次打开都维持实时订阅又会保留重复请求。一小时从完成时刻开始计时，
而不是到下个整点，因此整点前刚获取的结果也能完整复用一小时。

认证恢复时会话 ID 暂时未知，只隐藏数据，不清空快照。观察到确认退出登录或明确的
会话切换才清空；作用域检查立即隐藏不匹配的结果。即使会话切换发生在设置未挂载时，
其他登录会话仍然无法访问旧持久化缓存。

本次变更扩展了[用量分享报告决策](../feature/2026-09-09-usage-share-image.zh.md)
所述的用量页面，不改变导出卡片和用量计量。

[Spec 草案](../../../../specs/usage-detail-cache.zh.md)承载预期行为，并链接实现和测试。
本次无需修改后端或平台组合。
