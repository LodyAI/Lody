# 修复重新打包后的运行时缓存

Status: implemented
Translation: current

[English](2026-09-22-repacked-runtime-cache.md)

## 摘要

运行时制品可能改变而源码版本号不变，但缓存目录仅包含运行时名称、版本和平台。
旧元数据与新校验信息不匹配，导致 daemon 在启动清理时退出。现在将格式有效但已
过期的缓存视为未安装，通过已有校验下载流程替换。实际启动和安装时非法元数据仍报错，不能启动
不符合当前定义的制品。

## 决策与验证

返回缓存未命中同时覆盖状态查询、启动、显式安装和启动清理。旧版本回退扫描
已排除目标版本，因此不会再次选中被拒绝的制品。仅捕获启动异常会使 Pi 仍然
不可用。为缩小修复范围，本次不迁移缓存目录结构。

回归测试分别改变每个被比较的元数据字段，验证启动清理、替换后的命令内容及
新校验信息；保留非法元数据的拒绝测试。

隔离环境使用实际管理器方法和固定运行时定义，22 个所选测试全部通过；恢复旧的
不匹配异常后，4 个新增用例全部失败。随后在独立副本中安装完整依赖和子模块，实际管理器与协调器测试 39 项通过，
文档检查和桌面构建通过。完整 `pnpm check`（类型、lint、工作区测试、i18n 和
仓库边界）通过。CLI 包在 2 GiB 限制下构建通过；将该限制施加于渲染端
会内存不足，桌面整体构建使用其正常内存设置。

启动清理及紧随其后的更新扫描现在按运行时隔离失败。警告保留运行时名称和原因，
日志写入失败也不会中断维护。权限错误、意外异常和非 Error 拒绝不会阻止后续
运行时清理。非法缓存保留供排查，实际启动或安装仍拒绝它。
