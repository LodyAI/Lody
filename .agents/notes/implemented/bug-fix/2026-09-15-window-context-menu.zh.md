# 桌面窗口此前完全没有右键菜单

Status: implemented
Translation: current

[English](2026-09-15-window-context-menu.md)

## 摘要

在桌面应用里任何地方右键点击都毫无反应：选中对话文本无法复制，输入框无法粘贴，其他输入控件同样如此。Chromium 的右键菜单由嵌入层构建而非 Web 平台本身，因此 Electron 不附带任何默认菜单，Lody 里除图片预览自己的弹出菜单外从未绘制过右键菜单，只有菜单栏的复制快捷键可用。现在每个产品窗口上挂一个 `context-menu` 处理函数，由 `buildContextMenuTemplate` 依据 Chromium 报告的点击信息绘制原生菜单：可编辑区域得到撤销/重做/剪切/复制/粘贴/全选，启用状态由 Chromium 自己给出；只读文本得到复制；图片则让位给渲染进程，使一次点击永远不会叠出两个菜单。标签跟随产品语言而非 Chromium 打包的语言包；菜单栏的编辑项仍然不是如此，这一处不一致被保留。

## 决策

菜单在主进程绘制，并使用 Chromium 的 role。

这正是放在主进程的意义：`{ role: 'paste' }` 由 Chromium 针对当前聚焦的字段执行，因此输入框的 textarea 得到真正的 paste 事件与真正的撤销栈。渲染进程的菜单必须用剪贴板 API 重新实现这些语义，而且在不自行读取剪贴板的情况下根本无法提供粘贴。

先实现过一版基于应用自有 `@/ui/context-menu` 的渲染进程方案，随后否决（保留在 `fix/conversation-selection-context-menu` 分支）。它与侧边栏、终端、文件树菜单外观一致，并且在 Web 上可以让位给更完整的浏览器菜单——但它只覆盖对话消息区。输入框、搜索框、设置项以及其他每个面板都需要各自再包一层，而粘贴在所有地方仍然只能用键盘。覆盖面胜过视觉一致性：报告的缺陷是「右键没反应」，不是「某一个面板里右键没反应」。代价是真实且已被接受的——文本菜单是操作系统菜单，而应用里其他所有右键菜单都是带样式的 Radix 菜单。

三个细节是关键的：

- **图片让位。** `image-export-service.ts` 已经为图片预览绘制原生菜单，由渲染进程驱动，因为只有它持有图片字节。两个处理函数会看到同一次点击，因此 `mediaType === 'image'` 返回空模板。对话里的内联图片因此仍然没有菜单，与改动前一致。
- **空模板不画菜单。** 只有一个禁用复制的弹出菜单看起来像坏了，所以空白处右键保持一贯的无反应。这同时覆盖了 Chromium 报告了选区却不允许复制的情况。
- **只读分支不含 `selectAll`。** 在字段之外 Chromium 会选中整个聚焦文档，在应用外壳里会把侧边栏和其他面板一并卷进来，而不是选中「这一处」。在字段内部它恰好正确，予以保留。

模板构造是纯模块，因此可以在没有 `electron` 运行时的情况下用 `node --test` 运行，与 `image-export-core.ts` 的拆分方式相同。接线位于 `createMainWindow` 中 `installNavigationGuard` 旁边，那是所有产品窗口（主窗口、辅助窗口、引导窗口）唯一的工厂。公共浏览器的 `WebContentsView` 刻意不包含在内：`src/AGENTS.md` 有意让该面保持最小，扩大它是另一个决策。

标签来自 `menu.ts` 的 `translateMenu`，复用渲染进程已经为菜单栏推送的语言，因此中文应用在英文系统上显示「复制」。`common.undo`、`common.redo`、`common.cut`、`common.selectAll` 已加入两个语言文件；复制与粘贴此前已存在。

## 验证与限制

- `context-menu-template.test.mjs` 以纯数据覆盖各分支，并经变异验证：去掉图片守卫或空模板守卫都会使其失败。
- 在 Xvfb 下用真实 Electron 39.5.1 针对一个临时页面驱动，用 `Menu.prototype.popup` 记录传入内容（原生菜单会进入模态循环，探针无法关闭它）。无选区右键不画任何东西；只读选区只画出 `Copy`；textarea 中仅有光标时画出完整编辑集合，剪切/复制禁用、全选启用；该 textarea 中有选区时剪切与复制启用；图片不画任何东西；调用 `setMenuLanguage('zh_CN')` 后同样的点击画出 `复制` 以及 `撤销 / 重做 / 剪切 / 复制 / 粘贴 / 全选`。最后一项正是显式 `label` 覆盖 role 默认文案的证据。
- 粘贴全程显示为禁用，因为无头探针的剪贴板是空的——这本身就说明启用标志在正常工作。
- role 的**执行**没有被驱动：探针无法点击原生菜单项。它与菜单栏编辑项使用的是同一套机制，而那正是应用中 ⌘/Ctrl+C 今天生效的原因。
- 没有重新打包应用，也没有在 macOS 或 Windows 上运行；探针运行于 Linux。
