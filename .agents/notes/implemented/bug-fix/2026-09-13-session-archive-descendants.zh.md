# 归档对话时一并归档其后代

Status: implemented
Translation: current

[English](2026-09-13-session-archive-descendants.md)

## 摘要

侧边栏将来源对话及其创建的对话显示为一棵树，但归档来源后，后代仍保持活跃。
UI 和 CLI 现在共用递归归档选择器，包含子 Tab 与创建出来的独立对话。
UI 在元数据加载完整前拒绝归档，避免静默遗漏部分后代。
恢复和永久删除仍采用较窄的包含关系目标；后代继续拥有独立工作区。

## 决策与证据

本决策部分替代[包含关系生命周期](2026-09-10-session-containment-lifecycle.zh.md)
中的归档规则，保留其删除与来源保证。当前意图见修订后的
[关系契约草案](../../../../specs/session-relations.zh.md)。

选择器为包含关系或精确来源建立索引，去重遍历并防止循环。仅有来源路由根不构成归档边。
UI 对目标关闭终端并写入归档及 idle 状态；CLI 写入相同状态，MCP 调用 CLI。
资源继续由已有 daemon 收敛逻辑处理。重复归档可修复部分归档的树；多文档写入仍非事务，
失败通过显式重试恢复。

原有 hook 与 CLI 测试套件覆盖后代、Tab 来源、无关对话、循环与幂等、元数据未完整，
以及删除根后保留独立对话。恢复保持独立，避免重新激活此前独立归档的工作；
其原有元数据就绪缺口不在本次修改范围。

## 验证

hook 套件 35 项、CLI 命令套件 66 项测试通过。共享包类型检查、修改代码的 lint
与文档检查通过。侧边栏归档失败会显示错误，成功后才跳转页面。
