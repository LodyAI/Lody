# 保留会话创建物化失败的证据

Status: implemented
Translation: current

[English](2026-09-27-session-create-materialization-failure.md)

## 摘要

跨机器创建会话的操作被接受后，目标输入仍可能没有持久化。此前 MCP 首次写入端和租约工作进程都会丢弃物化错误，截止时只返回笼统的超时。现在最后一次失败的阶段和错误消息保存在机器本地 Operation 存储中，并随截止结果返回。这样失败原因可用于后续处理；由于原始 daemon 日志不可得，这项改动不能证明报告中的四次尝试究竟失败于哪个阶段。

## 决定

接受操作时仍先固定目标标识，再进行可能失败的远端工作。首次写入或恢复失败后继续重试：传输错误可能发生在写入成功之后，后续重试应先检查固定的 Turn 是否存在。只有当前持有物化 claim 的写入方可保存有长度上限的诊断，旧写入方不能覆盖新 claim 的证据。目标输入确实持久化后清除诊断。截止时保留 `TARGET_TIMEOUT` 错误码，并在存在记录时附上最后一次失败阶段与错误消息。

如果首次写入失败就立即终止已接受的 Operation，会失去短暂断线后恢复的机会。只写进程日志也不够，因为工作进程可能在截止前重启。

## 证据与限制

[Lody #956](https://github.com/LodyAI/Lody/issues/956) 记录了四次已接受但目标会话未持久化的跨机器创建，而目标本机创建成功。其日志明确是重建资料，不是 daemon 原始输出。代码检查发现 MCP 创建路径与恢复协调器会丢弃具体异常。存储和协调器回归套件覆盖 claim 归属、成功后清理和截止结果。尚未在真实跨机器 macOS 环境验证。
