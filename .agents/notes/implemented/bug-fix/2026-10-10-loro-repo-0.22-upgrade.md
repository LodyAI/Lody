## Abstract

Lody's existing protected Streams factory needs the released SDK contract before a
host can share its room AAD encoder and inspect safe protection failure reasons.
Upgrade the shared Repo catalog from 0.21.2 to the official 0.22.0 registry package,
while preserving the rest of main's dependency graph and current runtime policy.
The existing real-SDK synchronization tests pass with the new package. This makes
the APIs available; it does not install an encryption host or accept product E2EE.

## Decision and provenance

[Upstream #146](https://github.com/loro-dev/loro-repo/pull/146) exports the existing
`encodeStreamsRoomAdditionalData` encoder without changing its bytes, and adds a
readonly `payloadProtectionReason` with six allowed values. Provider messages are
not copied into the public error. Projection does not invoke a reason getter;
Proxy descriptor traps and existing code/retryable reads can still execute.

[Release #147](https://github.com/loro-dev/loro-repo/pull/147) merged at
`7967a5f616ef5fedde87219143348ce92bd889ba`. The normal Test and Release Please/publish
workflows succeeded, and [0.22.0](https://github.com/loro-dev/loro-repo/releases/tag/loro-repo-v0.22.0)
became npm's latest version. Its official archive contains the same 71 files and
uncompressed tar bytes as the reviewed local pack; only the gzip OS header differs
(macOS versus Ubuntu). The lockfile records the registry integrity.

Retain main's Streams CRDT 0.16.2 / Client 0.9.0, Loro 1.16.3 and Flock WASM 0.4.3,
including the distinct SQLite peer graphs and Roost's unrelated Client 0.8.0.
Replace the previous exact release-age exception with `loro-repo@0.22.0` after
source review and registry verification; do not broaden that exception.
Waiting for the normal age threshold was an alternative, but would delay consuming
this already reviewed release. No local tarball or source-path dependency is used.

This follows the [factory decision](../architecture/2026-10-10-workspace-streams-content.md)
and [safe diagnostics decision](2026-10-10-streams-sync-error-context.md).
The factory and diagnostics projection stay unchanged; exposing the SDK reason
field here does not add it to Lody's diagnostic whitelist or define a stop policy.

## Verification and limits

Node 24.21.0 and repository pnpm 10.20.0 install the frozen lockfile. Existing tests
pass: 24 factory cases, 26 adjacent room/wait cases, 52 shared Streams/auth/codec
cases, and four CLI SQLite checkpoint cases. They cover ordinary synchronization,
read-only reconnect, ordinary/protected snapshots, Meta/named Flock identities,
saving before cursor advancement, failed-save retry and asynchronous verification
rejection without skipping failed data. The provider fixture is not cryptography.

A separate official-registry installation verifies all seven ESM entries, public
types, three independent logical-room AAD vectors, and real sync/join rejection for
all six reasons without private text or imported data. That smaller installation
uses Loro 1.10.3 / Flock WASM 0.4.2; the Lody tests use the versions listed above.
CommonJS Streams loading and strict checking of the older Loro declarations without
`skipLibCheck` retain their upstream baseline limitations. This is not an exhaustive
peer-version matrix, a live-service test or packaged desktop acceptance.

Repository validation: `pnpm format`, `pnpm check:quick` and `pnpm run docs check`
pass (existing documentation warnings). `pnpm check` passes full typechecking and
lint; components pass 5,033 tests and Streams RPC passes 124 with three skips. The
shared suite reports 1,358 passed and seven socket-permission failures, so the full
check is not green and later groups, including the full CLI run, are incomplete.
The two failing shared suites pass separately with socket permission; the affected
CLI preview and Git broker suites also pass separately (33 cases). No unrelated
implementation was changed to mask those environment failures.
