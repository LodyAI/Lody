# 隔离损坏的界面证据，保留工作区身份

Status: implemented
Translation: current
PR: [#1964](https://github.com/LodyAI/Lody/pull/1964)

[English](2026-10-27-e2ee-renderer-evidence-recovery.md)

## 摘要

一条坏创建请求会阻塞整个账号的待处理列表，损坏的持久身份标记也让准入重试失效。现在逐条隔离无效请求并保留原文。准入 Retry 和原生账本入口可从主进程独立验证的身份重建损坏标记，替换前先归档原文。有效身份冲突继续拒绝，需要核对身份或后续配对；服务端元数据不能提供替代 pin。

## 决策与边界

流程由现有[引导文档](../../../docs/e2ee-workspace-bootstrap.zh.md)说明。此次恢复不改变账本、密文、credential 或已有证据格式。请求必须与规范的账号/请求 key 一致；无效条目原样保留，精确 key 的保存和清除仍拒绝损坏或改变的原文。整个存储无法读取时，依赖持久化的新建仍会阻塞。

原有 host account/status 端口读取自身保留且已验证的账本，不依赖界面标记。恢复在 status 前后检查账号、工作区 ID、当前界面范围、可读 pin、模式证明和已观察 genesis。有效冲突不覆盖。先在独立归档 key 保存并回读所有损坏标记，再替换；额度不足保留原文。清缓存保留归档。原有可选缓存修复与身份替换仍分开。

host 沿用已有 status reader，恢复不新增原生 lease 或关闭路径。过期界面请求不能修改其他账号/工作区。恢复失败只影响该工作区，提供身份核对与重新配对指引；其他工作区沿用原有准入规则。遵循[故障隔离文档](../../../docs/failure-containment.md)，不新增运行时 owner 或整个账号的阻塞。

## 证据与限制

真实 jsdom localStorage 测试覆盖坏 JSON / key 不匹配与健康、新请求共存、native 同身份恢复与原文归档、有效冲突、账号切换和额度不足。路由测试覆盖界面标记损坏时读取原生已验证历史。新增 pending 测试在原实现失败；禁用 native 恢复后对应边界测试失败。原有 runtime、准入、控制测试继续适用。局部检查不证明真实系统钥匙串、真实配对、打包桌面、私有云组合或生产验收；按要求完整仓库检查交 CI。
