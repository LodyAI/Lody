# Core 问题可见性与等待展示

Status: implemented
Translation: current

[English](2026-10-21-dsh-question-wait-presentation.md)

## 摘要

Lody 把 DSH 的用户问题显示成权限等待，并在等待用户回答时继续附加增长的工作时长。
锁定的 DSH 适配器已经使用携带 Core 元数据的标准 ACP 表单征询；Lody 有意把表单桥接到
现有持久化请求与回答队列。会话现在通过这些元数据识别待回答问题，使用问题等待文案，
并在等待用户时省略实时工作时长。待处理表单也会读取尾部窗口中越过无关加载缺口的已加载正文。
线路协议、存储协议和必须由人回答的约束不变；
真实 DSH 和完整桌面验证与合成回归检查分开说明。

## 决策与证据

[Issue #1786](https://github.com/LodyAI/Lody/issues/1786) 指向
`AgentClient.unstable_createElicitation` 中的兼容桥。
锁定提供方的[问题桥](../../../../packages/acp-extension-dsh/src/user-questions.ts)
已经发送带 `_meta.lody.elicitation` 的 `elicitation/create`。
另建提供方专用通路或增加会话状态，会不必要地改变混合版本行为。
现有问题卡片和回答序列化支持仅有 Core 元数据、没有 Claude/Codex 别名的请求。

活动会话使用与输入区相同的待回答问题判定，并由实时 presence 控制是否显示活动状态。
持久化 `requestPermission` 保持兼容，可见活动文案则区分问题。
警告活动行不再挂载持续增长的工作时长标签；已完成轮次计时和回答持久化保持原样。
桌面收件箱已经检查 `requestKind: ask_user_question`，共享通知目录也已有问题专用文案。
托管推送投递不属于此次本地修复的范围。

本决策补充[问题连续性决策](2026-10-13-question-request-continuity.md)。
当前行为由[实时状态指南](../../../docs/sessions-live-status.md)维护。
测试覆盖 Core 表单解析、真实问题卡片选择及取消、ACP 回答内容，以及确定性的 255 秒等待。
下述合成数据回归同时覆盖已有工具补充元数据与新建合成工具。四个所属套件共 74 项测试通过；
组件类型检查、i18n 检查通过，定向 lint 无错误。系统 Chrome 中四项既有问题恢复浏览器用例通过。
尚未人工视觉复核、运行真实 DSH 会话或完整桌面验证。
根目录格式化通过；`pnpm check` 在构建 Claude ACP 子模块时因其依赖缺失而中断。
仓库文档检查报告十处指向未初始化 Kimi/Pi/Grok 子模块的链接错误，修改文档未报错。

## 历史部分加载时的问题可见性

用户还报告问题卡片缺失时，其他输出仍在实时更新。CLI 先持久化请求，再发布等待 presence，
但界面通过独立通路接收 presence 和历史。`useConversationTail` 返回的连续前缀遇到第一条
未加载正文就停止，因此无关旧正文可能遮住更新轮次中已加载的问题；独立窗口读取的消息列表
仍能正常显示新内容。

Hook 现在同时暴露同一租用窗口内跳过未加载正文、保持引用稳定的 `availableTurns`。
输入区权限队列和活动行问题判定使用这份选择结果。原有连续历史消费者、读取租约、epoch
隔离、缓存归属及存储协议不变，没有引入完整历史镜像或第二条加载通路。

真实 Loro reader/React 回归通过显式 Promise 阻塞旧正文，向已加载的活动轮次同步 Core 问题
和并发文本，断言在轮次结束或释放旧读取之前，文本和表单均可见。两种请求形态在修复前均失败，
修复选择逻辑后均通过；释放阻塞后仍只显示一个表单。这复现了与反馈吻合的具体原因，但不等于
确认用户原始会话当时的确切传输状态。
