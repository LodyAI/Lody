# ACK 投递失败后继续执行已接受的生命周期操作

Status: implemented
Translation: current
PR: https://github.com/LodyAI/Lody/pull/488

[English](2026-09-08-machine-lifecycle-ack.md)

## 摘要

此前 CLI 已准备好重启或升级，但当「已接受」响应无法追加时就永远不会触发退出，其 pending 标志
随后会无限期拒绝后续请求。现在共享的 RPC 辅助逻辑最多尝试投递 ACK 五秒，并在成功、失败或超时
后都继续执行已接受的工作。这一窄修复保留了既有的进程归属与重试限制：客户端可能已超时，而机器
仍在执行已接受的操作。

## 决策与限制

是否接受由既有的 CLI 准备路径决定。投递错误在本地记录；被拒绝的请求仍走普通响应路径，绝不
触发生命周期回调。内部钩子更名为 `onMachineLifecycleResponseSettled` 以反映其新含义。保留
`start.ts` 中既有的一次性退出守卫。

「ACK 出错后清除 pending」被否决，因为远端追加可能在其响应丢失之前就已提交。截止时间限定了
等待；底层追加可能稍后完成，但无法再触发另一次生命周期操作。进程级串行化、跨重启去重与完成态
UI 仍是独立工作。本记录是同一 PR 中
[Windows 启动器修复](2026-09-08-windows-daemon-upgrade.md)的限定范围后续。
[接受契约](../../../../specs/machine-lifecycle-ack.md)仍为 draft。

## 验证

假时钟传输层测试覆盖了：重启与升级在 ACK 成功、重试耗尽、投递停滞后迟到成功或被拒的情形，以及
被拒操作在响应投递成功或失败时的情形。测试断言已接受的工作恰好推进一次且不产生自相矛盾的错误
响应，被拒的工作绝不推进。这些测试不使用真实 daemon 重启、远程网络或真实时钟休眠。

RPC 包通过了 110 个测试（三个可选集成测试被跳过），完整的 `pnpm check` 在 macOS 上通过。既有的
本地 IPC 测试在沙箱外运行以允许创建 socket。Windows 上的执行仍未在本地验证。
