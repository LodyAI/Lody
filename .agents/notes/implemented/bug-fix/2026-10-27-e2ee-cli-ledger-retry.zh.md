# CLI 账本的有界恢复

Status: implemented
Translation: current

[English](2026-10-27-e2ee-cli-ledger-retry.md)

## 摘要

一次验证、冲突或未分类 ingest 错误会持续阻止所有新 seal，直到其他操作显式刷新。CLI 现在最多重新获取被拒后缀三次，保留最后已验证视图，并在正常验证成功前继续拒绝新 seal。显式刷新或重连重新开启有限次数的尝试。持续无效的历史不会变成可接受状态，关闭会取消待运行重试。

## 决策与生命周期

现有工作区 Legacy facade 持有一个刷新任务和一个重试 timer。ingest 失败依次等待 250 ms、1 s、4 s；SDK seal 可提前请求一次剩余尝试，但不等待它，仍返回 `e2ee_invalid_ledger`。并发触发复用现有刷新；显式 `refresh()` 清 timer 并重置次数，已验证的正常推进也重置次数。不跳过失败页，不重置 pin，不发布未验证状态。已有 reader 和本地持久编辑继续保留，次数用尽后等待显式刷新或重连。

关闭同步停止接纳并清 timer，再等待既有 epoch 转换和刷新，最后关闭 Scope/custody。timer 不阻止 CLI 退出；诊断接收方的错误被观察，不会使后台任务产生未处理拒绝。不新增账号或全局封锁，也不新增资源 owner。网络超时仍归云适配器；次数上限不表示原始网络工作已经取消。

只重试存储错误无法修复随后恢复正常的无效/冲突响应，而重新完整验证不会降低安全性。无限重试会对持续坏历史产生无界请求，因此不采用。facade 仍依赖 Promise 云端及应用编排；本次不伪称原生迁移或添加包装 runtime，保留既有登记的 Legacy 边界。

此修复改变 M2 此前仅手动恢复验证/冲突错误的策略。是否接受仍由正常刷新与身份绑定判断。

## 证据与限制

真实 crypto/SQLite 配合假时钟覆盖签名拒绝、原件冲突和注入的未分类 ingest 缺陷，验证恰好三次自动读取、已验证 head/count 不变、seal 持续拒绝、显式重试成功、后台恢复成功，以及关闭后不再读取。签名/冲突场景在原实现上因没有重试而失败。保留已有真实 SDK save queue 场景，包括撤销和换 epoch。具体检查见 PR。

未证明线上云服务、真实 OS 钥匙串、安装版桌面、CLI 打包或生产验收。本地原件/pin 持续损坏仍需独立恢复或身份重置流程；重试不能制造可信证据。
