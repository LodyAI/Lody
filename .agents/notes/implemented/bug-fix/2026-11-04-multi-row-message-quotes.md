# Quote continuous text across response rows

Status: implemented
Translation: current
PR: https://github.com/LodyAI/Lody/pull/2304

[中文](2026-11-04-multi-row-message-quotes.zh.md)

## Abstract

A single response can render its text entries in separate virtual rows, so comparing the endpoints' text containers wrongly rejects a continuous selection. The quote action accepts that selection when both endpoints belong to the same turn and every intervening row is mounted and contains quoteable text. It reconstructs a Markdown snapshot from the selected rendered content, keeping supported formatting for preview and Agent delivery. Cross-turn and incomplete intervals still require separate selections to avoid capturing a misleading partial snapshot.

## Decision and limits

The original [quote implementation](../feature/2026-11-01-conversation-selection-quote-reintroduction.md) treated every separate text container as a separate passage. Sharing a turn identity and verifying the entire virtual row interval permits ordinary continuous selection across response entries without assuming that unmounted, loading, tool, or other rows are prose. The selection-retention system still owns hydration and row mounting; the action checks the interval again on acceptance. This does not introduce source navigation or change quote serialization. Browser coverage uses the production conversation renderer and composer in Storybook; it does not establish physical touch or Safari behavior.

## Follow-up research: selected formatting

The first version of this fix snapshotted `Selection.toString()`, so its quote contained selected rendered text rather than original Markdown. A synthetic Chromium selection containing bold text, a hyperlink, a list, a code block and a table returned plain text with neither bold markers, the link destination, list bullets nor code fences; the table used tabs and newlines. This was a browser experiment on a small synthetic DOM, not a complete test of Lody's Markdown renderer, selection copying, math, or other browsers. Lody's separate math clipboard handling is not invoked by the quote action.

The [VS Code response-selection resolver](https://github.com/microsoft/vscode/blob/e576c7bbeb39772a1d1ebe472545def0d93e6d8b/src/vs/workbench/contrib/chat/browser/responseSelectionResolver.ts) likewise captures `Selection.toString().trimEnd()`; its [quote action](https://github.com/microsoft/vscode/blob/e576c7bbeb39772a1d1ebe472545def0d93e6d8b/src/vs/workbench/contrib/chat/browser/responseSelectionSideChatController.ts) wraps that text as a Markdown blockquote. This source inspection concerns that action, not VS Code's separate copy-as-Markdown feature. On November 4, read-only inspection of installed ChatGPT/Codex desktop 26.1027.61615's packaged `overlay-40c64ef1bda5.js` and `app-initial-18b189e867e7.js` found a range-to-text path that handles selected math and table text specially, with a plain range-text fallback. Its text traversal is not evidence of original Markdown reconstruction; no live app acceptance was performed. [GitHub's documentation](https://docs.github.com/en/get-started/writing-on-github/getting-started-with-writing-and-formatting-on-github/basic-writing-and-formatting-syntax#quoting-text) documents selected-text and whole-comment quote actions but does not establish their formatting fidelity.

GitHub's separate open-source [`quote-selection` implementation](https://github.com/github/quote-selection/blob/f3934361ed0d35b4aaf85b81aa942fce27d223a7/src/index.ts) has a `MarkdownQuote` variant that clones the selected DOM and inserts Markdown syntax; its basic `Quote` variant instead uses plain selection text. This establishes a useful implementation option, not which version is deployed on GitHub or exact fidelity for every partial selection. Codex CLI's [selection-copy implementation](https://github.com/openai/codex/blob/a33fb9751c1e468b0062aae63e8f06e9d75e2376/codex-rs/tui/src/markdown_copy.rs) retains semantic annotations while rendering and serializes balanced Markdown for selected ranges. Its source explicitly distinguishes this from reproducing the original response's source spelling, which is available through `/copy`. This clipboard feature does not establish what the desktop annotation action sends.

The follow-up converts selected DOM to Markdown, retaining partial ancestor formatting and converting supported links, lists, tables, code and math into a single snapshot. It reconstructs semantics rather than slicing the original Markdown: delimiter choice, whitespace, unsupported widgets and partial table structure may differ. The converter excludes UI controls and expands partial formula selections to the whole formula. Conversion failure is reported instead of silently sending plain text. Existing v1 quote snapshots and their serialization remain compatible. Behavioral tests cover conversion and the session input; browser coverage uses the production renderer. A live Agent request and Safari/touch acceptance remain unverified.
