# 保留原生 Git 身份和签名配置

Status: implemented
Translation: current

[English](2026-10-23-native-git-identity.md)

## 摘要

Lody 将机器级身份注入所有者会话，覆盖了仓库身份和条件包含配置。现在，所有者命令
使用原生 Git 配置和环境，成员命令保留请求者署名并关闭自动签名。轮次覆盖项只应用到
新命令环境，不改写仓库配置。已有 ACP 进程仍保留启动时的策略，因此本次修复尚未
解决适配器进程内部的实时身份切换。

## 决策

本次处理 [#1840](https://github.com/LodyAI/Lody/issues/1840)，替代
[有界资料查询说明](2026-09-16-bounded-session-user-identity.zh.md)中的所有者身份选择。
[身份规范](../../../../specs/git-commit-identity.zh.md)仍为草案。
所有者不再获得合成的兜底身份，缺失身份时沿用原生 Git 配置和错误。
Fork 不能复用其他目录中缓存的所有者身份。成员资料查询和中性身份兜底保持原有行为。

Session 将成员署名保存在启动配置之外。在 shell、代理及凭据环境合并完成后，同时
设置作者和提交者，再追加关闭提交及标签签名、清空签名密钥的配置。切回所有者后，
新命令自然恢复原生设置，无需猜测哪些用户配置应该删除。此策略独立于会话所有者的
网络凭据，也覆盖使用原生认证的本地项目。显式 Git 参数仍可开启签名，这不是密钥沙箱。

删除已无必要的凭据策略查询及其重试、超时兼容层。创建流程保留绑定身份前的取消检查；
后续轮次直接根据已冻结的请求者同步判断所有权。本次不新增资源所有权、重启、取消或
恢复协议。剩余逻辑为纯身份选择和环境构造，无需进行原生 Effect 迁移。

不采用删除托管裸仓库整个 `[user]` 段的方案：该操作还会删除签名密钥和
`useConfigOnly`，仓库所在位置不能证明这些值已过期。托管仓库和本地仓库的配置均
保持完整。自动清理需要能够识别 Lody 历史写入值的证据。

## 验证和限制

Session 环境回归用例在修复前失败，修复后通过。真实 Git 提交覆盖仓库身份、条件包含、
关联 worktree、所有者显式环境、缺失身份、成员兜底、无签名提交及标签，以及 native
和 managed 模式下从成员切回所有者的行为。ACP 启动环境捕获验证初始署名和保留的启动
快照。七个聚焦套件通过 421 项测试，包含策略无响应时的启动、启动前取消，以及退出后的
替代会话。仓库级 `pnpm check`、`pnpm format` 和 `pnpm run docs check` 均通过，
CLI 全量测试为 4514 项通过、4 项跳过。尚未替换已安装的应用或运行中的 daemon。
