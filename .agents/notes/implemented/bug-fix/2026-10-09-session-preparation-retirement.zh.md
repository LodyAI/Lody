# 会话预热退出清理屏障

Status: implemented
Translation: current

[English](2026-10-09-session-preparation-retirement.md)

## 摘要

取消预热会在异步清理结束前移除其租约。正式会话冷启动可能复用工作树，随后又被旧预热的迟到清理删除，导致首条提示发送前失败。现在按会话保留退出清理屏障，直到创建与释放结束，冷启动及替代预热都先等待该屏障。代价是部分冷启动延迟增加；若创建或释放永不结束，仍需调用方现有的初始化取消与截止时间处理。

## 决策

`SessionPreparationService` 同时管理可用租约与正在退出的资源。退出先发布屏障，再触发 abort 监听器。即使租约已移除，claim 未命中与 discard 仍返回屏障。替代预热等待同会话的旧清理及被替换请求者的租约；其他请求者不能覆盖同会话的有效租约。关闭流程也等待尚未返回创建结果的退出资源。即使迟到资源未经启动便释放，也会安装就绪 Promise 的拒绝处理器。

Session manager 已在冷启动前等待 claim 未命中或 discard 返回的清理，因此修复归属服务层，而非再加一次目录存在检查。存在检查无法阻止之后的删除。工作树标记的所有权锁仍独立生效；此屏障负责 daemon 内运行时释放与工作目录创建的先后关系。

```text
取消 / 过期 / 失败
  -> 移除可用租约，同时发布退出清理屏障
  -> 等待迟到创建 -> 释放资源 -> 解除屏障
  -> 冷启动或替代预热可以使用工作目录
```

此修改实现[预热交接约定](../../../../specs/session-worktree-lifecycle.zh.md#预热交接)，不改变归档恢复保留规则、跨进程标记所有权，也不会修复已安装应用中已损坏的驻留会话。

## 验证与限制

所属服务测试使用显式 Promise 屏障、虚拟 TTL 时钟及临时目录，覆盖取消、启动和就绪失败、不兼容、迟到资源发布、连续替换、关闭、所有权与容量限制，并确认冷启动创建的文件在旧清理全部结束后仍保留。取消回归用例在原实现上因缺少清理屏障而失败。

当前工作树未安装依赖，ACP 子模块也未初始化，因此通过隔离配置复用本机已有 Vitest 工具。针对性严格 TypeScript 检查将共享 Session ID 映射到其真实源文件。16 个服务测试、针对性严格类型检查、lint 与格式检查通过。已尝试根目录的 `pnpm check` 和 `pnpm format`，但因未安装 `tsgo` / `oxfmt` 失败。未验证完整 CLI、桌面集成及已安装应用。仓库文档检查原本就存在指向缺失子模块的断链，超出本次范围。此处不保存用户对话或原始日志。
