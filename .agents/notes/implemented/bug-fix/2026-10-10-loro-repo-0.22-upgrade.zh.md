## 摘要

Lody 已有受保护的 Streams 工厂，但宿主共享房间 AAD 编码器和读取安全错误原因前，需要先接入正式 SDK 接口。
本次把共享 Repo catalog 从 0.21.2 升到 npm 正式发布的 0.22.0，保留 main 其余依赖和当前运行时策略。
已有真实 SDK 同步测试在新包上通过。此次只使接口可用，不接入加密宿主，也不代表产品 E2EE 已验收。

## 决定与来源

[上游 #146](https://github.com/loro-dev/loro-repo/pull/146) 导出已有
`encodeStreamsRoomAdditionalData`，编码字节不变；同时增加只读的
`payloadProtectionReason`，只允许六类值，不复制 provider 私有错误文字。
投影不会调用 reason getter；Proxy 的 descriptor trap，以及原有 code/retryable 属性读取仍可能执行。

[发布 #147](https://github.com/loro-dev/loro-repo/pull/147) 合入提交为
`7967a5f616ef5fedde87219143348ce92bd889ba`。正常 Test 和 Release Please/publish
流程通过，[0.22.0](https://github.com/loro-dev/loro-repo/releases/tag/loro-repo-v0.22.0)
已成为 npm latest。正式包与已审本地 pack 的 71 个文件和解压后的 tar 字节完全相同；
差异仅为 gzip OS 头（macOS 与 Ubuntu）。锁文件记录 registry 的完整性校验值。

保留 main 的 Streams CRDT 0.16.2 / Client 0.9.0、Loro 1.16.3、Flock WASM 0.4.3，
包括不同 SQLite peer 依赖图和 Roost 独立的 Client 0.8.0。
源码审查和 registry 验证后，把原有精确发布时间例外替换为 `loro-repo@0.22.0`，不扩大例外范围。
也可以等待默认发布时间门槛，但会延后接入已经审查的版本。不使用本地 tarball 或源码路径依赖。

本决定承接[工厂扩展](../architecture/2026-10-10-workspace-streams-content.zh.md)和
[安全诊断](2026-10-10-streams-sync-error-context.zh.md)。工厂和诊断投影不变；
SDK 增加原因字段不等于 Lody 诊断白名单新增字段，也不定义停止同步策略。

## 验证与限制

使用 Node 24.21.0、仓库指定 pnpm 10.20.0 完成冻结锁文件安装。
已有测试通过：工厂 24 项、相邻房间与等待 26 项、共享 Streams/认证/codec 52 项、CLI SQLite checkpoint 4 项。
覆盖普通同步、只读重连、普通及受保护快照、Meta/named Flock 身份、保存后推进游标、保存失败重试，
以及异步验证拒绝后不跳过失败数据。测试 provider 不是真实密码学实现。

另一个从正式 registry 安装的独立环境验证七个 ESM 入口、公开类型、三类逻辑房间的独立 AAD 向量，
以及真实 sync/join 中六类拒绝原因，无私有文字泄漏或数据导入。
该独立环境使用 Loro 1.10.3 / Flock WASM 0.4.2；Lody 测试使用上面列出的版本。
CommonJS Streams 入口、旧 Loro 声明关闭 `skipLibCheck` 后的严格检查仍有上游基线限制。
这不是完整 peer 版本矩阵、真实服务端测试或桌面打包验收。

仓库检查：`pnpm format`、`pnpm check:quick`、`pnpm run docs check` 通过，保留原有文档警告。
`pnpm check` 的完整类型检查和 lint 通过；components 5,033 项通过，Streams RPC 124 项通过、3 项跳过。
共享包 1,358 项通过、7 项因 socket 权限失败，因此不能声称全仓检查通过，后续组（包括 CLI 全量）未完成。
两个失败的共享套件在允许 socket 后单独通过；受影响的 CLI preview 和 Git broker 套件也单独通过（33 项）。
没有为消除这些环境失败而修改无关实现。
