# 移动工作区底部导航的连续动画

Status: implemented
Translation: current

[English](2026-10-05-mobile-workspace-dock-motion.md)

## 摘要

移动导航外壳与子元素的布局动画相互叠加，导致选中图标明显拉伸和位移。已接受的
连续变形方案保持所有带稳定键的标签挂载，并用一个持续存在的弹簧协调实际尺寸、
位置和透明度。向下滚动收起，向上滚动展开，列表与编辑器命令式信号行为一致。
浏览器验证覆盖实际几何与交互；Android 真机和 WebView 性能尚未验证。

## 决策

选择了原型 D，而非复制图标并交叉淡化的尺寸变形方案 B，或整个面板淡化的方案 C。
原方案 A 同时执行布局投影、子项退出缩放和文字／高亮的即时移除。此前 Chromium
探索测量发现，原本 24×24 的选中 SVG 一度约为 88×22，单纯调整缓动无法修复。

生产[组件](../../../../packages/components/src/components/mobile/mobile-workspace-tabbar.tsx)
用一个从展开 0 到收起 1 的弹簧，刚度 420、阻尼 40、质量 1、静止阈值 0.001。
直接改变宽高，不使用祖先缩放或共享布局标识；重新设定目标保留速度。稳定的
观察槽提供可用宽度，可选操作保留 56px 槽位，按钮本身缩小至 48px。派生 MotionValue
驱动几何，无须每帧更新 React 状态。

```text
稳定的底部导航行
├─ 被观察的弹性槽 → 改变实际尺寸的外壳 → 持续挂载的带键标签
└─ 可选的固定 56px 槽 → 改变实际尺寸的新建会话按钮
                       一个弹簧驱动两个分支
```

控件组合 `@lody/ui` Button 与 motion 渲染元素；StyleX 和 UI token 负责布局与内容
样式。选中图标保持不透明且为 24×24。收起时其他标签立即 inert，展开时等它们
可见才恢复交互。在设置 inert 前转移焦点，因为 Chromium 可能在布局 effect 运行
前就清除焦点。没有匹配的选择时保持展开。保留旧 `layoutId` 参数但不使用，消除
跨实例标识冲突。

DOM 与命令式滚动共用方向累计，在反向、来源切换、到顶或点击展开时重置。
命令式信号有效时由其独占基准，即使列表仍然挂载。参见
[行为草案](../../../../specs/mobile-workspace-dock.zh.md)。

交互参考 Apple 的[滚动收起标签栏](https://developer.apple.com/videos/play/wwdc2025/284/?time=151)
与[可中断弹簧](https://developer.apple.com/videos/play/wwdc2023/10158/)。实现采用 Web
几何变化，不实现原生 Liquid Glass 材质。代价是对少量导航元素进行有界布局计算并
保留隐藏标签，避免变换缩放或复制选中内容。

## 验证边界

已执行：13 个 Chromium 浏览器用例、3 个导航组件测试和 9 个现有移动列表测试通过；
范围内 lint、格式和 diff 检查通过。原组件运行几何回归测试时失败：图标宽度为
80.25px 而非 24px。文档检查报告 62 个指向缺失 ACP 子模块的断链，修改的文档没有
错误，也没有已注册的 SHA 保护主题。

所属 Storybook 场景与 Playwright 测试在受控帧步长下采样 SVG 实际尺寸、透明度、
节点身份及外壳内可见性，覆盖两种主题、首／中／末标签、方向阈值、中途反向、
焦点、减少动态效果、尺寸变化和没有新建按钮的情况。组件测试覆盖滚动来源切换、
标签集合变化、没有选择以及实例独立性。浏览器时钟在 Motion 加载前安装，使其
捕获的动画调度器使用受控时钟。尺寸测试等待 ResizeObserver 实际通知，不猜测延迟。
全局减少动态效果 CSS 给每个节点设置了极短但非零的过渡时长；动画驱动的元素明确
使用 `transition-property: none`，避免弹簧跳转后又被 CSS 二次插值。

共享 UI 是公开代码，Android 外壳不是。这些测试不能证明真机帧率或生产窗口性能。
包级类型检查与 Storybook 全量依赖扫描遇到无关的 viewer、ACP、Electron 安装依赖
缺失。根目录格式检查通过；`pnpm check` 在 shared 包类型检查阶段因缺失 ACP SDK
而停止。跟踪：[上游 Issue #1257](https://github.com/LodyAI/Lody/issues/1257)。

## 浏览器性能采样

在 Chromium 145.0.7632.6 无头浏览器、393×852、DPR 1 下，对开发版 Storybook iframe
中的生产组件进行采样。四个场景覆盖 iOS、Material、命令式信号以及无 FAB 的双标签，
分别使用正常速度与 CDP 4 倍 CPU 限速。每个场景记录 240 个真实动画帧，负载包括空闲、
八次滚动目标切换（含间隔四帧的反向），以及每帧 3px 的连续向下／向上滚动。数据来自
CDP timeline／Performance 指标、long-task 观察器和 React DevTools 提交计数器；测量
窗口内没有逐帧读取几何。这些是探索性样本，不是耗时验收门槛。

| 负载 | 正常速度 rAF 间隔 p95 | 4 倍 CPU 限速 rAF 间隔 p95 |
| --- | --- | --- |
| 空闲 | 9.7–9.8ms | 10.1–10.2ms |
| 收起／展开与反向 | 9.5–9.9ms | 10.1–10.3ms |
| 连续滚动 | 9.4–10.0ms | 10.2–10.3ms |

未观察到 50ms 以上的长任务或浏览器错误。最大回调间隔为 17.1ms，没有超过 25ms。
限速的目标切换样本中，单次 layout 事件 p95 最高为 0.79ms，paint 事件最高为 0.671ms。
实际尺寸动画仍逐帧进行布局与绘制，不是纯合成器动画。仅切换动画目标的序列产生
12–30 次 React 根提交，并非每个动画帧都有提交。

连续信号输入明显更重：240 帧内有 343–351 次根提交，DOM 滚动场景为 6 次。4 倍限速
下，信号场景累计 renderer TaskDuration 约为 1.45s，DOM 场景为 0.16–0.29s。这包括
story 每次滚动更新信号的状态和共享组件，不代表真实 Monaco 编辑器或完整应用窗口。
如果真机仍有开销，应优先调查信号路径逐次滚动触发的 React 工作。本次采样没有导致
额外的生产代码修改。

无头浏览器的回调节奏不等于合成器实际呈现帧率。开发模式开销、宿主调度、未校准的
CPU 限速和较小的合成列表限制了结论的推广。Android 真机／WebView、GPU 光栅化与
合成以及生产构建性能仍需实机验证。原始本地结果和 timeline trace 保存在本次性能
采样的临时产物中，没有作为仓库 fixture 提交。
