# 保留侧栏时同步动画主内容区宽度

Status: implemented
Translation: current

[English](2026-09-26-sidebar-content-width-animation.md) | 中文

## 摘要

保留侧栏的修复消除了昂贵的重挂载，但一次性切换弹性布局空间使对话主内容区瞬间跳到
目标宽度，而侧栏仍在滑动。完整宽度的桌面布局现在同步过渡侧栏位移和负右边距，
让相邻主内容区在同一段 220 毫秒动画中连续改变宽度；要求减少动态效果时立即切换。
宽度动画需要逐帧布局，但侧栏仍保持挂载，滚动与行内状态不丢失。

## 决策

- `WebWorkspaceLayout` 在同一个保留挂载的容器上管理两项 CSS 过渡，让侧栏位置与
  它占用的弹性布局空间同步。关闭时容器仍为 inert、`aria-hidden`，侧栏专属数据
  来源继续暂停。
- 主内容区的真实文字和布局需要跟随宽度变化，因此 CSS 过渡会逐帧更新布局；
  仅拉伸或裁剪最终尺寸的画面不能替代。保留并记忆化侧栏子树避免了原先的会话行
  重建。减少动态效果时过渡时长为零；紧凑布局的浮层行为不变。

[先前的侧栏切换决策](2026-09-26-sidebar-toggle-hitch.zh.md)选择一次性切换布局空间来
避免逐帧布局，但这是不完整的体验取舍：侧栏平滑移动时主内容区仍会明显跳变。
本决策只取代该布局动画选择，不改变保留 DOM、暂停专属来源及重挂载时恢复滚动的做法。

## 证据与限制

- 侧栏切换测试检查同步的位移与边距目标、CSS 过渡配置、DOM 同一性、滚动保留及
  焦点行为。五个相关测试套件共 46 项通过。
- 确定性的 Chromium 几何探针把两项 CSS 过渡暂停在 110 毫秒。在宽 1000 px
  的合成弹性布局中，主内容宽度从 720 px 到收起中途的 987.34 px，终点为
  1000 px；重新展开中途为 732.64 px，终点回到 720 px。这证明浏览器会插值，
  但不是完整 Electron 渲染器或帧耗时预算的验证。
- 先前 React + jsdom 切换基准只衡量重挂载工作，不能证明本次布局动画的耗时。
  如果大型主内容区再次卡顿，应先采集打包版渲染器帧记录，再决定交互调整。
