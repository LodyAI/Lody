# 公共页面 URL 使用静态主机的目录形式

Status: implemented
Translation: current

[English](2026-09-30-public-site-directory-urls.md)

## 摘要

带版本号的更新日志 slug 含有点号，旧的扩展名判断因此生成了不带尾斜杠的 sitemap、canonical
和语言替代 URL，但静态主机会将这些页面重定向到目录 URL。普通内部链接也输出不带尾斜杠
的页面路径。现在页面元数据和 sitemap 生成明确处理页面 URL，原生链接与 Fumadocs 适配器
则按照与路由器一致的方式规范化本站页面导航。静态资源、应用路径、查询参数、片段及外部
目标保留原有含义；本地回归检查无需部署，线上行为只会在发布后改变。

## 决策与证据

- `lib/site-url.mjs` 在浏览器代码与 Node 生成器之间共享 URL 处理。
  `absolutePageUrl` 处理已知是页面的 URL，因此版本号或带点号的标题不再被误判为文件扩展名。
  元数据图片使用普通绝对 URL 解析，不应用页面规范化。
- 混合导航使用 `siteHref`：仅规范化公共站点路由，可识别的文件仍保留文件形式。
  [此前导航记录](2026-09-14-docs-web-app-links-leave-the-spa.zh.md)定义的站点与应用边界保持不变。
  透明的 `SiteAnchor` 保留原生链接行为、事件处理器和下载属性。Fumadocs 对站点页面继续使用
  客户端导航，对文件及其他目标使用原生链接。
- TanStack Router 使用 `trailingSlash: 'always'`，避免水合后的导航再次移除 canonical
  元数据与静态链接中已有的尾斜杠。
- 公开源代码可直接复现问题：两个旧 URL 辅助函数都使用 `/\.[^/]+$/` 区分资源，误判了
  `20260929-0.102.0` 等更新日志 slug。此前生成的 sitemap 因此保留不带尾斜杠的 URL。

只修改 sitemap 会留下矛盾的 canonical 与替代标签；只重写预渲染 HTML 则会与水合后的链接
渲染不一致。共享渲染阶段的 URL 规则能同时修复两者，无需修改内容、托管重定向或现有静态
内容与性能架构。

## 验证

行为测试覆盖两种语言的更新日志、canonical/语言替代/Open Graph 一致性、图片资源（含无
扩展名图片）、查询参数与片段保留、外部/应用/文件链接、规范化幂等性以及完整生成的 sitemap。
现有生产构建浏览器扫描还会检查页面与语言替代 URL、所有内部页面链接，以及静态输出上的
真实桌面端和移动端导航。

仅安装站点的冻结依赖不会安装 `tw-animate-css`，但现有样式从整个工作区依赖该包。因此
本地构建验证补充了锁定的 1.4.0 版本，没有修改依赖清单或锁文件。仓库级应用检查依赖与此
任务无关的工作区和子模块安装，不能与公共站点检查混为一谈。

本地结果：54 项站点测试、站点 TypeScript 检查和生产构建均通过。独立 HTML 扫描验证了
246 个 sitemap URL（含 20 个带点号的版本页面）、249 个目录页面以及 8,594 个内部链接。
执行环境不允许 Chromium 创建本地 socket，因此交互式浏览器验证无法启动。仓库文档检查
只报告了 62 个指向未初始化 ACP 子模块的链接；根目录聚合检查在未安装工作区依赖的无关
软件包处停止。这些检查不应标记为通过。
