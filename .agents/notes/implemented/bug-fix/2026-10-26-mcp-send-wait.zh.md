# 限制新对话 MCP 确认等待

Status: implemented
Translation: current

[English](2026-10-26-mcp-send-wait.md)

## 摘要

此前新对话发送按钮一直等待项目 MCP 默认配置就绪，直接提交还会显示加载文案；
目录停滞时可能无限阻塞。现在直接使用已加载的本地快照，远端更新由后台应用。仅本地读取未完成时，
发送内部最多等待两秒，不显示 MCP 专用加载文案。失败保留草稿并使用普通发送错误提示，绝不接受未经确认的空选择。

## 决策与归属

本次取代[原策略](../architecture/2026-10-09-project-default-mcp.zh.md)中编辑器等待远端追平的门槛。
按本次明确要求，选择乐观使用本地配置，不把远端新鲜度作为发送条件。目录 hook 在用户输入时已开始加载；已就绪或显式选择
立即捕获，未就绪的发送借用现有共享目录，在写入首条消息之前从就绪快照捕获默认选择。
所有同步模式均使用已加载的本地快照。Flock 订阅更新后续草稿选择，不改变已捕获的发送 ids。
新副本在收到远端更新前可能只有空或过期快照，这是接受的可用性取舍，不等于读取失败。
CLI/Operation 的写入流程不在本次编辑器修改范围内。

hook 只拥有有界等待者。超时、切换项目或工作区、卸载都会释放它的租约和计时器，
不会取消其他消费者的同步。迟到的目录就绪不能重新提交已超时的消息；下次点击可使用
已完成的快照。目录一直不可用仍会让发送迅速失败；本改动不修复传输恢复，也不另建同步所有者。

直接删除校验会静默写入错误的空选择，永久禁用按钮则隐藏了无限等待。
有界发送流程保留确认，同时及时归还操作权。本次仅修改 React 目录消费者，
不将现有共享目录迁移至 Effect。

## 验证

项目默认 MCP 的现有测试通过真实共享目录覆盖本地延迟读取、缓存默认配置和后台更新、超时后重试、
切换项目取消和显式空选择。选择、目录和 landing 派生状态三个测试集的 106 项测试通过，组件类型检查通过。
定向 lint 和 `pnpm format` 通过。完整 `pnpm check` 在 CLI 类型检查处因当前检出
缺少 Claude/Codex/Grok/Devin ACP 子模块及 Claude SDK 清单而停止。文档检查保留
31 项既有子模块链接错误，没有新增错误。打包桌面交互尚未验证。

## 消融证据

每个变体均运行相同的选择、目录与 landing 派生状态测试集。保留的删除逐项累积；
破坏性变体从清理后的基线分别开始，验证后独立恢复。

| 变体                                     | 结果                 | 决定                           |
| ---------------------------------------- | -------------------- | ------------------------------ |
| 加强确定性取消断言后的基线               | 106 项通过           | 基线                           |
| 删除无人使用的 `defaultsFailed` 返回字段 | 106 项通过           | 保留删除；调用方观察发送拒绝   |
| 删除 hook 层重复的失败检查               | 106 项通过           | 保留删除；目录快照负责报告失败 |
| 可选可变清理句柄改为确定的租约和计时器   | 106 项通过           | 保留简化                       |
| 删除作用域切换和卸载取消                 | 3 项失败，103 项通过 | 恢复取消                       |
| 删除发送等待期限                         | 1 项失败，105 项通过 | 恢复期限                       |

原项目切换测试等待任意最终拒绝，可能把期限到达误当成取消。现在用假时钟且不推进时间，
断言项目切换、工作区切换和卸载立即取消；期限测试在明确推进时钟后断言完成。
这些测试验证发送结果，不检查源码形态或 mock 调用次数。共享目录在 acquire 期间不
同步调用监听者，因此检查初始快照前，清理所需的租约和计时器已经确定，无需第二份
失败标记或可选清理句柄。
