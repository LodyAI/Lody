# 按因果版本确认队列更新

Status: implemented
Translation: current

[English](2026-10-27-queue-signal-before-content.md)

## 摘要

回合结束后，如果元数据先于控制文档中的消息行到达，排队消息可能失去自动调度触发。
后台根据暂时为空的队列确认信号并移除订阅。现在队列写入方在修改后携带 Loro 因果前沿，
后台只有观察到该信号对应的版本且队列为空时才确认。真实文档回归测试在两种到达顺序下均通过。
没有凭据的旧客户端会保守地保留监听，以额外的空闲订阅换取不静默漏发。

## 原因与修正

`createDirectWorkspaceWriter` 先写 `mq`，再通过另一同步平面写元数据；本地顺序不保证远端
到达顺序。仅队列激活没有待处理用户回合指针，因此不进入调度器的历史等待分支。
此前 `markMessageQueueSignalChecked` 没有证明对应更新已到达，就根据空队列确认信号。
其他激活理由结束后，`reconcileSessionWatch` 移除控制文档和历史订阅，晚到消息便可能滞留，
直到编辑发布新水位才恢复。

```text
队列修改 → 捕获控制文档因果前沿 → 发布水位与前沿
  → 后台收到元数据 → 版本缺失时保留监听
  → 内容到达 → 提升并执行队列消息 → 队列清空后才确认
```

写入方在释放存储或允许其他编辑介入之前捕获 `messageQueueUpdateVersion`，其中包含既有水位
和控制文档因果前沿，不增加历史读取、内容复制、网络等待或控制文档根字段。后台用已应用文档
版本（`version`，而不是仅操作日志）检查全部前沿操作。不同水位的凭据不能确认新信号。
编辑、提升或执行阻塞的队列行继续遵循原有规则。OSS 迁移随其他调度元数据一起清除此凭据。

[此前的队列修复](2026-10-26-dead-turns-and-orphaned-queue.zh.md)保护已存在于本地的消息，
本次进一步保护尚未到达的内容。固定延迟、确认本地待上传操作为空或全局扫描，都不能证明
某个特定的入站控制修改已经到达。

## 所有权、兼容与边界

既有 watcher 为每个已激活会话拥有一个控制文档和历史订阅。本次没有新增计时器、Fiber、重试循环、
注册表或阻塞式就绪等待，不影响其他会话推进。版本暂时缺失时保持待处理，由正常文档交付触发
下一次检查；归档、删除、转移机器归属和 watcher 停止仍按既有路径释放订阅。停止与编辑语义不变。
这是既有 Promise 编排中的同步因果检查；迁移到原生 Effect 会扩展到尚未完成的 Repo/watcher
边界而不能帮助本次修复，因此未包含迁移。

混合版本下，缺失凭据或旧水位残留的凭据均不能作为证明。即使观察到空队列，后台也保留其激活信号，
直到后续带版本的队列修改可以清除。旧客户端如果仅删除队列，可能留下空闲监听，直到发生上述释放
边界。这是明确的兼容成本，不代表交付时间有界或同步成功。旧后台已经确认的孤立信号仍需要新的激活；
本次不扫描全部历史会话。旧后台忽略新凭据，需要升级才能获得修复。

## 验证

- 现有 watcher 测试使用真实 `SessionDocument`、Loro 副本、控制 Mirror 和历史后端，显式控制
  元数据与二进制更新交付。内容先到和元数据先到两种顺序，在有无版本凭据时都执行队列消息一次并
  清空队列。修复前元数据先到的用例失败：未执行、消息仍在队列。
- 确认测试覆盖缺失凭据、控制内容未到、凭据水位过期，以及远端入队再删除最终为空的情况。
  它替换了此前仅断言 mock 调用的空队列确认测试。
- 写入器测试覆盖入队、编辑、重排和删除：旧副本不包含凭据前沿，导入更新后前沿和队列结果均一致。
  测试不使用网络或真实等待。
- 完整 watcher 测试 64 个通过；完整 workspace-writer 测试 12 个通过；调度判定、队列编辑文档行为
  和 OSS 迁移测试共 49 个通过。修改代码的格式与 lint 检查通过，CLI 和 components 类型检查通过。
  Agent 执行和传输仍为注入边界，未声称验证打包桌面、真实 Provider 或某次用户现场故障。未使用捕获的用户数据。
