# 定时任务运行配置保留 ACP 类型

Status: implemented
Translation: current

PR: https://github.com/LodyAI/Lody/pull/1306

[English](2026-10-08-schedule-typed-run-config.md)

## 摘要

定时任务复用了会话控件，却采用仅允许字符串的持久化 schema。默认值、控件
回调和提案因此把 ACP 布尔值字符串化；界面再转回来，普通会话执行校验则拒绝。
现在任务复用 ACP 值 schema，UI 引用类型从共享任务契约派生。基于目标能力的
兼容投影保留旧定义及授权指纹；协议 v2 阻止新客户端向旧守护进程写入其不支持
的带类型配置。

## 决策

此前的[机器级定时任务决策](../feature/2026-09-24-machine-owned-scheduled-tasks.zh.md)
复用了视觉控件，但适配层和测试仍固化了第二套值契约。复用必须覆盖默认值、
编辑、Role/会话提案、Loro 存储及准备好的会话轮次。字符串与布尔值保持原始
类型，凭据过滤和大小限制保留。

无条件转换 `"false"` 会损坏 select 值；读取时重写旧任务会改变 Registry 指纹
和冻结的运行定义。因此由一个共享投影仅在目标声明 boolean 类型时转换精确
的布尔字面量，用于 UI 显示和任务进入会话的边界。其他值继续由普通会话校验。
不引入 provider 特例、权限绕过、重置尝试次数或重放已提交工作。

守护进程声明 schedules v2，已有写入和执行门禁要求此版本；旧目标仍可查看、
暂停及删除。新守护进程可读取旧定义及待执行记录。部署时必须先更新所属机器
的守护进程，新客户端才能编辑或执行该机器的任务。

## 验证

回归覆盖默认值与提案的类型保留、凭据/非法值拒绝、Loro 快照传输后 Registry
指纹一致、旧值投影不修改原数据、旧守护进程保存门禁，以及真实会话准备路径
中的新旧布尔值和 select 字符串。非法布尔值仍被普通校验拒绝。定向测试（121 项）、shared/components/CLI
类型检查、改动文件格式和类型感知 lint、文档检查通过。全仓库类型检查、lint、
格式化、i18n 和边界检查也通过。`pnpm check` 在会话注入的 Git 包装环境下
因无关的原生 Git transport 测试中断（CLI 3503 项通过）。移除注入的 Git
变量并使用系统 Git 后，该测试套件 6 项全部通过；未重跑剩余全量套件。
未执行或改写用户实际任务。
