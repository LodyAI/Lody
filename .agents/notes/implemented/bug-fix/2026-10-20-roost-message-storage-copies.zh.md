# Roost 状态与批处理回执中的消息副本

Status: implemented
Type: bug-fix
Translation: current
Date: 2026-10-20

[English](2026-10-20-roost-message-storage-copies.md)

## 摘要

封存后的消息修正此前会把整条消息复制进状态和 SDK 命令回执。现在状态只记录相对指定已封存 primary 的操作，执行机器使用 Roost 的本地批处理恢复日志。含 432 KiB 不变正文、修正 32 次的合成用例，其保留更新由 889,477 字节降为 4,113 字节，同时保留 primary 签名、完整逻辑读取、旧状态读取和幂等恢复。SQLite 3/4 专项测试通过；消费者合并前仍需统一发布新 SDK 并更新依赖。

## 决策与范围

- 状态只记录变化的字段、文本及数组成员，绑定 primary Turn ID，读取时重建完整应用消息。在兼容容器内，已有整条消息状态继续可读，在下次正常修改时转为差量；不重写或裁剪已封存记录及保留更新。不增加 SQLite 容器迁移。投影复用已解码的 primary，增量生成只转换操作偏移，不再次序列化累计文本或不变正文。
- SDK 在同一事务中准备本地命令计划与精简 pending 回执，再原子提交正文操作、发布信息、最终封存与计划退役。CLI 拥有整个数据库；Turn 导出同步已提交历史，迁移未完成的本地工作须携带包含恢复日志的完整数据库。其他宿主仍可使用 SDK 原有的可复制恢复默认模式。
- 本决策替换此前[写放大修复](2026-10-16-roost-storage-write-amplification.zh.md)的部分处理，不改变带条件校验的原生流式写入、不可变人类输入和分支事务。
- 不部署、不清理历史、不截断 WAL、不合并 PR、不发包。后续统一发布包含相关修复的 Roost 版本，集中更新一次 Lody 共享依赖 catalog，再让相关 PR rebase 并重跑检查。

## 验收与故障边界

测试通过生产 SQLite 路径验证封存、封存后修正、后续流式输出、权限投影、关闭重开及原生回复丢失。大段不变文本不得出现在每条 state 更新和批处理回执中，测量保留更新字节而非 WAL 文件长度。验证 Unicode 偏移、字段删除、嵌套数组和错误基准/路径。错误状态继续使该历史读取报错，不切换后端、不重试写入。恢复日志的准备和应用故障由 SDK 处理，Lody 不另建恢复循环。

SDK 实现为 [Roost #16](https://github.com/loro-dev/roost/pull/16)。统一发包前不改包版本；以下检查使用该实现的本地打包产物，不是当前发布 API。

- 两个改动的 CLI 测试文件，在已发布的 SQLite 3 native 上 **82 项通过**；使用 SQLite 4 native 与独立的 [namespace 配套 #1735](https://github.com/LodyAI/Lody/pull/1735) SQL 测试补丁，也 **82 项通过**。覆盖旧状态重开及转换、首次状态已提交但投影前丢失回复、后续输出、权限、分支和输入合同、Unicode、字段删除、错误基准/路径及 JSON 自有键。

- 格式、全部包类型检查、普通类型感知 lint、Effect lint、i18n 和全部八项仓库边界检查通过。首次提交草稿时，根目录 `test:ci` 仍在运行，交接前记录结果。以上检查使用拟发布 SDK 产物。未部署、未发包。
