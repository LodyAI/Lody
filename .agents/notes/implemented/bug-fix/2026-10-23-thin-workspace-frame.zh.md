# 将工作区外框收为薄包边

Status: implemented
Translation: current

[English](2026-10-23-thin-workspace-frame.md)

## 摘要

工作区页面原有的 8px 间距让内容面看起来像悬浮卡片，并在侧栏收起后使每个页面顶栏都低于固定的 macOS 窗口按钮中心线。外框现在使用最小间距 token 作为 4px 薄包边，并配合 14px 同心圆角；位于外框内的 macOS 顶栏补偿其坐标起点，而原生窗口按钮保持不动。这样无需增加标题栏高度，就能恢复顶栏对齐，并保留控件与页面边缘之间可见的安全空间。静态启动外框与真实工作区仍严格共享同一份几何。

## 几何与职责

`WorkspaceCard` 负责窗口底面与页面画布之间的视觉分隔。包边使用 `space[1]`（4px），内圆角使用 `radius.large`（14px），近似对应 18px 窗口圆角扣除包边和发丝边框后的同心形状。`WORKSPACE_FRAME_CSS` 中可在文档阶段使用的 fallback 采用相同字面值，避免静态启动外框在 React 挂载前绘制旧几何。侧栏可见时页面左边仍直接锚定侧栏；侧栏收起时则在四周露出薄包边。

Electron 保留 `trafficLightPosition: { x: 16, y: 16 }`，因此原生按钮中心仍为 y=23。位于 4px 外框内、没有底边的 44px 行使用 6px 底部 padding：`4 + (44 - 6) / 2 = 23`。带 1px 底边的行使用 5px：`4 + (43 - 5) / 2 = 23`。侧栏行从窗口原点开始，保留既有顶部 padding。Landing 展开按钮使用 5px 局部 top offset，使 28px 控件同样得到 `4 + 5 + 14 = 23` 的中心。调整后，28px 控件与可见画布边缘之间保留 5px；文字拥有更大的安全距离。

没有采用只在侧栏收起时移动原生按钮的方案，因为窗口控件会在布局操作时跳动，而且渲染层状态必须跨到 Electron 主进程。保留 8px 间距再把页面控件抬到 y=23，则 28px 按钮与画布边缘之间只剩 1px。把所有页面顶栏抽到新的窗口级 slot 也能统一坐标，但它会把一次视觉修正扩大为跨页面所有权迁移，并不能改善已经确认的薄包边构图。

## 验证

启动外框浏览器覆盖会断言 4px 原点和 14px 圆角，并继续比较静态首帧外框与真实 `WorkspaceCard`。定向组件覆盖也会锁定外框内的 macOS padding 与 Landing 控件偏移；打包后的 macOS 原生截图仍是非整数显示缩放下最终的光学验收。

本修正仅部分替换此前[启动外框交接决定](../feature/2026-10-19-boot-shell-layout-handoff.zh.md)记录的几何；其中关于启动所有权和就绪条件的保证仍然有效。
