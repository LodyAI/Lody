# 避免 Provider 操作按钮遮挡 Codex 重置预测

Status: implemented
Translation: current
PR: https://github.com/LodyAI/Lody/pull/1407

[English](2026-10-10-codex-reset-provider-actions.md)

## 摘要

紧凑 Provider 行在鼠标悬停或键盘聚焦时，会将刷新和删除操作覆盖在行尾内容之上。当 Codex 行没有行内限额进度条时，这层操作区域会遮住重置预测按钮的文字和部分图标。现在预测入口保持正常的行尾位置，悬停操作显示在受保护的行尾内容之前。隐藏操作不占据布局空间，因此静止状态没有空按钮槽位，操作出现时预测入口也不会移动。操作可能暂时覆盖 Provider 的非交互文字，与紧凑行原有交互一致。

## 原因与决策

`ProviderRow` 的 `reveal` 样式同时承担绝对定位、不透明悬停背景和显隐控制。`CodexResetForecastChip` 位于同一行尾区域。这是共享布局缺陷，无需使用 Windows 专属渲染规则。

将显隐控制与覆盖定位拆开。带预测入口的紧凑行以行尾控件组作为定位锚点，操作覆盖层紧邻该控件组之前。这既保护预测入口和行内进度条，也不会将预测入口推离正常的行尾边距。其他紧凑行保留原有行尾覆盖布局。刷新期间操作始终显示，并保持相同的锚定位置。

最初的修复为隐藏操作预留了正常布局空间。虽然避免了重叠，但静止状态出现空的刷新／删除区域，因此在本 PR 中将其替换。最终布局在悬停和键盘聚焦时保持预测入口的位置，不再永久预留操作区域。资格判断、交互触发加载和弹窗归属继续由原组件负责。

这是对[设置记录行布局](../feature/2026-09-26-settings-row-grammar.zh.md)的局部修正，不改变重置语义或 Provider 资格。

## 验证

Storybook 场景覆盖宽、窄容器中的有效预测，以及没有限额进度条的空预测行。6 项中英文 Chromium 测试通过：静止时操作隐藏，无进度条行的预测入口后没有空操作槽位，悬停时预测入口不移动，显示的操作不与其重叠，并且鼠标和键盘均能打开预测弹窗。原始布局可复现预测入口与刷新按钮重叠 60px。另用 Playwright 截图检查了最终的静止和悬停状态。

现有 Provider 与预测单元测试共 85 项通过，components 包类型检查和修改文件的 lint、格式检查通过。完整 `pnpm check` 在 CLI 类型检查阶段被未初始化的 ACP 适配器子模块阻断。当前环境尚未验证 Windows Electron 安装包。
