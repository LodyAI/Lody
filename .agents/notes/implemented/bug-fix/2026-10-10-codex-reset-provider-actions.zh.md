# 区分 Provider 额度、预测与管理操作

Status: implemented
Translation: current
PR: https://github.com/LodyAI/Lody/pull/1407

[English](2026-10-10-codex-reset-provider-actions.md)

## 摘要

紧凑 Provider 行将剩余额度、第三方重置概率和 Provider 操作混在同一行尾区域。悬停覆盖层会遮挡预测入口，而调整位置后，不同意义的百分比和操作仍被视觉分组。现在行内展示身份、明确标注的剩余额度，以及常驻的 Provider 管理菜单；重置预测通过额度详情进入。没有用量数据时仍能访问预测，但打开它多了一步。这样各百分比和操作有了明确归属，同时消除了悬停覆盖层和空操作槽位。

## 决策

原始布局可复现预测入口与刷新控件重叠 60px。为隐藏操作占位会留下永久空白；把悬停操作移到预测之前虽然避免了重叠，却让 Provider 操作与预测概率被归为一组。这些中间实现在同一 PR 内由 [Provider 额度展示草案](../../../../specs/provider-quota-details.zh.md)中的层级替代。

`ProviderRow` 负责身份、各配置的额度选择，以及管理菜单。容器网格在空间充足时将额度放在名称旁，空间不足时移到下方。紧凑摘要显示两个窗口和额外窗口数量；详情和入口的无障碍描述保留全部窗口。刷新、删除沿用原有操作和确认流程，通过标明 Provider 名称的菜单访问。

`ProviderUsageDetails` 负责只读的剩余额度摘要、常驻的「额度详情」按钮和 popover。按钮使用标准凸起控件和展开箭头，进入详情不再依赖用户猜测指标能否点击。预测是其中单独注明第三方来源的入口，概率仅在预测弹窗里显示。符合条件但尚未报告额度的 Codex 行保留详情入口，明确显示用量不可用。预测弹窗托管在 popover 外，关闭 popover 不会将它卸载。列出 Provider 和打开额度详情均不请求预测；明确点击预测入口后沿用共享 store。Composer 的预测加载和展示保持不变。

## 验证与限制

- Provider 行、机器详情和预测相关测试共 92 项通过。真实 store 集成测试验证列出 Provider 和打开额度详情时预测保持 idle，点击预测入口后才观察到已加载状态及空预测弹窗。
- 8 项中英文 Chromium 测试覆盖宽窄布局、无额度数据、额度百分比与预测概率的区分、键盘进入、popover 到弹窗的切换、刷新结果、删除确认，以及窄容器中的额外额度窗口。身份、额度和菜单在悬停时保持原位。
- Playwright 截图检查带合成 5h／7d 数据的默认行、额度详情，以及标明 Provider 名称的菜单。
- 完整 `pnpm check` 仍在 CLI 类型检查阶段受未初始化的 ACP 适配器子模块限制。尚未验证 Windows Electron 安装包。
