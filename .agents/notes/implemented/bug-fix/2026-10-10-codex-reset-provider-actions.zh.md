# 区分 Provider 额度、预测与管理操作

Status: implemented
Translation: current

[English](2026-10-10-codex-reset-provider-actions.md)

## 摘要

紧凑 Provider 行将剩余额度、第三方重置概率和 Provider 操作混在同一行尾区域。悬停覆盖层会遮挡预测入口，而调整位置后，不同意义的百分比和操作仍被视觉分组。最终行内展示身份、明确标注的只读剩余额度、平面的直接预测入口，以及具名的 Provider 管理菜单。预测概率仅在现有预测弹窗内显示。打开预测只需一次操作，不经过重复行内数据的中间额度 popover。

## 决策

原始布局可复现预测入口与刷新控件重叠 60px。中间修复曾为隐藏操作占位，或将操作移到预测旁边。随后增加的额度详情中间层重复行内已有的 5h／7d 数据，并给预测增加第二步，因此在同一 PR 内删除。最终层级记录于 [Provider 额度概览草案](../../../../specs/provider-quota-overview.zh.md)。

`ProviderRow` 负责身份、各配置的精确额度选择，以及具名管理菜单。容器网格在空间充足时将额度放在身份旁，空间不足时移到下方。刷新、删除保留原有操作和确认流程。紧凑菜单仅展示两项操作，删除前保留分隔线，不再重复 Provider 标题；入口的无障碍名称仍标明 Provider。`ProviderUsageSummary` 以剩余额度语义展示全部已报告窗口，额外窗口通过换行保留，不予隐藏。独立的平面「重置预测」入口直接打开现有弹窗，入口文字不带预测概率。

符合条件的 Codex 行在没有用量数据或有效预测时仍保留直接入口。列出 Provider 不请求预测；入口打开弹窗时沿用现有共享 store。弹窗说明第三方来源，关闭后将焦点返回稳定的入口。Composer 的预测行为保持不变。

额度文字使用 mini 按钮的 footnote 字号和单位行高。概览、额度组及各 meter 中的文字均按基线对齐，仅图形进度条单独居中。Chromium 测得旧版 11px 额度文字和居中布局存在约 1px 的文字基线偏差，修正后各段文字基线一致。

## 验证与限制

- Provider 行、机器详情和预测相关测试共 92 项通过。真实 store 集成测试验证列出 Provider 时保持 idle，仅在点击直接预测入口后观察到加载完成。
- 8 项中英文 Chromium 测试覆盖鼠标和键盘直接打开、不存在中间额度 UI、宽窄面板、无额度数据、概率仅在弹窗内显示、共用文字基线、焦点返回、刷新结果和删除确认。Claude 三窗口场景验证窄行内所有额度 meter 均可见且不越界。
- Playwright 截图检查带合成额度数据的最终宽窄行，以及直接打开的预测弹窗。
- 完整 `pnpm check` 仍在 CLI 类型检查阶段受未初始化的 ACP 适配器子模块限制。尚未验证 Windows Electron 安装包。
