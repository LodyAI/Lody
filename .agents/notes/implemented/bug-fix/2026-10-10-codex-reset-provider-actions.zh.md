# 避免 Provider 操作按钮遮挡 Codex 重置预测

Status: implemented
Translation: current

[English](2026-10-10-codex-reset-provider-actions.md)

## 摘要

紧凑 Provider 行在鼠标悬停或键盘聚焦时，会将刷新和删除操作覆盖在行尾内容之上。当 Codex 行没有行内限额进度条时，这层操作区域会遮住重置预测按钮的文字和部分图标。包含预测入口的行现在通过 flex 布局为操作按钮预留空间，同时保留悬停和聚焦时显示操作的行为。代价是静止状态下 Provider 名称可用的空间略少，但预测入口能够完整显示并独立点击。

## 原因与决策

`ProviderRow` 的 `reveal` 样式同时承担绝对定位、不透明悬停背景和显隐控制。`CodexResetForecastChip` 位于同一行尾区域，却没有为覆盖层的宽度预留空间。这是共享布局缺陷，无需使用 Windows 专属渲染规则。

将显隐控制与覆盖定位拆开。带预测入口的紧凑行始终让操作区域参与正常布局，包括不可见时；其余紧凑行保留原有覆盖布局。Provider 名称和元信息已有截断能力，因此优先让出文字空间，而非挤压控件。预测入口的资格判断、交互触发加载和弹窗归属继续由原组件负责。

这是对[设置记录行布局](../feature/2026-09-26-settings-row-grammar.zh.md)的局部修正，不改变重置语义或 Provider 资格。

## 验证

Storybook 场景覆盖宽、窄容器中的有效预测，以及没有限额进度条的空预测行。桌面设置浏览器测试检查真实控件边界、点击目标，以及中英文下通过鼠标和键盘打开预测弹窗。现有 Provider 与预测单元测试共 85 项通过，components 包类型检查和修改文件的 lint、格式检查通过。使用本机已有的 Chromium 可执行文件，6 项浏览器测试全部通过。恢复旧覆盖布局后，无进度条场景的回归测试失败，测得预测入口与刷新按钮重叠 60px。当前环境尚未验证 Windows Electron 安装包。
