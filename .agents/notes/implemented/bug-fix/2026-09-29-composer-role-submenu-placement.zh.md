# Composer 角色子菜单位置

Status: implemented
Translation: current

[English](2026-09-29-composer-role-submenu-placement.md)

## 摘要

新建聊天页底部 Composer 的角色子菜单原先远离主菜单；第一次尝试让它贴着角色行展开，又使它盖住底部控件。固定的 17rem 双栏高度也让角色较少时列表下方留有大片空白。现在子菜单较矮时相对主菜单垂直居中，较高时底边不超过主菜单底边；双栏按内容增长至最多 14rem。主菜单、权限菜单和角色子菜单保留组件统一的弹层内边距，不再用自定义左右负 margin 抵消；过长内容仍可滚动。

## 决策

`DesktopRunConfigMenu` 将角色子菜单锚定到主菜单弹层。子菜单较矮时垂直居中；较高时上移超出高度的一半，使底边不超过主菜单。角色行仍负责展开和选择；若把较高的弹层直接锚定到这一行，在新建聊天页底部就会盖住底部控件。较小视口下纵向碰撞平移保持弹层留在屏幕内。列表和详情栏不再固定高度，14rem 上限约束较长内容，两个区域分别滚动。产品层不再抵消菜单弹层统一的左右内边距；该补偿曾导致主菜单与子菜单各情境下的行间距不一致。

仍保留双栏，让用户选择角色前看清其配置。只有左栏角色项滚动；新增按钮停在左栏底部，上方不加分隔线，详情标题与配置项之间也不加分隔线。长指令或更多角色可能需要滚动查看。

## 证据与验证

- 用户提供的桌面截图中，17rem 子菜单的底边贴着角色行；列表下方有大片空白，左侧内容比主菜单多一层缩进。
- Storybook 的 `Sessions/ComposerRunConfigMenu` 新建聊天场景使用产品的 `ChatLandingView`，Composer 固定在底部，运行配置控件为实际组件。在 915×760 视口中，主菜单位于 y=405–711，较矮的角色子菜单位于 y=442–674，上下各留 37px。在 700×740 视口中，子菜单切换为居中的单列列表，没有横向溢出。已有会话的较高详情场景在 915×760 下，子菜单与主菜单同在 y=660 结束。选择角色后菜单关闭，Composer 显示所选角色。亮色、暗色及中文菜单保留相同的标准内边距。合成的长列表场景展示了列表和详情栏各自滚动。
- 现有角色面板行为测试和组件类型检查覆盖选择与渲染；Storybook 场景用于验证 DOM 测试无法测量的浏览器弹层定位。在长列表场景中，左栏位于 y=446–670，角色项在 y=446–642 内滚动，滚动后新增按钮仍固定在 y=642–670。

## 尚存限制

桌面类窗口允许缩窄到 400px。在源码组件的新建聊天 Story 中，视口宽度为 580px 或更小时，紧凑子菜单仍占据 x=321–585px，右侧被裁切。这是独立的窄窗口导航问题：主菜单左右两边都放不下第二个弹层。若改为主菜单内部的逐级进入形态，就不再依赖横向空间；这种交互尚未实现，也未在桌面程序中验证。此工作区缺少 Claude、Codex 和 Grok 子模块，本地 Electron 无法启动。

已有会话的 Story 按会话 Agent 筛选角色并禁用 Agent 行，与会话调用方一致。但详情栏仍展示角色保存的预设指令，而已有会话只会应用角色的运行配置。菜单没有说明“展示的信息”与“实际应用的内容”的区别；这是另一项待定的设计问题。

当前行为见 [Composer 运行配置说明](../../../docs/sessions-run-config.md)。
