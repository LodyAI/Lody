# 已创建会话卡片恢复已关闭标签页

Status: implemented
Translation: current

[English](2026-09-17-created-session-card-reopens-closed-tab.md)

## 摘要

子对话标签页关闭后，创建该对话的 Turn 中“查看对话”卡片仍把子会话当作独立根
Session 跳转。父 Session 随后读到共享关闭标记并替换该选中项，导致按钮无法重新打开
对话。现在导航会识别当前工作区中已知的子标签；若目标已关闭，则先执行既有生命周期
恢复动作再选中它，其他 Session 仍使用正常路由跳转。
选中操作会等待打开状态投影到本地，因此旧的关闭元数据不会把明确指向子会话 C 的
请求重定向到已打开的兄弟标签 A 或 B。

## 决策

持久化的 Operation 结果只需要保存创建出的 Session id。这里不重复保存父 Session id，
因为当前元数据才是包含关系权威，而且同一类卡片也可能指向顶层 Session。因此，
SessionDetail 的导航边界会用完整的有序标签集合解析裸目标。命中时按本地标签导航；
若对应元数据已关闭或属于历史归档，则先通过共享恢复 action 恢复，再由 URL 选中。
恢复写入可能早于元数据投影完成，因此选中请求会以精确子会话 id 保存。只有该 id
不再处于关闭状态后才执行导航；若用户期间进行了新的导航，则取消待处理的选中请求。
请求同时记录发起它的 Session，因为只比较 `urlTab` 会让延迟恢复从无 `?tab` 的 Session A
穿透到同样无 `?tab` 的 Session B。

未继续让所有卡片都绕行子会话根 URL。该路由虽然能发现父 Session，却不能表达用户的
“重新打开”意图，并会正确地被父工作区的关闭状态协调逻辑覆盖。也未采用“点击任何
Session 都自动恢复”，因为指向无关 Session 的卡片必须保留普通路由行为。

这是对[共享关闭功能记录](../feature/2026-09-16-shared-tab-closure.zh.md)和
[会话标签关闭规范](../../../../specs/session-tab-closure.zh.md)的缺陷修正。

## 验证

导航回归测试覆盖裸子会话目标、显式根 Session 加标签目标，以及无关 Session。
组件类型检查与聚焦的会话导航、action、标签栏测试是所需的可执行检查。原生视觉验收
仍不在单元测试边界内。
