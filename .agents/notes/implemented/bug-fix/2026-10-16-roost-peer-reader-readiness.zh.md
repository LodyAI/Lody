# Roost 查看者等待后端身份并观察主机检查点

Status: implemented
Translation: current

[English](2026-10-16-roost-peer-reader-readiness.md)

## 摘要

冷启动查看者可能在 Roost 元数据到达前选中旧版 Loro，导致读取器永久空白；正确选择
Roost 后，独立控制游标停止通知也可能使页面一直过期。现在渲染器等待后端身份，
持续读取主机能力，并通过有界的主机请求观察已提交检查点。真实 Repo、Native SQLite、
IndexedDB 和加密 RPC 测试覆盖了元数据晚到、提示丢失、取消以及前台容量独立性。
这是 Roost 集成边界的修复，不能据此认定生产网络时延或独立 Roost 副本同步已经验证。

## 严格审查更正：reset 判断的是覆盖证据

10 月 17 日审查发现渲染器有一处 P1 恢复缺陷。明确的检查点 reset 仍会进入两条旧优化：
控制版本连续时只更新最后提示的消息，或把最新一页当作足够的证据推进原缓存。
原生写入提交后丢失回复，可能留下日志覆盖缺口，同时控制版本仍连续。
计数连续无法证明最后提示包含更早被编辑的消息；这些快捷路径可能保留过期前缀，
却把缓存标为新的版本或检查点。

现在 reset 会在恢复尝试之间保留替换状态，跳过这两条快捷路径，在另一槽位按同一
检查点暂存分页，覆盖完整后才发布。版本相等时也必须匹配新检查点，旧可读副本头
不能满足完成判断。若覆盖证据恢复，完整验证过的增量响应可以结束先前的替换状态。
没有重放命令，正常且已验证的增量仍保持有界读取。

所属渲染器回归编辑完整缓存的 120 条会话中首条和末条正文，只提供尾部提示，
并控制第一份更早分页响应。相等、连续和跳号三种版本都验证：替换完成前旧副本可读，
完成后两处修改一起发布。连续版本用例在修复前明确进入未验证的提示增量路径而失败；
原测试只覆盖跳号版本，漏掉了这个组合。

CLI 所有者套件还串起真实 MessageHandler ACP 缓冲、Native SQLite、生产 RPC 客户端与
服务端的加解密，以及两个独立作用域的渲染器桥接和 IndexedDB 副本。两端控制文档
始终空白，稀疏工具开始/完成及 31 段 Unicode 正文均到达两端，主机重开后内容精确一致。
原生提交成功但回复丢失时，同一自动排空流程恢复，正文没有重复。
传输和浏览器 IndexedDB 使用测试实现，Agent 事件和外围主机服务使用合成夹具，
没有调用模型或真实网络；控制恢复时钟不会推进原生 I/O 期限。

## 发现及与 Loro 的比较

基线和首轮增量修复都在页面取得控制房间同步租约之前，只读取一次元数据。
缺少后端字段被当成旧版 Loro，后续目录补丁不会重组缓存的读取器；主机能力也只采样一次。

Loro 读取持续同步的本地文档，先订阅再取得初始快照，正文也在同一个文档中到达。
Roost 则通过主机 RPC 更新独立的只读投影，Loro 控制文档只携带提示。
过早选择后端和缺少观察恢复，在 Roost 新增的集成边界上才有这些后果，
不能描述为以前 Loro 的问题，也没有证据表明是 Effect 运行时缺陷。

受控实验让控制游标保持不变，但允许正常主机读取。首轮修复在一分钟虚拟时间后仍然
过期，另一次游标通知才使其恢复。这证明缺少恢复触发，不证明生产订阅延迟的原因。
选定方案暴露主机已提交历史的观察能力，不增加定期正文扫描。

## 后端及能力就绪

运行时先使用 Repo 原子的订阅和快照观察会话元数据，再选择历史后端。
明确的 Roost 身份还需要所属机器。临时空控制文档缺少后端字段时保持等待；
旧错误读取器留下的空 Loro 列表不能作为旧版后端证据。
已有非空旧版历史在没有 Roost 游标时仍可离线读取。
已知 Roost 游标旁旧错误读取器写入的 Loro 条目也不能证明旧版身份。
判断只读取容器长度和路径，不序列化整个控制文档 JSON。

其余旧版目录行需要等待该会话所属数据面的元数据恢复。
双数据面运行时中，本机 Meta 先完成不能证明远端云会话身份已经确定。
明确后端到达会完成同一次等待中的 acquire，无需重新打开页面。
Repo 的有限等待拥有独立取消信号；成功、删除和运行时退出都会释放
元数据/状态监听及就绪等待。
恢复完成后，所属机器仍缺失或已知 Roost 游标时，继续等待元数据变化；
不会再次等待已完成的恢复屏障或选成旧版后端。
初始删除标记及之后的删除都会结束待完成的读取器。

Roost 读取器在生命周期内观察所属机器的能力元数据。
增量和观察能力在工作开始时求值，能力晚到会唤醒已有桥接。
能力缺失保留旧版协议路径，释放时停止观察。
检查点路径晚到会停止不必要的旧页面预热，同时保留 reset 的原子替换。

## 检查点观察

独立发布的 `sessionHistoryWatch: 1` 要求 `sessionHistoryIncremental: 1`。
本地控制通过 `session/history-read` 的 `watchChanges` 查询使用该能力；
远端 RPC 使用可单独调度的 `session/history-watch` 方法。
请求、结果及历史错误处理保留所属会话加密和主机归属验证。

Native 后端先登记等待者，再检查提供的检查点。
检查点已变化时立即返回，否则由发布操作唤醒。
随后读取复用同一套持久 `readChanges` 和一致正文响应，
覆盖初始读取到观察登记之间的写入、提示漏报及重连。
缓存正文、成员关系和检查点原子提交之后才观察下一检查点。
检查点未变时不读历史正文、不替换缓存，也不触发正文失效。
只缓存历史末尾时，增量修复成功也直接结束，不再追加最新整页读取。

服务端最多等待 15 秒，远端响应预算为 45 秒。
远端最多接纳 128 个观察请求，与普通读取容量独立。
MessageHandler 也将跨传输的主机等待者限制在 128 个。
等待停在 JavaScript 中，不占 Native Worker 或写入队列；唤醒后，实际读取才取得
普通 RPC 许可或有界本地观察读取许可。
同一会话的本地观察使用独立通道，避免一个空闲查看者串行阻塞另一个查看者。
不会为每个页面创建 SSE 连接，远端复用工作区 Machine RPC 传输。

## 生命周期与恢复

- 触发：活跃历史观察者、主机发布、控制提示、实时能力以及可见性/连接恢复进入同一个刷新所有者。
- 所有者：每个会话桥接持有一个进行中的刷新及其真实读取，共享 RPC 客户端持有已发出的请求；Native 等待者不持有写入槽位。
- 取消：隐藏或离线的远端页面不开始新观察，本地 IPC 离线仍可工作。
  退订/释放隔离迟到结果；已发出的页面请求自然结束或达到有界期限。
  服务端停止和后端关闭取消等待者。结束元数据等待只释放该等待本身。
- 交接：持久主机日志先于检查点响应，缓存原子发布先于下一检查点观察。
- 恢复：被新观察超越立即重试，真实故障退避，日志证据不足明确 reset；不重放用户命令。

渲染器原生 Effect 迁移仍然延期：Repo 组合、缓存和传输消费者还是未完成的 Lody Promise 边界。
已有的原生 Effect 主机就绪服务继续作为 RPC 前置条件；没有新增 Effect runner 或升级依赖。

## 验证及限制

运行时套件使用真实 Repo 订阅，分别控制本机/云端元数据恢复，并覆盖 Roost 身份晚到、
旧空列表、恢复后确认旧版字段缺失和等待中关闭。
渲染器套件在打开后改变能力，并在控制游标保持空白时通过主机观察更新可见正文。
Native 测试覆盖发布、登记间隙、期限、取消、关闭及后续写入可用性。
加密 RPC 测试覆盖真实客户端方法，以及 128 个等待请求存在时普通读取、发送和 ping 仍能完成。

最终聚焦检查通过：CLI/Inbox 215 项，其中 Native 所有者合同 72 项；
渲染器/就绪 84 项；RPC 139 项通过，另有 3 项原有集成跳过。
共享层全套 1508 项通过。类型检查、类型感知 lint、Effect lint、格式化，
以及单独补完的测试后边界/i18n 检查通过。

最终根目录 `pnpm check` 中 CLI 4284 项通过，包括整个 Native 所有者套件，
但两个未修改的 Inbox 操作资源校验用例失败，错误为
`Known resources are still running or cannot be verified`。
它们的 59 项所属套件在聚焦运行中通过，不能据此认定全套失败的原因。
递归检查在 CLI 停止，没有完成全部后续包套件。
文档仍有 subagent-events 双语文档的六处 Kimi/Pi 基线失效链接，
因为这里未初始化这些隔离子模块；改动文档未新增链接错误，没有注册 SHA 保护主题。
全量检查仍未全绿。

产品版 macOS arm64 安装包编译及打包成功，原生 smoke 和签名校验通过。
其 CLI 与已部署的 Docker CLI 字节一致，严格复查更正在渲染器。
不可变构建来源记录于安装包交付，打包不会把新渲染器安装进正在运行的应用。

所有回归使用本地合成数据，没有访问链接中的产品会话、私有 Web/mobile 源码、权限服务或真实网络。
缓存无法提供本机从未同步的正文。独立执行副本、既有数据库压缩及生产部署是另外的工作。
