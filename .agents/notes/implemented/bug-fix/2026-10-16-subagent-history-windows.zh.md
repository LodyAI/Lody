# 将子代理历史写入缩小到子代理输出窗口

Status: implemented
Translation: current
PR: [#1612](https://github.com/LodyAI/Lody/pull/1612)

[English](2026-10-16-subagent-history-windows.md)

## 摘要

此前的工具流式写入优化仍会让子代理批次导出并处理整段会话，每个规范化事件也会线性查找
run。现在同一个写入器按索引定位根工具、旧任务和规范化 run，再分别读取所属 turn 和子代理
输出中的局部窗口。原有 reducer 继续按顺序处理通知，所有修改在首次写入前统一校验。
真实 Loro 合成测试检查结果一致，并拒绝读取无关历史；首次建索引和远端导入之后仍需扫描
元数据，结构性操作和旧存储形式也保留回退路径。

## 问题与决定

[此前的修复](2026-10-14-daemon-history-writes-scale-with-turn-size.zh.md)明确没有覆盖子代理。
独立的[历史探针](https://github.com/leynos/Lody/pull/1)在 `a06a69f3` 基线上复现了全历史路由
和重复 run 查找；三个相关源码哈希与本任务起点 `14ca6d0c1` 相同。这些计数说明工作量增长，
不证明线上阻塞时长或每次超时、恢复失败的原因。另一个[文件锁探针](https://github.com/leynos/Lody/pull/2)
检查既有的排队和清理边界，没有证明循环死锁。

`history-agent-window.ts` 替换写入器原来仅支持工具的窗口内部实现。批次显式声明根会话与
run、父 run 或父工具、旧任务 ID，以及根工具和子代理工具 ID。相关 turn 按实际存储顺序暴露
被选中的项目，仅在根文本、思考更新需要时读取当前 turn 的尾部。子代理输出另有独立窗口，
只包含被引用的工具、计划项，以及文本、思考追加所需的最后一项。仅更新 snapshot 或 progress
时，不转换已有输出。即使所属 turn 已经结束，
新项目仍追加到它的实际列表末尾。

索引保留工具、旧任务和规范化 run 各自原有的重复项选择规则。自身写入只更新受影响位置；
其他写入或导入使索引版本失效。reducer 每批只建立一次根会话/run 索引，新增 run 时更新。
祖先关系、根会话隔离、终态处理、稀疏字段合并和内容过滤继续由 reducer 负责。存储布局、
协议、输出容量、超时与锁策略均不改变。本次属于同步计算，不改变 Effect 生命周期单元。

只缓存 `findRun` 会留下全历史转换；缩小到所属 turn 会留下整个 turn 的转换；只缩小到任务
仍会反复转换完整子代理输出。嵌套窗口同时避开这三种开销，并保留唯一的校验和写入入口。
当前职责和回退范围见[历史写入说明](../../../docs/session-history-writes.md)。

## 验证

现有 CLI 存储测试逐批对比真实全历史写入结果，覆盖旧 turn 归属、不同根会话中的同名 run、
嵌套任务、循环和缺失祖先、重复计划、终态与迟到事件，以及 Devin 生命周期和内部通知。
另一个真实 Loro 测试在连续 32 个子代理批次中禁止导出整个历史、turn 或子代理列表，也禁止
读取无关历史项目；最后检查工具、文本和 progress，并保留无关的旧格式非法子项目及未知字段。
远端导入测试同时移动所属 turn 和子代理项目，并引入此前缺失的 run。非法子代理修改在首次
写入前拒绝整批，前面的合法父级文本也不会提交。

shared reducer 测试对 128 个已有 run 和 32 个 progress 事件限制检查次数并检查最终状态。
临时恢复旧路由会触发整列表导出保护；恢复旧 `findRun` 会超过检查次数上限。这些是确定性的
行为与读取工作量验证，不依赖实际耗时阈值。

额外的临时真实 Loro 合成实验使用 192 个 turn、3,072 个根工具，以及包含 2,048 个工具的
子代理输出，JSON 约 14.76 MiB。16 个批次中，除首批外全历史写入中位耗时 81.82 ms，
窗口写入为 0.205 ms；包括两个元数据索引在内的首次窗口写入为 20.14 ms。最终存储内容一致。
这些是单机测量，不代表线上延迟上限，也没有复现报告中的 6–19 秒阻塞。

实现验证使用独立检出、锁定依赖和固定的 Core/DSH 构建。shared 全部 1,507 项测试，以及
8 个相关 CLI 测试文件的 85 项测试通过。shared/CLI 类型检查和 `check:quick` 通过。
文档检查保留起始检出因子模块文件缺失而产生的 82 项既有断链错误，没有新增错误。不声称
已经完成真实 provider/daemon、生产同步或发布部署验收。
