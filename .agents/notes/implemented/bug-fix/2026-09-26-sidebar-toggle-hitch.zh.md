# Cmd+B 切换时保留桌面侧栏

Status: implemented
Translation: current

[English](2026-09-26-sidebar-toggle-hitch.md) | 中文

## 摘要

此前每次收起后按 Cmd+B 展开，都会重建整棵桌面侧栏，再以 220 毫秒的布局边距动画
逐帧改变内容区宽度。会话行和工作状态标记较多时，React 挂载与反复布局叠加。
现在完整宽度的侧栏保持挂载，用变换滑动、一次性调整分栏占位；隐藏时停止其预取与键盘导航
来源。普通切换因此保留滚动和行内状态，代价是隐藏时仍保留 UI 订阅，而且初始折叠
的窗口也会在首次渲染时挂载侧栏。

## 决策

- `WebWorkspaceLayout` 保留完整宽度侧栏的 DOM。负右边距立即释放分栏宽度，
  变换使侧栏滑出被根容器裁切的区域，不再逐帧调整内容区。隐藏的包装层设置
  `inert` 和 `aria-hidden`，不能被导航访问。
- 记忆化的侧栏内容边界隔离 Cmd+B 可见性更新，避免重渲染 `LoroAppSidebar`。
  只有一个小叶节点监听有效可见性，并挂载或卸载预取上报与键盘导航组件。因此
  隐藏侧栏仍暂停预取并撤销导航回调；前台会话和 Tasks 同步独立继续。筛选浮层随
  侧栏关闭；焦点离开不可操作的侧栏及其浮层，但不抢走其他面板或模态框的焦点。
- 紧凑桌面仍使用浮层退出动画；进入设置页仍会卸载侧栏。已有的按工作区滚动
  恢复覆盖这些重挂载。工作状态标记的视口门控仍有用：隐藏标记无需持续运行
  全部方块动画。

保留原有条件挂载会保住隐藏时 CPU，却复现切换卡顿。保留子树但继续用
`marginLeft` 动画虽能避免 React 重挂载，内容区仍会每帧重排。本次同时去掉这两项
开销，不改变紧凑浮层。

## 证据与局限

- `tests/web-workspace-sidebar-toggle.test.tsx` 覆盖收起和展开后的 DOM、滚动和输入
  状态同一性，包括初始隐藏的侧栏，并验证隐藏时预取来源消失。既有滚动与工作
  标记测试也通过。
- 生产模式 React + jsdom 基准使用 180 条合成混合状态会话。一次运行中，保留侧栏
  的切换均值为 17.44 ms（69 样本），重挂载 45 行预览为 193.56 ms、重挂载全部
  180 行为 727.95 ms（各 16 样本）。这是 JavaScript 代理指标，不是 Electron
  帧耗时：未涵盖完整 `LoroAppSidebar` 数据路径、Chromium 布局与绘制、真实 Web
  Animations。它支持“消除了重挂载工作”的结论，不能证明打包版渲染器的帧率。
- 完整宽度侧栏隐藏时仍接收普通元数据订阅；预取、键盘导航回调和离屏标记动画暂停。初始折叠
  时现在也要承担首次挂载。若启动或后台 CPU 回退，应重新评估这些成本。

本决策改变了先前[滚动恢复决策](../feature/2026-09-25-compact-desktop-layout.zh.md)中
普通切换的行为，延续[工作标记基准](../feature/2026-09-24-sidebar-working-grid.zh.md)。
当前意图见[桌面窗口 Spec](../../../../specs/desktop-windows.zh.md)。
