## 摘要

用户提供的 macOS 桌面截图中，第一颗窗口按钮比导航图标中心偏右约 6px，而导航、项目、仓库和会话文字也分别从四个略有差异的位置开始。只移动原生窗口按钮仍会留下侧栏内部的不齐。现在主窗口将按钮组左移 6px，桌面侧栏各行共用 15px 图标／组标题列与 37px 普通文字列。由于 Linux 无法绘制 Electron 的 macOS 窗口按钮，仍需在 macOS 上验证视觉结果。

## 更正

[原生基线的后续修正](2026-09-30-macos-traffic-light-baseline.zh.md)确认 `trafficLightPosition` 定位的是第一颗按钮的外框而非圆心，因此下文的 `x = 14` 结论越过了侧栏图标的共同中心线。

## 证据与职责

截图中，第一颗按钮的圆心相对窗口约为 x=30，导航图标中心约为 x=24。此前窗口设置 `trafficLightPosition.x = 20`，Electron 据此定位原生按钮组。截图中约 6px 的视觉差距与按钮组偏离侧栏图标列一致。窗口现在使用 `x = 14`，保留 `y = 16` 和原有全屏条件。

第一轮错误地认为导航下面的各行已对齐。按侧栏左边界计算的源码盒子位置显示：导航文字起点为 38px，本地项目 37px，仓库 39px，普通会话 35px；组标题起点是 15px。现在桌面导航图标从 15px 开始，文字从 37px 开始；其他行保留 15px 起始槽，并将普通文字统一到 37px。移动端导航保留原间距。嵌套会话有意增加 12px 树形缩进，作者头像和置顶标记也会因实际内容推后标题，它们不是基线错误。

## 验证与限制

已核对源码和截图几何关系。当前工作树未安装前端依赖，运行环境为 Linux，因此此处未产出原生 macOS 修改后截图或 Electron 冒烟测试。Lody 对话中更新后的对比图是几何示意，不是原生产品截图。macOS 构建仍需在常规和非整数显示缩放下确认第一颗按钮圆心、侧栏文字列以及折叠／返回控件的位置。
