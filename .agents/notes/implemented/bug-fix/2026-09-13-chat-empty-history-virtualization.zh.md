# 将空历史留在对话虚拟列表之外

Status: implemented
Translation: current

[English](2026-09-13-chat-empty-history-virtualization.md)

PR: [#674](https://github.com/LodyAI/Lody/pull/674)

## 摘要

对话加载历史后可能看不到第一条用户消息，却仍能看到 Agent 回复。静态分享让
`leadingContent` 始终非空，因此空历史开始携带零高度占位行挂载 Virtua。
第一条真实用户消息继承了该索引的零高度缓存，可能一直被排除在渲染范围之外。
修复将空历史展示移到 Virtua 外，保留顶部内容，并禁止虚拟行构建器输出空占位项。

## 原因与决策

#646（`0e372f0b`）用包含来源提示和分享请求的 Fragment 替换了可空的来源提示。
此前空历史的提前返回要求顶部内容为空，因此改动后普通空对话会产生两条零高度
虚拟行：顶部容器与空历史占位项。一次加载用户消息和 Agent 回复时，用户消息
继承了占位项的高度缓存。Virtua 0.49.1 的偏移查询选择相同起点处更靠后的回复，
用户消息没有 DOM，因而无法重新测量。React key 的变化不会清除索引尺寸缓存。

使用 React 19.2.0、Virtua 0.49.1、生产滚动 hook 与合成消息的 Chromium 探针
复现了滚动位置为零、缓存为 `[0, 0, 200]`、用户 DOM 不存在的状态。
历史就绪后重新挂载，缓存变成 `[0, 100, 200]`，用户消息恢复。首次挂载即有完整
历史，或空历史后只加载一条用户消息时，没有复现。

`view.tsx` 现在无论顶部内容是否存在，都将空历史作为独立展示。该展示保留来源
提示和分享内容，真实消息出现后才创建虚拟列表。`buildChatVirtualRows` 跳过空
占位项，使滚动计数也与真实行保持一致。不改变持久化历史、派发行为或分享权限。

实时 presence 可能在历史到达之前提供活动标签。空历史展示也渲染
`AgentActivityRow`，保留标签及其色调，否则提前返回会隐藏启动、思考和权限警告。
只有活动状态时仍不挂载 Virtua；历史加载后，活动行再次由虚拟列表承载。

空历史滚动容器采用与有历史时相同的标题栏 inset 和顶部留白。inset 属于整个
展示区域，因此来源提示和分享内容也能避开移动端浮动标题栏。活动行只保留自身
间距，不再重复添加标题栏 inset。

撤掉分享或强制滚到顶部都没有修复缓存生命周期本身。按消息数量给虚拟列表换 key
会让每次追加都重置滚动和测量；以空历史为边界，修改范围更小。

## 验证

`SessionChatHydration.stories.tsx` 使用真实消息列表，通过明确的加载操作切换历史。
`tests/e2e/session-chat-hydration.spec.ts` 在旧路径中等待浏览器测量空行，再同时加载
用户消息和 Agent 回复，检查顶部可见性和顺序，并覆盖加载前后存在顶部内容的情况。
旧渲染器在首条用户消息缺失的可见性断言上失败，修复版通过两种顶部内容场景。
测试只使用合成消息；这是组件与浏览器回归验证，不是完整工作区和传输链路 E2E。
活动状态验证覆盖空数组和空占位项，包括警告色调、标签移除和恢复，以及历史
加载后恰好保留一条活动行。
移动端验证检查顶部内容避开模拟的标题栏 inset、加载历史前后位置一致，并确认
活动行不会重复添加 inset。
