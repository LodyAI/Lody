# 权限请求的历史写入顺序

Status: implemented
Translation: current

[English](2026-09-20-permission-stream-order.md)

## 摘要

权限请求可能在此前收到的文本尚未离开 ACP 缓冲区时插入工具条目，
把同一句话拆成多个 Markdown 块。现在权限处理先等待回合历史门控，
再排空缓冲和正在写入的通知，然后附加权限请求。如果有界排空结束后
仍有待写通知，则通过现有的不可见权限取消路径返回取消。
本修复解决本地持久化乱序，不重排提供方本身交错发送的文本与工具事件。

## 决策与验证

复用已有排空和重试机制，不添加第二个写入者，也不跨工具拼接所有文字。
消息 ID 不一定能区分单条消息中的多个文本块，盲目合并会破坏正常工具与回答边界。
真实 SessionDocument 测试覆盖工具已缓冲、权限补建工具、后续回答保持独立，
以及写入失败后重试、排空期间切换回合后取消旧权限。
