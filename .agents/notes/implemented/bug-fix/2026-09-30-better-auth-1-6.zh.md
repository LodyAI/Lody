# Better Auth 1.6 维护版本基线

Status: implemented
Translation: current

[English](2026-09-30-better-auth-1-6.md)

## 摘要

共享认证依赖此前锁定在 Better Auth 1.5.5。本次将核心、API-key 和 Electron
依赖统一升级到 1.6.33，Convex 集成升级到 0.12.5，在适配器支持范围内获取
1.6 维护线的修复。保留两个既有运行时补丁。真实账号 OAuth 和打包后的原生
客户端登录仍需部署验证。

## 决策与证据

npm 的 `release-1.6` 标签指向 2026 年 9 月 14 日发布的 1.6.33。
虽然 `latest` 为 1.7.6，Convex 集成 0.12.5 声明的范围是
`better-auth >=1.6.11 <1.7.0`，选择 1.7 会违反这个兼容约束。
参考 [Convex 迁移指南](https://labs.convex.dev/better-auth/migrations/migrate-to-0-12)
和 [1.6.33 发布说明](https://github.com/better-auth/better-auth/releases/tag/v1.6.33)。

内外两层工作区的版本目录与锁文件必须一致。根 devDependencies 将
`@better-auth/utils` 固定为与 Better Auth 1.6.33 一致的 0.4.2；否则自动安装
peer 依赖会选择 0.5.0，生成互不兼容的 core 插件类型。API-key 请求处理器仍会启动过期
清理，因此保留移除请求期间清理的补丁，保留显式清理端点。Electron 服务端
入口仍引用 Node buffer/crypto，因此保留使用 Web Crypto 常量时间比较的补丁。
只迁移这两项修改，保留上游的一次性 token 消费与强制 S256 校验。

此决策补充[桌面登录协调器](../architecture/2026-09-17-desktop-login-coordinator.zh.md)：
应用持有 state/verifier 的方式和 cookie hooks 不变，不引入新的登录协调层或
持久化凭据格式。共享客户端工厂通过 const 泛型保留插件元组的具体类型；
通用 `BetterAuthClientPlugin[]` 在 1.6 中会丢失 session 和 organization
类型推断。单例只暴露固定基础插件的契约；由于 TypeScript 无法在泛型函数体
内化简 Better Auth 的条件类型，此处使用局部类型断言。

## 验证范围

两个锁文件均通过冻结校验，补丁成功应用，适配器 schema 已重新生成，实际
表结构不变。全仓类型检查与 lint、595 个后端测试、60 个前端认证测试、公共
边界检查及文档检查通过。工作区、Web 和 CLI 生产构建以 12 GiB Node 堆上限
通过。完整构建在 Electron 打包阶段因本地缺少 `VITE_ELECTRON_UPDATE_URL`
停止；Electron 类型检查通过。线上 OAuth 回调及打包桌面端、移动端登录尚未验证。

三个 Git remote 测试失败由会话注入的 URL 重写引起。使用普通 Git 并移除
测试进程的注入配置后，三个测试均通过。

## 上线顺序

在消费工作区完成依赖升级之前，同时保留 1.5.5 和 1.6.33 的补丁文件。先合并
公共仓库升级，再单独更新消费方的子模块指针，最后合并消费方依赖升级。提前
删除旧补丁会导致中间的指针更新版本无法安装依赖。
