# 在审批前显示 Kimi 计划

Status: implemented
Translation: current

[English](2026-10-27-kimi-pending-plan-review.md)

## 摘要

Kimi 在请求审批前流式发送 ExitPlanMode 参数，因此最初的计划卡片可能只有 `{}`。审批请求已经携带计划正文，但 Lody 保留早先内容，丢弃了正文。现在，尚未回答的 switch-mode 审批请求会用所携带的审阅内容替换参数预览。其他工具和已回答请求继续保留原有内容；此消费端修复不需要发布新适配器。

## 证据与决策

在 Kimi 固定版本 `6a72b37485e95cbda37a86bae6fe4a918686b46b` 中，引擎等待执行前审批钩子完成后才发送工具开始事件。ACP 适配器的 `buildPermissionToolCallUpdate` 已包含计划，而 `session.ts` 在稍后的工具开始事件中才发送独立 Markdown 计划。因此，先前的[计划卡片修复](2026-09-21-kimi-plan-cards.md)不能保证独立计划在决策前到达。Lody 的 `mergeToolCallWithPermission` 原先优先保留任何已有内容，包括流式参数，而忽略审批内容。

共享历史合并现在接受尚未回答的 `switch_mode` 卡片所携带、经过过滤的审阅内容。未提供内容或过滤后为空时保留当前正文；已有结果后的重复请求不能替换它。普通工具沿用保留已有内容的策略，避免扩大对其他工具历史的影响。界面已支持读取第一段审阅正文并排除动作摘要。与 [Claude 拒绝后的展示修复](2026-10-22-claude-rejected-plan-display.zh.md)不同，本问题发生在审批接收阶段。已卡住的历史卡片需要新的审批事件或重试回合；此修复不能恢复已经被丢弃的正文。

## 验证与限制

现有 Loro 历史动作测试新增了未回答前正文可见、普通工具内容保留、审批未提供正文以及取消后重复请求的覆盖。当前嵌套工作树没有安装依赖，缺少 `vitest`，因此未能运行该套件。无外部依赖的 Node 断言运行了实际合并函数和界面解析函数：旧优先级复现 `{}`，修复后在尚无审批结果时显示 Markdown，并通过 JSON 恢复与上述保留场景。未执行真实 Kimi 会话或桌面界面验证；完整工作区类型与构建检查尚未验证。
