# 编辑消息时不把对话校正到末尾

Status: implemented
Translation: current

[English](2026-09-27-message-editor-scroll-jitter.md)

## 摘要

编辑最新用户消息时，编辑器增加换行会让对话出现明显跳动。编辑器位于带稳定 key 的对话行内，
因此每次 textarea 增高都会上报行几何变化，而滚动引擎仍会把处于跟随模式的视口校正到真实末尾。
现在消息行把编辑状态报告给专用的滚动暂停 ref，在不改变跟随模式、也不增加新的滚动写入器的情况下
阻止这些校正。

## 问题与决定

`UserMessageEditor` 根据 `scrollHeight` 同步增高 textarea。它挂载在用户消息行内，每增加一行都会
改变该行的测量高度。对话滚动引擎观察到这个几何变化后，在 `follow` 模式下调用自己的底部校正。
这个校正适合流式输出，却会在用户编辑消息时移动视口。

`SessionChatStreamView` 在其他抑制原因旁维护 `editingUserMessageRef`。连接层只把回调传给最后一个可编辑
的用户消息行；该行在编辑开始时通过 layout effect 报告 `true`，在编辑结束或卸载时清除状态。回调接入
滚动引擎的 `ScrollHost` 暂停路径，因此行测量仍会提交，滚动引擎仍是唯一的跟随模式滚动写入者。
原有的抑制路径继续用于有意的程序化导航，并会释放跟随模式。

修复有意保持当前 `follow`、`read`、`sent` 意图不变。编辑开始时释放跟随会导致编辑器关闭后流式输出不再跟随，
新增第二个滚动写入器又会重新引入竞争校正。因此编辑结束后，后续几何变化继续使用编辑开始前已经处于的模式。

## 证据与限制

- 实现继续由现有 `ScrollController` 作为唯一的跟随模式滚动写入者；暂停信号只控制几何变化是否写入校正，
  不改变保存的滚动意图。
- 尚未在真实桌面端或 Web 对话中验证。
