# 保证开源信息公示弹窗内的列表可以滚动

Status: implemented
Translation: current

[English](2026-10-15-open-source-notices-scroll.md)

## 摘要

开源信息公示弹窗会裁掉长列表，却无法滚动，导致用户看不到后面的条目。
现在，限制最大高度的 ScrollArea 将内部视口作为可以收缩的 flex 子项布局。
统计卡片也进入同一个滚动区域，避免在较矮窗口中纵向排列时耗尽列表空间，
标题与关闭按钮则保留在滚动区域外。Chromium 浏览器测试已在三种窗口尺寸下
滚动到内置资源和依赖列表的最后一项；本次未验证打包后的 Electron 和触摸设备。

## 原因与修复

原先 ScrollArea 外框设置了 `max-height: 70vh`，内部视口却在没有确定父级高度时
使用 `height: 100%`。在 1180×800 的浏览器窗口中，外框高 560px，视口的可视高度
和内容高度却同为 1948px。外框隐藏了溢出内容，真正的滚动视口没有产生可滚动的
溢出区域。把外框设为 flex 纵列，并把视口的最小高度设为零后，视口就能在外框
和弹窗各自的高度上限内收缩。

统计卡片留在滚动区域外还会产生另一个问题：在 400×360 的窗口中，三张卡片
纵向排列后，剩余视口高度变成零。现在统计卡片位于同一视口内的折叠列表之前，
间距使用现有设计 token。现有组件继续负责 Radix 滚动条、折叠控件、许可证选择器、
弹窗焦点约束和延迟触发行为。无需固定视口高度，也就不用单独计算响应式标题和
统计卡片所占的空间。

本次修复补充了此前的[弹窗宽度修复](2026-09-25-dialog-content-width-prop.zh.md)和
[触发时序修复](2026-09-25-base-ui-trigger-prevent-default.zh.md)，不改变它们的决定。
当前实现职责见[产品界面 README](../../../../packages/components/src/components/README.md#about-notices)。

## 验证

现有的[桌面设置浏览器测试](../../../../packages/components/tests/e2e/desktop-settings-layout.spec.ts)
在 1180×800、707×394、400×360 三种窗口尺寸下打开真实的“关于”页面嵌套弹窗。
每个用例检查滚动溢出与边界、实际滚轮位移、最后一个内置资源和最后一个 MIT
依赖的可见性、许可证选择器，以及关闭后的焦点恢复。三个用例在原布局上全部
失败，在修复后全部通过。测试使用随产品提交的公示数据和明确的浏览器状态，
没有网络测试数据或固定等待。

原工作区的组件类型检查、本次改动的 lint 和格式检查均通过。其完整桌面设置
浏览器测试有 19 项通过、3 项失败；恢复原版公示弹窗后，两项导航焦点失败和一项角色共享
开关缺失失败也能复现。仓库文档检查报告双语 subagent-events 提案中六处既有
断链，本次修改的文档没有错误，也没有已登记的 SHA 保护主题。

基于当前 `main` 的 PR 分支已通过根目录 `pnpm format`。完整的 `pnpm check`
在构建未修改的 Claude 适配器时停止，因为复用的已安装 SDK 类型缺少 `run_id`、
`availableCommands` 等字段。全新的依赖图和完整 PR 验证交由 CI 完成。
