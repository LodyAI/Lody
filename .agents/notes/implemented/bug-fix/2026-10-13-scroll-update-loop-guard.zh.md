# 限制会话滚动的同步更新链

## 摘要

滚动引擎单个事务的 commit 上限，无法限制连续事务重启或滚动回调不断改变父组件状态。新的 controller 预算允许一段同步执行中出现 24 次未收敛 commit，超过后记录诊断，向消息列表错误边界抛出明确错误。边界卸载不稳定列表、保留输入框，用户主动重试后创建新的 controller。这能中止合成的引擎驱动更新链，但既不证明用户报告的生产 React #185 根因，也不检测每个子组件独立产生的循环。

## 检测和退出

`afterCommit` 对未收敛工作计数，跨越行 key 变化和事务重启。正常事务仍保留原有六次 commit 上限；24 次为多个连续事务留出余量。超过预算表示疑似不收敛更新链，不是死循环的数学证明。隐藏、空列表、已释放或已收敛的 commit 不消耗预算。

host 安排一个微任务，在同步执行结束后清零计数。它不写滚动位置、不报告视口、不请求 commit，也不重试事务。因此独立用户事件和流式更新不会跨批次累积预算。计数重置后，失败 controller 仍保留错误状态。

预算耗尽时，取消进行中的 glide、清除事务、记录 `update-loop` 诊断，并抛出 `ConversationScrollUpdateLoopError`。trace 包含同步更新次数、意图、目标与实际位置、锚点 key，现有复制报告会包含该 trace。诊断只包含几何和标识，不包含消息正文；环形缓冲区也保留详细条目。

静默丢弃后续 commit 可能留下未覆盖或重叠的视口，自动重新调度则可能重启同一更新链。因此使用已有局部错误页作为明确恢复边界；如果底层触发因素仍在，重试可能再次失败。它不会刷新页面或清空会话数据。

## 验证

模型覆盖重复事务失效、错误锁定和大量独立更新。适配器测试使用真实 React，让滚动回调交替改变父状态，断言明确的边界错误与诊断，再关闭触发因素并主动重试，检查消息行已挂载、覆盖视口且位置稳定。既有随机种子滚动、隐藏标签、原生输入和错误页测试仍位于原有测试套件。依赖树复用本地其他 checkout，workspace 导入指向当前源码。

三个定向套件全部通过，共 122 项测试，包括 40 个随机模型种子。定向格式和 lint 完成，lint 无错误。重试 fixture 在恢复 controller 的首个 layout effect 之前安装浏览器几何；已完整测量的恢复列表不一定需要补充 commit，不能依赖额外 commit 掩盖 fixture 安装过晚的问题。

生产崩溃仍未复现，参见[排查记录](../../proposed/bug-fix/2026-10-13-message-list-update-depth-investigation.zh.md)。复用环境中仍有依赖缺失和 SDK 类型不匹配，完整包类型检查受限。根级 `pnpm check` 和 `pnpm format` 因缺少已安装工具而无法完成。沙箱外文档检查报告 82 个指向缺失 ACP 子模块文件的断链，变更文档范围内没有错误；不声称完成根级全量 check 或真机验收。
