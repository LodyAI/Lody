# 保留文件预览错误并支持显式恢复

Status: implemented
Translation: current

[English](./2026-10-16-file-preview-failure-recovery.md)

## 摘要

文件预览曾将所有 realpath 失败转为“找不到文件”，因此访问权限或 I/O 故障也会让实际存在的文件显示为已删除。再次打开已经激活的错误标签只改变焦点，没有重新读取。此次保留文件系统错误分类，提供“重试”，并在新的打开请求到来时重新读取失败的预览，同时保留成功快照和未保存编辑。本地结构化日志记录解析与读取阶段，不包含文件内容；这些修复并不证明某一用户设备报告的具体根因。

## 决策与职责

- 路径策略保留 native/fallback realpath 及容错目录扫描中的非缺失错误；EACCES/EPERM 映射为权限不足，其余非缺失错误为暂时性 I/O 故障。只有 ENOENT/ENOTDIR 表示缺失。
- 远程请求仍先检查所有候选路径是否位于允许的根目录，再返回错误分类；解析成功后仍按真实路径授权。
- 失败的查看器负责显式重试。新的打开/焦点请求只重试错误或缺失状态，成功预览保留快照和未保存编辑。依赖变化或卸载时沿用读取 effect 的清理逻辑，忽略迟到结果；不声称取消底层文件系统读取。
- CLI 记录工作区/所有者拒绝、请求路径、工作区根目录、所有者、规范路径及有数量上限的探测错误。Electron 记录实际读取结果与耗时。JSON 转义路径中的控制字符；不记录文件内容或资源能力 URL。
- 此次保留现有 Promise 服务与同步解析器。原生 Effect 迁移将涉及尚未完成迁移的 MessageHandler 工作区解析与 Electron 资源所有权，不宣称迁移单元或清单完成。

## 验证与限制

现有路径策略及服务测试使用真实临时文件和注入的操作系统错误，验证错误分类、远程边界屏蔽及不含内容的日志。现有 React 查看器测试验证通过重新打开和“重试”从错误恢复到内容，以及后续焦点请求保留成功快照。测试数据均为合成数据，没有提交设备日志或用户路径。尚未完成打包设备复现，也未确认原始设备故障的根因。
