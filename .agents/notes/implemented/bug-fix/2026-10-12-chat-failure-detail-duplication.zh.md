# 对话失败详情只显示一次

Status: implemented
Translation: current

[English](2026-10-12-chat-failure-detail-duplication.md)

## 摘要

同一张对话失败卡片同时显示可读摘要和原始错误。摘要去掉 `Internal error:`
前缀后与原文不再相等，因此完整字符串去重仍会重复显示错误及其中的操作建议。
卡片现在只显示一次完整原文，仅在原文和标题中均未包含时添加本地化操作建议。
原始 JSON、调用栈和剪贴板报告均保留；取舍是保留提供方的格式，不再另列可读摘要。

## 决策与证据

`ChatFailedNoticeView` 原先将操作建议、提取摘要、原始错误拼接，并用 `indexOf`
做相等过滤。现在由现有纯函数模块中的 `buildChatFailedNoticeDetail` 组装显示内容。
独立的旧详情弹窗保留摘要提取函数。本问题与此前的
[重复历史通知修复](2026-10-04-pre-prompt-duplicate-failure-notice.zh.md)不同，
不涉及存储、分发或历史记录修改。

比较前去除提供方前缀只能处理普通文本，仍会重复显示嵌在 JSON 中的摘要。
选择一份完整原文可以同时解决两种情况，又不丢失诊断字段。

## 验证与限制

现有辅助函数测试集覆盖带前缀的多段错误、内嵌建议、上游 JSON、不同语言的独立建议、
空白及调用栈保留，以及仅标题的错误。现有通知 Storybook 增加合成的恢复失败案例，
断言每段详情只出现一次。直接 Node 断言通过，覆盖纯详情函数和剪贴板报告行为。
工作树缺少依赖，无法运行 Vitest、Storybook 和组件类型检查。文档检查报告仓库已有错误，
改动文档没有新增诊断。路由超时本身不属于此次展示修复。
