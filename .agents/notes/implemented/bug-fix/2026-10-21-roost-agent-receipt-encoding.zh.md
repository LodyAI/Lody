# 压缩 Roost 逐事件回执编码

Status: implemented
Type: bug-fix
Translation: current
Date: 2026-10-21

[English](2026-10-21-roost-agent-receipt-encoding.md)

## 摘要

Lody 原本用 JSON 保存每个 agent 通知的重试身份和内容摘要，UUID 会话的一条回执占 248 B。
新的本地索引以 82 B 保留完整身份、摘要和全部回执，不改变历史事务、签名更新、outbox 保留
或 Roost 本体。合成完整会话对比中，SQLite 增量中位数由 744 KiB 降到 554 KiB，减少 25.5%；
这是磁盘收益，不代表进程内存或网络流量同比下降。实验性格式不保留旧格式读取或迁移：
含 v1 agent 回执的会话会被拒绝，需要新建会话。

## 格式及正确性边界

`roost-content-patches.ts` 负责 v2 编码。规范小写 UUID、`publication` 类型和
`agent:<64 位小写十六进制>` segment 使用标记 0、完整 16 B UUID 和完整 32 B 操作摘要。
其他受支持身份使用标记 1 加原有规范 application JSON 编码。两种表示互不相撞，
大写 ID、额外字段、换行和非 UUID ID 不会被归一化为另一个身份；无效 Unicode 仍由
原有规范编码器拒绝。值包含版本字节 2 和全部 32 B 内容摘要，长度或版本错误直接报错，
不能被当成回执缺失。

`roost-history-generation.ts` 只读取 `lody_agent_operation_receipts_v2`。
打开 owner、恢复或写入前，对 v1 namespace 做最多一行的存在性查询，并仅在 stream
句柄存活期间缓存通过结果；旧格式及混合格式 generation 均被拒绝。它不解码、不转换、
不删除旧记录，同一数据库中的新会话互不影响。升级时应停用之前的 CLI owner，
不支持新旧二进制同时写同一数据库。

原子内容修改/索引事务、重试和冲突判断、当前及祖先 generation 查询顺序保持原样。
结构性操作仍使用 SDK 的当前回执路径，这不是旧格式回退。不清理回执、投影、签名帧或
outbox；不改通知分批、刷新时机、FULL/WAL 持久性和包版本。纯编码及一次有界检查可沿用
现有 Promise Native owner，本次不进行生命周期或 Effect 迁移。

[流式写入决策](2026-10-16-roost-storage-write-amplification.zh.md)定义了回执保留契约，
本次仅替换其中的本地回执编码，与[SDK 消息状态副本优化](2026-10-20-roost-message-storage-copies.zh.md)
相互独立。Outbox 引用需要另改 Roost core，不在本次范围内。

## 验证及测量

四个所属测试套件共 104 项通过。新增测试覆盖精确身份、损坏值、拒绝旧/混合格式且不删除数据、
后续 Native 守卫失败时内容与回执一起回滚、65 条命令的前 30 条提交后丢回复、重开后的
重叠重试、冲突内容，以及分支移除和 generation 替换后的回执查询。已有流式测试改用 UUID，
确认保留全部 128 条回执且恰好占 128 × 82 B，并保留未变内容及重开校验。

手动基准使用实际 Lody adapter、Native 0.2.0 和每轮新建的 SQLite 数据库，基线为公开提交
`a8cffe6f1be2a7b6983770afdebe5231b0a7ae10`。负载包含两轮交互（4 条逻辑消息）、40 个
合成工具、224 批共 917 条通知，最后关闭重开。最终 JSON 为 46,409 B。每轮交互包含
20 个 pending/in-progress/completed execute 工具，各有 512 B 合成终端输出，随后是文本分块。
两轮分别有 459/458 条通知，按整数边界各分成 112 批。四个 macOS arm64 进程按
基线/压缩/压缩/基线顺序运行，每个进程舍弃一次预热，测四个新库，每种方案共八次观测。
SQLite 增量按 `page_count × page_size` 的变化计量；两种方案均不计临时 WAL/SHM、
单独的身份数据库和 Loro 控制数据。

| 指标 | 基线 | 压缩后 |
| --- | ---: | ---: |
| 回执数 | 917 | 917 |
| 回执 KV 字节 | 227,416 | 75,194 |
| 总 SQLite 增量中位数 | 744 KiB | 554 KiB |
| 总 SQLite 增量范围 | 736–748 KiB | 540–568 KiB |
| 完整写入负载均值 / 中位数 | 1622.9 / 1548.6 ms | 1470.6 / 1327.9 ms |
| 进程 CPU 均值 | 1603.6 ms | 1476.3 ms |
| 完整读取均值 / 中位数 | 9.19 / 7.26 ms | 11.08 / 6.32 ms |
| 重开并完整读取均值 / 中位数 | 37.80 / 36.46 ms | 39.63 / 33.58 ms |

所有运行重开前后的逻辑历史均一致；两种方案均保留 272 条签名更新（76,960 B KV）和
272 条 outbox 记录（72,608 B KV）。读取和重开均值含压缩方案 44.3/83.9 ms 的离群值；
有噪声的本地样本证明了空间收益，不保证所有条件下的延迟。这是合成重放，不是原始真实
对话，也没有部署，不能把 554 KiB 说成之前实测 804 KiB 会话的新结果。之前对同一批 KV
的布局实验另确认节省 168–220 KiB；真实收益取决于负载、通知数和页布局。真实用户内容及
基准数据库不进入仓库，手动计时负载不加入 CI。

## 下一版 Native 存储格式的验证

Roost Native 的独立改动停用未被消费的通用 outbox，保留更新日志、事件记录和
持久远端同步工作队列。Lody 已使用这些 Native API，运行时接入无需增加路径。
两处体积断言把所有非 v4 容器误当成已删除的 v3 schema，现直接查询 namespace
联表；已发布 Native 0.2.0 和候选格式都采用该布局。保留内容、不可变日志、
回执体积和有界投影断言；容器版本门禁由 Native 的测试负责。

通过 `NAPI_RS_NATIVE_LIBRARY_PATH` 加载候选 release 动态库后，86 项 adapter
契约测试全部通过，覆盖不确定提交、重启、重试、分页和封存后历史变更。
使用正常锁定依赖的全仓 `pnpm check`、格式和文档检查也通过。本次验证不改包版本，
不部署两边仓库；Native 优化仍需协调发包，再明确升级依赖。
