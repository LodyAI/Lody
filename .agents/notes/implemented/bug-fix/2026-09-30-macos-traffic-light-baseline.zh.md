# 修正 macOS 窗口按钮基线

Status: implemented
Translation: current

[English](2026-09-30-macos-traffic-light-baseline.md)

## 摘要

上一轮侧栏列对齐后，macOS 窗口按钮仍然看起来向左偏移，因为当时把 `trafficLightPosition.x` 当作了圆心坐标。原生 Retina 截图表明，Electron 实际把该点作为第一颗按钮外框左上角的 inset。主窗口现在采用相同的 16px 水平与垂直 inset，使第一颗按钮的圆心落在 `(23, 23)`，与现有侧栏图标和顶部行的中心线重合。在非整数显示缩放下仍需原生验证。

## 更正与基线约定

此结论更正[上一轮对齐决策](2026-09-29-macos-sidebar-traffic-light-column.zh.md)中的坐标判断，但不推翻其侧栏行调整。用户提供的 2x 截图中，窗口从图像坐标 `(118, 86)` 开始，第一颗按钮外框从 `(146, 118)` 开始；两者相差 `(28, 32)` 图像像素，即 `(14, 16)` 布局像素。因此按钮圆心为 `(21, 23)`，在视觉上比 x=23 的导航图标圆心向左 2px。配置的 `{x: 14, y: 16}` 与外框 inset 完全对应；x 和 y 并不是圆心坐标。

修正后的窗口位置是 `{x: 16, y: 16}`。原生按钮直径为 14px，因此圆心是 `(23, 23)`。现有桌面侧栏几何保持不变：6px 外层 gutter 加行 padding／border，使导航、项目和仓库的 16px 图标盒从 x=15 开始、圆心位于 x=23；普通文字从 x=37 开始。普通 Session 行静止时没有前置图标，但标题仍保留相同的 x=37 基线。嵌套 Session、作者头像和置顶内容继续保留有意增加的缩进。

## 依赖的窗口控件与验证

三颗按钮组成的区域现在结束于 x=76。Landing 页的展开按钮仍从 x=96 开始，保留 20px 间距；侧栏折叠后的 Session 顶栏与全屏图片查看器仍保留至少 80px 的安全区域。垂直圆心仍为 y=23，因此现有 44px 行加 2px 顶部 padding、以及 h-7 控件都无需调整。

已审计源码几何、原生截图和每一种桌面侧栏行。这个嵌套 checkout 没有安装前端依赖，因此无法启动完整应用；改用受控 Electron 39.5.1 fixture 渲染修改前后的相同侧栏几何，并由浏览器自动化确认图标中心保持 x=23、窗口按钮外框从 x=14 移到 x=16。当前 macOS TCC 权限拒绝 ScreenCaptureKit 进行原生窗口截图，因此验收图由真实 Electron renderer 截图与两个原生外框位置的精确叠加组成。仍应在完整原生应用中确认非整数显示缩放下的结果。
