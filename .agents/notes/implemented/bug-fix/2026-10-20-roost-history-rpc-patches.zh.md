## 摘要

Roost 历史监听虽然能定位变化消息，却会反复返回不断增长的完整正文。新增独立协商的只读能力，复用已验证的原生更新区间生成普通流式编辑的内容增量。前端仅在缓存检查点匹配时应用增量，并原子提交正文与新检查点。结构变化、封存及状态和权限变化、证据缺失和旧端继续使用完整正文读取。本次不改变数据库格式、签名历史、回执保留方式或 Roost 包。

## 决策与边界

- 先验证前端检查点的完整变化链，再从已有原生事件和更新日志生成有界的逻辑内容操作；不新增持久化增量日志或服务器历史副本。
- 只优化完整区间均属于当前未封存且没有状态或权限投影的 primary 消息的非结构编辑。创建、封存、代际变化及其他物理记录继续读取完整逻辑消息；缺失的原生区间不生成增量。
- 独立协商 `sessionHistoryPatches`。旧请求保持原响应结构，新前端面对旧 daemon 不发送新参数。保留归属加密、就绪检查、版本失效检查和读请求配额。
- 增量携带基准检查点。先在缓存正文的独立副本上准备结果，再使用现有事务原子更新成员、正文和检查点；缺失或不可用的基准通过带检查点保护的完整读取恢复。
- 保持 Unicode 标量偏移、字段删除、数组编辑和已有未知字段；保持逻辑消息身份不可变，非法路径不得部分修改缓存。
- 复用现有 `readStable`、Worker 所有权和读取队列。这是现有所有者上的只读计算，不迁移生命周期，也不新增 Effect runtime、任务所有者或存储写入者。

```mermaid
flowchart LR
  Journal[原生事件与更新] --> Verified[已验证的检查点区间]
  Verified --> Patches[逻辑内容增量]
  Patches --> RPC[按归属加密的历史 RPC]
  RPC --> Cache[原子提交缓存正文与检查点]
  Verified --> Full[不适用时读取完整正文]
  Full --> RPC
```

## 验证与限制

真实 Native SQLite 与归属 RPC 测试保留一段 352 KiB 的合成工具结果，连续修改文本 32 次。每次增量还原都与完整正文响应相同，包含 Unicode 标量编辑；响应 JSON 总量低于完整正文路径的 2%。该结果衡量流式传输，不代表数据库体积或端到端延迟。

真实加密 RPC 测试让支持增量的客户端和旧路径客户端同时连接同一归属端，验证文本及工具结果一致、检查点监听、原生已提交响应丢失后的恢复和持久化重开。前端 bridge 使用真实 IndexedDB 缓存，验证准确基准、过期基准和非法路径的受保护修复、修复失败时检查点不推进，以及重开。合并的原生编辑可在重开后恢复；封存、状态修正和删除带投影默认值的 `fileDiff` 字段走完整读取。共享测试覆盖安全 JSON 键、独立副本失败、身份不可变和能力协商。

快速路径要求完整连续的原生区间，不超过 256 次编辑和 4 MiB 导出帧；每个变化消息只能有一个未封存 primary，且没有后继片段或状态、权限投影。其他区间继续完整读取；本次不减少持久化历史或回执存储。

仓库整体检查记录在 PR 中。本决策补充[已有检查点恢复设计](2026-10-16-roost-incremental-history.md)，不改变其一致性合同。
