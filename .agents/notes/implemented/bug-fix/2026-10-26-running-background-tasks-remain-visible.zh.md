# 运行中的后台任务留在回答下方

Status: implemented
Translation: current
PR: [#1912](https://github.com/LodyAI/Lody/pull/1912)

[English](2026-10-26-running-background-tasks-remain-visible.md)

## 摘要

助手在后台任务结束前先给出回答时，已结束回合的折叠逻辑会把任务面板一并隐藏，尽管面板本身设计为在任务运行期间保持展开。现在，虚拟行构建器会在任一任务待执行或运行时，将任务面板留在回答之后；所有任务进入终态后，面板恢复到现有的工作详情折叠组。任务身份、顺序以及其他工作的折叠判定保持不变。确定性的 Storybook 场景和虚拟行测试覆盖了该状态变化与历史重建。

## 决策

`buildChatVirtualRows` 负责放置消息级任务行。已结束回合折叠时，它原本会把任务行放进最后一个段落的工作详情中，因此 `SubagentTaskPanel` 根本不会挂载，也就无法执行自身的运行中展开规则。现在构建器使用已有的 `isRunning` 判定：只要有任务待执行或运行中，就把整行任务面板放在可见回答之后、页脚之前。终态任务仍沿用原来的工作详情位置。任务行继续使用现有的消息派生 key，`collectSubagentTasks` 的顺序也不变。

折叠资格判定保持原样，以保留既有工作组标题，并将改动限定在任务行位置。没有增加状态、抽象或持久化行为。

## 证据与验证

基线 `91fa467a` 下，新增的虚拟行验收因运行中任务行没有出现在可见列表而失败（`taskRowIndex === -1`）。调整位置后，`tests/plan-turn-virtual-rows.test.ts` 的 8 个测试全部通过。`FinishedAnswerWithRunningBackgroundTasks` Storybook 场景使用合成提示、一项运行中任务和一项已完成任务；`agent-browser` 截图对比显示基线中面板缺失，修复后面板出现在回答下方。历史重建断言保留了行 key 和首次出现顺序的任务 id。

## 权衡与限制

当同一行含有运行中和终态任务时，现有面板会在所有任务结束前将整组显示在回答下方；它不会把一个消息级面板拆成多个独立行。所有任务进入终态后，该组恢复现有的工作详情展开行为。本改动不影响 provider 任务合并或历史重载语义。
