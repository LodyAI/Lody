# 保留 Core 单题表单的完整问题

Status: implemented
Translation: current

PR: https://github.com/LodyAI/Lody/pull/1528

[English](2026-10-13-core-single-question-prompt.md)

## 摘要

Codex 单题表单显示成了 `Input requested`，因为 Lody 优先使用请求提示，覆盖了字段描述里的完整问题。共享转换代码现在对 Core 表单统一优先读取字段描述，同时保留旧版 Claude 单题表单使用请求提示的规则。选项描述原本就能传到前端，仍可在问题卡片的详情窗口查看。已经通过真实 Codex 在 Lody Nightly 中复现，并通过本地解析、持久化历史、CLI 转换和真实问题卡片测试。尚未启动修复后的桌面应用，也没有修补之前已经保存的错误问题文本。

## 决定与证据

锁定的 Codex 适配器版本为 `b67f2eaab63247159c8cbdbd4075334f69729daf`，
它把简短标题放在字段的 `title`，完整问题放在 `description`，通用提示放在表单的
`message`。Core 锁定在 `97007e746737cae86dc17c8ed577447ceb1b2aa6`。
共享解析器原本能够正确处理多道 Core 问题，但对所有单题表单都套用了旧版 Claude
优先读取请求提示的规则。AgentClient 随后保存了这个错误的标准化问题，因此前端收到的文本已经不正确。

修复使用解析器已有的 Core 表单识别结果，不根据供应商名字或通用提示的具体文字判断。
适配器的映射原本就是正确的；修改适配器的通用提示只会掩盖消费者的问题，其他 Core
生产方仍会受到影响。缺少字段描述时，继续回退到请求提示和标题。没有 Core 元数据的旧版
Claude 单题表单仍优先使用请求提示。

```text
Core 字段描述 → 共享问题 → 权限历史 → 问题卡片
旧版 Claude 单题请求提示 ────↗
```

这是对[回答附注转换决定](../feature/2026-09-20-ask-question-answer-notes.zh.md)的补充，
不改变回答关联、协议字段和历史写入责任。当前行为记录在
[AgentClient README](../../../../apps/cli/src/agent/README.md)。

## 验证与限制

- 真实 Codex Plan 会话在 Nightly 发出了一道选择题。问题卡片显示通用提示，打开选项详情后能看到完整选项描述。观察结束后取消了测试问题。
- 修复前，共享层的选择题和自由输入两项回归测试都失败，实际文本都是通用提示，已有 52 项测试通过。CLI 回归测试因为同一问题失败，已有 53 项测试通过。
- 修复后，共享层 56 项、CLI 转换和通知 58 项、组件 15 项测试通过。共享测试经过 HistoryWriter，导出 Loro 快照并重新打开，验证问题和回答。组件详情测试现在读取解析后的 Core 表单，在打开真实问题卡片的选项描述之前检查完整问题。
- Shared、CLI 和 components 的类型检查通过；修改文件的格式检查、lint（无错误，存在原有警告）和 `pnpm run docs check` 也通过。
- 准备 PR 时，`pnpm format` 通过，并执行了 `pnpm check`。沙箱外的全量类型检查和 lint 通过；CLI 套件为 4,087 项通过、1 项失败、4 项跳过。未修改的 SSH 子模块测试以 `context_unreadable` 失败，单独运行也能复现。此前沙箱内的完整组件套件通过 5,182 项测试；该轮检查遇到文件系统和 socket 限制后停止。其余根级边界和 i18n 检查单独执行通过，不声称仓库全量验证为绿色。
- 没有修改供应商或子模块版本、锁文件，也不需要存储迁移。之前已保存错误标准化问题的记录保持原样。修复后桌面应用的实际验收和仓库全量检查与以上定向验证分开。
