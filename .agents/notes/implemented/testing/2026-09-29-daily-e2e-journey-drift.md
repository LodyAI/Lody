# Realign Desktop Daily journeys with the current UI and ACP sessions

Status: implemented
Translation: current

English | [中文](2026-09-29-daily-e2e-journey-drift.zh.md)

## Abstract

Desktop Daily Issue #507 kept failing after the desktop UI changed, because several page objects selected retired roles or treated shared status indicators as proof of one state. The journeys now follow the current accessible controls, distinguish Turn ACP sessions from title generation, and tolerate transient terminal relay disconnects while still requiring a successful cleanup observation. The October 25 run passed 22 of 24 journeys on every platform; the Role machine selector and archive confirmation corrections preserve the configuration-freezing and Session lifecycle assertions. Local full regression also exposed a synthetic ACP response-selection error after history replay, corrected without changing product behavior. A new full three-platform Daily run remains required to close the issue.

## Evidence and decision

The [September 29 full Daily run](https://github.com/LodyAI/Lody/actions/runs/36539627906) built successfully on macOS, Linux, and Windows, then failed six or seven of 24 scenarios per leg. The macOS and Linux logs repeatedly show a missing `Agent Provider` heading, old theme button and preview-item selectors, a Goal dialog lookup for the current popover, and a project removal lookup matching both the dialog and a success toast. Context copy targeted the first fork button on the page and timed out while its menu item stayed outside the viewport. Linux also found the same attachment prompt in both history and the pending-message surface. These are locator failures: each replacement stays scoped to the user-visible action or history row being asserted.

The MCP startup assertion selected the last `session-new` event. Title generation launches another ACP session without the Turn's selected MCP, so the last event may belong to the title. The synthetic ACP fixture now marks title and Turn sessions using the existing `LODY_TITLE_AGENT` environment signal. The journey waits for the Turn session and its own completed prompt before checking its MCP startup configuration. This keeps an actually empty Turn selection observable as a failure.

The September 28 run also failed the queue journey on all three platforms: the queued prompt appeared on multiple page surfaces, so its global text locator resolved to multiple elements. The queue Page Object now finds the row through its `Remove from queue` control and the row's prompt. The September 29 run passed this journey, but the ambiguous locator remained a repeatable failure mode.

On Windows, `terminal.list` returned `terminal_socket_closed` immediately after Session archive. The terminal relay rejects pending requests on socket close and connects again on the next request. Cleanup polling now represents this transport error as a nonmatching observation and continues until the relay returns an empty terminal list; persistent unavailability still times out. This does not establish why the socket closed.

The Windows fork and session-management journeys timed out after their source prompt. Their [artifact screenshot and trace](https://github.com/LodyAI/Lody/actions/runs/36539627906) show the source response completed under the intended project. The old fixture found its ACP prompt event only through a `realpathSync` equality between the recorded `cwd` and the synthetic project root; the artifact did not retain the ACP event log, so the exact path difference cannot be established. The fixture now marks title versus Turn ACP sessions and correlates the completed prompt with the Turn session id. It also keeps its synthetic event log in the scenario artifact for future path diagnosis.

The [first PR full run](https://github.com/LodyAI/Lody/actions/runs/36563017669) passed 22 of 24 macOS journeys. Its failure screenshots showed that the theme selector is a button with `role="combobox"`, so a Playwright button-role lookup cannot find it. After the final Agent Provider deletion, the current empty machine page shows `No agents on <machine> yet`, not the retired `No providers on this machine yet.` copy. The follow-up assertions now use the actual role and current empty-state text, in both supported locales.

The [follow-up PR full run](https://github.com/LodyAI/Lody/actions/runs/36570175372) built the desktop and passed all 24 macOS journeys and 249 steps, including both previously failing settings journeys.

A [subsequent full run](https://github.com/LodyAI/Lody/actions/runs/36572327622) with only the note updated passed 23 of 24 journeys: context copy opened the first user message's sole menu item, but its virtualized anchor moved above the viewport. The trace records the menu positioner at a negative vertical coordinate and the conversation scroll position at its bottom, so Playwright's pointer click waited for an item outside the viewport. A keyboard-focus attempt failed in the [next run](https://github.com/LodyAI/Lody/actions/runs/36574680042): the open menu item did not automatically receive focus. The journey now uses a real upward wheel gesture over the conversation and waits for scroll position zero before opening the first message's menu. It retains the pointer click and clipboard prefix/exclusion assertions, so an unusable menu still fails rather than being bypassed.

The [September 30 run](https://github.com/LodyAI/Lody/actions/runs/36687531414) exposed two separate observation errors. A Session row indicator can represent unread state, active work, sending, or a permission request, so its presence cannot decide whether the journey must mark a Session unread. The journey now consults the read-state menu action and keeps the existing indicator and reopen assertions. On Windows, `terminal.list` can reject with `terminal_socket_closed`, `terminal_socket_unavailable`, or `daemon_unavailable` while the relay reconnects after worktree cleanup. Those errors remain nonmatching poll results; only a successful empty terminal list proves cleanup, and a persistent outage still times out.

The [October 7 run](https://github.com/LodyAI/Lody/actions/runs/37592246516) failed MCP removal and project reopen on macOS, Linux, and Windows. MCP settings replaced the old `main` landmark with a tab panel while retaining the product-owned `data-settings-surface`; the removal lookup now uses that surface and keeps its accessible name, confirmation, deletion, and prior-Turn assertions. The project picker now renders projects as `menuitemradio`, so the Page Object uses that current role with an exact project name and retains the one-option assertion. Windows also reproduced the terminal relay outage above; the run predates the cleanup observation correction.

## October 25: Role machine tabs and explicit archive scope

The [October 25 full Daily](https://github.com/LodyAI/Lody/actions/runs/40172314079) built successfully on all three platforms and failed only `LODY-ROLE-001` and `LODY-SESSION-004`. Linux screenshots confirm that the Role editor already shows its selected local-machine tab while the test waits for a retired machine dropdown option; the archive journey stops at the unanswered sub-conversation confirmation. These failures do not establish a product regression.

The Role Page Object now selects the sole machine tab inside the named Machine tablist and checks its selected state before choosing the exact synthetic Agent config. The fresh isolated desktop owns one local machine; an unexpected additional tab fails explicitly. Accepted Role identity, revision, machine/config pair, instruction freezing across edit/removal, and cleanup assertions remain in place. The [multi-machine Role contract](../../../../specs/agent-role-machine-targets.md) explains the current editor.

The relation lifecycle journey explicitly chooses **Archive all** in the visible alert dialog, then waits for it to close before observing archive state. This follows the [sub-conversation confirmation decision](../feature/2026-10-22-archive-sub-conversation-confirmation.md): recursive archive requires a user choice. The journey still requires all four Sessions to be archived, opened worktrees/processes to be released, permanent root deletion to remove only the root and contained Tab, and independent opened Sessions to retain dangling provenance. Bypassing the dialog through an API or weakening those expectations would miss the user-visible contract.

## Resumed context-copy fixture

The local full run on the current main base exposed a separate failure in `LODY-CONTEXT-001`: after Stop, the custom ACP session is recreated with previous conversation context followed by `=== Current Request ===`. Its recorded wire contains the first rich prompt in history and the new completion request at the end. The simulator's first-marker match chose the historical rich prompt, so the UI correctly displayed the wrong synthetic response and could never show the expected completion tail.

The simulator now classifies only the current-request suffix when that replay envelope exists, while ordinary prompts retain their original classification. This keeps the real Stop/recreate/history replay path and the existing clipboard prefix, incomplete/completed response, and Session-isolation assertions. A direct ACP wire check proves both the ordinary rich response and the resumed completion response. The [repair PR](https://github.com/LodyAI/Lody/pull/1868) includes this additional fixture correction; it does not change the CLI replay contract.

A successful full Daily on macOS, Linux, and Windows is still the closure signal for Issue #507.

The complete root test sweep is not claimed green. Full three-platform Daily recovery remains unverified.
