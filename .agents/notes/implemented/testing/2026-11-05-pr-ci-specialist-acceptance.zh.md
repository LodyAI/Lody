# 专项验收不再随日常 PR 重跑

Status: implemented
Translation: current

[English](2026-11-05-pr-ci-specialist-acceptance.md) | 中文

## 摘要

日常 PR 保留静态检查和受影响包的测试。额外的 E2EE 与对话浏览器验收改为手动；桌面 PR 旅程通过明确标签或手动触发。
这些套件验证浏览器、运行时和打包应用的专项行为，但无关改动不再默认重复支付其准备成本。
相应代价是：作者不请求专项验收时，浏览器或桌面回归可能更晚才被发现。

## 决定

[`ci.yml`](../../../../.github/workflows/ci.yml) 保留 `Static checks`、五个测试组及其必需的 `Tests` 汇总。
普通 E2EE 包级测试继续自动运行。Node 22 签名向量已由包级套件覆盖，手动验收矩阵只检查额外的 Node 24 和 26。

对话浏览器验收移到手动工作流。这部分替代了[滚动引擎决策](../architecture/2026-09-27-conversation-scroll-engine.zh.md)
中的 PR 执行策略；其行为契约和浏览器回归测试继续适用。

桌面 PR 旅程通过 `e2e`、`e2e-full` 或手动触发，取消宽泛的源码路径触发。
并发取消放在实际桌面执行任务上，无关标签事件不会取消正在运行的验收。已有每日三平台 full 套件继续自动运行。

## 取舍

以前通过一次不能证明未来改动不会回归。浏览器验收手动化和桌面旅程按需运行，确实减少了合并前的自动发现能力。
修改相关行为时，作者可本地运行专项套件，或在 Actions 中选择分支执行。
每日桌面套件在合并后发现问题，不能证明单个 PR 在合并前安全。

本次精简不新增夜间套件、必跑门禁或细粒度浏览器路径过滤。
静态检查和普通行为测试仍用于捕获新增回归，能够本地执行本身不代表它们多余。
原有[测试分组与缓存决策](2026-09-26-ci-test-groups-and-pnpm-store-cache.zh.md)继续拥有并行执行和缓存策略。
