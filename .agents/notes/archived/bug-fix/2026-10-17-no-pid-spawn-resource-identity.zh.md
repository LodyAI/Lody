# 无 PID 的启动失败保持资源身份完整

Status: implemented
Archived: 2026-10-30
Translation: current

[English](2026-10-17-no-pid-spawn-resource-identity.md)

## 摘要

缺少 `gh` 等辅助命令时，即使没有创建进程，Session 的资源身份仍被永久标成不完整。
PR 检测虽然捕获了命令错误，Inbox 收尾仍保留本轮并阻塞后续输入。沙箱现在识别
无 PID 的子进程发出的原始错误，命令继续失败，但不引入资源不确定状态。
其他失败和已有的不确定状态仍然阻塞；恢复调度保持不变。

## 决定与边界

沙箱在获取进程的同步阶段订阅 Node 子进程错误。只有子进程没有 PID，且共享进程层
解包后的异常正是该事件中的错误对象，才符合例外。仅凭 errno 无法区分启动失败与
日志登记、配置或清理失败。启动计数器仍会在获取完成前保持日志不完整，并覆盖并发
启动；已有的不确定标记永远不会因此被清空。

Session 继续拥有资源；已获取的进程、取消、终止和后继准入遵循现有的
[Inbox 契约](../../implemented/architecture/2026-10-12-operation-inbox.zh.md)。日志写入失败和
未解决的释放失败仍由保留的恢复 owner 处理。本次只修正获取证据，不改变实际释放
保证。安装 `gh` 只是避开其中一个触发条件；本次无需修改凭据、PATH 或添加自动恢复。

现有原生进程容器已经拥有获取与清理职责。这项小修正属于其 Session 旧接口的日志
适配层；进一步原生迁移会延伸到 Session 消费者，因此暂缓。

## 验证

现有沙箱测试覆盖仍有 Agent 运行时的无 PID ENOENT/EACCES、新观察者、并发获取，
以及已有日志不确定状态的保留。新增成功断言在原实现上失败。测试使用共享的假进程表
和显式配置屏障，没有真实等待。39 项沙箱/容器测试全部通过，进程和 Inbox 边界检查、
格式化及定向 lint 通过（保留两项既有声明顺序警告）。当前检出没有安装依赖，验证
复用了已有的 Effect 4.0.2 环境，并显式映射到本次检出的共享进程源码；这不等于完整
锁定安装、类型检查或构建通过。文档检查仍有既有子模块链接缺失，本记录的两种语言
没有检查错误。
