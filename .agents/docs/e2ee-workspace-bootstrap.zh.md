# E2EE 工作区创建与账本查看

[English](e2ee-workspace-bootstrap.md)

这个开发者预览可以创建模式固定的新加密工作区，并查看经过验证的控制账本。尚未开放文档同步、聊天、附件、机器、邀请或恢复登记。公开 OSS 桌面仍只运行本地模式；云端组合提供控制接口。这不代表全平台 Beta 验收完成。

## 创建过程的责任

```mermaid
sequenceDiagram
  participant UI as 创建页面
  participant Host as 桌面密钥保管
  participant Cloud as 云端控制服务
  UI->>UI: 持久保存绑定账号的创建请求
  UI->>Host: 按原请求 ID 和字段准备
  Host->>Host: 保存原创世记录、受保护设备密钥与 epoch 密钥
  Host->>Host: 重新读回并验证密钥后标记就绪
  Host-->>UI: 公开的签名创世记录与哈希
  UI->>Cloud: 按请求 ID 提交原创世记录
  Cloud-->>UI: 固定工作区 ID、模式与创世哈希
  UI->>UI: 校验回执、固定创世哈希、完成请求
```

开发者选项控制新建入口，不控制已有工作区访问或未确认请求的重试。只有具备持久准备能力的宿主才提供创建。桌面主进程独立验证当前登录账号；IPC 不提供任意签名或私钥导出。Ed25519、X25519 私钥以及 epoch zero 留在桌面保管中，云端创建只接收公开的规范签名字节。这个预览中的工作区名称和 slug 仍属于普通云端元数据。

每个请求 ID 固定账号、名称、slug 与创世记录。云端结果未知时重试相同字节，不改变模式或替换身份。不同窗口分别保留未确认请求；完成其中一个不能删除另一个。宿主存储负责处理中断的密钥准备；中断后缺少受保护材料时明确失败，不静默生成替代密钥。

云端响应将产品工作区 ID 绑定到 `contentMode=e2ee`、版本 1 和 `cryptoOrgId=genesisHash`。这是现有云服务内的加密组织标识，不是切换部署。普通工作区创建 API 不能创建或转换加密工作区。云端账号成员资格只允许读取公开控制记录，不代表能够解密内容或登记设备。

## 历史与运行时边界

历史从创世开始，分页始终固定同一个声明的账本头和条数。客户端用 core 验证器检查每个签名、状态变化、索引和最终检查点。分页不能静默跳过、重排、重复、截断或拼接记录。每行解释账本操作，并可查看原始公开字段。本批创建只产生创世记录；之后接入的有效记录通过同一个读取器展示，不虚构历史事件。

已验证的历史检查点按账号和工作区保留，并使用独立存储键，避免多个窗口覆盖较新的观察结果。只有 core 实际验证过的前缀才会被记录。后续分页和刷新必须与每个已有检查点一致；刷新失败或尚未补齐历史时，继续保留之前的历史，不接受更短或冲突的链。

本地固定的创世哈希独立于历史响应。没有本地记录的设备会明确显示“以服务端创世为起点”的验证状态；签名有效本身不能证明拿到的是预期组织。账本页面不声称新设备已被授权加入。

已知加密模式或本地创世记录优先于服务端后来返回的明文声明。普通缓存清理必须保留这些身份记录。经过在线认证的明文描述可按账号、工作区和 slug 保存，供之后离线启动本地运行时使用，因为本批不允许原地改模式。未认证模式的旧缓存需要先联网查询一次，任意缓存工作区 ID 不能证明它是明文。加密控制页不创建旧 Repo 或执行运行时；后端也独立拒绝其普通 Streams、令牌、分享和执行入口。

历史组织的四个模式/加密字段全部缺失时，服务端排除已有加密工作区证据后，可以明确返回 `legacy-unclassified` 准入。它延续旧行为，不将组织分类为明文；按账号、工作区和 slug 固定后也可供离线启动。本地加密记录始终优先。部分字段缺失、未知格式或查询失败都不能获得这个兼容入口。

没有已保存的准入记录时，初始化需要服务端工作区 ID 和同一账号的真实认证，再查询工作区模式。上述模式准入等待及未响应的模式查询都会在 15 秒后结束；模式关卡可见时，会显示连接或认证原因并提供原地重试。没有本地登录令牌时，外层登录或权限等待页可能先出现，仍使用原有的恢复界面。同一账号重新认证或浏览器恢复联网也会重试失败的准入。取消或超时会释放认证订阅；切换工作区不等待旧查询返回，迟到的旧响应也不能打开旧工作区。准入完成后的认证刷新不会重建运行时。缓存 ID 被同一个服务端 ID 确认、其他账号或工作区的存储事件，都会保留当前运行时和待发送内容。当前工作区的加密证据发生变化时仍会重新检查准入。

已认证的普通或 legacy 准入可以打开当前运行时，即使存储配额已满、无法写入离线缓存。此时影响的是下次启动的离线准入，不是当前已验证的准入。描述符校验、证据读取和加密身份写入仍在失败时阻止启动；不能把信任锚冲突、损坏证据或模式降级当成缓存写入异常忽略。

## 账本兼容性

账本 v1 在生产部署第一次开放创建时冻结，而不是在这些代码合入时；此前经所有者批准的格式修改可以重新生成样例，开放生产创建前须先对权限账本中的待定事项做格式审查。冻结之后永久有效：契约见[基础规范](../../specs/e2ee-foundations.zh.md#格式兼容性)，由独立 Python 编码器生成的 `packages/e2ee-core/test/ledger-v1-vector.json` 必须原样通过验证。新操作需要此前出现过由 Owner 或 Admin 个人设备签署的能力声明（标签 9）。当前客户端不支持任何能力，因此遇到真实声明时在该位置停止验证：控制页展示已验证的部分、停止翻页，并提示用户升级 Lody。更新的模式版本或未知的 `activation` 同样失败关闭，提示升级，而不是报告损坏。快照和其他格式仍只支持当前格式，因为它们可以从 v1 历史重建。

## 加密标识与本机救援

工作区列表（桌面切换器、移动端面板、引导页）根据列表里的 `contentMode` 显示锁图标。这份元数据只用于展示：准入仍以持久化的模式描述为准，缺失或伪造的列表数据既不能打开明文数据，也不能阻止进入加密路由。控制页标题为“加密工作区”，并带“开发者预览”标记。页面开头是账本核验卡片：64 位核验码、标签旁的账本版本（已验证记录数）和二维码。页面不显示 pin 相关结论：在其他设备上“历史一致但未 pin”是正常情况，对此告警只会让人不安；真正的故障仍以提示框显示。说明文字、工作区 ID 和创世哈希都收在帮助按钮后面。核验码是核心库的比对摘要（`ledgerStateDigest`，与比对记录中的 `stateDigest` 相同），绑定协议、创世、版本、head 和实际权限状态，符合[白皮书](../../specs/e2ee/whitepaper.zh.md)对安全码的要求；只比 head 哈希不够。成员通过复制或扫码在带外比对（摄像头经 `getUserMedia` 和 `jsqr`，粘贴始终可用）。版本和摘要都相同即一致；对方版本较旧且其 head 等于本账本该位置的记录，说明是同一历史的旧副本；同一位置或共同位置上的其他差异均为不一致。比对结果不持久保存，因此页面尚不显示“已独立核对”。下方依次是当前成员，以及每条记录一行的可读摘要，展开后显示记录字段和原始字节。已知资料的成员显示头像和姓名：目前只有当前账号，且仅当本机持有创建时的 pin 时才对应到创世成员；其他成员按加入顺序显示为“成员 N”，操作归属于签名设备所属的成员。姓名是账号资料中的展示数据，不是账本事实。`e2ee-ledger-overview.ts` 和 `e2ee-ledger-verification.ts` 只做这些推导，不授予任何权限。页面不宣称内容已受保护，因为目前还没有接入任何内容。

提供任何恢复手段之前，先对失败分类。服务端历史验证失败、网络和登录问题，只提供刷新和诊断信息。身份冲突（pin 或已知模式与服务端不一致，或 pin 无法读取）按可能的替换或降级处理，客户端不提供重置。进度冲突（服务端历史相对本机记录的进度出现回滚或分叉）提供两步确认的重置，只清除该工作区的已观察进度，应在支持人员确认服务端历史无误后使用。无法读取的可选缓存（模式证明和已观察进度）可以删除；pin、已知加密标记和创建请求永远不删。明文工作区因缓存无法读取导致模式准入失败时，重试只删除这些条目，并在原地重新读取存储。“复制诊断信息”生成的报告只含标识、哈希、数量、构建信息和错误码，不含账号 ID、密钥、签名或记录正文；剪贴板被拒绝时报告仍可见。

## 后续接入

恢复登记、经过授权的设备加入、账本变更、加密数据通道与全平台保管仍是后续批次。关闭新建选项保留已有控制访问及待确认请求恢复。本预览不证明生产已部署、原生系统密钥库可用、恢复覆盖完整或加密实时协作已经可用。

部署顺序：先发布提供 `e2eeWorkspaces.describe` 的后端，再发布新客户端。普通工作区首次取得准入记录也调用此接口，关闭开发者选项不会跳过它。超时让首次准入失败可以在当前页面重试，但没有验证证明的旧缓存仍不能离线打开；localStorage 配额耗尽时，新的普通模式证明也无法保存供下次离线启动。这是发布与离线可用性的限制，不能因此把缓存 ID 当作明文证明。

## 云接口背后的私有账本存储

创建与历史读取使用 Convex action，模式描述仍为 query。私有后端把原始签名账本放在独立 Streams bucket，完整验证 core 权限后才做条件追加。公开 DTO 不提供 Streams 地址或凭据；客户端仍独立验证原始记录与已保存的检查点。

创建分为数据库预留与外部创世记录的原子写入、读回确认。待处理请求保留原始字节，只有持久写入状态的拥有者可以发出写请求。调用已结束且确定尚未发出写入、或每次写入都被明确拒绝时，可以释放状态供相同请求重试。结果未知的追加，先读回原位置；位置为空时，用保存的 CAS offset 重发同一份已签名字节，绝不靠超时或重新签名判断。结果未知的创世 PUT 会留下一个永久标记，阻止擦除和账号删除完成：当前 Streams 服务允许迟到的 PUT 在已删除的 URL 上重建 stream。只有 Streams 的永久删除墓碑（[loro-streams#428](https://github.com/loro-dev/loro-streams/issues/428)）加上延迟旧 PUT 的联调测试才能解除这道限制；超时、HEAD 404 或修改 Convex 数据行都不能替代。这些改动不开放内容运行时或产品账本编辑 UI。
